# Project Governance

University CS Docs uses a maintainer-led, contribution-friendly governance model.

## Roles

### Contributors

Anyone who reports an issue, improves content, submits code, reviews a change, or helps another participant is a contributor.

### Reviewers

Reviewers are trusted contributors who regularly provide accurate, constructive reviews in an area such as a course, accessibility, application code, or resource provenance. Review responsibility may be granted or withdrawn by maintainers based on sustained participation.

### Maintainers

Maintainers set project direction, manage releases and repository settings, enforce community standards, resolve security reports, and make final merge decisions. The current lead maintainer is [Mooketsi Vincent Magwaza](https://github.com/MooketsiMagwaza).

## Decision-making

- Routine fixes and additions are decided through pull-request review.
- Significant changes to information architecture, assessment policy, licensing, security, or contributor workflow should begin with an issue or Discussion.
- Decisions favor course accuracy, student usefulness, accessibility, maintainability, verifiable sources, and lawful redistribution.
- Maintainers seek contributor input when practical but retain final responsibility for the repository.
- When consensus is not possible, a maintainer documents the decision and its trade-offs in the relevant issue or pull request.

## Merging

Changes to `main` should arrive through pull requests, pass required automated checks, receive the required review, and resolve review conversations. Maintainers may use an emergency exception for a narrowly scoped security or production fix and document it afterward.

## Becoming a reviewer or maintainer

Regular contributors may be invited based on demonstrated technical or subject-matter judgment, reliable reviews, respectful conduct, and sustained stewardship. Access follows least privilege and can be removed for inactivity, security reasons, or violations of project policy.

## Amendments

Governance changes are proposed through a pull request and should explain the motivation and expected community impact.
