## 2. Growth rates, slowest growth first

| Big-O | Name | Lecture's verdict | Doubling `n` makes it |
|---|---|---|---|
| O(1) | constant | Excellent | the same |
| O(log n) | logarithmic | Good | one more step |
| O(n) | linear | Fair | twice as long |
| O(n log n) | n-log-n | Bad | a little more than twice |
| O(n^2) | quadratic | Worst | four times as long |
| O(n^3) | cubic | Worst | eight times as long |
| O(2^n) | exponential | Worst | squares the work |
| O(n!) | factorial | Worst | far worse still |

## 3. Counting steps: the template

Count each line as a constant `c` multiplied by the number of times it runs, then add the lines. Then keep the fastest-growing term and drop its coefficient.

| Code shape | Times the line runs |
|---|---|
| A statement outside any loop | 1 |
| Statements in a sequence | add their times |
| `for (int i = 0; i < n; i++)` header | init 1, test `n + 1`, update `n` |
| The body of that loop | `n` |
| The body of a loop nested inside it (also to `n`) | `n * n` |
| The body of a loop whose bound is `i` | `0 + 1 + ... + (n - 1) = n(n - 1) / 2` |
| A loop that halves (`i = i / 2`) | about `log2 n` |
| `if` / `else` | the test, plus the more expensive branch |

**Worked count.** For the method below, set every `c` to 1:

```java title="CountSteps.java"
public class CountSteps {
    static int addNums(int n) {
        int sum = 0;                          // c1: 1 time
        for (int i = 1; i <= n; i++) {        // c2: n + 1 tests (and n updates)
            sum += i;                         // c3: n times
        }
        return sum;                           // c4: 1 time
    }

    public static void main(String[] args) {
        System.out.println(addNums(100));
    }
}
```

```text
5050
```

`T(n) = c1 + c2(n + 1) + c3 n + c4`, which is `1 + (n + 1) + n + 1 = 2n + 3` when every `c` is 1. Counting the `n` updates of `i++` as a separate line gives `3n + 3` instead. The fastest-growing term is `n` either way, so `T(n)` is **O(n)**. Different counting conventions change the exact formula but never the Big-O, which is why the exam asks for the order.

## 4. Reading Big-O straight from the loops

| Loop shape | Cost | Why | Used again in |
|---|---|---|---|
| One loop to `n` | O(n) | the body runs `n` times | linear search (Lecture 8) |
| A loop with a step of 2 or 3 | O(n) | about `n / 2` or `n / 3` passes: only the coefficient changes | |
| Two loops one after the other | O(n) + O(n) = O(n) | add, then drop the constant | |
| A loop nested in a loop, both to `n` | O(n^2) | `n` times `n` | bubble sort (Lecture 9) |
| Inner bound is the outer counter `i` | O(n^2) | `1 + 2 + ... + n` is about `n^2 / 2` | selection and insertion sort (Lecture 9) |
| Three nested loops, all to `n` | O(n^3) | `n` times `n` times `n` | |
| A loop to `n` with an inner loop that runs 5 times | O(n) | the inner bound is a constant factor | |
| A loop, then a nested pair | O(n) + O(n^2) = O(n^2) | add, then keep the dominant term | |
| Loop to a fixed number like `10` | O(1) | the bound does not depend on `n` | |
| Loop with `i = i / 2` | O(log n) | halving `n` reaches 1 in `log2 n` steps | binary search (Lecture 8) |
| Loop to `n` with a halving loop inside | O(n log n) | `n` times `log n` | merge sort halves the problem (Lecture 9) |

```java title="Shapes.java"
public class Shapes {
    public static void main(String[] args) {
        int n = 16;
        int linear = 0;
        int nested = 0;
        int sequence = 0;
        int constantInner = 0;
        int dependent = 0;
        int halving = 0;

        for (int i = 0; i < n; i++) {
            linear++;                                 // n times: O(n)
        }
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                nested++;                             // n * n times: O(n^2)
            }
        }
        for (int i = 0; i < n; i++) {
            sequence++;                               // two loops one after the other:
        }
        for (int i = 0; i < n; i++) {
            sequence++;                               // n + n = 2n times: O(n)
        }
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < 5; j++) {
                constantInner++;                      // 5n times: O(n)
            }
        }
        for (int i = 0; i < n - 1; i++) {
            for (int j = i + 1; j < n; j++) {
                dependent++;                          // the selection sort loops: n(n - 1) / 2 times
            }
        }
        for (int i = n; i > 1; i = i / 2) {
            halving++;                                // log2 n times: O(log n)
        }
        System.out.println(linear + " " + nested + " " + sequence + " " + constantInner + " " + dependent + " " + halving);
    }
}
```

```text
16 256 32 80 120 4
```

For `n = 16`, the counts are 16, 256, 32, 80, 120 and 4: `n`, `n^2`, `2n`, `5n`, `n(n - 1) / 2` and `log2 n`.

## 5. Simplifying T(n) to Big-O

Two rules, in this order:

1. **Keep only the fastest-growing term.** `3n^2 + 4n + 2` becomes `3n^2`.
2. **Drop its constant coefficient.** `3n^2` becomes `n^2`.

| `T(n)` | Big-O |
|---|---|
| `5` | O(1) |
| `7n - 3` | O(n) |
| `7n - 2` | O(n) |
| `3n^2 + 5n` | O(n^2) |
| `3n^3 + 20n^2 + 5` | O(n^3) |
| `3 log n + 5` | O(log n) |
| `8n^2 log n + 5n^2 + n` | O(n^2 log n) |
| `2n` against `4 + 3n^2` | linear against quadratic: the second grows faster |

The coefficient 20 in `3n^3 + 20n^2 + 5` does not make `n^2` dominate: the cubic term is the larger one from `n = 7`.

## 6. Best, worst and average case

| Case | Meaning |
|---|---|
| Best | The shortest possible runtime for size `n`; assumes everything goes well |
| Average | The expected runtime over inputs of size `n`; difficult to calculate |
| Worst | The maximum runtime for size `n`; the most commonly used, and the most crucial in domains such as surgery and air traffic control |

A search through an unsorted array of 8 items shows all three: best 1 comparison, worst 8, average 4.5 when the target is present. That is O(1), O(n) and O(n).

Say which case you mean. "A search is O(n)" means the **worst** case unless stated otherwise.

## 7. Common errors

| Mistake | Correction |
|---|---|
| Counting only the loop body and ignoring the loop header | The test runs `n + 1` times, one more than the body |
| Writing `O(3n)` or `O(n + 5)` | Drop constants: `O(n)` |
| Calling two nested loops O(n) because each is "just a loop" | Multiply nested loops: O(n^2) |
| Multiplying two loops that are one after the other | Add them: O(n) + O(n) = O(n) |
| Calling a loop with an inner loop of 5 passes O(n^2) | The inner bound is constant: O(n) |
| Mixing up the best case with the cost of the algorithm | State the case; the default is the worst |
| Treating `n` in `T(n)` and the value in the loop bound as unrelated | `n` is whatever the bound depends on |
