## Two ways to compare algorithms

Suppose there are two algorithms for the same problem. How do we know which is faster?

**Option 1: experiment**

Write both programs, run them on the same data sets of different sizes (timing them with `System.currentTimeMillis()`), repeat several times, average the times and compare.

**Problems:** you must write both programs first; the results depend on the computer, the operating system and even the programming style; and you can only test a limited number of inputs, so an algorithm might be slow on data you never tried.

**Option 2: count (the method we use)**

Don't run anything. Count the basic steps the algorithm takes, as a formula in terms of the input size *n*. This works on paper, on pseudo-code, before any program exists, and the answer is the same on every computer.

## Primitive operations

A **primitive operation** is one basic, low-level action, such as:

- declaring a variable or assigning a value: `sum = 0`
- one arithmetic operation: `a + b`
- evaluating a comparison: `i <= n`
- looking up an array element: `arr[i]`
- calling a method, or returning from one: `return sum`

We assume each primitive operation takes some fixed amount of time, called a **constant**. We name the constants *c*₁, *c*₂, *c*₃, … (one per line of code), because we don't know or care exactly how many nanoseconds each takes. Then the total running time for an input of size *n* is written **T(*n*)**, read "T of n".

<Callout type="note">

In exams it's common to say "each constant counts as 1" when simplifying. So *c*₁ × 1 + *c*₂ × *n* becomes 1 + *n*. That's what the revision notes do, and it never changes the final Big-O answer.

</Callout>

## The three counting rules

<Steps>

<Step title="Sequence: add them up">

Statements that run one after another: T = cost of the first + cost of the second + …

</Step>

<Step title="if / else: the condition, plus the more expensive branch">

Only one branch runs, but for the worst case we assume the slower one: T = condition + max(if-branch, else-branch).

</Step>

<Step title="Loops: cost of the body × number of times it repeats">

And the loop's condition is checked one more time than the body runs.

</Step>

</Steps>

### Why does a loop condition run *n* + 1 times?

Take `for (int i = 1; i <= n; i++)` with *n* = 3. Watch the condition:

| Check number | `i` | `i <= 3`? | What happens |
| --- | --- | --- | --- |
| 1 | 1 | true | body runs (1st time) |
| 2 | 2 | true | body runs (2nd time) |
| 3 | 3 | true | body runs (3rd time) |
| 4 | 4 | false | loop ends |

The body ran 3 times, but the condition was checked **4** times: once for every pass, plus one final time that comes out false and stops the loop. In general: **condition *n* + 1 times, body *n* times**. A `for` header actually has three parts, each counted separately:

- `int i = 1` (initialisation): runs **once**.
- `i <= n` (condition): runs ***n* + 1** times.
- `i++` (update): runs ***n*** times, once after each pass of the body.

## The lecture's examples

### a) One statement and b) a sequence

```java title="Constant time"
i = 1;            // c1 × 1                    T(n) = c1             → constant
// ---
i = 1;            // c1 × 1
val += i;         // c2 × 1                    T(n) = c1 + c2        → still constant
```

### c) Selection (if / else)

```java title="Selection"
if (a > 0)        // c1 × 1
    val = 10;     // c2 × 1
else
    val = 1;      // c3 × 1
// T(n) = c1 + max(c2, c3) = 1 + max(1, 1) = 2   → constant: O(1)
```

### d) One loop

```java title="Single loop"
tot = 0;                   // c1 × 1
c = 1;                     // c2 × 1
while (c <= n) {           // c3 × (n + 1)    ← condition: one extra check at the end
    tot = tot + c;         // c4 × n
    c = c + 1;             // c5 × n
}
// T(n) = c1 + c2 + c3(n + 1) + c4·n + c5·n
//      = 1 + 1 + (n + 1) + n + n          (setting every c to 1)
//      = 3n + 3                            → proportional to n: O(n)
```

<Callout type="caution" title="About the slide's version">

The slide's loop uses `c = c + 2` but still says the body runs *n* times. With `+ 2`, `c` takes the values 1, 3, 5, …, so the body actually runs about *n*/2 times. The formula changes (roughly 1.5*n* + 3), but the growth rate doesn't: it's still O(*n*). If you meet this in an exam, either count it as *n*/2 or note that halving doesn't affect Big-O.

</Callout>

### e) A loop inside a loop

```java title="Nested loops"
c = 1;                     // c1 × 1
while (c <= n) {           // c2 × (n + 1)
    i = 1;                 // c3 × n              ← inside the outer loop: runs n times
    while (i <= n) {       // c4 × n(n + 1)       ← (n + 1) checks, done n times over
        print(i);          // c5 × n·n
        i = i + 1;         // c6 × n·n
    }
    c = c + 1;             // c7 × n
}
```

The trick for anything inside the inner loop: it runs *n* times *for each* of the *n* outer passes, so *n* × *n* = *n*² times. Now add everything, setting each *c* to 1:

<KeyTerm label="Working" tone="green">

T(*n*) = *c*₁ + *c*₂(*n*+1) + *c*₃*n* + *c*₄*n*(*n*+1) + *c*₅*n*² + *c*₆*n*² + *c*₇*n*<br /> = 1 + (*n* + 1) + *n* + (*n*² + *n*) + *n*² + *n*² + *n*<br /> = 3*n*² + 4*n* + 2<br /> → the fastest-growing term is *n*², so T(*n*) is **O(*n*²)**.

</KeyTerm>

## Fully worked exam question

This is the question in the revision notes: *"What is the time complexity of this method?"*

```java title="AddNums.java"
public static int addNums(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum += i;
    }
    return sum;
}
```

Make a table with one row per operation. The `for` header is split into its three parts:

<TraceTable>

| Code | Constant | How many times? | Cost |
| --- | --- | --- | --- |
| `addNums(int n)` (the call) | *c*₁ | 1 | *c*₁ × 1 |
| `int sum = 0;` | *c*₂ | 1 | *c*₂ × 1 |
| `int i = 1` | *c*₃ | 1 | *c*₃ × 1 |
| `i <= n` | *c*₄ | *n* + 1 | *c*₄ × (*n* + 1) |
| `i++` | *c*₅ | *n* | *c*₅ × *n* |
| `sum += i;` | *c*₆ | *n* | *c*₆ × *n* |
| `return sum;` | *c*₇ | 1 | *c*₇ × 1 |

</TraceTable>

<KeyTerm label="Model answer" tone="green">

T(*n*) = *c*₁·1 + *c*₂·1 + *c*₃·1 + *c*₄(*n* + 1) + *c*₅·*n* + *c*₆·*n* + *c*₇·1<br /> = 1 + 1 + 1 + (*n* + 1) + *n* + *n* + 1<br /> = 3*n* + 5<br /> = **O(*n*)**, because 3*n* is the dominant term and constants are dropped.

</KeyTerm>

<Callout type="tip">

Don't panic about whether your lecturer counts the method header as a step, or counts `sum += i` as one operation or two. Different counting choices give different numbers (3*n* + 5, 4*n* + 4, …) but *the same Big-O*. Show your table clearly, be consistent, and you'll get the marks.

</Callout>

## From T(*n*) to Big-O

A formula like 3*n*² + 4*n* + 2 is precise but clumsy. What we really want is its **growth rate**: how the time increases as *n* gets large. The rules (see [Big-O](/docs/sem3/csi247/03-time-complexity/notes/algorithm-analysis) for the full explanation):

1. Keep only the **fastest-growing term** (the dominant term).
2. Drop its **coefficient** (the number in front).
3. Drop all **lower-order terms** and plain constants.

Why can we throw these away? Because when *n* is huge they hardly matter. For *n* = 1,000,000, 3*n*² is 3 trillion, while 4*n* is only 4 million: less than a ten-thousandth of a percent of the total.

| T(*n*) | Dominant term | Big-O |
| --- | --- | --- |
| 7*n* − 3 | 7*n* | O(*n*) |
| 3*n*² + 5*n* | 3*n*² | O(*n*²) |
| 8*n*² log *n* + 5*n*² + *n* | 8*n*² log *n* | O(*n*² log *n*) |
| 4 + 3*n*² | 3*n*² | O(*n*²) |
| 2*n* | 2*n* | O(*n*) |

### Ranking growth rates

| Big-O | Name | Lecture's verdict | Example |
| --- | --- | --- | --- |
| O(1) | constant | Excellent | `arr[i]`, one if/else |
| O(log *n*) | logarithmic | Good | binary search |
| O(*n*) | linear | Fair | linear search, one loop |
| O(*n* log *n*) | n-log-n | Bad | merge sort |
| O(*n*²) | quadratic | Worst | bubble, selection, insertion sort |
| O(*n*³) | cubic | Worst | three nested loops |
| O(2<sup>n</sup>), O(*n*!) | exponential, factorial | Worst | trying every subset / every ordering |

*Table 12a.1 — Fastest at the top. "Bad" for n log n is relative: it is the best possible for sorting by comparisons.*

## Best, average and worst case

The lecture lists three estimates. The **best case** is the shortest possible time (everything goes well). The **average case** is the expected time over all inputs of size *n*; it's hard to calculate. The **worst case** is the longest possible time, and it's the one used most, because it's a guarantee. In some applications, like surgery equipment or air-traffic control, only the worst case matters.

<CheckQuestion question={<>Big-O of 7<em>n</em> − 2?</>}>

<CheckQuestion question={<>Big-O of 3<em>n</em>³ + 20<em>n</em>² + 5?</>}>

O(*n*³). Even though 20 is bigger than 3, *n*³ grows faster than *n*² once *n* \> 20/3.

</CheckQuestion>

<CheckQuestion question={<>Big-O of 3 log <em>n</em> + 5?</>}>

O(log *n*).

</CheckQuestion>

<CheckQuestion question={<>Write an algorithm for the average of <em>n</em> numbers, and give its Big-O.</>}>

```java title="Average.java"
public static double average(int[] a) {   // n = a.length
    double total = 0;                     // 1
    for (int i = 0; i < a.length; i++) {  // 1 + (n + 1) + n
        total += a[i];                    // n
    }
    return total / a.length;              // 1
}
// T(n) = 3n + 4 → O(n)
```

</CheckQuestion>

<CheckQuestion question={<>Print every character of a String of length <em>n</em>: Big-O?</>}>

One loop over the characters, each print constant: `for (int i = 0; i < s.length(); i++) System.out.println(s.charAt(i));` → O(*n*).

</CheckQuestion>

<CheckQuestion question={<>An iterative algorithm for <em>n</em>!: Big-O?</>}>

`long f = 1; for (int i = 2; i <= n; i++) f *= i; return f;` The loop runs *n* − 1 times → O(*n*).

</CheckQuestion>

<CheckQuestion question={<>Count T(<em>n</em>) for: <code>for (int i = 0; i &lt; n; i++) for (int j = 0; j &lt; n; j++) count++;</code></>}>

Outer: init 1, condition *n* + 1, update *n*. Inner (all together): init *n*, condition *n*(*n* + 1), update *n*², body *n*². Total = 1 + (*n*+1) + *n* + *n* + (*n*² + *n*) + *n*² + *n*² = 3*n*² + 4*n* + 2 → O(*n*²).

</CheckQuestion>

</CheckQuestions>

<Callout type="key">

Count each line: how many times × its constant. Sequence → add. if/else → condition + the bigger branch. Loop condition → *n* + 1, loop body → *n*, nested body → *n*². Then keep the dominant term and drop coefficients for Big-O.

</Callout>
