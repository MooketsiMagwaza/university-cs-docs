## 1. How to earn the marks

| Command word | What the marker wants |
|---|---|
| Determine / derive | The T(n) written in full from a table of the lines, each with its constant and how many times it runs, then the Big-O with the dominant term named |

## 2. Simplifying to Big-O

### Exam question 1: the lecture's Big-Oh exercise (6 marks)

Determine the Big-Oh of each of these growth rates: (a) 7n − 2, (b) 3n³ + 20n² + 5, (c) 3 log n + 5. For (b), say why the coefficient 20 does not make n² the dominant term. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Determine" asks for a Big-Oh with the working. The rules from the lecture: focus on the dominant term, drop constants, coefficients and lower-order terms. Part (b) asks for a reason as well.

</Step>

<Step title="2. Plan">

For each expression list its terms, rank them by growth (1, log n, n, n log n, n², n³) and keep the highest. For (b), find the value of `n` from which 3n³ is larger than 20n².

</Step>

<Step title="3. Solution">

(a) The terms are 7n and a constant. 7n dominates, so the Big-Oh is **O(n)**. (b) The terms are 3n³, 20n² and a constant. n³ grows faster than n², so the dominant term is 3n³ and the Big-Oh is **O(n³)**. (c) The terms are 3 log n and a constant. The Big-Oh is **O(log n)**.

```java title="CrossOver.java"
public class CrossOver {
    // Question: from which n is 3n^3 larger than 20n^2?
    public static void main(String[] args) {
        for (long n = 1; n <= 10; n++) {
            long cubic = 3 * n * n * n;
            long quadratic = 20 * n * n;
            System.out.println("n = " + n + ": 3n^3 = " + cubic + ", 20n^2 = " + quadratic + ", 3n^3 larger: " + (cubic > quadratic));
        }
    }
}
```

```text
n = 2: 3n^3 = 24, 20n^2 = 80, 3n^3 larger: false
n = 3: 3n^3 = 81, 20n^2 = 180, 3n^3 larger: false
n = 4: 3n^3 = 192, 20n^2 = 320, 3n^3 larger: false
n = 5: 3n^3 = 375, 20n^2 = 500, 3n^3 larger: false
n = 6: 3n^3 = 648, 20n^2 = 720, 3n^3 larger: false
n = 7: 3n^3 = 1029, 20n^2 = 980, 3n^3 larger: true
n = 8: 3n^3 = 1536, 20n^2 = 1280, 3n^3 larger: true
n = 9: 3n^3 = 2187, 20n^2 = 1620, 3n^3 larger: true
n = 10: 3n^3 = 3000, 20n^2 = 2000, 3n^3 larger: true
```

</Step>

<Step title="4. Check">

For small `n` the term 20n² is larger (n = 6: 720 against 648). From `n = 7` the cubic term is larger (1029 against 980) and the gap keeps widening, so for large `n` the coefficient 20 does not matter. Big-Oh describes large `n`, which is why the answer to (b) is O(n³).

</Step>

## 3. Deriving an algorithm and its time complexity

The lecture's second exercise slide asks for the time complexity, in Big-O, of three algorithms, with the note "derive the algorithms first". Each answer below writes the algorithm, counts its steps with every constant set to 1, and checks the count for three sizes of input.

### Exam question 3: the average of n numbers (6 marks)

Write an algorithm that determines the average of `n` numbers held in an array, and derive its time complexity in Big-O. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Write" and "derive": the algorithm comes first, then the count. The input size is `n`, the number of elements.

</Step>

<Step title="2. Plan">

Add every element to a total with one loop, then divide by `n`. Count each line: the declaration, the loop header (initialisation once, condition `n + 1`, update `n`), the body `n`, and the return.

</Step>

<Step title="3. Solution">

| Line | Times | Steps |
|---|---|---|
| `double total = 0;` | 1 | 1 |
| `int i = 0` | 1 | 1 |
| `i < a.length` | n + 1 | n + 1 |
| `i++` | n | n |
| `total += a[i];` | n | n |
| `return total / a.length;` | 1 | 1 |

T(n) = 1 + 1 + (n + 1) + n + n + 1 = 3n + 4, which is **O(n)**.

```java title="AverageSteps.java"
public class AverageSteps {
    // Question: the average of n numbers, with the steps counted.
    static int steps;

    static boolean check(boolean condition) {
        steps++;
        return condition;
    }

    static double average(int[] a) {
        steps = 0;
        steps++;
        double total = 0;                     // 1
        steps++;                              // the initialisation i = 0, once
        for (int i = 0; check(i < a.length); i++, steps++) {   // condition n + 1, update n
            steps++;
            total += a[i];                    // n
        }
        steps++;                              // the return
        return total / a.length;
    }

    public static void main(String[] args) {
        System.out.println("average of 10, 20, 30: " + average(new int[] {10, 20, 30}));
        int[] sizes = {10, 100, 1000};
        for (int n : sizes) {
            average(new int[n]);
            System.out.println("n = " + n + ": T(n) = " + steps + ", 3n + 4 = " + (3 * n + 4));
        }
    }
}
```

```text
average of 10, 20, 30: 20.0
n = 10: T(n) = 34, 3n + 4 = 34
n = 100: T(n) = 304, 3n + 4 = 304
n = 1000: T(n) = 3004, 3n + 4 = 3004
```

</Step>

<Step title="4. Check">

The counted T(n) equals 3n + 4 for all three sizes. Multiplying `n` by 10 multiplies T(n) by almost 10, which is the signature of linear growth: **O(n)**.

</Step>

</Steps>

</details>

### Exam question 4: print the characters of a string (5 marks)

Write an algorithm that prints all the characters in a string of length `n`, and derive its time complexity in Big-O. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The input size is the length `n` of the string. One print per character is the work.

</Step>

<Step title="2. Plan">

A loop from 0 to `n - 1` that prints `s.charAt(i)`. Count the loop header and the body.

</Step>

<Step title="3. Solution">

```java title="PrintCharsSteps.java"
public class PrintCharsSteps {
    // Question: print every character of a string of length n, with the steps counted.
    static int steps;

    static boolean check(boolean condition) {
        steps++;
        return condition;
    }

    static void printChars(String s) {
        steps = 0;
        steps++;                              // the initialisation i = 0, once
        for (int i = 0; check(i < s.length()); i++, steps++) {   // condition n + 1, update n
            steps++;
            System.out.print(s.charAt(i));    // n prints
        }
        System.out.println();
    }

    public static void main(String[] args) {
        printChars("Naledi");
        System.out.println("steps for 6 characters: " + steps);
        int[] sizes = {10, 100, 1000};
        for (int n : sizes) {
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) {
                sb.append('x');
            }
            java.io.PrintStream out = System.out;
            System.setOut(new java.io.PrintStream(new java.io.ByteArrayOutputStream()));
            printChars(sb.toString());
            System.setOut(out);
            System.out.println("n = " + n + ": T(n) = " + steps + ", 3n + 2 = " + (3 * n + 2));
        }
    }
}
```

```text
Naledi
steps for 6 characters: 20
n = 10: T(n) = 32, 3n + 2 = 32
n = 100: T(n) = 302, 3n + 2 = 302
n = 1000: T(n) = 3002, 3n + 2 = 3002
```

T(n) = 1 + (n + 1) + n + n = 3n + 2, which is **O(n)**.

</Step>

<Step title="4. Check">

For the 6 characters of `Naledi` the count is 20, which is 3 x 6 + 2, and the three larger sizes agree with 3n + 2. One loop, one print per character, constant work in the body: linear.

</Step>

</Steps>

### Exam question 5: an iterative algorithm for n! (5 marks)

Write an iterative algorithm that computes `n!` and derive its time complexity in Big-O. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Iterative" means a loop, not recursion. The input size is `n`, the number whose factorial is computed.

</Step>

<Step title="2. Plan">

Start the product at 1 and multiply it by 2, 3, ..., `n`. The loop runs `n - 1` times.

</Step>

<Step title="3. Solution">

```java title="FactorialSteps.java"
public class FactorialSteps {
    // Question: an iterative n!, with the steps counted (n at least 1).
    static int steps;

    static boolean check(boolean condition) {
        steps++;
        return condition;
    }

    static long factorial(int n) {
        steps = 0;
        steps++;
        long f = 1;                           // 1
        steps++;                              // the initialisation i = 2, once
        for (int i = 2; check(i <= n); i++, steps++) {   // condition n, update n - 1
            steps++;
            f = f * i;                        // n - 1
        }
        steps++;                              // the return
        return f;
    }

    public static void main(String[] args) {
        System.out.println("5! = " + factorial(5));
        int[] sizes = {10, 100, 1000};
        for (int n : sizes) {
            factorial(n);
            System.out.println("n = " + n + ": T(n) = " + steps + ", 3n + 1 = " + (3 * n + 1));
        }
    }
}
```

```text
5! = 120
n = 10: T(n) = 31, 3n + 1 = 31
n = 100: T(n) = 301, 3n + 1 = 301
n = 1000: T(n) = 3001, 3n + 1 = 3001
```

T(n) = 1 + 1 + n + (n − 1) + (n − 1) + 1 = 3n + 1, which is **O(n)**.

</Step>

<Step title="4. Check">

The condition `i <= n` is checked for `i` = 2, ..., `n + 1`, which is `n` checks, one more than the `n - 1` passes. The program's count equals 3n + 1 at each size. The algorithm is linear in `n`, the same order as the average and the string printer. (The factorial value itself overflows a `long` beyond 20, but the number of steps does not depend on that.)

</Step>

</Steps>

</details>

## 4. Counting T(n) for given code

### Exam question 6: a selection inside a loop (5 marks)

Determine T(n), with every constant set to 1, for the code below and give its Big-O. (5 marks)

```java
for (int i = 1; i <= n; i++) {
    if (i % 2 == 0)
        evens++;
    else
        odds++;
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A selection inside a repetition: apply the loop rule to the body, and the selection rule inside the body. The two branches cost the same, so the larger branch is one statement either way.

</Step>

<Step title="2. Plan">

Count the loop header (initialisation 1, condition `n + 1`, update `n`), then per pass the condition of the `if` (1) plus one branch (1).

</Step>

<Step title="3. Solution">

T(n) = 1 + (n + 1) + n + n(1 + 1) = 4n + 2, which is **O(n)**.

```java title="SelectionInLoop.java"
public class SelectionInLoop {
    // Question: count the steps of a loop with an if/else in its body.
    static int steps;

    static boolean check(boolean condition) {
        steps++;
        return condition;
    }

    static int count(int n) {
        steps = 0;
        int evens = 0;
        int odds = 0;
        steps++;                              // the initialisation i = 1, once
        for (int i = 1; check(i <= n); i++, steps++) {
            if (check(i % 2 == 0)) {          // the condition of the if: n times
                steps++;
                evens++;                      // one branch: 1 step
            } else {
                steps++;
                odds++;
            }
        }
        return steps;
    }

    public static void main(String[] args) {
        System.out.println(count(10));
        System.out.println(count(100));
    }
}
```

```text
42
402
```

</Step>

<Step title="4. Check">

For `n = 10` the count is 42 = 4 x 10 + 2 and for `n = 100` it is 402. The branch taken changes between passes, but each costs one step, so the larger branch is the same as either.

</Step>

</Steps>

</details>

### Exam question 7: a nested loop with a constant inner bound (6 marks)

Determine T(n), with every constant set to 1, for the code below, and give its Big-O. Explain why it is not O(n²). (6 marks)

```java
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= 5; j++) {
        x++;
    }
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

It is a nested repetition, but the inner loop does not depend on `n`: it always runs 5 times. The nested rule multiplies the number of times each loop runs, so the inner loop contributes a factor 5, not `n`.

</Step>

<Step title="2. Plan">

Outer header: 1, `n + 1`, `n`. Inner header, once per outer pass: initialisation 1, condition 6, update 5. Inner body: 5 per outer pass.

</Step>

<Step title="3. Solution">

T(n) = 1 + (n + 1) + n + n(1 + 6 + 5 + 5) = 1 + n + 1 + n + 17n = 19n + 2, which is **O(n)**.

```java title="ConstantInner.java"
public class ConstantInner {
    // Question: a nested loop whose inner loop runs 5 times, with the steps counted.
    static int steps;

    static boolean check(boolean condition) {
        steps++;
        return condition;
    }

    static int count(int n) {
        steps = 0;
        int x = 0;
        steps++;                              // outer initialisation, once
        for (int i = 1; check(i <= n); i++, steps++) {
            steps++;                          // inner initialisation, n times
            for (int j = 1; check(j <= 5); j++, steps++) {
                steps++;
                x++;                          // the body, 5n times
            }
        }
        return steps;
    }

    public static void main(String[] args) {
        System.out.println(count(10));
        System.out.println(count(100));
        System.out.println(count(1000));
    }
}
```

```text
192
1902
19002
```

</Step>

<Step title="4. Check">

The program gives 192, 1902 and 19002, which are 19n + 2 for `n` = 10, 100 and 1000. Multiplying `n` by 10 multiplies the steps by about 10, not 100, so it is linear. It is not O(n²) because only one of the two loops depends on `n`.

</Step>

</Steps>

</details>

### Exam question 8: where does the quadratic overtake the linear? (5 marks)

Algorithm X takes 5n + 20 steps and algorithm Y takes n² steps. For which values of `n` is Y slower than X? Which is better for large inputs, and why? (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

X has a linear growth rate and Y a quadratic one. Y is slower when its step count is larger. Find the smallest `n` for which n² exceeds 5n + 20.

</Step>

<Step title="2. Plan">

Evaluate both for `n` = 1, 2, 3 ... until Y is larger, and check that it stays larger.

</Step>

<Step title="3. Solution">

```java title="Overtake.java"
public class Overtake {
    // Question: from which n does Y = n^2 take more steps than X = 5n + 20?
    public static void main(String[] args) {
        for (int n = 5; n <= 12; n++) {
            int x = 5 * n + 20;
            int y = n * n;
            System.out.println("n = " + n + ": X = " + x + ", Y = " + y + ", Y slower: " + (y > x));
        }
    }
}
```

```text
n = 5: X = 45, Y = 25, Y slower: false
n = 6: X = 50, Y = 36, Y slower: false
n = 7: X = 55, Y = 49, Y slower: false
n = 8: X = 60, Y = 64, Y slower: true
n = 9: X = 65, Y = 81, Y slower: true
n = 10: X = 70, Y = 100, Y slower: true
n = 11: X = 75, Y = 121, Y slower: true
n = 12: X = 80, Y = 144, Y slower: true
```

</Step>

<Step title="4. Check">

Y is faster up to `n = 7` (49 against 55) and slower from `n = 8` (64 against 60), and the gap grows after that. For large inputs X is better: its time is proportional to `n` while Y's is proportional to n², so Y falls further behind each time `n` grows. For small inputs the constants decide, which is why algorithms are compared by their growth rate.

## 6. Explaining the method

### Exam question 9: experimentation and the methodological approach (6 marks)

Describe the two options for comparing two algorithms that solve the same problem, give the limitations of the first, and say why the second is preferred. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two options, the limitations of the first, and a preference. The lecture's headings are "Option 1: Experimentation" and "Option 2: Methodological approach".

</Step>

<Step title="2. Plan">

Describe each option in a sentence or two, list the limitations as separate short points, then state what the second option gives that the first cannot.

</Step>

<Step title="3. Solution">

**Option 1, experimentation.** Implement both algorithms (for example in Java), run the two programs on identical data sets of different sizes `n`, record each runtime several times (for example with `System.currentTimeMillis()`), compute the averages and compare them: the shorter, the better. The results can be plotted on a graph.

**Limitations.** The algorithms must be implemented first. The same environment (hardware and software) is needed for both. The results may not hold for all data sets, because experiments use limited input sets, so an algorithm may be less efficient on data not tested. Other factors affect the runtime: whether the hardware is representative, and programming style.

**Option 2, the methodological approach.** Ignore specific running time and use mathematical techniques to estimate complexity. No implementation is needed. The runtime is defined as a function of the input size `n`, based on the number of primitive operations in the algorithm (pseudo code or a program), and expressed in a standard notation (Big-O).

</Step>

<Step title="4. Check">

The preference follows from the limitations: the methodological approach is independent of the hardware and of the data set, which the lecture says a good analysis must be, and it focuses on how the algorithm scales as `n` grows.

</Step>

</Steps>

</details>

### Exam question 11: best, average and worst case (5 marks)

## 7. Errors to check before handing in

- `T(n)` is written in full from a table of the lines before the Big-O.
- The loop condition is counted `n + 1` times and the body `n` times.
- Loops one after another are added; loops inside each other are multiplied; a loop whose bound does not depend on `n` contributes a constant factor.
- The Big-O keeps the dominant term and drops its coefficient and the lower-order terms, and never includes a constant.
- A selection counts the condition plus the larger branch.
- The algorithm is written first when the question says to derive it.

## Summary

<Callout type="key" title="Remember">

Write the algorithm, count each line (condition `n + 1`, body `n`), add T(n), then keep the dominant term. The average of `n` numbers, printing a string of length `n` and an iterative `n!` are all O(n). A nested loop is O(n²) only when both bounds depend on `n`. Rank the orders as 1, log n, n, n log n, n², n³, 2ⁿ, n!. Experiments depend on the hardware and the data; counting primitive operations does not. The worst case is quoted because it is a guarantee.

</Callout>

<CheckQuestion question="The factorial loop starts at 2 and runs to n. Why is its T(n) 3n + 1 and not 3n + 2?">

The loop body and the update run `n - 1` times, not `n`, because the counter starts at 2. The condition is checked `n` times, so the total is 1 + 1 + n + (n - 1) + (n - 1) + 1 = 3n + 1. The Big-O is the same: O(n).
