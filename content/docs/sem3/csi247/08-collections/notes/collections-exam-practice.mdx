## 1. How to answer these questions

1. **Read.** Underline the command words: *trace*, *draw*, *write*, *explain*, *what happens*.
2. **Plan.** Name the structure and the operation (an array, an `ArrayList`, a `LinkedList`, an iterator). Say what each operation changes.

## 2. Lab 8, question 1: Person, ArrayList, file input and sort

<Steps title="Answering the question">

<Step title="1. Read the question">

</Step>

<Step title="2. Plan">

`Person` needs a constructor, `compareTo` that returns `fullname.compareTo(other.fullname)`, `toString` and `equals` (with `instanceof` and a cast). The tester splits each line at the commas, converts the `id` and `age` with `Integer.parseInt`, and adds each `Person` to the list. `people.remove(2)` removes the third record and shifts the later ones left. The list has 6 items, so index 8 does not exist.

</Step>

<Step title="3. Solution">

```java title="Person.java"
public class Person implements Comparable<Person> {
    private int id;
    private String fullname;
    private int age;

    Person(int id, String fullname, int age) {
        this.id = id;
        this.fullname = fullname;
        this.age = age;
    }

    int getId() {
        return id;
    }

    String getFullname() {
        return fullname;
    }

    int getAge() {
        return age;
    }

    public int compareTo(Person other) {
        return fullname.compareTo(other.fullname);      // the order is by fullname
    }

    public String toString() {
        return id + " " + fullname + " (" + age + ")";
    }

    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }
        if (!(obj instanceof Person)) {
            return false;
        }
        Person other = (Person) obj;
        return id == other.id && fullname.equals(other.fullname) && age == other.age;
    }
}
```

## 4. Memory: an array of Integer and an ArrayList copy

### Exam question 3: array, ArrayList and shared objects (8 marks)

Draw the state of memory after this code, and state whether `list.get(0)` and `marks[0]` refer to the same object. (8 marks)

```java
Integer[] marks = new Integer[4];
marks[0] = 73;  marks[1] = 81;  marks[2] = 69;  marks[3] = 60;
ArrayList<Integer> list = new ArrayList<Integer>(Arrays.asList(marks));
list.add(70);
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Four assignments to an array, then a list built from the array and one `add`. The drawing must show where each Integer lives and what the list copied.

</Step>

<Step title="2. Plan">

`new Integer[4]` makes an array of four references, all `null`. Each assignment autoboxes an `int` into an `Integer` object and stores its address. `new ArrayList<Integer>(Arrays.asList(marks))` makes a **new** hidden array and copies the **references**; the Integer objects are not copied. `add(70)` adds a fifth reference.

</Step>

<Step title="3. Solution">

Stack: `marks` holds the address of the `Integer[]` (100); `list` holds the address of the `ArrayList` object (say 600). Heap: the `Integer[]` at 100 holds four addresses, 200, 300, 400 and 500, which are the four `Integer` objects 73, 81, 69 and 60. The `ArrayList` object has `size` 5 and an `elementData` field pointing at its own hidden array, whose first four cells hold the same addresses 200, 300, 400 and 500, and whose fifth cell holds the address of a new `Integer` 70 object. So there are two arrays and five `Integer` objects. `list.get(0)` and `marks[0]` hold the same address (200): the same object.

</Step>

<Step title="4. Check">

```java title="SharedObjects.java"
import java.util.ArrayList;
import java.util.Arrays;

public class SharedObjects {
    public static void main(String[] args) {
        Integer[] marks = new Integer[4];
        marks[0] = 73;
        marks[1] = 81;
        marks[2] = 69;
        marks[3] = 60;
        ArrayList<Integer> list = new ArrayList<Integer>(Arrays.asList(marks));
        list.add(70);

        System.out.println(list + " " + marks.length);
        System.out.println(list.get(0) == marks[0]);
        System.out.println(list.get(3) == marks[3]);
        marks[0] = 5;                                     // a new Integer replaces the reference in the array only
        System.out.println(list.get(0) + " " + marks[0]);
    }
}
```

```text
[73, 81, 69, 60, 70] 4
true
true
73 5
```

The two containers hold the same objects, so `==` is `true`. Replacing `marks[0]` changes the array's reference only: the list still holds the old 73. Changing one array does not change the other because the list has its own hidden array.

</Step>

</Steps>

</details>

## 6. Write an iterator loop

### Exam question 5: remove failing marks (6 marks)

Write a method `removeBelow(ArrayList<Integer> marks, int pass)` that removes every mark below `pass` using an `Iterator` and returns how many it removed. Show it on `[73, 45, 90, 38, 50, 61]` with pass mark 50. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A method, an iterator, a removal and a count. The list must be changed while it is traversed, so the removal must go through the iterator.

</Step>

<Step title="2. Plan">

Create `Iterator<Integer> it = marks.iterator()`. In a `while (it.hasNext())` loop call `next()` once, test the value, and call `it.remove()` and add 1 to the count when it is below `pass`.

</Step>

<Step title="3. Solution">

```java title="FailedMarks.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Iterator;

public class FailedMarks {
    static int removeBelow(ArrayList<Integer> marks, int pass) {
        int removed = 0;
        Iterator<Integer> it = marks.iterator();
        while (it.hasNext()) {
            int mark = it.next();                   // one next() per hasNext()
            if (mark < pass) {
                it.remove();                        // removes the mark just returned
                removed++;
            }
        }
        return removed;
    }

    public static void main(String[] args) {
        ArrayList<Integer> marks = new ArrayList<Integer>(Arrays.asList(73, 45, 90, 38, 50, 61));
        int count = removeBelow(marks, 50);
        System.out.println(count + " removed, left " + marks);
    }
}
```

```text
2 removed, left [73, 90, 50, 61]
```

</Step>

<Step title="4. Check">

45 and 38 are below 50, so two are removed, and 50 stays because the test is "below". Each pass of the loop calls `next()` once and `remove()` at most once after it. A for-each loop with `marks.remove(...)` would throw `ConcurrentModificationException`.

</Step>

</Steps>

</details>

## 7. Make a class Comparable on two keys

### Exam question 6: age, then name (8 marks)

A `Member` has a `name` and an `age`. Write `compareTo` so that members are sorted by age, and members of the same age are sorted alphabetically by name. Show the result for Thato 30, Kago 25, Neo 30, Amo 25. (8 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two keys: the first decides the order, the second breaks ties. The result is a sorted list.

</Step>

<Step title="2. Plan">

Compare the ages first and return a negative or positive number if they differ. Only when they are equal, return the result of `name.compareTo(other.name)`. Returning 0 only when both match keeps `compareTo` consistent with `equals`.

</Step>

<Step title="3. Solution">

```java title="Member.java"
public class Member implements Comparable<Member> {
    String name;
    int age;

    Member(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public int compareTo(Member other) {
        if (age != other.age) {
            return age < other.age ? -1 : 1;           // the first key
        }
        return name.compareTo(other.name);             // equal ages: the second key
    }

    public String toString() {
        return name + " " + age;
    }
}
```

```java title="MemberSort.java"
import java.util.ArrayList;
import java.util.Collections;

public class MemberSort {
    public static void main(String[] args) {
        ArrayList<Member> list = new ArrayList<Member>();
        list.add(new Member("Thato", 30));
        list.add(new Member("Kago", 25));
        list.add(new Member("Neo", 30));
        list.add(new Member("Amo", 25));
        Collections.sort(list);
        System.out.println(list);
    }
}
```

```text
[Amo 25, Kago 25, Neo 30, Thato 30]
```

</Step>

<Step title="4. Check">

The two 25-year-olds come first, Amo before Kago; then the two 30-year-olds, Neo before Thato. If `compareTo` returned 0 whenever the ages matched, the order of the tied members would stay as they were added.

</Step>

</Steps>

## 8. Compare the structures

### Exam question 7: array, ArrayList and LinkedList (6 marks)

Compare an array, an `ArrayList` and a `LinkedList` on: whether the size can change, how an element is reached, and the cost of inserting at the front. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Three structures and three points of comparison: nine facts, so a table is the natural answer.

</Step>

<Step title="2. Plan">

Use the lecture's wording: an array has a static size and contiguous memory; an `ArrayList` is a dynamic array that creates a larger array and copies when full; a `LinkedList` is a list of nodes reached from the head.

</Step>

<Step title="3. Solution">

| | Array | `ArrayList` | `LinkedList` |
|---|---|---|---|
| Size | fixed when created | grows and shrinks (a new, larger array and a copy when full) | grows and shrinks node by node |
| Reaching an element | directly by index, `A[i]` | directly: `get(i)` and `set(i, e)` | start at the head and follow links; no direct access |
| Insert at the front | not possible without a bigger array and copying | shifts every element one place right | only links change |

</Step>

<Step title="4. Check">

Each cell comes from the lecture's list of efficient and inefficient methods: `get`, `set` and `add` at the end are efficient for an `ArrayList`; `add(index, ...)` and `remove(index)` shift elements, which is why the lecture moves to a linked structure.

</Step>

</Steps>

## 9. A mixed trace

### Exam question 8: array, view, list and iterator (8 marks)

Give the exact output of this program and explain the last line. (8 marks)

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.Iterator;
import java.util.List;

public class MixedTrace {
    public static void main(String[] args) {
        Integer[] raw = {40, 15, 33, 8};
        List<Integer> view = Arrays.asList(raw);
        ArrayList<Integer> list = new ArrayList<Integer>(view);
        list.add(0, 21);
        list.remove(Integer.valueOf(33));
        Collections.sort(list);

        Iterator<Integer> it = list.iterator();
        int sum = 0;
        while (it.hasNext()) {
            int v = it.next();
            if (v % 2 == 1) {
                it.remove();
            } else {
                sum += v;
            }
        }
        System.out.println(list + " sum " + sum);

        Arrays.sort(raw);
        System.out.println(Arrays.toString(raw) + " " + view);
    }
}
```

<CheckQuestion question="In the Lab 8 sorted output, why is Amo Seretse before Kagiso Moeng although the file lists Kagiso first?">

`Person.compareTo` compares `fullname`, and `Collections.sort` orders by it, so the order is alphabetical by name, not the order in the file.

<CheckQuestion question="After new ArrayList(Arrays.asList(marks)), do the list and the array share the Integer objects?">

Yes. The constructor copies the references into the list's own hidden array, so `list.get(0) == marks[0]` is `true`. The two arrays are separate: replacing `marks[0]` does not change the list.

</CheckQuestion>

<CheckQuestion question="Why can a list be changed through an iterator but not inside a for-each loop?">

The for-each loop uses an iterator privately. Changing the list directly makes that iterator detect a modification and throw `ConcurrentModificationException`; `Iterator.remove()` updates the list and the iterator together.

</CheckQuestion>

<CheckQuestion question="How does compareTo order objects by two keys?">

Compare the first key; if the objects differ on it, return the result. Only when they are equal on the first key, return the comparison of the second key.

</CheckQuestion>
