
A **collection** is an object that groups many related items into one unit. The only collection met so far is the array. The framework (in `java.util`) is made of interfaces and classes: `Iterable` is the root interface (it permits traversal), `Collection` extends it and is implemented through its sub-interfaces `List`, `Set` and `Queue`, and the classes are `ArrayList` and `LinkedList` (a `List`), `LinkedList` and `ArrayDeque` (a `Queue`) and `HashSet` and `TreeSet` (a `Set`). Interfaces such as these are called **abstract data types**: a type's logical form, the data and the operations on it.

## 2. The Arrays class

`Arrays` is a utility class in `java.util` whose static methods support array operations: creating, searching, sorting, comparing and converting to a `String`. The syntax is `Arrays.methodName(...)`. This is the lecture's program:

```java title="ArraysSort.java"
import java.util.Arrays;

public class ArraysSort {
    // Question (Lecture 13): sort an array of Integer objects.
    public static void main(String[] args) {
        Integer[] arr = {73, 64, 59, 15, 91, 27, 82};

        Arrays.sort(arr);
        System.out.println("Integer Array is: " + Arrays.toString(arr));
    }
}
```

```text
Integer Array is: [15, 27, 59, 64, 73, 82, 91]
```

`Arrays.sort(arr)` sorts in ascending order by default and needs no loop. `Arrays.toString(arr)` returns the array's `String` representation, like the `toString` of `Object`, `Shape` and `Account`. The lecture lists what the methods save you from writing: `sort` works for primitives (an adaptation of quick sort) and for arrays of objects (an adaptation of merge sort, called Timsort), in time `O(n log n)`; `binarySearch` runs in `O(log n)`.

### The same methods with other arrays

```java title="ArraysVariants.java"
import java.util.Arrays;

public class ArraysVariants {
    // Question: sort an int array and a String array, and search a sorted array.
    public static void main(String[] args) {
        int[] scores = {82, 47, 91, 15};
        Arrays.sort(scores);
        System.out.println(Arrays.toString(scores));

        String[] words = {"pear", "Apple", "banana", "apple"};
        Arrays.sort(words);
        System.out.println(Arrays.toString(words));

        int[] sorted = {15, 27, 59, 64, 73, 82, 91};
        System.out.println(Arrays.binarySearch(sorted, 64));    // found
        System.out.println(Arrays.binarySearch(sorted, 60));    // not found, would go at index 3
        System.out.println(Arrays.binarySearch(sorted, 5));     // would go at index 0
        System.out.println(Arrays.binarySearch(sorted, 100));   // would go at index 7

        Integer[] arr = {3, 1, 2};
        System.out.println(arr.toString().startsWith("[Ljava.lang.Integer;@"));
    }
}
```

```text
[15, 47, 82, 91]
[Apple, apple, banana, pear]
3
-4
-1
-8
true
```

Three things to observe. The `String` array sorts by the Unicode values of the characters, so every uppercase letter comes before every lowercase letter: `Apple` is before `apple`, and `apple` before `banana`. `binarySearch` needs a sorted array: it returns the index when it finds the value (64 is at index 3), and otherwise `-(insertion point) - 1`, a negative number: 60 would go at index 3, giving -4. And printing an array directly does not show its elements: `arr.toString()` is the type and an address, which is why `Arrays.toString` is used.

<Callout type="mistake" title="Common error">

Printing an array with `System.out.println(arr)`. The output is the type code and a hash such as `[Ljava.lang.Integer;@...`, not the elements. Use `Arrays.toString(arr)`.

</Callout>

`marks = myList.toArray(marks)` has to assign the result back: the array `marks` has 4 cells but the list now has 5 elements, so `toArray` allocates a new array of the right size and returns it. The next program shows the details that explain the code.

```java title="ListArrayLinks.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class ListArrayLinks {
    // Question: why does the slide copy the array into a new ArrayList instead of using Arrays.asList directly?
    public static void main(String[] args) {
        Integer[] arr = {73, 81, 69, 60};
        List<Integer> view = Arrays.asList(arr);

        try {
            view.add(70);
        } catch (UnsupportedOperationException e) {
            System.out.println("add on Arrays.asList: " + e.getClass().getName());
        }
        view.set(0, 1);
        System.out.println("array after view.set(0, 1): " + Arrays.toString(arr));

        ArrayList<Integer> copy = new ArrayList<Integer>(view);
        copy.add(70);
        Integer[] small = copy.toArray(arr);          // arr has 4 cells, the list has 5 elements
        System.out.println("into the 4-cell array: same array? " + (small == arr) + " " + Arrays.toString(small));
        Integer[] exact = new Integer[5];
        System.out.println("into a 5-cell array: same array? " + (copy.toArray(exact) == exact));
    }
}
```

```text
add on Arrays.asList: java.lang.UnsupportedOperationException
array after view.set(0, 1): [1, 81, 69, 60]
into the 4-cell array: same array? false [1, 81, 69, 60, 70]
into a 5-cell array: same array? true
```

`Arrays.asList(arr)` is a fixed-size list that is a view of the array: `set` writes through to the array and `add` is not allowed (`UnsupportedOperationException`). Copying it into `new ArrayList<Integer>(...)` gives a list that can grow. `toArray(a)` fills `a` itself only when `a` is large enough; otherwise it returns a new array, which is why the result must be assigned.

<Callout type="mistake" title="Common error">

Calling `myList.toArray(marks)` and ignoring the result. When the array is too small the returned array is a different object, and `marks` still holds the old four cells.

</Callout>

## 4. Iterating through a collection

The lecture gives three ways to move through a collection. The standard loop and the `while` loop both state **how to move** from one element to the next. The for-each loop does not: it uses an `Iterator` privately. The third way, the `Iterator` itself, is needed because the collections are not indexed: you cannot write `list[0]`.

```java title="IterationWays.java"
import java.util.ArrayList;
import java.util.Iterator;

public class IterationWays {
    // Question (Lecture 13): visit each element of an array and of an ArrayList in the three ways.
    public static void main(String[] args) {
        int[] grades = {85, 12, 69, 74, 48, 52};

        for (int i = 0; i < grades.length; i++) {      // a) the standard way
            System.out.print(grades[i] + " ");
        }
        System.out.println();

        int count = 0;                                  // a) with a while loop
        while (count < grades.length) {
            System.out.print(grades[count] + " ");
            count += 1;
        }
        System.out.println();

        for (int mark : grades) {                       // b) for-each
            System.out.print("[ " + mark + " ]");
        }
        System.out.println();

        ArrayList<Integer> nums = new ArrayList<Integer>();
        nums.add(73);
        nums.add(92);
        nums.add(58);
        nums.add(60);
        Iterator<Integer> iterate = nums.iterator();    // c) an Iterator
        while (iterate.hasNext()) {
            System.out.print(iterate.next() + ", ");
        }
        System.out.println();
    }
}
```

```text
85 12 69 74 48 52
85 12 69 74 48 52
[ 85 ][ 12 ][ 69 ][ 74 ][ 48 ][ 52 ]
73, 92, 58, 60,
```

The `Iterator` interface (in `java.util`) offers `hasNext()` (is there a next element?), `next()` (return it and move on), `remove()` (remove the last element returned by `next`) and `forEachRemaining(action)`. An iterator **points between elements** and moves forward only. The lecture's picture is a list of 51, 35, 12, 81, 54, 16; read the first three elements, then call `remove()`.

<MemoryDiagram scenario="iterator" />

```java title="IteratorMoves.java"

    public static void main(String[] args) {

        Iterator<Integer> it = nums.iterator();

        System.out.println(it.next());
        System.out.println(it.next());

    }

```


The slide lists the values returned by the three calls as 81, 54 and 16, but the picture on the next slide removes 12, the third element. The three calls return 51, 35 and 12, as the run shows, and `remove()` then removes 12. The next call to `next()` returns 81.

### Iterator rules and mistakes

```java title="IteratorRules.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Iterator;

public class IteratorRules {
    // Question: what goes wrong when an iterator is misused, or when a list is changed inside a for-each loop?
    public static void main(String[] args) {
        ArrayList<Integer> nums = new ArrayList<Integer>(Arrays.asList(73, 92, 58, 60));

        Iterator<Integer> it = nums.iterator();
        while (it.hasNext()) {                // remove every even number through the iterator
            if (it.next() % 2 == 0) {
                it.remove();
            }
        }
        System.out.println("odd numbers left: " + nums);

        try {
            nums.iterator().remove();         // remove() before any next()
        } catch (IllegalStateException e) {
            System.out.println("remove before next: " + e.getClass().getName());
        }

        Iterator<Integer> two = new ArrayList<Integer>(Arrays.asList(1, 2, 3)).iterator();
        try {
            while (two.hasNext()) {
                two.next();
                two.next();                    // two next() calls for one hasNext()
            }
        } catch (java.util.NoSuchElementException e) {
            System.out.println("next past the end: " + e.getClass().getName());
        }

        ArrayList<Integer> four = new ArrayList<Integer>(Arrays.asList(73, 92, 58, 60));
        try {
            for (Integer n : four) {
                if (n == 92) {
                    four.remove(n);            // changes the list inside a for-each loop
                }
            }
        } catch (java.util.ConcurrentModificationException e) {
            System.out.println("remove inside for-each: " + e.getClass().getName() + ", list now " + four);
        }
    }
}
```

```text
odd numbers left: [73]
remove before next: java.lang.IllegalStateException
next past the end: java.util.NoSuchElementException
remove inside for-each: java.util.ConcurrentModificationException, list now [73, 58, 60]
```

`remove()` removes the last element returned by `next()`, so calling it before any `next()` throws `IllegalStateException`. Calling `next()` when there is no next element throws `NoSuchElementException`, so each `hasNext()` test should be followed by one `next()`. A for-each loop uses an iterator privately, so removing from the list directly inside the loop makes the iterator fail with `ConcurrentModificationException`; to remove while traversing, use `Iterator.remove()` as in the first loop.

<Callout type="mistake" title="Common error">

Removing from a list inside a for-each loop. It fails with `ConcurrentModificationException` (the list above shows 92 already gone), though a list of three elements with the second one removed would end quietly, because the loop's `hasNext()` is then false and `next()` is never asked. Do not rely on that: remove through the iterator.

</Callout>

### The lecture's exercise: names, characters and palindromes

The exercise reads 10 full names into `ArrayList<String> names`, then uses an `Iterator` to display each name, the number of characters in it and its first character, one per line; then it is changed to show only the palindromes with a method `palindrome()`. The names come from the keyboard in the exercise (`Scanner` with `nextLine()`); the program below stores the same ten names in an array so that it runs unattended.

```java title="NamesIterator.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Iterator;

public class NamesIterator {
    // Question (Lecture 13, exercise b): show each name with its length and first character, then only the palindromes.
    static boolean palindrome(String name) {
        String lower = name.toLowerCase();
        int i = 0;
        int j = lower.length() - 1;
        while (i < j) {
            if (lower.charAt(i) != lower.charAt(j)) {
                return false;
            }
            i++;
            j--;
        }
        return true;
    }

    public static void main(String[] args) {
        ArrayList<String> names = new ArrayList<String>(Arrays.asList(
                "Kago", "Anna", "Thato", "Otto", "Mpho", "Hannah", "Neo", "Bob", "Tebogo", "Lerato"));

        Iterator<String> it = names.iterator();
        while (it.hasNext()) {
            String name = it.next();
            System.out.println(name + ": " + name.length() + " characters, first " + name.charAt(0));
        }

        System.out.println("Palindromes:");
        Iterator<String> again = names.iterator();
        while (again.hasNext()) {
            String name = again.next();
            if (palindrome(name)) {
                System.out.println(name);
            }
        }
    }
}
```

```text

Mpho: 4 characters, first M

Neo: 3 characters, first N
```

The iterator is created again for the second pass because an iterator moves forward only and cannot be rewound. `palindrome` compares the first and last characters and works inwards, ignoring case.

## 5. The List interface and ArrayList

A **list** is a linear sequence that stores an ordered collection, normally adds at the end, can store duplicates and can add and remove elements at random locations. `List<E>` extends `Collection<E>`, and as an interface you cannot create a `List` object: a class must implement it, either an array implementation (`ArrayList`) or a linked implementation made of nodes. The lecture's abstract operations are `add(e)`, `add(i, e)` (others move right; careful with `IndexOutOfBoundsException`), `set(i, e)` (replaces and returns the old value), `get(i)`, `remove(i)` (removes and returns the element), `size()` and `isEmpty()`. This is the lecture's list code, in the order it is printed:

```java title="ListDemo.java"
import java.util.ArrayList;
import java.util.List;

public class ListDemo {
    // Question (Lecture 13): what do the List operations on the slide do?
    public static void main(String[] args) {
        List<Integer> marks = new ArrayList<Integer>();    // list created as an ArrayList
        marks.add(84);                                      // adds 84
        marks.add(62);                                      // adds 62
        System.out.println(marks);                          // print the contents

        marks.add(2, 73);                                   // the slide: error! Why?
        marks.add(73);                                      // the slide: allowed. Why?

        System.out.println(marks.size());                   // number of elements
        System.out.println(marks.isEmpty());                // is it empty?
        System.out.println(marks);
    }
}
```

```text
[84, 62]
4
false
[84, 62, 73, 73]
```

The slide marks `marks.add(2, 73)` as an error and `marks.add(73)` as allowed. Run in the order the slide shows, with two elements already in the list, both lines work: `add(i, e)` accepts any index from 0 up to and including `size()`, and index 2 is the position just after the last element, so `73` is added at the end. The exception appears when the index is beyond `size()`. The next program shows that, and the slide's other "error! Why?" line, `marks.remove(84)`.

```java title="ListErrors.java"
import java.util.ArrayList;
import java.util.List;

public class ListErrors {
    // Question (Lecture 13): when does add(i, e) fail, and why does marks.remove(84) fail?
    public static void main(String[] args) {
        List<Integer> marks = new ArrayList<Integer>();
        marks.add(84);
        marks.add(62);
        marks.add(73);
        marks.add(73);

        try {
            marks.add(9, 1);                               // index 9 is beyond size() = 4
        } catch (IndexOutOfBoundsException e) {
            System.out.println("add(9, 1): " + e.getClass().getName());
        }
        try {
            marks.remove(84);                              // 84 is an int, so this is remove(int index)
        } catch (IndexOutOfBoundsException e) {
            System.out.println("remove(84): " + e.getClass().getName());
        }
        marks.remove(Integer.valueOf(84));                 // remove the OBJECT 84
        System.out.println("after remove(Integer.valueOf(84)): " + marks);
    }
}
```

```text
add(9, 1): java.lang.IndexOutOfBoundsException
remove(84): java.lang.IndexOutOfBoundsException
after remove(Integer.valueOf(84)): [62, 73, 73]
```

`remove` is overloaded: `remove(int i)` removes the element at index `i` and `remove(E e)` removes the first occurrence of an object. The literal `84` is an `int`, so Java chooses the index version, and there is no index 84 in a list of four elements. `Integer.valueOf(84)` is an object, so it chooses the other version and removes the element 84.

<Callout type="mistake" title="Common error">

Writing `marks.remove(84)` to remove the value 84 from a list of `Integer`. It is read as an index and throws `IndexOutOfBoundsException`. Pass an object: `marks.remove(Integer.valueOf(84))`.

</Callout>

### ArrayList operations, one at a time

`ArrayList<E>` is the most widely used implementation of `List`: a generic class (`ArrayList<Dog>`, `ArrayList<String>`) that stores its elements in a dynamic array. Java adjusts the size, it grows when you add and shrinks when you remove, and the capacity need not be given (`new ArrayList<String>()`), though it may be (`new ArrayList<String>(20)`).

```java title="ArrayListOps.java"
import java.util.ArrayList;

public class ArrayListOps {
    // Question (Lecture 13): apply each ArrayList operation and say what it returns and what it does to the list.
    public static void main(String[] args) {
        ArrayList<String> names = new ArrayList<String>();
        names.add("Kago");
        names.add("Neo");
        names.add("Thato");
        System.out.println(names + " size " + names.size());

        names.add(1, "Lesego");                          // insert at index 1: the others move right
        System.out.println("add(1, Lesego): " + names);

        String old = names.set(2, "Mpho");               // replace index 2, return the old value
        System.out.println("set(2, Mpho) returned " + old + ": " + names);

        String gone = names.remove(0);                    // remove index 0, the others move left
        System.out.println("remove(0) returned " + gone + ": " + names);

        boolean removed = names.remove("Thato");          // remove the first occurrence of an object
        System.out.println("remove(Thato) returned " + removed + ": " + names);

        System.out.println("indexOf(Mpho) " + names.indexOf("Mpho") + ", indexOf(Zed) " + names.indexOf("Zed"));
        System.out.println("get(1) " + names.get(1));

        ArrayList<String> sized = new ArrayList<String>(20);
        System.out.println("capacity 20, size " + sized.size() + ", isEmpty " + sized.isEmpty());

        names.add("Mpho");                                // duplicates are allowed
        names.remove("Mpho");                             // only the first occurrence goes
        System.out.println(names);
    }
}
```

### Implementing a list with an array

The lecture's design for an array-based list: the array starts with some default capacity; to insert, check whether there is room; if there is, insert; if not, **create a new array twice as large as the current one, copy the elements across, and insert in the new array**. Some operations need no extra work (`get`, `set` and `add` at the end); `add(i, e)` and `remove(i)` involve **shifting** a potentially large number of elements. The class below counts both kinds of work.

```java title="DynamicArray.java"
public class DynamicArray {
    private int[] data = new int[2];     // default capacity 2, to keep the example short
    private int size = 0;
    int copies = 0;                      // elements copied when the array grows
    int shifts = 0;                      // elements moved by add(i, e) and remove(i)

    void add(int e) {                    // add at the end
        if (size == data.length) {
            grow();
        }
        data[size++] = e;
    }

    void add(int i, int e) {             // insert at index i
        if (size == data.length) {
            grow();
        }
        for (int k = size; k > i; k--) { // shift right, starting from the end
            data[k] = data[k - 1];
            shifts++;
        }
        data[i] = e;
        size++;
    }

    int remove(int i) {                  // remove index i
        int old = data[i];
        for (int k = i; k < size - 1; k++) { // shift left, starting from the front
            data[k] = data[k + 1];
            shifts++;
        }
        size--;
        return old;
    }

    private void grow() {                // twice as large, then copy
        int[] bigger = new int[data.length * 2];
        for (int k = 0; k < size; k++) {
            bigger[k] = data[k];
            copies++;
        }
        data = bigger;
    }

    int capacity() {
        return data.length;
    }

    int size() {
        return size;
    }
}
```

```java title="DynamicArrayDemo.java"
public class DynamicArrayDemo {
    // Question (Lecture 13): which operations are cheap and which need shifting or copying?
    public static void main(String[] args) {
        DynamicArray list = new DynamicArray();
        for (int i = 1; i <= 5; i++) {
            list.add(i * 10);
            System.out.println("add(" + (i * 10) + "): size " + list.size() + ", capacity " + list.capacity() + ", copies so far " + list.copies);
        }

        list.add(0, 5);
        System.out.println("add(0, 5): shifts " + list.shifts);

        list.shifts = 0;
        list.add(list.size(), 99);
        System.out.println("add at the end: shifts " + list.shifts);

        list.shifts = 0;
        list.remove(0);
        System.out.println("remove(0): shifts " + list.shifts);

        list.shifts = 0;
        list.remove(list.size() - 1);
        System.out.println("remove the last: shifts " + list.shifts);
    }
}
```

```text
add(10): size 1, capacity 2, copies so far 0
add(20): size 2, capacity 2, copies so far 0
add(30): size 3, capacity 4, copies so far 2
add(40): size 4, capacity 4, copies so far 2
add(50): size 5, capacity 8, copies so far 6
add(0, 5): shifts 5
add at the end: shifts 0
remove(0): shifts 6
remove the last: shifts 0
```

The array grows from 2 to 4 (2 elements copied) and from 4 to 8 (4 more copied), so a growth is `O(n)` but happens rarely. Inserting at the front of a list of 5 elements moved all 5; adding or removing at the end moved none; removing the first element of a list of 7 moved 6. That is the lecture's classification: `get`, `set` and `add(e)` are efficient, `add(i, e)` and `remove(i)` are not, and the lecture's answer to the inefficient methods is a linked structure (next lesson).

## 6. Comparable and Collections.sort

`Collections` is another utility class in `java.util`, and its `sort(list)` sorts any collection that implements the `List` interface, such as an `ArrayList`. It uses merge sort, in time `O(n log n)`. The list elements must be of a `Comparable` type.

```java title="CollectionsSort.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;

public class CollectionsSort {
    // Question (Lecture 13): sort a list of Integer.
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<Integer>(Arrays.asList(4, 7, 1, 5));

        System.out.println("List before sorting: " + nums);
        Collections.sort(nums);
        System.out.println("List after sorting: " + nums);
    }
}
```

```text
List before sorting: [4, 7, 1, 5]
List after sorting: [1, 4, 5, 7]
```

`Comparable<T>` is a generic interface in `java.lang` with one method, `public int compareTo(T obj)`. It gives a class a **natural ordering**. The returned value says how the two objects compare:

| `s1.compareTo(s2)` returns | Meaning |
|---|---|
| a positive integer | `s1 > s2` |
| a negative integer | `s1 < s2` |
| 0 | `s1 == s2` |

The natural ordering is consistent when `e1.equals(e2)` and `e1.compareTo(e2) == 0` give the same outcome for every pair of objects of the class. `String` implements `Comparable`: its `compareTo` compares lexicographically, by the Unicode values of the characters.

```java title="CompareToDemo.java"
public class CompareToDemo {
    // Question (Lecture 13): what does String compareTo return?
    public static void main(String[] args) {
        String str1 = "CSI247";
        String str2 = "CSI247";
        int outcome = str1.compareTo(str2);
        System.out.println(outcome == 0);                      // the slide's question
        System.out.println(str1.equals(str2));

        System.out.println("apple".compareTo("banana"));       // a before b
        System.out.println("b".compareTo("a"));                // b after a
        System.out.println("Kago".compareTo("Kagome"));        // a prefix is smaller
    }
}
```

```text
true
true
-1
1
-2
```

`compareTo` returns 0 for equal strings, as `equals` returns `true`. For the others only the sign matters: it is negative when the first string comes first, positive when it comes later, and for a prefix the shorter string is smaller. Do not test `compareTo` against -1 or 1.

### Making your own class Comparable

The lecture's `Book` has a `title` and a `year`, and it is ordered by year. `compareTo` must handle the negative, positive and zero cases.

```java title="Book.java"
public class Book implements Comparable<Book> {
    private String title;
    private int year;

    Book(String n, int a) {
        title = n;
        year = a;
    }

    String getTitle() {
        return title;
    }

    int getYear() {
        return year;
    }

    public int compareTo(Book bk) {
        if (year == bk.year)
            return 0;               // must match the logic in equals()
        else if (year > bk.year)
            return 1;
        else
            return -1;
    }
}
```

```java title="BookTester.java"
import java.util.ArrayList;
import java.util.Collections;

public class BookTester {
    // Question (Lecture 13): sort a list of books by year.
    public static void main(String[] args) {
        ArrayList<Book> myBooks = new ArrayList<Book>();
        myBooks.add(new Book("Java Programming", 2003));
        myBooks.add(new Book("Learn Java", 2014));
        myBooks.add(new Book("Java is Fun", 2000));

        Collections.sort(myBooks);               // possible because Book implements Comparable
        for (Book bk : myBooks) {                 // enhanced for-loop
            System.out.println(bk.getTitle() + " " + bk.getYear());
        }
    }
}
```

```text
Learn Java 2014
```

The books come out in ascending order of year. The sort calls `compareTo` on pairs of books, so the order is whatever `compareTo` says.

### The same idea with other orderings

One change to `compareTo` changes the order. The two classes below are `Book` with the title as the key, and `Book` with the signs reversed.

```java title="BookByTitle.java"

    String title;
    int year;

    BookByTitle(String title, int year) {
        this.title = title;
        this.year = year;
    }

    public int compareTo(BookByTitle other) {
        return title.compareTo(other.title);       // String already knows how to compare itself
    }
}
```

```java title="NewestFirstBook.java"
public class NewestFirstBook implements Comparable<NewestFirstBook> {

    int year;

    }

        if (year == other.year)
            return 0;

}
```

### Consistency with equals

The lecture warns that `compareTo` must match the logic in `equals`. A class that compares only the year in `compareTo`, but both title and year in `equals`, is inconsistent.

```java title="LooseBook.java"
public class LooseBook implements Comparable<LooseBook> {
    String title;
    int year;

    LooseBook(String title, int year) {
        this.title = title;
        this.year = year;
    }

    public boolean equals(Object obj) {
        if (!(obj instanceof LooseBook)) {
            return false;
        }
        LooseBook other = (LooseBook) obj;
        return title.equals(other.title) && year == other.year;
    }

    public int compareTo(LooseBook other) {
        if (year == other.year)
            return 0;                                // ignores the title
        else if (year > other.year)
            return 1;
        else
            return -1;
    }
}
```

```java title="ConsistencyCheck.java"
public class ConsistencyCheck {
    // Question (Lecture 13): is e1.equals(e2) always the same as e1.compareTo(e2) == 0?
    public static void main(String[] args) {
        LooseBook a = new LooseBook("Java is Fun", 2000);
        LooseBook b = new LooseBook("Learn Java", 2000);
        System.out.println("compareTo == 0: " + (a.compareTo(b) == 0));
        System.out.println("equals: " + a.equals(b));
    }
}
```

```text
compareTo == 0: true
equals: false
```

The two books have the same year and different titles: `compareTo` says they are equal and `equals` says they are not, so the ordering is not consistent with `equals`. The repair is to break ties in `compareTo` by the title (`return title.compareTo(other.title)` when the years are equal) so that both methods agree.

## Summary

<Callout type="key" title="Remember">

`Arrays.sort` and `Arrays.toString` handle arrays (ascending, no loop; `O(n log n)`), `binarySearch` needs a sorted array, and printing an array directly shows an address. An `ArrayList` is built with `new ArrayList<E>(Arrays.asList(array))` and gives an array back with `toArray(array)` (assign the result). A collection is traversed with a standard loop, a for-each loop (which uses an iterator privately) or an `Iterator` (`hasNext`, `next`, `remove` of the last element seen); change a list while traversing it only through the iterator. A `List` allows duplicates and positions: `add(i, e)` accepts indexes 0 to `size()`, `remove(int)` removes by index and `remove(Object)` by value. An array-based list is fast to read and append and slow to insert or remove at the front, because of shifting. `Collections.sort` needs `Comparable` elements, and `compareTo` returns negative, zero or positive and should agree with `equals`.

</Callout>
