An abstract class models a partially implemented family. An interface specifies a capability or role that possibly unrelated classes can promise.

## 1. Abstract Shape

“A general Shape has an area” is meaningful, but calculating it requires concrete dimensions.

~~~java
public abstract class Shape {
    private String colour;

    protected Shape(String colour) {
        this.colour = colour;
    }

    public String getColour() {
        return colour;
    }

    // Every concrete Shape must supply this operation.
    public abstract double getArea();
}
~~~

An abstract class cannot be instantiated, but an abstract-class reference can refer to a concrete subclass object.

~~~java
Shape shape = new Circle("Blue", 2.0); // Legal.
// Shape impossible = new Shape("Blue"); // Illegal: abstract class.
~~~

## 2. Interfaces specify capabilities

~~~java
public interface Measurable {
    double measure(); // public abstract by default.
}

public interface Labelled {
    String label();
}

public class Parcel implements Measurable, Labelled {
    private double mass;

    public Parcel(double mass) {
        this.mass = mass;
    }

    @Override
    public double measure() {
        return mass;
    }

    @Override
    public String label() {
        return "Parcel " + mass + " kg";
    }
}
~~~

A class extends at most one class but can implement multiple interfaces.

## 3. Concrete-class obligation

A concrete subclass/implementation must supply every inherited abstract method. An incomplete class must itself remain abstract.

| Type | Implements all required methods? | May instantiate? |
|---|---:|---:|
| abstract Shape | no | no |
| abstract partial subclass | not necessarily | no |
| concrete Circle | yes | yes |
| interface Measurable | signature only | no |
| concrete Parcel | yes | yes |

## 4. Interface polymorphism

~~~java
public static double total(Measurable[] items) {
    double sum = 0.0;
    for (Measurable item : items) {
        sum += item.measure(); // Runtime object chooses implementation.
    }
    return sum;
}
~~~

The algorithm knows only the capability. A Parcel, Circle adapter, or future class can participate when it implements Measurable.

## 5. Choosing the mechanism

| Need | Prefer |
|---|---|
| shared state and base implementation for one family | abstract class |
| a capability across unrelated classes | interface |
| several independent roles on one class | interfaces |
| construct the general type directly | concrete class, not abstract/interface |
