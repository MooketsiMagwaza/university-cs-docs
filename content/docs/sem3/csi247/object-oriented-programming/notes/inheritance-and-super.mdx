Inheritance lets a new class reuse and extend the accessible behaviour of an existing class.

## 1. The is-a test

Use inheritance when the sentence “a subclass **is a** superclass” is true:

- a Circle is a Shape;
- a Rectangle is a Shape;
- an Account is **not** a Scanner, so that inheritance would be meaningless.

Inheritance is not merely a way to avoid typing code. It establishes a substitutability relationship.

## 2. Superclass implementation

~~~java
public class Shape {
    private String colour;

    public Shape(String colour) {
        this.colour = colour;
    }

    public String getColour() {
        return colour;
    }

    public void setColour(String colour) {
        this.colour = colour;
    }

    @Override
    public String toString() {
        return colour + " shape";
    }
}
~~~

The private field belongs to the Shape part of every subclass object. Subclass code cannot access it directly; it uses inherited public/protected behaviour.

## 3. Subclass construction

~~~java
public class Circle extends Shape {
    private double radius;

    public Circle(String colour, double radius) {
        super(colour);       // Construct the Shape part first.
        this.radius = radius;
    }

    public double getRadius() {
        return radius;
    }
}
~~~

Construction order for <code>new Circle("Blue", 2.0)</code>:

| Step | Statement/effect | Object state |
|---:|---|---|
| 1 | allocate one Circle object | fields have defaults |
| 2 | <code>super("Blue")</code> | Shape colour becomes Blue |
| 3 | <code>this.radius = 2.0</code> | Circle radius becomes 2.0 |
| 4 | constructor returns reference | object is ready |

If a subclass constructor does not explicitly call <code>super(...)</code>, Java inserts <code>super()</code>. Compilation fails when the superclass has no accessible no-argument constructor.

## 4. What is and is not inherited

| Member | Subclass object has it? | Subclass code directly names it? |
|---|---|---|
| public method | yes | yes |
| protected method/field | yes | subject to package/subclass access rules |
| package-private member | yes | only from same package |
| private field/method | object contains superclass state | no direct access |
| superclass constructor | invoked during construction | not inherited as a callable subclass method |

## 5. super and this

- <code>this</code> is the current complete object.
- <code>super(...)</code> invokes a superclass constructor and must be the first constructor statement.
- <code>super.method()</code> explicitly invokes the superclass implementation of an inherited method.

~~~java
@Override
public String toString() {
    return super.toString() + ", circle radius " + radius;
}
~~~
