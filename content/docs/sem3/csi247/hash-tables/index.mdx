A hash table answers a practical question: “Can a key lead us near its value without scanning everything?” It uses a **hash function** to choose a bucket, then resolves collisions inside that bucket.

## 2. Collisions are normal

Two unequal keys can choose the same bucket. Separate chaining keeps multiple entries at that bucket.

<div className="not-prose my-6 flex flex-wrap items-center justify-center gap-2 font-mono">
  <div className="rounded-lg border-2 border-blue-500 p-3">bucket 3</div><span>→</span><div className="rounded-lg border-2 border-emerald-600 p-3">CSI247 → Room 4</div><span>→</span><div className="rounded-lg border-2 border-emerald-600 p-3">MAT247 → Room 8</div>
</div>

Lookup hashes the key to bucket 3, then compares keys in that chain using <code>equals</code>.

## 3. The equality contract

If <code>a.equals(b)</code> is true, <code>a.hashCode() == b.hashCode()</code> must also be true. Unequal objects may share a hash.

~~~java
public final class StudentKey {
    private final String number;

    @Override
    public boolean equals(Object other) {
        if (this == other) return true;
        if (!(other instanceof StudentKey)) return false;
        StudentKey that = (StudentKey) other;
        return number.equals(that.number);
    }

    @Override
    public int hashCode() {
        return number.hashCode();
    }
}
~~~

Keys should not mutate in a way that changes their equality/hash while stored. The map would search the new bucket while the entry remains in the old one.

## 4. Load factor and resizing

<code>load factor = number of entries / number of buckets</code>. As chains grow, lookup becomes slower. Resizing creates more buckets and redistributes entries using their hashes.

| Situation | Expected lookup | Worst case |
|---|---:|---:|
| well-distributed hashes | O(1) | — |
| many collisions in one chain | — | O(N) in the simple chained model |
| resize | O(N) for that resize | amortised across many inserts |

## 5. Put trace

| Step | operation | bucket | result |
|---:|---|---:|---|
| 1 | put(A, 70) | 2 | new entry |
| 2 | put(B, 80) | 2 | collision; append/check chain |
| 3 | put(A, 75) | 2 | equals finds A; replace value |

Map keys are unique; a later put with an equal key replaces the associated value.
