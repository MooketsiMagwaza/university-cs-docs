This module rebuilds Lectures 2–5 as five connected visual lessons. The key thread is **what each variable actually stores**. That one distinction explains primitive values, object references, array mutation, parameter passing, `null`, and why generics use wrapper/reference types.

## Lesson map

| Order | Lesson | Central question |
|---:|---|---|
| 1 | [Values, Variables, Primitives and References](/docs/sem3/csi247/java-fundamentals/notes/values-primitives-references) | Does the variable store a value or a route to an object? |
| 2 | [Strings, Control Flow and Input/Output](/docs/sem3/csi247/java-fundamentals/notes/strings-control-io) | How does data enter, branch, repeat, and leave a program? |
| 3 | [Methods, Parameters, Returns and Scope](/docs/sem3/csi247/java-fundamentals/notes/methods-parameters-scope) | What is copied into a call, and where can each name be used? |
| 4 | [User-Defined Classes and Objects](/docs/sem3/csi247/java-fundamentals/notes/classes-and-objects) | How does a blueprint produce independent objects with state and behaviour? |
| 5 | [Arrays and Arrays of Objects](/docs/sem3/csi247/java-fundamentals/notes/arrays-and-objects) | What does an array cell hold, and how do method calls mutate an array? |

## How to study the recap

For each lesson, draw the memory picture before reading the Java trace. Say the evaluated condition aloud, predict the next value/reference, and only then inspect the result. Finish the local quiz and the larger [exam-style question bank](/docs/sem3/csi247/java-fundamentals/questions).

The [Java playground](/docs/sem3/csi247/java-playground) contains runnable recap examples. Change one value or boundary at a time so the visual model and output remain connected.
