## 2. Class structure

~~~java
public class Account {
    // Private instance variables: each Account object owns these values.
    private int number;
    private double balance;

    // Constructors initialise a newly created object.

    // Public methods form the object's usable interface.
}
~~~

Private state prevents unrelated code from bypassing the class rules. Public methods decide which changes are valid.

## 3. Constructors initialise objects

A constructor has the class name and no return type. It runs after <code>new</code> allocates an object.

~~~java
public Account() {
    this(0, 0.0); // Delegate to the two-parameter constructor.
}

public Account(int number, double balance) {
    this.number = number;   // Field on the left, parameter on the right.
    this.balance = balance;
}
~~~

If a class declares no constructor, Java supplies a no-argument default constructor. Once any constructor is declared, that automatically supplied constructor is no longer added.

## 4. this means the current object

Inside an instance method, <code>this</code> refers to the receiver object—the object to the left of the dot at the call site.


## 5. Setters, getters, and behaviour

~~~java
public int getNumber() {
    return number; // Observe state without changing it.
}

public double getBalance() {
    return balance;
}

public void setNumber(int newNumber) {
    if (newNumber <= 0) {
        throw new IllegalArgumentException("number must be positive");
    }
    number = newNumber;
}

public void deposit(double amount) {
    if (amount <= 0) {
        throw new IllegalArgumentException("deposit must be positive");
    }
    balance += amount; // Mutate this Account object's state.
}

public boolean withdraw(double amount) {
    if (amount <= 0 || amount > balance) {
        return false; // Reject invalid or unaffordable withdrawal.
    }
    balance -= amount;
    return true;
}
~~~

| Call | Condition with values | State change | Return |
|---|---|---|---|
| <code>acc.deposit(500)</code> | <code>500 &gt; 0</code> true | balance 1000 → 1500 | none |
| <code>acc.withdraw(200)</code> | <code>200 &lt;= 1500</code> true | 1500 → 1300 | true |
| <code>acc.withdraw(2000)</code> | <code>2000 &lt;= 1300</code> false | unchanged | false |

## 6. Object equality and text

<code>==</code> asks whether two variables contain the same reference. A class-defined <code>equals</code> can ask whether two distinct objects represent equal data.

~~~java
@Override
public boolean equals(Object other) {
    if (this == other) {
        return true; // Same reference is certainly equal.
    }
    if (!(other instanceof Account account)) {
        return false; // null or another class is not an Account.
    }
    return number == account.number
        && Double.compare(balance, account.balance) == 0;
}

@Override
public String toString() {
    return String.format("Account{%d, P%.2f}", number, balance);
}
~~~

## 8. Signatures and overloading

A method signature consists of its name and parameter types—not its return type.

| Declaration | Signature |
|---|---|
| <code>deposit(double amount)</code> | <code>deposit(double)</code> |
| <code>withdraw(double amount)</code> | <code>withdraw(double)</code> |
| <code>transfer(Account other, double amount)</code> | <code>transfer(Account,double)</code> |

Overloaded methods share a name but must have different parameter lists. Changing only the return type does not create a new signature.

## 9. Complete tester

~~~java
public class AccountTester {
    public static void main(String[] args) {
        Account first = new Account(21347, 38763.87);
        Account second = new Account(61342, 0.0);

        second.deposit(500.0);
        boolean withdrew = first.withdraw(1000.0);

        System.out.println(first);
        System.out.println(second);
        System.out.println("withdrawal accepted = " + withdrew);
        System.out.println("same account data = " + first.equals(second));
    }
}
~~~
