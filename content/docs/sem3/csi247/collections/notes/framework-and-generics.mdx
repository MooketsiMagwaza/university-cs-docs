## 1. Interface first, implementation second

~~~java
List<String> modules = new ArrayList<>();
//   interface             implementation
~~~

The variable promises only List operations. The object currently uses an ArrayList. This keeps client code flexible.

## 2. The element type flows through the API

| Expression | Result after E becomes Book |
|---|---|
| <code>boolean add(E item)</code> | <code>boolean add(Book item)</code> |
| <code>E get(int index)</code> | <code>Book get(int index)</code> |
| <code>boolean contains(Object value)</code> | still accepts Object for comparison |
| <code>Iterator&lt;E&gt;</code> | <code>Iterator&lt;Book&gt;</code> |

~~~java
List<Book> books = new ArrayList<>();
books.add(new Book("Algorithms"));
Book first = books.get(0); // No cast.
// books.add("wrong");     // Compile-time error.
~~~

## 3. Collection is not Collections

| Name | Kind | Purpose |
|---|---|---|
| <code>Collection&lt;E&gt;</code> | interface | common operations for groups of elements |
| <code>Collections</code> | utility class | static algorithms such as sort, reverse, min, max |
| <code>Map&lt;K,V&gt;</code> | separate interface | key/value associations; not a subtype of Collection |

## 4. Core operations

~~~java
List<String> names = new ArrayList<>();
names.add("Ava");
names.add("Mpho");
boolean found = names.contains("Ava");
int count = names.size();
boolean removed = names.remove("Mpho");
names.clear();
~~~

<CommonMistake title="Using a raw collection">
<code>List values = new ArrayList();</code> discards the element guarantee. Supply a type argument such as <code>List&lt;Integer&gt;</code>.
</CommonMistake>
