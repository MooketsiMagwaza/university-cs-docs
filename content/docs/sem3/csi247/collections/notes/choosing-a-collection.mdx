## 1. Behaviour before speed

First choose the interface whose rules match the problem. Then compare implementations by the operations that dominate the workload.

| Structure | Strength | Cost or warning |
|---|---|---|
| ArrayList | fast indexed access; compact sequence | middle insertion/removal shifts elements |
| LinkedList | deque operations at ends | indexed access walks nodes; extra links |
| ArrayDeque | efficient stack/queue at ends | no indexed list API; no null elements |
| HashSet / HashMap | expected constant membership/key lookup | no sorted order; needs correct equals/hashCode |
| TreeSet / TreeMap | remains sorted | operations are logarithmic |

## 3. Equality is part of the structure

Hash collections use <code>hashCode</code> to find a region and <code>equals</code> to confirm a match. Equal objects must have equal hash codes.

~~~java
@Override
public boolean equals(Object other) {
    if (this == other) return true;
    if (!(other instanceof Student)) return false;
    Student that = (Student) other;
    return studentNumber.equals(that.studentNumber);
}

@Override
public int hashCode() {
    return studentNumber.hashCode();
}
~~~
