---
title: "3. Bounds, Comparable and Meaningful Operations"
description: "Restrict type parameters so generic code can safely use Number or Comparable operations, including multiple bounds."
---

An unbounded T is known only to be some reference type. A bound gives the compiler an additional guarantee and therefore additional legal operations.

## 1. Upper bounds

~~~java
public class NumericBox<T extends Number> {
    private final T value;

    public NumericBox(T value) {
        this.value = value;
    }

    public double doubled() {
        return value.doubleValue() * 2; // Legal because Number declares it.
    }
}
~~~

<code>extends</code> is used for both class and interface bounds.

## 2. What the bound permits

Without a bound:

~~~java
public static <T> double twice(T value) {
    // return value.doubleValue() * 2; // Compiler does not know T has this method.
    return 0;
}
~~~

With <code>&lt;T extends Number&gt;</code>, the compiler knows every allowed T supports Number's public methods. It still does not know which exact numeric wrapper arrives.

## 3. Comparable connects values to an ordering

~~~java
public static <T extends Comparable<T>> T maximum(T first, T second) {
    if (first.compareTo(second) >= 0) {
        return first;
    }
    return second;
}
~~~

Read the header slowly:

> T must be a type that can compare itself with another T.

## 4. Multiple bounds

~~~java
public static <T extends Shape & Comparable<T>> T largerShape(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
~~~

The class bound, when present, must come first; interface bounds follow with <code>&amp;</code>. An allowed T must satisfy **all** bounds.

## 5. Implementing Comparable correctly

~~~java
public final class Student implements Comparable<Student> {
    private final String id;
    private final int mark;

    public Student(String id, int mark) {
        this.id = id;
        this.mark = mark;
    }

    @Override
    public int compareTo(Student other) {
        return Integer.compare(mark, other.mark);
    }
}
~~~

The sign matters:

- negative: this comes before other;
- zero: same ordering position;
- positive: this comes after other.

Avoid subtraction such as <code>mark - other.mark</code> for large integer ranges because it can overflow.

## 6. Bound versus runtime test

A bound rejects an unsuitable type at compilation. An <code>instanceof</code> test asks about an object during execution. Prefer a bound when the generic algorithm fundamentally requires a capability.
