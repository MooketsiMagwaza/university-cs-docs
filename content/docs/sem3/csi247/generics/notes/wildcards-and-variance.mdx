This is the part of Generics that usually feels backwards. The key is to stop reading the angle brackets as decoration: they describe exactly what a container may safely accept and return.

## 1. The surprising rule

An <code>Integer</code> is a <code>Number</code>, but a <code>List&lt;Integer&gt;</code> is **not** a <code>List&lt;Number&gt;</code>.

  <div className="rounded-2xl border border-red-500 bg-red-500/5 p-5"><div className="text-sm font-semibold text-red-700 dark:text-red-300">ILLEGAL</div><div className="mt-3 font-mono">List&lt;Number&gt; x = ints;</div><p className="mb-0 mt-3 text-sm">A whole List of Integer cannot become a writable List of Number.</p></div>
</div>

Why? If the assignment were allowed, this would corrupt the original list:

~~~java
List<Integer> integers = new ArrayList<>();

// Imagine Java allowed this unsafe assignment:
// List<Number> numbers = integers;
// numbers.add(3.14); // A Double would enter a List<Integer>!
~~~

Therefore ordinary generic types are **invariant**: the type arguments must match exactly.

## 2. The three wildcard shapes

| Parameter type | Plain-language promise | Safe to read as | Safe non-null value to add |
|---|---|---|---|
| <code>List&lt;?&gt;</code> | a list of some unknown type | <code>Object</code> | none |
| <code>List&lt;? extends Number&gt;</code> | a list of one unknown Number subtype | <code>Number</code> | none |
| <code>List&lt;? super Integer&gt;</code> | a list whose type is Integer or one of its supertypes | <code>Object</code> | <code>Integer</code> |

## 3. Producer Extends: read Number values

~~~java
public static double sum(List<? extends Number> values) {
    double total = 0.0;

    for (Number value : values) {
        total += value.doubleValue();
    }
    return total;
}
~~~

The list **produces** Number values for the method. It may actually be a <code>List&lt;Integer&gt;</code>, <code>List&lt;Double&gt;</code>, or another Number subtype.

~~~java
sum(List.of(2, 4, 6));       // List<Integer>
sum(List.of(1.5, 2.5));      // List<Double>
~~~

The method must not add <code>3</code>. The hidden exact type might be <code>Double</code>, and an Integer would violate it.

## 4. Consumer Super: write Integer values

~~~java
public static void addCountdown(List<? super Integer> destination) {
    destination.add(3);
    destination.add(2);
    destination.add(1);
}
~~~

The destination **consumes** Integers. It may be a <code>List&lt;Integer&gt;</code>, <code>List&lt;Number&gt;</code>, or <code>List&lt;Object&gt;</code>; every one can legally hold an Integer.

Reading gives only <code>Object</code>, because the actual destination might be a List of Object.

## 5. PECS as a memory rule

**P**roducer → **E**xtends. **C**onsumer → **S**uper.

| Method need | Parameter | Reason |
|---|---|---|
| read T values | <code>? extends T</code> | every element is at least a T |
| insert T values | <code>? super T</code> | the destination is guaranteed to accept T |
| both read and write exact T | <code>List&lt;T&gt;</code> | exact agreement is required |

PECS is not a slogan replacing reasoning. Ask two concrete questions: “What type can come out?” and “What type may go in?”

## 6. Trace a copy method

~~~java
public static <T> void copy(
        List<? extends T> source,
        List<? super T> destination) {

    for (T item : source) {
        destination.add(item);
    }
}
~~~

For <code>copy(List&lt;Integer&gt;, List&lt;Number&gt;)</code>:

| Step | Statement | Known type | Why safe |
|---:|---|---|---|
| 1 | source returns an item | Integer, therefore T can be Number | Integer is a Number |
| 2 | assign to <code>T item</code> | Number view | widening is safe |
| 3 | destination accepts item | Number | destination is List&lt;Number&gt; |

## 7. What plain <code>?</code> means

~~~java
public static void printAnything(List<?> values) {
    for (Object value : values) {
        System.out.println(value);
    }
}
~~~

The method neither needs a particular element subtype nor inserts values. It can inspect size, retrieve as Object, clear the list, or remove elements. It cannot add a meaningful value because the exact element type is unknown.

## 8. Do not confuse a wildcard with a type parameter

~~~java
public static <T> T first(List<T> values) { // T names one type and returns it.
    return values.get(0);
}

public static Object firstUnknown(List<?> values) { // ? is anonymous.
    return values.get(0);
}
~~~

Use <code>&lt;T&gt;</code> when multiple parts of the signature must share the same type. Use <code>?</code> when the exact type does not need a name.
