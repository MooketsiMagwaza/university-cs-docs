| If you need to… | Use | Remember |
|---|---|---|
| reuse a class while preserving its stored type | <code>class Box&lt;T&gt;</code> | T is a placeholder, not an object |
| use primitive-like values | wrappers | <code>Integer</code>, not <code>int</code> |
| give one method its own type | <code>static &lt;T&gt; T method(...)</code> | declare T before return type |
| call a method on T | a bound | <code>T extends Comparable&lt;T&gt;</code> |
| read values from many subtype lists | <code>? extends T</code> | producer extends |
| insert T into several compatible lists | <code>? super T</code> | consumer super |
| relate parameter and return types | named <code>T</code> | wildcards cannot express that relationship |

## The five checks

1. What concrete type replaces each parameter?
2. Is the type a reference type?
3. Does code need a capability that requires a bound?
4. Does the container produce values, consume values, or both?
5. Has a raw type removed compile-time safety?

<Callout type="info" title="One-sentence model">
Generics let a declaration temporarily name a type so the compiler can preserve relationships between inputs, stored values, and outputs.
</Callout>
