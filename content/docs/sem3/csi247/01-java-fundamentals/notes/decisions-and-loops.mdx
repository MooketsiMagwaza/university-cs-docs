## Making decisions with `if`

An `if` statement runs a block of code only when a condition (a `boolean` expression) is `true`. You can add an `else` block that runs when it is `false`, and chain extra conditions with `else if`. Java checks the conditions from top to bottom and runs the **first** block whose condition is true, then skips the rest of the chain.

```java title="Grades.java"
int mark = 72;

if (mark >= 80) {
    System.out.println("Distinction");
} else if (mark >= 50) {          // only checked if the first condition was false
    System.out.println("Pass");    // ← this one runs: 72 is not ≥ 80, but is ≥ 50
} else {                           // runs only if NONE of the conditions above were true
    System.out.println("Fail");
}
```

Order matters. If we had tested `mark >= 50` first, a mark of 95 would print "Pass" and never reach the distinction check.

### `switch` for many fixed choices

When you compare one value against many fixed possibilities, a `switch` is tidier than a long `else if` chain. Modern Java (14 and later) has an arrow form that is easy to read:

```java title="Days.java"
int day = 3;
String name = switch (day) {
    case 1, 7 -> "Weekend";
    case 2, 3, 4, 5, 6 -> "Weekday";
    default -> "Not a day";      // used when no case matches
};
System.out.println(name);        // Weekday
```

## Repeating with loops

A **loop** repeats a block of code. Each single run of the block is called an **iteration**. Every loop needs three things, or it will either never run or never stop: a starting state, a condition that is checked to decide whether to continue, and a change that eventually makes the condition false.

### The `while` loop

A `while` loop checks its condition; if it's true, it runs the body, then goes back and checks again. It stops the first time the condition is false. If the condition is false right at the start, the body never runs at all.

```java title="Countdown.java"
int n = 3;                     // 1. starting state
while (n > 0) {                // 2. condition checked BEFORE every iteration
    System.out.println(n);
    n--;                       // 3. progress towards making the condition false
}
System.out.println("Lift off!");
```

```text
3
2
1
Lift off!
```

<Callout type="mistake" title="Infinite loops">

If you forget the `n--;` line, `n` stays 3 forever, the condition is always true, and the program never ends. If that happens, stop it with <kbd>Ctrl</kbd>+<kbd>C</kbd> in the terminal or the stop button in your IDE.

</Callout>

### The `for` loop

Counting loops are so common that Java packs the three parts into one line. This is the loop you will see in almost every searching and sorting algorithm.

```java title="ForLoop.java"
//   start      condition   change after each iteration
for (int i = 0; i < 5;      i++) {
    System.out.println("i is " + i);
}
// prints i is 0, i is 1, i is 2, i is 3, i is 4   (5 iterations, never 5 itself)
```

Exactly what happens, in order: (1) `int i = 0` runs once. (2) The condition `i < 5` is checked; if false, the loop ends. (3) The body runs. (4) `i++` runs. (5) Go back to step 2. The variable `i` only exists inside the loop.

### Nested loops

A loop can sit inside another loop. For each single iteration of the outer loop, the inner loop runs completely. Bubble sort and selection sort are built exactly like this, which is why (as you'll see on the Big-O page) they take time proportional to *n × n*.

```java title="Nested.java"
for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 4; col++) {
        System.out.print(row * col + "\t");   // \t is a tab character
    }
    System.out.println();                     // new line after each row
}
// The body of the inner loop runs 3 × 4 = 12 times in total.
```

```text
1	2	3	4
2	4	6	8
3	6	9	12
```

### `break` and `continue`

- `break` exits the loop immediately, skipping any remaining iterations. Linear search uses this idea: once you've found the item, there's no point looking further.
- `continue` skips the rest of the *current* iteration and jumps to the next one.

```java title="BreakContinue.java"
for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) continue;   // even number → skip the print, go straight to i++
    if (i > 7) break;           // first odd number above 7 → leave the loop entirely
    System.out.print(i + " ");
}
// prints: 1 3 5 7
```

## Tracing: running the code in your head

The single most useful skill for understanding algorithms is **tracing**: pretending to be the computer, executing one line at a time, and writing down every variable's value in a table. Every algorithm page in this course includes a trace table. Let's trace a loop that adds up the numbers 1 to 4.

```java title="Sum.java"
int sum = 0;
for (int i = 1; i <= 4; i++) {
    sum = sum + i;
}
System.out.println(sum);   // 10
```

| Moment | `i` | `i <= 4`? | `sum` after the body |
| --- | --- | --- | --- |
| before the loop | — | — | 0 |
| iteration 1 | 1 | true | 0 + 1 = 1 |
| iteration 2 | 2 | true | 1 + 2 = 3 |
| iteration 3 | 3 | true | 3 + 3 = 6 |
| iteration 4 | 4 | true | 6 + 4 = 10 |
| check again | 5 | **false** → stop | 10 |

<Callout type="tip">

When code confuses you, don't stare at it. Take a piece of paper, draw columns for every variable, and trace it. It's how professionals find bugs too.

</Callout>

<Callout type="key">

`if` chooses; loops repeat. A loop needs a start, a condition and progress. A loop inside a loop multiplies the work. Trace with a table whenever you are unsure.

</Callout>
