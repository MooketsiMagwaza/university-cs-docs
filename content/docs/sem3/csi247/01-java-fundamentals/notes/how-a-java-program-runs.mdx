## What is a program?

A computer is a machine that follows instructions extremely quickly and extremely literally. It cannot guess what you mean. A **program** is a list of instructions, written down precisely, that tells the computer what to do step by step. Your phone's calculator is a program. So is a web browser, a game or a banking app.

Deep down, a computer's processor only understands **machine code**: long sequences of numbers that mean things like "add these two values" or "jump to that instruction". Writing machine code by hand is slow and error-prone, so people invented **programming languages**. A programming language is a set of words and grammar rules that are readable by humans but still precise enough to be translated into machine code automatically. Java is one such language. Others you may have heard of include Python, C, JavaScript and C#.

<KeyTerm title="Source code">

The text of a program as written by a person in a programming language. Java source code is stored in plain text files whose names end in `.java`.

</KeyTerm>

## From your text to a running program

Java uses a two-step process to get from your source code to something the computer can run. Understanding these two steps explains many of the error messages you will see later.

<Steps>

<Step title="You write source code">

You type your instructions into a file, for example `Hello.java`, using any text editor or an IDE (an *Integrated Development Environment*: a text editor with programming tools built in, such as IntelliJ IDEA, Eclipse, or VS Code).

</Step>

<Step title="The compiler checks and translates it">

A program called the **compiler** (its command is `javac`, short for "Java compiler") reads your file. First it checks that you followed every grammar rule of Java. If you made a mistake, such as forgetting a semicolon or using a word Java doesn't know, it refuses to continue and prints a **compile-time error** telling you the line number. If everything is correct, it translates your code into **bytecode** and saves it in a file ending in `.class`, for example `Hello.class`.

</Step>

<Step title="The Java Virtual Machine runs the bytecode">

Bytecode is not the machine code of any real processor. It is the machine code of an imaginary, standardised computer. A program called the **Java Virtual Machine** (JVM, started with the command `java`) reads the bytecode and carries it out on your actual computer. Mistakes that only show up while the program is running, such as dividing by zero, are called **run-time errors** or **exceptions**.

</Step>

</Steps>

### Why two steps instead of one?

The two-step design is the reason Java became popular. Because bytecode is the same everywhere, you compile your program *once* and the resulting `.class` files run on Windows, macOS, Linux and other systems without changes. Only the JVM has to be different on each system, and someone else has already written those. The compile step also catches many mistakes early, before the program ever runs. Modern JVMs are also very fast: while your program runs, they notice which parts are used most and translate those parts into real machine code on the fly. This is called **just-in-time (JIT) compilation**.

<Callout type="note">

To compile and run Java on your own computer you install a **JDK** (Java Development Kit). It contains the compiler `javac`, the JVM launcher `java`, and Java's standard library of ready-made code. Free JDKs are available from several vendors, for example the OpenJDK builds from Adoptium. If you'd rather not install anything, many websites let you type and run Java in your browser; search for "online Java compiler".

</Callout>

## Your first program, word by word

Here is the smallest useful Java program. It prints one line of text on the screen. Don't worry if it looks strange; we will go through every single word.

```java title="Hello.java"
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
```

```text
Hello, world!
```

| Piece | What it means |
| --- | --- |
| `public` | An *access modifier*: it says who is allowed to use what follows. `public` means "anyone, anywhere". We study access modifiers properly on the Encapsulation page. |
| `class Hello` | Declares a **class** named `Hello`. In Java, all code must live inside a class. For now think of a class as a named container for code; the OOP section explains the full meaning. A `public` class must be saved in a file with exactly the same name plus `.java`, so this one must be in `Hello.java`. |
| `{ … }` | Curly braces mark the beginning and end of a **block**: a group of code that belongs together. The outer pair holds everything in the class. Every `{` needs a matching `}`. |
| `static` | Means this method belongs to the class itself, so Java can run it without first creating an object. Fully explained on the Classes & objects page. |
| `void` | The *return type*. `void` means "this method does its job but hands no value back". |
| `main` | The name of the method. `main` is special: when you run a program, the JVM looks for a method with exactly this name and signature and starts there. It is the program's front door. |
| `(String[] args)` | The *parameter list*. `main` receives an array of text values (`String[]`) called `args`, containing anything typed after the program name on the command line. We won't use it, but it must be written. |
| `System.out.println(…)` | A ready-made method from Java's standard library that prints a line of text to the screen, then moves to a new line. `System` is a class, `out` is the "standard output" (usually the screen) and `println` means "print line". |
| `"Hello, world!"` | A **string literal**: a piece of text written directly in the code. Double quotes mark where the text starts and ends; they are not printed. |
| `;` | The semicolon ends a **statement** (one complete instruction), like a full stop ends a sentence. |

### Compiling and running it yourself

If you have a JDK installed, save the listing as `Hello.java`, open a terminal (also called a command prompt) in the same folder, and type these two commands. The first compiles, the second runs. Notice that you give `javac` the file name *with* `.java`, but give `java` only the class name, *without* `.class`.

```text title="Terminal"
javac Hello.java      ← creates Hello.class
java Hello            ← runs it, prints: Hello, world!
```

<Callout type="tip">

Since Java 11 you can also skip the separate compile step for a single-file program and just type `java Hello.java`. Java compiles it in memory and runs it straight away.

</Callout>

## The grammar rules every Java file follows

- **Java is case-sensitive.** `Main`, `main` and `MAIN` are three different names. `system.out.println` (small s) will not compile.
- **Statements end with a semicolon.** Forgetting one is the most common compile error of all.
- **Blocks are wrapped in braces.** Indentation (the spaces at the start of lines) is ignored by the compiler, but humans rely on it to see the structure, so always indent the contents of a block by four spaces.
- **Comments are ignored by the compiler.** `// like this` runs to the end of the line. `/* like this */` can span several lines. Use them to explain *why* your code does something.
- **Names (identifiers)** may contain letters, digits, `_` and `$`, but may not start with a digit and may not be one of Java's reserved keywords such as `class` or `int`. By convention, class names start with a capital letter (`BankAccount`), while variable and method names start with a small letter and capitalise each following word (`accountBalance`, `printReport`). This style is called *camelCase*.
- **Code runs from top to bottom**, one statement at a time, starting at the first line inside `main`, unless a decision or loop (next pages) changes the order.

```java title="Comments.java"
// This whole line is a comment. The compiler skips it.
public class Comments {
    public static void main(String[] args) {
        /* A comment can also
           span several lines like this. */
        System.out.println("Line one");   // a comment can follow code on the same line
        System.out.print("No new line after this. ");   // print (not println) stays on the same line
        System.out.println("Line two");
    }
}
```

```text
Line one
No new line after this. Line two
```

<Callout type="mistake">

Saving `public class Hello` in a file called `hello.java` or `MyProgram.java`. The compiler will reply *"class Hello is public, should be declared in a file named Hello.java"*. The file name must match the public class name exactly, including capital letters.

</Callout>

<Callout type="key">

You write **source code** → `javac` checks and compiles it to **bytecode** → the **JVM** runs the bytecode, starting at `main`. Grammar mistakes are caught at compile time; problems that depend on the data are found at run time.

</Callout>

## Check your understanding

<CheckQuestions>

<CheckQuestion question={<>What is the difference between a <code>.java</code> file and a <code>.class</code> file?</>}>

A `.java` file contains source code: human-readable text you wrote. A `.class` file contains bytecode produced by the compiler from that source. The JVM runs `.class` files, not `.java` files.

</CheckQuestion>

<CheckQuestion question={"Your program compiles, but crashes while running when it divides by zero. Is that a compile-time or a run-time error?"}>

A run-time error. The grammar was fine, so the compiler accepted it; the problem only appears when the program actually runs with that data. Java reports it as an `ArithmeticException`.

</CheckQuestion>

<CheckQuestion question={"Why can one compiled Java program run on both Windows and macOS?"}>

Because it is compiled to bytecode, which is the same on every system. Each operating system has its own JVM that knows how to run that standard bytecode on that particular machine.

</CheckQuestion>

</CheckQuestions>
