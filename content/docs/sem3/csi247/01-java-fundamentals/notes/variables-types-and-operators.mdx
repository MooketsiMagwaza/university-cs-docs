## What a variable is

<Callout type="analogy">

Picture a row of labelled boxes. Each box has a **name** written on the label, a **type** that says what may be put inside (only whole numbers, only text…), and a **value**: whatever is currently inside. You can look inside a box as often as you like, and you can throw out the old contents and put in something new.

</Callout>

A **variable** is a named location in the computer's memory that holds one value. In Java every variable has a **type**, fixed when you create it, which decides what values it can hold and what you can do with them. Java checks types at compile time, so if you try to put text into a box meant for numbers, the program won't compile. Languages that work like this are called *statically typed*.

### Declaring, assigning and initialising

```java title="Variables.java"
public class Variables {
    public static void main(String[] args) {
        int age;                 // DECLARATION: create a box called age that holds whole numbers
        age = 19;                // ASSIGNMENT: put the value 19 into it

        int year = 2026;         // declaration + assignment in one line = INITIALISATION

        age = age + 1;           // read the current value (19), add 1, store the result (20) back
        System.out.println(age);             // 20
        System.out.println("Year: " + year); // Year: 2026   (+ joins text and a number)
    }
}
```

Read the `=` sign as **"becomes"**, never as "equals". The statement `age = age + 1;` would be nonsense in mathematics, but in Java it means: *work out the right-hand side using the current value of `age`, then store the result in `age`*. The right side is always fully calculated first, then copied into the variable on the left.

<Callout type="mistake">

Using a local variable before giving it a value. `int x; System.out.println(x);` fails to compile with *"variable x might not have been initialized"*. Java refuses to let you read a box that has never had anything put in it.

</Callout>

## Primitive types

Java has eight built-in **primitive types**. A primitive value is a simple, raw value stored directly in the variable's box: a number, a single character, or true/false. In practice you will use four of them almost all the time: `int`, `double`, `boolean` and `char`.

| Type | Holds | Size | Range / example |
| --- | --- | --- | --- |
| `byte` | whole number | 8 bits | −128 to 127 |
| `short` | whole number | 16 bits | −32,768 to 32,767 |
| `int` | whole number (the default choice) | 32 bits | about −2.1 billion to 2.1 billion (−2<sup>31</sup> to 2<sup>31</sup>−1). Example: `42` |
| `long` | large whole number | 64 bits | about ±9.2 × 10<sup>18</sup>. Write an `L` after the literal: `9000000000L` |
| `float` | decimal number, less precise | 32 bits | about 7 significant digits. Write an `f`: `3.14f` |
| `double` | decimal number (the default choice) | 64 bits | about 15–16 significant digits. Example: `3.14` |
| `boolean` | truth value | — | only `true` or `false` |
| `char` | one character | 16 bits | written in single quotes: `'A'`, `'7'`, `'?'` |

A **bit** is a single binary digit, 0 or 1. More bits means more possible patterns, so a bigger range of values. That is why `long` can hold much bigger numbers than `int`.

<Callout type="caution" title="Overflow">

If a calculation goes past the maximum of its type, Java does not stop with an error. The value silently "wraps around" to the other end of the range, like a car's odometer rolling over. `int big = 2147483647; big = big + 1;` gives `-2147483648`. This is called **integer overflow**. It matters later, in binary search and in comparators.

</Callout>

<Callout type="caution" title="Decimals are approximate">

`double` stores numbers in binary, and many decimal fractions (like 0.1) cannot be represented exactly in binary, just as 1/3 cannot be written exactly in decimal. So `0.1 + 0.2` prints `0.30000000000000004`. Never use `==` to compare two calculated doubles, and use the `BigDecimal` class for money in real applications.

</Callout>

## Text: the `String` type

Text is so common that Java has a special type for it: `String` (capital S). A string is a sequence of characters written between **double** quotes. Unlike the eight primitives, `String` is a *class*, which means a `String` variable holds a reference to an object rather than the raw characters. That difference will make full sense on the Classes & objects page; for now just notice that `String` has a capital letter and comes with useful built-in methods.

```java title="Strings.java"
String name = "Neo";
String greeting = "Dumela, " + name + "!";   // + joins (concatenates) strings
System.out.println(greeting);                // Dumela, Neo!
System.out.println(greeting.length());       // 12   — number of characters
System.out.println(name.charAt(0));          // N    — character at position 0 (counting starts at 0!)
System.out.println(name.toUpperCase());      // NEO
System.out.println(name.equals("Neo"));      // true — compare TEXT with .equals, never with ==
System.out.println("Score: " + 3 + 4);       // Score: 34   (left to right: text + 3 → text, then + 4)
System.out.println("Score: " + (3 + 4));     // Score: 7    (brackets force the sum first)
```

<Callout type="mistake">

Using `==` to compare strings. `==` asks "are these the very same object in memory?", not "do these contain the same letters?". Two strings can contain identical text but be different objects, so `==` may give `false`. Always use `a.equals(b)` for text. The reason is explained on the Classes & objects page.

</Callout>

## Operators

### Arithmetic

| Operator | Meaning | Example | Result |
| --- | --- | --- | --- |
| `+` | add (or join strings) | `7 + 2` | `9` |
| `-` | subtract | `7 - 2` | `5` |
| `*` | multiply | `7 * 2` | `14` |
| `/` | divide | `7 / 2` and `7.0 / 2` | `3` and `3.5` (see below!) |
| `%` | remainder ("modulo") | `7 % 2` | `1` |

**Integer division.** When *both* sides of `/` are whole-number types, Java does whole-number division and throws away any fractional part (it does not round). So `7 / 2` is `3`, and `1 / 2` is `0`. If at least one side is a `double`, you get normal division: `7.0 / 2` is `3.5`. This rule is actually useful: binary search and merge sort rely on it to find the middle of a range.

**Remainder.** `a % b` gives what is left over after dividing `a` by `b`. `10 % 3` is `1` because 10 = 3 × 3 + 1. A classic use: `n % 2 == 0` is true exactly when `n` is even.

**Order of operations** follows normal maths: `*`, `/` and `%` happen before `+` and `-`, and operators of equal priority go left to right. Use brackets whenever you are unsure: `(2 + 3) * 4` is 20, while `2 + 3 * 4` is 14.

### Shortcuts

```java title="Shortcuts.java"
int count = 10;
count += 5;    // same as count = count + 5;   → 15
count -= 3;    // same as count = count - 3;   → 12
count *= 2;    // same as count = count * 2;   → 24
count /= 4;    // same as count = count / 4;   → 6
count++;       // add 1  (increment)           → 7
count--;       // subtract 1 (decrement)       → 6
```

### Comparison operators

These compare two values and always produce a `boolean`: `true` or `false`. They are the raw material of every decision a program makes, and of every search and sort algorithm in this course.

| Operator | Question it asks | Example | Result |
| --- | --- | --- | --- |
| `==` | equal to? (two equals signs!) | `5 == 5` | `true` |
| `!=` | not equal to? | `5 != 3` | `true` |
| `<` / `>` | less than? / greater than? | `3 < 5` | `true` |
| `<=` / `>=` | less than or equal? / greater than or equal? | `5 >= 6` | `false` |

<Callout type="mistake">

Confusing `=` (assignment: "becomes") with `==` (comparison: "is equal to?"). `if (x = 5)` does not compile in Java for an `int`, which is lucky; the fix is `if (x == 5)`.

</Callout>

### Logical operators

These combine booleans into bigger conditions.

| Operator | Name | True when… | Example |
| --- | --- | --- | --- |
| `&&` | AND | both sides are true | `age >= 18 && hasTicket` |
| `\|\|` | OR | at least one side is true | `isWeekend \|\| isHoliday` |
| `!` | NOT | the value is false (it flips it) | `!isEmpty` |

`&&` and `||` are **short-circuit** operators: they stop as soon as the answer is known. In `a && b`, if `a` is false the whole thing must be false, so `b` is never even evaluated. Insertion sort uses this deliberately: `while (j >= 0 && a[j] > key)` checks that `j` is a valid position *before* reading `a[j]`, so it never reads outside the array.

## Converting between types (casting)

Java converts automatically when no information can be lost, for example from `int` to `double` (this is called a *widening* conversion). Going the other way could lose information (the decimal part), so Java insists you ask for it explicitly with a **cast**: the target type in brackets.

```java title="Casting.java"
int whole = 7;
double d = whole;               // automatic widening: d is 7.0

double price = 9.99;
int rands = (int) price;        // explicit cast: chops off the fraction → 9 (does NOT round)

int total = 7, count = 2;
double avg1 = total / count;            // 3.0  — integer division happened FIRST, then widened
double avg2 = (double) total / count;   // 3.5  — cast one side first, so real division happens

long rounded = Math.round(9.99);        // 10   — use Math.round when you actually want rounding
```

## `final`: values that never change

Putting `final` in front of a variable means it can be assigned only once. After that, any attempt to change it is a compile error. Use it for constants. By convention, constants that belong to a whole class are written in capitals with underscores: `static final double VAT_RATE = 0.14;`

<Callout type="key">

A variable is a named, typed box. `=` means "becomes". Whole-number division drops the fraction. Compare numbers with `==` but text with `.equals`. Every comparison produces a `boolean`, which is what decisions and algorithms are built on.

</Callout>
