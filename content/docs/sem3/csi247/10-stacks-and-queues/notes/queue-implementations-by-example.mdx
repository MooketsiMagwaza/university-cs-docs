A queue adds at one end, the tail, and removes at the other, the front, so the first element in is the first element out (FIFO). Lecture 16 implements it twice: with a singly linked list that keeps `front` and `tail` references, and with an array that keeps `front` and `tail` indexes. This lesson works through both with the lecture's Exercise 1, the memory after each operation, Java's own `Queue` and `PriorityQueue`, the errors in the lecture's code, and the flaw in the array queue that the lecture warns about. It follows [Stack Implementations by Example](/docs/sem3/csi247/10-stacks-and-queues/notes/stack-implementations-by-example).

## 1. The templates

```text
Queue rule (FIFO):  enqueue adds at the tail; dequeue removes the front element and returns it; peek returns the front without removing it.
                    Elements leave in the order they joined.

Linked queue:       front and tail are REFERENCES (both null when empty).
                    enqueue: oldTail = tail; tail = new node; if the queue was empty front = tail, else oldTail.next = tail
                    dequeue: save front.data; front = front.next; if the queue is now empty tail = null

Array queue:        front and tail are INDEXES (both -1 when empty).
                    enqueue: if the queue is empty front = tail = 0, else tail++; then queue[tail] = element
                    dequeue: take queue[front], then front++        size = tail - front + 1 (0 when front is -1)
```

The four kinds of queue in the lecture:

| Type | Rule |
|---|---|
| Normal queue | FIFO: insert at the tail, remove from the front |
| Circular queue | the last element is connected to the first, forming a circle |
| Double-ended queue (deque) | insertions and deletions at both the front and the tail |
| Priority queue | items are ordered by key value; the item with the lowest (or highest) key is always in front, and insertions keep the ordering |

## 3. Java's Queue

`Queue<E>` is an interface in `java.util` that extends `Collection<E>`, so you cannot create a `Queue` object: a concrete class must implement it. The lecture names `LinkedList`, `PriorityQueue` and `ArrayDeque`. The common methods are `add` (insert), `remove` (remove and return the front element; it throws an exception when the queue is empty) and `peek` (return the front element without removing it; `null` when empty).

```java title="JavaQueueDemo.java"
import java.util.ArrayDeque;
import java.util.Iterator;
import java.util.LinkedList;
import java.util.PriorityQueue;
import java.util.Queue;

public class JavaQueueDemo {
    // Question (Lecture 13 and 16): use a LinkedList and an ArrayDeque as queues, and the lecture's PriorityQueue.
    public static void main(String[] args) {
        Queue<String> list = new LinkedList<String>();
        list.add("Kago");
        list.add("Naledi");
        list.add("Thato");
        System.out.println(list + " peek " + list.peek());
        System.out.println("remove " + list.remove() + ", then " + list);

        Queue<Integer> deque = new ArrayDeque<Integer>();
        deque.add(5);
        deque.add(9);
        System.out.println("ArrayDeque remove " + deque.remove() + ", peek " + deque.peek());

        Queue<String> empty = new LinkedList<String>();
        System.out.println("peek on an empty queue: " + empty.peek());
        try {
            empty.remove();
        } catch (java.util.NoSuchElementException e) {
            System.out.println("remove on an empty queue: " + e.getClass().getName());
        }

        Queue<String> pQueue = new PriorityQueue<String>();
        pQueue.add("Maths");
        pQueue.add("Chemistry");
        pQueue.add("Physics");
        System.out.println(pQueue);
        System.out.println("Queue has " + pQueue.size() + " elements");
        pQueue.remove();
        System.out.println(pQueue);
        System.out.println("Queue has " + pQueue.size() + " elements");
        Iterator<String> iterator = pQueue.iterator();
        while (iterator.hasNext()) {
            System.out.print(iterator.next() + " ");
        }
        System.out.println();
    }
}
```

```text
[Kago, Naledi, Thato] peek Kago
remove Kago, then [Naledi, Thato]
ArrayDeque remove 5, peek 9
peek on an empty queue: null
remove on an empty queue: java.util.NoSuchElementException
[Chemistry, Maths, Physics]
Queue has 3 elements
[Maths, Physics]
Queue has 2 elements
Maths Physics
```

A `LinkedList` or an `ArrayDeque` used as a queue gives FIFO order: the first element added (Kago) is the one removed. `peek` on an empty queue returns `null`, but `remove` throws `NoSuchElementException`. The `PriorityQueue` is different: it keeps the items ordered by their natural order, so the string that comes first alphabetically (Chemistry) is in front and is the one `remove()` takes, whatever the order of the `add` calls. Printing a `PriorityQueue` does not show the items in sorted order; only the front is guaranteed to be the lowest.

### Priority queue order

```java title="PriorityOrder.java"
import java.util.PriorityQueue;
import java.util.Queue;

public class PriorityOrder {
    // Question: in what order does a priority queue of integers give its elements back?
    public static void main(String[] args) {
        Queue<Integer> pq = new PriorityQueue<Integer>();
        int[] values = {40, 10, 30, 20};
        for (int v : values) {
            pq.add(v);
        }
        StringBuilder out = new StringBuilder();
        while (!pq.isEmpty()) {
            out.append(pq.remove()).append(" ");
        }
        System.out.println("added 40 10 30 20; removed " + out.toString().trim());
    }
}
```

```text
added 40 10 30 20; removed 10 20 30 40
```

Removing the front repeatedly gives the integers lowest first: 10, 20, 30, 40, although they were added in a different order. The lecture says a priority queue is normally represented with a heap, but it can also use an array or a linked list.

## 4. The linked queue

The linked queue is a singly linked list with a `front` reference (where elements leave) and a `tail` reference (where they join). There is no size limit, so `isFull()` does not apply. The lecture calls the class `Queue1` and stores `String` values; here it is `LinkedQueue`, so that it can sit beside the array queue.

<MemoryDiagram scenario="queuelinked" />

```java title="LinkedQueue.java"
public class LinkedQueue {
    private class Node {
        String data;                          // the node's data part
        Node next;                            // a pointer to the next node in the queue

        Node(String data) {
            this.data = data;
            this.next = null;                 // the last node of the queue
        }
    }

    public Node front;                        // keeps track of the front node
    public Node tail;                         // keeps track of the last node

    public LinkedQueue() {                    // initially the queue is empty
        front = null;
        tail = null;
    }

    public boolean isEmpty() {
        return front == null;
    }

    public int size() {                       // the lecture's take-home method: count the nodes
        int count = 0;
        for (Node cur = front; cur != null; cur = cur.next) {
            count++;
        }
        return count;
    }

    public void enqueue(String data) {
        Node oldTail = tail;
        tail = new Node(data);                // the new tail
        if (isEmpty()) {
            front = tail;                     // the first node is also the front
        } else {
            oldTail.next = tail;
        }
    }

    public String dequeue() {
        if (isEmpty()) {
            return null;                      // nothing to remove
        }
        String data = front.data;
        front = front.next;
        if (isEmpty()) {
            tail = null;                      // the queue became empty: tail must not keep the old node
        }
        return data;
    }

    public String peek() {
        if (!isEmpty()) {
            return front.data;
        }
        return null;                          // no element in the queue
    }

    public boolean contains(String key) {
        for (Node cur = front; cur != null; cur = cur.next) {
            if (cur.data.equals(key)) {
                return true;
            }
        }
        return false;
    }

    public String getFront() {
        return front == null ? null : front.data;
    }

    public String getTail() {
        return tail == null ? null : tail.data;
    }
}
```

```text
empty queue: dequeue null, peek null
one element: front Kago, tail Kago
dequeue Kago
now: empty true, front null, tail null
enqueue again: front Mpho, tail Mpho, size 1
```

With one element, `front` and `tail` refer to the same node. After the dequeue `front` is `null`, and the line `tail = null` makes `tail` agree with it. If that line were missing, `tail` would still refer to the removed node: `getTail()` would return its data for an empty queue, and the old node could not be garbage collected.

### The lecture's dequeue, as printed

The lecture prints `dequeue()` with `String data` declared inside the `if (!isEmpty())` block and `return data;` after the closing brace:

```java
public String dequeue() {
    if (! isEmpty()) {
        String data = front.data;
        front = front.next;
        if (isEmpty())
            tail = null;
    }
    return data;
}
```

`javac` reports `error: cannot find symbol` for `data` in the `return` line, because a variable declared in a block exists only inside that block. The repair is to return inside the block and to return `null` for the empty queue, as in `LinkedQueue` above. The lecture's tester also mixes `Queue1`, `Queue2`, `q`, `q1` and `e` for the same object; make the class name and the variable consistent before compiling.

<Callout type="mistake" title="Common error">

Forgetting that the first `enqueue` must set **both** references. On an empty queue `oldTail` is `null`, so `oldTail.next = tail` would throw `NullPointerException`; the lecture's `enqueue` therefore tests `isEmpty()` and sets `front = tail` instead.

</Callout>

## 5. The array queue

The array queue stores the elements in an array and keeps two indexes, `front` and `tail`. Initially the queue is empty and both indexes are -1, smaller than the smallest array index. Because the array has a fixed size, an `enqueue` on a full queue must be refused, and the lecture warns: "Careful: Overflow!!! (ArrayIndexOutOfBounds)".

<MemoryDiagram scenario="queuearray" />

```java title="ArrayQueue.java"
public class ArrayQueue {
    private String[] queue;                   // an array to store the queue elements
    private int front;                        // the index of the front element
    private int tail;                         // the index of the tail element

    public ArrayQueue(int n) {
        queue = new String[n];                // an array of the specified size
        front = -1;                           // -1 for an empty queue
        tail = -1;
    }

    public int size() {                       // the lecture's take-home method
        if (front < 0) {
            return 0;                         // nothing has been enqueued yet
        }
        return tail - front + 1;              // 0 when front has moved past tail
    }

    public boolean isEmpty() {
        return size() == 0;
    }

    public boolean isFull() {                 // the lecture's test: all array slots occupied
        return size() == queue.length;
    }

    public boolean isFullAtBack() {           // a repair for this design: no room after the tail
        return tail == queue.length - 1;
    }

    public void enqueue(String elem) {
        if (isFull()) {
            System.out.println("Full!!");
        } else {
            if (isEmpty()) {
                front = tail = 0;             // index 0
            } else {
                tail++;                       // advance tail
            }
            queue[tail] = elem;               // store the data
        }
    }

    public String dequeue() {
        if (isEmpty()) {
            return null;
        }
        String ele = queue[front];
        front++;                              // the element leaves the queue, not the array
        return ele;
    }

    public String peek() {
        if (!isEmpty()) {
            return queue[front];
        }
        return null;                          // queue empty: no front element
    }

    public boolean contains(String key) {
        if (isEmpty()) {
            System.out.println("Empty.");
        } else {
            for (int i = front; i <= tail; i++) {   // only the slots that are in the queue
                if (queue[i].equals(key)) {
                    return true;
                }
            }
        }
        return false;
    }

    @Override
    public String toString() {
        StringBuilder sb = new StringBuilder("front=" + front + " tail=" + tail + " [");
        for (int i = 0; i < queue.length; i++) {
            sb.append(queue[i]);
            if (i < queue.length - 1) {
                sb.append(", ");
            }
        }
        return sb.append("]").toString();
    }
}
```

### The effect of enqueue and dequeue on front and tail

```java title="FrontAndTail.java"
public class FrontAndTail {
    // Question (Lecture 16 pictures): enqueue 26, 69, 48 into an array of 6, then dequeue three times, then enqueue 52.
    public static void main(String[] args) {
        ArrayQueue q = new ArrayQueue(6);
        System.out.println("new:          " + q + " size " + q.size());
        q.enqueue("26");
        System.out.println("enqueue 26:   " + q + " size " + q.size());
        q.enqueue("69");
        q.enqueue("48");
        System.out.println("enqueue 69, 48: " + q + " size " + q.size());
        System.out.println("dequeue " + q.dequeue() + ":   " + q + " size " + q.size());
        System.out.println("dequeue " + q.dequeue() + ":   " + q + " size " + q.size());
        System.out.println("dequeue " + q.dequeue() + ":   " + q + " size " + q.size() + ", empty " + q.isEmpty());
        q.enqueue("52");
        System.out.println("enqueue 52:   " + q + " size " + q.size());
    }
}
```

```text
new:          front=-1 tail=-1 [null, null, null, null, null, null] size 0
enqueue 26:   front=0 tail=0 [26, null, null, null, null, null] size 1
enqueue 69, 48: front=0 tail=2 [26, 69, 48, null, null, null] size 3
dequeue 26:   front=1 tail=2 [26, 69, 48, null, null, null] size 2
dequeue 69:   front=2 tail=2 [26, 69, 48, null, null, null] size 1
dequeue 48:   front=3 tail=2 [26, 69, 48, null, null, null] size 0, empty true
enqueue 52:   front=0 tail=0 [52, 69, 48, null, null, null] size 1
```

The first `enqueue` sets `front = tail = 0`; every further one moves `tail` forwards by one. A `dequeue` removes the item from the **queue**, not from the array: it only moves `front` forwards, so the old strings stay in the array (the printed array still shows `26`, `69` and `48` after they were dequeued). `front` keeps increasing until it passes `tail`; at that moment `size()` is `tail - front + 1 = 0` and the queue is empty. The next `enqueue` sees an empty queue and sets both indexes back to 0, overwriting the stale `26` with `52`.

### The flaw: overflow with free slots

The lecture's `isFull()` compares the **number of elements** with the length of the array. But `enqueue` always moves `tail` forwards, and a `dequeue` moves `front` forwards without freeing the slots behind it. So a queue can have free slots in front of `front` and still run out of array behind `tail`.

```java title="ArrayQueueFlaw.java"
public class ArrayQueueFlaw {
    // Question: enqueue A, B, C, D into an array of 4, dequeue one, then enqueue E. What happens?
    public static void main(String[] args) {
        ArrayQueue q = new ArrayQueue(4);
        String[] letters = {"A", "B", "C", "D"};
        for (String s : letters) {
            q.enqueue(s);
        }
        System.out.println("dequeue " + q.dequeue() + ": size " + q.size() + ", isFull " + q.isFull() + ", isFullAtBack " + q.isFullAtBack());
        try {
            q.enqueue("E");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("enqueue E: " + e.getClass().getName());
        }
        System.out.println(q);
    }
}
```

```text
dequeue A: size 3, isFull false, isFullAtBack true
enqueue E: java.lang.ArrayIndexOutOfBoundsException
front=1 tail=4 [A, B, C, D]
```

After one dequeue the queue holds three elements in an array of four, so the lecture's `isFull()` says there is room. But `tail` is already the last index (3), so `tail++` makes it 4 and `queue[4]` throws `ArrayIndexOutOfBoundsException`. The failed call has also left the queue damaged: `tail++` ran before the store, so `tail` is now 4, outside the array (the last line of the output). One repair for this design is to test whether there is room **after the tail**, `tail == queue.length - 1`, which is what `isFullAtBack()` does; the cost is that the free slot in front is wasted until the queue empties. The queue types in the lecture's list include the **circular queue**, in which the last element is connected to the first, precisely so that the slots at the start can be reused.

### Exam question 3: why the queue overflows (6 marks)

An array queue of capacity 4 holds the elements A, B, C and D. A is dequeued, and then `enqueue("E")` is called. Explain what happens and why, although the queue holds only three elements. Give one repair. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The queue has three elements, so a test that counts elements says "not full". The question is about where `tail` is, not how many elements there are.

</Step>

<Step title="2. Plan">

Follow the indexes: four enqueues put `front = 0` and `tail = 3`. The dequeue makes `front = 1`. `enqueue` then does `tail++`.

</Step>

<Step title="3. Solution">

`isFull()` compares `size()` (3) with `queue.length` (4), so it is `false` and `enqueue` goes ahead. It executes `tail++`, so `tail` becomes 4, and `queue[tail] = elem` stores outside the array: `ArrayIndexOutOfBoundsException`. Slot 0 is free but unreachable, because `tail` only moves forwards. **Repair:** refuse the `enqueue` when `tail == queue.length - 1` (no room after the tail), or use a circular queue in which `tail` wraps round to the start.

</Step>

<Step title="4. Check">

The program above printed the exception for this exact sequence, and `isFullAtBack()` was `true` at the same moment. The flaw does not occur when the queue becomes empty, because the next `enqueue` resets `front` and `tail` to 0.

</Step>

</Steps>

### Exam question 4: dequeue in the linked queue (6 marks)

Write `dequeue()` for a linked queue with `front` and `tail` references. Explain why it sets `tail = null` in one case, and say what `javac` reports for the lecture's version that returns `data` outside the `if`. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A method, an explanation and a compiler message. The method removes the front node and returns its data, and the empty queue has no front node.

</Step>

<Step title="2. Plan">

If the queue is empty, return `null`. Otherwise save `front.data`, move `front` to `front.next`, and, if the queue is now empty, set `tail` to `null` as well. Return the saved data.

</Step>

<Step title="3. Solution">

```java
public String dequeue() {
    if (isEmpty()) {
        return null;
    }
    String data = front.data;
    front = front.next;
    if (isEmpty()) {
        tail = null;
    }
    return data;
}
```

When the last node is removed, `front` becomes `null` but `tail` would still refer to the removed node; setting `tail = null` keeps the two references consistent. In the lecture's version `data` is declared inside the `if` block and returned after it, so `javac` reports `error: cannot find symbol` (`symbol: variable data`).

</Step>

```java title="GenQueue.java"
public class GenQueue<T> {
    private class Node {
        T data;
        Node next;

        Node(T data) {
            this.data = data;
        }
    }

    private Node front;
    private Node tail;

    public boolean isEmpty() {
        return front == null;
    }

    public void enqueue(T data) {
        Node n = new Node(data);
        if (isEmpty()) {
            front = n;
        } else {
            tail.next = n;
        }
        tail = n;
    }

    public T dequeue() {
        if (isEmpty()) {
            return null;
        }
        T data = front.data;
        front = front.next;
        if (front == null) {
            tail = null;
        }
        return data;
    }

    public boolean contains(T key) {
        for (Node cur = front; cur != null; cur = cur.next) {
            if (cur.data.equals(key)) {
                return true;
            }
        }
        return false;
    }
}
```

```java title="GenArrayQueue.java"
public class GenArrayQueue<T> {
    private T[] queue;
    private int front = -1;
    private int tail = -1;

    @SuppressWarnings("unchecked")
    public GenArrayQueue(int n) {
        queue = (T[]) new Object[n];          // an array of T cannot be created directly
    }

    public int size() {
        return front < 0 ? 0 : tail - front + 1;
    }

    public boolean isFullAtBack() {
        return tail == queue.length - 1;
    }

    public boolean enqueue(T elem) {
        if (isFullAtBack()) {
            return false;
        }
        if (size() == 0) {
            front = tail = 0;
        } else {
            tail++;
        }
        queue[tail] = elem;
        return true;
    }

    public T dequeue() {
        if (size() == 0) {
            return null;
        }
        return queue[front++];
    }
}
```

## 7. Linked queue or array queue?

| | Linked queue | Array queue |
|---|---|---|
| `front` and `tail` are | references to nodes | indexes |
| Empty when | `front == null` | `front == -1`, or `front` is past `tail` |
| Capacity | none: grows and shrinks dynamically | fixed by the array size |
| `isFull()` | not applicable | needed (and the design can overflow as shown) |
| `enqueue`, `dequeue`, `peek` | O(1) | O(1) |
| Per element | the value and a reference (a node) | the value |

## Summary

<Callout type="key" title="Remember">

A queue joins at the tail and leaves at the front (FIFO): elements come out in the order they went in. A linked queue keeps `front` and `tail` references; the first `enqueue` sets both, and the dequeue that empties the queue must set `tail` to `null` as well. An array queue keeps `front` and `tail` indexes (both -1 when empty): `enqueue` moves `tail`, `dequeue` moves `front` and erases nothing, and `size()` is `tail - front + 1`. Because both indexes only move forwards, the array queue can run out of room behind `tail` while it has free slots in front; a circular queue is the type that reuses them. Java's `Queue` is an interface (`LinkedList`, `ArrayDeque`, `PriorityQueue`): `add`, `remove` (throws when empty) and `peek` (`null` when empty); a priority queue keeps the lowest key in front.

</Callout>

Nothing: it returns `queue[front]` and moves `front` forwards. The element leaves the queue but stays in the array until a later `enqueue` overwrites it.

<CheckQuestion question="Why does Queue.remove() throw an exception on an empty queue while peek() returns null?">

`remove()` must return the removed element and cannot do so, so it reports the error; `peek()` only looks at the front and returns `null` when there is none.

Lowest first: 10, 20, 30, 40. The item with the lowest key is always in front, whatever the order of the insertions.
