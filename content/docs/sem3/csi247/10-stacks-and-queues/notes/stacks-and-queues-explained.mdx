## Stacks: last in, first out

<Callout type="analogy">

A pile of plates. You put a clean plate on **top** of the pile, and you take a plate from the **top**. The plate you put down last is the first one you pick up. You can't pull one out of the middle.

</Callout>

<KeyTerm title="Stack (LIFO)">

A collection where items are added and removed at only one end, called the **top**. The last item in is the first item out: **LIFO**.

</KeyTerm>

| Operation | What it does | Cost |
| --- | --- | --- |
| `E push(E item)` | Puts `item` on top | O(1) |
| `E pop()` | Removes the top item and returns it | O(1) |
| `E peek()` | Returns the top item *without* removing it ("take a look") | O(1) |
| `boolean empty()` | `true` if the stack has no items | O(1) |

<SvgFigure src="sem3/csi247/10-stacks-and-queues/notes/stacks-and-queues-explained" id="stacks-queues-1">

**Figure 29.1** Everything happens at the top. After `push(1)`, `push(2)`, `push(3)`, `pop()`, `push(4)` the stack is 1, 2, 4 (bottom to top), and `peek()` returns 4.

</SvgFigure>

**Where stacks are used:** the undo button (the last thing you did is the first thing undone); the browser's back button; checking that brackets match in an expression; evaluating expressions; and the [call stack](/docs/sem3/csi247/01-java-fundamentals/notes/arrays-and-methods) itself, which is why a method that calls another must wait until that one returns.

### Java's `Stack` class

`java.util.Stack<E>` is a generic class (`public class Stack<E> extends Vector<E>`).

```java title="StackDemo.java"
import java.util.*;

Stack<String> stack = new Stack<String>();
stack.push("Data Structures");
stack.push("Big Java");
stack.push("Java for Everyone");
stack.push("Marketing Principles");
stack.push("Financial Markets");      // the last one pushed is now on top

System.out.println(stack.size());
System.out.println(stack);            // printed bottom → top
System.out.println(stack.pop());      // removes the TOP
System.out.println(stack.pop());
System.out.println(stack);
System.out.println(stack.size());
```

```text
5
[Data Structures, Big Java, Java for Everyone, Marketing Principles, Financial Markets]
Financial Markets
Marketing Principles
[Data Structures, Big Java, Java for Everyone]
3
```

Notice that printing a `Stack` lists it from bottom to top, so the top is at the *right* end.

<Callout type="mistake">

Calling `pop()` or `peek()` on an empty `Stack` throws `EmptyStackException`. Check with `empty()` first: `if (!stack.empty()) x = stack.pop();`

</Callout>

## Queues: first in, first out

<Callout type="analogy">

The queue at the cafeteria, the bank or the bus stop. New people join at the **back**; the person at the **front** is served next. Whoever arrived first leaves first.

</Callout>

<KeyTerm title="Queue (FIFO)">

A collection where items are added at one end, the **rear** (or tail), and removed from the other end, the **front** (or head). The first item in is the first item out: **FIFO**.

</KeyTerm>

<SvgFigure src="sem3/csi247/10-stacks-and-queues/notes/stacks-and-queues-explained" id="stacks-queues-2">

**Figure 29.2** Ann arrived first and is served first. Dee just joined at the rear.

</SvgFigure>

### Queues in Java

`Queue<E>` is an *interface* (`public interface Queue<E> extends Collection<E>`), so you can't write `new Queue`. You create an object of a class that implements it, most commonly `LinkedList` (an ordinary FIFO queue) or `PriorityQueue`.

| Method | What it does |
| --- | --- |
| `boolean add(E e)` | Inserts at the rear. Returns `true`; throws `IllegalStateException` if a size-limited queue is full. |
| `E remove()` | Removes and returns the front item (throws an exception if the queue is empty). |
| `E peek()` | Returns the front item without removing it, or `null` if the queue is empty. |
| `boolean isEmpty()`, `int size()` | Is it empty? How many items? |
| `boolean contains(Object o)` | Is `o` in the queue? |
| `Iterator iterator()`, `Object[] toArray()` | Walk through it; copy it to an array. |

<Callout type="note">

There's also a gentler pair: `offer(e)` (like `add`, but returns `false` instead of throwing when full) and `poll()` (like `remove`, but returns `null` when empty).

</Callout>

### An ordinary FIFO queue

```java title="QueueDemo.java"
Queue<String> q = new LinkedList<>();   // LinkedList: add at the tail, remove at the head, both O(1)
q.add("Ann");
q.add("Ben");
q.add("Cy");
System.out.println(q + " " + q.peek());       // [Ann, Ben, Cy] Ann
System.out.println(q.remove() + " " + q);     // Ann [Ben, Cy]     ← first in, first out
```

### The lecture's example: a `PriorityQueue`

A **priority queue** doesn't serve in arrival order. It always serves the item with the *highest priority* first, and for Strings and numbers that means the **smallest** one (alphabetically first, or lowest number). Think of a hospital emergency room: the most urgent patient goes first, whoever came in first.

```java title="PQDemo.java"
import java.util.Queue;
import java.util.PriorityQueue;
import java.util.Iterator;

Queue<String> pQueue = new PriorityQueue<String>();
pQueue.add("Maths");
pQueue.add("Chemistry");
pQueue.add("Physics");
System.out.println(pQueue);
System.out.println("Queue has " + pQueue.size() + " elements");
pQueue.remove();                         // removes the HIGHEST-PRIORITY item: Chemistry (alphabetically first)
System.out.println(pQueue);
System.out.println("Queue has " + pQueue.size() + " elements");

Iterator<String> iterator = pQueue.iterator();
while (iterator.hasNext()) {
    System.out.print(iterator.next() + " ");
}
System.out.println();
```

```text
[Chemistry, Maths, Physics]
Queue has 3 elements
[Maths, Physics]
Queue has 2 elements
Maths Physics
```

<Callout type="mistake">

Assuming `remove()` took out "Maths" because it was added first. That's what a plain FIFO queue would do, but a `PriorityQueue` removes the *smallest* element, "Chemistry". Also, a `PriorityQueue` only guarantees that the *front* is the smallest; printing it or iterating over it isn't guaranteed to show everything in sorted order (with only a few items, it often happens to look sorted).

</Callout>

## Tracing stacks and queues

Exams often list operations and ask for the final contents. Keep a column for the structure and one for the value returned:

<TraceTable>

| Operation | Stack (bottom → top) | Returned | Queue (front → rear) | Returned |
| --- | --- | --- | --- | --- |
| add/push 1 | `1` |   | `1` |   |
| add/push 2 | `1 2` |   | `1 2` |   |
| add/push 3 | `1 2 3` |   | `1 2 3` |   |
| remove/pop | `1 2` | 3 | `2 3` | 1 |
| add/push 4 | `1 2 4` |   | `2 3 4` |   |
| peek | `1 2 4` | 4 | `2 3 4` | 2 |

</TraceTable>

Same operations, different results: that is LIFO versus FIFO in one table.

## Building them yourself

Both are easy to build on a linked list, with every operation O(1):

- **Stack**: push = `addFirst`, pop = `removeFirst`, peek = `getFirst`. The head of the list is the top of the stack.
- **Queue**: add = `addLast` (needs a `tail` reference to be O(1)), remove = `removeFirst`, peek = `getFirst`.

A stack can also be built on an `ArrayList` by pushing and popping at the *end*, where adding and removing don't shift anything.

<Callout type="key">

Stack = LIFO: `push`, `pop`, `peek` at the top. Queue = FIFO: `add` at the rear, `remove`/`peek` at the front. `Queue` is an interface: use `LinkedList` for FIFO, `PriorityQueue` to always serve the smallest first.

</Callout>
