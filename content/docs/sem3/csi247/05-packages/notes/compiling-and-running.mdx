**Compiling** turns Java source into class files. **Running** asks Java to find a compiled class by its fully qualified name and invoke its main method. A **root** is the directory before the package path.

<PackageBuildStory />

## 1. Worked example A: compile and run A/B/Tester

Run commands from `project`, the parent of `src` and `classes`. The previous lesson supplies fully commented A.java, B.java and Tester.java. Compiling all three explicitly makes the first build easy to follow.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-1">

Three source files produce three class files under one output root.

</SvgFigure>

```text
javac -d classes -sourcepath src src/pkg/A.java src/pkg/B.java src/app/Tester.java
java -cp classes app.Tester
```

| Stage | Evaluated lookup/action | Result |
|---|---|---|
| Compile A | Declaration = pkg; output root = classes | classes/pkg/A.class |
| Compile B | Declaration = pkg; output root = classes | classes/pkg/B.class |
| Compile Tester | Declaration = app; output root = classes | classes/app/Tester.class |
| Load main | classes + app/Tester.class; exists? true | app.Tester loaded |
| Construct A/B | classes + pkg/A.class and pkg/B.class; exist? true | Dependencies loaded |
| Execute | Public static main found? true | Prints 42, then class B |

The class name in the launcher is `app.Tester`, not a filename. With a directory classpath, Java maps that name to `app/Tester.class` below the root.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-2">

Classpath root plus binary name selects the compiled file.

</SvgFigure>

## 2. Worked example B: let sourcepath find dependencies

On a clean output directory, `javac -d classes -sourcepath src src/app/Tester.java` can discover A and B when their sources are correctly located. The imports establish source names; `-sourcepath` supplies places to find those names.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-3">

Dependency discovery uses the mirrored source tree.

</SvgFigure>

| Needed type | Root | Constructed source path | Evaluated condition |
|---|---|---|---|
| pkg.A | src | src/pkg/A.java | Found? true → compile A |
| pkg.B | src | src/pkg/B.java | Found? true → compile B |
| pkg.A with source only in scratch | src | src/pkg/A.java | Found? false → look for another usable definition or report failure |

Already compiled dependencies can instead be supplied through `-cp classes`. `-sourcepath` concerns source files; `-cp` concerns compiled definitions. A compiler classpath and a runtime classpath have separate invocations; setting one command does not configure the other.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-4">

The compiler can use both source and compiled dependencies; the launcher uses compiled classes.

</SvgFigure>

## 3. Worked example C: a different package root

For `school.app.Main` importing `school.people.Student`, the root is still `src` for sources and `classes` for output. It is not `src/school` or `classes/school`.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-5">

The full package path follows the root; no package component is removed.

</SvgFigure>

```text
javac -d classes -sourcepath src src/school/app/Main.java
java -cp classes school.app.Main
```

## 4. Worked example D: trace failures before changing code

With files under `classes/app` and `classes/pkg`, these launcher commands request different things.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-6">

A file can be physically present yet have the wrong identity for the requested name.

</SvgFigure>

| Command or diagnostic | Evaluated question | Diagnosis/repair |
|---|---|---|
| `java -cp classes app.Tester` | Correct file and binary name? true | Runs |
| `java -cp classes/app app.Tester` | classes/app/app/Tester.class exists? false | Root should be classes |
| `java -cp classes/app Tester` | Bytecode identity equals Tester? false | Root classes; name app.Tester |
| `java -cp classes Tester` | classes/Tester.class exists? false | Include package in name |
| `package pkg does not exist` | Compiler can locate required source/class? false | Check declaration, input roots and paths |
| `doubled() is not public` | Class found? true; member access allowed? false | Fix intended API access, not classpath |
| `Main method not found` | Class found? true; required entry point present? false | Check method signature and chosen target |

Classify the layer first: parse source, resolve names, check access, load classes, then enter main. Import edits cannot repair the launcher's root, and a larger classpath cannot open a private member.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-7">

Locate the failing stage before choosing a repair.

</SvgFigure>

## 5. Properties and platform rules

| Item | Meaning |
|---|---|
| `-d classes` | Output root; javac creates subdirectories from declared packages |
| `-sourcepath src` | Root(s) for automatic source dependency lookup |
| `-cp classes` | Root(s) for compiled class lookup; valid on javac and java |
| `-classpath` | Equivalent spelling of -cp |
| Windows multiple entries | Separate with `;`: `classes;lib/example.jar` |
| Linux/macOS multiple entries | Separate with `:`: `classes:lib/example.jar` |
| Source paths | Paths identify files; forward slashes work in the shown Java commands |
| Type names | Case-sensitive dotted names; do not append .class |

A named package is determined by its declaration, not the working directory. An absolute classpath root also works when launching from another directory.

<SvgFigure src="sem3/csi247/05-packages/notes/compiling-and-running" id="diagram-8">

Changing where the shell starts does not rename the class.

</SvgFigure>

## 6. Fully commented Java to inspect identities

The previous lesson's A/B/Tester is the complete build exercise. Save this additional entry point as `src/app/LookupCheck.java` to inspect the identities Java records.

```java
package app; // This entry point's binary name is app.LookupCheck.

import pkg.A; // Name resolution in this source only.
import pkg.B; // Both public dependency classes still live in pkg.

public class LookupCheck {
    public static void main(String[] args) {
        // Class literals inspect identities without confusing them with paths.
        System.out.println(A.class.getName()); // pkg.A
        System.out.println(B.class.getName()); // pkg.B
        System.out.println(LookupCheck.class.getName()); // app.LookupCheck
        A value = new A(21); // Requires accessible class and public constructor.
        System.out.println(value.doubled()); // Uses the public API; prints 42.
    }
}
```

```text
javac -d classes -sourcepath src src/app/LookupCheck.java
java -cp classes app.LookupCheck
```

```text
pkg.A
pkg.B
app.LookupCheck
42
```
