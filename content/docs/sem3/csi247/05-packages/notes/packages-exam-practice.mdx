## 1. How to answer these questions

1. **Read.** Underline what is asked: the package, the import, the folder, the command, the message.
2. **Plan.** For a package question, write the layout first: `src/packageName/ClassName.java` and `classes`.
3. **Solve.** Write each command in order: compile the package, compile the tester, run the tester, always from the folder above `src` and `classes`.
4. **Check.** Does each file start with the right `package` statement, is the class `public`, and does every `import` name the package and the class?

## 2. Packages and imports

### Exam question 1: which package? (6 marks)

State the package of `Scanner`, `String`, `PrintWriter`, `StringTokenizer`, `Math`, `Random` and `FileReader`, and say which of them need an import. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Seven classes from the lecture and from earlier labs; for each, its package and whether an import is needed.

</Step>

<Step title="2. Plan">

`java.lang` holds the fundamental classes and is imported by default. `java.util` holds the collections framework and utility classes. `java.io` holds the classes for file input and output.

</Step>

<Step title="3. Solution">

| Class | Package | Import needed? |
|---|---|---|
| `String` | `java.lang` | no: `java.lang` is imported by default |
| `Math` | `java.lang` | no |
| `Scanner` | `java.util` | yes: `import java.util.Scanner;` or `java.util.*` |
| `StringTokenizer` | `java.util` | yes |
| `Random` | `java.util` | yes |
| `PrintWriter` | `java.io` | yes: `import java.io.PrintWriter;` or `java.io.*` |
| `FileReader` | `java.io` | yes |

</Step>

<Step title="4. Check">

The packages were printed by asking each class for its full name:

```java title="WhichPackage.java"
import java.io.FileReader;
import java.io.PrintWriter;
import java.util.Random;
import java.util.Scanner;
import java.util.StringTokenizer;

public class WhichPackage {
    public static void main(String[] args) {
        System.out.println(String.class.getName());
        System.out.println(Math.class.getName());
        System.out.println(Scanner.class.getName());
        System.out.println(StringTokenizer.class.getName());
        System.out.println(Random.class.getName());
        System.out.println(PrintWriter.class.getName());
        System.out.println(FileReader.class.getName());
    }
}
```

```text
java.lang.String
java.lang.Math
java.util.Scanner
java.util.StringTokenizer
java.util.Random
java.io.PrintWriter
java.io.FileReader
```

The full name is the package, a dot and the class name. `String` and `Math` compiled without an import in this program, while the other five have one.

</Step>

</Steps>

</details>

### Exam question 2: names that follow the recommendation (4 marks)

The lecture recommends that a package name starts with a lowercase letter and uses a capital at the beginning of each new word. Which of these names follow it: `pkg`, `bankAccounts`, `BankAccounts`, `bank_accounts`? (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Four names and a two-part rule: a lowercase first letter, and a capital at the start of each new word.

</Step>

<Step title="2. Plan">

Check each name against both parts. A one-word name has no new word, so only the first part applies.

</Step>

<Step title="3. Solution">

`pkg` follows it (one word, lowercase). `bankAccounts` follows it (lowercase first letter, a capital at the start of the second word). `BankAccounts` does not: it starts with a capital. `bank_accounts` does not follow the recommendation either: it joins the words with an underscore instead of a capital letter.

</Step>

<Step title="4. Check">

The same convention is what the lecture's example `pkg` uses. Whatever name you choose, it must be written the same way in the `package` statement, in the folder name and in the `import`.

</Step>

</Steps>

</details>

## 3. Creating and using a package

### Exam question 3: build a package (12 marks)

Create a package `bankAccounts` with a class `Account` (a balance and `deposit`, `getBalance`) and a class `Savings` that uses `Account`. Write a tester that deposits into a savings object and prints the balance. Give the layout and the commands. (12 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A package of two classes, one using the other, a tester outside the package, the layout and the commands.

</Step>

<Step title="2. Plan">

Layout: `src/bankAccounts/Account.java`, `src/bankAccounts/Savings.java`, `src/BankTester.java`, and `classes`. The two classes begin with `package bankAccounts;`; the classes and the methods the tester calls are `public`. Compile the package, then the tester with `-classpath classes`, then run from the folder above `src` and `classes`.

</Step>

<Step title="3. Solution">

```java title="src/bankAccounts/Account.java" project="bank"
package bankAccounts;

public class Account {
    private double balance;

    public void deposit(double amount) {
        balance += amount;
    }

    public double getBalance() {
        return balance;
    }
}
```

```java title="src/bankAccounts/Savings.java" project="bank"
package bankAccounts;

public class Savings extends Account {          // same package: no import needed
    private final double rate = 0.05;

    public void addInterest() {
        deposit(getBalance() * rate);
    }
}
```

```java title="src/BankTester.java" project="bank"
import bankAccounts.Savings;

public class BankTester {
    public static void main(String[] args) {
        Savings s = new Savings();
        s.deposit(1000);
        s.addInterest();
        System.out.println(s.getBalance());
    }
}
```

```text title="terminal" project="bank"
$ mkdir classes
$ javac -d classes -sourcepath src src/bankAccounts/Account.java
$ javac -d classes -sourcepath src src/bankAccounts/Savings.java
$ ls classes/bankAccounts
Account.class
Savings.class
$ javac -d classes -classpath classes src/BankTester.java
$ java -classpath classes BankTester
1050.0
```

</Step>

<Step title="4. Check">

The compiled package is in `classes/bankAccounts` with a class file for each source file. `Savings` needs no import for `Account` because they are in the same package; the tester is in the default package and imports `bankAccounts.Savings`. It can call `deposit` and `getBalance`, which are inherited public methods.

</Step>

</Steps>

</details>

### Exam question 4: the file is in the wrong folder (8 marks)

A student saved `Account.java`, which begins with `package bankAccounts;`, directly in `src` instead of in `src/bankAccounts`. Explain what the compiler reports for the tester, and repair it. (8 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The `package` statement says the class is in `bankAccounts`, but the file is not in a folder of that name. The tester asks the compiler for `bankAccounts.Account`.

</Step>

<Step title="2. Plan">

`-sourcepath src` makes the compiler look for the source of `bankAccounts.Account` at `src/bankAccounts/Account.java`. The folder mirrors the package name, so a file in the wrong folder is not found.

</Step>

<Step title="3. Solution">

```java title="src/Account.java" project="bank2"
package bankAccounts;

public class Account {
    public String owner() {
        return "Kago";
    }
}
```

```java title="src/AccountTester.java" project="bank2"
import bankAccounts.Account;

public class AccountTester {
    public static void main(String[] args) {
        System.out.println(new Account().owner());
    }
}
```

```text title="terminal" project="bank2"
$ mkdir classes
$ javac -d classes -sourcepath src src/AccountTester.java
src\AccountTester.java:1: error: package bankAccounts does not exist
import bankAccounts.Account;
                   ^
src\AccountTester.java:5: error: cannot access Account
        System.out.println(new Account().owner());
                               ^
  bad source file: src\Account.java
    file does not contain class Account
    Please remove or make sure it appears in the correct subdirectory of the sourcepath.
src\Account.java:3: error: duplicate class: bankAccounts.Account
public class Account {
       ^
3 errors
```

The repair is to put the file where the package name says, `src/bankAccounts/Account.java`, and compile again:

```java title="src/bankAccounts/Account.java" project="bank2"
package bankAccounts;

public class Account {
    public String owner() {
        return "Kago";
    }
}
```

```text title="terminal" project="bank2"
$ javac -d classes -sourcepath src src/AccountTester.java
$ java -classpath classes AccountTester
Kago
```

</Step>

<Step title="4. Check">

The first message, `package bankAccounts does not exist`, points at the import line: the compiler found no folder `bankAccounts` under `src`. The others come from the compiler opening `src/Account.java` while it searched, finding that it declares `bankAccounts.Account`, and complaining that the file "does not contain class Account" and that it should appear "in the correct subdirectory of the sourcepath". Both point to the same repair: the folder is named like the package, as the lecture's steps ask.

</Step>

</Steps>

</details>

## 4. Access across packages

### Exam question 5: protected across packages (8 marks)

The class `Animal` in the package `base` has a `protected` method `sound()` and a `public` method `name()`. A class `Dog extends Animal` in another package calls `sound()`; a class `Outsider`, which is not a sub class, also calls `sound()`. State what happens in each case and why. (8 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

One protected member, two users outside the package: a sub class and a class that is not a sub class.

</Step>

<Step title="2. Plan">

A `protected` member is accessible within its class, by other classes in the same package, and by all sub classes in the same or other packages. A class that is neither in the package nor a sub class gets no access.

</Step>

<Step title="3. Solution">

```java title="src/base/Animal.java" project="protect"
package base;

public class Animal {
    protected String sound() {
        return "...";
    }

    public String name() {
        return "animal";
    }
}
```

```java title="src/Dog.java" project="protect"
import base.Animal;

public class Dog extends Animal {
    public String bark() {
        return sound() + " woof";                 // a sub class may use the protected method
    }

    public static void main(String[] args) {
        Dog d = new Dog();
        System.out.println(d.name() + ": " + d.bark());
    }
}
```

```java title="src/Outsider.java" project="protect"
import base.Animal;

public class Outsider {
    public static void main(String[] args) {
        Animal a = new Animal();
        System.out.println(a.name());
        System.out.println(a.sound());            // not a sub class, not in the package
    }
}
```

```text title="terminal" project="protect"
$ mkdir classes
$ javac -d classes -sourcepath src src/Dog.java
$ java -classpath classes Dog
animal: ... woof
$ javac -d classes -sourcepath src src/Outsider.java
src\Outsider.java:7: error: sound() has protected access in Animal
        System.out.println(a.sound());            // not a sub class, not in the package
                            ^
1 error
```

</Step>

<Step title="4. Check">

`Dog` compiles and runs: as a sub class it may use `sound()` although it is in another package. `Outsider` can call the public `name()` but not `sound()`: the compiler reports that `sound()` has protected access. Making a class `public` and making its members `public` are separate decisions.

</Step>

</Steps>

</details>

## 5. Writing with and without imports

### Exam question 6: no import statements (6 marks)

Rewrite this program so that it has no `import` statement, and say whether it still compiles. (6 marks)

```java
import java.util.Scanner;
import java.util.StringTokenizer;

public class Words {
    public static void main(String[] args) {
        Scanner in = new Scanner("alpha beta gamma");
        StringTokenizer t = new StringTokenizer(in.nextLine());
        System.out.println(t.countTokens());
    }
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two imported classes from `java.util`. The question is about using the full names instead of imports.

</Step>

<Step title="2. Plan">

An import only lets you use the short name. Writing the full name, the package and the class, works without it: `java.util.Scanner`.

</Step>

<Step title="3. Solution">

```java title="Words.java"
public class Words {
    public static void main(String[] args) {
        java.util.Scanner in = new java.util.Scanner("alpha beta gamma");
        java.util.StringTokenizer t = new java.util.StringTokenizer(in.nextLine());
        System.out.println(t.countTokens());
    }
}
```

```text
3
```

</Step>

<Step title="4. Check">

It compiles and prints 3 without any import. The price is longer code, which is why the `import` statement exists; the full name is also the way to use two classes with the same short name in one program.

</Step>

</Steps>

</details>

## 6. The idea of a package

### Exam question 7: what are packages for? (8 marks)

Define a package, state two advantages and the two categories, and give an example of each category. (8 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A definition, two advantages, two categories and an example for each.

</Step>

<Step title="2. Plan">

Use the lecture's wording: a package is a group of related classes organised into a folder, which might have sub-folders.

</Step>

<Step title="3. Solution">

A package is a group of related classes organised into a folder, which might have sub-folders. Advantages: it promotes writing better and more maintainable code, and it prevents name conflicts (two packages can each have a class called `Item`, told apart by the full name `shop.Item` and `store.Item`). Categories: built-in packages, which come bundled with the language (the Java API), such as `java.util`, which holds `Scanner`; and user-defined packages, which must be created by programmers, such as `pkg` with classes `A` and `B`.

</Step>

<Step title="4. Check">

Each example was used in this chapter: `Scanner` from `java.util` in `BuiltIns`, `pkg.A` in the compiled `demo` project, and `shop.Item` against `store.Item` in the conflict example, where the short name alone was ambiguous.

</Step>

</Steps>

</details>

## Summary

<Callout type="key" title="Remember">

Find the package of a class from the API: `java.lang` needs no import; `java.util` and `java.io` do. A package name starts with a lowercase letter, with a capital at the start of each new word. The source folder mirrors the package name (`src/bankAccounts/Account.java` starts with `package bankAccounts;`), the classes and members used from outside must be `public`, and a `protected` member is also open to sub classes in other packages. Compile the package with `javac -d classes -sourcepath src ...`, the tester with `-classpath classes`, and run it from the folder above `src` and `classes` with `java -classpath classes Tester`. A file in the wrong folder gives `package ... does not exist`. Packages promote maintainable code and prevent name conflicts.

</Callout>

## Check your understanding

<CheckQuestions>

<CheckQuestion question="Why does a source file saved in src instead of src/bankAccounts produce package bankAccounts does not exist?">

With `-sourcepath src` the compiler looks for the source of `bankAccounts.Account` at `src/bankAccounts/Account.java`. The package name has to be mirrored by the folder, so the file is not found.

</CheckQuestion>

<CheckQuestion question="Why can Dog call the protected sound() of Animal from another package, but Outsider cannot?">

A `protected` member is accessible in the same package and by sub classes in any package. `Dog` is a sub class; `Outsider` is neither in the package nor a sub class.

</CheckQuestion>

<CheckQuestion question="What do the full name java.util.Scanner and the import java.util.Scanner; have in common?">

Both let the program refer to the class `Scanner` in the package `java.util`. The import lets you write the short name `Scanner`; the full name works without any import.

</CheckQuestion>

<CheckQuestion question="Which package is imported by default, and why do String and Math need no import?">

`java.lang`. `String` and `Math` are fundamental classes in `java.lang`.

</CheckQuestion>

<CheckQuestion question="How do packages prevent name conflicts?">

A class's full name includes its package, so two classes with the same short name in different packages are different classes (`shop.Item` and `store.Item`). The short name alone is ambiguous only when both packages are imported with an asterisk.

</CheckQuestion>

</CheckQuestions>
