## Searching and sorting arrays

Searching answers **where is the value?** Sorting rearranges values so later work - especially binary search - becomes easier. The algorithms in this chapter are small enough to trace by hand and different enough to make time, space, stability, and preconditions concrete.

Before starting, review [Big-O notation](/docs/sem3/csi247/time-complexity). Every implementation here uses Java 8-compatible syntax and was checked with `javac --release 8` on JDK 21.

| Order | Lesson | Main question |
|---:|---|---|
| 1 | [Linear Search](/docs/sem3/csi247/sorting-and-searching/notes/linear-search) | How do I search any array and account for every comparison? |
| 2 | [Binary Search](/docs/sem3/csi247/sorting-and-searching/notes/binary-search) | How does sorted order let me discard half the search space? |
| 3 | [Bubble Sort](/docs/sem3/csi247/sorting-and-searching/notes/bubble-sort) | How do adjacent swaps fix the largest remaining value? |
| 4 | [Selection Sort](/docs/sem3/csi247/sorting-and-searching/notes/selection-sort) | How does selecting one minimum differ from swapping neighbours? |
| 5 | [Insertion Sort](/docs/sem3/csi247/sorting-and-searching/notes/insertion-sort) | How does a sorted prefix grow one value at a time? |
| 6 | [Merge Sort](/docs/sem3/csi247/sorting-and-searching/notes/merge-sort) | How does divide and conquer achieve `O(n log n)` time? |
| 7 | [Choosing an Algorithm](/docs/sem3/csi247/sorting-and-searching/notes/choosing-an-algorithm) | Which algorithm fits the data, operation, and constraints? |

## Chapter outcomes

- Trace successful and unsuccessful linear and binary searches.
- Implement index-returning search methods with a consistent `-1` result for absence.
- Show every pass of bubble, selection, and insertion sort.
- Draw the split and merge stages of merge sort.
- Explain best- and worst-case time, auxiliary space, stability, and adaptiveness.
- Choose an algorithm for a stated scenario and justify the choice.
