## Before you start

You should be able to:

- trace linear and binary search and state when each can be used;
- trace one or more passes of Bubble, Selection, and Insertion Sort;
- show the split and merge stages of Merge Sort;
- compare best- and worst-case time complexities;
- explain stability, auxiliary space, and when an algorithm is a sensible choice.

## Retrieval round: explain before you code

Close the notes and answer these aloud. A correct algorithm name alone is not enough: name the condition, the movement and the guarantee.

| Prompt | Your answer should include |
|---|---|
| Why can binary search discard half? | Sorted input; midpoint comparison; new inclusive bounds |
| Why does bubble need an entire pass? | An ordered pair says nothing about later pairs; largest active value travels right |
| Why can selection make no swap but still take quadratic time? | It must finish every suffix scan; `n(n-1)/2` comparisons |
| Where is the insertion key while cells are overwritten? | A separate variable; larger prefix values shift right; final `j+1` insertion |
| Why does a merge look only at two fronts? | Both runs already sorted; smaller front is globally smallest unread value |
| What changes during a recursive split? | Range indexes and call stack; not the array's values |
| What makes a sort stable? | Original order of equal records; compare labelled duplicates, not just integers |

## A 20-minute closed-book check

1. **4 minutes — search:** search for 7 in `[-5,-2,0,1,2,4,5,6,7,10]`; then search for 3. Record every `(low,mid,high)` triple.
2. **5 minutes — movement:** trace insertion on `[5,2,4,1]`. Mark the held key, each shift and each final insertion.
3. **5 minutes — merge:** split `[8,3,7,1]`, list actual merge-return order, and show the two front pointers for the final merge.
4. **3 minutes — counts:** derive the selection comparison count for six items. Contrast sorted-input insertion and optimized bubble.
5. **3 minutes — explanation:** give a stability counterexample for selection and explain how merge preserves equal records.

<details>
<summary>Checkpoints, not just final arrays</summary>

- Search 7: `(0,4,9)`, `(5,7,9)`, `(8,8,9)`; return 8. Search 3: probe values 2, 6, 4, then bounds cross; return -1.
- Insertion passes: `[2,5,4,1]`, `[2,4,5,1]`, `[1,2,4,5]`. Shift counts: 1, 1, 3.
- Merge returns: `[3,8]`, `[1,7]`, then `[1,3,7,8]`. Final choices: right 1, left 3, right 7, leftover left 8.
- Selection: `5+4+3+2+1 = 15`. Sorted insertion and optimized bubble each make five key comparisons; selection still makes fifteen.
- Selection `[2A,2B,1]` becomes `[1,2B,2A]`. Merge chooses LEFT on equality to keep original relative order.

## Decide what to revise

Rate each check as **independent**, **correct with a hint**, or **not yet**. Revisit the corresponding visual lesson for the latter two; then retry with different values. Do not count a memorized final array as a successful trace.

| Error you made | What it reveals | Repair |
|---|---|---|
| Returned a value instead of an index | Search contract unclear | Write the method's return meaning first |
| Reused a failed midpoint | Bounds update unclear | Cross out ruled-out indexes before recalculating |
| Called every movement a swap | Operations conflated | Label swap / shift / temp copy / copy-back separately |
| Merged before a child returned | Recursion order unclear | Follow depth-first calls, then sorted returns |
| Got Big-O right but counts wrong | Work model unclear | Separate key tests, bound tests and writes |

Continue with the [worked practice paper](/docs/sem3/csi247/sorting-and-searching/questions) and use the [cheat sheet](/docs/sem3/csi247/sorting-and-searching/cheat-sheet) only after your first attempt.
