## Library methods are not the handwritten lesson algorithms

`Arrays.binarySearch` requires the correct sorted ordering, but its missing-key result is **not always -1**. The API encodes the insertion point as `-(insertionPoint) - 1`. Our teaching implementation returns exactly -1 when absent. Do not mix the two contracts in an answer.

Similarly, the sorting algorithm used by a Java library method can depend on the overload and JDK version. Use the API documentation for library guarantees; use the lesson's actual code when counting operations or proving stability.

## Verify an animation actively

Before pressing play, predict the next state. After a movement, check:

1. Did an array value move, or did only an index/pointer move?
2. Was it a swap, a one-way shift, or a copy to a separate output?
3. Which part is guaranteed sorted now?
4. Did the animation use the same input and algorithm variant as the question?

For merge sort, a level-by-level tree is a structural picture. The recursive implementation executes left child, right child, merge in **depth-first** order. Use the numbered return sequence in our lesson to reconcile the two.
