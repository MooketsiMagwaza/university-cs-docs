Linear search learns almost nothing from a mismatch. **Binary search** uses sorted order to discard half of the remaining positions after each comparison.

<Callout type="warn" title="The precondition is part of the algorithm">
The searched range must be sorted in the same order assumed by the comparisons. Binary search can compile, run, and still return the wrong answer on an unsorted array.
</Callout>

## 1. The idea in plain language

Binary search looks at the middle card of a **sorted** array. The middle value proves that one whole side cannot contain the key, so that side is crossed out. Repeat with the half that remains.

## 3. Properties and the three indexes

Three indexes describe the part of the array that may still contain the key:

- `low`: first possible index;
- `high`: last possible index;
- `mid`: index probed in this iteration.

For an ascending array:

| Comparison | What it proves | Update |
|---|---|---|
| `arr[mid] == key` | The key is at `mid` | return `mid` |
| `arr[mid] < key` | `mid` and everything left of it are too small | `low = mid + 1` |
| `arr[mid] > key` | `mid` and everything right of it are too large | `high = mid - 1` |

The `+ 1` and `- 1` matter: `mid` has already been checked, so it must leave the next range.

| Property | Binary search |
|---|---|
| Required order | Sorted in the same direction as the comparisons |
| Best-case time | `O(1)` - first midpoint matches |
| Worst-case time | `O(log n)` - the range halves each iteration |
| Iterative extra space | `O(1)` |
| Recursive extra space | `O(log n)` call stack |

## 4. Iterative implementation

```java
// Precondition: ascending order; the inclusive range contains every possible match.
public static int binarySearch(int[] arr, int key) {
    // The first possible candidate is index 0.
    int low = 0;
    // The last possible candidate is length-1, including -1 for an empty array.
    int high = arr.length - 1;

    // An inclusive one-element range still needs checking; stop only when it becomes empty.
    while (low <= high) {
        // Use integer division and avoid adding two potentially large indexes.
        int mid = low + (high - low) / 2;

        // This midpoint is too small: exclude it and everything to its left.
        if (arr[mid] < key) {
            // Exclude the already checked midpoint to guarantee a smaller range.
            low = mid + 1;
        // This midpoint is too large: exclude it and everything to its right.
        } else if (arr[mid] > key) {
            // Exclude the already checked midpoint to guarantee a smaller range.
            high = mid - 1;
        } else {
            // Return the matching index, not the value stored there.
            return mid;
        }
    }
    // Every still-possible cell was ruled out; report absence.
    return -1;
}
```

`low + (high - low) / 2` computes the same midpoint as `(low + high) / 2` for ordinary indexes, but avoids overflowing when two very large positive indexes are added.

## 5. Why the time is logarithmic

Each unsuccessful probe leaves at most half the previous candidates.

```text
n candidates -> n/2 -> n/4 -> n/8 -> ... -> 1 -> 0
```

The number of halvings needed to reach one item is proportional to `log2(n)`. Binary search therefore has:

| Case | Time | Why |
|---|---:|---|
| Best | `O(1)` | The first midpoint is the key |
| Average | `O(log n)` | Each probe discards about half |
| Worst | `O(log n)` | The key is absent or found at the last remaining position |
| Iterative auxiliary space | `O(1)` | Only indexes are stored |

If the data is not already sorted, sorting it first costs extra. For one search, a linear scan may be cheaper than `O(n log n)` sorting followed by `O(log n)` searching. For many searches on data that stays sorted, the preparation cost can be worthwhile.

## 6. Recursive version

The recursive method makes the shrinking range explicit in its parameters.

```java
// Search the inclusive range recursively; start with low=0 and high=length-1.
public static int binarySearchRecursive(
        int[] arr, int key, int low, int high) {
    // Empty-range base case: return before calculating or reading a midpoint.
    if (low > high) {
        // Every still-possible cell was ruled out; report absence.
        return -1;
    }

    // Use integer division and avoid adding two potentially large indexes.
    int mid = low + (high - low) / 2;
    // This midpoint is too small: exclude it and everything to its left.
    if (arr[mid] < key) {
        // Return the child's answer unchanged: this frame must not discard the search result.
        return binarySearchRecursive(arr, key, mid + 1, high);
    }
    // This midpoint is too large: exclude it and everything to its right.
    if (arr[mid] > key) {
        // Return the child's answer unchanged: this frame must not discard the search result.
        return binarySearchRecursive(arr, key, low, mid - 1);
    }
    // Return the matching index, not the value stored there.
    return mid;
}
```

Call it with `binarySearchRecursive(values, key, 0, values.length - 1)`. The base case is an empty range, `low > high`. Its time remains `O(log n)`, but the recursive calls consume `O(log n)` stack space.

## 7. Descending arrays and duplicates

For a descending array, the equality test stays the same but the direction tests reverse. If `arr[mid] < key`, the larger key lies to the **left**, not the right.

Duplicates introduce a contract choice. The basic method may return any matching index. To find the first match, record a match and continue left:

```java
// For ascending data, retain a match and keep searching left for an earlier one.
public static int firstIndexOf(int[] arr, int key) {
    // The first possible candidate is index 0.
    int low = 0;
    // The last possible candidate is length-1, including -1 for an empty array.
    int high = arr.length - 1;
    // No match has been seen yet; -1 is not a valid array index.
    int answer = -1;

    // An inclusive one-element range still needs checking; stop only when it becomes empty.
    while (low <= high) {
        // Use integer division and avoid adding two potentially large indexes.
        int mid = low + (high - low) / 2;
        // This midpoint is too small: exclude it and everything to its left.
        if (arr[mid] < key) {
            // Exclude the already checked midpoint to guarantee a smaller range.
            low = mid + 1;
        } else {
            if (arr[mid] == key) {
                answer = mid;
            }
            // Exclude the already checked midpoint to guarantee a smaller range.
            high = mid - 1;
        }
    }
    // Return the earliest recorded matching index, or -1.
    return answer;
}
```

## 8. Common errors

| Attempt | What happens | Repair |
|---|---|---|
| Search unsorted data | A discarded half may contain the key | Sort first or use linear search |
| Use `while (low < high)` | A one-element range may never be checked | Use `low <= high` for this contract |
| Set `low = mid` or `high = mid` | The same midpoint can repeat forever | Exclude it with `mid + 1` or `mid - 1` |
| Start `high` at `arr.length` | `mid` may become an invalid index | Use `arr.length - 1` for inclusive bounds |
| Change comparisons for descending order incompletely | The search moves in the wrong direction | Write the order invariant before the code |

## Evaluated branches, recursive returns, and descending order

A probe is one visited midpoint, regardless of how many relations the branch chain evaluates. For the ascending implementation above, searching for 88 gives:

| Probe | low, mid, high | Evaluated Java key tests | Update |
|---:|---|---|---|
| 1 | 0,4,8 | `50 < 88 → true`; greater-than branch skipped | low=5 |
| 2 | 5,6,8 | `76 < 88 → true`; greater-than branch skipped | low=7 |
| 3 | 7,7,8 | `83 < 88 → true`; greater-than branch skipped | low=8 |
| 4 | 8,8,8 | `90 < 88 → false; 90 > 88 → true` | high=7 |
| Exit | low=8, high=7 | `8 <= 7 → false` | return -1 |

Totals: **four probes, five key comparisons, five loop-guard tests**. The recursive equivalent has five calls (the last range is empty), five base-case guards, the same four probes and five key comparisons, and returns -1 through `(8,7) → (8,8) → (7,8) → (5,8) → (0,8)`.

### Complete runnable direction and recursion examples

```java
public class BinarySearchFormsDemo {
    // Ascending input; low/high are inclusive. Start at 0 and length-1.
    public static int ascendingRecursive(int[] arr, int key, int low, int high) {
        if (low > high) return -1; // Empty range: do not read a midpoint.
        int mid = low + (high - low) / 2; // Integer, overflow-safe midpoint.
        if (arr[mid] < key) {
            // Eliminate all smaller candidates, including the checked midpoint.
            return ascendingRecursive(arr, key, mid + 1, high);
        }
        if (arr[mid] > key) {
            // Forward the child's answer so a match survives stack unwinding.
            return ascendingRecursive(arr, key, low, mid - 1);
        }
        return mid; // Both strict tests failed, so the values are equal.
    }

    // Descending input: smaller midpoint values exclude the RIGHT half.
    public static int descendingIterative(int[] arr, int key) {
        int low = 0; // First possible index.
        int high = arr.length - 1; // Last possible index, inclusive.
        while (low <= high) { // A single candidate must still be checked.
            int mid = low + (high - low) / 2;
            if (arr[mid] < key) {
                high = mid - 1; // Larger keys must lie left in descending data.
            } else if (arr[mid] > key) {
                low = mid + 1; // Smaller keys must lie right.
            } else {
                return mid; // Basic search may return any duplicate match.
            }
        }
        return -1; // The possible range is exhausted.
    }

    // Same descending invariant, now expressed in recursive parameters.
    public static int descendingRecursive(int[] arr, int key, int low, int high) {
        if (low > high) return -1; // Empty-range base case.
        int mid = low + (high - low) / 2;
        if (arr[mid] < key) {
            return descendingRecursive(arr, key, low, mid - 1); // Search left.
        }
        if (arr[mid] > key) {
            return descendingRecursive(arr, key, mid + 1, high); // Search right.
        }
        return mid; // Equality succeeds at this frame.
    }

    public static void main(String[] args) {
        // Use separate ordered fixtures, including duplicate and empty inputs.
        int[] ascending = {2, 6, 12, 32, 50, 59, 76, 83, 90};
        int[] descending = {90, 83, 76, 59, 50, 32, 12, 6, 2};
        System.out.println("ascending absent=" + ascendingRecursive(ascending, 88, 0, 8));
        System.out.println("descending found=" + descendingIterative(descending, 83));
        System.out.println("descending recursive=" + descendingRecursive(descending, 83, 0, 8));
        System.out.println("empty=" + descendingRecursive(new int[]{}, 7, 0, -1));
        System.out.println("duplicate=" + ascendingRecursive(new int[]{2, 4, 4, 4, 9}, 4, 0, 4));
    }
}
```

```text
ascending absent=-1
descending found=1
descending recursive=1
empty=-1
duplicate=2
```

For descending key 83, the complete evaluated trace is:

| Call / probe | low, mid, high | Evaluated comparisons | Next action |
|---:|---|---|---|
| 1 | 0,4,8 | `50 < 83 → true` | high=3 / call(0,3) |
| 2 | 0,1,3 | `83 < 83 → false; 83 > 83 → false` | Return 1 |
| Return | frame (0,8) resumes | `return childResult` | Return 1 to main |

Two probes, three key comparisons; iterative loop guard runs twice because success returns from inside it. Recursion uses two base-case guards and two simultaneous frames.

### Duplicate index contracts and boundary cases

For ascending `[2,4A,4B,4C,9]`, basic search returns index 2, while `firstIndexOf` above records 2, searches `0..1`, probes index 0 then index 1, and returns 1. The tags identify equal records; searching does not rearrange them. An empty array returns -1 without a probe; `[7]` returns 0 for key 7 and -1 for key 9. An absent key below the minimum or above the maximum must also exhaust a range safely.
