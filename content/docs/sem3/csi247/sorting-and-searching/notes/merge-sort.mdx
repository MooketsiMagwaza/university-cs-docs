Merge sort uses **divide and conquer**: break one large sorting problem into smaller sorting problems, solve those, then combine their answers.

The stopping rule is simple: a range containing zero or one value is already sorted. That is the **base case**.

## 1. First understand the merge

If two runs are already sorted, their smallest remaining values must be at their fronts. Compare only those two cards, copy the smaller card to the output, and advance only the pointer that supplied it.

<MergeFrontWorkbench />

The diagram separates three counts:

- a **key comparison** compares values, such as <code>9 &lt;= 5</code>;
- a **guard check** asks whether a pointer remains inside a run;
- a **write** copies a value to temporary output or back to the array.

When one run is exhausted, its guard becomes false. The other run is already sorted, so its leftover cards are copied without more key comparisons.

### Why equal cards come from the left first

For ascending order, <code>left[i] &lt;= right[j]</code> chooses the left card when values are equal.

## 2. Then understand the recursive journey

Splitting does **not** rearrange cards. It only changes the active <code>start</code>, <code>mid</code>, and <code>end</code> indexes. Java finishes the entire left recursive call, then the right call, then resumes the waiting parent and merges.

<MergeRecursionExplorer />

The parent frame stays on the call stack while its child runs. A base case returns immediately and does not call <code>merge</code>. A parent merges only after both children have returned sorted.

<CommonMistake title="Drawing values moving while the range splits">
During division, draw brackets, index ranges, or tree edges. Move value cards only during a merge write. A split describes two smaller problems; it does not copy values.
</CommonMistake>

### Compact call-and-return table for 0..3

| Event | Active statement | Actual values | Consequence |
|---:|---|---|---|
| 1 | <code>sort(arr, 0, 3)</code> | <code>mid = 1</code> | Parent waits for 0..1 |
| 2 | <code>sort(arr, 0, 1)</code> | <code>mid = 0</code> | Parent waits for 0..0 |
| 3 | <code>sort(arr, 0, 0)</code> | <code>0 &gt;= 0</code> → true | Base case returns |
| 4 | <code>sort(arr, 1, 1)</code> | <code>1 &gt;= 1</code> → true | Base case returns |
| 5 | <code>merge(arr, 0, 0, 1)</code> | both children sorted | Range 0..1 returns |
| 6 | <code>sort(arr, 2, 3)</code> | <code>mid = 2</code> | Same pattern on the right |
| 7 | <code>merge(arr, 2, 2, 3)</code> | both children sorted | Range 2..3 returns |
| 8 | <code>merge(arr, 0, 1, 3)</code> | both large halves sorted | Root returns |

Calls travel **down** the tree. Sorted runs are built on the way **back up**.

## 4. Properties after the mechanism

| Property | Result | Visual reason |
|---|---|---|
| Best, average, worst time | O(n log n) | Every level processes all n values; about log₂ n levels |
| Extra array space | O(n) | A merge temporarily stores the active range |
| Call-stack space | O(log n) | Each child is roughly half its parent |
| Stable | Yes, with left-first ties | Use ascending &lt;= or descending &gt;= |
| Adaptive | No, standard version | It still divides and merges sorted input |
| In place | No, taught version | Values pass through temporary storage |

<MergeComplexityFigure />

For eight values there are three merge levels and eight positions per level: roughly <code>8 × 3 = 24</code> copied positions. For sixteen values the shape is <code>16 × 4 = 64</code>, not <code>16² = 256</code>.

## 5. Fully commented recursive Java

Read this after the diagrams: the code is the same story expressed with indexes.

~~~java
public static void mergeSort(int[] arr, int start, int end) {
    // Zero- and one-element ranges are already sorted.
    // This also handles an empty initial range 0..-1.
    if (start >= end) {
        return;
    }

    // Find the last index of the left half without start + end overflow.
    int mid = start + (end - start) / 2;

    // Java completes the left child before it starts the right child.
    mergeSort(arr, start, mid);
    mergeSort(arr, mid + 1, end);

    // Both halves are now sorted, so their fronts can be merged.
    mergeAscending(arr, start, mid, end);
}

private static void mergeAscending(int[] arr, int start, int mid, int end) {
    // Hold exactly the values belonging to this parent range.
    int[] temp = new int[end - start + 1];

    // Point to the front unconsumed card in each sorted run.
    int left = start;
    int right = mid + 1;
    int out = 0; // Next empty position in temp.

    // Compare fronts while BOTH runs still contain a card.
    while (left <= mid && right <= end) {
        // <= takes an equal left record first, preserving stability.
        if (arr[left] <= arr[right]) {
            temp[out] = arr[left];
            left++; // Advance only the run that supplied the card.
        } else {
            temp[out] = arr[right];
            right++;
        }
        out++;
    }

    // At most one loop copies values; the other run is empty.
    while (left <= mid) {
        temp[out] = arr[left];
        left++;
        out++;
    }
    while (right <= end) {
        temp[out] = arr[right];
        right++;
        out++;
    }

    // Copy the completed sorted run back to its original array range.
    for (int i = 0; i < temp.length; i++) {
        arr[start + i] = temp[i];
    }
}
~~~

### Complete runnable example

~~~java
import java.util.Arrays;

public class MergeSortDemo {
    public static void mergeSort(int[] arr, int start, int end) {
        // Stop when this call owns at most one value.
        if (start >= end) {
            return;
        }

        // Split into inclusive ranges start..mid and mid+1..end.
        int mid = start + (end - start) / 2;
        mergeSort(arr, start, mid);       // Sort the complete left half.
        mergeSort(arr, mid + 1, end);     // Then sort the complete right half.
        merge(arr, start, mid, end);      // Finally combine their answers.
    }

    private static void merge(int[] arr, int start, int mid, int end) {
        int[] temp = new int[end - start + 1]; // Protected output buffer.
        int left = start;                       // Front of left run.
        int right = mid + 1;                    // Front of right run.
        int out = 0;                            // Next output slot.

        while (left <= mid && right <= end) {
            if (arr[left] <= arr[right]) {      // Left-first ties are stable.
                temp[out] = arr[left];
                left++;
            } else {
                temp[out] = arr[right];
                right++;
            }
            out++;
        }

        while (left <= mid) {                   // Possible left leftovers.
            temp[out] = arr[left];
            left++;
            out++;
        }
        while (right <= end) {                  // Possible right leftovers.
            temp[out] = arr[right];
            right++;
            out++;
        }

        for (int i = 0; i < temp.length; i++) { // Publish the parent run.
            arr[start + i] = temp[i];
        }
    }

    public static void main(String[] args) {
        int[] values = {63, 29, 72, 85, 18, 49, 3, 54};
        mergeSort(values, 0, values.length - 1);
        System.out.println(Arrays.toString(values));
    }
}
~~~

## 6. Descending order

Splitting is identical. Only the merge choice changes: take the **larger** front card. Use <code>&gt;=</code>, rather than <code>&gt;</code>, so equal left records remain first.

~~~java
private static void mergeDescending(int[] arr, int start, int mid, int end) {
    int[] temp = new int[end - start + 1];
    int left = start;
    int right = mid + 1;
    int out = 0;

    while (left <= mid && right <= end) {
        // Choose the larger front. >= keeps equal left records first.
        if (arr[left] >= arr[right]) {
            temp[out] = arr[left];
            left++;
        } else {
            temp[out] = arr[right];
            right++;
        }
        out++;
    }

    // Copy whichever sorted run still contains values.
    while (left <= mid) {
        temp[out] = arr[left];
        left++;
        out++;
    }
    while (right <= end) {
        temp[out] = arr[right];
        right++;
        out++;
    }

    // Replace only the active range with its descending result.
    for (int i = 0; i < temp.length; i++) {
        arr[start + i] = temp[i];
    }
}
~~~

## 7. Iterative bottom-up merge sort

Recursion discovers runs by splitting down to size one. The iterative form starts with one-card runs directly, then merges neighbours of width 1, 2, 4, and so on.

~~~text
width 1: [63] [29] [72] [85] [18] [49] [3] [54]
           ↓ merge neighbours
width 2: [29,63] [72,85] [18,49] [3,54]
           ↓ merge neighbours
width 4: [29,63,72,85] [3,18,49,54]
           ↓ merge neighbours
width 8: [3,18,29,49,54,63,72,85]
~~~

Both forms use O(n log n) time and temporary array space. Bottom-up merge sort replaces recursive frames with width-controlled loops; it does not remove the merge buffer.

## 8. Common errors

| Broken idea | Visible symptom | Repair |
|---|---|---|
| No base case | Stack keeps growing on a tiny range | Return for zero or one value |
| Right call starts at mid | Midpoint belongs to both children | Start right at mid + 1 |
| Merge runs before both calls | Inputs are not guaranteed sorted | Sort left, sort right, then merge |
| Stop when one run empties | Values disappear | Copy leftovers from either run |
| Write over unread array values | Later comparisons read destroyed input | Use temp, then copy back |
| Strict tie comparison | Equal right records can overtake | Use left-first &lt;= or &gt;= |

## 9. Exam-style practice

1. **Front-pointer trace (8 marks).** Merge [2, 9] and [4, 5, 8]. For every write, show i, j, evaluated condition, selected value, and temp.
2. **Call trace (7 marks).** For [5, 2, 4, 1], list every call in execution order and every merge on return.
3. **Odd length (6 marks).** Draw the range tree for indexes 0..4; state mid at each non-base node.
4. **Debugging (6 marks).** Delete both leftover loops, give an input that loses a value, trace it, and repair it.
5. **Stability (5 marks).** Merge [2A, 5C] and [2B, 4D]; show why left-first ties preserve order.
6. **Descending (7 marks).** State the comparison and tie choice, then merge [9, 2] with [8, 5, 4].
7. **Complexity (6 marks).** For n = 16, state merge levels, positions per level, and growth class.
8. **Code writing (12 marks).** Write the method header, base case, safe midpoint, recursive calls, and merge call in exact order.
