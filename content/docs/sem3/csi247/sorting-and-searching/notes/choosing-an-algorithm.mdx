Algorithm choice is a justification problem. A strong answer names the operation, states the relevant facts about the data, rules out unsuitable algorithms, and connects the choice to a measured cost or property.

Binary search is not automatically faster when the cost of obtaining and maintaining sorted order is included.

## 2. Sort choice

| Algorithm | Best | Worst | Space | Stable as taught | Adaptive as taught | Useful clue |
|---|---:|---:|---:|---|---|---|
| Bubble | `O(n)` | `O(n²)` | `O(1)` | Yes | Yes | Mainly teaching; early stop exposes sorted input |
| Selection | `O(n²)` | `O(n²)` | `O(1)` | No | No | At most one swap per pass |
| Insertion | `O(n)` | `O(n²)` | `O(1)` | Yes | Yes | Small or nearly sorted data |
| Merge | `O(n log n)` | `O(n log n)` | `O(n)` arrays | Yes | No | Predictable time; suitable for larger inputs |

`O(n²)` and `O(n log n)` separate dramatically as `n` grows. For `n = 1,000`, the dominant terms are about one million versus about ten thousand. Constants and implementations still matter, but the growth-rate gap eventually dominates.

## 3. Properties beyond time

### Stability

Suppose student records are already ordered by name, then sorted by mark. A stable mark sort preserves name order among students with equal marks. Stability matters when equal keys carry other data.

### Auxiliary space

An in-place algorithm uses only constant extra storage beyond the array. The taught bubble, selection, and insertion sorts are in-place. The taught array merge sort allocates temporary storage proportional to the input.

### Adaptiveness

An adaptive algorithm benefits from existing order. Optimized bubble sort and insertion sort do less work on nearly sorted input. Selection sort still scans each remaining suffix; merge sort still performs its divide-and-merge structure.

### Writes

If writing is unusually expensive, selection sort's at-most-one swap per pass may matter. Do not translate this into "selection sort is faster" without the stated cost model; it still makes `O(n²)` comparisons.

## 5. Worked scenarios

### Scenario A: one attendance lookup

An unsorted array of 35 student IDs is loaded once and searched once.

**Choice:** linear search. It works immediately in `O(n)` worst-case time. Sorting first would cost more work than this single lookup saves.

### Scenario B: results portal

A fixed array of 50,000 sorted student IDs receives thousands of lookups.

**Choice:** binary search. The precondition already holds and every lookup takes `O(log n)` worst-case time with `O(1)` auxiliary space.

### Scenario C: nearly sorted daily readings

Ten new readings are appended to a small array that was sorted yesterday.

**Choice:** insertion sort is defensible. Most values are already near their final position, so few shifts are expected; it is stable and in-place.

### Scenario D: large unpredictable array

A large array must be sorted with a predictable bound, and `O(n)` temporary storage is available.

**Choice:** merge sort. Its worst-case time is `O(n log n)` and it is stable as implemented.

<CommonMistake title="Choosing binary search because O(log n) is smaller">
That comparison omits the precondition and preparation. If an unsorted array is searched once, sorting it in `O(n log n)` just to run one `O(log n)` search is usually worse than one `O(n)` linear scan.
</CommonMistake>

## 6. Practice

Choose and justify an algorithm for each case. State any assumption your answer needs.

1. Sort 20 nearly ordered marks in place while preserving equal-mark order.
2. Sort 2,000,000 unpredictable records when temporary memory is available and a quadratic worst case is unacceptable.
3. Find one name in an unsorted array of 12 records.
4. Repeatedly search a sorted array of unique ID numbers.
5. Sort values on storage where writes are much more expensive than comparisons.

<Accordions>
<Accordion title="Check questions 1, 2, and 5">

**1.** Insertion sort: the input is small and nearly sorted, and the taught version is stable and in-place.

**2.** Merge sort: its worst-case time is `O(n log n)`, and the scenario explicitly permits its `O(n)` temporary storage.

**5.** Selection sort is worth considering because it performs at most one swap per pass. The answer must mention that its comparisons remain `O(n²)` and that a production library algorithm may still be preferable.

</Accordion>
