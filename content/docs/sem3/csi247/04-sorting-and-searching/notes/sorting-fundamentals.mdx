<FrameBox label="The idea">

Sorting is putting things in order, like arranging cards in your hand. There are many strategies: some simple but slow, some clever and fast.

</FrameBox>

<FrameBox label="The definition">

A sorting algorithm rearranges a collection so that every element is less than or equal to the one after it, according to some ordering (ascending order). Reversing the ordering gives descending order.

</FrameBox>

<FrameBox label="Why it matters">

Sorted data makes other jobs fast: binary search (O(log *n*)), finding duplicates (they end up side by side), finding the median, merging lists.

</FrameBox>

<FrameBox label="What studying it teaches">

The core ideas of algorithm design all appear in sorting: loops and invariants, recursion, divide and conquer, and Big-O analysis.

</FrameBox>

</ConceptFrame>

## Comparison sorts

Every algorithm in this course is a **comparison sort**: the only thing it ever asks about the data is "should *a* come before *b*?". It never looks inside the values in any other way. That's powerful, because it means the same algorithm can sort numbers, words, dates or students, as long as you can answer that one question. The [Comparable & Comparator](/docs/sem3/csi247/04-sorting-and-searching/notes/comparable-and-comparator) page shows how to answer it for your own classes. (It can be proved that no comparison sort can beat O(*n* log *n*) comparisons in the worst case, so merge sort is as good as it gets in that sense.)

## Four ways to judge a sort

### 1. Time

How the number of comparisons and moves grows with *n*, in the best, average and worst case (see the Big-O page). The simple sorts are O(*n*²); the efficient ones are O(*n* log *n*).

### 2. Space

How much extra memory is needed beyond the array itself.

### 3. In-place

A sort is **in-place** if it rearranges the elements inside the original array using only O(1) extra memory (a handful of variables), rather than copying them into a second array. Bubble, selection, insertion and quick sort are in-place (quick sort also uses stack space for recursion); merge sort is not.

### 4. Stability

A sort is **stable** if elements that compare as equal stay in the same relative order they had before sorting. This only matters when equal elements can be told apart, for example two students with the same grade but different names. It's very useful for sorting by several fields: sort by name first, then *stably* by grade, and students with the same grade remain in alphabetical order.

## The helper used by in-place sorts

You met this on the Arrays & methods page. Every listing that calls `swap` assumes this method is in the same class.

```java title="Swap.java"
static void swap(int[] a, int i, int j) {
    int tmp = a[i];     // 1. save a[i]
    a[i] = a[j];        // 2. overwrite a[i] with a[j]
    a[j] = tmp;         // 3. put the saved value into a[j]
}
```
