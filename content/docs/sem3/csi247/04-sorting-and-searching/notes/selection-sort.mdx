title: "Selection sort"
description: "Find the smallest."
---

Put it first. Repeat on what's left.

<ConceptFrame>

<FrameBox label="The idea">

Lining people up by height: scan everyone, pick the shortest, they step to the front. Scan the rest, pick the next shortest, they step up next…

</FrameBox>

<FrameBox label="The definition">

Treat the array as a sorted part on the left (initially empty) and an unsorted part on the right. Each round, **select** the minimum of the unsorted part and swap it to the boundary, growing the sorted part by one.

</FrameBox>

<FrameBox label="Why it works">

The smallest remaining value must belong in the next position, so one swap places it permanently. After *n*−1 rounds, the last element must be the largest.

</FrameBox>

<FrameBox label="What it is for">

It makes at most *n*−1 swaps, the fewest of any simple sort. That helps when writing data is far more expensive than reading it.

</FrameBox>

</ConceptFrame>

## The code

```java title="SelectionSort.java"
public static void selectionSort(int[] a) {
    int n = a.length;

    for (int i = 0; i < n - 1; i++) {       // i = boundary: a[0..i-1] is sorted and final
        int min = i;                        // index of the smallest value seen so far

        for (int j = i + 1; j < n; j++) {   // scan the rest of the unsorted part
            if (a[j] < a[min]) {
                min = j;                    // remember WHERE the new smallest is
            }
        }

        if (min != i) {
            swap(a, i, min);                // at most ONE swap per round
        }
    }
}
```

Note that we remember the *index* of the minimum (`min`), not its value. We need the index so we know which position to swap with.

## Analysis

- **Time, O(*n*²) in every case.** To be sure it has found the minimum, the inner loop must look at every remaining element, even if the array is already sorted. That's always (*n*−1) + (*n*−2) + … + 1 = *n*(*n*−1)/2 comparisons. There's no early exit.
- **Swaps: at most *n*−1**, one per round, far fewer than bubble sort's up to *n*(*n*−1)/2.
- **Space, O(1).** In-place.

<Callout type="caution" title="Why it isn't stable">

The long-distance swap can jump an element over an equal one. Sort `[4ₐ, 4ᵦ, 1]`: round 0 finds 1 and swaps it with 4ₐ, giving `[1, 4ᵦ, 4ₐ]`. The two 4s have changed their relative order.

</Callout>

<Callout type="key">

Select the minimum, swap it to the front, shrink the problem. Always *n*(*n*−1)/2 comparisons, but at most *n*−1 swaps. Not stable, no early exit.

</Callout>
