title: "Bubble sort"
description: "Compare neighbours."
---

Swap them if they're in the wrong order. Repeat until nothing moves.

<ConceptFrame>

<FrameBox label="The idea">

Big values "bubble up" to the end of the array, like air bubbles rising to the surface of water: each pass carries the largest remaining value all the way to the right.

</FrameBox>

<FrameBox label="The definition">

Repeatedly walk through the array comparing each pair `a[j]`, `a[j+1]` and swapping them if `a[j] > a[j+1]`. Each walk is a **pass**. After pass *k*, the last *k* elements are in their final places.

</FrameBox>

<FrameBox label="Why it works">

The largest value wins every comparison it's part of, so it keeps getting swapped to the right until it reaches the end. And if a whole pass makes zero swaps, every neighbouring pair is in order, which means the whole array is sorted.

</FrameBox>

<FrameBox label="What it is for">

Teaching. It's the easiest sort to understand and prove correct, but it's almost never the right choice in real code.

</FrameBox>

</ConceptFrame>

## Step by step

<Steps>

<Step title="Start a pass at the left end">

Compare `a[0]` with `a[1]`. If the left one is bigger, swap them.

</Step>

<Step title="Move one step right">

and compare `a[1]` with `a[2]`, and so on, up to the last unsorted pair.

</Step>

<Step title="At the end of the pass">

, the largest unsorted value has arrived at the right end of the unsorted part. It's now final, so the next pass can stop one position earlier.

</Step>

<Step title="If a pass made no swaps at all, stop">

: the array is sorted. Otherwise start another pass.

</Step>

</Steps>

## Hand trace

Sorting `[5, 1, 4, 2, 8]`. Pass 1, comparison by comparison:

| Compare | Out of order? | Array afterwards |
| --- | --- | --- |
| 5 and 1 | yes → swap | `[1, 5, 4, 2, 8]` |
| 5 and 4 | yes → swap | `[1, 4, 5, 2, 8]` |
| 5 and 2 | yes → swap | `[1, 4, 2, 5, 8]` |
| 5 and 8 | no | `[1, 4, 2, 5, 8]` |

And the whole sort, pass by pass:

| Pass | Array after the pass | Swaps | Now final |
| --- | --- | --- | --- |
| start | `[5, 1, 4, 2, 8]` | — | — |
| 1 | `[1, 4, 2, 5, 8]` | 3 | 8 |
| 2 | `[1, 2, 4, 5, 8]` | 1 | 5 |
| 3 | `[1, 2, 4, 5, 8]` | 0 | no swaps → stop early |

Notice that the 8 was already in place, and that the array was in fact sorted after pass 2. Bubble sort only *knows* it's sorted after a full pass with no swaps, which is why pass 3 is needed.

## The code

```java title="BubbleSort.java"
public static void bubbleSort(int[] a) {
    int n = a.length;

    for (int pass = 0; pass < n - 1; pass++) {      // at most n-1 passes are ever needed
        boolean swapped = false;                    // did this pass change anything?

        // After `pass` passes, the last `pass` elements are final,
        // so this pass only needs to look at pairs up to index n-2-pass.
        for (int j = 0; j < n - 1 - pass; j++) {
            if (a[j] > a[j + 1]) {                  // neighbours out of order?
                swap(a, j, j + 1);                  // '>' (not '>=') never swaps equal values → STABLE
                swapped = true;
            }
        }

        if (!swapped) {
            break;                                  // no swaps → every pair is in order → done
        }
    }
}
```

Why `j < n - 1 - pass`? The loop body reads `a[j + 1]`, so `j` must stop at least one short of the last index, which explains the `- 1`. The `- pass` skips the elements that earlier passes have already put in their final places.

## Analysis

- **Worst case, O(*n*²):** a reverse-sorted array. Every comparison causes a swap, and all *n*−1 passes are needed: (*n*−1) + (*n*−2) + … + 1 = *n*(*n*−1)/2 comparisons and the same number of swaps.
- **Best case, O(*n*):** an already-sorted array. The first pass makes *n*−1 comparisons, no swaps, and the `swapped` flag stops the sort. Without the flag, the best case would also be O(*n*²).
- **Space, O(1):** only a few variables. It's in-place.
- **Stable:** it only ever swaps neighbours, and only when the left one is strictly greater, so equal elements never pass each other.

<Callout type="mistake">

Writing the inner loop as `j < n`. On the last iteration `a[j + 1]` is `a[n]`, which doesn't exist, and the program crashes with `ArrayIndexOutOfBoundsException`.

</Callout>

<Callout type="key">

Compare neighbours, swap if wrong, repeat. Each pass fixes one more element at the end. The `swapped` flag gives O(*n*) on sorted input. Stable, in-place, but O(*n*²) in general.

</Callout>
