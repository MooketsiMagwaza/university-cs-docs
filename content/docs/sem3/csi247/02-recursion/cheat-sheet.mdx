## 1. Placeholders used in every template on this page

| Placeholder | Meaning | Example |
|---|---|---|
| `method` | The name of the recursive method | `factorial`, `power`, `fibonacci` |
| `param` | The value that shrinks on each call | `n`, `y` |
| `baseCondition` | The test that is true for the smallest input | `n == 1`, `y == 0`, `n <= 1` |
| `baseValue` | What the method returns at the base case, with no further call | `1` for `factorial(1)`, `1` for `power(x, 0)` |
| `smaller` | The argument of the recursive call, closer to the base case | `n - 1`, `y - 1` |
| `combine` | How the answer of the smaller call becomes the answer for this call | `n * ...`, `x * ...`, `... + ...` |

## 2. The anatomy of a recursive method

Every recursive method has exactly two cases (Lecture 6): a **base case** that returns directly, without recursion, and a **recursive case** that calls the method again on something smaller and uses the answer.

**Template:**

```java
static ReturnType method(ParamType param) {
    if (baseCondition) {
        return baseValue;                    // base case: no further call
    }
    return combine(method(smaller));         // recursive case: a smaller problem
}
```

**Example:**

```java title="Factorial.java"
public class Factorial {
    static int factorial(int n) {
        if (n == 0) {
            return 1;                        // base case
        }
        return n * factorial(n - 1);         // recursive case
    }

    public static void main(String[] args) {
        System.out.println(factorial(5));
        System.out.println(factorial(0));
    }
}
```

```text
120
1
```

**Watch for:** the base case is tested **first**. Putting the recursive call before the test means the method never reaches the base case. The lecture's version tests `n == 1`, which answers 1 and above but not 0.

## 3. The termination checklist

Ask three questions of every recursive call before calling the method finished:

| Check | Question to ask | Fails when |
|---|---|---|
| Base case exists | Is there an input that returns a value with no further call? | Every path makes another call |
| Argument changes | Does every recursive call pass a different argument? | `sum(n)` calls `sum(n)` |
| Moves toward the base case | Does the change bring the argument closer to a base case that exists? | `factorial(-3)` counts down by 1, away from `0`, forever |

All three must hold together. Every chain of recursive calls must progress towards the base case, and only one recursive option executes in a call.

**What happens when it fails:** this is infinite recursion. The calls pile up on the stack until Java throws a `StackOverflowError`. The lecture's example is a method with no base case.

```java title="Overflow.java"
public class Overflow {
    static int broken(int n) {
        return n + broken(n - 1);            // no base case
    }

    public static void main(String[] args) {
        try {
            broken(5);
        } catch (StackOverflowError e) {
            System.out.println("StackOverflowError: no base case was ever reached");
        }
    }
}
```

```text
StackOverflowError: no base case was ever reached
```

## 4. The three methods of Lab 3

| Method | `baseCondition` | `smaller` | `combine` | Calls per step |
|---|---|---|---|---|
| `factorial(n)` | `n == 1` | `n - 1` | `n * ...` | one |
| `power(x, y)` | `y == 0` | `y - 1` | `x * ...` | one |
| `fibonacci(n)` | `n <= 1` (returns `n`) | `n - 1` and `n - 2` | `... + ...` | two |

```java title="Lab3Methods.java"
public class Lab3Methods {
    // The three methods of Lab 3, recursive and iterative.
    static long factorial(int n) {
        if (n == 1) {
            return 1;
        }
        return n * factorial(n - 1);
    }

    static long factorialLoop(int n) {
        long prod = 1;
        for (int i = 1; i <= n; i++) {
            prod = prod * i;
        }
        return prod;
    }

    static int fibonacci(int n) {
        if (n <= 1) {
            return n;                        // two base cases: fibonacci(0) = 0 and fibonacci(1) = 1
        }
        return fibonacci(n - 1) + fibonacci(n - 2);
    }

    static void series(int n) {
        for (int i = 0; i < n; i++) {
            System.out.print(fibonacci(i) + " ");
        }
        System.out.println();
    }

    static int power(int x, int y) {
        if (y == 0) {
            return 1;                        // anything to the power 0 is 1
        }
        return x * power(x, y - 1);
    }

    static int powerLoop(int x, int y) {
        int result = 1;
        for (int i = 1; i <= y; i++) {
            result = result * x;
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println(factorial(7) + " " + factorialLoop(7));
        series(6);
        System.out.println(power(3, 2) + " " + powerLoop(3, 2));
        System.out.println(power(2, 8) + " " + powerLoop(2, 8));
    }
}
```

```text
5040 5040
0 1 1 2 3 5
9 9
256 256
```

The recursive and iterative versions print the same values. The base case of a product returns 1, the identity for multiplication.

## 5. Tracing a recursive method: the trace table

A recursive trace has two directions: the calls go **down** until the base case, then the answers come **back up**. Fill the first four columns top to bottom, then the Results column bottom to top. This is the lecture's table for `factR(5)`.

| Level | `n` | `n == 1`? | Returned | Results |
|---|---|---|---|---|
| 0 | 5 | false | `5 * factR(4)` | 5 * 24 = **120** |
| 1 | 4 | false | `4 * factR(3)` | 4 * 6 = 24 |
| 2 | 3 | false | `3 * factR(2)` | 3 * 2 = 6 |
| 3 | 2 | false | `2 * factR(1)` | 2 * 1 = 2 |
| 4 | 1 | true | `1` | 1 |

```java title="FactR5.java"
public class FactR5 {
    static long factR(int n) {
        if (n == 1) {
            return 1;
        }
        return n * factR(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(factR(5));
    }
}
```

```text
120
```

`factR(n)` makes `n` calls, one per row of the table.

## 6. Linear recursion and a branching call tree

`factorial` calls itself **once** per step, so its calls form a chain. `fibonacci(n) = fibonacci(n - 1) + fibonacci(n - 2)` calls itself **twice**, so its calls branch into a tree, and identical sub-calls such as `fibonacci(2)` are recomputed every time they reappear.

| Property | `fibonacci` (branching) | Loop (linear) |
|---|---|---|
| Recursive calls per step | Two | None |
| Shape of the calls | A tree | A chain of passes |
| Repeated sub-calls | Yes, `fibonacci(2)` many times | No |
| Work for `fibonacci(20)` | 21,891 calls | 20 passes |

```java title="Fib.java"
public class Fib {
    static int calls = 0;

    static int fib(int n) {
        calls++;
        if (n <= 1) {
            return n;                        // two base cases: fib(0) = 0 and fib(1) = 1
        }
        return fib(n - 1) + fib(n - 2);
    }

    public static void main(String[] args) {
        System.out.println(fib(10) + " after " + calls + " calls");
        calls = 0;
        System.out.println(fib(20) + " after " + calls + " calls");
    }
}
```

```text
55 after 177 calls
6765 after 21891 calls
```

`fibonacci(n)` reaches back **two** steps, so it needs answers for both `0` and `1`. Count how far back the recursive step reaches: that is how many base cases you need.

## 7. Recursion over a range (used again in Lectures 8 and 9)

The same two cases fit a range of positions `low..high` that is halved on each call. Lecture 8 sets the exercise "convert the iterative binary search into a recursive one", and Lecture 9's merge sort is recursive on a range.

| Where | `baseCondition` | `smaller` |
|---|---|---|
| Recursive binary search (Lecture 8) | `low > high` (not found), or `arr[mid] == key` (found) | `mid + 1..high` or `low..mid - 1` |
| Merge sort (Lecture 9) | `start < end` is false: at most one element | `start..mid` and `mid + 1..end`, then merge |

```java title="RangeSearch.java"
public class RangeSearch {
    static int calls;

    static int search(int[] arr, int key, int low, int high) {
        calls++;
        if (low > high) {
            return -1;                       // base case: empty range, not found
        }
        int mid = low + ((high - low) / 2);
        if (arr[mid] == key) {
            return mid;                      // base case: found
        }
        if (arr[mid] < key) {
            return search(arr, key, mid + 1, high);   // both new ranges leave mid out
        }
        return search(arr, key, low, mid - 1);
    }

    public static void main(String[] args) {
        int[] arr = {8, 18, 23, 29, 34};
        System.out.println(search(arr, 29, 0, arr.length - 1) + " after " + calls + " calls");
        calls = 0;
        System.out.println(search(arr, 100, 0, arr.length - 1) + " after " + calls + " calls");
    }
}
```

```text
3 after 2 calls
-1 after 4 calls
```

Each call halves the range, so a search takes about log2 `n` calls, plus one more for the empty range when the key is missing. The searching and sorting algorithms themselves are in [Sorting and searching](/docs/sem3/csi247/04-sorting-and-searching).

## 8. Converting between recursion and a loop

Every recursive solution has a corresponding iterative solution, and the reverse (Lecture 6). The base case becomes the starting value, and the recursive case becomes the loop body.

| Recursive part | Loop part |
|---|---|
| The base case value (`1` for `power`) | The starting value of the result |
| The recursive case `x * power(x, y - 1)` | The loop body `result = result * x` |
| The smaller argument `y - 1` | The loop counter, repeated `y` times |

```java title="LoopToRecursion.java"
public class LoopToRecursion {
    // loop version
    static int powerLoop(int x, int y) {
        int result = 1;                      // the base case value
        for (int i = 1; i <= y; i++) {
            result = result * x;             // the recursive case
        }
        return result;
    }

    // recursive version
    static int powerRec(int x, int y) {
        if (y == 0) {
            return 1;
        }
        return x * powerRec(x, y - 1);
    }

    public static void main(String[] args) {
        System.out.println(powerLoop(2, 8) + " " + powerRec(2, 8));
        System.out.println(powerLoop(6, 3) + " " + powerRec(6, 3));
    }
}
```

```text
256 256
216 216
```

## 9. Common errors

| Mistake | What happens | Repair |
|---|---|---|
| No base case | `StackOverflowError` | Add a test for the smallest input before the call |
| Base case after the recursive call | Same: the call runs first | Put the test first |
| Argument does not change | `StackOverflowError` | Pass `n - 1` or `y - 1` |
| Moves away from the base case | `StackOverflowError` | Pass the smaller argument, not `n + 1` |
| Base case that does not cover every input | `factorial(0)` with the base case `n == 1` never stops | Use `n <= 1` |
| One base case where two are needed | Wrong answers or an exception | Count how far back the step reaches |
| Forgetting to use the returned value | The answer is thrown away | `return n * factorial(n - 1);`, not just `factorial(n - 1);` |
| `return = n * factR(n - 1);` | `error: illegal start of expression` | Delete the `=` |
| Wrong base case value | Every result is wrong, for example 0 from the base case of a product | Return the identity: 1 for a product, 0 for a sum |

## 10. Cost

| Method | Calls | Boxes on the stack at the deepest point | Loop version |
|---|---|---|---|
| `factorial(n)` | `n` | `n` (and `main`) | `n` passes, no calls |
| `power(x, y)` | `y + 1` | `y + 1` (and `main`) | `y` passes, no calls |
| `fibonacci(n)` | 25 for `n = 6`, 109 for `n = 9` | grows with `n` | `n` passes, no calls |
| Recursive binary search (Lecture 8) | about log2 `n`, one more if the key is missing | about log2 `n` | a loop |

Recursion has the overhead of multiple method calls; for some problems the recursive solution is simpler and more elegant. Each pending call keeps its own box on the stack with its own parameters, and a method that never reaches its base case fills the stack.
