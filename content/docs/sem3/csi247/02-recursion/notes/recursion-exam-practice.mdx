This lesson has no new teaching. It is sixteen questions in the forms an examiner uses for recursion, each answered the way a marker wants to see it. Cover the answer, work the question on paper with a trace table, then open the answer and compare. The ideas are in [Recursion by Example](/docs/sem3/csi247/02-recursion/notes/recursion-by-example), [Recursion on Arrays and Strings by Example](/docs/sem3/csi247/02-recursion/notes/recursion-on-data-by-example) and [Recursion Patterns by Example](/docs/sem3/csi247/02-recursion/notes/recursion-patterns-by-example).

## 1. How to earn the marks

A marker looks for the same things in every recursion answer.

| Command word | What the marker wants |
|---|---|
| Trace | A table with one row per call: the arguments, whether the base case is true, the expression returned, and the result filled from the bottom up. The final value, clearly marked |
| Write | The signature, the base case (with the right value for the combination), the recursive call on a smaller input, and the combination. The precondition if there is one |
| Convert | The rule applied: parameters, base case, arguments; or starting value, loop condition, loop body. Both versions tested on one input |
| Explain / State | The reason in one or two sentences, using the words base case, smaller input, stack frame |
| Find the fault | The input that fails, the exact line, the kind of fault, and the repair tested on that input |

Every answer should end with a check on a small input and on the edge case (0, an empty array, an empty string, one element).

## 2. Tracing: four questions

### Exam question 1: what does it compute? (4 marks)

```java
static int f(int n) {
    if (n <= 0) {
        return 0;
    }
    return n % 3 + f(n / 3);
}
```

Trace `f(14)` and say what the method computes in general. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Trace" asks for a table and "say what it computes" asks for one sentence. The argument is divided by 3 each call, so it shrinks by a factor, and the base case is `n <= 0`.

</Step>

<Step title="2. Plan">

Make a row for each value of `n` until it reaches 0, writing the expression returned (`n % 3 + f(n / 3)`) and then filling the results from the bottom.

</Step>

<Step title="3. Solution">

| `n` | Call | `n <= 0`? | Returned | Result |
|---|---|---|---|---|
| 14 | `f(14)` | false | `2 + f(4)` | 2 + 2 = **4** |
| 4 | `f(4)` | false | `1 + f(1)` | 1 + 1 = 2 |
| 1 | `f(1)` | false | `1 + f(0)` | 1 + 0 = 1 |
| 0 | `f(0)` | true | `0` | 0 |

```java title="BaseThreeSum.java"
public class BaseThreeSum {
    // Question: trace f(14) and say what f computes.
    static int f(int n) {
        if (n <= 0) {
            return 0;
        }
        return n % 3 + f(n / 3);
    }

    public static void main(String[] args) {
        System.out.println(f(14));
        System.out.println(f(9));
        System.out.println(f(0));
    }
}
```

```text
4
1
0
```

</Step>

<Step title="4. Check">

The method takes the last digit in base 3 (`n % 3`) and then the rest (`n / 3`), exactly as `digitSum` does in base 10, so it returns **the sum of the digits of n written in base 3**. Check: 14 in base 3 is 112, and 1 + 1 + 2 = 4, which matches. 9 is 100 in base 3, so the sum is 1, and 0 gives 0.

</Step>

</Steps>

</details>

### Exam question 2: what does it print? (4 marks)

```java
static void g(int n) {
    if (n == 0) {
        return;
    }
    g(n / 2);
    System.out.print(n % 2);
}
```

State the output of `g(13)`, and say what the method prints in general. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The method prints, so the order of the output is the question. The print is **after** the recursive call, so the digits come out as the calls return, from the deepest call to the outermost.

</Step>

<Step title="2. Plan">

Go down: 13, 6, 3, 1, 0. At 0 stop. Come back up printing `n % 2` for 1, 3, 6, 13 in that order.

</Step>

<Step title="3. Solution">

```java title="PrintBinary.java"
public class PrintBinary {
    // Question: what does g(13) print?
    static void g(int n) {
        if (n == 0) {
            return;
        }
        g(n / 2);
        System.out.print(n % 2);
    }

    public static void main(String[] args) {
        g(13);
        System.out.println();
        g(8);
        System.out.println();
        g(1);
        System.out.println();
        g(0);
        System.out.println("[nothing]");
    }
}
```

```text
1101
1000
1
[nothing]
```

| `n` | Call | Prints (on the way up) |
|---|---|---|
| 13 | `g(13)` | `13 % 2 = 1`, fourth |
| 6 | `g(6)` | `6 % 2 = 0`, third |
| 3 | `g(3)` | `3 % 2 = 1`, second |
| 1 | `g(1)` | `1 % 2 = 1`, first |
| 0 | `g(0)` | base case, prints nothing |

</Step>

<Step title="4. Check">

Reading the prints in the order they happen (1, 1, 0, 1) gives `1101`, the binary form of 13. In general the method prints **n in binary**, most significant digit first. `g(0)` prints nothing, so 0 needs special handling if "0" should appear. Moving the print before the recursive call would print the digits in reverse: `1011`.

</Step>

</Steps>

</details>

### Exam question 3: two parameters (4 marks)

```java
static int m(int a, int b) {
    if (a == 0) {
        return b;
    }
    return m(a - 1, b + 2);
}
```

Trace `m(3, 1)` and state, as a formula, what `m(a, b)` returns. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two parameters change at once: `a` goes down by 1 and `b` goes up by 2. The base case is `a == 0`, and it returns `b`, not a constant, so the answer is built in `b` on the way down.

</Step>

<Step title="2. Plan">

Write the pair `(a, b)` for each call. When `a` reaches 0 the value of `b` is the result, and it passes up unchanged.

</Step>

<Step title="3. Solution">

| Call | `a == 0`? | Returned |
|---|---|---|
| `m(3, 1)` | false | `m(2, 3)` |
| `m(2, 3)` | false | `m(1, 5)` |
| `m(1, 5)` | false | `m(0, 7)` |
| `m(0, 7)` | true | `7` |

```java title="TwoParameters.java"
public class TwoParameters {
    // Question: trace m(3, 1) and say what m(a, b) returns.
    static int m(int a, int b) {
        if (a == 0) {
            return b;
        }
        return m(a - 1, b + 2);
    }

    public static void main(String[] args) {
        System.out.println(m(3, 1));
        System.out.println(m(0, 5));
        System.out.println(m(4, 0));
    }
}
```

```text
7
5
8
```

</Step>

<Step title="4. Check">

`m(3, 1)` is **7**. Each of the `a` calls adds 2 to `b`, so the method returns **`b + 2 * a`**: 1 + 6 = 7, 5 + 0 = 5, and 0 + 8 = 8. Like `factAcc`, this method has nothing left to do on the way back up.

</Step>

</Steps>

</details>

### Exam question 4: how many times is fib(3) called? (5 marks)

For the recursive `fib` with base cases `fib(0) = 0` and `fib(1) = 1`, state how many times `fib(3)` is called during the evaluation of `fib(6)`, and the total number of calls. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The unit counted is one call with the argument 3. `fib(n)` for n of at least 2 makes one call with `n - 1` and one with `n - 2`.

</Step>

<Step title="2. Plan">

Count calls per argument from the top. The calls with argument `n` come from the calls with `n + 1` and from the calls with `n + 2`, so `count(n) = count(n + 1) + count(n + 2)`, starting with `count(6) = 1`.

</Step>

<Step title="3. Solution">

`count(6) = 1`, `count(5) = 1`, `count(4) = 1 + 1 = 2`, `count(3) = 2 + 1 = 3`, `count(2) = 3 + 2 = 5`, `count(1) = 5 + 3 = 8`, `count(0) = 5`. The total is 1 + 1 + 2 + 3 + 5 + 8 + 5 = 25.

```java title="FibSixCount.java"
public class FibSixCount {
    // Question: how often is each argument called when fib(6) is evaluated?
    static int[] counts = new int[7];

    static int fib(int n) {
        counts[n]++;
        if (n <= 1) {
            return n;
        }
        return fib(n - 1) + fib(n - 2);
    }

    public static void main(String[] args) {
        fib(6);
        int total = 0;
        for (int n = 6; n >= 0; n--) {
            System.out.println("fib(" + n + "): " + counts[n]);
            total += counts[n];
        }
        System.out.println("total " + total);
    }
}
```

```text
fib(6): 1
fib(5): 1
fib(4): 2
fib(3): 3
fib(2): 5
fib(1): 8
fib(0): 5
total 25
```

</Step>

<Step title="4. Check">

`fib(3)` is called **3 times** and the total is **25**, as the program shows. The counts 1, 1, 2, 3, 5, 8 are Fibonacci numbers themselves, which is why the work grows so fast. The total agrees with the earlier table: `fib(6)` makes 25 calls.

</Step>

</Steps>

</details>

## 3. Writing methods: five questions

### Exam question 5: binary string to decimal (5 marks)

Write a recursive method `int toDecimal(String bits)` that converts a string of `0` and `1` characters to its value: `"1101"` gives 13. The empty string gives 0. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The input is a string, the output an `int`, and the empty string is given as the base case. The string must be shortened by one character each call.

</Step>

<Step title="2. Plan">

The value of `"1101"` is 2 times the value of `"110"` plus the last bit. So drop the **last** character with `substring(0, length - 1)`, double the answer, and add the last bit. A character `'1'` minus `'0'` is the number 1.

</Step>

<Step title="3. Solution">

```java title="ToDecimal.java"
public class ToDecimal {
    // Question: convert a string of 0s and 1s to its value, recursively.
    static int toDecimal(String bits) {
        if (bits.isEmpty()) {
            return 0;                         // base case: no bits
        }
        int last = bits.charAt(bits.length() - 1) - '0';       // 0 or 1
        return 2 * toDecimal(bits.substring(0, bits.length() - 1)) + last;
    }

    public static void main(String[] args) {
        System.out.println(toDecimal("1101"));
        System.out.println(toDecimal("0"));
        System.out.println(toDecimal("1"));
        System.out.println(toDecimal(""));
        System.out.println(toDecimal("100000"));
    }
}
```

```text
13
0
1
0
32
```

</Step>

<Step title="4. Check">

`"1101"`: `2 * toDecimal("110") + 1`; `"110"`: `2 * toDecimal("11") + 0`; `"11"`: `2 * toDecimal("1") + 1`; `"1"`: `2 * 0 + 1 = 1`. Back up: 3, 6, 13. The edge cases `""` (0) and `"100000"` (32) agree with the program.

</Step>

</Steps>

</details>

### Exam question 6: the last position of a value (5 marks)

Write a recursive method `int lastIndexOf(int[] a, int target, int n)` that looks at the first `n` elements of `a` and returns the index of the **last** occurrence of `target`, or -1. Call it for `{10, 20, 30, 20}`. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

`n` is a count of the elements still to look at, so the last of them is `a[n - 1]`. Searching from the back means the first match found is the last occurrence.

</Step>

<Step title="2. Plan">

Base case 1: `n == 0`, nothing left, return -1. Base case 2: `a[n - 1]` equals the target, return `n - 1`. Otherwise search the first `n - 1` elements.

</Step>

<Step title="3. Solution">

```java title="LastIndexOf.java"
public class LastIndexOf {
    // Question: the index of the last occurrence of target among the first n elements, or -1.
    static int lastIndexOf(int[] a, int target, int n) {
        if (n == 0) {
            return -1;                        // nothing left to look at
        }
        if (a[n - 1] == target) {
            return n - 1;                     // found at the back
        }
        return lastIndexOf(a, target, n - 1);
    }

    public static void main(String[] args) {
        int[] a = {10, 20, 30, 20};
        System.out.println(lastIndexOf(a, 20, a.length));
        System.out.println(lastIndexOf(a, 10, a.length));
        System.out.println(lastIndexOf(a, 99, a.length));
        System.out.println(lastIndexOf(new int[] {}, 5, 0));
    }
}
```

```text
3
0
-1
-1
```

</Step>

<Step title="4. Check">

For 20: `n = 4`, `a[3] = 20`, so the answer is 3 at once and the earlier 20 at index 1 is not reached. For 10: the calls go from `n = 4` down to `n = 1`, where `a[0] = 10`, giving 0. For 99 the count reaches 0 and the answer is -1, as it is for the empty array.

</Step>

</Steps>

</details>

### Exam question 7: print an array backwards (3 marks)

Write a recursive method `void printReverse(int[] a, int i)` that prints the elements of `a` from the last to the first, on one line, without a loop. (3 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Without a loop" means recursion, and the order of the output is reversed, so the print must be **after** the call, as in the binary example.

</Step>

<Step title="2. Plan">

Handle position `i` after everything to its right: recurse with `i + 1` first, then print `a[i]`. The base case is `i == a.length`, where nothing is printed.

</Step>

<Step title="3. Solution">

```java title="PrintReverse.java"
public class PrintReverse {
    // Question: print the elements from last to first, recursively.
    static void printReverse(int[] a, int i) {
        if (i == a.length) {
            return;
        }
        printReverse(a, i + 1);               // everything to the right first
        System.out.print(a[i] + " ");         // then this one, on the way back up
    }

    public static void main(String[] args) {
        printReverse(new int[] {4, 8, 15, 16}, 0);
        System.out.println();
        printReverse(new int[] {}, 0);
        System.out.println("[nothing]");
    }
}
```

```text
16 15 8 4
[nothing]
```

</Step>

<Step title="4. Check">

The calls go down to `i = 4` before anything is printed. Then 16, 15, 8 and 4 are printed as the calls return. The empty array prints nothing.

</Step>

</Steps>

</details>

### Exam question 8: an integer as a binary string (5 marks)

Write a recursive method `String toBinary(int n)` for `n` of at least 0 that **returns** the binary form: 13 gives `"1101"` and 0 gives `"0"`. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The method returns a `String` rather than printing, so the answer is built by concatenation, and `0` must give `"0"`, not the empty string.

</Step>

<Step title="2. Plan">

The binary form of `n` is the binary form of `n / 2` followed by the digit `n % 2`. A number below 2 is one digit: that is the base case, and it also covers 0.

</Step>

<Step title="3. Solution">

```java title="ToBinary.java"
public class ToBinary {
    // Question: return the binary form of n (n at least 0) as a String.
    static String toBinary(int n) {
        if (n < 2) {
            return "" + n;                    // base case: 0 and 1 are single digits
        }
        return toBinary(n / 2) + n % 2;       // the digits of n / 2, then the last digit
    }

    public static void main(String[] args) {
        System.out.println(toBinary(13));
        System.out.println(toBinary(0));
        System.out.println(toBinary(1));
        System.out.println(toBinary(8));
        System.out.println(toBinary(255));
    }
}
```

```text
1101
0
1
1000
11111111
```

</Step>

<Step title="4. Check">

`toBinary(13)` is `toBinary(6) + 1`, which is `toBinary(3) + 0 + 1`, which is `toBinary(1) + 1 + 0 + 1` = `"1101"`. The base case `n < 2` makes `toBinary(0)` return `"0"`. Because the left operand of the first `+` is a `String`, `n % 2` is appended as a digit and is not added to anything.

</Step>

</Steps>

</details>

### Exam question 9: digital root (5 marks)

The **digital root** of a number is found by adding its digits and repeating on the result until one digit remains: 9875 gives 29, then 11, then 2. Write a recursive method `int digitalRoot(int n)` and use a recursive helper for the digit sum. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two recursions are asked for, one inside the other. The helper `digitSum` is the one from the first lesson; `digitalRoot` calls itself on the sum.

</Step>

<Step title="2. Plan">

If `n` is already a single digit (below 10), return it. Otherwise the answer is the digital root of the digit sum of `n`; the digit sum is smaller than `n` for any `n` of at least 10, so the argument shrinks.

</Step>

<Step title="3. Solution">

```java title="DigitalRoot.java"
public class DigitalRoot {
    // Question: repeat the digit sum until one digit remains.
    static int digitSum(int n) {
        if (n == 0) {
            return 0;
        }
        return n % 10 + digitSum(n / 10);
    }

    static int digitalRoot(int n) {
        if (n < 10) {
            return n;                         // base case: one digit
        }
        return digitalRoot(digitSum(n));      // the argument gets smaller
    }

    public static void main(String[] args) {
        System.out.println(digitalRoot(9875));
        System.out.println(digitalRoot(7));
        System.out.println(digitalRoot(99));
        System.out.println(digitalRoot(0));
    }
}
```

```text
2
7
9
0
```

</Step>

<Step title="4. Check">

`digitalRoot(9875)`: the digit sum is 29, which is not below 10, so continue with 29; its digit sum is 11; its digit sum is 2, which is below 10, so the answer is 2. For 99 the sum is 18, then 9. A single digit and 0 are returned at once.

</Step>

</Steps>

</details>

## 4. Converting: three questions

### Exam question 10: a loop with an accumulator (5 marks)

Convert this method to a recursive method with an accumulator, and state what it returns for 1230. (5 marks)

```java
static int reverseDigits(int n) {
    int r = 0;
    while (n > 0) {
        r = r * 10 + n % 10;
        n = n / 10;
    }
    return r;
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The loop changes two variables, `n` and `r`. The answer is `r`. "With an accumulator" tells you `r` becomes a parameter that carries the answer down.

</Step>

<Step title="2. Plan">

Apply the three rules. Parameters: `n` and `r`. Base case: the opposite of `n > 0`, which is `n == 0` for non-negative `n`, returning `r`. Recursive case: the call `reverseDigits(n / 10, r * 10 + n % 10)`. The first call passes 0 for `r`.

</Step>

<Step title="3. Solution">

```java title="ReverseDigits.java"
public class ReverseDigits {
    // Question: the loop and its recursive version.
    static int reverseLoop(int n) {
        int r = 0;
        while (n > 0) {
            r = r * 10 + n % 10;
            n = n / 10;
        }
        return r;
    }

    static int reverseRec(int n, int r) {
        if (n == 0) {
            return r;                         // loop condition false: r holds the answer
        }
        return reverseRec(n / 10, r * 10 + n % 10);
    }

    public static void main(String[] args) {
        int[] values = {1234, 1230, 7, 0};
        for (int n : values) {
            System.out.println(n + ": " + reverseLoop(n) + " " + reverseRec(n, 0));
        }
    }
}
```

```text
1234: 4321 4321
1230: 321 321
7: 7 7
0: 0 0
```

</Step>

<Step title="4. Check">

Both give 4321 for 1234. For 1230 both give **321**: the leading zero of the reversed number (0321) is a number, 321, so the zero is lost. For 0 and for a single digit the base case or one step returns at once.

</Step>

</Steps>

</details>

### Exam question 11: a recursion with two calls, as a loop (5 marks)

The method `ways(n)` returns 1 for `n` of 0 or 1, and otherwise `ways(n - 1) + ways(n - 2)`. Write a loop version using two variables and show that the two agree for 0 to 8. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A branching recursion cannot be converted by renaming parameters. It depends on the two previous values, so a loop must **keep the last two values** in variables.

</Step>

<Step title="2. Plan">

Start with `a = ways(0) = 1` and `b = ways(1) = 1`. Each pass computes the next value as `a + b`, then moves the pair along: `a` takes `b`'s old value, `b` takes the new one. After the pass for `i`, `b` holds `ways(i)`.

</Step>

<Step title="3. Solution">

```java title="WaysLoop.java"
public class WaysLoop {
    // Question: ways(n) with a loop, compared with the recursive version for 0 to 8.
    static int waysRec(int n) {
        if (n <= 1) {
            return 1;
        }
        return waysRec(n - 1) + waysRec(n - 2);
    }

    static int waysLoop(int n) {
        int a = 1;                            // ways(0)
        int b = 1;                            // ways(1)
        for (int i = 2; i <= n; i++) {
            int next = a + b;
            a = b;
            b = next;
        }
        return b;
    }

    public static void main(String[] args) {
        for (int n = 0; n <= 8; n++) {
            System.out.println(n + ": " + waysRec(n) + " " + waysLoop(n) + " " + (waysRec(n) == waysLoop(n)));
        }
    }
}
```

```text
0: 1 1 true
1: 1 1 true
2: 2 2 true
3: 3 3 true
4: 5 5 true
5: 8 8 true
6: 13 13 true
7: 21 21 true
8: 34 34 true
```

</Step>

<Step title="4. Check">

All nine lines agree. For `n = 0` and `n = 1` the loop does not run and `b` is still 1, the two base cases. The loop makes `n - 1` passes; the recursion makes an exponential number of calls.

</Step>

</Steps>

</details>

### Exam question 12: recursion against iteration (4 marks)

Using the Fibonacci method as your example, state two advantages and two disadvantages of recursion compared with iteration. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"State" needs four short points, two for and two against, and the example must be Fibonacci. Quote numbers from a run where you can.

</Step>

<Step title="2. Plan">

Advantages: the code mirrors the definition; some problems (trees, backtracking, divide and conquer) are much simpler recursively. Disadvantages: the cost of the calls (time and one stack frame each) and the risk of a `StackOverflowError`; repeated work in a branching recursion.

</Step>

<Step title="3. Solution">

**For recursion.** (1) The code is the definition: `fib(n) = fib(n - 1) + fib(n - 2)` with two base cases, and is easy to check against it. (2) Problems whose natural shape is a tree, such as subsets, permutations and Hanoi, are short to write recursively and hard to write with a loop.

**Against recursion.** (3) Every call costs time and a stack frame. In the earlier lesson, `fib(30)` made 2,692,537 calls, against 30 passes of the loop. (4) A very deep recursion ends in a `StackOverflowError`, and a branching recursion recomputes the same values: `fib(2)` is computed three times inside `fib(5)`. Remembering the answers (memoisation) reduced the calls to 59 without leaving the recursive form.

</Step>

<Step title="4. Check">

Each point is a different idea and at least one carries a number from a real run. A weak answer says only "recursion is slower"; a good answer says why (repeated work, frames) and when it does not matter (a halving recursion has only log n frames).

</Step>

</Steps>

</details>

## 5. Finding the fault: three questions

### Exam question 13: the argument goes the wrong way (4 marks)

Explain why `sum(3)` ends in a `StackOverflowError` and repair the method. (4 marks)

```java
static int sum(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sum(n + 1);
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The method has a base case (`n == 0`) and a recursive case. Check the third requirement: does the recursive case move **towards** the base case?

</Step>

<Step title="2. Plan">

Write the arguments for `sum(3)`: 3, 4, 5, 6 and so on. They go up, away from 0, so the base case is never reached.

</Step>

<Step title="3. Solution">

```java title="SumWrongWay.java"
public class SumWrongWay {
    // Question: why does sum(3) never finish, and how is it repaired?
    static int broken(int n) {
        if (n == 0) {
            return 0;
        }
        return n + broken(n + 1);
    }

    static int fixed(int n) {
        if (n <= 0) {
            return 0;                         // a range test also protects negative n
        }
        return n + fixed(n - 1);
    }

    public static void main(String[] args) {
        try {
            broken(3);
        } catch (StackOverflowError e) {
            System.out.println("broken(3): " + e.getClass().getName());
        }
        System.out.println(fixed(3));
        System.out.println(fixed(0));
        System.out.println(fixed(-2));
    }
}
```

```text
broken(3): java.lang.StackOverflowError
6
0
0
```

</Step>

<Step title="4. Check">

The fault is `n + 1`, which should be `n - 1`. After the repair `fixed(3)` is 3 + 2 + 1 = 6. Changing the base case to `n <= 0` also makes a negative argument return 0 instead of calling itself forever, but note that the specification should say what a negative `n` means.

</Step>

</Steps>

</details>

### Exam question 14: a base case that is not enough (4 marks)

This palindrome test works for `"abba"` but fails for `"aba"`. Name the exception, explain why, and repair it. (4 marks)

```java
static boolean isPal(String s) {
    if (s.length() == 0) {
        return true;
    }
    if (s.charAt(0) != s.charAt(s.length() - 1)) {
        return false;
    }
    return isPal(s.substring(1, s.length() - 1));
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The method drops **two** characters each call, so the length goes down by 2. Check which lengths reach the base case.

</Step>

<Step title="2. Plan">

Length 4 goes to 2, then 0: the base case. Length 3 goes to 1, then to `substring(1, 0)`, which has its end before its start. Run it to see the exception name.

</Step>

<Step title="3. Solution">

```java title="PalindromeFault.java"
public class PalindromeFault {
    // Question: why does isPal("aba") fail, and how is it repaired?
    static boolean isPal(String s) {
        if (s.length() == 0) {
            return true;
        }
        if (s.charAt(0) != s.charAt(s.length() - 1)) {
            return false;
        }
        return isPal(s.substring(1, s.length() - 1));
    }

    static boolean isPalFixed(String s) {
        if (s.length() <= 1) {
            return true;                      // empty or a single character
        }
        if (s.charAt(0) != s.charAt(s.length() - 1)) {
            return false;
        }
        return isPalFixed(s.substring(1, s.length() - 1));
    }

    public static void main(String[] args) {
        System.out.println(isPal("abba"));
        try {
            isPal("aba");
        } catch (StringIndexOutOfBoundsException e) {
            System.out.println("isPal(aba): " + e.getClass().getName());
        }
        System.out.println(isPalFixed("aba"));
        System.out.println(isPalFixed("abba"));
        System.out.println(isPalFixed("abca"));
    }
}
```

```text
true
isPal(aba): java.lang.StringIndexOutOfBoundsException
true
true
false
```

</Step>

<Step title="4. Check">

For `"aba"` the first call drops the ends and leaves `"b"` (length 1). That call compares `'b'` with itself, which is equal, and then evaluates `substring(1, 0)`, which throws `StringIndexOutOfBoundsException`. Odd lengths end at length 1, so the base case must include 1: `s.length() <= 1`. The repaired method returns `true` for `"aba"` and `"abba"` and `false` for `"abca"`.

</Step>

</Steps>

</details>

### Exam question 15: reversing in place (4 marks)

This method reverses an array in place. It works for `{1, 2, 3}` but fails for `{1, 2}`. Name the exception, explain the fault and repair it. (4 marks)

```java
static void reverse(int[] a, int lo, int hi) {
    if (lo == hi) {
        return;
    }
    int t = a[lo];
    a[lo] = a[hi];
    a[hi] = t;
    reverse(a, lo + 1, hi - 1);
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two indexes move towards each other, `lo` up and `hi` down. The base case tests for equality. Ask whether they always meet.

</Step>

<Step title="2. Plan">

For 3 elements they meet at index 1. For 2 elements `lo = 0`, `hi = 1`, then `lo = 1`, `hi = 0`: they cross without ever being equal.

</Step>

<Step title="3. Solution">

```java title="ReverseFault.java"
import java.util.Arrays;

public class ReverseFault {
    // Question: why does the reversal fail for an even number of elements?
    static void broken(int[] a, int lo, int hi) {
        if (lo == hi) {
            return;
        }
        int t = a[lo];
        a[lo] = a[hi];
        a[hi] = t;
        broken(a, lo + 1, hi - 1);
    }

    static void fixed(int[] a, int lo, int hi) {
        if (lo >= hi) {
            return;                           // met or crossed
        }
        int t = a[lo];
        a[lo] = a[hi];
        a[hi] = t;
        fixed(a, lo + 1, hi - 1);
    }

    public static void main(String[] args) {
        int[] odd = {1, 2, 3};
        broken(odd, 0, 2);
        System.out.println(Arrays.toString(odd));
        try {
            broken(new int[] {1, 2}, 0, 1);
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("broken: " + e.getClass().getName());
        }
        int[] even = {1, 2};
        fixed(even, 0, 1);
        System.out.println(Arrays.toString(even));
    }
}
```

```text
[3, 2, 1]
broken: java.lang.ArrayIndexOutOfBoundsException
[2, 1]
```

</Step>

<Step title="4. Check">

For `{1, 2}` the pair swaps once, `lo` becomes 1 and `hi` becomes 0, and they are not equal, so the swap runs again and the indexes move on to 2 and -1, which are outside the array. Testing `lo >= hi` stops as soon as the indexes meet or cross, for any length including 0. The repaired method gives `[2, 1]`.

</Step>

</Steps>

</details>

## 6. Counting calls and stack depth: one question

### Exam question 16: calls and depth, linear against halving (5 marks)

The method `sumLinear(lo, hi)` adds the numbers from `lo` to `hi` one at a time. The method `sumHalves` adds the elements of an array by splitting the range in half. For n = 16 and n = 64 elements, state the number of calls and the greatest depth of the stack for each, and say which is more likely to overflow the stack. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two quantities are asked for each method: the number of calls and the greatest depth. Count the first call as depth 1.

</Step>

<Step title="2. Plan">

`sumLinear` makes one call per number plus one for the empty range, so n + 1 calls, each one level deeper than the last: depth n + 1. `sumHalves` splits until one element: 2n - 1 calls, and the depth is the number of halvings plus 1.

</Step>

<Step title="3. Solution">

```java title="CallsAndDepth.java"
public class CallsAndDepth {
    // Question: the calls and the greatest depth of a linear and a halving sum.
    static int calls;
    static int maxDepth;

    static int sumLinear(int lo, int hi, int depth) {
        calls++;
        if (depth > maxDepth) {
            maxDepth = depth;
        }
        if (lo > hi) {
            return 0;
        }
        return lo + sumLinear(lo + 1, hi, depth + 1);
    }

    static int sumHalves(int[] a, int lo, int hi, int depth) {
        calls++;
        if (depth > maxDepth) {
            maxDepth = depth;
        }
        if (lo == hi) {
            return a[lo];
        }
        int mid = (lo + hi) / 2;
        return sumHalves(a, lo, mid, depth + 1) + sumHalves(a, mid + 1, hi, depth + 1);
    }

    public static void main(String[] args) {
        int[] sizes = {16, 64};
        for (int n : sizes) {
            calls = 0;
            maxDepth = 0;
            sumLinear(1, n, 1);
            System.out.println("n " + n + " linear: calls " + calls + ", depth " + maxDepth);
            calls = 0;
            maxDepth = 0;
            sumHalves(new int[n], 0, n - 1, 1);
            System.out.println("n " + n + " halving: calls " + calls + ", depth " + maxDepth);
        }
    }
}
```

```text
n 16 linear: calls 17, depth 17
n 16 halving: calls 31, depth 5
n 64 linear: calls 65, depth 65
n 64 halving: calls 127, depth 7
```

</Step>

<Step title="4. Check">

Linear: n + 1 calls and depth n + 1 (17 and 65 here). Halving: 2n - 1 calls (31 and 127) but depth only 5 and 7, which is log base 2 of n plus 1. The linear version is far more likely to overflow the stack for a large n, because its depth grows with n; the halving version does more calls in total but never has more than about log n frames waiting at once.

</Step>

</Steps>

</details>

## 7. Errors to check before handing in

- The **base case** exists, is reachable from every legal input (use `<=` or `>=` when the argument steps by more than 1), and returns the **identity value** for the combination.
- The recursive call has a **smaller** argument, in the right direction (`n - 1`, not `n + 1`).
- A method that calls itself twice has **two** base cases, or one that covers the value just above the one it can skip.
- A count is not an index: with a count `n` the last element is `a[n - 1]`.
- A print before the call prints going down; a print after the call prints coming up.
- In a string method, the first `+` must have a `String` on its left, or two `char` values are added as numbers.
- A trace has a row for every call, the Returned column written going down, and the Result column filled going up.
- State the **precondition** (non-negative, non-empty) when the method has no sensible answer outside it.

## Summary

<Callout type="key" title="Remember">

For every recursion answer, find the base case and its value, the smaller input and its direction, and the combination, and check one small input and the edge case. Print before the call to print going down, after it to print coming up. A base case written with `==` can be stepped over; use a range. A linear recursion has depth n, a halving recursion has depth about log n, and a method that calls itself twice can make an exponential number of calls.

</Callout>
