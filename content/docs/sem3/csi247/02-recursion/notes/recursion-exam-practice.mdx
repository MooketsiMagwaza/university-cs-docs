## 1. How to earn the marks

| Command word | What the marker wants |
|---|---|
| Trace | A trace table with a row per call: the level, the parameter, whether the base case condition is true, the expression returned with the recursive call unevaluated, and the result filled in from the bottom up. The final value clearly marked |
| Write | The signature, the base case (with the right value), the recursive call on a smaller input, and the way the answer is combined. The inputs for which it is valid |
| Convert | The loop version of a recursion (or the reverse), tested on the same input, with the outputs compared |
| Explain | The reason in one or two sentences, using the words base case, recursive case, stack |
| Draw | The stack of calls at the stated moment: one box per call with its parameter and what it is waiting for |

## 2. Tracing: three questions

### Exam question 1: trace factR(7) (6 marks)

Trace the call `factR(7)` using a trace table, where `factR` is

```java
public static long factR(int n) {
    if (n == 1)
        return 1;
    else
        return n * factR(n - 1);
}
```

(6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Trace" asks for a table in the lecture's format: level, `n`, the condition `n == 1`, what is returned (the recursive call left unevaluated) and the result, which is filled in from the bottom up. The base case is `n == 1`.

</Step>

<Step title="2. Plan">

Go down from `n = 7` to `n = 1`, one row per call, writing `n * factR(n - 1)` in the Returned column. When `n == 1` is true, that row returns 1. Then fill the Results column from the last row upwards.

</Step>

<Step title="3. Solution">

| Level | `n` | `n == 1`? | Returned | Result |
|---|---|---|---|---|
| 0 | 7 | false | `7 * factR(6)` | 7 * 720 = **5040** |
| 1 | 6 | false | `6 * factR(5)` | 6 * 120 = 720 |
| 2 | 5 | false | `5 * factR(4)` | 5 * 24 = 120 |
| 3 | 4 | false | `4 * factR(3)` | 4 * 6 = 24 |
| 4 | 3 | false | `3 * factR(2)` | 3 * 2 = 6 |
| 5 | 2 | false | `2 * factR(1)` | 2 * 1 = 2 |
| 6 | 1 | true | `1` | 1 |

```java title="TraceFactR.java"
public class TraceFactR {
    // Question: check the trace of factR(7) by printing each result as the call returns.
    static int calls;

    static long factR(int n) {
        calls++;
        long result;
        if (n == 1) {
            result = 1;
        } else {
            result = n * factR(n - 1);
        }
        System.out.println("factR(" + n + ") = " + result);
        return result;
    }

    public static void main(String[] args) {
        factR(7);
        System.out.println("calls " + calls);
    }
}
```

```text
factR(1) = 1
factR(2) = 2
factR(3) = 6
factR(4) = 24
factR(5) = 120
factR(6) = 720
factR(7) = 5040
calls 7
```

</Step>

<Step title="4. Check">

The program prints the results in the order they come back up, 1, 2, 6, 24, 120, 720, 5040, which is the Result column read from the bottom. There are 7 calls, one for each level. As a check, 7! = 7 x 6 x 5 x 4 x 3 x 2 x 1 = 5040.

</Step>

</Steps>

</details>

### Exam question 2: trace power (6 marks)

Trace `power(6, 3)` and `power(2, 8)`, where `power(x, y)` returns 1 when `y == 0` and `x * power(x, y - 1)` otherwise. State how many calls each makes. (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two traces are asked for, and a count of calls for each. In this method `x` never changes and `y` goes down by one, so the base case is `y == 0`.

</Step>

<Step title="2. Plan">

Write one row per value of `y`, from the starting `y` down to 0. Fill the Result column from the bottom. The number of calls is the number of rows.

</Step>

<Step title="3. Solution">

For `power(6, 3)`:

| Level | `x` | `y` | `y == 0`? | Returned | Result |
|---|---|---|---|---|---|
| 0 | 6 | 3 | false | `6 * power(6, 2)` | 6 * 36 = **216** |
| 1 | 6 | 2 | false | `6 * power(6, 1)` | 6 * 6 = 36 |
| 2 | 6 | 1 | false | `6 * power(6, 0)` | 6 * 1 = 6 |
| 3 | 6 | 0 | true | `1` | 1 |

For `power(2, 8)` there are nine rows, `y` = 8 down to 0, and the results coming back up are 1, 2, 4, 8, 16, 32, 64, 128, 256.

```java title="TracePower.java"
public class TracePower {
    // Question: check the traces of power(6, 3) and power(2, 8).
    static int calls;

    static int power(int x, int y) {
        calls++;
        int result;
        if (y == 0) {
            result = 1;
        } else {
            result = x * power(x, y - 1);
        }
        System.out.println("power(" + x + ", " + y + ") = " + result);
        return result;
    }

    public static void main(String[] args) {
        power(6, 3);
        System.out.println("calls " + calls);
        calls = 0;
        power(2, 8);
        System.out.println("calls " + calls);
    }
}
```

```text
power(6, 0) = 1
power(6, 1) = 6
power(6, 2) = 36
power(6, 3) = 216
calls 4
power(2, 0) = 1
power(2, 1) = 2
power(2, 2) = 4
power(2, 3) = 8
power(2, 4) = 16
power(2, 5) = 32
power(2, 6) = 64
power(2, 7) = 128
power(2, 8) = 256
calls 9
```

</Step>

<Step title="4. Check">

The program agrees with both tables: 216 after 4 calls, and 256 after 9 calls. In general `power(x, y)` makes `y + 1` calls, one more than the exponent.

</Step>

</Steps>

### Exam question 3: trace fibonacci (8 marks)

The recursive method `fibonacci(n)` returns 0 when `n` is 0, 1 when `n` is 1, and `fibonacci(n - 1) + fibonacci(n - 2)` otherwise. Trace `fibonacci(6)` by listing every call, state its value, and state the value of `fibonacci(9)` and how many calls it makes. (8 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A method that calls itself twice does not make a chain of calls: it makes a tree. A table with one row per call is long, so list the calls in the order they happen, indented by their depth, and mark the base cases with their values.

</Step>

<Step title="2. Plan">

Start at `fibonacci(6)`. Each call below `n` of 2 or more lists `fibonacci(n - 1)` first and its whole subtree, then `fibonacci(n - 2)`. Base cases print their value. Then add the values going up.

</Step>

<Step title="3. Solution">

```java title="TraceFibonacci.java"
public class TraceFibonacci {
    // Question: list every call made by fibonacci(6), then fibonacci(9).
    static int calls;

    static int fibonacci(int n, int depth, boolean show) {
        calls++;
        if (show) {
            String indent = "";
            for (int i = 0; i < depth; i++) {
                indent += "  ";
            }
            System.out.println(indent + "fibonacci(" + n + ")");
        }
        if (n <= 1) {
            return n;
        }
        return fibonacci(n - 1, depth + 1, show) + fibonacci(n - 2, depth + 1, show);
    }

    public static void main(String[] args) {
        int value = fibonacci(6, 0, true);
        System.out.println("fibonacci(6) = " + value + ", calls " + calls);
        calls = 0;
        value = fibonacci(9, 0, false);
        System.out.println("fibonacci(9) = " + value + ", calls " + calls);
    }
}
```

```text
fibonacci(6)
  fibonacci(5)
    fibonacci(4)
      fibonacci(3)
        fibonacci(2)
          fibonacci(1)
          fibonacci(0)
        fibonacci(1)
      fibonacci(2)
        fibonacci(1)
        fibonacci(0)
    fibonacci(3)
      fibonacci(2)
        fibonacci(1)
        fibonacci(0)
      fibonacci(1)
  fibonacci(4)
    fibonacci(3)
      fibonacci(2)
        fibonacci(1)
        fibonacci(0)
      fibonacci(1)
    fibonacci(2)
      fibonacci(1)
      fibonacci(0)
fibonacci(6) = 8, calls 25
fibonacci(9) = 34, calls 109
```

</Step>

<Step title="4. Check">

The tree has 25 lines, so `fibonacci(6)` makes 25 calls and returns 8 (0, 1, 1, 2, 3, 5, 8). `fibonacci(9)` returns 34 and makes 109 calls. The same small values are called again and again: `fibonacci(2)` appears five times in the tree for 6. This is why the recursive version makes so many more calls than the loop version makes steps.

</Step>

</Steps>

</details>

## 3. Writing and converting: three questions

### Exam question 4: display the series (Lab 3, question 1b) (5 marks)

Write a method `fibonacci(int n)` that displays the first `n` numbers of the Fibonacci series, starting with 0 and 1. For example, `fibonacci(6)` displays `0 1 1 2 3 5`. Use a recursive method to find each number. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command word is "write". Two methods are needed: one that finds the number at a given position recursively, and one that displays the first `n` positions. The series starts at position 0.

</Step>

<Step title="2. Plan">

`fib(i)` has base cases 0 and 1 and two recursive calls. The display method loops `i` from 0 to `n - 1` and prints `fib(i)`.

</Step>

<Step title="3. Solution">

```java title="FibonacciSeries.java"
public class FibonacciSeries {
    // Question: display the first n Fibonacci numbers.
    static int fib(int i) {
        if (i <= 1) {
            return i;                         // base cases: fib(0) = 0 and fib(1) = 1
        }
        return fib(i - 1) + fib(i - 2);
    }

    static void fibonacci(int n) {
        for (int i = 0; i < n; i++) {
            System.out.print(fib(i) + " ");
        }
        System.out.println();
    }

    public static void main(String[] args) {
        fibonacci(6);
        fibonacci(1);
        fibonacci(9);
    }
}
```

```text
0 1 1 2 3 5
0
0 1 1 2 3 5 8 13 21
```

</Step>

<Step title="4. Check">

`fibonacci(6)` displays `0 1 1 2 3 5`, as the question says. `fibonacci(1)` displays just `0`. Each number is the sum of the two before it: 5 = 2 + 3.

</Step>

</Steps>

### Exam question 5: remove the base case (Lab 3, question 3) (4 marks)

Comment out the base case of `power` and say what happens when `power(2, 3)` is called. Repair the method. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command words are "say what happens" and "repair". The base case `if (y == 0) return 1;` is removed, so the method has only the recursive case.

</Step>

<Step title="2. Plan">

Without a base case no call can return a value without making another call, so the argument goes 3, 2, 1, 0, -1 and so on, and the frames pile up until the stack is full.

</Step>

<Step title="3. Solution">

```java title="PowerBaseCase.java"
public class PowerBaseCase {
    // Question: what happens when the base case of power is commented out?
    static int broken(int x, int y) {
        // if (y == 0) return 1;
        return x * broken(x, y - 1);
    }

    static int fixed(int x, int y) {
        if (y == 0) {
            return 1;                         // the base case is back
        }
        return x * fixed(x, y - 1);
    }

    public static void main(String[] args) {
        try {
            broken(2, 3);
        } catch (StackOverflowError e) {
            System.out.println("broken(2, 3): " + e.getClass().getName());
        }
        System.out.println(fixed(2, 3));
    }
}
```

```text
broken(2, 3): java.lang.StackOverflowError
8
```

</Step>

<Step title="4. Check">

The outcome is infinite recursion: Java reports a `StackOverflowError`. After the repair, `fixed(2, 3)` returns 8. The cause named in the lecture is a missing base case; the repair is to put it back.

</Step>

</Steps>

</details>

### Exam question 6: the iterative versions (Lab 3, question 4) (6 marks)

Write iterative versions of `factorial`, `fibonacci` (the value at position `n`) and `power`, and test them against the recursive versions. Is the output different? (6 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Three conversions are asked for, with a test. Use the rule: the base case value becomes the starting value of the loop, and the recursive case becomes the loop body.

</Step>

<Step title="2. Plan">

Factorial and power start at 1 and multiply. Fibonacci keeps the last two values in two variables and moves them along on each pass. Compare each loop with its recursive version on the Lab 3 test values.

</Step>

<Step title="3. Solution">

```java title="IterativeVersions.java"
public class IterativeVersions {
    // Question: iterative versions of factorial, fibonacci and power, compared with the recursive ones.
    static long factR(int n) {
        if (n == 1) {
            return 1;
        }
        return n * factR(n - 1);
    }

    static long factL(int n) {
        long prod = 1;
        for (int i = 1; i <= n; i++) {
            prod = prod * i;
        }
        return prod;
    }

    static int fibR(int n) {
        if (n <= 1) {
            return n;
        }
        return fibR(n - 1) + fibR(n - 2);
    }

    static int fibL(int n) {
        int a = 0;
        int b = 1;
        for (int i = 0; i < n; i++) {
            int next = a + b;
            a = b;
            b = next;
        }
        return a;
    }

    static int powerR(int x, int y) {
        if (y == 0) {
            return 1;
        }
        return x * powerR(x, y - 1);
    }

    static int powerL(int x, int y) {
        int result = 1;
        for (int i = 1; i <= y; i++) {
            result = result * x;
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println("factorial(7): " + factR(7) + " " + factL(7));
        System.out.println("fibonacci(9): " + fibR(9) + " " + fibL(9));
        System.out.println("power(2, 8): " + powerR(2, 8) + " " + powerL(2, 8));
        System.out.println("power(3, 2): " + powerR(3, 2) + " " + powerL(3, 2));
    }
}
```

```text
factorial(7): 5040 5040
fibonacci(9): 34 34
power(2, 8): 256 256
power(3, 2): 9 9
```

</Step>

<Step title="4. Check">

The outputs are the same for every test value, so the answer is no: the iterative and recursive versions give the same results for valid input. They differ in cost: the recursive `fibonacci(9)` made 109 calls (question 3) while the loop does 9 passes. They also differ for an input outside the base case, such as `factorial(0)`, as the previous lesson showed.

</Step>

</Steps>

</details>

### Exam question 7: fix the errors in the handout code (4 marks)

The handout gives this recursive factorial. Say whether it compiles, give the error message if not, and fix it. (4 marks)

```java
public static long factR(int n) {
    if (n == 1)
        return 1;
    else
        return = n * factR(n - 1);
}
```

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Fix the errors, if any" asks you to compile it in your head first. Look at each statement for a syntax fault before looking at the logic.

</Step>

<Step title="2. Plan">

The logic is correct: base case `n == 1`, recursive case `n * factR(n - 1)`. The fault is in the last statement: `return` is followed by `=`, which is not valid.

</Step>

<Step title="3. Solution">

It does not compile. The compiler reports `error: illegal start of expression` at the `=` after `return`. The repair is to delete the `=`:

```java title="FactRFixed.java"
    public static void main(String[] args) {

```

```text
120
1
```

</Step>

<Step title="4. Check">

The repaired method prints 120 for `factR(5)` and 1 for `factR(1)`. The compiler message was taken from a real compile of the handout's method. A second point worth noting in the answer: the base case `n == 1` still leaves `factR(0)` without an answer.

### Exam question 8: the two cases (4 marks)

Explain the difference between recursion and a recursive method, and state the two cases every recursive method must implement and the purpose of each. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Two definitions and two cases are asked for, so the answer has four parts. No code is needed.

</Step>

<Step title="2. Plan">

Define recursion as a technique, and a recursive method as a method written using that technique. Then the base case, then the recursive case, each with its purpose.

</Step>

<Step title="3. Solution">

**Recursion** is a programming technique in which a method calls itself to solve a problem; it is associated with repetition. A **recursive method** is a method implemented using recursion. Every recursive method must implement two cases. The **base case** stops the recursion: it is a simple case that is answered without using recursion, and at least one is needed. The **recursive case** is where the method calls itself, with an input that is closer to the base case, to help compute the final answer.

</Step>

<Step title="4. Check">

Each part has its own sentence, and the answer says that a base case must not use recursion and that every chain of recursive calls must progress towards it. A method with a recursive case and no base case is the infinite recursion of question 5.

</Step>

</Steps>

</details>

### Exam question 9: recursion against iteration (4 marks)

State the problem with recursion compared with iteration, one reason to use it anyway, and whether every recursive solution has an iterative version. Use `fibonacci` as the example. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Three statements are needed, and the example must be `fibonacci`. Quote the numbers from question 3 and question 6.

</Step>

<Step title="2. Plan">

The problem: the overhead of many method calls. The benefit: some recursive solutions are simpler and more elegant. And yes, every recursive solution has an iterative one, and the reverse.

</Step>

<Step title="3. Solution">

The problem with recursion is the overhead of multiple method calls: the recursive `fibonacci(9)` makes 109 calls, while the iterative version does 9 passes of a loop and makes none. The reason to use recursion anyway is that for some problems the recursive solution is simpler and more elegant: the recursive `fibonacci` is a direct copy of the definition. Every recursive solution has a corresponding iterative solution and every iterative solution can be rewritten recursively, so the choice is about when recursion is appropriate.

</Step>

<Step title="4. Check">

The answer gives a cost with a number, a benefit, and the equivalence in both directions, and it does not claim that recursion is always slower or always clearer.

</Step>

</Steps>

</details>

### Exam question 10: draw the call stack (5 marks)

Draw the stack of calls at the moment `factR(4)` reaches its base case, one box for each call with its value of `n` and what it is waiting for. State what happens to the boxes afterwards. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Draw the stack" asks for one box per call that is still active. `main` called `factR(4)`, which called `factR(3)`, and so on, so five boxes exist at the deepest point, and the newest is on top.

</Step>

<Step title="2. Plan">

List the boxes from the top of the stack down. Each call except the top one is waiting for the call above it to return a value to multiply by its own `n`.

</Step>

<Step title="3. Solution">

```java title="StackFrames.java"
public class StackFrames {
    // Question: which calls are on the stack when factR(4) reaches its base case?
    static long factR(int n, String waiting) {
        if (n == 1) {
            System.out.println("waiting calls, newest first: " + waiting);
            return 1;                         // the base case answers without another call
        }
        return n * factR(n - 1, n + " " + waiting);
    }

    public static void main(String[] args) {
        System.out.println(factR(4, ""));
    }
}
```

```text
waiting calls, newest first: 2 3 4
24
```

| Stack (top first) | `n` | State |
|---|---|---|
| `factR(1)` | 1 | base case: returns 1 at once |
| `factR(2)` | 2 | waiting to compute `2 * factR(1)` |
| `factR(3)` | 3 | waiting to compute `3 * factR(2)` |
| `factR(4)` | 4 | waiting to compute `4 * factR(3)` |
| `main` | | waiting for `factR(4)` to return a value |

</Step>

<Step title="4. Check">

The program lists the calls still waiting, newest first: 2, 3 and 4, with `factR(1)` running on top of them. Afterwards the boxes are removed from the top: `factR(1)` returns 1, then `factR(2)` returns 2, `factR(3)` returns 6 and `factR(4)` returns 24 to `main`. Each box has its own `n`, which is why the calls do not disturb each other. Without a base case the boxes would never stop being added, and the stack would run out of space.

</Step>

</Steps>

</details>

## 5. Errors to check before handing in

- The **base case** exists, does not use recursion, and covers every input that can reach the method (the base case `n == 1` does not cover 0).
- The recursive call moves **towards** the base case (`n - 1`, not `n + 1`), and only one recursive option executes in a call.
- The base case returns the right value for the combination: 1 for a product, 0 for a sum.
- A method that calls itself twice (Fibonacci) has two base cases.
- A trace has a row for every call, the Returned column written going down, and the Result column filled from the bottom up.
- When comparing the iterative and recursive versions, test both on the same inputs, including the smallest valid one.

## Summary

<Callout type="key" title="Remember">

Trace in the lecture format: level, parameter, base case condition, returned expression, result from the bottom up. Write each method with its base case first and test the recursive and iterative versions on the same values. A missing or unreachable base case is infinite recursion and ends in a `StackOverflowError`. The call stack holds one box per active call, newest on top, and each box has its own parameter. The recursive Fibonacci is simple but makes 25 calls for 6 and 109 for 9.
