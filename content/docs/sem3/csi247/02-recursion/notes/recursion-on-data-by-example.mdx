When the input is a number, the argument itself shrinks. When the input is an array or a string, the thing that shrinks is an **index**, a **range** or a **shorter string**, so most of these methods have a public method and a helper with an extra parameter. This lesson works through arrays, strings, ranges and accumulators with many variations and the exam questions that go with them. It follows [Recursion by Example](/docs/sem3/csi247/02-recursion/notes/recursion-by-example), which covers counters, powers, digits and branching recursion.

## 1. The template: a public method and a helper

The caller passes the array. The recursion needs to know where it is, so a second method carries an extra parameter.

```text
static ReturnType method(Type[] a) {            // the method the caller sees
    return helper(a, 0);                        // start at the first position
}

static ReturnType helper(Type[] a, int i) {     // i is the position still to be handled
    if (i == a.length) {                        // base case: past the last element
        return identity;
    }
    return combine(a[i], helper(a, i + 1));     // this element, then the rest
}
```

Use this table to choose the helper parameters and the base case for each data shape.

| Data and direction | Helper parameters | Base case | Smaller problem |
|---|---|---|---|
| Array, front to back | `a`, `i` | `i == a.length` | `i + 1` |
| Array, back to front | `a`, `n` (how many elements are left) | `n == 0` | `n - 1` |
| Array, a range | `a`, `lo`, `hi` | `lo > hi`, or `lo == hi` | `lo + 1`, or a half |
| String, from the front | `s` | `s.isEmpty()` | `s.substring(1)` |
| String, both ends | `s` | `s.length() <= 1` | `s.substring(1, s.length() - 1)` |

Trace by writing the array (or string) and the position in the first column, one row per call, and the returned value in the last column filled from the bottom up.

## 2. Array recursion with an index

### Sum from the front

```java title="ArraySum.java"
public class ArraySum {
    // Question: return the sum of the elements of an int array, recursively.
    static int sum(int[] a) {
        return sum(a, 0);
    }

    static int sum(int[] a, int i) {
        if (i == a.length) {
            return 0;                         // base case: no elements left, an empty sum
        }
        return a[i] + sum(a, i + 1);          // this element plus the sum of the rest
    }

    public static void main(String[] args) {
        System.out.println(sum(new int[] {4, 8, 15, 16}));
        System.out.println(sum(new int[] {}));
        System.out.println(sum(new int[] {7}));
    }
}
```

```text
43
0
7
```

The empty array is handled by the base case alone: `i` starts at 0, which equals `a.length`, so the answer is 0. Because the base case is "past the end", no special code for an empty array is needed.

### Sum from the back

```java title="ArraySumBack.java"
public class ArraySumBack {
    // Question: the same sum, with a count n of the elements still to add.
    static int sumBack(int[] a, int n) {
        if (n == 0) {
            return 0;                         // base case: nothing left to add
        }
        return a[n - 1] + sumBack(a, n - 1);  // the last of the n elements, then the first n - 1
    }

    public static void main(String[] args) {
        int[] marks = {4, 8, 15, 16};
        System.out.println(sumBack(marks, marks.length));
        System.out.println(sumBack(marks, 2));
        System.out.println(sumBack(marks, 0));
    }
}
```

```text
43
12
0
```

Here the parameter is a **count**, not an index, so the last element is `a[n - 1]`. Passing a smaller `n` sums only the first `n` elements: `sumBack(marks, 2)` is 4 + 8. Mixing up "index" and "count" is the usual slip: with a count the first call is `a.length`, not `a.length - 1`.

### The largest element, with the base case on the last element

```java title="ArrayMax.java"
public class ArrayMax {
    // Question: return the largest element of a non-empty int array.
    static int max(int[] a) {
        return max(a, 0);
    }

    static int max(int[] a, int i) {
        if (i == a.length - 1) {
            return a[i];                      // base case: the last element is the largest of itself
        }
        return Math.max(a[i], max(a, i + 1)); // larger of this element and the largest of the rest
    }

    public static void main(String[] args) {
        System.out.println(max(new int[] {4, 19, 7, 12}));
        System.out.println(max(new int[] {5}));
        try {
            max(new int[] {});
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println(e.getClass().getName());
        }
    }
}
```

```text
19
5
java.lang.ArrayIndexOutOfBoundsException
```

A maximum has no identity value to return for an empty array, so the base case is a one-element array and the method has a **precondition**: the array is not empty. For the empty array `i == a.length - 1` is `0 == -1`, which is false, and `a[0]` throws. State the precondition in the answer.

### Search: the first matching index

```java title="IndexOfRec.java"
public class IndexOfRec {
    // Question: return the index of the first occurrence of target, or -1.
    static int indexOf(int[] a, int target, int i) {
        if (i == a.length) {
            return -1;                        // base case 1: ran off the end, not found
        }
        if (a[i] == target) {
            return i;                         // base case 2: found it here
        }
        return indexOf(a, target, i + 1);     // look further along
    }

    public static void main(String[] args) {
        int[] a = {10, 20, 30, 20};
        System.out.println(indexOf(a, 20, 0));
        System.out.println(indexOf(a, 30, 0));
        System.out.println(indexOf(a, 99, 0));
    }
}
```

```text
1
2
-1
```

Two base cases: one for "not found" and one for "found". Nothing is combined on the way up; the answer simply travels back unchanged. The first 20 is found at index 1, so the later 20 is never reached.

### Count the elements that satisfy a condition

```java title="CountEvens.java"
public class CountEvens {
    // Question: count the even elements of an int array.
    static int countEvens(int[] a, int i) {
        if (i == a.length) {
            return 0;
        }
        int here = (a[i] % 2 == 0) ? 1 : 0;   // 1 for this element if it qualifies
        return here + countEvens(a, i + 1);
    }

    public static void main(String[] args) {
        System.out.println(countEvens(new int[] {1, 2, 3, 4, 6}, 0));
        System.out.println(countEvens(new int[] {1, 3, 5}, 0));
        System.out.println(countEvens(new int[] {}, 0));
    }
}
```

```text
3
0
0
```

The combination adds either 1 or 0. The same shape counts marks above a limit, names that start with a letter, or any other test.

<Callout type="mistake" title="Common error">

Using `i == a.length - 1` as the base case of a **sum** or a **count**. It skips the last element's contribution unless the base case returns it, and it throws on the empty array. For methods that have an identity value (0 for a sum, 0 for a count) use `i == a.length` and return the identity. Use `a.length - 1` only when the method has no value for an empty array (a maximum) and say so.

</Callout>

### Exam question 1: is the array sorted? (5 marks)

Write a recursive method `boolean isSorted(int[] a)` that returns `true` when the elements are in ascending order (equal neighbours are allowed). Say what it returns for an empty array and for a one-element array, and trace it on `{1, 2, 2, 5}` and `{3, 1, 2}`. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command words are "write", "say" and "trace". The input is an `int[]`, the output a `boolean`. "Equal neighbours are allowed" means the test for a fault is "left is greater than right", not "left is at least right".

</Step>

<Step title="2. Plan">

Compare the element at `i` with the one at `i + 1`. If it is larger the array is not sorted. Otherwise the answer depends on the rest, from `i + 1`. When `i` has no right neighbour (`i` is the last index or beyond), there is nothing to compare: the answer is `true`. That one base case also covers the empty array and the one-element array.

</Step>

<Step title="3. Solution">

```java title="IsSorted.java"
public class IsSorted {
    // Question: return true when the array is in ascending order, equal neighbours allowed.
    static boolean isSorted(int[] a) {
        return isSorted(a, 0);
    }

    static boolean isSorted(int[] a, int i) {
        if (i >= a.length - 1) {
            return true;                      // no neighbour to compare: nothing out of order
        }
        if (a[i] > a[i + 1]) {
            return false;                     // found a pair out of order
        }
        return isSorted(a, i + 1);
    }

    public static void main(String[] args) {
        System.out.println(isSorted(new int[] {1, 2, 2, 5}));
        System.out.println(isSorted(new int[] {3, 1, 2}));
        System.out.println(isSorted(new int[] {}));
        System.out.println(isSorted(new int[] {9}));
        System.out.println(isSorted(new int[] {1, 2, 3, 2}));
    }
}
```

```text
true
false
true
true
false
```

</Step>

<Step title="4. Check">

Trace `{1, 2, 2, 5}`: `i = 0`: 1 > 2 is false; `i = 1`: 2 > 2 is false; `i = 2`: 2 > 5 is false; `i = 3`: `3 >= 3`, base case, `true`. Trace `{3, 1, 2}`: `i = 0`: 3 > 1 is true, so `false` at once, and the 2 is never examined. The empty and one-element arrays return `true` because `i = 0` is already `>= a.length - 1`.

</Step>

</Steps>

</details>

## 3. String recursion

A `String` cannot be changed, but `substring(1)` gives a new string without the first character, which is a smaller problem. `charAt(0)` is the first character and `isEmpty()` tests for the base case.

```text
first = s.charAt(0)           the character handled in this call
rest  = s.substring(1)        the smaller problem
```

### Reverse a string

```java title="ReverseString.java"
public class ReverseString {
    // Question: return the reverse of a string, recursively.
    static String reverse(String s) {
        if (s.isEmpty()) {
            return "";                        // base case: the reverse of nothing
        }
        return reverse(s.substring(1)) + s.charAt(0);   // reverse the rest, then put the first at the end
    }

    public static void main(String[] args) {
        System.out.println(reverse("Naledi"));
        System.out.println(reverse("a"));
        System.out.println("[" + reverse("") + "]");
    }
}
```

```text
idelaN
a
[]
```

`reverse("Naledi")` is `reverse("aledi") + 'N'`, and so on. The first character is attached **after** the call returns, so it ends up last. Writing it before the call would copy the string unchanged.

### Count a character

```java title="CountChar.java"
public class CountChar {
    // Question: count how many times c appears in s.
    static int countChar(String s, char c) {
        if (s.isEmpty()) {
            return 0;
        }
        int here = (s.charAt(0) == c) ? 1 : 0;
        return here + countChar(s.substring(1), c);
    }

    public static void main(String[] args) {
        System.out.println(countChar("mississippi", 's'));
        System.out.println(countChar("mississippi", 'i'));
        System.out.println(countChar("mississippi", 'z'));
        System.out.println(countChar("", 'a'));
    }
}
```

```text
4
4
0
0
```

### Palindrome: shrink from both ends

```java title="Palindrome.java"
public class Palindrome {
    // Question: is the string the same forwards and backwards?
    static boolean isPalindrome(String s) {
        if (s.length() <= 1) {
            return true;                      // base case: empty or one character
        }
        if (s.charAt(0) != s.charAt(s.length() - 1)) {
            return false;                     // the ends differ
        }
        return isPalindrome(s.substring(1, s.length() - 1));   // drop both ends
    }

    public static void main(String[] args) {
        String[] words = {"level", "kayak", "abba", "Botswana", "ab", "a", ""};
        for (String w : words) {
            System.out.println("[" + w + "] " + isPalindrome(w));
        }
    }
}
```

```text
[level] true
[kayak] true
[abba] true
[Botswana] false
[ab] false
[a] true
[] true
```

Dropping two characters each time means the base case must accept both lengths 0 (an even-length palindrome shrinks to nothing) and 1 (an odd-length one shrinks to its middle). A test `s.length() == 0` alone would pass an odd-length string down to length -1 and throw.

### Remove a character

```java title="RemoveChar.java"
public class RemoveChar {
    // Question: return s with every occurrence of c removed.
    static String removeChar(String s, char c) {
        if (s.isEmpty()) {
            return "";
        }
        String rest = removeChar(s.substring(1), c);
        if (s.charAt(0) == c) {
            return rest;                      // drop this character
        }
        return s.charAt(0) + rest;            // keep it, in front of the cleaned rest
    }

    public static void main(String[] args) {
        System.out.println(removeChar("banana", 'a'));
        System.out.println(removeChar("xyz", 'a'));
        System.out.println(removeChar("aaa", 'a').length());
    }
}
```

```text
bnn
xyz
0
```

This is the choice pattern again: one branch keeps the character and one drops it. The result is built on the way back up.

### Two characters added as numbers

```java title="DoubleChars.java"
public class DoubleChars {
    // Question: double every character, so "abc" becomes "aabbcc". One version is wrong.
    static String doubleChars(String s) {
        if (s.isEmpty()) {
            return "";
        }
        char c = s.charAt(0);
        return "" + c + c + doubleChars(s.substring(1));
    }

    static String wrong(String s) {
        if (s.isEmpty()) {
            return "";
        }
        return s.charAt(0) + s.charAt(0) + wrong(s.substring(1));
    }

    public static void main(String[] args) {
        System.out.println(doubleChars("abc"));
        System.out.println(wrong("abc"));
    }
}
```

```text
aabbcc
194196198
```

In `wrong`, `s.charAt(0) + s.charAt(0)` adds two `char` values as numbers (97 + 97 = 194) because neither operand is a `String`; only the `+` that meets the string result concatenates. The method compiles and returns a string of digits. Starting the expression with `""` makes every `+` a concatenation.

<Callout type="mistake" title="Common error">

Adding two `char` values and expecting text. `'a' + 'b'` is the number 195, not `"ab"`. In a recursive string method, start the expression with a `String` (`"" + c + c`, or `s.substring(0, 1) + ...`) or place a `String` on the left of the first `+`.

</Callout>

### Exam question 2: remove repeated neighbours (5 marks)

Write a recursive method `String compress(String s)` that replaces each run of the same character by one copy: `"aabbbc"` becomes `"abc"`. Give the result for `"abba"` and for the empty string, and explain why `"abba"` does not become `"ab"`. (5 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command words are "write", "give" and "explain". The input and output are `String`. "A run of the same character" means adjacent equal characters only, so `"abba"` keeps both a's because they are not neighbours.

</Step>

<Step title="2. Plan">

Compare the first two characters. If they are equal, drop the first and compress what is left, so the run shrinks one at a time. If they differ, keep the first and compress the rest. A string of length 0 or 1 has no pair to compare, so it is the base case and is returned as it is.

</Step>

<Step title="3. Solution">

```java title="Compress.java"
public class Compress {
    // Question: replace each run of equal neighbouring characters by one copy.
    static String compress(String s) {
        if (s.length() <= 1) {
            return s;                         // base case: no pair to compare
        }
        if (s.charAt(0) == s.charAt(1)) {
            return compress(s.substring(1));  // same as the next: drop this one
        }
        return s.charAt(0) + compress(s.substring(1));   // differs: keep this one
    }

    public static void main(String[] args) {
        System.out.println(compress("aabbbc"));
        System.out.println(compress("abc"));
        System.out.println("[" + compress("") + "]");
        System.out.println(compress("aaaa"));
        System.out.println(compress("abba"));
    }
}
```

```text
abc
abc
[]
a
aba
```

</Step>

<Step title="4. Check">

`compress("abba")`: the first two characters `a`, `b` differ, so keep `a` and compress `"bba"`; there `b`, `b` are equal, so drop one and compress `"ba"`; `b`, `a` differ, so keep `b` and compress `"a"`, which is the base case. The result is `"a" + "b" + "a"` = `"aba"`. Only neighbours are compared, so the two a's at the ends are never seen together. The empty string is returned unchanged.

</Step>

</Steps>

</details>

## 4. Range recursion: lo and hi

A range `lo` to `hi` can shrink from one end (`lo + 1`) or be **split in half**. The second form is the divide-and-conquer shape behind binary search and merge sort.

### Sum of a range of numbers

```java title="SumRange.java"
public class SumRange {
    // Question: return lo + (lo + 1) + ... + hi. An empty range (lo above hi) sums to 0.
    static int sumRange(int lo, int hi) {
        if (lo > hi) {
            return 0;                         // base case: empty range
        }
        return lo + sumRange(lo + 1, hi);
    }

    public static void main(String[] args) {
        System.out.println(sumRange(3, 7));
        System.out.println(sumRange(5, 5));
        System.out.println(sumRange(7, 3));
    }
}
```

```text
25
5
0
```

The base case `lo > hi` is a range with no numbers in it. A range with exactly one number (`lo == hi`) is not special: it adds `lo` and then reaches the empty range.

### Recursive binary search with the calls counted

```java title="BinarySearchRec.java"
public class BinarySearchRec {
    // Question: search a sorted array for key between positions lo and hi, recursively.
    static int calls;

    static int search(int[] a, int key, int lo, int hi) {
        calls++;
        if (lo > hi) {
            return -1;                        // base case 1: empty range, not found
        }
        int mid = (lo + hi) / 2;
        if (a[mid] == key) {
            return mid;                       // base case 2: found
        }
        if (a[mid] < key) {
            return search(a, key, mid + 1, hi);    // the key can only be on the right
        }
        return search(a, key, lo, mid - 1);        // the key can only be on the left
    }

    public static void main(String[] args) {
        int[] a = {8, 18, 23, 29, 34};
        int[] keys = {29, 5, 8, 34};
        for (int key : keys) {
            calls = 0;
            int index = search(a, key, 0, a.length - 1);
            System.out.println("key " + key + ": index " + index + ", calls " + calls);
        }
    }
}
```

```text
key 29: index 3, calls 2
key 5: index -1, calls 3
key 8: index 0, calls 2
key 34: index 4, calls 3
```

Each call throws away half of the range, so the number of calls grows like log of the length. A missing key (5) costs the most calls because the range has to shrink to empty.

### Divide and conquer: the largest element by halves

```java title="MaxHalves.java"
public class MaxHalves {
    // Question: find the largest element by splitting the range in half, and count the calls.
    static int calls;

    static int maxRange(int[] a, int lo, int hi) {
        calls++;
        if (lo == hi) {
            return a[lo];                     // base case: one element
        }
        int mid = (lo + hi) / 2;
        int left = maxRange(a, lo, mid);
        int right = maxRange(a, mid + 1, hi);
        return Math.max(left, right);         // combine the two halves
    }

    public static void main(String[] args) {
        int[] sizes = {1, 2, 4, 8, 16};
        for (int n : sizes) {
            int[] a = new int[n];
            for (int i = 0; i < n; i++) {
                a[i] = (i * 7) % 10;
            }
            calls = 0;
            int largest = maxRange(a, 0, n - 1);
            System.out.println("n " + n + ": largest " + largest + ", calls " + calls);
        }
    }
}
```

```text
n 1: largest 0, calls 1
n 2: largest 7, calls 3
n 4: largest 7, calls 7
n 8: largest 9, calls 15
n 16: largest 9, calls 31
```

Unlike binary search, both halves are searched, so every element is visited: the calls are `2n - 1` (one per element plus the splits above them). The depth of the calls is only about log of `n`, which is why the stack does not overflow for large arrays, even though the total work is linear.

<Callout type="mistake" title="Common error">

Recursing on `mid` instead of `mid + 1` (or `mid - 1`). With `lo = 3`, `hi = 4`, `mid = 3`, a key larger than `a[3]` would call `search(a, key, 3, 4)`, the same range as before. The range never shrinks, so the call repeats until `StackOverflowError`. Both new ranges must exclude `mid`, which has already been checked.

</Callout>

## 5. Accumulators: build the answer on the way down

An **accumulator** is an extra parameter that carries the answer so far. The result is built as the calls go down, so when the base case is reached the answer is already complete and is returned unchanged up the chain.

```text
helper(smaller input, combine(accumulator, this part))     // work done going down
base case: return accumulator                              // nothing is left to do going up
```

### Factorial with an accumulator

```java title="FactAcc.java"
public class FactAcc {
    // Question: write factorial with an accumulator and show the accumulator at each call.
    static long factAcc(int n, long acc) {
        System.out.println("factAcc(" + n + ", " + acc + ")");
        if (n <= 1) {
            return acc;                       // base case: the answer is already built
        }
        return factAcc(n - 1, acc * n);       // multiply on the way down
    }

    public static void main(String[] args) {
        System.out.println("result " + factAcc(5, 1));
    }
}
```

```text
factAcc(5, 1)
factAcc(4, 5)
factAcc(3, 20)
factAcc(2, 60)
factAcc(1, 120)
result 120
```

The accumulator starts at 1, the identity for multiplication, and is multiplied by `n` as the calls go down: 1, 5, 20, 60, 120. When the base case is reached nothing remains to be multiplied. Java does **not** turn this into a loop, so it still uses one stack frame per call; the form is cleaner, not cheaper.

### A string accumulator

```java title="ReverseAcc.java"
public class ReverseAcc {
    // Question: reverse a string with an accumulator instead of combining on the way up.
    static String reverseAcc(String s, String acc) {
        if (s.isEmpty()) {
            return acc;                       // base case: everything has been moved
        }
        return reverseAcc(s.substring(1), s.charAt(0) + acc);   // put the first in front of what is built
    }

    public static void main(String[] args) {
        System.out.println(reverseAcc("Naledi", ""));
        System.out.println(reverseAcc("a", ""));
    }
}
```

```text
idelaN
a
```

Each character is placed in front of the accumulator, so the first character ends up last. Compare with `reverse` earlier in this lesson: there the attaching happened on the way back up; here it happens on the way down.

### Reversing an array in place with two indexes

```java title="ReverseInPlace.java"
import java.util.Arrays;

public class ReverseInPlace {
    // Question: reverse an int array in place, recursively, with a pair of indexes.
    static void reverse(int[] a, int lo, int hi) {
        if (lo >= hi) {
            return;                           // base case: the indexes have met or crossed
        }
        int temp = a[lo];
        a[lo] = a[hi];
        a[hi] = temp;                         // swap the two ends
        reverse(a, lo + 1, hi - 1);           // then the part between them
    }

    public static void main(String[] args) {
        int[][] arrays = {{1, 2, 3, 4, 5}, {1, 2}, {7}, {}};
        for (int[] a : arrays) {
            reverse(a, 0, a.length - 1);
            System.out.println(Arrays.toString(a));
        }
    }
}
```

```text
[5, 4, 3, 2, 1]
[2, 1]
[7]
[]
```

Nothing is returned: the work is the swap, and the array itself changes (the callee changes the caller's array, because only the reference is copied). The base case is `lo >= hi`, which covers the empty array (`hi` is -1), one element (`lo == hi`) and the middle of an odd-length array.

<Callout type="mistake" title="Common error">

Starting the accumulator at the wrong value, or returning something other than the accumulator in the base case. `factAcc(5, 0)` multiplies 0 by every `n` and returns 0. The starting value is the identity of the combination (1 for a product, 0 for a sum, `""` for a string), and the base case returns the accumulator, not a constant.

</Callout>

### Exam question 4: rewrite with an accumulator (4 marks)

The method `int sum(int[] a, int i)` returns `a[i] + sum(a, i + 1)` and 0 when `i == a.length`. Rewrite it with an accumulator, `int sumAcc(int[] a, int i, int acc)`, and state what is left to do on the way back up in each version. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command words are "rewrite" and "state". The given method adds on the way **up**: each call waits for the sum of the rest and then adds its own element. The new one must carry the sum so far as a third parameter.

</Step>

<Step title="2. Plan">

Move the addition into the argument: instead of adding `a[i]` to the result, pass `acc + a[i]` down. The base case then returns `acc`. The first call starts with an accumulator of 0, the identity for a sum.

</Step>

<Step title="3. Solution">

```java title="SumAcc.java"
public class SumAcc {
    // Question: rewrite the array sum with an accumulator.
    static int sum(int[] a, int i) {
        if (i == a.length) {
            return 0;
        }
        return a[i] + sum(a, i + 1);
    }

    static int sumAcc(int[] a, int i, int acc) {
        if (i == a.length) {
            return acc;                       // the sum was built on the way down
        }
        return sumAcc(a, i + 1, acc + a[i]);
    }

    public static void main(String[] args) {
        int[] a = {4, 8, 15, 16};
        System.out.println(sum(a, 0));
        System.out.println(sumAcc(a, 0, 0));
        System.out.println(sumAcc(new int[] {}, 0, 0));
    }
}
```

```text
43
43
0
```

</Step>

<Step title="4. Check">

Both give 43. In `sum`, every call still has an addition waiting after its recursive call returns, so the work is done on the way **up**. In `sumAcc`, the recursive call is the last thing each call does and there is nothing left to do on the way up; the base case already holds the finished answer. For the empty array, `sumAcc` returns the starting accumulator, 0.

</Step>

</Steps>

</details>

## Summary

<Callout type="key" title="Remember">

For an array, a string or a range, a public method calls a helper that carries the position. Use `i == a.length` as the base case when the method has an identity value for the empty input, and `a.length - 1` only when it has none (a maximum). A count `n` is not an index: the last element is `a[n - 1]`. A string shrinks with `substring(1)` or `substring(1, length - 1)`, and a `char` plus a `char` is a number, so start with a `String`. A range recursion must exclude `mid` when it recurses. Halving a range gives about log of `n` levels. An accumulator carries the answer down, starts at the identity value, and is returned by the base case.

</Callout>

`a[n - 1]`. `n` is a count of elements, so the last of them is at index `n - 1`; `a[n]` would be past the end for `n == a.length`.

The first `+` adds two chars as numbers (97 + 97 = 194); only then is the number joined to the string, so the text begins with `194`, not `aa`. Start with `""` to force concatenation.

<CheckQuestion question="A recursive binary search calls itself with (lo, mid) instead of (mid + 1, hi) when the key is larger. What happens for lo = 3, hi = 4?">

`mid` is 3 and the call is `search(a, key, 3, 4)` again with the same range, so the range never shrinks and the recursion ends in a `StackOverflowError`. The new range must exclude `mid`.

Nothing. The recursive call is the last step of each call and the base case already holds the finished answer, which passes back up unchanged. Java still keeps one stack frame per call.
