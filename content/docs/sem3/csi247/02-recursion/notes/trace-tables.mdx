## Tracing a loop

<Steps>

<Step title="Make a column for every variable">

that changes, one for the loop condition, and one for any output.

</Step>

<Step title="Write the starting values">

in the first row.

</Step>

<Step title="Go through the code exactly as Java would">

Each time a variable changes, write its new value in a new row (or in the same row, if your table has one row per loop pass). Never skip a step because "it's obvious".

</Step>

<Step title="Stop when the condition is false">

, and write that final false check too: it's the reason the loop ended.

</Step>

</Steps>

Here is the method from the revision notes, traced for `addNums(4)`:

```java title="AddNums.java"
public static int addNums(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum += i;                // sum = sum + i
    }
    return sum;
}
```

<TraceTable>

| Step | `i` | `i <= 4`? | `sum` afterwards |
| --- | --- | --- | --- |
| start | — | — | 0 |
| pass 1 | 1 | true | 0 + 1 = 1 |
| pass 2 | 2 | true | 1 + 2 = 3 |
| pass 3 | 3 | true | 3 + 3 = 6 |
| pass 4 | 4 | true | 6 + 4 = 10 |
| end | 5 | false | loop stops → return **10** |

</TraceTable>

**What does the method do?** (A typical part (a) question.) Looking at the table, it returns 1 + 2 + … + *n*: the sum of the whole numbers from 1 to *n*.

## Tracing a recursive method

A recursive method calls itself (see [Recursion](/docs/sem3/csi247/02-recursion/notes/recursion-in-java)). Each call waits for the one it started, so a recursive trace has two directions: the calls go *down* until the base case, then the answers come back *up*. The format from the revision notes captures exactly that with five columns:

<table><tr><th>Column</th><th>What to write</th><th>Fill in…</th></tr><tr><td><code>n</code></td><td>the parameter's value in this call</td><td rowSpan={4}>top to bottom (calls going down)</td></tr><tr><td>Method call</td><td>the call itself, e.g. <code>Myst(5)</code></td></tr><tr><td>Base case? (e.g. <code>n == 1</code>?)</td><td>true or false</td></tr><tr><td>Returned</td><td>the <code>return</code> expression <em>with the recursive call still unsolved</em>, e.g. <code>5 + Myst(4)</code></td></tr><tr><td>Result</td><td>the actual number that call returns</td><td><strong>bottom to top</strong> (answers coming back)</td></tr></table>

### Worked example: `Myst(6)`

```java title="Myst.java"
public static int Myst(int n) {
    if (n == 1) return 1;          // base case
    return n + Myst(n - 1);        // recursive case: n plus the answer for one less
}
```

**Pass 1, top to bottom.** Start with `n` = 6. It isn't 1, so the method returns `6 + Myst(5)`, but it can't finish yet: it must wait for `Myst(5)`. Write that and move to the next row. Keep going until `n == 1` is true; that row returns a plain number.

**Pass 2, bottom to top.** Now fill the Result column starting from the last row. `Myst(1)` = 1. The row above needed `2 + Myst(1)` = 2 + 1 = 3. The row above that needed `3 + Myst(2)` = 3 + 3 = 6. And so on up to the top.

<TraceTable>

| `n` | Method call | `n == 1`? | Returned | Result ↑ |
| --- | --- | --- | --- | --- |
| 6 | `Myst(6)` | false | `6 + Myst(5)` | 6 + 15 = **21** |
| 5 | `Myst(5)` | false | `5 + Myst(4)` | 5 + 10 = 15 |
| 4 | `Myst(4)` | false | `4 + Myst(3)` | 4 + 6 = 10 |
| 3 | `Myst(3)` | false | `3 + Myst(2)` | 3 + 3 = 6 |
| 2 | `Myst(2)` | false | `2 + Myst(1)` | 2 + 1 = 3 |
| 1 | `Myst(1)` | true | `1` | 1 |

</TraceTable>

So `Myst(6)` returns **21** (= 6 + 5 + 4 + 3 + 2 + 1). The Result column is only filled in at the end, from the bottom up, because no call can finish until the call below it has.

<Callout type="mistake" title="Check your notes">

The handwritten trace in the revision notes has an arithmetic slip: it shows `5 + 10 = 25` and therefore `6 + 25 = 27`. The correct values are `5 + 10 = 15` and `6 + 15 = 21` (Java prints 21). A quick check that catches this kind of mistake: `Myst(n)` is 1 + 2 + … + *n*, which equals *n*(*n*+1)/2 = 6 × 7 / 2 = 21.

</Callout>

### Example 2: two parameters

```java title="Mystery.java"
public static int mystery(int a, int b) {
    if (b == 0) return 0;               // base case
    return a + mystery(a, b - 1);       // b shrinks by 1 each call; a never changes
}
```

<TraceTable>

| `a` | `b` | Method call | `b == 0`? | Returned | Result ↑ |
| --- | --- | --- | --- | --- | --- |
| 3 | 4 | `mystery(3, 4)` | false | `3 + mystery(3, 3)` | 3 + 9 = **12** |
| 3 | 3 | `mystery(3, 3)` | false | `3 + mystery(3, 2)` | 3 + 6 = 9 |
| 3 | 2 | `mystery(3, 2)` | false | `3 + mystery(3, 1)` | 3 + 3 = 6 |
| 3 | 1 | `mystery(3, 1)` | false | `3 + mystery(3, 0)` | 3 + 0 = 3 |
| 3 | 0 | `mystery(3, 0)` | true | `0` | 0 |

</TraceTable>

It adds `a` to itself `b` times, so `mystery(a, b)` computes **`a × b`** using only addition.

### Example 3: printing on the way down and on the way up

When a recursive method prints something, ask: does the print happen *before* the recursive call (on the way down) or *after* it (on the way back up)?

```java title="Echo.java"
public static void echo(int n) {
    if (n == 0) return;                 // base case: do nothing
    System.out.print(n + " ");          // BEFORE the call → happens going down
    echo(n - 1);
    System.out.print(n + " ");          // AFTER the call  → happens coming back up
}
// echo(3) prints:  3 2 1 1 2 3
```

<TraceTable>

| Order | Which call is running | What it does | Output so far |
| --- | --- | --- | --- |
| 1 | `echo(3)` | prints 3, then calls `echo(2)` and waits | `3` |
| 2 | `echo(2)` | prints 2, calls `echo(1)`, waits | `3 2` |
| 3 | `echo(1)` | prints 1, calls `echo(0)`, waits | `3 2 1` |
| 4 | `echo(0)` | base case: returns immediately | `3 2 1` |
| 5 | `echo(1)` resumes | prints 1, returns | `3 2 1 1` |
| 6 | `echo(2)` resumes | prints 2, returns | `3 2 1 1 2` |
| 7 | `echo(3)` resumes | prints 3, returns | `3 2 1 1 2 3` |

</TraceTable>

## Converting a loop into recursion

"Provide a recursive version of the method" is a classic exam question. Work through it in three steps, writing them down (examiners give marks for each):

<Steps>

<Step title="Find the base case">

the smallest input you can answer immediately. For `addNums`, the sum from 1 to 1 is just 1, so: `n == 1` → return 1.

</Step>

<Step title="Find the recursive case">

express the answer using the answer for a smaller input. The sum 1 + … + *n* equals *n* + (1 + … + (*n* − 1)), so: return `n + addNums(n - 1)`.

</Step>

<Step title="Write the method">

: base case first, then the recursive case.

</Step>

</Steps>

```java title="AddNumsRecursive.java"
// base case:      n == 1  → return 1
// recursive case: return n + addNums(n - 1)
public static int addNums(int n) {
    if (n == 1) {
        return 1;
    }
    return n + addNums(n - 1);
}
```

Notice this is exactly `Myst` from above: you've already traced it. More conversions:

| Task | Base case | Recursive case |
| --- | --- | --- |
| factorial *n*! | `n <= 1` → 1 | `n * factorial(n - 1)` |
| power *b*<sup>e</sup> | `e == 0` → 1 | `b * power(b, e - 1)` |
| sum of an array from index `i` | `i == a.length` → 0 | `a[i] + sum(a, i + 1)` |
| count down from *n* | `n == 0` → stop | print `n`, then `countDown(n - 1)` |
| linear search from index `i` | `i == a.length` → −1; `a[i] == key` → `i` | `search(a, key, i + 1)` |

Recursive versions of linear and binary search, with traces, are on the [searching exam drill](/docs/sem3/csi247/04-sorting-and-searching/notes/searching-exam-drill) page.

<Callout type="mistake">

Forgetting to `return` the recursive call's result. Writing `n + addNums(n - 1);` without `return` doesn't compile in a method that returns `int`, and writing `addNums(n - 1); return n;` throws the smaller answer away.

</Callout>

<Callout type="key">

Loops: one column per variable, one row per pass, include the final false check. Recursion: columns *n* | call | base case? | returned | result. Fill the first four going down, then the Result column going up from the base case.

</Callout>
