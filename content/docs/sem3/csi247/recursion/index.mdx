Recursion is not “a method magically calling itself.” It is a sequence of **separate method calls**, each with its own parameters and local variables, waiting on the call stack.

## 1. The smallest complete model

Every correct recursive method needs:

1. a **base case** that answers a small problem directly;
2. a **recursive case** that moves toward the base case;
3. a way to combine the smaller answer into the current answer.

~~~java
public static int sumTo(int n) {
    if (n <= 0) {           // Base case: stop making calls.
        return 0;
    }

    return n + sumTo(n - 1); // Smaller input: n moves toward 0.
}
~~~

### Returns unwind upward

| Returning frame | Expression can now finish | Returns |
|---|---|---:|
| <code>sumTo(0)</code> | base answer | 0 |
| <code>sumTo(1)</code> | <code>1 + 0</code> | 1 |
| <code>sumTo(2)</code> | <code>2 + 1</code> | 3 |
| <code>sumTo(3)</code> | <code>3 + 3</code> | 6 |

The answer is built during **unwinding**, not while calls are still descending.

## 3. Recursive array search

~~~java
public static int find(int[] data, int target, int index) {
    if (index == data.length) { // No cells remain.
        return -1;
    }
    if (data[index] == target) { // Current cell matches.
        return index;
    }
    return find(data, target, index + 1); // Search the suffix.
}
~~~

| Call | condition checked | decision |
|---|---|---|
| <code>find([8,3,6], 6, 0)</code> | <code>8 == 6</code> false | recurse with 1 |
| <code>find(..., 1)</code> | <code>3 == 6</code> false | recurse with 2 |
| <code>find(..., 2)</code> | <code>6 == 6</code> true | return 2 |

## 4. Recursive versus iterative

~~~java
public static int iterativeSumTo(int n) {
    int total = 0;
    for (int value = 1; value <= n; value++) {
        total += value;
    }
    return total;
}
~~~

| Question | Recursive | Iterative |
|---|---|---|
| Where is unfinished work stored? | call-stack frames | explicit loop variables |
| Extra space for sumTo(N) | O(N) | O(1) |
| Time | O(N) | O(N) |
| Natural fit | recursive structures/divide-and-conquer | straightforward repetition |

Java does not guarantee tail-call optimisation. A tail-recursive Java method may still consume one frame per call.

## 5. How to design one

1. State what the method returns for one input.
2. Write the smallest valid input and answer it directly.
3. Express the current answer using a strictly smaller input.
4. Prove the smaller input reaches the base case.
5. Trace calls downward and returns upward separately.

<CommonMistake title="A base case that is never reached">
If <code>n</code> starts positive but the recursive call uses <code>n + 1</code>, the method moves away from <code>n == 0</code> and eventually throws <code>StackOverflowError</code>.
</CommonMistake>
