## Trace a class through the toolchain

Without looking at the cheat sheet, start from `package school.people; public class Student` and produce:

1. Its fully qualified name.
2. Its conventional source path below `src`.
3. Its compiled path below `classes` when using `javac -d classes`.
4. The import required in `school.app.Main`.
5. A compile command from the project root.
6. A run command for `school.app.Main`.

<details>
<summary>Compare your answers</summary>

`school.people.Student`; `src/school/people/Student.java`; `classes/school/people/Student.class`; `import school.people.Student;`; `javac -d classes -sourcepath src src/school/app/Main.java`; `java -cp classes school.app.Main`.

The compiler command assumes Main uses Student and both sources follow the declared tree. The run command names Main, not Student. Imports and paths do not replace public constructor/member access where it is required.

</details>

## Explain the distinctions in your own words

| Pair | Evidence of a complete explanation |
|---|---|
| Package versus folder | Declaration gives identity; directories support lookup conventions |
| Import versus classpath | Source-name convenience versus locating compiled definitions |
| `-sourcepath` versus `-d` | Where to find source dependencies versus where to put output |
| Compile versus run | `.java` to `.class` versus invoking a class's entry point |
| Type access versus member access | A found, public class may still have an inaccessible constructor |
| Package versus subpackage | Similar prefix does not imply shared package-private access |

## Ten-minute troubleshooting round

For each error, write **failing layer → evidence → repair**.

- `cannot find symbol: class Scanner` in a source using the simple name.
- `package school.people does not exist` while Student's source sits outside the supplied source root.
- `Student() is not public` when another package calls its constructor.
- `Could not find or load main class Main` for a declared `school.app.Main`.
- `Main method not found` after the correct class has been found.

<details>
<summary>Diagnostic answers</summary>

1. Name resolution: add `import java.util.Scanner;` or use the fully qualified name.
2. Dependency lookup: correct the source tree/sourcepath, explicitly supply the source, or supply valid compiled bytecode on the compile classpath.
3. Access: the class was found; make the constructor public if it is intended for callers in another package.
4. Runtime identity: use `java -cp classes school.app.Main` from the project root.
5. Entry-point signature: provide `public static void main(String[] args)` in the intended target.

</details>

## Readiness checklist

You are ready when you can reconstruct paths without guessing, explain why an import cannot fix access, compile from a stated working directory, and distinguish a missing class from a missing main method. If any step needs a hint, retry [Questions 3, 5 and 8](/docs/sem3/csi247/packages/questions) with a different package name.
