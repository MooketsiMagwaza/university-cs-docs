Package code is easiest to understand when source files and compiled files are separated:

```text
project/
  src/       <- .java source tree
  classes/   <- compiler output and package folders
```

Run every command in this lesson from `project`, the parent directory of both folders.

<PackageBuildStory />

## 1. Compile the complete example

With `A.java`, `B.java`, and `Tester.java` from the previous lesson:

```text
javac -d classes -sourcepath src src/pkg/A.java src/pkg/B.java src/app/Tester.java
```

| Part | Meaning |
|---|---|
| `javac` | Run the Java compiler |
| `-d classes` | Put generated `.class` files under the `classes` root |
| `-sourcepath src` | Look under `src` for package-structured source dependencies |
| final arguments | Source files to compile |

The output mirrors the declared packages:

```text
classes/
  pkg/
    A.class
    B.class
  app/
    Tester.class
```

`-d` does not invent the package name. The `package` declaration determines the subdirectory; `-d` chooses its root.

## 2. Run the main class

```text
java -cp classes app.Tester
```

```text
42
class B
```

`-cp classes` makes `classes` the **classpath root**. `app.Tester` is the fully qualified class name. Do not add `.class`, use a slash, or run `java Tester` from inside `classes/app`.

The classpath root is the directory **above** the package folder. Java combines `classes` with `app.Tester`, translates the dot to a folder separator, and loads `classes/app/Tester.class`. Dependencies such as `pkg.A` are resolved from the same root.

## 3. Compile one entry point and its dependencies

Because `Tester.java` imports `pkg.A` and `pkg.B`, `javac` can locate their source through `-sourcepath`:

```text
javac -d classes -sourcepath src src/app/Tester.java
```

This compiles required source dependencies when they are found in the expected package paths. Listing all three files is more explicit for a first exercise; compiling the entry point demonstrates why correct structure matters.

## 5. A deliberate classpath failure

If the compiled file is `classes/app/Tester.class`, this command is wrong:

```text
java -cp classes/app Tester
```

It treats `classes/app` as the root and asks for a class in the unnamed package. But the bytecode says its name is `app.Tester`.

Correct:

```text
java -cp classes app.Tester
```

<CommonMistake title="Running from the package directory">
The filesystem location and the class's binary name are related but not interchangeable. Run from a classpath root and name the class with dots, including its package.
</CommonMistake>

## 6. Platform notes

- `/` works in the shown source paths on common shells and Java tooling; Windows also accepts its usual path conventions.
- A classpath with several entries uses `;` on Windows and `:` on Linux/macOS.
- `-cp` and `-classpath` are equivalent spellings.
- Package names are case-sensitive even if a local filesystem sometimes hides the mistake.
