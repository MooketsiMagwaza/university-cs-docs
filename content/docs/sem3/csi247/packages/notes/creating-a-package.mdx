A user-defined package applies the same naming system to your own classes. Three structures must agree:

1. the `package` declaration;
2. the source folder path;
3. the compiled class folder path.

<PackageFolderStory />

## 1. Package names and folders

Package names are normally lowercase. Larger projects use a reversed Internet domain followed by project areas, such as `bw.ac.ub.csi247.sorting`. The lecture's smaller `pkg` example is suitable for learning the mechanics.

```text
project/
  src/
    pkg/
      A.java
      B.java
    app/
      Tester.java
  classes/
```

The first non-comment statement in `A.java` and `B.java` is `package pkg;`. `Tester.java` declares `package app;` because its folder is `src/app`.

## 2. Two classes in package pkg

`src/pkg/A.java`:

```java
package pkg;

public class A {
    private final int value;

    public A(int value) {
        this.value = value;
    }

    public int doubled() {
        return value * 2;
    }
}
```

`src/pkg/B.java`:

```java
package pkg;

public class B {
    public String label() {
        return "class B";
    }
}
```

The public class name and filename match exactly, including case. A public constructor and public method are accessible from `app.Tester`; the private field stays inside `A`.

## 3. A class in another package

`src/app/Tester.java`:

```java
package app;

import pkg.A;
import pkg.B;

public class Tester {
    public static void main(String[] args) {
        A first = new A(21);
        B second = new B();

        System.out.println(first.doubled());
        System.out.println(second.label());
    }
}
```

```text
42
class B
```

The imports are written after the package declaration and before the class declaration.

## 4. What packages protect

Java has four access levels:

| Modifier | Same class | Same package | Subclass elsewhere | Unrelated class elsewhere |
|---|:---:|:---:|:---:|:---:|
| `private` | yes | no | no | no |
| no modifier (package-private) | yes | yes | no | no |
| `protected` | yes | yes | yes, through inheritance | no |
| `public` | yes | yes | yes | yes |

If `A.doubled()` had no modifier, `app.Tester` could not call it because `app` and `pkg` are different packages.

<CommonMistake title="Calling package-private 'default' access public">
No modifier does not mean Java inserts `public`. It means package-private access: the member is visible only to classes in the same package.
</CommonMistake>

## 5. One package may span source files

A package is a namespace, not one source file and not one object. Any number of source files may declare `package pkg;`, provided the project and compiler can find them under the matching package path.

A source file may declare at most one package. A compilation unit can contain several top-level classes, but at most one public top-level class, and its name determines the filename. Keeping one top-level class per file is the clearest course convention.

## 6. Common errors

| Attempt | What happens | Repair |
|---|---|---|
| Save `A.java` outside the folder matching `pkg` | Tooling or compilation cannot resolve the expected path | Put it under `src/pkg` |
| Write `package Pkg;` but folder is `pkg` | Case-sensitive package mismatch on many systems | Use identical lowercase spelling |
| Put `import` before `package` | Syntax error | Package first, then imports |
| Name file `ClassA.java` for `public class A` | Compiler requires the public type in `A.java` | Match filename and class name |
| Access a package-private member from `app` | Access error | Make the API public or keep the collaborator in the same package |
