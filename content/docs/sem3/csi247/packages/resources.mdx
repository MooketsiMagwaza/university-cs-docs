## Use the reference that answers your actual problem

| Question | Reference | What to look for |
|---|---|---|
| What does an import make available? | JLS chapter 7 above | Single-type, type-on-demand and static imports |
| Why is the method inaccessible? | JLS access control above | Exact package boundaries and protected receiver restrictions |
| Where does the compiler find a dependency? | `javac` reference above | `--source-path` / `-sourcepath` and `--class-path` / `-cp` |
| Where are compiled classes written? | `javac` reference above | `-d` output root and generated package directories |
| What does the launcher need? | `java` reference above | Classpath root and fully qualified main class |

The lesson examples remain compatible with Java 8. The linked Java 21 references also discuss newer features; named modules and source-file launch mode are not required for these classpath exercises.

## A focused study route

1. Read [Built-in packages and imports](/docs/sem3/csi247/packages/notes/built-in-packages-and-imports), then explain what an import does **not** do.
2. Follow [Creating a package](/docs/sem3/csi247/packages/notes/creating-a-package), drawing the tree by hand.
3. Use [Compiling and running](/docs/sem3/csi247/packages/notes/compiling-and-running) to connect source identity to bytecode lookup.
4. Attempt the [practice questions](/docs/sem3/csi247/packages/questions), then classify your mistakes with the [chapter review](/docs/sem3/csi247/packages/review).
5. Use the [cheat sheet](/docs/sem3/csi247/packages/cheat-sheet) for final recall, not as a substitute for tracing a path.

## Build a reproducible debugging example

When asking for help, include the source tree, package declarations, exact commands, current working directory, and complete error text. Keep compile and run output separate. This makes it possible to identify whether the problem is lookup, identity, access or entry-point selection.

The full chapter downloads work offline. HTML retains controls and feedback; PDF expands the walkthrough and answers for annotation. Do not run commands from a diagram without first checking its assumed project root.
