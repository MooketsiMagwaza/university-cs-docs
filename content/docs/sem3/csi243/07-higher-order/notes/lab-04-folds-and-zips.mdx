## 1. October Lab 4 Q1: sumsq without map

The Lab 4 restriction is to use `foldr` without `map`. Rather than building a list of squares first, square the current element inside the combining function. The seed is the answer for no elements, not the first element of the range.

**Template to adapt**

```text
total [] = seed
total (x:xs) = combine x (total xs)
-- Therefore: total xs = foldr combine seed xs
```

First imagine a square-total function on a list: its empty answer is 0 and its non-empty equation is `total (x:xs) = x*x + total xs`. Replace the recursive result by `acc` to obtain a two-argument step, then supply `[1..n]`.

## 5. October Lab 4 Q3a: implement the three-list traversal

A three-list zipper emits one answer only when all three heads exist. Derive its type from that sentence: one element from each list may have a different type, and the rule returns a fourth type.

**Template to adapt**

```text
zipWithx :: (a -> b -> c -> d) -> [a] -> [b] -> [c] -> [d]
zipWithx _ [] _ _ = []
zipWithx _ _ [] _ = []
zipWithx _ _ _ [] = []
zipWithx f (x:xs) (y:ys) (z:zs) = f x y z : zipWithx f xs ys zs
```

For one output, require `(x:xs)`, `(y:ys)` and `(z:zs)`. If any of these heads is absent, return `[]`. Otherwise prepend `f x y z` to the recursive call on all three tails.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command write requests the recursive implementation. The most general signature must allow three independent input element types and a separate output type. A library alias would omit the requested work.

</Step>

<Step title="2. Plan">

For one output, require `(x:xs)`, `(y:ys)` and `(z:zs)`. If any of these heads is absent, return `[]`. Otherwise prepend `f x y z` to the recursive call on all three tails.

</Step>

<Step title="3. Solution">

```haskell
zipWithx :: (a -> b -> c -> d) -> [a] -> [b] -> [c] -> [d]
zipWithx _ [] _ _ = []
zipWithx _ _ [] _ = []
zipWithx _ _ _ [] = []
zipWithx f (x:xs) (y:ys) (z:zs) = f x y z : zipWithx f xs ys zs
```

The rule type is `a -> b -> c -> d`. Each recursive step emits one d and removes one cell from every input. The three wildcard base equations cover all seven empty-list combinations.

### Common errors and repairs

A program with no `main` can hold useful definitions, but it is not the requested executable test program. A wrongly indented statement after `main = do` can give GHC's key phrase `parse error`; align statements inside the do block. Use a separate line and indentation for each printed test.

A test suite containing only equal-length lists misses the faulty zipper above. A suite comparing a named function with a lambda copied from the same wrong formula can also pass. Add independently calculated results, all seven empty cases, each shortest input and the school-domain validator.

Keep these failure categories distinct: a malformed lambda missing `->` has a syntax error, an operator not parenthesised as an argument may be parsed as unintended infix use, a two-argument rule used as a three-argument rule has a type error, a missing pattern can fail only when demanded, and a wrong weight denominator can compile and run while giving the wrong answer.
