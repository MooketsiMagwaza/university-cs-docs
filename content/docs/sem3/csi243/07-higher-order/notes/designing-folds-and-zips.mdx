## 1. Derive a square total from recursive equations

The Lab 4 restriction is to use `foldr` without `map`. Rather than building a list of squares first, square the current element inside the combining function. The seed is the answer for no elements, not the first element of the range.

**Template**

```text
total [] = seed
total (x:xs) = combine x (total xs)
-- Therefore: total xs = foldr combine seed xs
```

Here `total xs` is the result for the tail; replace that whole recursive call by `acc`. For squares, `total [] = 0` and `total (x:xs) = x*x + total xs`, so `combine x acc = x*x + acc`. Generate `[1..n]` only after deriving the list operation. Our range policy is explicit: `n <= 0` denotes an empty range and returns zero. This is a range sum, not a claim about factorials or negative squares.

### Worked variation: Positive range

Start with a normal case.

<HaskellTryIt>

```haskell
-- Question: sumsq; predict the result of the main call and justify the design.
sumsq :: Int -> Int
sumsq n = foldr (\x acc -> x*x + acc) 0 [1..n]

main :: IO ()
main = print (sumsq 4)
```

```text
30
```

</HaskellTryIt>

The range is `[1,2,3,4]`. Replace the tail by zero: `1 + (4 + (9 + (16 + 0))) = 30`.

## 2. Choose the multiplicative seed: productTo

A product needs one as its empty result: inserting zero would destroy every non-empty answer. Appendix C.1 asks for the product of the inclusive range from one to n.

**Template**

```text
productOf [] = 1
productOf (x:xs) = x * productOf xs
-- Replace the recursive result by acc: combine x acc = x * acc
```

Thus the operator is `(*)`, the seed is `1`, and the range is `[1..n]`. We define `productTo n` as an empty-range product for non-positive n, returning 1. If a specification calls it factorial, restrict its domain to non-negative integers or reject negative input separately; returning 1 does not make a negative factorial valid.

### Worked variation: Several factors

Start with a normal case.

```haskell
main :: IO ()

```

```text
120
```

</HaskellTryIt>

The expansion is `1*(2*(3*(4*(5*1))))`. Each factor occurs once.

## 3. Change the result type: myLength

Counting cells does not inspect their contents. An element may be a Boolean, a string or another list while the accumulated result is an `Int`. The fold's element type and result type need not be equal.

**Template**

```text
size [] = 0
size (x:xs) = 1 + size xs
-- step ignores x and adds one to the tail count
```

Use `_` for the unused element and `acc` for the tail count. In `foldr :: (a -> b -> b) -> b -> [a] -> b`, choose `b = Int` while `a` remains arbitrary. Neither equality nor numeric operations on the elements are needed.

## 4. Derive a conditional count

A conditional count contributes one for a matching element and zero otherwise. The accumulator already counts matches in the tail; failing the predicate must preserve that count.

**Template**

```text
count p [] = 0
count p (x:xs) = if p x then 1 + count p xs else count p xs
```

Replace both occurrences of `count p xs` by the same `acc`. This gives `\x acc -> if p x then 1 + acc else acc`. Appendix C.3 specialises the predicate to `even`; thresholds, negative numbers and characters use the same design.

### Worked variation: Mixed even and odd

Start with a normal case.

<HaskellTryIt>

```haskell
-- Question: conditional count; predict the result of the main call and justify the design.
countBy :: (a -> Bool) -> [a] -> Int
countBy p = foldr (\x acc -> if p x then 1 + acc else acc) 0

countEvens :: [Int] -> Int
countEvens = countBy even

main :: IO ()
main = print (countEvens [1,2,4,7])
```

```text
2
```

</HaskellTryIt>

Only 2 and 4 contribute one; 1 and 7 preserve the suffix count.

## 5. Adapt the contribution: cube and weighted totals

Changing a square total into a cube total changes only what each element contributes. The additive seed and tail-result role stay the same. This is the Appendix C.4 adaptation.

**Template**

```text
totalContribution contribution = foldr (\x acc -> contribution x + acc) 0
```

The placeholder `contribution` computes one term; `acc` totals all later terms. A cube uses `x*x*x`; a weighted square uses `weight*x*x`. A range-based cube total uses `[1..n]`, with the same non-positive empty-range policy as `sumsq`.

### Worked variation: Positive cube range

```haskell
main :: IO ()
main = print (sumCubes 3)
```

```text
36
```

</HaskellTryIt>

The terms are 1, 8 and 27; nesting gives `1+(8+(27+0))`.

## 6. Derive a list-valued fold: mapping

A fold can return a list. Mapping transforms the head and puts it before the already-transformed tail. This derives the definition rather than memorising a one-line rewrite from Folds and Function Composition.

**Template**

```text
mapped f [] = []
mapped f (x:xs) = f x : mapped f xs
```

The empty output is `[]`. The step is `\x acc -> f x : acc`; `acc` already has type `[b]`, so the step has type `a -> [b] -> [b]`. Use `(:)` to add one output element and preserve input order.

### Worked variation: Numeric transformation

Start with a normal case.

<HaskellTryIt>

```haskell

mapFold f = foldr (\x acc -> f x : acc) []

main :: IO ()
main = print (mapFold (\x -> x*x) [2,-3])
```

```text
[4,9]
```

</HaskellTryIt>

Square 2 and -3, then cons 4 before 9. The order is preserved.

### Common errors and repairs

`myZipWith f xs ys = f xs ys` applies the rule to entire lists rather than heads and does not implement the given type in general. GHC reports `Couldn't match` with the signature. Forgetting a stopping equation instead compiles with a possible `non-exhaustive` warning and can fail when lengths differ.

## 17. A design and diagnostic checklist

| Specification clue | Design decision | First check |
|---|---|---|
| Add transformed contributions | Fold with seed zero and transform inside the step | Empty input and one element |
| Multiply contributions | Fold with seed one | An empty list and a list containing zero |
| Count matches | Add one conditionally, otherwise keep the count | No matches and a boundary match |
| Keep or transform elements | List-valued fold with seed `[]` | Order and duplicates |
| Match two or three lists | Zipper with one stopping equation per list | Each list shortest in turn |
| Return a weighted mean | Sum the weights in the denominator; convert before division | All marks equal and a fractional result |
| Require equal dimensions | Validate lengths before truncating | A deliberately unequal input |

A right fold groups combinations to the right; it does not imply that execution always begins at the last element. Use the lazy-evaluation lesson for demand, and Applying Higher-Order Functions by Hand for a full trace. Left and right folds are not interchangeable merely because the result type agrees. Even for an associative operation, a seed on opposite ends needs care: with append and seed `["z"]`, left and right placement can change the list. With append and its identity `[]`, both groupings agree on finite defined lists. Floating-point addition is not exactly associative.

For a left-fold adaptation of a numeric contribution total, use `\acc x -> acc + contribution x`: the accumulator is the first parameter. Scans, seedless folds and their tracing rules belong to the prerequisite lessons; a seedless fold does not solve an empty-input requirement.

### Distinguish four kinds of failure

The deliberately rejected and crashing examples below are plain fences. They are not browser exercises.

**Wrong rule arity.** Under the declared type, `f x y` has type `c`, so it cannot in general be applied to `z`. GHC's key phrase is `Couldn't match`.

```haskell
-- Incorrect: two-argument rule type but three applications.
badArity :: (a -> b -> c) -> [a] -> [b] -> [c] -> [c]
badArity f (x:xs) (y:ys) (z:zs) = f x y z : []
```

Repair the rule type to `a -> b -> c -> d`, the result to `[d]`, and supply the full recursive equations from section 11.

**Wrong operator argument.** Parenthesise an operator to pass it as a function. The following expression can parse as infix multiplication with `zipWith` on the left; it is not the intended application. Its list application is ill typed, giving GHC's key phrase `Couldn't match`. Do not assume every unparenthesised operator produces a parse error.

```haskell
-- Incorrect: pass (*) rather than a bare *.
badProducts = zipWith * [1,2] [3,4]
```

With `zipWith (*)` the operator is a two-argument function. With `zipWithx (+)` the syntax is valid but its arity is wrong for Int lists. A malformed lambda missing `->` is instead a syntax error, with the key phrase `parse error`. Syntax and type failures require different repairs.

**Incomplete patterns and partial output.** This version handles only the all-empty combination.

```haskell
-- Incorrect: this main deliberately reaches an uncovered pattern.
badZip :: (a -> b -> c -> d) -> [a] -> [b] -> [c] -> [d]
badZip _ [] [] [] = []
badZip f (x:xs) (y:ys) (z:zs) =
  f x y z : badZip f xs ys zs

main :: IO ()
main = print (badZip (\x y z -> x+y+z) [1,2] [10] [100,200])
```

The first cons cell exists and contains 111. The remaining call is `badZip f [2] [] [200]`, which matches neither equation. As printing demands the tail, evaluation raises `Non-exhaustive patterns`. A prefix of the printed list can already have been produced before failure; there is no complete printed list value, so do not report `[111]` as the result. Exact interleaving of buffered stdout and the exception on stderr is not a deterministic transcript. Repair all three stopping cases, and re-test each list shortest.

**Wrong answer with no GHC diagnostic.** A zero product seed, division by the wrong weight sum, or replacing the false branch of a filter step by `[]` can type-check. Test a counterexample tied to the specification; successful compilation does not establish correctness.

## Summary

<Callout type="key" title="Remember">

Read the empty case to choose the seed. Replace the recursive tail result by an accumulator to derive the step. A list-valued fold uses `[]`, while sums use zero and products use one. Weighted Int inputs need conversion before fractional division. A zipper needs a stopping case for each required input list, and its rule's arity must match the number of heads. State truncation, negative-range and validation policies explicitly.

</Callout>
