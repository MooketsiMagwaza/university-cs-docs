A higher-order function receives or returns a function. To evaluate its call on paper, keep that function as an argument until the defining equation tells you where to apply it. This lesson makes each replacement visible: a final value alone is not a trace.

## 1. The tracing template

First identify the function, its arguments and the result type. A **substitution** replaces a parameter by the argument supplied for it. Match the input to a defining equation, replace only that call, then evaluate one smaller application or one primitive operation. Preserve everything around the chosen call. For an if-expression, calculate the test before selecting its branch.

```text
original call -- given call
= defining body with arguments inserted -- named equation; list substitutions
= one application with its body inserted -- lambda substitution or function equation
= one smaller expression -- arithmetic, test or constructor rule
= final value -- last named reduction
```

Read the placeholders as the actual function, arguments and body from your question. Repeat the middle two steps as often as necessary; never replace several independent arithmetic operations in one line.

`[a,b]` abbreviates `a : b : []`, and a `String` is `[Char]`. A line labelled "list notation" or "string notation" changes only the spelling. `(:)` constructs one list cell. The following elementary equations are used throughout:

```text
(\x -> body) argument = body[x := argument] -- LAM
(op) x y = x op y -- OP
(op k) x = x op k -- SEC-R
(k op) x = k op x -- SEC-L
id x = x -- ID
if True then a else b = a -- IF-T
if False then a else b = b -- IF-F
```

These are notation templates: substitute the actual operator or body. The minus exception matters: `(-k)` means a negative literal, so use `subtract k` for subtraction of `k`. EVEN and ODD name the tests for divisibility by two. Arithmetic, comparisons, equality and MAX name their primitive rules. Multi-argument lambdas are curried: substitute one separate argument at a time. A pair-pattern lambda matches both fields in one pattern match.

These are equational traces of finite, defined values. They calculate results rather than specify GHC's internal evaluation order. Unused branches and tails need not be reduced.

### A lambda: substitute before calculating

```text
(\x -> x + 2) 3 -- given call
= 3 + 2 -- LAM: x := 3
= 5 -- addition
```

The body gets the argument in place of every free occurrence of the parameter.

### An operator: preserve operand order

```text
(-) 8 3 -- given call
= 8 - 3 -- OP: left := 8, right := 3
= 5 -- subtraction
```

Subtraction uses the first argument as its left operand.

### A section: identify the missing operand

```text
(10 -) 4 -- given call
= 10 - 4 -- SEC-L: argument := 4
= 6 -- subtraction
```

The fixed operand is 10. In contrast, `subtract 10 4` is `4 - 10`.

**Common error.** Jumping from a call straight to a value omits the requested method. GHC cannot diagnose missing written reasoning. Show the defining equation, argument substitutions and primitive reductions.

**Practice with answer.** `(\x -> x * x) (4 :: Int)` has type `Int`: substitute `x := 4` (LAM) to get `4 * 4`, then `16` (multiplication).

## 2. Mapping with `map`

`map` transforms each element independently. It preserves the number and order of the elements; the supplied function consumes one element at a time.

**Template:** `map transform inputList`. Replace `transform` by a one-argument function and `inputList` by its inputs.

Labelled equations for paper traces:

```text
map :: (a -> b) -> [a] -> [b]
map f [] = [] -- M0
map f (x:xs) = f x : map f xs -- M1
```

### A section on two numbers

<HaskellTryIt>

```haskell
main :: IO ()
main = print (map (+2) [1,3])
```

```text
[3,5]
```

</HaskellTryIt>

```text
map (+2) [1,3] -- given call
= (+2) 1 : map (+2) [3] -- M1: f := (+2), x := 1, xs := [3]
= (1 + 2) : map (+2) [3] -- SEC-R: argument := 1
= 3 : map (+2) [3] -- addition
= 3 : ((+2) 3 : map (+2) []) -- M1: x := 3, xs := []
= 3 : ((3 + 2) : map (+2) []) -- SEC-R: argument := 3
= 3 : (5 : map (+2) []) -- addition
= 3 : (5 : []) -- M0
= [3,5] -- list notation
```

The section receives each element afresh.

### A lambda on a singleton

<HaskellTryIt>

```haskell
main :: IO ()
main = print (map (\x -> x * x) [4])
```

```text
[16]
```

</HaskellTryIt>

```text
map (\x -> x * x) [4] -- given call
= (\x -> x * x) 4 : map (\x -> x * x) [] -- M1
= (4 * 4) : map (\x -> x * x) [] -- LAM: x := 4
= 16 : map (\x -> x * x) [] -- multiplication
= 16 : [] -- M0
= [16] -- list notation
```

Both occurrences of the parameter receive the same input.

### An empty Boolean list

<HaskellTryIt>

```haskell

```

```text
[]
```

</HaskellTryIt>

```text

= [] -- M0: f := not
```

No application of `not` is needed.

**Common error.** `map (+) [1,2]` produces functions waiting for another number. Printing it gives a missing `Show` instance diagnostic for a function type. Supply the other operand, as in `map (+2) [1,2]`.

**Practice with answer.** `map not [True]` gives `[False]`: M1, `not True = False`, M0, list notation.

## 3. Selecting with `filter`

`filter` keeps elements passing a predicate, which is a function returning `Bool`. A failed test removes that element but does not stop the search.

**Template:** `filter predicate inputList`. The predicate tests each element; the elements themselves remain unchanged.

Labelled equations for paper traces:

```text
filter :: (a -> Bool) -> [a] -> [a]
filter p [] = [] -- F0
filter p (x:xs) = if p x then x : filter p xs else filter p xs -- F1
```

### A comparison section

<HaskellTryIt>

```haskell
main :: IO ()
main = print (filter (>2) [1,3])
```

```text
[3]
```

</HaskellTryIt>

```text
filter (>2) [1,3] -- given call
= if (>2) 1 then 1 : filter (>2) [3] else filter (>2) [3] -- F1
= if 1 > 2 then 1 : filter (>2) [3] else filter (>2) [3] -- SEC-R
= if False then 1 : filter (>2) [3] else filter (>2) [3] -- comparison
= filter (>2) [3] -- IF-F
= if (>2) 3 then 3 : filter (>2) [] else filter (>2) [] -- F1
= if 3 > 2 then 3 : filter (>2) [] else filter (>2) [] -- SEC-R
= if True then 3 : filter (>2) [] else filter (>2) [] -- comparison
= 3 : filter (>2) [] -- IF-T
= 3 : [] -- F0
= [3] -- list notation
```

Only the second element passes.

### A lambda predicate

<HaskellTryIt>

```haskell
main :: IO ()
main = print (filter (\x -> x == 0) [0])
```

```text
[0]
```

</HaskellTryIt>

```text
filter (\x -> x == 0) [0] -- given call
= if (\x -> x == 0) 0 then 0 : filter (\x -> x == 0) [] else filter (\x -> x == 0) [] -- F1
= if 0 == 0 then 0 : filter (\x -> x == 0) [] else filter (\x -> x == 0) [] -- LAM: x := 0
= if True then 0 : filter (\x -> x == 0) [] else filter (\x -> x == 0) [] -- equality
= 0 : filter (\x -> x == 0) [] -- IF-T
= 0 : [] -- F0
= [0] -- list notation
```

The test returns a Boolean; the retained element is still zero.

### An empty input

<HaskellTryIt>

```haskell

```

```text
[]
```

</HaskellTryIt>

```text
filter even [] -- given call
= [] -- F0
```

There is nothing to test.

**Common error.** `filter (+1) [1,2]` does not supply a Boolean test. GHC reports a type mismatch or a missing numeric instance for `Bool`, depending on inferred types. Repair it with `filter (>1) [1,2]`.

**Practice with answer.** `filter odd [2]` gives `[]`: F1, `odd 2 = False`, IF-F, F0.

## 4. Folding from the right with `foldr`

A fold reduces a list to one result. `foldr` gives its combining function the element first and the result for the remaining suffix second. The seed replaces the empty tail.

**Template:** `foldr combine seed inputList`. `combine` has an element argument and a result argument; `seed` is the empty-list result.

Labelled equations for paper traces:

```text
foldr :: (a -> b -> b) -> b -> [a] -> b
foldr f z [] = z -- R0
foldr f z (x:xs) = f x (foldr f z xs) -- R1
```

### A lambda with a weighted accumulator

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldr (\x acc -> x + 2 * acc) 0 [1,2,3])
```

```text
17
```

</HaskellTryIt>

```text
foldr (\x acc -> x + 2 * acc) 0 [1,2,3] -- given call
= (\x acc -> x + 2 * acc) 1 (foldr (\x acc -> x + 2 * acc) 0 [2,3]) -- R1
= (\acc -> 1 + 2 * acc) (foldr (\x acc -> x + 2 * acc) 0 [2,3]) -- LAM: x := 1
= 1 + 2 * foldr (\x acc -> x + 2 * acc) 0 [2,3] -- LAM: acc := recursive result
= 1 + 2 * ((\x acc -> x + 2 * acc) 2 (foldr (\x acc -> x + 2 * acc) 0 [3])) -- R1
= 1 + 2 * ((\acc -> 2 + 2 * acc) (foldr (\x acc -> x + 2 * acc) 0 [3])) -- LAM: x := 2
= 1 + 2 * (2 + 2 * foldr (\x acc -> x + 2 * acc) 0 [3]) -- LAM: acc := recursive result
= 1 + 2 * (2 + 2 * ((\x acc -> x + 2 * acc) 3 (foldr (\x acc -> x + 2 * acc) 0 []))) -- R1
= 1 + 2 * (2 + 2 * ((\acc -> 3 + 2 * acc) (foldr (\x acc -> x + 2 * acc) 0 []))) -- LAM: x := 3
= 1 + 2 * (2 + 2 * (3 + 2 * foldr (\x acc -> x + 2 * acc) 0 [])) -- LAM: acc := recursive result
= 1 + 2 * (2 + 2 * (3 + 2 * 0)) -- R0
= 1 + 2 * (2 + 2 * (3 + 0)) -- multiplication
= 1 + 2 * (2 + 2 * 3) -- addition
= 1 + 2 * (2 + 6) -- multiplication
= 1 + 2 * 8 -- addition
= 1 + 16 -- multiplication
= 17 -- addition
```

Independent check: expanding the weights gives `1 + 2 * 2 + 4 * 3 = 17`.

### Subtraction reveals the nesting

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldr (-) 0 [1,2,3])
```

```text
2
```

</HaskellTryIt>

```text
foldr (-) 0 [1,2,3] -- given call
= (-) 1 (foldr (-) 0 [2,3]) -- R1
= 1 - foldr (-) 0 [2,3] -- OP: left := 1, right := recursive result
= 1 - ((-) 2 (foldr (-) 0 [3])) -- R1
= 1 - (2 - foldr (-) 0 [3]) -- OP
= 1 - (2 - ((-) 3 (foldr (-) 0 []))) -- R1
= 1 - (2 - (3 - foldr (-) 0 [])) -- OP
= 1 - (2 - (3 - 0)) -- R0
= 1 - (2 - 3) -- subtraction
= 1 - (-1) -- subtraction
= 2 -- subtraction
```

This is right-nested subtraction, not successive subtraction from zero.

### An empty input

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldr (+) 10 [])
```

```text
10
```

</HaskellTryIt>

```text
foldr (+) 10 [] -- given call
= 10 -- R0: z := 10
```

No combining call occurs.

**Common error.** Swapping `f x recursiveResult` to `f recursiveResult x` silently changes subtraction. GHC accepts both when the types agree. Keep the element first.

**Practice with answer.** `foldr (-) 0 [4]` gives `4`: R1 gives `(-) 4 (foldr (-) 0 [])`, OP gives `4 - foldr (-) 0 []`, R0 gives `4 - 0`, subtraction gives `4`.

| Suffix processed | Element | Accumulator from right | New result |
|---|---|---|---|
| `[]` | none | seed | `0` |
| `[3]` | `3` | `0` | `3` |
| `[2,3]` | `2` | `3` | `8` |
| `[1,2,3]` | `1` | `8` | `17` |

## 5. Folding from the left with `foldl`

`foldl` carries an accumulator from left to right. Its function takes the accumulator first and the next element second. The following arithmetic reductions calculate the value; ordinary `foldl` need not force each accumulator immediately.

**Template:** `foldl combine seed inputList`. Start at `seed`; after each element use `combine oldAccumulator element`.

Labelled equations for paper traces:

```text
foldl :: (b -> a -> b) -> b -> [a] -> b
foldl f z [] = z -- L0
foldl f z (x:xs) = foldl f (f z x) xs -- L1
```

### The same subtraction arguments

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldl (-) 0 [1,2,3])
```

```text
-6
```

</HaskellTryIt>

```text
foldl (-) 0 [1,2,3] -- given call
= foldl (-) ((-) 0 1) [2,3] -- L1: z := 0, x := 1
= foldl (-) (0 - 1) [2,3] -- OP
= foldl (-) (-1) [2,3] -- subtraction
= foldl (-) ((-) (-1) 2) [3] -- L1: z := -1, x := 2
= foldl (-) ((-1) - 2) [3] -- OP
= foldl (-) (-3) [3] -- subtraction
= foldl (-) ((-) (-3) 3) [] -- L1: z := -3, x := 3
= foldl (-) ((-3) - 3) [] -- OP
= foldl (-) (-6) [] -- subtraction
= -6 -- L0
```

The grouping is `((0 - 1) - 2) - 3`. The matching right-fold call gave `2`.

### A lambda on one element

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldl (\acc x -> acc * 10 + x) 0 [7])
```

```text
7
```

</HaskellTryIt>

```text
foldl (\acc x -> acc * 10 + x) 0 [7] -- given call
= foldl (\acc x -> acc * 10 + x) ((\acc x -> acc * 10 + x) 0 7) [] -- L1
= foldl (\acc x -> acc * 10 + x) ((\x -> 0 * 10 + x) 7) [] -- LAM: acc := 0
= foldl (\acc x -> acc * 10 + x) (0 * 10 + 7) [] -- LAM: x := 7
= foldl (\acc x -> acc * 10 + x) (0 + 7) [] -- multiplication
= foldl (\acc x -> acc * 10 + x) 7 [] -- addition
= 7 -- L0
```

The accumulator is the first parameter.

### An empty input

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldl (*) 5 [])
```

```text
5
```

</HaskellTryIt>

```text
foldl (*) 5 [] -- given call
= 5 -- L0
```

The chosen seed is returned unchanged.

**Common error.** `foldl (:) [] [1,2]` has incompatible list and element roles; GHC reports a type mismatch containing `Couldn't match`. Use `foldl (flip (:)) [] [1,2]` to prepend each new element.

**Practice with answer.** `foldl (-) 10 [3]` gives `7`: L1, OP, subtraction, L0.

| Call | Seed | First update | Second update | Third update |
|---|---|---|---|---|
| `foldl (-) 0 [1,2,3]` | `0` | `-1` | `-3` | `-6` |
| `foldr (-) 0 [1,2,3]`, working from the right | `0` | `3` | `-1` | `2` |

Subtraction is non-commutative: swapping operands changes the answer. Its grouping also matters: the right fold yields `1 - (2 - (3 - 0))`; the left fold yields `((0 - 1) - 2) - 3`. The rows process opposite ends of the list.

## 6. Using the last element as seed: `foldr1`

`foldr1` folds a non-empty list from the right, using its last element as the starting result. No separate seed is inserted. Elements and intermediate results have the same type.

**Template:** `foldr1 combine nonEmptyList`. There must be a last element to start from.

Labelled equations for paper traces:

```text
foldr1 :: (a -> a -> a) -> [a] -> a
foldr1 f [x] = x -- R10
foldr1 f (x:y:xs) = f x (foldr1 f (y:xs)) -- R11
foldr1 f [] = error "Prelude.foldr1: empty list" -- R1E
```

### Subtraction

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldr1 (-) [8,3])
```

```text
5
```

</HaskellTryIt>

```text
foldr1 (-) [8,3] -- given call
= (-) 8 (foldr1 (-) [3]) -- R11
= 8 - foldr1 (-) [3] -- OP
= 8 - 3 -- R10
= 5 -- subtraction
```

A singleton tail supplies the seed.

### A lambda

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldr1 (\x y -> x + 2 * y) [1,2])
```

```text
5
```

</HaskellTryIt>

```text
foldr1 (\x y -> x + 2 * y) [1,2] -- given call
= (\x y -> x + 2 * y) 1 (foldr1 (\x y -> x + 2 * y) [2]) -- R11
= (\y -> 1 + 2 * y) (foldr1 (\x y -> x + 2 * y) [2]) -- LAM: x := 1
= 1 + 2 * foldr1 (\x y -> x + 2 * y) [2] -- LAM: y := recursive result
= 1 + 2 * 2 -- R10
= 1 + 4 -- multiplication
= 5 -- addition
```

The final element is not combined with an extra zero.

### A singleton string list

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldr1 (++) ["hi"])
```

```text
"hi"
```

</HaskellTryIt>

```text
foldr1 (++) ["hi"] -- given call
= "hi" -- R10: x := "hi"
```

Append is never called.

**Common error.** `foldr1 (+) []` raises an exception with message `Prelude.foldr1: empty list`. Use `foldr (+) 0` when empty input should mean zero. The failing call is deliberately outside a runnable block.

**Practice with answer.** `foldr1 max [2,9]` gives `9`: R11, R10, then `max 2 9 = 9`.

## 7. Using the first element as seed: `foldl1`

`foldl1` starts at the first element and left-folds the remaining list. It requires a non-empty list.

**Template:** `foldl1 combine nonEmptyList`. Use the first element as the accumulator, not as the first value to subtract from zero.

Labelled equations for paper traces:

```text
foldl1 :: (a -> a -> a) -> [a] -> a
foldl1 f (x:xs) = foldl f x xs -- L10
foldl1 f [] = error "Prelude.foldl1: empty list" -- L1E
```

### Three subtractions

<HaskellTryIt>

```haskell
main :: IO ()
main = print (foldl1 (-) [8,3,1])
```

```text
4
```

</HaskellTryIt>

```text
foldl1 (-) [8,3,1] -- given call
= foldl (-) 8 [3,1] -- L10
= foldl (-) ((-) 8 3) [1] -- L1
= foldl (-) (8 - 3) [1] -- OP
= foldl (-) 5 [1] -- subtraction
= foldl (-) ((-) 5 1) [] -- L1
= foldl (-) (5 - 1) [] -- OP
= foldl (-) 4 [] -- subtraction
= 4 -- L0
```

Start from 8, then subtract 3 and 1.

### A digit-building lambda

<HaskellTryIt>

```haskell
main :: IO ()

```

```text
23
```

</HaskellTryIt>

```text
foldl1 (\a x -> a * 10 + x) [2,3] -- given call
= foldl (\a x -> a * 10 + x) 2 [3] -- L10
= foldl (\a x -> a * 10 + x) ((\a x -> a * 10 + x) 2 3) [] -- L1
= foldl (\a x -> a * 10 + x) ((\x -> 2 * 10 + x) 3) [] -- LAM: a := 2
= foldl (\a x -> a * 10 + x) (2 * 10 + 3) [] -- LAM: x := 3
= foldl (\a x -> a * 10 + x) (20 + 3) [] -- multiplication
= foldl (\a x -> a * 10 + x) 23 [] -- addition
= 23 -- L0
```

The initial digit is already present in the accumulator.

## 8. Keeping left accumulators with `scanl`

`scanl` uses the left-fold recurrence but returns the seed and every new accumulator. For `n` input elements it returns `n + 1` values.

**Template:** `scanl combine seed inputList`. Each output entry records a prefix result.

Labelled equations for paper traces:

```text
scanl :: (b -> a -> b) -> b -> [a] -> [b]
scanl f z [] = [z] -- SL0
scanl f z (x:xs) = z : scanl f (f z x) xs -- SL1
flip f x y = f y x -- FLIP
```

### Running subtraction

<HaskellTryIt>

```haskell
main :: IO ()
main = print (scanl (-) 0 [1,2])
```

```text
[0,-1,-3]
```

</HaskellTryIt>

```text
scanl (-) 0 [1,2] -- given call
= 0 : scanl (-) ((-) 0 1) [2] -- SL1
= 0 : scanl (-) (0 - 1) [2] -- OP
= 0 : scanl (-) (-1) [2] -- subtraction
= 0 : ((-1) : scanl (-) ((-) (-1) 2) []) -- SL1
= 0 : ((-1) : scanl (-) ((-1) - 2) []) -- OP
= 0 : ((-1) : scanl (-) (-3) []) -- subtraction
= 0 : ((-1) : [-3]) -- SL0
= [0,-1,-3] -- list notation
```

The first entry is the state before using any input.

### Building reversed prefixes

The runnable version spells the empty character-list seed as `""`, equal to `[] :: String`. The paper trace below retains the original `[]` spelling. Both have the same Haskell value and type; the string literal also supplies the site interpreter with a string representation for the empty accumulator.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (scanl (flip (:)) "" "abc")
```

```text
["","a","ba","cba"]
```

</HaskellTryIt>

```text
scanl (flip (:)) [] "abc" -- given call
= [] : scanl (flip (:)) (flip (:) [] 'a') "bc" -- SL1
= [] : scanl (flip (:)) ((:) 'a' []) "bc" -- FLIP: x := [], y := 'a'
= [] : scanl (flip (:)) ('a' : []) "bc" -- OP
= [] : scanl (flip (:)) "a" "bc" -- string notation
= [] : ("a" : scanl (flip (:)) (flip (:) "a" 'b') "c") -- SL1
= [] : ("a" : scanl (flip (:)) ((:) 'b' "a") "c") -- FLIP
= [] : ("a" : scanl (flip (:)) ('b' : "a") "c") -- OP
= [] : ("a" : scanl (flip (:)) "ba" "c") -- string notation
= [] : ("a" : ("ba" : scanl (flip (:)) (flip (:) "ba" 'c') "")) -- SL1
= [] : ("a" : ("ba" : scanl (flip (:)) ((:) 'c' "ba") "")) -- FLIP
= [] : ("a" : ("ba" : scanl (flip (:)) ('c' : "ba") "")) -- OP
= [] : ("a" : ("ba" : scanl (flip (:)) "cba" "")) -- string notation
= [] : ("a" : ("ba" : ["cba"])) -- SL0
= ["","a","ba","cba"] -- list/string notation
```

Independent check: reverse the prefixes `""`, `"a"`, `"ab"`, `"abc"`. The seed has type `String`; the full result has type `[String]`.

### An empty input

<HaskellTryIt>

```haskell
main :: IO ()

```

```text
[7]
```

</HaskellTryIt>

```text

```

Even without input there is one accumulator.

**Practice with answer.** `scanl (+) 0 [5]` is `[0,5]`: SL1, OP, addition, SL0, list notation.

| Next character | Old accumulator | New cons application | New accumulator |
|---|---|---|---|
| none | seed | none | `""` |
| `'a'` | `""` | `'a' : ""` | `"a"` |
| `'b'` | `"a"` | `'b' : "a"` | `"ba"` |
| `'c'` | `"ba"` | `'c' : "ba"` | `"cba"` |

Printing a list of strings includes the double quotes, and prints an empty string as `""`.

## 9. Keeping right accumulators with `scanr`

`scanr` returns the right-fold result of every suffix, followed by the seed for the empty suffix. Work arithmetic from the right, but write the output in the original suffix order.

**Template:** `scanr combine seed inputList`. Use the first result of the tail scan as the next right accumulator.

Labelled equations for paper traces:

```text
scanr :: (a -> b -> b) -> b -> [a] -> [b]
scanr f z [] = [z] -- SR0
scanr f z (x:xs) = let qs = scanr f z xs in f x (head qs) : qs -- SR1
head (q:qs) = q -- HEAD
```

### Subtraction over suffixes

<HaskellTryIt>

```haskell
main :: IO ()
```

## Summary

<Callout type="key" title="Remember">

Use one labelled equation per line and show substitutions before arithmetic. `map` transforms, `filter` selects anywhere, and prefix operations stop at the first failure. A right fold combines an element with a suffix result; a left fold combines an accumulator with the next element. Scans keep the seed and intermediate values. The `1` folds require non-empty input. Zips stop at the shortest list. `flip` exchanges arguments, `curry` and `uncurry` change tuple packaging, composition builds a function, and dollar applies one.

</Callout>

## Check your understanding

<CheckQuestions>

<CheckQuestion question="Why can subtraction distinguish left and right folds when addition often cannot?">

Subtraction depends on order and grouping. `foldr (-) 0 [1,2,3]` is `2`; `foldl (-) 0 [1,2,3]` is `-6`.

</CheckQuestion>

<CheckQuestion question="What does an empty input contribute to a scan?">

Both `scanl f z []` and `scanr f z []` give `[z]`. A scan with an explicit seed has one more output than input elements.

</CheckQuestion>

<CheckQuestion question="Why does scanl (flip (:)) [] build reversed prefixes?">

The scan supplies the accumulator first. FLIP turns `flip (:) acc x` into `(:) x acc`, which prepends each new element.

</CheckQuestion>

<CheckQuestion question="How do composition and dollar differ?">

`f . g` is a function waiting for input. `f $ x` applies `f` to `x`. Both `(f . g) x` and `f $ g x` reduce to `f (g x)`.

</CheckQuestion>

<CheckQuestion question="Which functions here require a non-empty input?">

`foldr1` and `foldl1`. Use folds with an explicit seed when empty input should have a result.

</CheckQuestion>

</CheckQuestions>
