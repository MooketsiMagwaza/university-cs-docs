## Practise without leaving the notes

Use this runner for the expression and list-processing ideas taught in CSI243. Pick an example, change part of it, and run it again. A successful program prints its result in the output panel. A broken program reports the kind of failure, the source location when available, and a hint about what to inspect.

## What this runner covers

The runner supports the course's most useful practice subset:

- numbers, Booleans, strings, characters, tuples, and lists;
- arithmetic, comparisons, Boolean operators, list cons, append, composition, and `$`;
- one-line function definitions, lambdas, operator sections, recursion, and `if/then/else`;
- `map`, `filter`, `zip`, `zipWith`, folds, scans, `take`, `drop`, `takeWhile`, and `dropWhile`;
- finite ranges such as `[1..10]` and lazy ranges such as `[1..]` when a finite consumer such as `take` limits the result;
- `main = do` practice using `let`, `print`, and `putStrLn`.

It deliberately does not pretend to be the complete Glasgow Haskell Compiler. Pattern matching equations, guards, modules, imports, custom types, type classes, and arbitrary `IO` still belong in GHCi or a `.hs` file compiled with GHC. The runner says **Course subset** above the editor so that simulated feedback is never mistaken for an authoritative GHC diagnostic.

## A useful error-reading loop

1. Read the error category first: parse, type, or runtime.
2. Use the line and column to find the smallest expression involved.
3. Check the function's argument order and the type of each value.
4. Change one thing and run again.

For full compiler setup and real GHCi commands, continue with [Setting Up and Using GHCi](/docs/sem3/csi243/02-expressions-types/notes/ghci).
