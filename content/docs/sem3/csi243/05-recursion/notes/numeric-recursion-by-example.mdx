Before each runnable variation, predict the output and identify its input partition. Blocks are self-contained. The safe wrappers use [Maybe in Depth](/docs/sem3/csi243/09-polymorphism/notes/maybe-in-depth); they reject invalid inputs rather than invent a numeric answer. Templates describe the general shape; runnable variations supply complete definitions.

## 1. Start from the words: cube and multTen

A specification describes the result that an input means. A recursive implementation is justified only when a smaller instance helps. Cubing and multiplying by ten are useful controls: neither needs recursion. Both accept all integers, including negatives. Use Integer for exact whole-number results; the type alone does not specify the formula.

For each design in this lesson, write purpose, examples, domain, base case, recursive relationship, signature, dry run and tests. If no recursion is needed, explain that decision. This applies the existing design procedure rather than replacing it.

### Related specification: A percentage formula with an explicit valid domain

A price after a percentage discount is the original price times the remaining fraction. Here price must be non-negative and percentage must lie from zero through one hundred. These are preconditions of the direct Double function; the checked wrapper rejects values outside that domain. The examples use finite values with exact simple outputs. General monetary rounding and floating tolerance belong to arithmetic and formatting lessons.

### Template and reading guide

```haskell
finalPrice :: Double -> Double -> Double
finalPrice price discount = price * (1 - discount / 100)
finalPriceChecked :: Double -> Double -> Maybe Double
finalPriceChecked price discount
  | price < 0 || discount < 0 || discount > 100 = Nothing
  | otherwise = Just (finalPrice price discount)
```

Subtract discount/100 from one to obtain the fraction remaining. Multiplying by discount/100 alone would compute the saving. The wrapper validates finite inputs before applying the formula; no recursion is necessary.

## 2. Factorial variants with agreeing domains

Factorial multiplies the positive integers up to a non-negative input. Extend the familiar countdown by comparing an ascending range product, a list product and a stride-two product. Validate negatives before entering a worker. An empty product is one, but an invalid factorial input is not an empty valid problem.

The double factorial n!! multiplies every second positive integer. It is not (n!)!. Its bases are 0!! = 1 and 1!! = 1 because both parities must stop. The Maybe wrappers use the already-taught safe-result pattern, not a new error mechanism.

### Template and reading guide

```text
checked n
  | n < 0 = Nothing
  | otherwise = Just (worker n)
worker 0 = 1
worker n = n * worker (n - 1)
```

Use the checked-worker template but subtract two. Both zero and one must return one. The countdown decreases by one for factorial, by two for double factorial; the ascending worker decreases the count of remaining factors.

### Worked variation: Equivalent countdown, ascending and list algorithms

<HaskellTryIt>

```haskell
factCountdown :: Integer -> Maybe Integer
factCountdown n
  | n < 0 = Nothing
  | otherwise = Just (down n)
  where
    down 0 = 1
    down k = k * down (k - 1)
factProduct :: Integer -> Maybe Integer
factProduct n
  | n < 0 = Nothing
  | otherwise = Just (between 1 n)
  where
    between a b
      | a > b = 1
      | otherwise = a * between (a + 1) b
productList :: [Integer] -> Integer
productList [] = 1
productList (x:xs) = x * productList xs
factViaList :: Integer -> Maybe Integer
factViaList n
  | n < 0 = Nothing
  | otherwise = Just (productList [1..n])
doubleFact :: Integer -> Maybe Integer
doubleFact n
  | n < 0 = Nothing
  | otherwise = Just (down n)
  where
    down k
      | k <= 1 = 1
      | otherwise = k * down (k - 2)

main :: IO ()
main = print ((factCountdown 5, factProduct 5, factViaList 5))
```

```text
(Just 120,Just 120,Just 120)
```

</HaskellTryIt>

The countdown multiplies 5,4,3,2,1; the other versions multiply 1,2,3,4,5. Integer multiplication gives 120 in either order.

## 4. Range traversal and reversed endpoints

Incrementing a lower bound can be progress: the number of remaining terms decreases. Signed endpoints are valid. Reversed bounds need a separate stated policy: empty, swap to normalise, or reject. These are different contracts, not equivalent implementations. A half-open range includes its lower endpoint but excludes its upper.

### Template and reading guide

```text
range lo hi
  | lo > hi = identity
  | otherwise = combine lo (range (lo + 1) hi)
```

In the range template identity is one and combine is multiplication. The measure is max 0 (hi-lo+1). For a half-open sum the stop test changes to lo >= hi.

## 5. Sum of factorials without restarting factorial

### Template and reading guide

## 6. Signed multiplication by repeated addition

The first argument is a value to add; the second is a repetition count. A negative value is harmless, but a negative count requires sign handling. Normalise the multiplier, add that many copies, then negate the result once. An alternative moves a negative multiplier upwards to zero while adding the negated value.

### Template and reading guide

## 8. Exponentiation by squaring and sharing

Halving an exponent can replace a countdown. For n=2q, square the power at q. For n=2q+1, also multiply by the base. Bind the half-power once and reuse it. Two separately written recursive calls describe repeated work rather than this intended shared design. Accept signed bases, reject negative exponents, and define exponent zero as one.

### Template and reading guide

```text
go 0 = 1
go n
  | even n = half * half
  | otherwise = x * half * half
  where half = go (n `div` 2)
```

In the template half is the result for quotient n div 2. A positive exponent halves to a smaller non-negative integer. Even parity needs half squared; odd parity needs an extra x.

### Worked variation: Even exponent

<HaskellTryIt>

## 9. Euclid: both parameters change

For positive b, the remainder lies from zero through b-1. This bound needs the normalised domain. Define gcd 0 0 as zero, following Prelude, as a convention for that exceptional pair.

### Template and reading guide

## 10. Derive lcm and protect the zero case

### Template and reading guide

## 14. Two-branch Fibonacci and repeated subproblems

A recurrence defines a value from earlier values. Standard Fibonacci uses seeds F(0)=0 and F(1)=1, then adds F(n-1) and F(n-2). Different seeds with the same recurrence define different sequences. Reject negative indices before branching. Both children decrease, but their descendants overlap: the same index can be recomputed in different branches. Two calls alone do not establish a complexity class; their sizes and local work matter.

### Template and reading guide

```text
go 0 = firstSeed
go 1 = secondSeed
go n = go (n - 1) + go (n - 2)
```

In the template the seeds determine values and both smaller indices are non-negative for n at least two. For entries, use different bases: C(0)=C(1)=1 and C(n)=1+C(n-1)+C(n-2). The one counts the current entry.

## 15. Fibonacci with adjacent-value accumulators

Carry two adjacent values instead of recomputing two branches. After k transitions they are F(k) and F(k+1). Advancing replaces (a,b) with (b,a+b), with both expressions using the old state. A remaining counter decreases to zero. This is one recursive call with several changing arguments, not two branches. Tail-call shape does not force arithmetic in lazy Haskell.

### Template and reading guide

```text
go 0 a b = a
go remaining a b = go (remaining - 1) b (a + b)
fib n = go n 0 1
```

In the template a is the current value, b the next, and remaining is the number of transitions left. Seed with (0,1) and return a after n transitions. The counter is the decreasing measure.

## 16. Compare the designs

| Shape | What changes | Decreasing measure |
| --- | --- | --- |
| Countdown | One count | Remaining terms or factors |
| Ascending range | Lower bound rises | Number of integers left |
| Multiplication | Normalise sign then count | Absolute multiplier |
| Squaring | Exponent halves | Non-negative exponent |
| Euclid | Both inputs change | Normalised second input |
| Decimal algorithm | Quotient removes a digit | Remaining magnitude |
| Direct Fibonacci | Two smaller indices | Index on each path |
| Accumulator Fibonacci | Counter and adjacent values | Remaining transitions |

A guard, pattern, if or case can express the same choice. Use [Writing Recursive Functions](/docs/sem3/csi243/05-recursion/notes/writing-recursive-functions) for the general conversions. Range conditions often suit guards; literal seeds suit patterns. Changing syntax must preserve the contract.

For correctness for all valid inputs, use [Proofs of Programs I](/docs/sem3/csi243/10-reasoning-revision/notes/proofs-of-programs-i); finite checks alone do not prove a universal claim. Cost derivations for repeated factorials, Fibonacci and halving belong to [Complexity by Recurrence](/docs/sem3/csi243/10-reasoning-revision/notes/complexity-by-recurrence). For pending accumulator expressions see [Lazy Evaluation](/docs/sem3/csi243/10-reasoning-revision/notes/lazy-evaluation).

The Test1 Fibonacci function returns Either String Integer. Its applicative expression `((+) <$> fibonacci (n - 1)) <*> fibonacci (n - 2)` combines two successful smaller results while retaining failure. It still has the same overlapping recursive subproblems; it is not an accumulator optimisation. See [Functor and Applicative Patterns](/docs/sem3/csi243/09-polymorphism/notes/functor-and-applicative-patterns) for its types and first-failure behaviour.
