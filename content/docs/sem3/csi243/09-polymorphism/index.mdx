## Key ideas

Two ideas, and the second solves a problem created by the first:

- **Parametric polymorphism** lets one function work for many types, using a type variable.
- **Type classes** let a type variable carry a requirement, so the function can actually do something with its values.

### The trade-off to carry forward

| Signature | Works on | The function may |
|---|---|---|
| `[Int] -> Int` | Only `Int` | Anything `Int` supports |
| `Num a => [a] -> a` | Any numeric type | Only what `Num` provides |
| `[a] -> Int` | Any type at all | Nothing to the elements |

More constraints means fewer types but more capability; fewer constraints means more types but less capability. **The right signature is the most general one that still permits what the function needs.**
