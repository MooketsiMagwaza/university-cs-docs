Chapter 5 closed a gap using `error`, and noted the cost: `error` stops the whole program and the caller cannot recover. This lesson shows exactly how badly that cost bites, introduces the tool that fixes it, and then shows how to define class membership yourself.

## 1. Watching a partial function fail

`safeHead` from Chapter 6 has a perfectly reasonable-looking signature, `[a] -> a`, but it lies to the type checker: there is no sensible `a` to return for an empty list, so it calls `error` instead.

```haskell
safeHead :: [a] -> a
safeHead []    = error "safeHead: empty list"
safeHead (x:_) = x

main :: IO ()
main = do
  putStrLn "First element of [10,20,30]:"
  print (safeHead [10, 20, 30])
  putStrLn "First element of []:"
  print (safeHead ([] :: [Int]))
```

```text
First element of [10,20,30]:
10
First element of []:
*** Exception: safeHead: empty list
```

Notice exactly where execution stops: the label `"First element of []:"` is printed — `putStrLn` already ran — but `print (safeHead ...)` never produces anything, and the program terminates right there. Nothing written *after* `main` in a larger program would run either.

A second version makes the cost more vivid still, because it involves no explicit `error` call at all — an *ordinary* arithmetic partiality is enough to do the same damage to an entire batch of work:

```haskell
-- Average a class's marks. Wrong for an empty class: sum [] `div`
-- length [] is 0 `div` 0, and integer division by zero is an error.
reportAverage :: [Int] -> Int
reportAverage xs = sum xs `div` length xs

main :: IO ()
main = do
  putStrLn "Class A average:"
  print (reportAverage [70, 80, 90])
  putStrLn "Class B average:"
  print (reportAverage [])
  putStrLn "Class C average:"
  print (reportAverage [60, 65])
```

```text
Class A average:
80
Class B average:
*** Exception: divide by zero
```

Read the output carefully: **"Class C average:" is never printed.** Class B's empty list did not just produce a wrong or missing result for Class B — it took the entire remaining batch down with it, including a perfectly good, computable result for Class C. This is what "`error` cannot be recovered from" costs in practice: one bad input among many ruins all of them.

<Callout type="warn" title="Two different partialities, one lesson">
`safeHead []` fails because *we* called `error` explicitly. `reportAverage []` fails because `div` is itself partial — it has no sensible answer for a zero divisor, and raises the built-in `divide by zero` exception without any `error` call in sight. Both are examples of a **partial function**: one whose signature promises a result for every input of the right type, but whose definition cannot actually produce one for some of them.
</Callout>

## 2. The `Maybe` type

`Maybe` is an ordinary data declaration in the Prelude:

```haskell
data Maybe a = Nothing | Just a
```

<Mermaid chart={`flowchart TD
  M["Maybe a"] --> N["Nothing — no value of type a"]
  M --> J["Just x — holds exactly one value x :: a"]`} caption="Maybe a is a two-constructor sum type, exactly like Bool's True and False, except the second constructor also carries a value. Nothing needs no argument; Just always needs exactly one." />

A `Maybe a` is either `Nothing`, meaning no result, or `Just` holding a value of type `a`. It is polymorphic, so `Maybe Int`, `Maybe String`, and `Maybe Shape` are all available.

```text
ghci> Just 5
Just 5
ghci> Nothing :: Maybe Int
Nothing
ghci> :type Just 'a'
Just 'a' :: Maybe Char
```

The point is that **failure becomes part of the result type**. A caller receiving a `Maybe Int` can see from the signature alone that the function might not produce an answer — nothing needs to crash to communicate that.

## 3. Replacing `error`

Compare the two ways of handling an empty list:

```haskell
-- Chapter 6: stops the program.
safeHead :: [a] -> a
safeHead []    = error "safeHead: empty list"
safeHead (x:_) = x

-- With Maybe: the caller decides what to do.
maybeHead :: [a] -> Maybe a
maybeHead []    = Nothing
maybeHead (x:_) = Just x
```

```text
ghci> maybeHead [1,2,3]
Just 1
ghci> maybeHead ([] :: [Int])
Nothing
```

No crash. The empty case produced a perfectly ordinary value.

Rewrite the batch-averaging example from Section 1 the same way, and the difference is dramatic:

```haskell
maybeAverage :: [Int] -> Maybe Int
maybeAverage []  = Nothing
maybeAverage xs  = Just (sum xs `div` length xs)

main :: IO ()
main = do
  print (maybeAverage [70, 80, 90])
  print (maybeAverage [])
  print (maybeAverage [60, 65])
```

```text
Just 80
Nothing
Just 62
```

**Every** report now appears — Class B is honestly marked `Nothing` instead of destroying Class C's result. The batch survives a bad input; only that one input is affected.

## 4. Handling a `Maybe`

Because `Nothing` and `Just` are ordinary constructors, you handle them by pattern matching — one equation per constructor, exactly as in Chapter 8:

```haskell
-- Describe the first element, or say there is none.
describeHead :: Show a => [a] -> String
describeHead xs =
  case maybeHead xs of
    Nothing -> "the list is empty"
    Just x  -> "the first element is " ++ show x
```

```text
ghci> describeHead [7,8]
"the first element is 7"
ghci> describeHead ([] :: [Int])
"the list is empty"
```

<Mermaid chart={`flowchart TD
  V["v :: Maybe a"] --> D{"Which constructor?"}
  D -->|"Nothing"| H1["Handle the no-value case"]
  D -->|"Just x"| H2["Use x, now safely known to be of type a"]`} caption="Pattern matching a Maybe always forces exactly these two branches. Omitting Nothing compiles (with a warning) but crashes at run time the moment a Nothing actually arrives." />

The compiler will not let you forget the `Nothing` case, which is the whole benefit: the failure cannot be ignored silently.

Pattern matching directly in a function's equations, rather than through `case`, works just as well and is often shorter:

```haskell
-- Use x if there is one, otherwise fall back to a default.
addDefault :: Maybe Int -> Int -> Int
addDefault Nothing  d = d
addDefault (Just x) _ = x

main :: IO ()
main = do
  print (addDefault (Just 7) 0)
  print (addDefault Nothing 0)
```

```text
7
0
```

The Prelude provides exactly this idea, generalised, as `fromMaybe`:

```haskell
import Data.Maybe (fromMaybe)

fromMaybe :: a -> Maybe a -> a

main :: IO ()
main = do
  print (fromMaybe 0 (maybeHead [5, 6]))
  print (fromMaybe 0 (maybeHead ([] :: [Int])))
```

```text
5
0
```

## 5. Two shapes of Maybe-producing function

The most common use is search — looking something up and possibly not finding it. Chapter 8 sketched it; here it is in full:

```haskell
type Assoc k v = [(k, v)]

-- Find the value stored against a key, if there is one.
lookUp :: Eq k => k -> Assoc k v -> Maybe v
lookUp _ [] = Nothing
lookUp key ((k, v):rest)
  | key == k  = Just v
  | otherwise = lookUp key rest
```

```text
ghci> let marks = [("Kago", 72), ("Naledi", 68)]
ghci> lookUp "Kago" marks
Just 72
ghci> lookUp "Sipho" marks
Nothing
```

Note the `Eq k` constraint: the function compares keys, so `k` cannot be an arbitrary type. The Prelude's own `lookup` has exactly this shape.

A second, genuinely different shape is **computing** a result that is only sometimes defined, with no searching involved at all:

```haskell
-- Divide safely: Nothing for a zero divisor, instead of a crash.
safeDivide :: Int -> Int -> Maybe Int
safeDivide _ 0 = Nothing
safeDivide m n = Just (m `div` n)

main :: IO ()
main = do
  print (safeDivide 10 2)
  print (safeDivide 7 0)
  print (safeDivide (-9) 3)
```

```text
Just 5
Nothing
Just (-3)
```

`lookUp` fails when nothing in the data matches. `safeDivide` fails when the arithmetic itself has no answer. Both return `Maybe`, and both hand the decision of what "no answer" means to the caller — but the *reason* for failure is completely different in each, which is exactly why "wrap it in Maybe" is a pattern you apply again and again, not a single fixed recipe.

## 6. Writing your own instances

`deriving` handles the obvious cases: equality by comparing every field, ordering by declaration or field order, display as the constructor name followed by its arguments. When you want genuinely different behaviour, you write the instance by hand.

Take the `Shape` type from Chapter 8:

```haskell
data Shape = Circle Float | Rectangle Float Float

area :: Shape -> Float
area (Circle r)      = pi * r * r
area (Rectangle w l) = w * l
```

**What.** An instance declaration supplies, for one specific type, the operations a class requires:

```haskell
instance ClassName TypeName where
  -- definitions of the class's operations
```

**Why.** A derived instance is always *structural* — it only ever looks at which constructor was used and what its raw fields are. Sometimes the behaviour you actually want depends on something *computed* from those fields instead, and no amount of generic field-by-field logic can produce that.

**When.** Use a hand-written instance when display should be human prose rather than constructor syntax, when equality should mean something domain-specific rather than "same constructor, same fields", or when ordering should follow a computed value rather than declaration order. Otherwise, default to `deriving` — it is shorter, and it is exactly right far more often than not.

A derived `Show` would print `Circle 2.0`. Suppose you want something friendlier:

```haskell
instance Show Shape where
  show (Circle r)      = "a circle of radius " ++ show r
  show (Rectangle w l) = "a " ++ show w ++ " by " ++ show l ++ " rectangle"
```

```text
ghci> print (Circle 2.0)
a circle of radius 2.0
```

**How.** The mechanism is the same type-directed dispatch from Lesson 2: wherever `show` is applied to a `Shape`, GHC looks up the one `Show Shape` instance in scope and runs the code written there, instead of generating field-by-field text.

Now `Shape` is a member of `Show`, and every function with a `Show a =>` constraint accepts it.

### An `Eq` instance, and an `Ord` instance built to match it

Suppose two shapes should count as equal when their areas match, regardless of which constructor produced them:

```haskell
instance Eq Shape where
  s1 == s2 = area s1 == area s2
```

```text
ghci> Rectangle 2 6 == Rectangle 3 4
True
```

A derived instance would have said `False`, because the constructors carry different numbers. Writing the instance by hand lets you define equality to mean what your problem needs.

Having decided that "equal" means "same area", the natural `Ord` instance orders shapes the same way — by area — rather than by declaration order or by their raw fields:

```haskell
instance Ord Shape where
  compare s1 s2 = compare (area s1) (area s2)
```

```haskell
import Data.List (sort)

main :: IO ()
main = do
  print (sort [Rectangle 3 4, Circle 2.0, Rectangle 1 1])
```

```text
[a 1.0 by 1.0 rectangle,a 3.0 by 4.0 rectangle,a circle of radius 2.0]
```

`sort` needs nothing but the `Ord Shape` instance — it has no idea "area" is involved at all. It asked `compare` for each pair and trusted the answer, exactly as it would for any other `Ord` instance, derived or hand-written.

**Properties.** Nothing forces two hand-written instances of *different* classes to agree with each other. Here they do, by design — `Eq` and `Ord` both key off `area`. But notice that `Rectangle 2 6 == Rectangle 3 4` is `True`, while `show (Rectangle 2 6)` and `show (Rectangle 3 4)` print two visibly different descriptions. Two values can be `==` and still *look* completely different when shown — "equal" here means "same area", not "indistinguishable in every respect". A derived `Eq` would never produce that surprise, because it only ever calls two values equal when every field is literally identical. Deciding whether that surprise is acceptable for your problem is exactly the judgement a hand-written instance asks you to make.

## 7. Naming the bigger pattern: Functor and Monad

Two things you have now met without their real names deserve those names before this chapter ends, because you will meet them again by name the moment you look at any real Haskell code or documentation.

### `fmap`: applying a function inside a box you don't open

Chapter 10's `facMaybe` used `fmap (n *) (facMaybe (n - 1))` to apply a multiplication *inside* a `Maybe`, without ever pattern-matching it by hand. That "apply a function to whatever's inside, without unwrapping it yourself" operation has a name and a class:

```haskell
class Functor f where
  fmap :: (a -> b) -> f a -> f b
```

Read the class header as: "any type constructor `f` that can be made a `Functor` supports `fmap`, which takes an ordinary function `a -> b` and lifts it to work on an `f a` instead, producing an `f b`." `Maybe` is one instance; **lists are another** — and you have been calling list's `fmap` by its other name, `map`, since Chapter 7:

```haskell
main :: IO ()
main = do
  print (fmap (+1) (Just 5))
  print (fmap (+1) Nothing)
  print (fmap (*2) [1, 2, 3])
```

```text
Just 6
Nothing
[2,4,6]
```

`fmap (+1) (Just 5) = Just 6`; `fmap (+1) Nothing = Nothing` — the fmap for `Maybe` is precisely the "apply if `Just`, pass through unchanged if `Nothing`" idea from Section 3, generalised into one reusable operation instead of a bespoke pattern match every time. `fmap (*2) [1,2,3]` behaves exactly like `map (*2) [1,2,3]` because, for lists, it *is* the same function — `map` is list's `fmap`.

### `>>=` and `do`: the pattern behind Chapter 3's desugaring, now named

Chapter 3's [do-notation section](/docs/sem3/csi243/03-defining-functions/notes/input-processing) showed that `main = do { a <- getLine; ... }` desugars to `getLine >>= \a -> ...`, and promised the real meaning of `>>=` would come later. Here it is:

```haskell
class Monad m where
  (>>=) :: m a -> (a -> m b) -> m b
  return :: a -> m a
```

`>>=` ("bind") takes an `m a` — a value of type `a` sitting inside some context `m` — and a function that says what to do with the plain `a` *once you have it*, and produces an `m b`. `IO` is one instance of `Monad`: `IO a` is "an action that, when performed, yields an `a`," and `>>=` is exactly "perform this action, then feed its result into what comes next" — the mechanism Chapter 3 traced by hand.

`Maybe` is a **second, completely independent** instance of `Monad` — and because `do`-notation is defined generically for *any* `Monad`, not specially for `IO`, the exact same `do` syntax works for chaining `Maybe`-producing functions, with the exact same short-circuiting Section 3 built by hand with nested `case`s:

```haskell
chain :: Int -> Int -> Int -> Maybe Int
chain a b c = do
  x <- safeDivide a b
  y <- safeDivide x c
  return y

main :: IO ()
main = do
  print (chain 100 5 2)
  print (chain 100 0 2)
  print (chain 100 5 0)
```

```text
Just 10
Nothing
Nothing
```

`chain 100 5 2`: `safeDivide 100 5` is `Just 20`, so `x = 20`; `safeDivide 20 2` is `Just 10`, so `y = 10`; `return y` wraps it back up as `Just 10`. `chain 100 0 2` fails at the very first `<-` — `safeDivide 100 0` is `Nothing` — and the whole `do` block short-circuits to `Nothing` without ever reaching the second line, exactly the way an `error` inside `IO`'s `do` block aborted the rest of `main` in Section 1, except recoverably: the caller gets `Nothing` back as an ordinary value, not a crash. `chain 100 5 0` shows the failure can just as easily come from the *second* line instead of the first.

## 8. Common errors

| Attempt | Problem | Repair |
|---|---|---|
| `maybeHead xs + 1` | `Maybe Int` is not `Int` | Pattern match, or use `fromMaybe` |
| Handling only `Just` | Non-exhaustive patterns at run time | Always cover `Nothing` |
| `Nothing` with no annotation at the prompt | The element type is undetermined | `Nothing :: Maybe Int` |
| Both `deriving (Show)` and `instance Show` | Duplicate instance | Remove one |
| `instance Show Shape` missing `show` | The class operation is undefined | Define every required operation |
| `lookUp :: k -> Assoc k v -> Maybe v` | `==` needs a constraint | `Eq k =>` |
| `sort [Circle 1, Rectangle 2 3]` with no `Ord Shape` | `sort` needs `Ord`, and none exists yet | Derive or write `instance Ord Shape` |
| Expecting `Eq` and `Show` to "agree" | Nothing enforces this for hand-written instances | Decide deliberately, and document the choice |
| Expecting `fmap` to unwrap the result | `fmap` keeps the same context (`Maybe`, `[]`, ...) | `fmap` returns `f b`, not `b` — pattern match if you need the bare value |
