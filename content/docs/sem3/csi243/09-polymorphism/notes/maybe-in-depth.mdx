A failed search, an empty list and an invalid calculation need a caller decision. This lesson extends the introductory Maybe lesson into a working method: design the failure cases, calculate with successful payloads, and choose how to consume or propagate absence.

<LearningObjectives items={["Design safe functions with explicit failure cases", "Define and trace standard Maybe consumers", "Distinguish mapping, collecting and chaining", "Use optional fields and read Eq, Ord and Show behaviour"]} />

## 1. The problem and the two constructors

A missing key has no associated value; `head []` has no first element; integer division by zero has no quotient. Returning `-1` hides failure among valid numbers: a temperature or balance can really be negative. A default `0` also hides information. `error` raises an exception instead of returning an ordinary result. `Maybe` keeps absence separate from every valid payload.

The Prelude declaration is shown for reading; do not redeclare it:

```haskell
data Maybe a = Nothing | Just a
```

`a` names the payload type. `Nothing :: Maybe a` carries no payload; `Just :: a -> Maybe a` carries exactly one. `Maybe Int` differs from `Int`. A present empty list `Just []` differs from `Nothing`. In `Just Nothing :: Maybe (Maybe Int)`, the outer result exists but the inner result is absent.

**Template:** construct absence with `Nothing :: Maybe PayloadType` and presence with `Just payload`. Consume it with one alternative per constructor. The type exposes absence; it does not force exhaustive matching without suitable warning settings.

This deliberately rejected program belongs outside a runnable block:

```haskell
-- Incorrect: arithmetic on the wrapper.
main :: IO ()
main = print ((Just 3 + 1) :: Maybe Int)
```

The key GHC diagnostic is `No instance for (Num (Maybe Int))`. Repair it by matching the constructors or mapping `(+1)` over the payload.

**Producer template:**

```haskell
optional invalid calculate input
  | invalid input = Nothing
  | otherwise = Just (calculate input)
```

`invalid` is a Boolean test, `calculate` computes the payload, and `input` is checked before the calculation. For lists, use `[]` and cons patterns instead. The next eight sections vary the reason for failure, the payload type and the boundary conditions.

## 2. `safeDiv`: a non-zero divisor

Integer `div` rounds down; negative quotients are valid. Use unbounded `Integer` here so the only excluded divisor is zero.

**Template:** `safeDiv numerator divisor`: reject a zero divisor before doing arithmetic.

**Defining equations:**

```haskell
safeDiv :: Integer -> Integer -> Maybe Integer
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)
```


```text

```

</HaskellTryIt>

**Hand trace:** `safeDiv 17 5 = Just (div 17 5) = Just 3`, by the non-zero equation.

## 6. `safeIndex`: two boundaries

Index from zero. Negative positions and running out of list are independent failure cases.

**Template:** `safeIndex items position`: reject negatives, then discard one cons per decrement.

**Defining equations:**

```haskell
safeIndex :: [a] -> Int -> Maybe a
safeIndex _ n | n < 0 = Nothing
safeIndex [] _ = Nothing
safeIndex (x:_) 0 = Just x
safeIndex (_:xs) n = safeIndex xs (n - 1)
```

### Variation: recursive selection

<HaskellTryIt>

</HaskellTryIt>

## 7. `findValue`: table lookup

Compare keys, stop at the first match, and fail only after exhausting the table. Duplicate keys therefore use the first value.

**Template:** `findValue wanted pairs`: `Eq k` supplies key equality; no constraint on values is needed.

**Defining equations:**

```haskell
findValue :: Eq k => k -> [(k,v)] -> Maybe v
findValue _ [] = Nothing
findValue key ((k,v):rest)
  | key == k = Just v
  | otherwise = findValue key rest
```

### Variation: skip then match

<HaskellTryIt>

```haskell
-- Predict findValue "b" [("a",3),("b",7 :: Int)].
findValue :: Eq k => k -> [(k,v)] -> Maybe v
findValue _ [] = Nothing
findValue key ((k,v):rest)
  | key == k = Just v
  | otherwise = findValue key rest

main :: IO ()
main = print (findValue "b" [("a",3),("b",7 :: Int)])
```

```text
Just 7
```

</HaskellTryIt>

**Hand trace:** `"b" == "a"` is `False`; recurse. `"b" == "b"` is `True`, so return `Just 7`.

### Variation: duplicate keys

<HaskellTryIt>

```haskell
-- Predict findValue 1 [(1,"first"),(1,"later")].

  | key == k = Just v

```


</HaskellTryIt>

## 9. `parseDigit`: one ASCII character

Accept one of the ten characters from zero to nine. This is not a parser for signed numbers or whole strings.

**Template:** `parseDigit character`: check the range, then subtract the code of zero.

**Defining equations:**

```haskell
parseDigit :: Char -> Maybe Int
parseDigit c
  | c >= '0' && c <= '9' = Just (fromEnum c - fromEnum '0')
  | otherwise = Nothing
```

### Variation: middle digit

## 11. Consuming by guarded `case`

After matching a constructor, guards can test its payload. Variables bound by the pattern are available only inside that alternative.

**Template:** `case optional of Nothing -> fallback; Just x | test x -> firstResult | otherwise -> secondResult`. Try guards in order.

**Defining equations:**

```haskell
describe :: Maybe Int -> String
describe m = case m of
  Nothing -> "missing"
  Just n | n < 0 -> "negative"
         | otherwise -> "non-negative"
```

### Variation: absent alternative

<HaskellTryIt>

```haskell
main :: IO ()

```

</HaskellTryIt>

## 12. `maybe`: choose and transform

The eliminator removes the outer wrapper: a default on absence, or a function applied to the payload. The result type may differ from the payload type.

**Template:** `maybe fallback transform optional`: `fallback :: b`, `transform :: a -> b`, `optional :: Maybe a`.

**Defining equations:**

```haskell
maybe :: b -> (a -> b) -> Maybe a -> b
maybe d _ Nothing = d
maybe _ f (Just x) = f x
```

### Variation: numeric transformation

<HaskellTryIt>

```haskell

```

```text
4
```

</HaskellTryIt>

**Hand trace:** `maybe 0 (+1) (Just 3) = (+1) 3 = 3 + 1 = 4`.

<HaskellTryIt>


</HaskellTryIt>

**Hand trace:** `maybe 0 (+1) Nothing = 0`; the transform is ignored.

### Variation: different result type

<HaskellTryIt>

## 30. Choosing a representation and repairing errors

| Representation | Information and decision |
|---|---|
| `Maybe a` | Zero or one payload; caller matches, defaults, transforms or propagates |
| `error "message"` | That path returns no ordinary result; exception handling needs a suitable surrounding effectful layer |
| A default `a` | Missing and present-default become indistinguishable |
| `[a]` as optional | Permits many values; the at-most-one rule needs separate enforcement |

A `Maybe` result type does not prove totality: a body can still loop, call `error` or omit a pattern. These definitions handle their stated failure domains explicitly.

| Mistake | Key GHC diagnostic or consequence | Repair |
|---|---|---|
| `Just 3 + 1 :: Maybe Int` | `No instance for (Num (Maybe Int))` | Map or match |
| `f :: Maybe Int; f = 3` | `No instance for (Num (Maybe Int))` | Return `Just 3` |
| An `Int` branch and a `String` branch | `Couldn't match type` | Choose one result type |
| Only a `Just` equation | `-Wincomplete-patterns`: `Pattern match(es) are non-exhaustive` | Add absence |
| `print Nothing` | Unresolved payload `Show` constraint | Annotate `Nothing :: Maybe Int` |
| `fromMaybe` without its import | `Variable not in scope` | Add `import Data.Maybe (fromMaybe)` inside the program |

Choosing `fromMaybe 0` for an optional count is a policy decision: does unknown really mean zero? Keep the wrapper if that distinction still matters.

## Summary

<Callout type="key" title="Remember">

Design the failure cases before calculating. Present zero and empty payloads remain `Just`. `maybe` transforms or defaults, `fromMaybe` defaults without transformation, and `catMaybes`/`mapMaybe` collect successes. Mapping preserves a wrapper; chaining passes a payload to a function already returning an optional result. Every consumer needs an absence policy.

</Callout>

## Check your understanding

<CheckQuestions>

<CheckQuestion question="Why does safeTail [4] return Just []?">

A cons has a tail even when that tail is empty. Only an empty input has no tail to return.

</CheckQuestion>

<CheckQuestion question="How does maybe differ from fromMaybe?">

`maybe d f` transforms a present payload with `f`; `fromMaybe d` returns that payload unchanged.

</CheckQuestion>

<CheckQuestion question="How does mapMaybe differ from map?">

It requires optional results, drops failures and unwraps successes. `map` keeps one result per input.

</CheckQuestion>

<CheckQuestion question="Why can mapping produce nested Maybe?">

Mapping adds a wrapper around a function result that may already be optional. Bind returns that optional result directly.

</CheckQuestion>

<CheckQuestion question="Does Maybe force exhaustive matching?">

No. It makes absence visible in the type. Cover both constructors and use incomplete-pattern warnings.

</CheckQuestion>

</CheckQuestions>
