## 1. Order laws and compiler checks

An order places values before, equal to, or after each other. A lawful total order is reflexive, total, antisymmetric and transitive. Antisymmetry says that values ordered both ways must be equal. Consistency connects compare and the relational methods to Eq. Ord has Eq as a superclass, but GHC checks method types and superclass availability, not these behavioural laws.

State the domain: use defined values whose comparisons terminate and whose component instances obey the laws. A derived instance delegates to fields; it cannot repair an unlawful field instance. Double NaN breaks reflexive equality and ordinary ordering. Undefined values and some infinite structures may not yield a comparison. These exceptions also affect derived wrappers.

**Template.** x, y and z range over the stated domain. Each implication is tested by negating its premises or accepting its conclusion. The laws concern results, not types.

```text
reflexive: x <= x
total: x <= y || y <= x
antisymmetric: if x <= y and y <= x, then x == y
transitive: if x <= y and y <= z, then x <= z
consistent: compare x y == EQ iff x == y
consistent: compare x y == LT iff x < y
consistent: compare x y == GT iff x > y
```

### Worked variation: Increasing integers


<HaskellTryIt>

```haskell
laws :: Ord a => a -> a -> a -> [Bool]
laws x y z =
  [ x <= x
  , x <= y || y <= x
  , not (x <= y && y <= x) || x == y
  , not (x <= y && y <= z) || x <= z
  , (compare x y == EQ) == (x == y)
  , (compare x y == LT) == (x < y)
  , (compare x y == GT) == (x > y)
  ]

main :: IO ()
main = print (laws (1 :: Int) 2 3)
```

```text
[True,True,True,True,True,True,True]
```

</HaskellTryIt>

The forward comparisons hold. The reverse premise of antisymmetry is false; transitivity concludes 1 &lt;= 3. Compare gives LT, agreeing with equality and both strict relations.

## 2. compare: methods without arithmetic

compare returns LT, EQ or GT, not a numeric difference. The two arguments have the same type. Ord permits these methods without Num. For a lawful instance, min and max return a value equal to one argument. When distinct representations compare equal, do not assume a universal promise about which representation survives a tie.

**Template.** a is the shared operand type; x and y are the two values. compare returns Ordering, while min and max return a value of type a.

```text
compare :: Ord a => a -> a -> Ordering
case compare x y of LT -> before; EQ -> tied; GT -> after
```

### Worked variation: Unequal integers


<HaskellTryIt>

```haskell
main :: IO ()

```

```text
LT
```

</HaskellTryIt>

### Worked variation: A character tie


<HaskellTryIt>

```haskell

```

```text

```

</HaskellTryIt>

Both arguments are q. Equality gives EQ for compare and a q value for either extremum.

<HaskellTryIt>

```haskell

main = print (compare "zebra" "ant")
```

```text

```

</HaskellTryIt>

The first characters decide: z follows a. No later character changes that decision.

## 5. Lexicographic decisions and ties

Lexicographic means compare corresponding components from the left and stop at the first difference. For lists, a proper prefix precedes the longer list. Tuples move to the next field only after a tie. This is neither length-first ordering nor adding field comparisons. Comparing projected keys can deliberately change a question's comparison policy without writing an instance.

**Template.** key1 and key2 extract the first and second comparison fields. Compare key1 first and use key2 only for a tie.

```text
compare (key1 x, key2 x) (key1 y, key2 y)
compare [x1,x2] [y1,y2] -- first unequal position decides
```

### Worked variation: A proper prefix


<HaskellTryIt>

```haskell
main :: IO ()
main = print (compare ([2] :: [Int]) [2,0])
```

```text
LT
```

</HaskellTryIt>

The first elements tie, then the left list ends. A proper prefix precedes the longer list.

### Worked variation: A final tuple field decides


<HaskellTryIt>

```haskell
main :: IO ()
main = print (compare (4 :: Int,"Ada",False) (4,"Ada",True))
```

```text
LT
```

</HaskellTryIt>

The numbers and names tie. False precedes True, so the final Bool decides.

### Worked variation: An early field dominates


<HaskellTryIt>

```haskell
main :: IO ()
main = print (compare (2 :: Int,"z") (3,"a"))
```

```text
LT
```

</HaskellTryIt>

2 precedes 3. The later string cannot reverse the earlier decision.

## 6. Show and Read round trips

Show produces Haskell-style text. Read consumes text using the instance selected by its result type. These are independent classes with no superclass link. The intended value round trip is read (show x) at x's type, with compatible instances and a readable representation. It does not imply show (read s) reproduces the spelling or whitespace of s. Print on a String adds quotes and escapes.

A custom Show may not be readable. Equality cannot certify a NaN round trip because NaN is unequal to itself. Partial values may not have a complete printable representation. Do not infer a universal inverse law merely from the two class names.

**Template.** value is the original value; TargetType must be its type. Show produces String, and the target selects the Read instance.

```text
show :: Show a => a -> String
read :: Read a => String -> a
read (show value) :: TargetType
```

### Worked variation: A negative integer


<HaskellTryIt>

```haskell
main :: IO ()
main = print (read (show (-12 :: Integer)) :: Integer)
```

```text
-12
```

</HaskellTryIt>

Show produces the text -12; Integer Read reconstructs the same number.

### Worked variation: A list of constructors


<HaskellTryIt>

```haskell

main = print (read (show ([True,False] :: [Bool])) :: [Bool])
```

```text
[True,False]
```

</HaskellTryIt>

The brackets, comma and constructor spellings are readable list syntax.

### Worked variation: A string with a space


<HaskellTryIt>

```haskell
main :: IO ()
main = print (read (show "a b") :: String)
```

```text
"a b"
```

</HaskellTryIt>

Show adds the Haskell syntax quotes needed by Read String. Print quotes the reconstructed String again.

## 7. Read selected by context

The result type chooses the Read instance. It can come from an expression annotation, a typed consuming operand, a function result signature, or a containing structure. Print alone adds Show without choosing a particular Read instance. Numeric defaulting resolves some numeric constraints; it does not mean every ambiguous read becomes Integer.

**Template.** text is a String, T is the chosen result type, and consumer is a function whose input fixes T. The result signature of f can provide the same context.

```text
read text :: T
consumer (read text) -- consumer :: T -> Result
f :: String -> T
f s = read s
```

### Worked variation: Expression annotation


<HaskellTryIt>


```text
18
```

</HaskellTryIt>

The annotation selects Integer Read.


```text

```

</HaskellTryIt>


</HaskellTryIt>

## 8. Malformed input and complete consumption

A fixed result type prevents ambiguity but does not make malformed text valid. Read expects one complete readable value, permitting surrounding whitespace. Trailing non-whitespace causes failure. Use the already taught readMaybe when failure is ordinary data; here the question is which class and syntax the parser needs, not how to build another safe parser.

**Template.** text is the entire input String. T is the selected parsed type; Maybe T distinguishes a successful result from failure.

```
readMaybe text :: Maybe T
-- import Text.Read (readMaybe)
-- require a unique complete parse at the chosen result type
```

## 13. Range forms and enumeration boundaries

A range can return its endpoint and stop without returning a successor beyond it. This differs from explicitly asking for succ at the last value. In stepped notation the second element sets the step; it is not an upper bound. A zero step can repeat forever when the bound permits the first value. Integer has Enum without an upper endpoint.

A guarded step can test the boundary before calling the method. The guard below needs Ord, Bounded and Enum. Safety relies on these instances describing the same intended sequence; their class constraints alone do not prove that relationship.

**Template.** next takes one value x. Its guard uses the upper bound of that same type. In two-value ranges y is the endpoint; in stepped ranges it is the second value and z is the endpoint.

```text
next :: (Ord a, Enum a, Bounded a) => a -> Maybe a
next x | x < maxBound = Just (succ x)
       | otherwise = Nothing
[x..y]     -- enumFromTo x y
[x,y..z]   -- enumFromThenTo x y z
[x..]      -- enumFrom x
[x,y..]    -- enumFromThen x y
```

## 16. Choosing Num from a method

Addition and integer literals need Num. Num has no Eq, Ord or Show superclass. Do not add such requirements merely because an input is numeric.

**Template.** x is the input, of type a. The body method selects the input requirement. Where b appears, it is a separately chosen result type rather than another name for a.

```text

twice x = x + x
```

The following table gives **immediate** superclasses. Following the requirements transitively supplies inherited methods. Ord also has Eq as a superclass.

| Class | Immediate superclasses | Representative method |
| --- | --- | --- |
| Num | none | (+) |
| Real | Num, Ord | toRational |
| Integral | Real, Enum | div, toInteger |
| Fractional | Num | (/), recip |
| RealFrac | Real, Fractional | properFraction |
| Floating | Fractional | sqrt, pi |
| RealFloat | RealFrac, Floating | isNaN, floatRadix |

There is no superclass path from Num to Eq or Show, nor from Fractional to Ord. Integral and Fractional are separate branches; the class system does not declare them mutually exclusive. Ordinary Int and Integer are Integral, while Float and Double inhabit both the RealFrac and Floating branches. Rational has RealFrac without Floating; Complex Double has Floating without RealFrac. These relationships are requirements on operations, not guarantees of all mathematical laws for all payloads.

## 21. RealFrac's properFraction and its two outputs

properFraction returns a pair: an integral part selected by context and a fractional remainder of the original input type. The whole part truncates towards zero, so a negative input has a negative or zero remainder. The reconstruction is fromIntegral wholePart + remainder, within the chosen type's numeric limitations. RealFrac supplies Fractional and Real; it does not fix the integral result to Int. ## 24. Context versus numeric defaulting

Inference uses the program's constraints and surrounding types. Defaulting is a later rule that chooses a concrete numeric type for certain otherwise unresolved constrained variables. Under ordinary standard numeric defaulting, Integer is tried before Double. A variable constrained by Fractional cannot default to Integer, so an ordinary fractional expression can default to Double. Defaulting is not inspection of the input text and does not make a bare Read/Show ambiguity disappear.

**Template.** First propagate context, then collect constraints, then ask whether standard numeric defaulting applies. Here a is the unresolved numeric type.

```text
read "5" + 1    -- Read a, Num a; printing also needs Show a
read "5" / 2    -- Read a, Fractional a; printing also needs Show a
consumer (read "5") -- a fixed consumer can select a without defaulting
```

### Worked variation: a whole-number default

The body contains Num, Read and Show requirements with no concrete consumer type.


<HaskellTryIt>


</HaskellTryIt>
