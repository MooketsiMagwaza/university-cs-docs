## 1. Type constructors and class relationships

`Int` is a type of values. `Maybe` needs a type argument before it describes values: `Maybe Int`. `Either` needs two; fixing its error type gives `Either String`, which still needs the success type. A **kind** describes the type arguments a constructor expects; `Type` means a type of ordinary values here.

**Template:** match `f a` by choosing a one-argument constructor f and then its payload type a.

| Expression | Kind / role |
|---|---|
| `Int`, `Maybe Int`, `Either String Int` | `Type`: complete types |
| `Maybe`, `[]`, `Either String` | `Type -> Type`: one type argument remains |
| `Either` | `Type -> Type -> Type`: two arguments remain |
| `Just`, `Left`, `Right` | Value constructors, used in expressions |

These interfaces already exist; read them rather than redeclaring them. A superclass supplies operations that the subclass must also support.

```haskell
class Functor f where
  fmap :: (a -> b) -> f a -> f b

class Functor f => Applicative f where
  pure :: a -> f a
  (<*>) :: f (a -> b) -> f a -> f b

class Applicative m => Monad m where
  (>>=) :: m a -> (a -> m b) -> m b
```

Every Monad must also have compatible Applicative and Functor instances; the reverse implications do not follow. The letters f and m range over constructors, not just Maybe.

Haskell Functor is not a parameterised module. A module functor in languages supporting it takes modules as parameters; a higher-order function takes functions as values. See [Modules and Abstraction Practice](/docs/sem3/csi243/08-modules-types/notes/modules-and-abstraction-practice) for the module terminology. This generic definition instantiates at three constructors:

## 2. Generic mapping and its infix spelling

`fmap` changes payloads while retaining the outer context. The instance identifies those payloads: each element for lists, a present value for Maybe, and the right side only for Either e. This compares the general abstraction across types rather than repeating safe-function design.

**Template:** `fmap transform value`, equivalently `transform <$> value`. Substitute into `(a -> b) -> f a -> f b`. The function input must match a; the result is still in f, now with payload b. `<$>` is infix fmap, not application of a contextual function.

### Variation: list type change

Change numeric elements into text.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (show <$> [2,5 :: Int])
```

```text
["2","5"]
```

</HaskellTryIt>

**Walk-through:** Each number is shown separately. The output remains a two-element list.

### Variation: empty list

Use the empty boundary.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap show ([] :: [Int]))
```

```text
[]
```

</HaskellTryIt>

**Walk-through:** There is no element to transform; the result has type [String].

### Variation: nested list payloads

Each string is one list element.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (length <$> ["ab","","cat"])
```

```text
[2,0,3]
```

</HaskellTryIt>

**Walk-through:** The three payload lengths are 2, 0 and 3, in the original order.

### Variation: optional pair

Transform a pair to its first field.

<HaskellTryIt>



</HaskellTryIt>

**Walk-through:** The payload changes from (Bool,String) to Bool.

### Variation: absent pair


```text

```

</HaskellTryIt>

**Walk-through:** Reverse sees the entire list, not each individual integer.

### Variation: right-side mapping

Fix the error type as String.

<HaskellTryIt>

```haskell

```

```text

```

</HaskellTryIt>


## 3. The Functor identity law

Mapping with a function that changes nothing must leave the entire value unchanged. GHC checks an instance's method types, not whether it keeps this promise.

**Template:** `fmap id value = value`, equivalently `fmap id = id`. The following equality tests need Eq only for testing; Functor itself does not require Eq. Tests on finite total data provide evidence, not a universal proof.

### Variation: list identity

Repeated elements must remain repeated.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap id [3,3,1 :: Int] == [3,3,1])
```

```text
True
```

</HaskellTryIt>

**Walk-through:** Id retains each occurrence, position and list length.

### Variation: absent identity

Check the empty-context boundary.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap id (Nothing :: Maybe Int) == Nothing)
```

```text
True
```

</HaskellTryIt>

**Walk-through:** Both sides are Nothing; mapping must not invent a payload.

### Variation: error identity

Check that a reason is not changed.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap id (Left "bad" :: Either String Int) == Left "bad")
```

```text
True
```

</HaskellTryIt>

**Walk-through:** Both sides carry exactly the same left reason.

## 4. The Functor composition law

Mapping twice must agree with mapping the combined function once. `g . h` applies h first, then g; this allows reliable refactoring.

**Template:** `fmap (g . h) value = fmap g (fmap h value)`, where h has type a -> b, g has type b -> c, and value has type f a. Both results have type f c.

### Variation: numeric composition

Compare one pass with two passes.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap ((+1) . (*2)) [1,3 :: Int] == fmap (+1) (fmap (*2) [1,3]))
```

```text
True
```

</HaskellTryIt>

**Walk-through:** Both sides give [3,7]: double first, then increment.

### Variation: type-changing composition

The intermediate payload is String.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap (length . show) (Just (12 :: Int)) == fmap length (fmap show (Just (12 :: Int))))
```

```text
True
```

</HaskellTryIt>

**Walk-through:** Show makes "12", then length makes 2; both sides give Just 2.

### Variation: composition on failure

Neither ordinary function receives an argument.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fmap (length . show) (Left "bad" :: Either String Int) == fmap length (fmap show (Left "bad" :: Either String Int)))
```

```text
True
```

</HaskellTryIt>

**Walk-through:** Both routes retain Left "bad" at the final right type Int.

## 5. A hand-written Tree Functor

A tree can store a payload at each node while leaves mark empty branches. Mapping must transform every payload and recur down both subtrees, preserving branch positions. It does not mirror, rebalance or sort.

**Template:** put the constructor awaiting its payload type in the instance head, write an equation for every data constructor, recur through recursive fields and transform payload fields.

```haskell
data Tree a = Leaf | Node (Tree a) a (Tree a) deriving (Show, Eq)

instance Functor Tree where
  fmap _ Leaf = Leaf
  fmap f (Node l x r) = Node (fmap f l) (f x) (fmap f r)
```

### Variation: empty tree

A Leaf has no payload to transform.

<HaskellTryIt>

```haskell
data Tree a = Leaf | Node (Tree a) a (Tree a) deriving (Show, Eq)

instance Functor Tree where
  fmap _ Leaf = Leaf
  fmap f (Node l x r) = Node (fmap f l) (f x) (fmap f r)

main :: IO ()
main = print (fmap length (Leaf :: Tree String))
```

```text
Leaf
```

</HaskellTryIt>

**Walk-through:** The Leaf equation retains the empty branch at type Tree Int.

### Variation: one node changes type

Map from text lengths to Int.

<HaskellTryIt>

```haskell
data Tree a = Leaf | Node (Tree a) a (Tree a) deriving (Show, Eq)

instance Functor Tree where
  fmap _ Leaf = Leaf
  fmap f (Node l x r) = Node (fmap f l) (f x) (fmap f r)

main :: IO ()
main = print (fmap length (Node Leaf "cat" Leaf))
```

```text
Node Leaf 3 Leaf
```

</HaskellTryIt>

**Walk-through:** Both recursive Leaf calls stay Leaf; the centre payload becomes 3.

### Variation: asymmetric shape and laws

An unequal branch shape exposes missed recursion or swapped fields.

<HaskellTryIt>

```haskell
data Tree a = Leaf | Node (Tree a) a (Tree a) deriving (Show, Eq)

instance Functor Tree where
  fmap _ Leaf = Leaf
  fmap f (Node l x r) = Node (fmap f l) (f x) (fmap f r)

t :: Tree Int
t = Node (Node Leaf 2 Leaf) 4 Leaf

main :: IO ()
main = print ((fmap (+1) t, fmap id t == t, fmap ((+1) . (*2)) t == fmap (+1) (fmap (*2) t)))
```

```text
(Node (Node Leaf 3 Leaf) 5 Leaf,True,True)
```

</HaskellTryIt>

**Walk-through:** The left child 2 becomes 3 and root 4 becomes 5. The two law checks agree on this asymmetric shape.

For all finite total trees, justify the laws by structural induction. Identity returns Leaf at the base case. At `Node l x r`, the subtree identity hypotheses and `id x = x` reconstruct the same node. For composition, both sides return Leaf at the base. At a node the composition hypotheses equate the two recursive fields, and `(g . h) x = g (h x)` equates the centre payload; the complete constructors agree.

See [Proofs of Programs I](/docs/sem3/csi243/10-reasoning-revision/notes/proofs-of-programs-i) for the proof layout. This Functor instance does not invent pure, application or bind: those need further compatible choices of behaviour.

## 6. Pure: introduce a successful context

`pure` puts an ordinary value into a chosen Applicative context: one possibility for lists, presence for Maybe, success for Either. It does not validate the payload or recover an existing failure.

**Template:** `pure payload :: Context PayloadType`. The result annotation or surrounding expression fixes f in `pure :: Applicative f => a -> f a`. If the payload is itself contextual, pure adds another layer.

Each runnable variation uses `pure (const payload) <*> seed`, where seed is one successful unit value (`[()]`, `Just ()` or `Right ()`). Here `const payload` ignores its unit argument and returns payload. This gives the same introduction as `pure payload` by the Applicative laws; the concrete seed makes the chosen context visible. Application itself is explained in Sections 7 to 9.

### Variation: singleton possibility

Choose the list instance.

<HaskellTryIt>

```haskell

main = print (pure (const (7 :: Int)) <*> [()] :: [Int])
```

```text
[7]
```

</HaskellTryIt>

**Walk-through:** List pure introduces exactly one alternative.

### Variation: one empty payload

Distinguish one empty list from no alternatives.

<HaskellTryIt>

```haskell

```

```text

```

</HaskellTryIt>

**Walk-through:** The outer singleton contains the entire empty payload.

### Variation: text possibility

A string becomes one alternative.

<HaskellTryIt>



</HaskellTryIt>

### Variation: Either success

<HaskellTryIt>

### Variation: Either text success

## 7. Maybe application: a contextual function

Mapping takes an ordinary function; application takes a function already inside the context and an argument in that same context. For Maybe both must be present.

**Template:** `wrappedFunction <*> wrappedArgument` has specialised type `Maybe (a -> b) -> Maybe a -> Maybe b`. The equations are `Nothing <*> _ = Nothing` and `Just f <*> value = fmap f value`. Application associates to the left: `u <*> v <*> w` means `(u <*> v) <*> w`.

### Variation: present function and argument

The first payload is a function.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (Just (*3) <*> Just (4 :: Int))
```

```text
Just 12
```

</HaskellTryIt>

**Walk-through:** The instance applies *3 to 4 and retains the resulting 12 inside Just.

### Variation: missing function

Only the function position is absent.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((Nothing :: Maybe (Int -> Int)) <*> Just 4)
```

```text
Nothing
```

</HaskellTryIt>

**Walk-through:** The first equation returns Nothing without needing an argument.

### Variation: missing argument

The ordinary function exists inside Just.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (Just length <*> (Nothing :: Maybe String))
```

```text
Nothing
```

</HaskellTryIt>

**Walk-through:** The second equation maps length over Nothing, still giving Nothing.

## 8. Either application: which failure survives?

For Either e both operands share one fixed error type. Application preserves the first left result encountered by its left-to-right combination structure. It does not accumulate all errors or promise eager evaluation of independent arguments.

**Template:** `Left e <*> _ = Left e`; `Right f <*> value = fmap f value`. A left function result wins; if that position succeeds, an argument error wins instead.

### Variation: both successful

Wrap the ordinary function with Right.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((Right (*2) :: Either String (Int -> Int)) <*> Right 6)
```

## 9. List application: the Cartesian product

Lists represent alternatives here. Apply the first function to every argument, then the next function to every argument, in order. Cartesian application means every combination is included; it differs from pairing positions with zipWith.

**Template:** `fs <*> xs = [f x | f <- fs, x <- xs]`. The function generator is outermost. On finite lists the number of results is `length fs * length xs`.

## 10. Lift binary and ternary functions

A curried function takes one argument and returns a function waiting for the rest. Mapping a binary function over the first context produces contextual functions ready for application. Only print the fully applied result: intermediate payload functions have no Show instance.

**Templates:** `combine <$> first <*> second`, equivalently `pure combine <*> first <*> second` or `liftA2 combine first second` from Control.Applicative. The runnable blocks define these helpers directly with the same general signatures, so each program is self-contained. For three arguments use `combine3 <$> first <*> second <*> third` or `liftA3 combine3 first second third`.

For `combine :: a -> b -> c`, mapping gives `f (b -> c)` and the next application gives `f c`. For `combine3 :: a -> b -> c -> d`, the intermediate types are `f (b -> c -> d)`, `f (c -> d)` and `f d`. Independent inputs can be specified without inspecting each other's successful payloads.

## 11. Applicative laws and compatible mapping

An Applicative instance needs coherent behaviour as well as correct method types. Its laws let us regroup contextual application without changing results. They say nothing about automatic parallel execution.

**Law templates:**

- Identity: `pure id <*> v = v`.
- Composition: `pure (.) <*> u <*> v <*> w = u <*> (v <*> w)`.
- Homomorphism: `pure f <*> pure x = pure (f x)`.
- Interchange: `u <*> pure y = pure ($ y) <*> u`.
- Compatibility: `fmap f x = pure f <*> x`.

For composition, u has type `f (b -> c)`, v has type `f (a -> b)` and w has type `f a`. One constructor f is used throughout. Each variation checks all five laws in this order. Compare only fully applied results, never the functions themselves. In homomorphism and interchange the programs spell the pure values using their concrete forms (Just, Right or singleton lists). These are the same law instances, with successful constructors written explicitly.

### Variation: Maybe law checks

Change the context while retaining all five law shapes.

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  let u = Just (+1)
      v = Just (*2)
      w = Just 3 :: Maybe Int
  print ((pure id <*> w) == w)
  print ((pure (.) <*> u <*> v <*> w) == (u <*> (v <*> w)))
  print ((pure (+1) <*> Just 3 :: Maybe Int) == Just 4)
  print ((u <*> Just 4) == (pure ($ 4) <*> u))
  print (fmap (+1) w == (pure (+1) <*> w))
```

```text
True
True
True
True
True
```

</HaskellTryIt>

**Walk-through:** Composition gives Just 7 on both sides, interchange gives Just 5, and homomorphism gives Just 4. Identity and compatibility retain equal contexts and payloads.

## 12. The exact Test1 Either Fibonacci expression

Test1 09 uses Fibonacci with an explicit negative-input reason. Here we explain its contextual combination; the algorithm design and accumulator alternative belong to [Designing Recursive Numeric Algorithms](/docs/sem3/csi243/05-recursion/notes/numeric-recursion-by-example).

**Template:** combine two `Either String Integer` results by mapping ordinary addition over the first and applying the resulting contextual partial function to the second. The exact source expression is `(+) <$> fibonacci (n - 1) <*> fibonacci (n - 2)`.

### Variation: negative boundary

Retain the exact supplied failure message.

<HaskellTryIt>

```haskell

fibonacci n
  | n < 0 = Left "fibonacci requires a non-negative index"
  | n == 0 = Right 0
  | n == 1 = Right 1
  | otherwise = (+) <$> fibonacci (n - 1) <*> fibonacci (n - 2)

main :: IO ()
main = print (fibonacci (-1))
```

```text
Left "fibonacci requires a non-negative index"
```

</HaskellTryIt>

**Walk-through:** The first guard succeeds; neither recursive call is reached.

### Variation: both bases

Test zero and one together.

<HaskellTryIt>

```haskell

  | n < 0 = Left "fibonacci requires a non-negative index"
  | n == 0 = Right 0
  | n == 1 = Right 1
  | otherwise = (+) <$> fibonacci (n - 1) <*> fibonacci (n - 2)

```


</HaskellTryIt>

**Walk-through:** Zero matches the second guard and one the third; neither uses application.

### Variation: recursive combination

Use a small non-base value.

<HaskellTryIt>

```haskell
fibonacci :: Integer -> Either String Integer
fibonacci n
  | n < 0 = Left "fibonacci requires a non-negative index"
  | n == 0 = Right 0
  | n == 1 = Right 1
  | otherwise = (+) <$> fibonacci (n - 1) <*> fibonacci (n - 2)

main :: IO ()
main = print (fibonacci 4)
```

```text
Right 3
```

</HaskellTryIt>

**Walk-through:** At 2 combine Right 1 and Right 0 to get Right 1. At 3 combine Right 1 and Right 1 to get Right 2. At 4 combine Right 2 and Right 1 to get Right 3.

Derive the recursive expression in order:

| Part | Type |
|---|---|
| `(+)` at this use | `Integer -> Integer -> Integer` |
| `fibonacci (n - 1)` | `Either String Integer` |
| `(+) <$> fibonacci (n - 1)` | `Either String (Integer -> Integer)` |
| `fibonacci (n - 2)` | `Either String Integer` |
| After application | `Either String Integer` |

Both recursive arguments are chosen from n; the second is not selected by inspecting the first successful Fibonacci value. On non-negative input the base guards prevent calls below zero: the recursive case begins only at n at least 2. Thus normal valid calls do not demonstrate internal error priority. If two independent subresults were Left "first" and Left "second", this same combination would retain Left "first", as Section 8 demonstrates. That is a property of Either application, not an error encountered by fibonacci 4.

Applicative spelling does not remove repeated subproblems or guarantee concurrent computation.

## Summary

<Callout type="key" title="Remember">

Functor maps an ordinary function over a context and obeys identity and composition. A Tree mapping preserves branches and transforms every payload. Applicative adds pure and application: lift a curried function and supply contextual arguments. Maybe requires presence, Either preserves the first left reason, and lists enumerate every combination in function-first order. The Test1 Fibonacci expression combines independently specified recursive results; its wrappers remain present in every intermediate type.

</Callout>
