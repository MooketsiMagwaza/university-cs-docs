Independent inputs can be combined without seeing their payloads. A dependent computation instead uses a successful payload to decide the next contextual step. Lists expose this distinction particularly clearly: a value may choose not only the next answer but how many answers exist.

## 1. Bind: a payload chooses the next context

Bind passes a successful payload to a function that already returns a contextual result. Unlike mapping, it does not put another outer wrapper around that returned result. The instance determines absence, errors, branching or effects. Monad has Applicative as a superclass, and Applicative has Functor; bind is the extra operation that can use the preceding payload to choose the next computation.

**Template:** `value >>= next` has type `Monad m => m a -> (a -> m b) -> m b`. Match the same constructor m on both sides of the continuation, its input with a and its final payload with b. The reverse-argument spelling is `next =<< value`. Return and pure introduce the same successful value for the standard instances here; neither means exit the enclosing function.

### Variation: generic Maybe instantiation

The continuation returns a list as its optional payload.

<HaskellTryIt>

```haskell
follow :: Monad m => (a -> m b) -> m a -> m b
follow next value = value >>= next

main :: IO ()
main = print (follow (\n -> Just [n,n+1]) (Just (3 :: Int)))
```

```text
Just [3,4]
```

</HaskellTryIt>

**Walk-through:** Here m = Maybe, a = Int, b = [Int]. The continuation returns the final wrapper directly.

### Variation: generic Either instantiation

Change both payload types while retaining the error type.

<HaskellTryIt>

```haskell
follow :: Monad m => (a -> m b) -> m a -> m b
follow next value = value >>= next

main :: IO ()
main = print (follow (\s -> if null s then Left "empty" else Right (length s)) (Right "cat" :: Either String String))
```

```text
Right 3
```

</HaskellTryIt>

**Walk-through:** Here m = Either String, a = String and b = Int. The successful text selects the length computation.

### Variation: generic list instantiation

Each payload chooses several possible results.

<HaskellTryIt>

```haskell
follow :: Monad m => (a -> m b) -> m a -> m b
follow next value = value >>= next

main :: IO ()
main = print (follow (\n -> [n,n*10]) [1,2 :: Int])
```

```text
[1,10,2,20]
```

</HaskellTryIt>

**Walk-through:** Here m = [], a = b = Int. The branch for 1 precedes the branch for 2.

### Variation: reverse bind with absence

Put the continuation before its source.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((\n -> Just (n+1)) =<< (Nothing :: Maybe Int))
```

```text
Nothing
```

</HaskellTryIt>

**Walk-through:** The reverse spelling still preserves absence without calling the continuation.

### Variation: reverse bind with an error

Fix the same error type on both steps.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((\n -> Right (n*2)) =<< (Left "input" :: Either String Int))
```

```text
Left "input"
```

</HaskellTryIt>

**Walk-through:** The existing reason is returned even though the continuation would succeed.

### Variation: reverse bind with branches

Only the written argument order changes.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((\n -> [n,n+1]) =<< [2,4 :: Int])
```

```text
[2,3,4,5]
```

</HaskellTryIt>

**Walk-through:** The branch for 2 is [2,3], followed by the branch for 4 as [4,5].

## 2. List bind is ordered branching

For a list, bind applies the continuation to every element and joins its result lists. A branch can produce zero, one or many results. An empty branch removes that branch only; later source alternatives still get their own turn.

**Template:** `xs >>= next = concatMap next xs`, equivalently `[y | x <- xs, y <- next x]`. Its equations are `[] >>= next = []` and `(x:xs) >>= next = next x ++ (xs >>= next)`. Keep input order and each branch's output order.

### Variation: variable branch sizes

Different source values choose differently sized results.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ([1,3 :: Int] >>= (\n -> [1..n]))
```

```text
[1,1,2,3]
```

</HaskellTryIt>

**Walk-through:** For 1 emit [1]; for 3 emit [1,2,3]; append in that order. The two 1s remain separate occurrences.

### Variation: one branch disappears

The failed alternative does not abort the entire list.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ([0,2,3 :: Int] >>= (\n -> if even n then [n,n+1] else []))
```

```text
[0,1,2,3]
```

</HaskellTryIt>

**Walk-through:** Zero gives [0,1], two gives [2,3], and odd three gives []. Earlier successful branches remain.

### Variation: empty source

No continuation call is made.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (([] :: [Int]) >>= (\n -> [n,n+1]))
```

```text
[]
```

</HaskellTryIt>

**Walk-through:** The empty-source equation returns []; no seed value or placeholder is created.

## 3. Mapping a contextual function, bind and join

If next returns a context, fmap retains an extra outer context: `fmap next value :: m (m b)`. Bind returns `m b` by combining the two contextual layers according to the instance. This is not arbitrary unwrapping: a list still has many answers, an error still has its reason, and a missing result still has no payload.

**Templates:** `value >>= next = join (fmap next value)` and `join nested = nested >>= id`. The library join is in Control.Monad and has type `Monad m => m (m a) -> m a`. The small definition below displays the same general operation without needing an import.

### Variation: nested Maybe

Compare mapping, binding and flattening the mapped result.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

next :: Int -> Maybe Int
next n = if n > 3 then Just n else Nothing

main :: IO ()
main = print ((fmap next (Just 2), Just 2 >>= next, flatten (fmap next (Just 2))))
```

```text
(Just Nothing,Nothing,Nothing)
```

</HaskellTryIt>

**Walk-through:** Next rejects 2. Mapping wraps that Nothing in Just; bind and flatten return Nothing directly.

### Variation: nested Either

An outer success may contain an inner failure.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

next :: Int -> Either String Int
next n = if n > 3 then Right n else Left "small"

main :: IO ()
main = print ((fmap next (Right 2 :: Either String Int), (Right 2 :: Either String Int) >>= next, flatten (fmap next (Right 2 :: Either String Int))))
```

```text
(Right (Left "small"),Left "small",Left "small")
```

</HaskellTryIt>

**Walk-through:** Mapping wraps the inner reason as a right payload. Bind and flatten expose that failure in the one remaining Either layer.

### Variation: nested lists

A list continuation produces a list for every source element.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

next :: Int -> [Int]
next n = [n,n+10]

main :: IO ()
main = print ((fmap next [1,2], [1,2] >>= next, flatten (fmap next [1,2])))
```

```text
([[1,11],[2,12]],[1,11,2,12],[1,11,2,12])
```

</HaskellTryIt>

**Walk-through:** Map retains the two branch lists; bind and flatten append them in order.

### Variation: flatten outer absence

There is no inner result to inspect.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

main :: IO ()
main = print (flatten (Nothing :: Maybe (Maybe Int)))
```

```text
Nothing
```

</HaskellTryIt>

**Walk-through:** Outer Nothing makes bind return Nothing.

### Variation: flatten nested success

Both layers contain successful payloads.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

main :: IO ()
main = print (flatten (Just (Just (4 :: Int))))
```

```text
Just 4
```

</HaskellTryIt>

**Walk-through:** Bind supplies the inner Just 4 to id, which returns it directly.

### Variation: flatten outer error

An outer error wins without an inner computation.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

main :: IO ()
main = print (flatten (Left "outer" :: Either String (Either String Int)))
```

```text
Left "outer"
```

</HaskellTryIt>

**Walk-through:** Bind propagates the outer Left unchanged.

### Variation: flatten nested Either success

Both Either layers are right.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

main :: IO ()
main = print (flatten (Right (Right (4 :: Int)) :: Either String (Either String Int)))
```

```text
Right 4
```

</HaskellTryIt>

**Walk-through:** The outer bind supplies Right 4 to id; exactly one layer remains.

### Variation: flatten empty outer list

There are no branch lists.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

main :: IO ()
main = print (flatten ([] :: [[Int]]))
```

```text
[]
```

</HaskellTryIt>

**Walk-through:** The empty source gives an empty result.

### Variation: flatten empty inner lists

There are branches but none produces a payload.

<HaskellTryIt>

```haskell
flatten :: Monad m => m (m a) -> m a
flatten nested = nested >>= id

main :: IO ()
main = print (flatten [[],[] :: [Int]])
```

```text
[]
```

</HaskellTryIt>

**Walk-through:** Each empty list contributes nothing; concatenation gives [].

## 4. Four independent-versus-dependent decisions

Use Applicative when contextual inputs are specified independently. Use bind when a successful payload selects the next contextual computation. A dependency in the final ordinary arithmetic alone does not require bind: a lifted function can calculate from all successful arguments.

**Decision template:** write the required inputs first. If the second can be written without the first payload, use `combine <$> first <*> second`. If the second is `next x` for an x obtained from first, use `first >>= \x -> next x`. In each contrast below, independent and dependent functions answer different specifications; they are not interchangeable rewrites.

### Contrast: two fields versus a selected lookup

Two supplied optional fields can be paired independently. Selecting a table entry by the first payload needs bind. The lookup operation itself is prerequisite material.

### Variation: both fields exist

Use an existing lookup key.

<HaskellTryIt>

```haskell
independent :: Maybe String -> Maybe Int -> Maybe (String,Int)
independent name mark = (,) <$> name <*> mark

dependent :: Maybe String -> Maybe Int
dependent name = name >>= \key -> lookup key [("Ada",70),("Bo",80)]

main :: IO ()
main = print ((independent (Just "Ada") (Just 9), dependent (Just "Ada")))
```

```text
(Just ("Ada",9),Just 70)
```

</HaskellTryIt>

**Walk-through:** The independent mark is the supplied 9. The dependent lookup uses "Ada" to select 70.

### Variation: present but unknown key

The optional name exists, but the selected search may fail.

<HaskellTryIt>

```haskell
independent :: Maybe String -> Maybe Int -> Maybe (String,Int)
independent name mark = (,) <$> name <*> mark

dependent :: Maybe String -> Maybe Int
dependent name = name >>= \key -> lookup key [("Ada",70),("Bo",80)]

main :: IO ()
main = print ((independent (Just "Cy") (Just 9), dependent (Just "Cy")))
```

```text
(Just ("Cy",9),Nothing)
```

</HaskellTryIt>

**Walk-through:** Pairing does not search a table. The dependent continuation searches for Cy and finds no entry.

### Variation: missing first input

Both operations see outer absence.

<HaskellTryIt>

```haskell
independent :: Maybe String -> Maybe Int -> Maybe (String,Int)
independent name mark = (,) <$> name <*> mark

dependent :: Maybe String -> Maybe Int
dependent name = name >>= \key -> lookup key [("Ada",70),("Bo",80)]

main :: IO ()
main = print ((independent Nothing (Just 9), dependent Nothing))
```

```text
(Nothing,Nothing)
```

</HaskellTryIt>

**Walk-through:** Application cannot pair a missing name; bind does not call lookup without a key.

### Contrast: two validated numbers versus a chosen validation

Two Either inputs can be added independently. A successful first payload can instead determine a new check. Error priority still follows the standard Either instance; independence does not imply error accumulation.

### Variation: valid independent inputs

The selected check can still fail.

<HaskellTryIt>

```haskell
independent :: Either String Int -> Either String Int -> Either String Int
independent first second = (+) <$> first <*> second

dependent :: Either String Int -> Either String Int
dependent first = first >>= \n ->
  if n > 5 then Right (n * 2) else Left "too small"

main :: IO ()
main = print ((independent (Right 3) (Right 4), dependent (Right 3)))
```

```text
(Right 7,Left "too small")
```

</HaskellTryIt>

**Walk-through:** Addition needs no extra check; the dependent rule rejects the successful payload 3.

### Variation: first failure

The continuation is skipped.

<HaskellTryIt>

```haskell
independent :: Either String Int -> Either String Int -> Either String Int
independent first second = (+) <$> first <*> second

dependent :: Either String Int -> Either String Int
dependent first = first >>= \n ->
  if n > 5 then Right (n * 2) else Left "too small"

main :: IO ()
main = print ((independent (Left "first") (Left "second"), dependent (Left "first")))
```

```text
(Left "first",Left "first")
```

</HaskellTryIt>

**Walk-through:** Independent combination retains its first error. Bind returns the same existing error without choosing a later check.

### Variation: dependent success

Change the payload so the chosen check passes.

<HaskellTryIt>

```haskell
independent :: Either String Int -> Either String Int -> Either String Int
independent first second = (+) <$> first <*> second

dependent :: Either String Int -> Either String Int
dependent first = first >>= \n ->
  if n > 5 then Right (n * 2) else Left "too small"

main :: IO ()
main = print ((independent (Right 8) (Left "second"), dependent (Right 8)))
```

```text
(Left "second",Right 16)
```

</HaskellTryIt>

**Walk-through:** The independent second input fails. The dependent path instead uses 8 to select and compute Right 16.

### Contrast: fixed Cartesian choices versus a dependent range

Independent list inputs give every pair. A range whose upper limit is the earlier element has a different branch size for each element.

### Variation: different branch sizes

The source contains 1 and 3.

<HaskellTryIt>

```haskell
independent :: [Int] -> [(Int,Int)]
independent xs = (,) <$> xs <*> [1,2]

dependent :: [Int] -> [(Int,Int)]
dependent xs = xs >>= \x -> [ (x,y) | y <- [1..x] ]

main :: IO ()
main = print ((independent [1,3], dependent [1,3]))
```

```text
([(1,1),(1,2),(3,1),(3,2)],[(1,1),(3,1),(3,2),(3,3)])
```

</HaskellTryIt>

**Walk-through:** The fixed second list has two choices for every x. The selected ranges have one and three choices.

### Variation: empty dependent branch

Zero has no range from 1 to itself.

<HaskellTryIt>

```haskell
independent :: [Int] -> [(Int,Int)]
independent xs = (,) <$> xs <*> [1,2]

dependent :: [Int] -> [(Int,Int)]
dependent xs = xs >>= \x -> [ (x,y) | y <- [1..x] ]

main :: IO ()
main = print ((independent [0,2], dependent [0,2]))
```

```text
([(0,1),(0,2),(2,1),(2,2)],[(2,1),(2,2)])
```

</HaskellTryIt>

**Walk-through:** The independent branch for zero still has two pairs. The dependent range [1..0] is empty.

### Variation: no source alternatives

Neither construction invents an x.

<HaskellTryIt>

```haskell
independent :: [Int] -> [(Int,Int)]
independent xs = (,) <$> xs <*> [1,2]

dependent :: [Int] -> [(Int,Int)]
dependent xs = xs >>= \x -> [ (x,y) | y <- [1..x] ]

main :: IO ()
main = print ((independent [], dependent []))
```

```text
([],[])
```

</HaskellTryIt>

**Walk-through:** Both are empty because their outer source is empty; this boundary alone cannot distinguish the specifications.

### Contrast: two positions versus an index selected by a value

Two supplied lists can form independent pairs. A first list can instead supply positions into a second list. The next branch must then use the selected position; it is not a Cartesian pairing of positions and all data.

For this policy, indices must be non-negative; oversized indices contribute no result. We use take/drop to avoid partial indexing. Negative indices are outside this function's stated domain.

### Variation: selected position

Use one position with two available values.

<HaskellTryIt>

```haskell
independent :: [Int] -> [String] -> [(Int,String)]
independent indices values = (,) <$> indices <*> values

dependent :: [Int] -> [String] -> [String]
dependent indices values = indices >>= \i -> take 1 (drop i values)

main :: IO ()
main = print ((independent [1] ["a","b"], dependent [1] ["a","b"]))
```

```text
([(1,"a"),(1,"b")],["b"])
```

</HaskellTryIt>

**Walk-through:** Cartesian pairing includes both texts. Drop 1 then take 1 selects only b.

### Variation: oversized index

A dependent branch can disappear.

<HaskellTryIt>

```haskell
independent :: [Int] -> [String] -> [(Int,String)]
independent indices values = (,) <$> indices <*> values

dependent :: [Int] -> [String] -> [String]
dependent indices values = indices >>= \i -> take 1 (drop i values)

main :: IO ()
main = print ((independent [3] ["a","b"], dependent [3] ["a","b"]))
```

```text
([(3,"a"),(3,"b")],[])
```

</HaskellTryIt>

**Walk-through:** The pair builder does no indexing. Drop 3 exhausts the values, so the selected branch is empty.

### Variation: repeated index

The same branch is visited twice.

<HaskellTryIt>

```haskell
independent :: [Int] -> [String] -> [(Int,String)]

## 5. Do notation is a readable bind tree

Do notation groups contextual steps; it is not restricted to IO. A bound variable is a payload, visible in subsequent lines. Desugaring makes scope and branching explicit. These examples use variable patterns only, so they need no refutable-pattern failure mechanism.

**Templates:** `do { x <- first; rest } = first >>= \x -> rest`; `do { final } = final`. With two bindings, nest the second bind inside the first lambda. The final expression must already be contextual. A let in do adds an ordinary local definition, not an additional contextual step.

### Variation: Maybe success

Use a payload that passes the selected check.

<HaskellTryIt>

  x <- source
  y <- if x > 2 then Just (x * 2) else Nothing
  pure (x + y)

expanded :: Maybe Int -> Maybe Int
expanded source = source >>= \x ->
  (if x > 2 then Just (x * 2) else Nothing) >>= \y ->
    pure (x + y)

main :: IO ()
main = print ((written (Just 3), expanded (Just 3)))
```

```text
(Just 9,Just 9)
```

</HaskellTryIt>

**Walk-through:** Bind x=3, then y=6, then pure 9; both forms retain one Maybe layer.

## 6. Let, payload bindings and return

A do binding with an arrow obtains a payload from a contextual step. A let defines an ordinary local expression and has no contextual failure or branch of its own. Pure and return introduce a contextual result; return does not exit the surrounding block.

**Templates:** `do { x <- source; let y = f x; pure y }` is `source >>= \x -> let y = f x in pure y`. Use `<-` for an m a source, and `let` for an ordinary a expression. Both names are in scope only in the following part of the block.

## 7. Discarding a payload: sequencing siblings

Sometimes a contextual step matters but its payload does not. Sequencing keeps the context's failure, branching or effects while ignoring that payload. It does not simply remove the step.

**Templates:** `first >> second = first >>= \_ -> second`. For the standard compatible instances here, `first *> second` gives the same result, using only Applicative. The sibling `first <* second` retains the first payload instead, while still combining the contexts. Their types are `m a -> m b -> m b` for bind sequencing, `f a -> f b -> f b` for right-retaining application, and `f a -> f b -> f a` for left-retaining application. The type of the ignored payload may differ from the retained one.

## 8. The Monad laws

The laws describe how successful introduction and dependent sequencing fit together. They allow refactoring without changing which failures or branches survive. A method can compile while violating these behavioural promises. For these finite total examples, Eq checks the answers; the Monad class does not require Eq.

**Templates:**

- Left identity: `pure x >>= k = k x`.
- Right identity: `value >>= pure = value`.
- Associativity: `(value >>= k) >>= h = value >>= (\x -> k x >>= h)`.

Associativity is regrouping, not swapping k and h. The continuation input and output types must still line up. Each variation below checks all three laws in order.

### Variation: Maybe law checks

Use a continuation that could fail on another input.

<HaskellTryIt>

```haskell
k :: Int -> Maybe Int

h x = Just (x * 2)

main :: IO ()
main = do
  let value = Just 2
  print (((pure 2 :: Maybe Int) >>= k) == k 2)
  print ((value >>= pure) == value)
  print (((value >>= k) >>= h) == (value >>= (\x -> k x >>= h)))
```

```text
True
True
True
```

</HaskellTryIt>

**Walk-through:** Left identity gives Just 3. Right identity preserves Just 2. Associativity gives Just 6 along both routes.

### Variation: Either law checks

<HaskellTryIt>

```haskell

h x = Right (x * 2)

  print (((pure 2 :: Either String Int) >>= k) == k 2)

```

```

## 9. Compose functions that return a context

Ordinary composition cannot directly connect `a -> m b` with `b -> m c`: the first produces m b, while the next wants b. **Kleisli composition** means composing such contextual functions by using bind between them.

**Template:** `chainSteps first next x = first x >>= next`, with type `Monad m => (a -> m b) -> (b -> m c) -> a -> m c`. Control.Monad supplies this left-to-right spelling as `first >=> next` and the reversed spelling as `next <=< first`. The hand-written definition below makes the mechanism explicit.

main = print (chainSteps (\n -> if n > 0 then Right n else Left "first") (\n -> Right (n*2)) (0 :: Int) :: Either String Int)
```

```text

```

</HaskellTryIt>

**Walk-through:** The first Left stops the chain; no second payload is calculated.

### Exam question 12: repair ordinary composition (5 marks)

Given `first :: String -> Maybe Int` and `next :: Int -> Maybe Bool`, explain why `next . first` is wrong and give the correct composition type and definition.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Explain" asks for the mismatched middle types, then a repair.

</Step>

<Step title="2. Plan">

Ordinary composition would need the first result to be Int, but it is Maybe Int. Bind supplies its successful payload.

</Step>

<Step title="3. Solution">

`combined :: String -> Maybe Bool` with `combined input = first input >>= next`. Equivalently use first >=> next from Control.Monad.

</Step>

<Step title="4. Check">

If first returns Nothing, combined returns Nothing. If first returns Just 4, combined is exactly next 4; no extra Maybe layer is introduced.

</Step>

</Steps>

</details>

**Common errors and repairs:** Ordinary composition at incompatible middle types is rejected with `Couldn't match`. Writing fmap next . first may compile but has result Maybe (Maybe Bool), adding a layer rather than combining steps. Use bind or the contextual composition operators.

**Practice:** What is the general result type of composing a -> Either e b with b -> Either e c?

<details>
<summary>Answer</summary>

a -> Either e c. The same e is required throughout; changing the success payload types does not change the error type.

</details>

## Summary

<Callout type="key" title="Remember">

Bind gives a successful payload to a contextual continuation; mapping retains an extra layer when the mapped function already returns a context. List bind joins ordered branches, including empty and repeated branches. Independent inputs combine applicatively; selected lookups, checks and ranges use bind. Do notation nests those binds while preserving scope. Let names plain expressions, and pure or return introduces a result without exiting. Sequencing can discard payloads while retaining failure or multiplicity. Monad laws allow regrouping, not reordering.

</Callout>

## Check your understanding

<CheckQuestions>

<CheckQuestion question="How does the continuation type distinguish bind from mapping?">

Bind takes a -> m b, while mapping takes a -> b. Bind returns m b directly.

</CheckQuestion>

<CheckQuestion question="Does one empty list branch abort every later branch?">

No. It contributes no results; later source alternatives are still visited.

</CheckQuestion>

<CheckQuestion question="When does a successful first value require bind?">

When its payload selects a subsequent contextual computation, such as a lookup or a varying range.

</CheckQuestion>

<CheckQuestion question="Does return exit a Maybe do block?">

No. It introduces success. A later expression can still determine the block's final result.

</CheckQuestion>

<CheckQuestion question="What does associativity allow?">

Regrouping binds while keeping the same continuation order and dependencies, not swapping the steps.

</CheckQuestion>
