## 1. The method and standard-type templates

For a **write** question, give a signature and every required branch. For a **trace** question, substitute one equation at a time. For **rewrite**, preserve the signature and test both constructors. For **justify**, name the information that the result must retain.

For a consumer, specialise each type variable before calculating. In `maybe d f m`, `d` has the result type; in `either f g e`, both handlers have one common result type. For a chain, list each stage and stop at the first absent or left result.

### Ordering: a three-way result

`Ordering` is the type with constructors `LT`, `EQ` and `GT`, in that declaration order. It records less than, equal to or greater than. `compare :: Ord a => a -> a -> Ordering` compares two values of the **same** type.

**Template:** `case compare first second of LT -> lessResult; EQ -> equalResult; GT -> greaterResult`. All three branch results share one type. For integer inputs, these equations describe `compare`:

```haskell
compareInt :: Int -> Int -> Ordering
compareInt x y
  | x < y = LT
  | x == y = EQ
  | otherwise = GT
```


```text

```

</HaskellTryIt>

**Hand trace:** The less-than test succeeds, so `compareInt` selects `LT`; standard `compare` agrees.

### Variation: equal

<HaskellTryIt>

```haskell
main = print (compare (5 :: Int) 5)
```

```text

```

</HaskellTryIt>

### Variation: greater than

<HaskellTryIt>


**Common error:** `compare` returns `Ordering`, not `Bool`; use a three-way match or an ordinary comparison test. Standard `Eq` distinguishes the three constructors, `Ord` uses `LT < EQ < GT`, and `Show` displays their names.

### Unit: one result with no payload

The unit type `()` has one ordinary, defined value, also written `()`. Like every Haskell type it can also have nontermination or undefined expressions; these are not extra ordinary constructors. `IO ()` describes an action whose result carries no interesting payload, not an action which does nothing.

**Template:** `finish :: Input -> ()`; `finish _ = ()`. A unit consumer matches `()`; equality and ordering always yield `True` and `EQ` for defined unit inputs.

```haskell
unitResult :: a -> ()
unitResult _ = ()
```

</HaskellTryIt>

**Hand trace:** The expression is already the unit value; `Show` writes `()`.

### Tuples: products store every field

A pair `(a,b)` holds an `a` **and** a `b`; this is a product type. A choice `Either a b` holds only one side. Tuple equality compares corresponding fields; ordering is lexicographic: the first unequal field decides. Derived display uses parentheses and commas.

**Template:** `consumePair (first,second) = combine first second`. These definitions show pair equality and ordering:

```haskell
equalPair :: (Eq a, Eq b) => (a,b) -> (a,b) -> Bool
equalPair (a,b) (c,d) = a == c && b == d
comparePair :: (Ord a, Ord b) => (a,b) -> (a,b) -> Ordering
comparePair (a,b) (c,d) = case compare a c of
  LT -> LT
  EQ -> compare b d
  GT -> GT
```

### Bool: a two-constructor type

The Prelude declaration is `data Bool = False | True`. A Boolean is one of these two values; the constructors do not carry fields. Its `Eq` instance compares constructors, `Ord` puts `False` before `True`, and `Show` writes their names.

**Template:** `case condition of False -> falseResult; True -> trueResult`. These equations consume every constructor:

```haskell
flagText :: Bool -> String
flagText False = "no"
flagText True = "yes"
```

**Hand trace:** The expression is the constructor `False`; display writes its name.

<HaskellTryIt>

**Common error:** `True` is not the integer 1 in Haskell; guard conditions must have type `Bool`.

### Exam question 9: three optional steps (4 marks)

Write a chain that requires a positive integer, halves it only if even, then halves the result only if even. Trace inputs 8, 6 and 0.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Write" needs all three stages and their composition; "trace" asks where each path succeeds or fails.

</Step>

<Step title="2. Plan">

Use `andThen` twice. Each stage returns an optional integer; no default should turn failure into success.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Predict map pipeline [8,6,0].
andThen :: Maybe a -> (a -> Maybe b) -> Maybe b
andThen Nothing _ = Nothing
andThen (Just x) f = f x
positive :: Int -> Maybe Int
positive n | n > 0 = Just n
           | otherwise = Nothing
half :: Int -> Maybe Int
half n | even n = Just (n `div` 2)
       | otherwise = Nothing
pipeline :: Int -> Maybe Int
pipeline n = andThen (andThen (positive n) half) half

main :: IO ()
main = print (map pipeline [8,6,0])
```

```text
[Just 2,Nothing,Nothing]
```

</HaskellTryIt>

`8 -> Just 8 -> Just 4 -> Just 2`. For 6: `Just 6 -> Just 3 -> Nothing`. For 0, positivity returns `Nothing` and both halves are skipped.

</Step>

<Step title="4. Check">

`pipeline 4 = Just 1`; `pipeline (-4) = Nothing`. Returning a plain `Int` from `half` would violate the continuation type.

</Step>

</Steps>

</details>

```haskell
  where
```

## Summary

<Callout type="key" title="Remember">

Read the command word, fix the types, select equations and check boundary cases. Optional absence, explained failure, a two-way choice and a product store different information. A mapping keeps context; a dependent chain stops at its first failure; a collector preserves the successful entries or separates the two sides. Standard instances follow constructor and field rules, not informal numerical guesses.

</Callout>
