## 1. Answering template

Read the command word. For evaluation, locate the first deciding method and reduce it. For a type, list each operation, unify its operand types and remove requirements already supplied by superclasses. For a repair, distinguish compile-time typing, run-time failure and incorrect behaviour. Check an ordinary case and an endpoint. The runnable checks below accompany complete written answers; three-or-more worked variations for each taught concept are in the patterns lesson.

The site interpreter cannot resolve these polymorphic bounds. The general answer above is ordinary Haskell; this executable specialisation fixes the endpoint type explicitly.

## 3. Common repairs and further practice

| Symptom | Category | Repair |
| --- | --- | --- |
| Ambiguous type variable at print (read s) | Compile-time selection | Supply the result type |
| Demanded read with trailing text | Run-time failure | Fix syntax or return a failure value |
| succ True or pred False | Run-time endpoint failure | Stop or define a cyclic policy explicitly |
| Bounded context used with range syntax | Missing Enum requirement | Add Enum |
| Num context used with ordering | Missing Ord requirement | Add Ord unless a stronger required class supplies it |
| Finite passing examples treated as proof | Reasoning error | Prove the law on its stated domain |

**Practice.** Replace the last Bool field in the tuple question with a differing first numeric field. Replace floor by sqrt in the conversion question. Explain whether the result still has an independent Integral type. Then explain why Integral and Fractional are separate branches without asserting that the class system forbids a type from having both instances.

<details>
<summary>Answers</summary>

A differing first field decides the tuple order immediately. For sqrt, the minimal type is Floating a => a -> a; there is no separate Integral result variable. Integral requires Real and Enum, while Fractional requires Num. Neither requires the other, and superclass declarations are requirements rather than a prohibition against declaring both.

</details>


## Summary

<Callout type="key" title="Remember">
Ord supplies methods; laws require lawful components and defined comparisons. Read needs a selected result type and valid complete text. Enum steps and Bounded endpoints are independent capabilities. Numeric constraints follow methods and superclass paths. Compilation and passing examples do not prove universal laws.
</Callout>

  <CheckQuestion question="Does a class constraint prove instance laws?">

No. It supplies operations. Behavioural laws need reasoning on a stated domain.

  </CheckQuestion>

  <CheckQuestion question="Why can read need context even with fixed input?">

Its input is String regardless of the result type. The result type selects the Read instance.

  </CheckQuestion>

  <CheckQuestion question="Which constraints enumerate from minBound to maxBound?">

Both Bounded a and Enum a. Neither class has the other as a superclass.

  </CheckQuestion>

  <CheckQuestion question="Does Fractional imply Ord?">

No. Fractional implies Num. Ordered fractional operations need Ord separately or an applicable stronger class such as RealFrac.
