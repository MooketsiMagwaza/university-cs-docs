## 1. Action types, bindings and the last expression

`IO a` describes an action with a result of type `a`. `IO ()` still performs effects; its result is unit. The last statement in a `do` block must be an action expression and supplies the whole block's result. Use `<-` to perform an action and bind its result, and `let` to name a pure expression. Naming an action with `let` is also legal, but does not perform it. Names in one `let` group can refer to one another in either written order; a later separate statement is not in scope earlier.

**Template.** `do { x <- action; let y = calculate x; finalAction y }`. `x` is the result, not an action. `finalAction y` determines the block result type.

### Variation: a helper returns useful data

<HaskellTryIt>

```haskell
answer :: IO Int
answer = do
  let n = 6
  pure (n * 7)
main :: IO ()
main = do
  x <- answer
  print x
```

```text
42
```

</HaskellTryIt>

The helper returns 42 without output. `print` displays it and gives `main` unit as its result.

### Variation: name an action and execute it twice

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  let say = putStrLn "ready"
  say
  say
```

```text
ready
ready
```

</HaskellTryIt>

The binding prints nothing. Each later action statement performs the described output.

### Variation: forward reference inside one let group

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  let total = base + 2
      base = 5 :: Int
  print total
```

```text
7
```

</HaskellTryIt>

Both names share the same recursive binding group, so `total` can use `base`.

## 2. getChar reads one character

`getChar :: IO Char` consumes exactly one character, including a space or newline, and leaves the remainder unread. In a line-buffered terminal you may need Enter before characters become available. That does not make `getChar` return a whole line. At EOF it raises an IO exception.

**Template.** `do { c <- getChar; useCharacter c }`; the final use must produce an action.

### Variation: letter

<HaskellTryIt input="A">

```haskell
main :: IO ()
main = do
  c <- getChar
  print c
```

```text
'A'
```

</HaskellTryIt>

`print` displays a Char with single quotes.

### Variation: space is not skipped

<HaskellTryIt input=" ">

```haskell
main :: IO ()
main = do
  c <- getChar
  print (c == ' ')
```

```text
True
```

</HaskellTryIt>

A space is a real input character.

### Variation: successive characters

<HaskellTryIt input="ab">

```haskell
main :: IO ()
main = do
  a <- getChar
  b <- getChar
  print [b,a]
```

```text
"ba"
```

</HaskellTryIt>

The two results are reversed into a String, whose printed representation has double quotes.

### Exam question: getChar reads one character (5 marks)

  </Step>

## 3. putChar writes one character

`putChar :: Char -> IO ()` writes one character without quotes or an added newline. `putStr [c]` writes the same characters as `putChar c`. `print c` instead uses the `Show Char` representation and ends the line.

**Template.** `putChar character >> putChar '\n'` writes one visible character then explicitly ends the line.

### Variation: explicit line ending

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  putChar 'Q'
  putChar '\n'
```

```text
Q
```

</HaskellTryIt>

The second action supplies the newline.

### Variation: three output forms

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  putChar 'A'
  putStr "A"
  print 'A'
```

```text
AA'A'
```

</HaskellTryIt>

The first two writes leave the cursor on the same line; the quoted Char from `print` follows them.

### Variation: newline is a character

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  putChar 'x'
  putChar '\n'
  putChar 'y'
  putChar '\n'
```

```text
x
y
```

</HaskellTryIt>

Four actions write two letters and two line endings.

## 4. getLine and leftover newlines

`getLine :: IO String` consumes a line terminator but returns only the preceding characters. It preserves spaces and returns `""` for an empty line. After a character read, the next line read obtains the remainder of that same line. It does not automatically advance to the next nonempty line.

**Template.** `do { c <- getChar; rest <- getLine; next <- getLine; ... }`. `rest` may be empty or contain several characters.

### Variation: spaces within a line

<HaskellTryIt input="Ada Lovelace">

```haskell
main :: IO ()
main = do
  s <- getLine
  print s
```

```text
"Ada Lovelace"
```

</HaskellTryIt>

The internal space survives; the terminator does not.

### Variation: empty remainder

<HaskellTryIt input="A
Bob">

```haskell
main :: IO ()
main = do
  c <- getChar
  rest <- getLine
  name <- getLine
  print (c,rest,name)
```

```text
('A',"","Bob")
```

</HaskellTryIt>

The first line read meets the leftover newline immediately. The next reads Bob.

### Variation: discard a nonempty remainder

<HaskellTryIt input="yes
next">

```haskell
main :: IO ()
main = do
  c <- getChar
  _ <- getLine
  next <- getLine
  print (c,next)
```

```text
('y',"next")
```

</HaskellTryIt>

The discarded text is `es`; discarding one character alone would be insufficient.

### Exam question: getLine and leftover newlines (5 marks)

Read a character command from its own line, discard the rest of that line, then print the next line as a name.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

  <Step title="1. Read the question">

The command is "read" with two different input units: one character from a command line, then a complete name line. Leftover command text must not become the name.

  </Step>

  <Step title="2. Plan">

Discard the whole remainder with `getLine`, even if the command line holds extra text.

  </Step>

  <Step title="3. Solution">

```haskell
main :: IO ()

  _ <- getChar
  _ <- getLine
  name <- getLine
  putStrLn name
```

  </Step>

  <Step title="4. Check">

For `x extra` then `Ada`, output is `Ada`. A command line containing only `x` also works.

  </Step>

</Steps>

</details>

**Common errors.** An extra `getChar` consumes only one character and can leave more text behind. Conversely, discarding another line after a complete `getLine` loses real data. These are logic errors with no GHC diagnostic; track the unread stream explicitly.

**Practice.** What does reading a line containing two spaces return?

<details>
<summary>Answer</summary>

The two-character String `"  "`, not `""`.

</details>

## 5. readLn parses a typed line

`readLn :: Read a => IO a` reads a line and parses its Haskell representation at a chosen type. `Read` names the parsing capability. It is approximately `getLine >>= (pure . read)`. Malformed input raises an exception; use the existing `readMaybe` parser from [Maybe in Depth](/docs/sem3/csi243/09-polymorphism/notes/maybe-in-depth) for recovery. A line of text is not automatically safe merely because it is entered by a user.

**Template.** `n <- (readLn :: IO Int)`. Alternatively use `text <- getLine` then `let n = read text :: Int` when valid input is guaranteed.

### Variation: signed integer

<HaskellTryIt input="-3">

```haskell
main :: IO ()
main = do
  n <- (readLn :: IO Int)
  print (n * 2)
```

```text
-6
```

</HaskellTryIt>

The result is numeric negative three, so doubling gives negative six.

### Variation: Boolean constructor

<HaskellTryIt input="True">

```haskell
main :: IO ()
main = do
  b <- (readLn :: IO Bool)
  print (not b)
```

```text
False
```

</HaskellTryIt>

`True` is the Haskell constructor spelling.

### Variation: structured input

<HaskellTryIt input="[1,2,3]">

```haskell
main :: IO ()
main = do
  xs <- (readLn :: IO [Int])
  print (sum xs)
```

```text
6
```

</HaskellTryIt>

The entire list is parsed from one line; its sum is six.

### Exam question: readLn parses a typed line (5 marks)

Read two valid integer lines and display their sum. Explain the malformed-input policy.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

  <Step title="1. Read the question">

The command is "read" and the two supplied lines are valid integer representations. The result is one numeric sum; a separate explanation must state that this version does not recover from malformed text.

  </Step>

  <Step title="2. Plan">

Annotate both reads as `IO Int`, add their results and print. This version assumes valid input.

  </Step>

  <Step title="3. Solution">

```haskell
main :: IO ()
main = do
  a <- (readLn :: IO Int)
  b <- (readLn :: IO Int)
  print (a + b)
```

  </Step>

  <Step title="4. Check">

Inputs 4 and -1 print `3`. Malformed input raises an exception rather than retrying.

  </Step>

</Steps>

</details>

**Common errors.** `readLn :: Int` omits the IO wrapper: key phrase `Couldn't match`. Use `IO Int`. `read "oops" :: Int` deliberately fails with key exception phrase `no parse`; do not put this crash in a runnable block.

**Practice.** How does `readLn :: IO String` differ from `getLine`?

<details>
<summary>Answer</summary>

It expects a Haskell String literal including source quotes. `getLine` returns the entered line directly.

</details>

## 6. pure supplies a result, not an exit

For IO, `pure :: a -> IO a` makes an action which produces a value without additional effects. `pure` and `return` have the same role here. Neither prints the value nor stops later actions. Prefer `pure` in new code and recognise `return` in older solutions. `pure () :: IO ()` is the do-nothing action.

**Template.** `do { x <- pure value; next x }`; use `pure ()` for an empty effect branch.

### Variation: number result

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  x <- (pure 12 :: IO Int)
  print (x + 1)
```

```text
13
```

</HaskellTryIt>

The bound result is an ordinary number.

### Variation: unit does not exit

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  putStrLn "before"
  pure ()
  putStrLn "after"
```

```text
before
after
```

</HaskellTryIt>

The middle action produces unit and execution continues.

### Variation: return text without printing it

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  s <- (pure "ok" :: IO String)
  print (length s)
```

```text
2
```

</HaskellTryIt>

The String is data. Only the final action writes output.

### Exam question: pure supplies a result, not an exit (5 marks)

A student uses `pure ()` to stop before printing "work". Repair the design so "work" is printed only if `go` is true.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

  <Step title="1. Read the question">

The command is "repair". The intended condition is Boolean `go`, and the only required effect is printing work when go is true. Returning unit does not implement that choice.

  </Step>

  <Step title="2. Plan">

Select the work action with `if`; place any dependent work inside the selected branch.

  </Step>

  <Step title="3. Solution">

```haskell
run :: Bool -> IO ()
run go = if go then putStrLn "work" else pure ()
main :: IO ()
main = run False
```

  </Step>

  <Step title="4. Check">

False produces no output, while true prints `work`. No imagined early return is needed.

  </Step>

</Steps>

</details>

**Common errors.** Expecting `pure ()` to stop is a logic error, with no GHC message. Ending `main :: IO ()` with `pure (3 :: Int)` instead gives a type error: key phrase `Couldn't match type`. Print 3 or return unit.

**Practice.** What does `do { pure "hidden"; putStrLn "visible" }` print?

<details>
<summary>Answer</summary>

Only `visible` and a newline. The unused String result is discarded.

</details>

## 8. Discarding sequencing with >>

For IO, `(>>) :: IO a -> IO b -> IO b` performs the left action, discards its result and then performs the right action. The combined result comes from the right. This specifies effect order, not strict evaluation of every pure subexpression. Consecutive unbound action statements in `do` use this pattern.

**Template.** `firstAction >> secondAction`; equivalently `do { firstAction; secondAction }`.

### Variation: ordered writes

<HaskellTryIt>

```haskell
main :: IO ()
main = putStrLn "first" >> putStrLn "second"
```

```text
first
second
```

</HaskellTryIt>

The first message is written before the second.

### Variation: consume and discard input

<HaskellTryIt input="secret">

```haskell
main :: IO ()
main = getLine >> putStrLn "discarded"
```

```text
discarded
```

</HaskellTryIt>

The input effect happens although its String result is ignored.

### Variation: keep the final result

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  n <- (putStrLn "start" >> pure (8 :: Int))
  print n
```

```text
start
8
```

</HaskellTryIt>

The combined action has type `IO Int`. It discards the first unit result, not the last number.

### Exam question: Discarding sequencing with >> (5 marks)

Rewrite `do { getLine; putStrLn "done" }` without `do` and give the type.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

  <Step title="1. Read the question">

The command is "rewrite". The input result is unused, so only action order matters.

  </Step>

  <Step title="2. Plan">

Apply the discard-result template directly.

  </Step>

  <Step title="3. Solution">

```haskell
main :: IO ()
main = getLine >> putStrLn "done"
```

  </Step>

  <Step title="4. Check">

Input `abc` is consumed; output is `done` and a newline. The type is `IO ()`.

  </Step>

</Steps>

</details>

**Common errors.** `getLine >> length` supplies a function instead of an action: key phrase `Couldn't match`. To use the read result, use `>>=` and a function returning an action.

**Practice.** What result does `pure True >> pure (7 :: Int) :: IO Int` produce?

<details>
<summary>Answer</summary>

7, without printing it. The left Boolean result is discarded.

</details>

## 9. Dependent sequencing with >>=

For IO, `(>>=) :: IO a -> (a -> IO b) -> IO b` performs an action, supplies its result to a function and performs the action that function returns. The function receives `a`, not `IO a`. A `<-` line followed by the remaining `do` statements expresses this same dependency.

**Template.** `action >>= \x -> nextAction x`; equivalently `do { x <- action; nextAction x }`.

### Variation: echo a result

<HaskellTryIt input="hello">

```haskell
main :: IO ()
main = getLine >>= putStrLn
```

```text
hello
```

</HaskellTryIt>

The obtained String becomes the argument of `putStrLn`.

### Variation: calculate from the result

<HaskellTryIt input="cat">

```haskell
main :: IO ()
main = getLine >>= \s -> print (length s)
```

```text
3
```

</HaskellTryIt>

The function creates an output action using the line length.

### Variation: choose the next effect

<HaskellTryIt input="no">

```haskell
main :: IO ()
main = getLine >>= \s -> if s == "yes" then putStrLn "accepted" else putStrLn "declined"
```

```text
declined
```

</HaskellTryIt>

The result chooses the declined branch.

### Exam question: Dependent sequencing with >>= (5 marks)

Without `do`, read a line and display its reverse.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

  <Step title="1. Read the question">

The command is "write"; output depends on the text obtained, so `>>` is insufficient.

  </Step>

  <Step title="2. Plan">

Use a lambda to calculate a reversed String and create an output action.

  </Step>

  <Step title="3. Solution">

```haskell
main :: IO ()
main = getLine >>= \s -> putStrLn (reverse s)
```

  </Step>

  <Step title="4. Check">

Input `abc` prints `cba`; an empty input line produces a blank output line.

  </Step>

</Steps>

</details>

**Common errors.** `getLine >>= reverse` returns a String where an IO action is required: key phrase `Couldn't match type`. Write `\s -> putStrLn (reverse s)`. Bind does not automatically turn any pure function into an effect.

**Practice.** Write `getLine >>= \s -> print (length s)` using `do`.

<details>
<summary>Answer</summary>

`do { s <- getLine; print (length s) }`.

</details>

## 10. Conditional actions with when

`when :: Bool -> IO () -> IO ()` in this lesson performs its action when the condition is true; otherwise it performs `pure ()`. Import it from `Control.Monad`. Its sibling uses the opposite condition. Both are for optional unit-result effects; an `if` expression is needed when branches must return useful data.

**Template.** `when condition action`; for several actions use `when condition $ do ...`.

### Variation: selected branch

<HaskellTryIt>

```haskell
import Control.Monad (when)
main :: IO ()
main = when True (putStrLn "selected")
```

```text
selected
```

</HaskellTryIt>

The condition selects the output action.

### Variation: skipped branch

<HaskellTryIt>

```haskell
import Control.Monad (when)
main :: IO ()
main = do
  when False (putStrLn "hidden")
  putStrLn "end"
```

```text
end
```

</HaskellTryIt>

The condition skips the first output, and the later action still runs.

### Variation: conditional block

<HaskellTryIt>

```haskell
import Control.Monad (when)
main :: IO ()
main = when True $ do
  putStrLn "one"
  putStrLn "two"
```

```text
one
two
```

</HaskellTryIt>

Both writes belong to one selected unit-result action.

### Exam question: Conditional actions with when (5 marks)

Use `when` to print "warning" exactly when a Boolean `bad` is true.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

  <Step title="1. Read the question">

The command is "use" and the contract is a single optional output effect.

  </Step>

  <Step title="2. Plan">

Use `bad` directly with `when`, or its negation with `unless`.

  </Step>

  <Step title="3. Solution">

```haskell
import Control.Monad (when)

```

  </Step>

  <Step title="4. Check">

## 12. Prompt until valid

A recursive action can obtain fresh input on each call, retry on failure and return the accepted value on success. The following complete program requires a mark in 0 to 100 inclusive. Termination depends on eventually receiving valid input. EOF raises an exception in this simple version; endlessly invalid lines cause endless retries.

**Template.** `ask = do { s <- getLine; case parse s of { valid -> pure value; invalid -> message >> ask } }`. Recurse only in the retry branch.

### Variation: valid immediately

    Just n | n >= 0 && n <= 100 -> pure n
    _ -> do
      putStrLn "Invalid"
      ask
main :: IO ()
main = do
  n <- ask
  putStrLn ("Accepted: " ++ show n)

## 13. Sentinel loops and carried state

A sentinel is a reserved input meaning stop. Test it before parsing data, and do not include it in the calculation. Carry changing totals as recursive parameters rather than attempting mutation. In this complete program `stop` is case-sensitive, negative numbers are valid data, and blank or malformed lines are rejected without changing the total. Valid input must eventually include the sentinel; EOF is not handled here.

**Template.** `loop state = readAction >>= \x -> if isStop x then finish state else loop (update state x)`. Invalid data can recurse with unchanged state.

## 18. Exact reports with printf

`printf` from `Text.Printf` inserts arguments into placeholders. `%s` inserts text, `%d` an integer and `%.2f` a floating value with exactly two digits after the decimal point, the formatting family required beside Test1 11. **Template.** `printf "%s: %d items, %.2f total\n" label count amount`. Match argument number, order and kind; these examples use an `IO ()` result.

## Summary

<Callout type="key" title="Remember">
An action and its result have different types. The final expression determines a do block's result. `pure` and `return` do not exit. Track leftover input when mixing character and line reads. `>>` discards a result; `>>=` uses it to choose the next action. Conditional effects return unit, recursive loops need an explicit stopping policy, and traversal combinators either collect or discard their results. Formatting affects text, not the original number.
</Callout>
