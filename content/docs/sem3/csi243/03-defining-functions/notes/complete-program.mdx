You already know strings, function application, `putStrLn`, and `print`. We can now assemble those pieces.

```haskell
-- PURPOSE: Calculate a cube, then display a label and the result.
-- Two hyphens start a comment. Haskell ignores the rest of this line.

-- TYPE: cube accepts one Integer and returns one Integer.
cube :: Integer -> Integer

-- PROCESS: Multiply the input x by itself three times.
cube x = x * x * x

-- ENTRY POINT: main is the action the runtime starts.
main :: IO ()
main = do
  -- OUTPUT 1: Write this String, then move to a new line.
  putStrLn "The cube of 4 is:"

  -- PROCESS THEN OUTPUT 2: Calculate cube 4, then display 64.
  print (cube 4)
```

Exact output:

```text
The cube of 4 is:
64
```

## Every component

| Piece | Read aloud | Meaning |
|---|---|---|
| `--` | comment | Ignore the rest of this line during compilation |
| `cube` | cube | A programmer-chosen function name |
| `::` | has type | Introduces a type signature |
| `Integer -> Integer` | Integer to Integer | One whole-number input gives one whole-number result |
| `=` | is defined as | Separates a definition from its meaning |
| `main` | main | The program's starting action |
| `IO ()` | I-O unit | An external-world action with no useful returned data |
| `do` | do | Begins a readable action sequence |
| `(cube 4)` | cube of four | The pure expression supplied to `print` |

`IO` marks a description of work involving the external world. `()` is **unit**, a value carrying no useful information. The useful outcome of terminal output is the visible effect.

## `do` and execution order

The `do` block lists multiple actions in order. Both action lines are aligned, so Haskell groups them into the same block.

<InteractiveStepper>
  <StepperStep title="Start">The runtime begins at `main`.</StepperStep>
  <StepperStep title="First action">`putStrLn` writes the label and newline.</StepperStep>
  <StepperStep title="Pure processing">`cube 4` evaluates to `64`.</StepperStep>
  <StepperStep title="Second action">`print` displays `64` and a newline.</StepperStep>
  <StepperStep title="Finish">The action sequence finishes with unit `()`.</StepperStep>
</InteractiveStepper>

<Callout type="info" title="This is action order, not evaluation order">
The steps above describe the order the two **IO actions** run in: `putStrLn` first, then `print`. They do not mean Haskell evaluates every expression strictly, top to bottom, the moment execution reaches it. Haskell is a **lazy** language — a pure expression like `cube 4` is only evaluated once its value is actually needed, which here happens to be while `print` is performing its action. For this particular program the difference is invisible, because `cube 4` has no side effects to delay. Treat the sequence above as "this is the order the *actions* run in," not "this is the order everything is *computed* in" — Chapter 10 covers lazy evaluation properly.
</Callout>

## Save, load, run

Save the source as `FirstProgram.hs`:

```text
ghci> :load FirstProgram.hs
Ok, one module loaded.
ghci> main
The cube of 4 is:
64
```

Compiler progress wording can vary. The successful load and exact two output lines are the important evidence.

## Common failures

| Failure | Cause | Repair |
|---|---|---|
| Output lines are not aligned | The layout no longer describes one clean sequence | Align actions beneath `do` |
| `main =` has nothing after it | Every definition needs a right side | Supply one action or a `do` block |
| `cube :: Integer` | This describes a value, not a function | Use `Integer -> Integer` |
| `print cube 4` | Application groups left incorrectly for this intention | Use `print (cube 4)` |
