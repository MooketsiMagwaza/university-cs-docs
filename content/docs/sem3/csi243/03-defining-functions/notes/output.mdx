This lesson assumes that you have never printed anything in Haskell. We will introduce each word and symbol before combining them into a complete program.

The lesson progresses through **text → names → function application → output functions → types → actions**.

## 1. Text is data: meet `String`

A computer must distinguish text from the names and instructions in a program. Haskell represents a piece of text using a type named `String`.

- A **character** is one symbol, such as `H`, `4`, or `!`.
- A **string** is a sequence of zero or more characters, such as `Hello World`.
- A **string literal** is text written directly in source code between double quotation marks.

Read this expression aloud as “the string Hello World”:

```haskell
-- The double quotation marks make all enclosed characters one String value.
"Hello World"
```

Exact GHCi result:

```text
"Hello World"
```

GHCi displays the quotation marks to show that the result is a `String` value. The quotation marks mark the text in Haskell source code; they are not part of the message that `putStrLn` writes to the terminal.

### Double quotes and single quotes are different

```haskell
-- Double quotes create a String, which may contain many characters.
"H"

-- Single quotes create one Char value, which contains exactly one character.
'H'
```

Exact GHCi results, in the same order:

```text
"H"
'H'
```

`String` and `Char` are different types. This lesson prints strings first; a later lesson will explore individual characters.

## 2. Unquoted words are program names

An **identifier** is a name used by a program. Examples include `print`, `score`, and `cube`. If a word is not inside quotation marks, Haskell tries to interpret it as a program name.

Capital letters do not turn names into text. An uppercase identifier such as `Hello` is normally treated as a **data-constructor name**. It remains a program name; quotation marks identify text.

## 3. Spaces apply functions

A **function** accepts an input and produces a result. Haskell normally applies a function by placing its argument after its name with a space.

```haskell
-- Apply the function abs to the argument (-5); the parentheses keep the negative number together.
abs (-5)
```

Exact GHCi result:

```text
5
```

Read `abs (-5)` aloud as “apply `abs` to negative five.” Unlike many languages, Haskell does not require `abs(-5)` syntax.

More than one space does not join words into a sentence. Every unquoted word remains program syntax.

### Application groups to the left

Function application is **left-associative**. That means:

```haskell
-- These parentheses reveal how Haskell groups three space-separated expressions.
((print Hello) World)
```

This grouping does not successfully run because `Hello` and `World` are not defined here. It reveals how Haskell parses `print Hello World`; it does **not** mean “print the sentence Hello World.”

## 4. Three output tools with different jobs

### `putStr`: write a string without ending the line

The name `putStr` can be read as “put string.” It accepts a `String`, writes its characters, and does **not** add a newline.

```haskell
-- Write CSI and deliberately leave the cursor on the same output line.
putStr "CSI"
```

Exact visible output, with the cursor left immediately after `I`:

```text
CSI
```

The output block cannot visually show the cursor position, so remember: `putStr` did not end that line.

### `putStrLn`: write a string and end the line

The name `putStrLn` can be read as “put string line.” The `Ln` suffix means that it adds a **newline** after the string. A newline is the invisible control character that moves subsequent output to the beginning of the next line.

```haskell
-- Write Hello World as text, then add a newline.
putStrLn "Hello World"
```

Exact output:

```text
Hello World
```

The quotation marks do not appear because they marked a string literal in the source code; they were not characters inside the string.

### `print`: display a value in Haskell-readable form

`print` is useful for numbers, Boolean values, lists, and other displayable values. It first obtains the value's readable representation and then adds a newline.

```haskell
-- Display the Integer value 42, then add a newline.
print 42

-- Display the Bool value True, then add a newline.
print True

-- Display the Haskell-readable representation of a String, including its quotes.
print "Hello World"
```

Exact output, in order:

```text
42
True
"Hello World"
```

Why are quotation marks visible in the third result? Because `print` displays a value in a Haskell-readable form. The readable representation of a string includes quotation marks.

## 5. `show` converts; it does not print

`show` takes a displayable value and produces a `String`. Producing a string value is a calculation. It does not perform terminal output.

```haskell
-- Convert the Integer 42 into the String "42"; no terminal output action is created here.
show 42
```

Exact GHCi result:

```text
"42"
```

GHCi displays the result because GHCi automatically shows the value of an expression you enter. The `show` function itself only returned the string.

The behavior of `print` can be understood with this simplified mental model:

```haskell
-- First convert 42 to the String "42", then give that String to putStrLn.
putStrLn (show 42)
```

Exact output:

```text
42
```

Parentheses make `show 42` happen first. Its resulting string becomes the input to `putStrLn`.

<CommonMistake title="Confusing show with printing">
`show 42` and `print 42` are easy to conflate because both eventually make `42` visible somewhere. They are not the same kind of thing: `show 42` is a **pure calculation** that produces the String `"42"` and performs no terminal output by itself — GHCi only displays it because GHCi echoes every expression's value. `print 42` is an **IO action**; running it is what actually writes characters to the terminal. Typing `show 42` inside a real program (not at the GHCi prompt) computes a string that vanishes unless something — `putStrLn`, for instance — goes on to display it.
</CommonMistake>

## 6. Reading type signatures from left to right

A **type signature** states what kind of input a function accepts and what kind of result it produces. Read `::` as “has type” and `->` as “to.”

| Signature | Read aloud | Meaning |
|---|---|---|
| `putStr :: String -> IO ()` | “putStr has type String to IO unit” | Accepts one string and creates an output action |
| `putStrLn :: String -> IO ()` | “putStrLn has type String to IO unit” | Accepts one string and creates a newline-ending output action |
| `show :: Show a => a -> String` | “for a displayable type a, show takes an a to a String” | Converts a displayable value to text |
| `print :: Show a => a -> IO ()` | “for a displayable type a, print takes an a to IO unit” | Creates an action that displays the value |

### What does `Show a =>` mean?

At beginner level, read `Show a =>` as:

> “The input may have any type called `a`, as long as Haskell knows how to show values of that type.”

`Show` is a **type class**: a named capability that types can provide. `Integer`, `Bool`, `Char`, and `String` provide `Show`, so `print` can display their values. You do not need to create a type-class instance yet; for now, recognize the constraint as a requirement.

### What does `IO ()` mean?

- `IO` marks an action that can interact with the outside world.
- The terminal is outside the program's pure calculations.
- `()` is pronounced **unit**.
- In `IO ()`, unit means the action returns no useful data after completing its effect.

`IO ()` does **not** mean that nothing happens. The useful result is the visible effect: characters are written to the terminal.

## 7. Value versus `IO` action

A `String` is text data. Applying `putStrLn` to that string creates an action that can send the text to the terminal.

- `"Hello"` is a `String` **value**.
- `show 42` calculates another `String` **value**.
- `putStrLn "Hello"` is an `IO ()` **action**.
- `print 42` is an `IO ()` **action**.

## 8. Why `print Hello World` fails

Consider the incorrect attempt:

```haskell
-- Incorrect: Hello and World are unquoted program names, not one String value.
print Hello World
```

There is no exact successful output because the expression fails before an output action can run. A compiler or GHCi reports an error about names such as `Hello` or `World` not being in scope; the exact wording can vary by GHC version.

    <StepTitle>Recognize three identifiers</StepTitle>

    `print`, `Hello`, and `World` are outside quotation marks, so Haskell treats all three as program names.
  </Step>

  <Step number={2}>
    <StepTitle>Apply the spacing rule</StepTitle>

    Spaces mean function application, not “join these words into a sentence.”
  </Step>

  <Step number={3}>
    <StepTitle>Group to the left</StepTitle>

    Haskell groups the expression as `((print Hello) World)`.
  </Step>

  <Step number={4}>
    <StepTitle>Encounter the first fundamental error</StepTitle>

    No constructor named `Hello` was defined or imported, so Haskell cannot obtain a value to give to `print`.
  </Step>

  <Step number={5}>
    <StepTitle>Correct the intended message</StepTitle>

    Put the complete message inside double quotation marks so it becomes one `String` value: `putStrLn "Hello World"`.
  </Step>
</StepByStep>

<CommonMistake title="Forgetting the quotation marks">
`print Hello World` is one of the most common first mistakes in Haskell, and it comes directly from habits formed in languages where bare words can be text. In Haskell, the only way to write a literal piece of text is between double quotation marks. Any bare, unquoted, lowercase-or-uppercase word is always a program name being looked up — never text — regardless of what it looks like to a human reader.
</CommonMistake>

Correct human-facing output:

```haskell
-- Correct: pass one String value to putStrLn so the message is shown without source-code quotes.
putStrLn "Hello World"
```

Exact output:

```text
Hello World
```

This alternative is valid but displays Haskell's representation of the string:

```haskell
-- Also valid: print shows the String in Haskell-readable form, including quotation marks.
print "Hello World"
```

Exact output:

```text
"Hello World"
```

## 9. Common errors and exact corrections

| Incorrect attempt | What Haskell thinks | Correction | Why the correction works |
|---|---|---|---|
| `putStrLn 42` | `42` is a number, but `putStrLn` requires a `String` | `putStrLn (show 42)` or `print 42` | Convert the number to text, or use the general display function |
| `print Hello World` | Three identifiers applied from left to right | `putStrLn "Hello World"` | Quotes make the message one string |
| `PutStrLn "Hello"` | A different, undefined uppercase name | `putStrLn "Hello"` | Haskell names are case-sensitive |
| `putStrLn 'H'` | `'H'` is a `Char`, not a `String` | `putStrLn "H"` | Double quotes create the required string |
| Two `putStr` calls expected on separate lines | Neither call adds a newline | Use `putStrLn` where the line should end | `putStrLn` appends the newline control character |
