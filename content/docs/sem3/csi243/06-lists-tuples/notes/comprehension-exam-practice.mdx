## 1. An answering template

```text
Read: identify the command word, inputs, output type and restrictions.
Plan: choose sources, patterns, tests and output; fix their order.
Solve: write the definition or trace, not just a guessed result.
Check: use a tiny input and a boundary or empty input; inspect order and count.
```

For ?evaluate?, give values in generation order. For ?write?, give a function of the requested type. For ?rewrite?, preserve order, duplicates and edge cases. For ?count?, count branches without enumerating their outputs. For ?find the error?, identify the fault, explain it and provide a repaired expression. Negative numbers in constructor arguments need parentheses, for example `Just (-2)`. Printed strings have quotes; printed numeric lists have no spaces after commas.

### Exam question 1: evaluate the ordered differences (5 marks)

Evaluate `[x-y | x <- [1,3], y <- [0,2], x /= y]`, showing the order of the candidates.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Evaluate asks for the list, with a trace. The output is subtraction, not a pair. The guard compares the original values.

</Step>

<Step title="2. Plan">

Use the independent-generator template. Hold x fixed through both y values, test, then subtract. A higher-order check uses outer concatMap and inner map/filter.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Evaluate [x-y | x <- [1,3], y <- [0,2], x /= y], showing the order of the candidates.
main :: IO ()
main = do
  print [x-y | x <- [1,3], y <- [0,2], x /= y]
  print (concatMap (\x -> map (\y -> x-y) (filter (\y -> x /= y) [0,2])) [1,3])
```

```text
[1,-1,3,1]
[1,-1,3,1]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| `(x,y) = (1,0)` | unequal: True | `1` |
| `(1,2)` | True | `-1` |
| `(3,0)` | True | `3` |
| `(3,2)` | True | `1` |

All four candidates pass, so both implementations retain four results, including the repeated 1.

</Step>

<Step title="4. Check">

A one-by-one source `[1]` and `[2]` would give `[-1]`. The displayed count is two times two, and the 3 branch starts only after the 1 branch ends.

</Step>

</Steps>

<Step title="1. Read the question">

Write requires a definition. Positive and even are both requirements. Adding five belongs to the output, after selection.

<Step title="2. Plan">

Use one generator and two tests. Translate as map (+5) after a filter combining positivity and parity.

```haskell
adjust :: [Int] -> [Int]
adjust xs = [x+5 | x <- xs, x > 0, even x]

main :: IO ()
main = do

  print (adjust [])
```

```text
[]
```

</HaskellTryIt>

| `x = 4` | True, True | `9` |
| empty input | no candidates | none |

Filtering the transformed values would ask a different question. Only 2 and 4 from the original source are kept.

### Exam question 3: recursion to comprehension and back (6 marks)

Rewrite the recursion `keep [] = []; keep (x:xs) = if x < 0 then (-x):keep xs else keep xs` as a comprehension, then write an equivalent recursion with guards.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Rewrite requires equivalent definitions, including ordering and empty behaviour. The recursion selects negative inputs and negates them.

</Step>

<Step title="2. Plan">

Match cons-with-transformation to an output expression, and the conditional to a test. The skip branch adds nothing.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Rewrite the recursion keep [] = []; keep (x:xs) = if x < 0 then (-x):keep xs else keep xs as a comprehension, then write an equivalent recursion with guards.
keepC :: [Int] -> [Int]
keepC xs = [-x | x <- xs, x < 0]

keepR :: [Int] -> [Int]
keepR [] = []
keepR (x:xs)
  | x < 0 = (-x) : keepR xs
  | otherwise = keepR xs

main :: IO ()
main = do
  print (keepC [-2,0,-1,3])
  print (keepR [-2,0,-1,3])
  print (keepC [])
  print (keepR [])
```

```text
[2,1]
[2,1]
[]
[]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| head `-2`, tail `[0,-1,3]` | negative: keep | `2` before recursive result |
| head `0` | not negative: skip | none |
| head `-1` | negative: keep | `1` before recursive result |
| head `3` | not negative: skip | none |
| `[]` | base case | empty tail |

The cons operations preserve the surviving order. The higher-order equivalent is `map negate (filter (<0) xs)`.

</Step>

<Step title="4. Check">

Both definitions give `[1]` on `[-1]` and `[]` on `[0]`. The explicit base case agrees with the comprehension on empty input.

</Step>

</Steps>

</details>

### Exam question 4: rewrite with map and filter (5 marks)

Rewrite `[length w + 1 | w <- ws, length w >= 2, w /= "no"]` using map and filter, and explain the order.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Rewrite asks for the same output for each ws. The tests refer to original words; outputs are numbers.

</Step>

<Step title="2. Plan">

Combine the tests in a filter, then map length plus one over surviving words. Do not try to test words after transforming them to Int.

<Step title="3. Solution">

```haskell
sizes :: [String] -> [Int]
sizes ws = map (\w -> length w+1) (filter (\w -> length w >= 2 && w /= "no") ws)

main :: IO ()
main = do
  print (sizes ["a","no","yes","ok"])
  print [length w+1 | w <- ["a","no","yes","ok"], length w >= 2, w /= "no"]
  print (sizes [])
```

```text
[4,3]
[4,3]
[]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| `w = "a"` | length test False | none |
| `w = "no"` | True, False | none |
| `w = "yes"` | True, True | `4` |
| `w = "ok"` | True, True | `3` |

Filtering keeps `["yes","ok"]`, then mapping gives `[4,3]`. The two different two-letter words need different treatment.

</Step>

<Step title="4. Check">

On `["no","go"]` the result is `[3]`; on empty input it is `[]`. This checks the exclusion as well as the threshold.

</Steps>

### Exam question 5: count without listing (5 marks)

Without listing tuples, count `[(x,y) | x <- [1..5], y <- [1..x], odd y]` and justify your answer.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Count asks for a scalar. This is a dependent generator with a test on y, so a fixed product of source lengths does not apply.

</Step>

<Step title="2. Plan">

For each x count odd integers from 1 to x: 1, 1, 2, 2, 3. Add the counts. For positive x the count is (x+1) div 2.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Without listing tuples, count [(x,y) | x <- [1..5], y <- [1..x], odd y] and justify your answer.
main :: IO ()
main = do
  print (sum [(x+1) `div` 2 | x <- [1..5]])
  print (length [(x,y) | x <- [1..5], y <- [1..x], odd y])
```

```text
9
9
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| `x = 1; y = 1` | True | count 1 |
| `x = 2; y = 1,2` | True, False | count 1 |
| `x = 3; y = 1,2,3` | True, False, True | count 2 |
| `x = 4; y = 1,2,3,4` | True, False, True, False | count 2 |
| `x = 5; y = 1,2,3,4,5` | True, False, True, False, True | count 3 |

The answer is 1 + 1 + 2 + 2 + 3 = 9. The length call is a check after the counting argument, rather than a substitute for it.

</Step>

<Step title="4. Check">

With outer bound 1 there is one survivor. With bound 0 there are none. The higher-order count is `sum (map (\x -> length (filter odd [1..x])) [1..5])`.

</Step>

</Steps>

Write `timesTable :: Int -> Int -> [(Int,Int,Int)]` containing `(r,c,r*c)` for rows 1 to m and columns 1 to n, in row order.

Write asks for a function of two limits. Row order means the row generator must be outermost. The result is a flat list of triples.

<Step title="2. Plan">

Use two generators, row first and column second. Return all three fields as one tuple. Positive bounds are inclusive; nonpositive bounds generate no entries.

```haskell
timesTable :: Int -> Int -> [(Int,Int,Int)]
timesTable m n = [(r,c,r*c) | r <- [1..m], c <- [1..n]]

main :: IO ()
main = do
  print (timesTable 2 3)

```

The higher-order version is `concatMap (\r -> map (\c -> (r,c,r*c)) [1..n]) [1..m]`. Neither form creates a nested matrix.

### Exam question 8: factors with an explicit domain (5 marks)

Write `factors :: Int -> [Int]` returning positive factors of n in increasing order. Return `[]` when n is not positive.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for positive divisors only. The explicit nonpositive convention avoids the infinite set of divisors of zero.

</Step>

<Step title="2. Plan">

Generate d from 1 through n and keep zero remainders. If n is not positive, the ascending range is empty and mod is never reached.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write factors :: Int -> [Int] returning positive factors of n in increasing order. Return [] when n is not positive.
factors :: Int -> [Int]
factors n = [d | d <- [1..n], n `mod` d == 0]

main :: IO ()
main = do
  print (factors 12)
  print (factors 1)
  print (factors 0)
  print (factors (-3))
```

```text
[1,2,3,4,6,12]
[1]
[]
[]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| `n = 12; d = 1,2,3,4` | all divide exactly | `1,2,3,4` |
| `d = 5` | False | none |
| `d = 6` | True | `6` |
| `d = 7,8,9,10,11` | all False | none |
| `d = 12` | True | `12` |
| `n = 1; d = 1` | True | `1` |
| `n = 0 or -3` | no candidates | none |

The equivalent is `filter (\d -> mod n d == 0) [1..n]`. Starting at 1 protects division from zero.

</Step>

<Step title="4. Check">

For a positive n, both 1 and n must appear; factors 1 must contain only one occurrence of 1. The program checks the nonpositive convention too.

</Step>

</Steps>

### Exam question 9: isPrime and the boundary at one (6 marks)

Write `isPrime :: Int -> Bool` using a comprehension. A prime is a positive integer greater than 1 whose only positive factors are 1 and itself.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for a Boolean function, not a list of primes. The definition excludes negatives, zero and one.

</Step>

<Step title="2. Plan">

Require n > 1, then check that the increasing factor list is exactly [1,n]. Use the factors template, and && to avoid unnecessary work for small n.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write isPrime :: Int -> Bool using a comprehension. A prime is a positive integer greater than 1 whose only positive factors are 1 and itself.
isPrime :: Int -> Bool
isPrime n = n > 1 && [d | d <- [1..n], n `mod` d == 0] == [1,n]

main :: IO ()
main = do
  print (map isPrime [-2,0,1,2,4,5])
  print [n | n <- [1..10], isPrime n]
```

```text
[False,False,False,True,False,True]
[2,3,5,7]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| `n = -2,0,1` | n > 1: False | False, no factor search needed |
| `n = 2; d = 1,2` | both divide | factors `[1,2]`: True |
| `n = 4; d = 1,2,3,4` | True, True, False, True | factors `[1,2,4]`: False |
| `n = 5; d = 1,2,3,4,5` | True, False, False, False, True | factors `[1,5]`: True |
| prime search `n = 1..10` | pass at 2,3,5,7 only | `[2,3,5,7]` |

The higher-order factor expression is `filter (\d -> mod n d == 0) [1..n]`. The outer prime search is `filter isPrime [1..10]`. This simple version prioritises a clear definition over speed.

</Step>

<Step title="4. Check">

2 is the smallest prime; 1 must be False. For 9 the internal divisor 3 makes the factor list `[1,3,9]`, so it is False.

</Step>

</Steps>

### Exam question 10: perfect numbers (7 marks)

Write `perfects :: Int -> [Int]` giving all positive perfect numbers at most the bound. A number is perfect when it equals the sum of its positive proper divisors (divisors smaller than itself).

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for a bounded list. Proper excludes n itself; including n would spoil the definition. Bounds are inclusive.

</Step>

<Step title="2. Plan">

For each n in 1 through limit, sum divisors d in 1 through n-1. Keep n when that sum equals n. This is a nested comprehension used inside a test.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write perfects :: Int -> [Int] giving all positive perfect numbers at most the bound. A number is perfect when it equals the sum of its positive proper divisors (divisors smaller than itself).
perfects :: Int -> [Int]
perfects limit = [n | n <- [1..limit], sum [d | d <- [1..n-1], n `mod` d == 0] == n]

main :: IO ()
main = do
  print (perfects 6)
  print (perfects 30)
  print (perfects 1)
  print (perfects 0)
```

```text
[6]
[6,28]
[]
[]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|
| `n = 1; d` absent | sum 0 /= 1 | none |
| `n = 2..5` | divisor sums 1,1,3,1 differ from n | none |
| `n = 6; d = 1..5` | divisibility True,True,True,False,False | sum `[1,2,3]` = 6: emit 6 |
| `n = 7..15` | proper-divisor sums 1,7,4,8,1,16,1,10,9 | none equal n |
| `n = 16..27` | sums 15,1,21,1,22,11,14,1,36,6,16,13 | none equal n |
| `n = 28; d = 1..27` | pass at 1,2,4,7,14; all others fail | sum 28: emit 28 |
| `n = 29,30` | sums 1,42 | neither equals n |

The higher-order equivalent is `filter (\n -> sum (filter (\d -> mod n d == 0) [1..n-1]) == n) [1..limit]`. Every candidate is checked; ordinary primes cannot pass because their only proper divisor is 1.

</Step>

<Step title="4. Check">

At bound 5 there is no result; at 6 the inclusive endpoint is retained. At bound 1 the inner list is empty and sum [] is 0, so 1 is correctly rejected.

</Step>

</Steps>

</details>

### Exam question 11: Pythagorean triples with order fixed (7 marks)

Write `triples :: Int -> [(Int,Int,Int)]` giving positive Pythagorean triples with `a <= b <= c <= n`, ordered first by c, then b, then a.

<Steps title="Answering the question">

<Step title="1. Read the question">

Write requires a search function. The inequalities specify positive ordered sides and the requested enumeration order fixes generator order.

<Step title="2. Plan">

Generate c first, b from 1 to c, and a from 1 to b. Keep equality of squared side sums. Do not accidentally put a first: that changes ordering.

<Step title="3. Solution">

```haskell
triples :: Int -> [(Int,Int,Int)]
triples n = [(a,b,c) | c <- [1..n], b <- [1..c], a <- [1..b], a*a+b*b == c*c]

main :: IO ()
main = do

  print (triples 0)
```

```text
[(3,4,5),(6,8,10)]
[]
[]
```

</HaskellTryIt>

| `c = 6..9` | all squared tests fail | none |
| `c = 10` | only (a,b) = (6,8) passes | `(6,8,10)` |

The grouped table includes all candidates in each triangular range. At c = 5 the successful equation is 9 + 16 = 25; at c = 10 it is 36 + 64 = 100. Nonprimitive multiples are allowed. align3 :: [a] -> [b] -> [c] -> [(a,b,c)]
```haskell
align3 xs ys zs = [(x,y,z) | (x,(y,z)) <- zip xs (zip ys zs)]

main :: IO ()
```

<Step title="1. Read the question">

Write asks for the product of two lists. Duplicates are explicitly significant, and the requested order fixes the first argument as the outer source.

</Step>

<Step title="2. Plan">

Use two independent generators, then pair their values. There is no selection test. Use concatMap and map for the second implementation.

<Step title="3. Solution">

<HaskellTryIt>

```haskell
cartesian :: [a] -> [b] -> [(a,b)]
cartesian xs ys = [(x,y) | x <- xs, y <- ys]

main :: IO ()
main = do
  print (cartesian [1,1] "ab")

  print (cartesian [1] ("" :: String))
```

### Exam question 14: flatten while transforming (5 marks)

Write `flattenDoubled :: [[Int]] -> [Int]` doubling every number and flattening rows in their original order. Empty rows contribute nothing.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for a flat list, not a matrix. Every number contributes; there is no positivity or parity restriction.

</Step>

<Step title="2. Plan">

Use a dependent inner generator drawing from the current row. The output is twice x; flatten each completed row using concatMap.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write flattenDoubled :: [[Int]] -> [Int] doubling every number and flattening rows in their original order. Empty rows contribute nothing.
flattenDoubled :: [[Int]] -> [Int]
flattenDoubled xss = [2*x | xs <- xss, x <- xs]

main :: IO ()
main = do
  print (flattenDoubled [[1,-2],[],[3]])
  print (concatMap (map (*2)) [[1,-2],[],[3]])
  print (flattenDoubled [])
```

```text
[2,-4,6]
[2,-4,6]
[]
```

</HaskellTryIt>

| Generator values or recursive state, in order | Test or action | Contribution |
|---|---|---|

| `xs = []; x` absent | no candidates | none |
| `xs = [3]; x = 3` | pass | `6` |

The equivalent is `concatMap (map (*2)) xss`. Nested output such as `[[2*x | x <- xs] | xs <- xss]` would preserve rows and answer a different question.

</Step>

<Step title="4. Check">

### Exam question 15: rotations and the empty convention (7 marks)

Write `rotations :: [a] -> [[a]]` listing all left rotations, starting with the unchanged list. Use one result per position, preserve duplicates, and define the result for empty input to be `[]`.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for a polymorphic nested list. A left rotation moves a prefix to the end. The empty convention is stated because some other specifications choose one empty rotation.

</Step>

<Step title="2. Plan">

For each cut position i from zero to length xs minus one, put drop i xs before take i xs. A zero-based range avoids repeating the unchanged list at position length xs.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write rotations :: [a] -> [[a]] listing all left rotations, starting with the unchanged list. Use one result per position, preserve duplicates, and define the result for empty input to be [].
rotations :: [a] -> [[a]]
rotations xs = [drop i xs ++ take i xs | i <- [0..length xs-1]]

main :: IO ()
main = do
  print (rotations "abc")
  print (rotations [1,1])
  print (rotations ([] :: [Int]))
  print (map (\i -> drop i "abc" ++ take i "abc") [0..2])
```

```text
["abc","bca","cab"]
[[1,1],[1,1]]
[]
["abc","bca","cab"]
```

</HaskellTryIt>

| Generator values in order | Test or pattern | Contribution |
|---|---|---|
| `xs = "abc"; i = 0` | no test: pass | `"abc" ++ "" = "abc"` |
| `i = 1` | pass | `"bc" ++ "a" = "bca"` |
| `i = 2` | pass | `"c" ++ "ab" = "cab"` |
| `xs = [1,1]; i = 0,1` | both pass | `[1,1]` twice |
| `xs = []; i` absent from `[0..-1]` | no candidates | none |

The equivalent is `map (\i -> drop i xs ++ take i xs) [0..length xs-1]`. Every cut preserves element order within its two pieces. Repeated rotations are deliberately retained.

</Step>

<Step title="4. Check">

A singleton `[7]` gives `[[7]]`; the number of rotations of a finite list equals its length. The empty source gives zero candidates. Using a final index of length xs would incorrectly add a duplicate unchanged rotation.

</Step>

</Steps>

</details>

### Exam question 16: failed patterns and successful tests (5 marks)

Evaluate `[x+1 | Just x <- [Nothing,Just 0,Just 2,Nothing,Just (-1)], x >= 0]`, distinguishing pattern failure from test failure.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Evaluate asks for values; distinguishing failures requires explaining why each omitted candidate disappears. The pattern extracts the number before the test can use it.

</Step>

<Step title="2. Plan">

Use the refutable-pattern template. Nothing contributes an empty list; Just x reaches the nonnegative test. Transform only the survivors.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Evaluate [x+1 | Just x <- [Nothing,Just 0,Just 2,Nothing,Just (-1)], x >= 0], distinguishing pattern failure from test failure.
main :: IO ()
main = do
  print [x+1 | Just x <- [Nothing,Just 0,Just 2,Nothing,Just (-1)], x >= 0]
  print (concatMap (\v -> case v of { Just x -> if x >= 0 then [x+1] else []; Nothing -> [] }) [Nothing,Just 0,Just 2,Nothing,Just (-1)])
```

```text
[1,3]
[1,3]
```

</HaskellTryIt>

| Generator values in order | Test or pattern | Contribution |
|---|---|---|
| first `Nothing` | pattern fails; no test | none |
| `Just 0` | matches; True | `1` |
| `Just 2` | matches; True | `3` |
| second `Nothing` | pattern fails | none |
| `Just (-1)` | matches; False | none |

The result is `[1,3]`. Replacing the generator pattern with a partial helper would lose the safe-skip behaviour unless the helper handles Nothing explicitly.

</Step>

<Step title="4. Check">

### Exam question 17: let and a conditional result (5 marks)

Write `classify :: [Int] -> [(Int,String)]` pairing each input with "large" if its square exceeds 4 and "small" otherwise. Name the square with let inside the comprehension.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for a pair per input. Exceeds means greater than, not greater than or equal. The local square must be named, but it must not filter inputs.

</Step>

<Step title="2. Plan">

Generate x, bind s = x*x, and return a pair whose second field uses if. The condition belongs to the output, not a separate qualifier.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write classify :: [Int] -> [(Int,String)] pairing each input with "large" if its square exceeds 4 and "small" otherwise. Name the square with let inside the comprehension.
classify :: [Int] -> [(Int,String)]
classify xs = [(x,if s > 4 then "large" else "small") | x <- xs, let s = x*x]

main :: IO ()
main = do
  print (classify [-3,-2,0,2,3])
  print (classify [])
```

```text
[(-3,"large"),(-2,"small"),(0,"small"),(2,"small"),(3,"large")]
[]
```

</HaskellTryIt>

| Generator values in order | Test or pattern | Contribution |
|---|---|---|
| `x = -3; s = 9` | no guard; condition True | `(-3,"large")` |
| `x = -2; s = 4` | condition False | `(-2,"small")` |
| `x = 0; s = 0` | condition False | `(0,"small")` |
| `x = 2; s = 4` | condition False | `(2,"small")` |
| `x = 3; s = 9` | condition True | `(3,"large")` |

All candidates pass the generator. The equivalent is `map (\x -> let s = x*x in (x,if s > 4 then "large" else "small")) xs`. Notice that the expression let needs in, unlike the qualifier let.

</Step>

<Step title="4. Check">

For `[2]`, square 4 takes the small branch. Negative -3 still has square 9. The empty-input check yields no pairs. These examples use small Int inputs to avoid overflow.

</Step>

</Steps>

### Exam question 18: transpose with a stated width (6 marks)

Write `transposeRect :: Int -> [[a]] -> [[a]]` using nested comprehensions. The first argument is a nonnegative width; assume every row has exactly that many entries. Keep columns in order. For no rows, return one empty column per stated position.

<details>

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Write asks for a polymorphic matrix transformation. The explicit width makes even an empty matrix unambiguous. The rectangular-input precondition makes indexing safe.

</Step>

<Step title="2. Plan">

For column j from zero through width minus one, collect row !! j for every row. The outer output is an inner list, so columns remain separate.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: Write transposeRect :: Int -> [[a]] -> [[a]] using nested comprehensions. The first argument is a nonnegative width; assume every row has exactly that many entries. Keep columns in order. For no rows, return one empty column per stated position.
transposeRect :: Int -> [[a]] -> [[a]]
transposeRect width rows = [[row !! j | row <- rows] | j <- [0..width-1]]

main :: IO ()
main = do
  print (transposeRect 2 [[1,2],[3,4],[5,6]])
  print (transposeRect 0 ([[],[]] :: [[Int]]))
  print (transposeRect 2 ([] :: [[Int]]))
```

```text
[[1,3,5],[2,4,6]]
[]
[[],[]]
```

</HaskellTryIt>

| Generator values in order | Test or pattern | Contribution |
|---|---|---|
| `j = 0; row = [1,2],[3,4],[5,6]` | all indices valid | column `[1,3,5]` |
| `j = 1; same rows` | all indices valid | column `[2,4,6]` |
| width 0 | no j candidates | no columns |
| width 2; no rows | j = 0,1 pass; no inner candidates | two empty columns |

The equivalent is `map (\j -> map (\row -> row !! j) rows) [0..width-1]`. The given width, rather than head rows, supplies column positions. No indexing is attempted if there are no rows.

</Step>

<Step title="4. Check">

At width 1 with `[[7],[8]]` the result is `[[7,8]]`. Width zero gives no columns. Ragged inputs violate the precondition and may fail on !!; they are outside this specification.

</Step>

</Steps>

</details>

## 3. Common exam errors and repairs

| Error | Consequence or GHC diagnostic fragment | Repair |
|---|---|---|
| A numeric expression used as a test on Int | expected Bool, got Int | Compare it with a value |
| A dependent source placed before its binding | `Variable not in scope` | Bind names left to right |
| Semicolons between qualifiers | parse error on input `;` | Use commas |
| `let ... in` as a qualifier | parse error | Omit in in qualifier lets |
| A zero divisor tested by mod before nonzero is checked | runtime `divide by zero` | Check nonzero first |
| Including n in its own proper-divisor list | perfect-number definition is wrong | End that range at n-1 |
| Three independent sources for a zip-like specification | wrong count and order, but valid code | Generate from aligned zipped values |
| Filtering instead of using if in the output | missing output elements | Choose a value for each candidate |
| Flattening a matrix when rows must remain | flat list instead of nested list | Put the inner comprehension in the output |

The diagnostic fragments above are recognisable parts, not full transcripts: GHC also includes source locations and type context. Logical errors often compile without any diagnostic, so types alone do not check the specification.
