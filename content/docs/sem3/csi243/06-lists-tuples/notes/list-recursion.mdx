Chapter 5 recursed on numbers by counting towards a base case. Lists recurse the same way, but the shrinking is structural: each step removes the head and recurses on the tail.

The whole technique rests on one observation from the previous lesson: **every list is either empty, or an element consed onto another list.**

## 1. The standard split

That observation gives an exhaustive pair of patterns:

| Pattern | Matches | Role |
|---|---|---|
| `[]` | The empty list | **Base case** — nothing left to process |
| `(x:xs)` | A non-empty list | **Recursive step** — `x` is the head, `xs` is the tail |

Every recursive list function in this chapter has that shape:

```haskell
functionName []     = -- the answer for an empty list
functionName (x:xs) = -- combine x with functionName xs
```

The recursion terminates because `xs` is always one element shorter than the list you started with, so repeated calls must reach `[]`.

<Callout type="info" title="Naming convention">
The plural `xs` is read “exes” and means “the rest of the x values”. The course lecture notes recommend ending list argument names with `s` for exactly this reason: `ints`, `lists`, `scores`.
</Callout>

<CommonMistake title="Forgetting the [] equation">
Every recursive list function needs a `[]` case, even when the problem statement never mentions an empty list explicitly — it is what stops the recursion. Skip it and GHC compiles the function anyway, because the type checker only confirms types line up, not that every pattern is covered. The very first call on `[]` then crashes with `Non-exhaustive patterns`.
</CommonMistake>

## 2. Defining the Prelude functions

The best way to understand these is to write them. Each one is two lines.

```haskell
-- Is the list empty?
null' :: [a] -> Bool
null' []    = True
null' (_:_) = False

-- How many elements?
length' :: [a] -> Int
length' []     = 0
length' (_:xs) = 1 + length' xs

-- Add up the elements.
sum' :: [Integer] -> Integer
sum' []     = 0
sum' (x:xs) = x + sum' xs

-- Multiply the elements.
product' :: [Integer] -> Integer
product' []     = 1
product' (x:xs) = x * product' xs
```

Note the base cases. `sum' [] = 0` and `product' [] = 1` are not arbitrary: they are the values that leave the result unchanged, so `sum' [5]` correctly gives `5 + 0`.

`length'` uses `_` for the head because the *value* is irrelevant — only that an element exists.

### Tracing `length' [4,7,2]`

```text
length' [4,7,2]
= 1 + length' [7,2]
= 1 + (1 + length' [2])
= 1 + (1 + (1 + length' []))
= 1 + (1 + (1 + 0))          <- base case reached
= 1 + (1 + 1)
= 1 + 2
= 3
```

The same unwinding and rewinding as Chapter 5, with the list shrinking instead of a number.

## 3. Returning a list

<RecognitionStrategy title="Scalar result or list result?">
Check the return type before writing the recursive step. If the signature ends in a non-list type (`Int`, `Bool`, `Integer`…), the recursive step *combines* `x` with the recursive call using an operator (`+`, `&&`, comparison, …). If it ends in `[a]`, the recursive step usually *conses* `x` (or nothing, if `x` is filtered out) onto the recursive call. Mixing the two up — consing where a scalar is expected, or using `+` where a list is expected — is caught immediately as a type error.
</RecognitionStrategy>

So far the results were numbers. When the result is itself a list, the recursive step **conses** onto the result of the recursive call:

```haskell
-- Double every element.
doubleAll :: [Integer] -> [Integer]
doubleAll []     = []
doubleAll (x:xs) = (x * 2) : doubleAll xs
```

```text
ghci> doubleAll [1,2,3]
[2,4,6]
```

```text
doubleAll [1,2,3]
= 2 : doubleAll [2,3]
= 2 : (4 : doubleAll [3])
= 2 : (4 : (6 : doubleAll []))
= 2 : (4 : (6 : []))
= [2,4,6]
```

The base case returns `[]` because the result of transforming nothing is nothing.

## 4. Filtering: keeping some elements

When only some elements belong in the result, the recursive step uses guards to decide whether to cons the head or skip it:

```haskell
-- Keep only the elements larger than y.
largerY :: [Integer] -> Integer -> [Integer]
largerY [] _ = []
largerY (x:xs) y
  | x > y     = x : largerY xs y
  | otherwise = largerY xs y
```

```text
ghci> largerY [3,1,7,10] 4
[7,10]
ghci> largerY [] 4
[]
```

The two branches differ in one detail that is easy to miss: when the element is kept, it is consed on; when it is skipped, the recursive call is returned directly. Both branches still recurse on `xs`, so the list keeps shrinking either way.

Applying the same shape to a different test:

```haskell
-- Keep only the positive elements.
positiveNumbers :: [Integer] -> [Integer]
positiveNumbers [] = []
positiveNumbers (x:xs)
  | x > 0     = x : positiveNumbers xs
  | otherwise = positiveNumbers xs
```

```text
ghci> positiveNumbers [-1,5,-3,8]
[5,8]
```

<Callout type="info" title="You are writing filter">
`largerY` and `positiveNumbers` share a shape: recurse down the list, keep elements passing a test. Chapter 7 introduces `filter`, which captures that shape once so you never write it again. Writing it by hand first is what makes `filter` obvious later.
</Callout>

## 5. Inspecting more than one element

Some questions need two elements at a time. The pattern `(x:y:rest)` matches a list of **at least two** elements:

```haskell
-- Is the list sorted in descending order?
isSorted :: [Integer] -> Bool
isSorted []  = True
isSorted [_] = True
isSorted (x:y:rest)
  | x >= y    = isSorted (y:rest)
  | otherwise = False
```

```text
ghci> isSorted [5,3,1]
True
ghci> isSorted [3,1,5]
False
ghci> isSorted []
True
```

Three cases are needed, and all three come from the specification: an empty list is sorted; a one-element list is sorted; a longer list is sorted when its first two elements are in order **and** the rest is sorted.

Notice the recursive call is `isSorted (y:rest)`, not `isSorted rest` — `y` must be compared against the element after it, so it stays in the list.

## 6. Recursion with a position counter

To find the element at position `y`, count down as you walk along:

```haskell
-- Return the element at position y paired with y. Lists index from 0.
atPosition :: [a] -> Int -> (Int, a)
atPosition [] _ = error "atPosition: index outside the list"
atPosition (x:xs) y
  | y < 0     = error "atPosition: negative index"
  | y == 0    = (0, x)
  | otherwise = (y, snd (atPosition xs (y - 1)))
```

Two things shrink here: the list loses its head, and `y` decreases. Reaching `y == 0` means the current head is the element wanted.

A simpler version uses the built-in `!!` operator, which returns the element at position `y`:

```haskell
atPosition' :: [a] -> Int -> (Int, a)
atPosition' xs y
  | y < 0          = error "atPosition: negative index"
  | y >= length xs = error "atPosition: index outside the list"
  | otherwise      = (y, xs !! y)
```

Both are acceptable. The recursive version shows the mechanism; the second shows that recognising an existing Prelude function is also a skill.

## 7. Common errors

| Symptom | Cause | Repair |
|---|---|---|
| `Non-exhaustive patterns` | No `[]` equation | Every list recursion needs the empty case |
| Hangs forever | The recursive call passes the same list | Recurse on `xs`, not on the original argument |
| `x : recursiveCall` type error | Consing where the result is not a list | Check the signature's result type |
| Result reversed | Consing onto the wrong end | `x : rest` puts `x` first; use `++` to append |
| `Couldn't match [a] with a` | `x` used where `xs` was meant, or vice versa | `x` is an element, `xs` is a list |
| Wrong total for an empty list | Base case is not the identity value | `sum` needs `0`, `product` needs `1` |

<Accordion title="Check questions 2 and 5">

**2.**

```haskell
myReverse :: [a] -> [a]
myReverse []     = []
myReverse (x:xs) = myReverse xs ++ [x]
```

```text
ghci> myReverse [1,2,3,4]
[4,3,2,1]
```

The head must end up last, so the reversed tail is built first and `[x]` is appended. Note `[x]`, not `x` — `++` joins two *lists*.

<CommonMistake title="This myReverse is O(n²), not O(n)">
`++` walks its entire *left* operand to find the end before it can attach the right one — appending `[x]` costs time proportional to the length of `myReverse xs`. Since that append happens once per element, over the whole list the total work is `1 + 2 + ... + n`, which is `O(n²)`. The function is correct — every test passes — but it gets noticeably slower as the list grows, the same kind of hidden cost [dry-running](/docs/sem3/csi243/05-recursion/notes/dry-running) flags for naive `fib`: right answer, expensive answer.
</CommonMistake>

A faster version avoids `++` entirely by carrying the reversed-so-far result as an extra argument (an **accumulator**), so each step is a single `O(1)` cons instead of an `O(n)` append:

```haskell
-- Faster version: build the result in an accumulator instead of appending.
myReverseFast :: [a] -> [a]
myReverseFast xs = go xs []
  where
    go []     acc = acc
    go (y:ys) acc = go ys (y : acc)
```

```text
ghci> myReverseFast [1,2,3,4]
[4,3,2,1]
```

```text
go [1,2,3,4] []
= go [2,3,4] (1 : [])
= go [3,4]   (2 : (1 : []))
= go [4]     (3 : (2 : (1 : [])))
= go []      (4 : (3 : (2 : (1 : []))))
= [4,3,2,1]              <- base case reached, acc is returned as-is
```

Every step conses one element onto `acc` — no `++`, no re-walking already-built results — so this version is `O(n)`. `go` is a **local helper function**, defined in a `where` clause, that takes one extra argument the "public" `myReverseFast` doesn't need to expose: this accumulator-passing shape is a genuinely different pattern from the "cons in the recursive step" functions earlier in this lesson, and Chapter 5's [dry-running](/docs/sem3/csi243/05-recursion/notes/dry-running) lesson covers it as a general technique for turning `O(n²)` recursions into `O(n)` ones.

**5.**

```haskell
myAppend :: [a] -> [a] -> [a]
myAppend [] ys     = ys
myAppend (x:xs) ys = x : myAppend xs ys
```

Recurse on the **first** list. When it is exhausted, the answer is simply the second list, untouched. The second argument is carried along unchanged, exactly as the base value was in `power`.
