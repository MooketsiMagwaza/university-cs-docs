## 1. General template and translation rules

```text
[ output | generator, generator, test, let binding ]
[ result x y z | x <- xs, y <- source x, test x y, let z = value x y ]
```

`output` is one element. Each generator draws from a list; a test must be Boolean; a let names a value. Qualifiers run left to right. Names become available to later qualifiers and to the output, despite the output being written first. Pieces may repeat or be omitted: you do not need two generators or a let every time.

Translate the qualifiers one at a time. `rest` below means the remaining qualifiers; these are schematic rules rather than runnable Haskell.

```text
No qualifiers:                   [output]
[output | x <- xs, rest]       = concatMap (\x -> [output | rest]) xs
[output | test, rest]          = if test then [output | rest] else []
[output | let y = value, rest] = let y = value in [output | rest]
```

A refutable pattern needs a helper: matching candidates run the rest, nonmatching candidates return `[]`. Do not replace that with a partial lambda which crashes on a failed match. Simplify `concatMap (\x -> [f x]) xs` to `map f xs`; simplify identity output plus a test to `filter`. Use the functions needed by the shape rather than forcing all three into every answer.

For `[x+y | x <- [1,2], y <- [0,3], y > x]`, x = 1 gives `[4]` and x = 2 gives `[5]`. Flattening gives `[4,5]`. The translation is `concatMap (\x -> map (\y -> x+y) (filter (\y -> y > x) [0,3])) [1,2]`. It preserves each branch's position.

Tables sometimes group consecutive candidates with the same behaviour. No test means all candidates pass; none means no element is appended.

## 2. One generator and an output expression

A transformation produces one result per input. The output can have a different type from the source; duplicates survive.

### Template

```text
[f x | x <- xs]
map f xs
```

`xs` supplies inputs, x names one input and f builds one output. Every generated value passes.

### Worked variation: numbers become strings

Change the result type to String. Add one before showing the value; print includes quotation marks.

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  print ([show (x+1) | x <- [-2,0,2]])
  print (map (\x -> show (x+1)) [-2,0,2])
```

```text
["-1","1","3"]
["-1","1","3"]
```

## 3. One test: select before transforming

A Boolean qualifier filters the original candidate. Failed candidates emit nothing, not a placeholder.

### Template

```text
[f x | x <- xs, p x]
map f (filter p xs)
```

p must return Bool. Test the original x before evaluating the output.

### Worked variation: magnitude test then negation

Use a magnitude test, so a negative candidate can pass. Negation changes only the survivors.

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  print ([-x | x <- [-3,0,2], abs x > 1])
  print (map negate (filter (\x -> abs x > 1) [-3,0,2]))
```

```text
[3,-2]
[3,-2]
```

</HaskellTryIt>

|---|---|---|

| `x = 0` | False | none |
| `x = 2` | True | `-2` |

Collect the contributions in the table from top to bottom to get `[3,-2]`. The second print uses the equivalent implementation.

## 4. Several tests: every requirement must pass

Tests separated by commas mean all conditions must hold. Later tests are reached only after earlier ones pass; this can protect partial operations.

### Template

```text
[f x | x <- xs, p x, q x]
map f (filter (\x -> p x && q x) xs)
```

p and q are Boolean functions. Their conjunction is &&, not ||.

### Worked variation: sign and parity

Combine positivity and evenness. Only 2 passes both; test before adding ten.

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  print ([x+10 | x <- [-2,0,2,3], x > 0, even x])
  print (map (+10) (filter (\x -> x > 0 && even x) [-2,0,2,3]))
```

```text
[12]
[12]
```

</HaskellTryIt>

| Generator values in order | Test or pattern | Contribution |
|---|---|---|
| `x = -2` | first False; stop | none |
| `x = 0` | first False; stop | none |
| `x = 2` | True, True | `12` |
| `x = 3` | True, False | none |

Collect the contributions in the table from top to bottom to get `[12]`. The second print uses the equivalent implementation.

### Worked variation: membership and exclusion

| last `c = a` | True, False | none |

## 5. Two independent generators: order matters

Two sources produce every combination, a Cartesian product. Finish the inner run for one outer value before advancing the outer generator.

### Template

```text
[f x y | x <- xs, y <- ys, p x y]
concatMap (\x -> map (f x) (filter (p x) ys)) xs
```

x is fixed while y runs through its source. The last generator varies fastest.

### Worked variation: subtraction shows order

Use subtraction so both order and negative results are visible. Equal results at different positions are kept.

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  print ([x-y | x <- [0,2], y <- [1,3]])
  print (concatMap (\x -> map (\y -> x-y) [1,3]) [0,2])
```

```text
[-1,-3,1,-1]
[-1,-3,1,-1]
```

</HaskellTryIt>

|---|---|---|
| `(x,y) = (0,1)` | pass | `-1` |
| `(0,3)` | pass | `-3` |
| `(2,1)` | pass | `1` |
| `(2,3)` | pass | `-1` |

Collect the contributions in the table from top to bottom to get `[-1,-3,1,-1]`. The second print uses the equivalent implementation.

## 6. Dependent generators: a source for each outer value

A later source can depend on an earlier variable. Each outer value may therefore own a different number of inner candidates.

### Template

```text
[f x y | x <- xs, y <- source x, p x y]
concatMap (\x -> map (f x) (filter (p x) (source x))) xs
```

source x builds the inner list for this x. Its names must already be in scope.

### Worked variation: inclusive bounds

Use a shrinking source. Inclusive ranges give row lengths 3, 2 and 1, including equality.

<HaskellTryIt>

## 7. Patterns in generators: unpack or skip

A tuple pattern binds fields. A refutable pattern is one that can fail to match a candidate. In a list comprehension, failure skips that candidate; it does not crash the whole comprehension.

### Template

```text
[f a b | (a,b) <- pairs, p a b]
[f x | Just x <- values]
-- translation: concatMap helper values
-- helper (Just x) = [f x]; helper Nothing = []
```

Pairs match every member of a well-typed pair source. Just does not match Nothing. A nonempty-list pattern does not match an empty list.

### Worked variation: tuple fields with a guard

Unpack every pair, then select by its numeric field. No pair fails the pattern itself.

<HaskellTryIt>

```haskell
main :: IO ()
main = do
  print ([name | (name,n) <- [("Ada",2),("Bo",0),("Cy",3)], n > 1])
  print (map fst (filter (\pair -> snd pair > 1) [("Ada",2),("Bo",0),("Cy",3)]))
```

```text
["Ada","Cy"]
["Ada","Cy"]
```

</HaskellTryIt>

| Generator values in order | Test or pattern | Contribution |
|---|---|---|
| `("Ada",2)` | pattern matches; True | `"Ada"` |
| `("Bo",0)` | pattern matches; False | none |
| `("Cy",3)` | pattern matches; True | `"Cy"` |

Collect the contributions in table order to get `["Ada","Cy"]`. The second print checks the equivalent implementation.

### Worked variation: constructor failure

<HaskellTryIt>

## 12. Tuple builders: pairs, triples, triangles and aligned positions

Each output tuple is one list element. Independent generators build combinations. For matching positions, use zip or a shared valid index. Ordered side-length ranges avoid permutations of a triangle.

### Template


| Requirement | Comprehension | Higher-order functions | Recursion |
|---|---|---|---|
| Transform every element | one generator | `map f` | cons transformed head, recurse on tail |
| Select elements | Boolean qualifier | `filter p` | guard chooses cons or skip |
| Transform survivors | output plus test | `map f (filter p xs)` | test head, transform if kept |
| Flatten branches | extra generator | `concatMap` | append each inner result |
| Preserve rows | inner comprehension as output | outer map, inner map/filter | cons completed row |
| Align positions | source is zip or valid indices | zip or zipWith | consume both lists together |
| Return one total | wrap in sum or length | sum, length or a fold | combine head with recursive total |

Use a comprehension when each output comes from generated candidates. Prefer direct recursion when a process carries changing state, stops according to earlier results, or consumes two lists in a special way. Prefer `zipWith (+)` for pointwise sums and `map abs` for a bare transformation. An outer function can sum a comprehension, but the comprehension itself always returns a list. Avoid indexed transpose on ragged rows: indexing is partial, meaning some inputs make it fail. With infinite sources, an infinite inner run may prevent later outer branches being reached; finite examples do not justify reordering an infinite search.

### GHC diagnostic fragments

GHC includes locations, inferred types and suggestions. These are recognisable fragments, not complete transcripts; invalid attempts stay inline, outside runnable blocks.

| Wrong attempt | Diagnostic or reasoning failure | Repair |
|---|---|---|
| `[x \| x <- [1..3]; even x]` | parse error on input `;` | Use commas between qualifiers |
| `[x \| x <- [1..3], y > 0]` with no y binding | `Variable not in scope: y` | Bind y before testing it |
| guard `x+1` with an Int x | expected Bool, got Int | Use a comparison |
| generator `x <- (3 :: Int)` | a list is expected | Supply `[3]` |
| output if without else | parse error | Supply both branches |
| predicting zip order for two generators | valid program, wrong result | Finish each inner run |

## Summary

<Callout type="key" title="Remember">
Choose source, pattern, tests and output separately. Trace qualifiers left to right; the final generator varies fastest. Failed tests and generator patterns contribute nothing. Let binds without adding candidates. Nested output preserves rows; extra generators flatten branches. Translate using concatMap for generators, filter for selection and map for output. Preserve duplicates and distinguish candidate counts from survivor counts.
</Callout>

## Check your understanding

<CheckQuestion question="What happens when a Just generator pattern meets Nothing?">
That candidate is skipped; the next candidate is tried. Nothing emits no placeholder.
</CheckQuestion>

<CheckQuestion question="Why does swapping two independent generators change output order?">
The later generator varies fastest, so swapping them changes which inner run is completed first.
</CheckQuestion>

<CheckQuestion question="Why can an empty row remain in a nested result?">
The inner comprehension returns an empty list which is still one outer output element.
</CheckQuestion>

<CheckQuestion question="Does a comprehension let add combinations or need in?">
Neither. It binds a value for the current branch; later qualifiers and the output can use it.
</CheckQuestion>

Wrap the remaining translated comprehension in a lambda and use concatMap over the generator source.
