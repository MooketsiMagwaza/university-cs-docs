A **tuple** is a finite sequence of values of **possibly different types**. Components are separated by commas and enclosed in round brackets.

```haskell
(50, "csi243", "2013/14")
('2', False)
```

Where a list is homogeneous and variable in length, a tuple is heterogeneous and fixed. That single contrast decides which one a problem needs.

## 1. Arity

**Arity** is the number of components in a tuple, and it is part of the type.

| Tuple | Arity | Name |
|---|---|---|
| `()` | 0 | Unit |
| `(1, 'a')` | 2 | Pair |
| `(1, 'a', True)` | 3 | Triple |
| `(1, 2, 3, 4)` | 4 | 4-tuple |

Two rules follow:

- **Tuples of arity 1 are not allowed.** `(5)` is just `5` in brackets, not a tuple.
- **The unit `()`** is the empty tuple. You have already met it in `IO ()`, where it means the action returns no useful data.

## 2. The type records every position

A tuple's type lists the type of each position, in order:

```haskell
student :: (String, Integer, Bool)
student = ("Kago", 2026001, True)
```

This means `(String, Integer)` and `(Integer, String)` are **different types**, and neither can be used where the other is expected. Position carries meaning.

```text
ghci> :type ('2', False)
('2', False) :: (Char, Bool)
ghci> :type (50, "csi243", "2013/14")
(50, "csi243", "2013/14") :: Num a => (a, String, String)
```

<QuizRef src="sem3/csi243/06-lists-tuples/notes/tuples" id="check-type-records-position" />

## 3. Tuples are immutable and fixed

The elements in a tuple are fixed. You cannot add elements to a tuple as the program runs, and there is no cons operator for tuples.

Use a tuple when you know **in advance** how many values are to be stored, and a list when the count can vary.

<Callout type="warn" title="Arity cannot change">
Adding a component produces a value of a *different type*, not a longer tuple. A function returning `(Int, Int)` can never return `(Int, Int, Int)`.
</Callout>

<QuizRef src="sem3/csi243/06-lists-tuples/notes/tuples" id="check-immutable-and-fixed" />

## 4. `fst` and `snd`

Most tuples are pairs, so the Prelude provides two functions for them:

```text
ghci> fst (5, 'h')
5
ghci> snd (5, 'h')
'h'
ghci> fst ("Tebogo", "Lesego")
"Tebogo"
```

They are defined with tuple patterns, exactly as Chapter 4 showed:

```haskell
fst :: (a, b) -> a
fst (x, _) = x

snd :: (a, b) -> b
snd (_, x) = x
```

<Callout type="warn" title="Pairs only">
`fst` and `snd` work only on tuples of arity 2. For a triple, use a pattern: `(a, _, _)`.
</Callout>

<QuizRef src="sem3/csi243/06-lists-tuples/notes/tuples" id="check-fst-and-snd" />

## 5. Tuple patterns

Destructuring is usually clearer than repeated `fst`/`snd` calls:

```haskell
-- Add the components of a pair.
addPair :: (Integer, Integer) -> Integer
addPair (x, y) = x + y

-- Swap the components of a pair.
swap' :: (a, b) -> (b, a)
swap' (x, y) = (y, x)

-- Take the middle of a triple.
middle :: (a, b, c) -> b
middle (_, y, _) = y
```

```text
ghci> addPair (3, 4)
7
ghci> swap' (1, "one")
("one",1)
```

A complete program runs all three functions on a couple of different tuples each:

```haskell
main :: IO ()
main = do
  print (addPair (3, 4))
  print (addPair (10, -2))
  print (swap' (1, "one"))
  print (swap' ("Kago", True))
  print (middle (1, 2, 3))
  print (middle ('a', 'b', 'c'))
```

Exact output:

```text
7
8
("one",1)
(True,"Kago")
2
'b'
```

`swap'` is polymorphic in both positions — it works the same way whether the pair holds `(Integer, String)` or `(String, Bool)`, because `swap' (x, y) = (y, x)` never inspects what `x` or `y` actually are.

Patterns nest, so a tuple inside a tuple can be taken apart in one step:

```text
ghci> let nested = ((1, 'a'), "foo")
ghci> snd (fst nested)
'a'
```

<SiteDiagram chart={`flowchart TD

  A --> A1["1"]

`} caption="nested = ((1,'a'), 'foo') as a small tree. fst reaches the left branch, snd the right; snd (fst nested) walks left then right." />

`fst nested` walks to the left branch, `(1, 'a')`; `snd` of that walks to its right branch, `'a'` — reading the diagram top to bottom traces exactly the calls made.

Or with a single pattern:

```haskell
innerChar :: ((Int, Char), String) -> Char
innerChar ((_, c), _) = c
```

## 6. Nesting

There are no restrictions on the types of a tuple's components. They may be tuples, lists, or anything else:

```haskell
(50, ("cs", False))                  -- tuple of tuples
(['2', 'a', 'x'], [False, False])    -- tuple of lists
[("cs", False), ("sc", True)]        -- list of tuples
```

The last is the important one. **A list of tuples** is how Haskell represents a table before custom types are available: every row has the same shape, and there can be any number of rows.

```haskell
marks :: [(String, Integer)]
marks = [("Kago", 72), ("Naledi", 68), ("Thato", 91)]
```

```text
ghci> length marks
3
ghci> fst (head marks)
"Kago"
ghci> map snd marks
[72,68,91]
```

The last line uses `map` to apply `snd` to every pair in `marks` in turn, pulling out just the marks — read `map f lst` for now as "run `f` on each element of `lst`, and collect the results" (Chapter 7 covers `map` properly); here `f` is `snd`, so each `(name, mark)` pair contributes its `mark`.

A complete program pulls the same table apart four different ways:

```haskell
main :: IO ()
main = do
  print (length marks)
  print (fst (head marks))
  print (map snd marks)
  print (map fst marks)
```

Exact output:

```text
3
"Kago"
[72,68,91]
["Kago","Naledi","Thato"]
```

`map fst marks` mirrors `map snd marks` exactly, but pulls the other component out of every row — the names instead of the marks, in the same row order the table was written in.

## 7. Returning several results

A Haskell function returns one value. A tuple lets that one value carry several results:

```haskell
-- Return the sum and the absolute difference of two integers.
addAndDifference :: Integer -> Integer -> (Integer, Integer)
addAndDifference x y = (x + y, abs (x - y))
```

```text
ghci> addAndDifference 9 4
(13,5)
```

A complete program tries three pairs, including one where the arguments are swapped and one where they're equal:

```haskell
main :: IO ()
main = do
  print (addAndDifference 9 4)
  print (addAndDifference 4 9)
  print (addAndDifference 5 5)
```

Exact output:

```text
(13,5)
(13,5)
(10,0)
```

The first two lines are identical: `abs (x - y)` makes the difference symmetric, so swapping which argument is `x` and which is `y` changes nothing about either component. The third shows the zero case — two equal values sum to double one of them and differ by nothing.

The caller takes it apart with a pattern:

```haskell
report :: Integer -> Integer -> String
report x y = "Sum " ++ show total ++ ", difference " ++ show diff
  where
    (total, diff) = addAndDifference x y
```

## 8. Tuples as arguments

A tuple may also be the input, which is the curried-versus-tupled distinction from Chapter 3:

```haskell
add :: (Integer, Integer) -> Integer
add (x, y) = x + y
```

<ComparisonTable
  columns={[
    { header: 'Form', key: 'form' },
    { header: 'Signature', key: 'sig' },
    { header: 'Call', key: 'call' },
    { header: 'Use when', key: 'use' }
  ]}
  rows={[
    { form: 'Curried', sig: 'Integer -> Integer -> Integer', call: 'add 5 3', use: 'Normal Haskell style; supports partial application' },
    { form: 'Tupled', sig: '(Integer, Integer) -> Integer', call: 'add (5, 3)', use: 'The arguments genuinely arrive as one grouped value' }
  ]}
  highlightCol="use"
/>

Prefer the curried form unless the pair is a single conceptual thing — a coordinate, a key-value entry, a range.

These two shapes have standard names and standard converters in the Prelude: `curry :: ((a, b) -> c) -> a -> b -> c` turns a tupled function curried, and `uncurry :: (a -> b -> c) -> (a, b) -> c` does the reverse. Chapter 7's [Currying and Sections](/docs/sem3/csi243/07-higher-order/notes/currying-and-sections) lesson covers both in full, with worked examples — this chapter only needs the concept of the two shapes, not the conversion functions themselves.

<CommonMistake title="Passing a tuple to a curried function">
`add (5, 3)` looks like it should work, but if `add :: Integer -> Integer -> Integer` is curried, it doesn't — `(5, 3)` is a *single* pair, and `add` expects an `Integer` first, not a tuple. GHC reports a type error naming `(Integer, Integer)` where `Integer` was wanted. Either call `add 5 3` directly, or use `uncurry add (5, 3)` if the pair genuinely needs to travel together.
</CommonMistake>

The deciding question: **can the number of components change?** If yes, you need a list. If no, and the parts mean different things, you need a tuple.

<RecognitionStrategy title="List or tuple, at a glance">
Ask one question: can the number of components change while the program runs? If yes — a growing set of scores, names, or words — use a list. If no — a fixed grouping like a coordinate, a date, or one row of a table — use a tuple, even if it only ever holds two values.
</RecognitionStrategy>

## 10. Common errors

| Attempt | Problem | Repair |
|---|---|---|
| `fst (1,2,3)` | `fst` works only on pairs | Use a pattern `(a,_,_)` |
| `(5)` treated as a tuple | Arity 1 does not exist | `(5, x)` or just `5` |
| `(1,2) == (2,1)` expected `True` | Position is part of the value | Compare the intended components |
| `x : (1,2)` | Tuples have no cons | Use a list if it must grow |
| Passing `(5,3)` to `add :: Int -> Int -> Int` | That signature is curried | `add 5 3`, or change the signature |
| `[(1,'a'), (2,3)]` | List elements must share one type | Make every tuple the same type |
