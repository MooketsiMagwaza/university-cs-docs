## 1. words: split arbitrary whitespace

`words` separates text into nonempty runs of characters that are not whitespace. Whitespace includes spaces, tabs and newlines, so it is wider than the literal space character. Words retain encounter order; punctuation and letter case are unchanged. Empty or all-whitespace input gives `[]`, with no missing-result constructor or exception.

### Template and type

```haskell
words :: String -> [String]
```

```text
words text
```

`text` is one string; the answer is a list of whole strings. Whitespace runs disappear rather than becoming empty fields.

### Worked variation: repeated spaces

<HaskellTryIt>

```haskell
main :: IO ()
main = print (words "  red   blue ")
```

```text
["red","blue"]
```

</HaskellTryIt>

Skip leading spaces, collect red, skip the gap, collect blue and discard the last space. The gap lengths are lost.

### Worked variation: tabs and newlines

<HaskellTryIt>

```haskell
main :: IO ()
main = print (words "a\tb\nc")
```

```text
["a","b","c"]
```

</HaskellTryIt>

The tab ends a and the newline ends b. The three non-whitespace runs remain in order.

### Worked variation: empty and whitespace-only input

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((words "", words " \t\n"))
```

```text
([],[])
```

</HaskellTryIt>

Neither input contains a non-whitespace run. Neither produces a singleton empty string.

### Worked variation: normalising a round trip

<HaskellTryIt>

```haskell
main :: IO ()
main = print (unwords (words "  one\ttwo  "))
```

```text
"one two"
```

</HaskellTryIt>

Splitting retains one and two only. Joining supplies one ordinary space and cannot recover the tab or outer spaces.

## 2. unwords: join with ordinary spaces

`unwords` joins a list of strings in their existing order, putting exactly one ordinary space between adjacent elements. It does not inspect, trim or split an element. An empty list gives the empty string. An empty element still occupies a position, so it can create leading, trailing or repeated spaces. There is no failure result.

### Template and type

```haskell
unwords :: [String] -> String
```

```text
unwords pieces
```

`pieces` contains strings, not characters. For finite inputs, the alternative `intercalate " " pieces` gives the same text.

### Worked variation: ordinary word list

<HaskellTryIt>

```haskell
normaliseWords :: String -> String
normaliseWords = unwords . words

main :: IO ()
main = print (unwords ["red","blue"])
```

```text
"red blue"
```

</HaskellTryIt>

There is one boundary between two strings, so one space is inserted and neither end receives a separator.

### Worked variation: empty list and singleton

<HaskellTryIt>

```haskell
normaliseWords :: String -> String
normaliseWords = unwords . words

main :: IO ()
main = print ((unwords [], unwords ["solo"]))
```

```text
("","solo")
```

</HaskellTryIt>

Zero pieces have no content; one piece has no boundary. No space is added in either case.

### Worked variation: empty elements

<HaskellTryIt>

```haskell
normaliseWords :: String -> String
normaliseWords = unwords . words

main :: IO ()
main = print (unwords ["","a",""])
```

```text
" a "
```

</HaskellTryIt>

There are three pieces and two boundaries. Both boundaries receive a space even though the first and last pieces are empty.

### Worked variation: the reverse round trip can lose elements

<HaskellTryIt>

```haskell
normaliseWords :: String -> String
normaliseWords = unwords . words

main :: IO ()
main = print (words (unwords ["a b",""]))
```

```text
["a","b"]
```

</HaskellTryIt>

Joining gives a b followed by a space. Splitting again breaks the first piece into two words and forgets the empty final piece.

## 3. lines: split at newline characters

`lines` splits only at newline characters, not at every whitespace character. It removes each newline delimiter but preserves spaces, tabs and empty lines. An empty input gives `[]`. A final newline terminates the preceding line; it does not add an extra final empty element. Consecutive newlines can nevertheless encode empty lines. No newline is an error and no search can fail here.

### Template and type

```haskell
lines :: String -> [String]
```

```text
lines text
```

`text` is a whole string. Each result element is a line without its newline. A carriage return is an ordinary retained character for this pure function.

### Worked variation: text without a final newline

<HaskellTryIt>

```haskell
main :: IO ()
main = print (lines "a\nb")
```

```text
["a","b"]
```

</HaskellTryIt>

The first newline finishes a; the remaining b is the final line even without a terminating newline.

### Worked variation: blank lines and a final delimiter

<HaskellTryIt>

```haskell
main :: IO ()
main = print (lines "a\n\nb\n")
```

```text
["a","","b"]
```

</HaskellTryIt>

The first delimiter ends a, the next ends an empty line, and the final delimiter ends b without creating another element.

### Worked variation: three empty boundaries

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((lines "", lines "\n", lines "\n\n"))
```

```text
([],[""],["",""])
```

</HaskellTryIt>

No characters mean no lines. Each newline can terminate an empty line, so one and two newlines give one and two empty strings.

### Worked variation: whitespace is preserved

<HaskellTryIt>

```haskell
main :: IO ()
main = print (lines "a b\tc\r\n")
```

```text
["a b\tc\r"]
```

</HaskellTryIt>

Only the newline splits. The space, tab and carriage return stay inside the single line; print displays the last two with escapes.

<Step title="2. Plan">

### Common errors

Using `words` to preserve blank lines is accepted Haskell but loses the blank lines. Use `lines`. `lines ["a"]` has the wrong list depth and produces `Couldn't match type`; supply `"a"`. Do not assume `lines` removes a carriage return from an in-memory string.

### Practice with an answer

<summary>Answer</summary>

`["a b"]` versus `["a","b"]`: spaces do not delimit lines.

## 4. unlines: terminate every supplied line

`unlines` concatenates the given strings in order, adding a newline after every element, including the last and any empty element. Empty input gives `""`; a singleton empty line gives a one-newline string. It does not reject embedded newlines, but those make later splitting produce more lines. There is no failure form.

For finite text, `unlines (lines text)` recovers it exactly when it is empty or already ends in a newline. Otherwise the join adds the missing final terminator. This condition concerns this direction only; the reverse direction also needs each supplied line to contain no newline.

### Template and type

```haskell
unlines :: [String] -> String
```

```text
unlines lineTexts
```

`lineTexts` is a list of strings. Unlike `intercalate "\n"`, unlines adds a terminator after the final element as well. The finite-list alternative is `concatMap (++ "\n") lineTexts`.

### Worked variation: two lines

<HaskellTryIt>

```haskell
main :: IO ()
main = print (unlines ["a","b"])
```

```text
"a\nb\n"
```

</HaskellTryIt>

Append a newline to a, append one to b, then concatenate. The last newline belongs to the result string.

### Worked variation: no lines versus an empty line

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((unlines [], unlines [""]))
```

```text
("","\n")
```

</HaskellTryIt>

No elements generate no terminators. One empty element generates a newline, so these inputs remain distinguishable.

### Worked variation: missing terminator in a round trip

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((unlines (lines "a\nb"), unlines (lines "a\nb\n")))
```

```text
("a\nb\n","a\nb\n")
```

</HaskellTryIt>

Both inputs split to the same two lines. Joining supplies a final newline, losing the distinction between terminated and unterminated text.

### Worked variation: embedded delimiter changes the reverse round trip

<HaskellTryIt>

```haskell
main :: IO ()
main = print (lines (unlines ["a\nb",""]))
```

```text
["a","b",""]
```

</HaskellTryIt>

The joined text is a newline b newline newline. Splitting produces three lines, not the original two elements.

### Exam question 4: unlines (4 marks)

Expecting `unlines ["a","b"]` to omit the final newline is a logic error. Use `intercalate "\n"` for separators only. Passing a `String` directly to `unlines` produces `Couldn't match type`; it needs `[String]`.

Predict `unlines ["","x",""]`.

`"\nx\n\n"`: every one of the three supplied lines is terminated.

## 5. intersperse: insert one element

`intersperse` inserts one separator element between each pair of adjacent input elements. It preserves order and duplicates, adds nothing at either end, and returns `[]` for empty input. The separator must have the same type as one element. There is no missing-result form. A string therefore needs a `Char` separator, while a list of strings needs a `String` separator.

### Template and type

```haskell
intersperse :: a -> [a] -> [a]
```

```text
intersperse separator elements
```

`separator` is one value of type `a`; `elements` is a list of those values. A list of length n has n minus one boundaries when n is positive.

### Worked variation: characters in a string

The elements are a, b and c. Insert a hyphen in each of the two gaps; the output is still a String.

<HaskellTryIt>

```haskell
import Data.List (intersperse)

main :: IO ()
main = print (intersperse '-' "abc")
```

```text
"a-b-c"
```

</HaskellTryIt>

### Worked variation: whole strings as elements

Here each element is a whole string. A slash string becomes an extra list element; the output has not been flattened.

<HaskellTryIt>

```haskell
import Data.List (intersperse)

main :: IO ()
main = print (intersperse "/" ["a","b","c"])
```

```text
["a","/","b","/","c"]
```

</HaskellTryIt>

### Worked variation: empty and singleton lists

Neither zero nor one input element has a gap. No separator is emitted in either case.

<HaskellTryIt>

```haskell
import Data.List (intersperse)

main :: IO ()
main = print ((intersperse 0 ([] :: [Int]), intersperse 0 [7]))
```

```text
([],[7])
```

</HaskellTryIt>

`intersperse "," "ab"` mixes a String separator with Char elements. GHC reports `Couldn't match type`; use a character separator or a list of strings. Expecting a trailing separator is an accepted-program logic error.

`[True,False,True]`: insert one Boolean between the two existing ones.

## 6. intercalate: insert lists and flatten

`intercalate` joins a list of lists, placing a separator list between consecutive pieces and then flattening one layer. It preserves the order inside and between pieces. Empty outer input yields `[]`; empty inner pieces still create boundaries. There is no failure form. For strings, the pieces have type `[String]`, the separator has type `String` and the result is one `String`.

### Template and type

```haskell
intercalate :: [a] -> [[a]] -> [a]
```

```text
intercalate separator pieces
```

`separator` is a list and each member of `pieces` is another list of the same element type. The equivalent finite expression is `concat (intersperse separator pieces)`.

### Worked variation: several characters in a delimiter

Insert a two-character separator at both boundaries, then flatten. There is no leading or final separator.

<HaskellTryIt>

```haskell
import Data.List (intercalate, intersperse)

main :: IO ()
main = print (intercalate "::" ["a","b","c"])
```

```text
"a::b::c"
```

</HaskellTryIt>

### Worked variation: numeric pieces including an empty piece

The empty middle piece contributes no values but still has a boundary on either side. Both inserted zeros survive.

<HaskellTryIt>

```haskell
import Data.List (intercalate, intersperse)

main :: IO ()
main = print (intercalate [0] [[1,2],[],[3]])
```

```text
[1,2,0,0,3]
```

</HaskellTryIt>

### Worked variation: empty outer input and singleton

No pieces give no output. A single piece has no neighbour, so no separator is inserted.

<HaskellTryIt>

```haskell
import Data.List (intercalate, intersperse)

main :: IO ()
main = print ((intercalate "," [], intercalate "," ["solo"]))
```

```text
("","solo")
```

</HaskellTryIt>

## 7. find: the first matching value

`find` tests elements from left to right and returns the first satisfying value in `Just`. If no element passes, including on an empty list, it returns `Nothing`. It does not return every match or a position. The predicate, a function returning Bool, decides what counts as matching; find itself requires no Eq constraint.

### Template and type

```haskell
find :: Foldable t => (a -> Bool) -> t a -> Maybe a
```

```text
find predicate elements
```

The full GHC 9.10 library type uses `Foldable t`: a container that can be traversed and combined. On lists, choose `t = []`, giving the specialised type `(a -> Bool) -> [a] -> Maybe a` used throughout this section. This distinction follows the [base 4.20 Data.List reference](https://hackage-content.haskell.org/package/base-4.20.0.0/docs/Data-List.html#v:find).

`predicate` examines one element. Search stops at the first True. For finite defined inputs an alternative is `listToMaybe (filter predicate elements)` from Data.Maybe; the output stays optional.

### Worked variation: several matches

Test 1: False, then 4: True. Return the value 4; later even values do not change the answer.

<HaskellTryIt>

```haskell
import Data.List (find)

main :: IO ()
main = print (find even [1,4,2,6])
```

```text
Just 4
```

</HaskellTryIt>

### Worked variation: string values

Lengths are 1 then 4. Tree is the first string longer than three; stone is not returned despite also qualifying.

<HaskellTryIt>

```haskell
import Data.List (find)

main :: IO ()
main = print (find ((>3) . length) ["a","tree","stone"])
```

```text
Just "tree"
```

</HaskellTryIt>

### Worked variation: absent and empty

Both finite searches reach the end without a passing element. Nothing is a normal result, not an exception.

<HaskellTryIt>

```haskell
import Data.List (find)

main :: IO ()
main = print ((find (>9) [1,2], find even ([] :: [Int])))
```

```text
(Nothing,Nothing)
```

</HaskellTryIt>

`find 3 [1,3]` gives `No instance for` because 3 is being used as a predicate rather than a value to compare. Use `find (==3) [1,3]` for a value or `elemIndex 3 [1,3]` for a position. Arithmetic on a Maybe result without consuming it gives a type error; handle Nothing and Just.

## 8. findIndex: the first matching position

`findIndex` uses the same left-to-right predicate search as find but returns a zero-based Int position wrapped in Just. Empty input or no match gives Nothing. Positions count every element, including ones that fail the predicate. No equality constraint is needed beyond whatever the supplied predicate needs.

### Template and type

```haskell
findIndex :: (a -> Bool) -> [a] -> Maybe Int
```

```text
findIndex predicate elements
```

Count positions 0, 1, 2 and so on. Return the first position whose element makes the predicate True. The payload is an Int regardless of the element type.

### Worked variation: several matches

1 at position 0 fails; 4 at position 1 passes. The answer is 1, not the value 4 and not a one-based position 2.

<HaskellTryIt>

```haskell
import Data.List (findIndex)

main :: IO ()
main = print (findIndex even [1,4,2,6])
```

```text
Just 1
```

</HaskellTryIt>

### Worked variation: index zero can succeed

The first element is already empty. A successful zero position is Just 0, never the missing result.

<HaskellTryIt>

```haskell
import Data.List (findIndex)

main :: IO ()
main = print (findIndex null ["","x"])
```

```text
Just 0
```

</HaskellTryIt>

## 12. isSuffixOf: an exact ending

`isSuffixOf` tests whether the first list is exactly an ending of the second list. The elements must be contiguous, in the same order, with equality at every position. It returns Bool, not a remainder or an index; a failed test returns False. The empty list is a suffix of every list, including itself. A nonempty list is not a suffix of an empty one. Comparison is case-sensitive for Char.

### Template and type

```haskell
isSuffixOf :: Eq a => [a] -> [a] -> Bool
```

```text
candidate `isSuffixOf` whole
```

The candidate comes first, the whole list second. For finite lists an equivalent test is `isPrefixOf (reverse candidate) (reverse whole)`; the already-taught prefix test checks the other end.

```haskell
isInfixOf :: Eq a => [a] -> [a] -> Bool
```

## 14. stripPrefix: remove a verified beginning

## 15. Data.List.transpose: columns without padding

`transpose` turns rows into columns. The first output row contains the first available element from each input row, in row order; the next contains the second available elements, and so on. On rectangular input this is the familiar matrix transpose. On ragged input, short or empty rows contribute no element at a missing position; nothing is padded or repeated. Empty outer input and all-empty rows both give `[]`. No element ordering or equality constraint is needed, and raggedness is not an error.

### Template and type

```haskell
transpose :: [[a]] -> [[a]]
```

```text
transpose rows
```

`rows` is a list of lists with one element type. For nonempty rectangular rows the indexed nested comprehension from Comprehension Templates agrees; it can fail on short rows and needs special care on empty outer input. The library operation handles those shapes directly. Finite rectangular matrices with positive dimensions survive transposing twice; empty-row shapes and ragged shapes need separate checking.

## 16. Substring: choose and state a boundary policy

The lecture uses substring informally; Prelude supplies take and drop rather than a standard function named substring. Here `substring start count` drops start characters, then takes at most count of the remainder. Positions are zero-based. The second argument is a count, not an ending position. Our explicit policy is the existing take/drop behaviour: a negative start acts like zero, a non-positive count gives empty text, an oversized start gives empty text and an oversized count takes all remaining text. These cases do not fail. This counts Haskell Char elements rather than bytes or visual grapheme clusters.

### Template and type

```haskell
substring :: Int -> Int -> String -> String
```

```text
substring start count text = take count (drop start text)
substring start count = take count . drop start
```

Drop first, take second: composition applies its right-hand function first. The fully applied form makes this ordering visible. The definition also generalises to `[a]` with the signature `Int -> Int -> [a] -> [a]`, without needing equality.

### Worked variation: middle selection

Drop a and b, leaving cdef. Take three characters, cde; start plus count is not the last included position.

<HaskellTryIt>

```haskell
substring :: Int -> Int -> String -> String
substring start count = take count . drop start

main :: IO ()
main = print (substring 2 3 "abcdef")
```

```text
"cde"
```

</HaskellTryIt>

### Worked variation: truncated bounds

Starting at 4 leaves ef and an oversized take keeps it all. Starting beyond the end leaves nothing to take.

<HaskellTryIt>

```haskell
substring :: Int -> Int -> String -> String

main :: IO ()
main = print ((substring 4 9 "abcdef", substring 9 2 "abcdef"))
```

```text
("ef","")
```

</HaskellTryIt>

Negative drop removes nothing, negative take returns nothing, and empty text cannot supply characters under any positive count.

Both spellings drop the first value and retain the next two. The same list operations work on integers without changing the policy.

## 17. The lecture's cat: append with (++)

The lecture's informal cat means concatenate two lists, written `(++)` in Haskell. There is no Prelude string operation named cat. Lists already taught how append is built; the new exam task here is translating the lecture vocabulary and choosing the correct list level. Append keeps every element of the first list, then every element of the second; it neither separates, interleaves nor flattens nested elements. Empty input on either side acts as an identity, and there is no missing-result form.

### Template and type

```haskell
(++) :: [a] -> [a] -> [a]
```

```text
left ++ right
(++) left right
```

Both operands have the same list type. String append is the Char instance. Two whole lists are arguments; this differs from the one-element left argument of cons.

### Worked variation: joining text with no inserted separator

Copy rain then bow. A space would have to be supplied explicitly as content.

<HaskellTryIt>

```haskell
main :: IO ()
main = print ("rain" ++ "bow")
```

```text
"rainbow"
```

</HaskellTryIt>

### Worked variation: joining lists of strings

The elements are whole strings. The result is three strings, not the single string abc.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (["a","b"] ++ ["c"])
```

```text
["a","b","c"]
```

</HaskellTryIt>

### Worked variation: empty identities and alternate application

Either empty operand contributes no characters. Prefix operator application gives the same append operation as infix notation.

<HaskellTryIt>

```haskell
main :: IO ()
main = print (("" ++ "x", "x" ++ "", (++) "a" "b"))
```

```text
("x","x","ab")
```

</HaskellTryIt>

Writing `cat "a" "b"` without defining cat produces `Variable not in scope`. Use `"a" ++ "b"`. Writing `"a" ++ 'b'` produces `Couldn't match type`; the second operand must be a list, so use `"b"` or `['b']`.

## 18. Choosing by the answer shape

| Required answer | Operation | Empty or missing result |
|---|---|---|
| Nonempty whitespace-separated words | `words` | `[]` |
| One string with spaces between supplied pieces | `unwords` | `""` for no pieces |
| Newline-separated lines, keeping blank lines | `lines` | `[]` for empty input |
| Every supplied line with its own terminator | `unlines` | `""` for no lines |
| Separator elements, retaining the list layer | `intersperse` | `[]` |
| Separator lists, then one flattened result | `intercalate` | `[]` (a String may print as `""`) |
| First passing value | `find` | `Nothing` |
| First passing position | `findIndex` | `Nothing` |
| First equal position | `elemIndex` | `Nothing` |
| Every passing position | `findIndices` | `[]` |
| Every equal position | `elemIndices` | `[]` |
| Ending test | `isSuffixOf` | `False` on mismatch |
| Contiguous containment test | `isInfixOf` | `False` on mismatch |
| Verified prefix remainder | `stripPrefix` | `Nothing` on mismatch |
| Available columns | `transpose` | `[]` for no cells |
| Positional text segment | `take count . drop start` | `""` under this policy |
| Two lists joined end to end | `(++)` | Empty operands contribute nothing |

Predicates are functions returning Bool; a target value is an element. Keep that distinction when choosing between findIndex and elemIndex. For every match rather than the first value, use the already-taught `filter` or a comprehension. To check one character use elem; to check a contiguous list use isInfixOf. For the beginning use the existing isPrefixOf lesson, and use stripPrefix when the remainder matters. Case-insensitive matching requires an explicit normalisation policy before these equality-based tests; none automatically changes case.

## Summary

<Callout type="key" title="Remember">
Words discard whitespace layout; lines retain empty lines but do not store whether the final line was terminated. Unwords inserts spaces between pieces; unlines terminates every piece. Intersperse inserts an element; intercalate inserts a list and flattens. Singular searches return Maybe; plural index searches return lists. Suffix and infix tests require contiguous order, and stripPrefix verifies before removing. Substring needs a stated count and boundary policy. Transpose skips missing cells, so ragged and empty shapes can lose information. The lecture's cat is append, written ++.
</Callout>

<CheckQuestion question="Why can a split/join round trip change text?">
Splitting can discard gap sizes or final-terminator information; joining creates its own separators or terminators. Such a round trip normalises instead of remembering the original layout.
</CheckQuestion>

<CheckQuestion question="Which operation returns a matching value rather than a position?">
Find returns Maybe a; findIndex and elemIndex return Maybe Int. FindIndices and elemIndices return every matching position as [Int].
</CheckQuestion>

<CheckQuestion question="How do a failed prefix removal and a successful empty remainder differ?">
The failure is Nothing. Successful removal of the entire string is Just containing the empty string.
</CheckQuestion>

<CheckQuestion question="Does intercalate add a trailing separator?">
It adds separators only between supplied pieces. An empty last piece can nevertheless make the final boundary's separator appear at the end of the resulting text.
</CheckQuestion>

<CheckQuestion question="Why is double transpose unsafe as a general ragged round-trip law?">
Missing positions are not retained as cells, so the first transpose can lose which row was short or empty. Repeating it need not restore original row boundaries.
</CheckQuestion>
