## Task 1 — `has`

Write a function called `has` that recursively checks whether a given list contains a given element. The function takes the element and the list, and returns a `Bool`.

- What must the element type support for `==` to be usable inside `has`? Write the constraint into your signature — see [Reading `Eq a => [a] -> a -> Bool`](/docs/sem3/csi243/06-lists-tuples/notes/list-recursion#reading-eq-a--a---a---bool--the-constraint-and-the-argument-order) for exactly this signature shape, worked in full, including why the constraint is required and how to read it alongside the ordinary arguments.
- Give the base case and the recursive case. What should `has` return for an empty list, and why?
- Test it on a value present in the list, a value absent from it, and the empty list.

<Callout type="warn" title="Argument order is your choice — state it">
The task description says `has` "takes the element and the list" — element first. You may instead see the equivalent function written list-first, as `linearSearch :: Eq a => [a] -> a -> Bool`. Both are correct; they read differently, not differently *compute*. Whichever order you choose, keep your signature, your equations, and every call site consistent with each other.
</Callout>

## Task 2 — `isEmpty` and `len`

Write a function `isEmpty` that checks whether a character is an empty character (a space). Then write a function `len` that, given a string `xs`, counts the number of space characters in it — using the **in-built** `length` and `filter` functions, with `isEmpty` as `filter`'s predicate.

- Write `isEmpty :: Char -> Bool` first, on its own, and test it on `' '` and on an ordinary letter.
- Then write `len` as a single expression combining `filter isEmpty` and `length` — see [`filter`'s result doesn't have to be printed](/docs/sem3/csi243/07-higher-order/notes/map-and-filter#filters-result-doesnt-have-to-be-printed--it-can-feed-straight-into-another-function) for exactly this composition, worked through with a different predicate.
- Test `len` on a string with several spaces and on a string with none.

## Task 3 — `add`, three ways

Write a function `add` that adds `1` to an even integer, and `2` to an odd one. Then:

1. Write a **list comprehension** that applies `add` to every element of a given integer list.
2. Write the **same transformation** again using `map` and `add`.

Both should produce identical results on the same input — see [A conditional transform, three ways](/docs/sem3/csi243/07-higher-order/notes/map-and-filter#a-conditional-transform-three-ways-recursion-comprehension-map) for `add` worked through recursion, a comprehension, and `map` side by side, with a hand-traced example.

- State, in one sentence, why a guard-based function like `add` is still a valid argument to `map` — `map` places no restriction on *how* its function argument decides its answer, only on its type.
- Test both versions on the same list of at least four integers, including both even and odd values, and confirm the two outputs match exactly.
