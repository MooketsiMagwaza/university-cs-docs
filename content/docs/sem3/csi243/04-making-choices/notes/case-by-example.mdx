## 1. The matching template

The **scrutinee** is the expression being inspected. An **alternative** is a pattern together with its result, or its guarded results.

```haskell
-- Template: replace the placeholder names.
case expression of
  patternA -> resultA
  patternB -> resultB
  _        -> fallback
```

Read `expression` as the value to inspect, `of` as the start of the choices, `patternA` as a shape to try, and `->` as the separator before its result. Every result must have one compatible type. A variable pattern matches anything and binds a name; `_` matches anything without naming it.

For unguarded alternatives, the first matching pattern wins. With guards, the pattern must match **and one guard must succeed**. Use this tracing template:

```text
1. Identify the scrutinee and the result type.
2. Try the first pattern; if it fails, move down one alternative.
3. If it matches, record every variable binding.
4. Try its guards, if any, from top to bottom.
5. Select the first successful guarded result, or the unguarded result.
6. If every guard fails, try the NEXT alternative on the same scrutinee.
7. Substitute bindings into the selected result and evaluate it.
```

A failed Boolean guard is `False`. A guard that raises an exception does not mean "try the next alternative". Each runnable block below is a complete program with its question in a comment; to practise, keep the comment and replace the solution before revealing the explanation.

## 2. Boolean scrutinees

A Boolean has two constructors: `True` and `False`. The useful step is often computing the test before matching it. The result may be a number, string, list or tuple.

```haskell
case test of
  True -> whenTrue
  False -> whenFalse
```


### Permission rather than arithmetic

<HaskellTryIt>

```haskell
-- Question: Permission rather than arithmetic
choose :: Bool -> String
choose value = case value of
  True -> "enter"
  False -> "wait"

main :: IO ()
main = print (choose False)
```

```text
"wait"
```

</HaskellTryIt>

`False` fails the first pattern, then matches the second; its result is `"wait"`.

### A Boolean controls a list

<HaskellTryIt>

```haskell
-- Question: A Boolean controls a list

  True -> [1,2]
  False -> []

main :: IO ()

```

```text
[1,2]
```

</HaskellTryIt>

`True` matches immediately; the second alternative is not tried. Both results are lists of integers.

### A Boolean produces a tuple

<HaskellTryIt>

```haskell

  True -> ("ready",1)
  False -> ("closed",0)

```

</HaskellTryIt>

### Now compute a Boolean from an integer

<HaskellTryIt>

```haskell

  n -> case n > 0 of
    True -> n
    False -> 0

```

</HaskellTryIt>

The outer variable pattern binds `n = -4`. The inner scrutinee is `False`: `True` fails, `False` returns `0`.

## 3. Integer and character literals

A literal pattern tests one exact value, not a range. Characters have single quotes. Put special literals before a variable or wildcard default.

```haskell

  literal -> specialResult
  name -> resultUsingName
```

## 4. Tuples and combinations of tests

A tuple pattern matches all its components together. A nested pair is different from a triple. Components may have different types.

```haskell
case (first, second) of
  (patternA, patternB) -> result
  _ -> fallback
```


### A coordinate on an axis

<HaskellTryIt>

```haskell
-- Question: A coordinate on an axis
choose :: (Int, Int) -> String
choose value = case value of
  (0,0) -> "origin"
  (0,_) -> "vertical"
  (_,0) -> "horizontal"
  _ -> "away"

main :: IO ()
main = print (choose (0,7))
```

```text
"vertical"
```

</HaskellTryIt>

`(0,0)` fails on the second component; `(0,_)` succeeds, ignoring `7`.

### Bind both components

<HaskellTryIt>

```haskell
-- Question: Bind both components
choose :: (Int, Int) -> Int
choose value = case value of
  (x,y) -> x * 10 + y

main :: IO ()
main = print (choose (3,4))
```

```text
34
```

</HaskellTryIt>

The sole alternative binds `x = 3`, `y = 4`; substitution gives `3 * 10 + 4 = 34`.

### The tuple-of-tests idiom

<HaskellTryIt>

```haskell
-- Question: The tuple-of-tests idiom
choose :: (Int, Int) -> String
choose value = case value of
  (x,y) -> case (x > 0, y > 0) of
    (True,True) -> "both"
    (True,False) -> "x only"
    (False,True) -> "y only"
    (False,False) -> "neither"

main :: IO ()
main = print (choose (-2,5))
```

```text
"y only"
```

</HaskellTryIt>

Bind `x = -2`, `y = 5`. The inner scrutinee is `(False,True)`: alternatives one and two fail on the first field, then alternative three matches. Zero also makes `> 0` false.

### A nested tuple

<HaskellTryIt>

```haskell
-- Question: A nested tuple
choose :: ((Int, Int), Bool) -> Int

  ((x,y),True) -> x + y
  ((x,_),False) -> x

main :: IO ()
main = print (choose ((2,8),False))
```

```text
2
```

</HaskellTryIt>

The first alternative fails on the outer Boolean. The second binds `x = 2` inside the inner pair and ignores `8`.

## 5. Lists: exact lengths and open tails

`[x]` requires exactly one element, `[x,y]` exactly two. `(x:xs)` requires at least one and binds the tail. `(x:y:rest)` requires at least two; `rest` may be empty.

```haskell
case xs of
  [] -> emptyResult
  [x] -> singletonResult
  [x,y] -> pairResult
  (x:y:rest) -> longerResult
```


### Distinguish four lengths

<HaskellTryIt>

```haskell
-- Question: Distinguish four lengths
choose :: [Int] -> String
choose value = case value of
  [] -> "none"
  [x] -> "one"
  [x,y] -> "two"
  (x:y:rest) -> "many"

main :: IO ()
main = print (choose [5,6,7])
```

```text
"many"
```

</HaskellTryIt>

The first three exact lengths fail. The final pattern binds `x = 5`, `y = 6`, `rest = [7]`.

### An empty-list default

<HaskellTryIt>

```haskell
-- Question: An empty-list default

choose value = case value of
  [] -> 100
  (x:xs) -> x + length xs

main :: IO ()
main = print (choose [])
```

```text
100
```

</HaskellTryIt>

The first alternative matches immediately. No nonexistent head is accessed.

### A singleton calculation

<HaskellTryIt>

```haskell
-- Question: A singleton calculation
choose :: [Int] -> Int
choose value = case value of
  [] -> 0
  [x] -> x * x
  (x:xs) -> sum xs

main :: IO ()
main = print (choose [6])
```

```text
36
```

</HaskellTryIt>

The empty pattern fails; `[x]` binds `x = 6`, giving `6 * 6 = 36`. The cons alternative is skipped.

### A tail that is empty

<HaskellTryIt>

```haskell
-- Question: A tail that is empty

  (x:y:rest) -> (x + y,rest)
  _ -> (0,[])

main :: IO ()
main = print (choose [4,9])
```

```text
(13,[])
```

</HaskellTryIt>

The input has two cons cells, so the first pattern binds `x = 4`, `y = 9`, `rest = []`; the result is `(13,[])`.

## 6. Maybe and lookup

`Nothing` represents absence; `Just value` represents presence. Case analysis makes a failed lookup part of the answer instead of silently assuming success.

```haskell
case lookup key table of
  Nothing -> missingResult
  Just value -> resultUsingValue
```


### A present payload

<HaskellTryIt>

```haskell
-- Question: A present payload
choose :: Maybe Int -> Int
choose value = case value of
  Nothing -> 0
  Just n -> n + 1

main :: IO ()
main = print (choose (Just 2))
```

```text
3
```

</HaskellTryIt>

`Nothing` fails. `Just n` matches with `n = 2`; the result is `3`.

### An absent payload

<HaskellTryIt>

```haskell
-- Question: An absent payload
choose :: Maybe Int -> String
choose value = case value of
  Nothing -> "missing"
  Just n -> show n

main :: IO ()
main = print (choose Nothing)
```

```text
"missing"
```

</HaskellTryIt>

The first constructor matches. No value named `n` exists in this alternative.

### A successful lookup

<HaskellTryIt>

```haskell
-- Question: A successful lookup
choose :: String -> Int
choose value = case value of
  key -> case lookup key [("pen",3),("book",8)] of
    Nothing -> 0
    Just cost -> cost

main :: IO ()
main = print (choose "pen")
```

```text
3
```

</HaskellTryIt>

The variable pattern binds the key. Lookup yields `Just 3`; the inner `Nothing` fails and `Just cost` binds `3`.

### A missing lookup

<HaskellTryIt>

```haskell
-- Question: A missing lookup
choose :: String -> Bool
choose value = case value of
  key -> case lookup key [("red",1),("blue",2)] of
    Nothing -> False
    Just _ -> True

main :: IO ()
main = print (choose "green")
```

```text
False
```

</HaskellTryIt>

The outer variable matches; lookup finds no key, producing `Nothing`. The first inner alternative returns `False`.

## 7. Ordering and compare

`compare a b` returns one constructor of `Ordering`: `LT`, `EQ` or `GT`. Matching these constructors avoids repeating comparisons.

```haskell
case compare left right of
  LT -> smallerResult
  EQ -> equalResult
  GT -> largerResult
```


### Numerical comparison

<HaskellTryIt>

```haskell
-- Question: Numerical comparison
choose :: Int -> String
choose value = case value of
  n -> case compare n 7 of
    LT -> "before"
    EQ -> "same"
    GT -> "after"

main :: IO ()
main = print (choose 2)
```

```text
"before"
```

</HaskellTryIt>

Bind `n = 2`. Compare returns `LT`, matching the first inner alternative.

### Character comparison

<HaskellTryIt>

```haskell
-- Question: Character comparison
choose :: Char -> Int
choose value = case value of
  c -> case compare c 'a' of
    LT -> 1
    EQ -> 0
    GT -> 2

main :: IO ()
main = print (choose 'z')
```

```text
2
```

</HaskellTryIt>

The variable binds `'z'`. Comparison yields `GT`; `LT` and `EQ` fail, then `GT` gives `2`.

### Equal strings

<HaskellTryIt>

```haskell
-- Question: Equal strings
choose :: String -> Bool
choose value = case value of
  s -> case compare s "cat" of
    LT -> False
    EQ -> True
    GT -> False

main :: IO ()
main = print (choose "cat")
```

```text
True
```

</HaskellTryIt>

Compare yields `EQ`; the first inner pattern fails and the second returns `True`.

### An Ordering result

<HaskellTryIt>

```haskell
-- Question: An Ordering result
choose :: Int -> Ordering
choose value = case value of
  0 -> EQ
  n -> compare n 0

main :: IO ()
main = print (choose (-4))
```

```text
LT
```

</HaskellTryIt>

The zero pattern fails; `n = -4`, so `compare n 0 = LT`. A constructor prints without quotes.

## 8. Strings are lists of characters

A literal string pattern tests the entire string. A cons pattern exposes one `Char` and a remaining `String`. The patterns `""` and `[]` describe the same empty value.

```haskell
case text of
  "exact" -> exactResult
  [] -> emptyResult
  (c:rest) -> resultUsingCharacterAndTail
```


### An exact word is not a prefix

<HaskellTryIt>

```haskell
-- Question: An exact word is not a prefix
choose :: String -> Int
choose value = case value of
  "save" -> 1
  "load" -> 2
  _ -> 0

main :: IO ()
main = print (choose "save now")
```

```text
0
```

</HaskellTryIt>

The input differs from both complete literals. The wildcard gives `0`; literal matching does not test prefixes.

### The empty string

<HaskellTryIt>

```haskell
-- Question: The empty string
choose :: String -> String
choose value = case value of
  "" -> "blank"
  (c:rest) -> rest

main :: IO ()
main = print (choose "")
```

```text
"blank"
```

</HaskellTryIt>

The first literal matches the empty list of characters. There is no head to extract.

### A leading marker

<HaskellTryIt>

```haskell

  _ -> "plain"

```

</HaskellTryIt>

The first character is `'#'`; the first pattern binds `rest = "note"` and returns it.

### Exactly two characters

<HaskellTryIt>

## 9. User-defined constructors and fields

A declaration tells you the constructors available for matching. Enumeration constructors hold no fields; constructors with fields let patterns bind each stored value.

```haskell
data Item = Empty | Filled Int

measure item = case item of
  Empty -> 0
  Filled n -> n
```


### An enumeration

<HaskellTryIt>

```haskell
-- Question: An enumeration
data Signal = Red | Amber | Green

main :: IO ()
main = print (case Amber of
  Red -> "stop"
  Amber -> "prepare"
  Green -> "go")
```

```text
"prepare"
```

</HaskellTryIt>

`Amber` fails `Red`, then matches `Amber`. Constructor identity makes the choice.

### One stored field

<HaskellTryIt>

```haskell
-- Question: One stored field
data Credit = None | Credit Int

main :: IO ()
main = print (case Credit 12 of
  None -> 0
  Credit amount -> amount - 2)
```

```text
10
```

</HaskellTryIt>

`Credit 12` fails `None`. The second pattern binds `amount = 12`; subtraction gives `10`.

### Different numbers of fields

<HaskellTryIt>

```haskell
-- Question: Different numbers of fields
data Parcel = Letter Int | Box Int Int

main :: IO ()
main = print (case Box 3 4 of
  Letter weight -> weight
  Box width height -> width * height)
```

```text
12
```

</HaskellTryIt>

The input constructor is not `Letter`. `Box width height` binds `3` and `4`, giving area `12`.

### A recursive type

<HaskellTryIt>

```haskell
-- Question: A recursive type
data Tree = Leaf | Node Tree Int Tree

root :: Tree -> Maybe Int
root t = case t of
  Leaf -> Nothing
  Node _ x _ -> Just x

main :: IO ()
main = print (root (Node Leaf (-3) Leaf))
```

```text
Just (-3)
```

</HaskellTryIt>

The input is not `Leaf`. The second alternative binds `x = -3`, ignores both children and returns `Just (-3)`. GHC prints parentheses around the negative constructor argument.

## 13. Guards inside case alternatives

A pattern answers "does the value have this shape?" A guard answers "does this extra condition hold?" Use the pattern to expose fields, then guards to test ranges or relationships between those fields.

```haskell
-- Template: this is a case alternative, not a function equation.
case expression of
  pattern
    | guard1 -> result1
    | guard2 -> result2
    | otherwise -> result3
  nextPattern -> nextResult
```

Read it in two stages. First match `pattern`, binding any names it introduces. Those names are visible in that alternative's guards and results. Next try `guard1`; if it is `True`, select `result1` and stop. Otherwise try `guard2`. **The first `True` guard wins**, even when later guards would also be true.

`otherwise` is a Prelude name defined as `True`; it is not a special pattern or keyword. It succeeds whenever reached, so put it last. If there is no `otherwise` and every guard is false, try the **next alternative**, not the next guard of some unrelated pattern. Bindings introduced by one alternative do not become bindings of the next.

### Arrows in alternatives, equals in equations

| Location | Correct form | Meaning |
|---|---|---|
| Guard of a function equation | `f n \| n > 0 = n` | Defines the result of an equation |
| Guard of a case alternative | `n \| n > 0 -> n` | Selects the result of an alternative |

The initial function definition still needs `=`: `f x = case x of ...`. After a case guard, use `->`. These are separate grammatical positions.

### Variable pattern: negative, zero, positive

<HaskellTryIt>

```haskell
-- Question: Variable pattern: negative, zero, positive
signText :: Int -> String
signText value = case value of
  n
    | n < 0 -> "negative"
    | n == 0 -> "zero"
    | otherwise -> "positive"

main :: IO ()
main = do
  print (signText (-2))
  print (signText 0)
  print (signText 4)
```

```text
"negative"
"zero"
"positive"
```

</HaskellTryIt>

The variable pattern always binds `n`. For `-2`, the first guard is true and the others are skipped. For `0`, `n < 0` is false and `n == 0` is true. For `4`, both tests fail and `otherwise` is true. A variable pattern does not itself test a range.

### Tuple pattern: compare bound fields

<HaskellTryIt>

```haskell
-- Question: Tuple pattern: compare bound fields
lead :: (Int, Int) -> String
lead scores = case scores of
  (home,away)
    | home > away -> "home"
    | home == away -> "draw"
    | otherwise -> "away"

main :: IO ()
main = print (lead (2,5))
```

```text
"away"
```

</HaskellTryIt>

The tuple pattern binds `home = 2`, `away = 5`. Both named comparisons are false, so `otherwise` selects `"away"`. Names come from the pattern before any guard is tested.

### List pattern: guarded fall-through

<HaskellTryIt>

```haskell
-- Question: List pattern: guarded fall-through
headLabel :: [Int] -> String
headLabel xs = case xs of
  (x:_)
    | x > 10 -> "large"
    | x > 0 -> "small positive"
  [] -> "empty"
  (_:_) -> "non-positive"

main :: IO ()
main = do
  print (headLabel [-2,9])
  print (headLabel [12])
  print (headLabel [])
```

```text
"non-positive"
"large"
"empty"
```

</HaskellTryIt>

For `[12]`, both `x > 10` and `x > 0` would be true. Only the first is used: the answer is `"large"`. For `[]`, the first cons pattern fails without testing any guards; the empty alternative matches.

The required fall-through trace for `headLabel [-2,9]` is:

| Step | What is tried | Outcome |
|---|---|---|
| 1 | `(x:_)` against `[-2,9]` | Matches; bind `x = -2` |
| 2 | `x > 10` | `False`; try the next guard |
| 3 | `x > 0` | `False`; no guards remain |
| 4 | Next alternative `[]` against the original `[-2,9]` | Fails |
| 5 | Next alternative `(_:_)` against `[-2,9]` | Matches |
| 6 | Its unguarded result | `"non-positive"` |

It would be wrong to stop at step 1 and call the match successful overall. It would also be wrong to restart on the tail `[9]`: fall-through uses the **same scrutinee**.

### Pattern guards: obtain a value while testing

A **pattern guard** has the form `pattern <- expression`. It succeeds if the expression matches the pattern, and binds names for later guards in the same comma-separated sequence and for its result. This is matching, not assignment and not a Boolean comparison.

```haskell
-- Template: qualifiers in one guard sequence are tried left to right.
case key of
  k
    | Just v <- lookup k table, v > 0 -> resultUsingV
    | otherwise -> fallback
```

The lookup must return `Just v` **and** the Boolean condition must hold. If lookup returns `Nothing`, `v > 0` is not attempted. If lookup succeeds but `v > 0` is false, that guard sequence fails. A name bound in this sequence is not automatically available in the next `|` sequence.

### Pattern guard: lookup succeeds and its Boolean test passes

<HaskellTryIt>

```haskell
-- Question: Pattern guard: lookup succeeds and its Boolean test passes
reward :: String -> Int
reward key = case key of
  k
    | Just v <- lookup k [("a",3),("b",-2)], v > 0 -> v * 2
    | otherwise -> 0

main :: IO ()
main = print (reward "a")
```

```text
6
```

</HaskellTryIt>

`k` binds `"a"`. Lookup produces `Just 3`, binding `v = 3`; `v > 0` is true. The result is `3 * 2 = 6`.

<HaskellTryIt>

</HaskellTryIt>

### Rewrite function guards as case guards, and back

A function guard tests its equation's arguments; a case guard can test names from any matched scrutinee. To move function guards into a `case`, introduce a variable pattern, preserve guard order, and replace each guard's `=` with `->`. To move back, make that variable the function parameter and replace `->` with `=`. Do not move a payload-dependent guard outside the pattern that binds its payload.

### Two equivalent guarded definitions

<HaskellTryIt>

```haskell
-- Question: Two equivalent guarded definitions
discountEquation :: Int -> Int
discountEquation n
  | n >= 10 = 2
  | otherwise = 0

discountCase :: Int -> Int
discountCase value = case value of
  n
    | n >= 10 -> 2
    | otherwise -> 0

main :: IO ()
main = do
  print (discountEquation 10, discountCase 10)
  print (discountEquation 9, discountCase 9)
```

```text
(2,2)
(0,0)
```

</HaskellTryIt>

The case variable pattern always matches. For `10`, the first guard is true in both definitions. For `9`, it is false and `otherwise` wins in both. The guard separators differ; the decision order does not.

### Non-exhaustive guards and their repair

Matching a variable pattern does **not** guarantee a result when that alternative has guards. This deliberately failing program belongs in a plain fence:

```haskell
-- Incorrect: no result when n is zero or negative.
onlyPositive :: Int -> Int
onlyPositive x = case x of
  n | n > 0 -> n

main :: IO ()
main = print (onlyPositive 0)
```

The stable key part of the run-time message is `Non-exhaustive patterns in case` (GHC also includes a source location). With `-Wincomplete-patterns`, the warning includes `Pattern match(es) are non-exhaustive`. Repair it by adding `| otherwise -> 0` to the variable alternative, or `_ -> 0` as a later alternative. The `validCount` example demonstrates the latter repair.

### Guard mistakes, diagnosis and repair

These examples are intentionally rejected; they are not runnable exercises.

```haskell
-- Incorrect: function-equation punctuation in a case guard.
badArrow :: Int -> Int
badArrow x = case x of
  n | n > 0 = n
  _ -> 0
```

GHC's key diagnostic is `parse error on input '='`. Repair the guard separator to `->`. In the reverse direction, a function equation written `f n | n > 0 -> n` has `parse error on input '->'`; use `=` there.

```haskell
-- Incorrect: n is Int, but a Boolean guard must have type Bool.
badTest :: Int -> Int
badTest x = case x of
  n | n -> 1
  _ -> 0
```

GHC's diagnostic includes `Couldn't match expected type 'Bool' with actual type 'Int'`. Repair the guard to a test such as `n /= 0`.

```haskell
-- Incorrect: the guard escaped from its case alternative.
badLayout :: Int -> Int
badLayout x = case x of
  n
| n > 0 -> n
```

The key diagnostic is `parse error on input '|'`. Indent the guard beneath its pattern, with all guards aligned. A missing catch-all is different: it can compile successfully yet fail at run time, as `onlyPositive` shows. A name from another alternative is also unavailable: `Nothing -> n` cannot use the `n` from `Just n`; GHC reports `Variable not in scope`.

## 14. A whole-equation where and an alternative-local let

Use `where` for names needed across the equation, including several alternatives. Use `let ... in` inside one result for names needed only there. An equation-level `where` can see the function's parameters, but it cannot see a name bound only by a case alternative.

```haskell
-- Template: shared can see input; local can also see field.
f input = case input of
  Just field -> let local = field + shared in local
  Nothing -> shared
  where
    shared = 10
```

| Place | Can see the function parameter? | Can see this alternative's pattern variables? |
|---|---|---|
| Equation-level `where` | Yes | No |
| Guard or result of the alternative | Yes | Yes |
| `let` within that result | Yes | Yes |
| Another alternative | Yes | No |

### Share a value across alternatives

<HaskellTryIt>

```haskell
-- Question: Share a value across alternatives

  Nothing -> base
  Just n -> base + n
  where
    base = 5

main :: IO ()
main = print (charge Nothing, charge (Just 3))
```

```text
(5,8)
```

</HaskellTryIt>

For `Nothing`, the first alternative selects `base = 5`. For `Just 3`, the first fails, the second binds `n = 3` and computes `5 + 3`. Both alternatives can see the equation-level name.

Moving `square = n * n` from the `Just n` result to the whole-equation `where` fails: GHC reports `Variable not in scope: n`. Keep it in a `let` under that alternative, or make a helper with its own parameter, such as `square n = n * n`.

</Callout>

## 15. Case nested inside case

An outer match can expose a value whose shape needs a second decision. Indentation must show which alternatives belong to which `case`. A nested match can make a long pattern easier to discuss, while a nested pattern can make a short decision more compact.

```haskell
-- Template: the inner choices are further indented.
case outerValue of
  Outer inner -> case inner of
    InnerA -> resultA
    InnerB -> resultB
  Other -> fallback
```

### Inspect an optional list in two stages

<HaskellTryIt>

```haskell
-- Question: Inspect an optional list in two stages

  Nothing -> "absent"
  Just xs -> case xs of
    [] -> "empty"
    (_:_) -> "non-empty"

main :: IO ()
main = print (describe (Just []))
```

```text
"empty"
```

</HaskellTryIt>

The outer `Nothing` fails and `Just xs` binds `[]`. The first inner alternative then matches. The result is `"empty"`, not `"absent"`.

### Two optional values

<HaskellTryIt>

  Nothing -> Nothing
  Just x -> case second of

    Just y -> Just (x + y)

main :: IO ()

```

Just 7
```

</HaskellTryIt>

The first outer pattern fails; bind `x = 2`. The inner `Nothing` fails; bind `y = 5`, then return `Just 7`.

### A character followed by a test

### Only inspect the tail after a non-empty match

## 16. A case is a value inside a larger expression

A `case` does not have to occupy the entire right-hand side. It may contribute a number to arithmetic, supply an argument, or define a local value. Parentheses make its boundary clear.

```haskell
-- Templates; replace the placeholders.
1 + (case value of { pattern -> result; _ -> fallback })
function (case value of { pattern -> result; _ -> fallback })
let name = case value of { pattern -> result; _ -> fallback }
in expressionUsingName
```

### Arithmetic around the choice

<HaskellTryIt>

  Nothing -> 0
  Just n -> n)

main :: IO ()

```

5
```

</HaskellTryIt>

`Nothing` fails; `Just n` binds `4` and makes the case value `4`. The surrounding addition then gives `1 + 4 = 5`.

## 17. Four equivalent ways to implement a specification

Specification: an empty queue has fee 0; every non-empty queue has fee 2. This decision can be expressed with `if`, function guards, multiple equations, or `case`. Unlike a numerical recurrence, this example has no hidden restriction to positive inputs.

```haskell
-- Conversion templates.
f [] = emptyResult
f (x:xs) = nonEmptyResult

f input = case input of
  [] -> emptyResult
  (x:xs) -> nonEmptyResult
```

| Conversion | Rule |
|---|---|
| Equations to case | Make one equation over a fresh parameter; move each argument pattern to an alternative and replace its `=` with `->` |
| Case to equations | Move each pattern to the function's argument position, preserving order; replace `->` with `=` |
| If to case | Match the condition against `True` and `False`; reverse this to recover `if` |
| Function guards to case guards | Bind a variable pattern and preserve the tests and their order; replace guard `=` with `->`; reverse these changes to move back |

For several arguments, case-match a tuple of them. A computed scrutinee may need a helper equation to move back to multiple equations; it cannot simply become an argument pattern containing a function call.

### Conditional form

<HaskellTryIt>

```haskell
-- Question: Conditional form
queueFee :: [Int] -> Int
queueFee xs = if null xs then 0 else 2

main :: IO ()
main = print (queueFee [], queueFee [7])
```

```text
(0,2)
```

</HaskellTryIt>

For `[]`, `null` is true, so select the first result. For `[7]`, it is false, so select the second.

### Function-guard form

<HaskellTryIt>

```haskell
-- Question: Function-guard form
queueFee :: [Int] -> Int
queueFee xs
  | null xs = 0
  | otherwise = 2

main :: IO ()
main = print (queueFee [], queueFee [7])
```

```text
(0,2)
```

</HaskellTryIt>

For `[]`, the first guard succeeds. For `[7]`, it fails and `otherwise` succeeds.

### Multiple-equation form

<HaskellTryIt>

```haskell
-- Question: Multiple-equation form
queueFee :: [Int] -> Int
queueFee [] = 0
queueFee (_:_) = 2

main :: IO ()
main = print (queueFee [], queueFee [7])
```

```text
(0,2)
```

</HaskellTryIt>

For `[]`, the first equation matches. `[7]` fails it and matches the cons equation.

### Case form

<HaskellTryIt>

```haskell
-- Question: Case form
queueFee :: [Int] -> Int
queueFee xs = case xs of
  [] -> 0
  (_:_) -> 2

main :: IO ()
main = print (queueFee [], queueFee [7])
```

```text
(0,2)
```

</HaskellTryIt>

For `[]`, the first alternative matches. `[7]` fails it and matches the cons alternative. No Boolean test is needed.

## 18. Order, overlap, completeness and layout

An earlier general alternative can hide a later specific one. Completeness asks a different question: is there a successful alternative for every input? Check both pattern coverage and guard coverage.

```haskell
-- Ordering template: special shapes before the general fallback.
f input = case input of
  specificPattern -> specialResult
  generalPattern -> remainingResult
```

### Correct order for exact and open lengths

<HaskellTryIt>

```haskell
-- Question: Correct order for exact and open lengths
sizeTag :: [Int] -> String
sizeTag xs = case xs of
  [] -> "empty"
  [_] -> "single"
  (_:_:_) -> "longer"

main :: IO ()
main = print (sizeTag [], sizeTag [4], sizeTag [4,5])
```

```text
("empty","single","longer")
```

</HaskellTryIt>

`[]` matches first. `[4]` fails empty and matches the singleton. `[4,5]` fails both exact patterns and matches at least two cons cells. Together these cover every list length.

### A repaired optional match

<HaskellTryIt>

```haskell
-- Question: A repaired optional match
safe :: Maybe Int -> Int
safe m = case m of
  Just n -> n
  Nothing -> 0

main :: IO ()
main = print (safe Nothing, safe (Just 3))
```

```text
(0,3)
```

</HaskellTryIt>

`Nothing` fails the `Just` pattern, then matches absence. `Just 3` matches the first alternative with `n = 3`. Neither input falls off the end.

### Aligned alternatives and guards

<HaskellTryIt>

```haskell
-- Question: Aligned alternatives and guards
label :: Int -> String
label x = case x of
  0 -> "zero"
  n
    | n < 0 -> "minus"
    | otherwise -> "plus"

main :: IO ()
main = print (label (-1))
```

```text
"minus"
```

</HaskellTryIt>

The zero pattern fails. The aligned variable alternative binds `n = -1`; its first guard is true. The extra indentation ties the guards to `n`.

### Explicit braces and semicolons

<HaskellTryIt>

```haskell
-- Question: Explicit braces and semicolons
digit :: Int -> String
digit n = case n of { 0 -> "zero"; 1 -> "one"; _ -> "other" }

main :: IO ()
main = print (digit 1)
```

```text
"one"
```

</HaskellTryIt>

The first literal fails, the second matches. Braces mark the alternative group and semicolons separate alternatives, replacing layout. Prefer line breaks for long guarded choices.

### Unreachable alternatives and incomplete matches

```haskell
-- Incorrect order: the later alternative is unreachable.
hidden :: [Int] -> Int
hidden xs = case xs of
  _ -> 0
  [] -> 1
```

With overlap warnings enabled, GHC's key message is `Pattern match is redundant`. `hidden []` would select `_` and yield `0`. Repair by moving the empty pattern first. Similarly, `(x:xs)` before `[x]` hides a singleton alternative.

```haskell
-- Incorrect: deliberately crashes for an absent value.
unsafe :: Maybe Int -> Int
unsafe m = case m of
  Just n -> n

main :: IO ()
main = print (unsafe Nothing)
```

With `-Wincomplete-patterns`, GHC warns `Pattern match(es) are non-exhaustive`. At run time the key text is `Non-exhaustive patterns in case`; a source location is included too. The `safe` variation above repairs the missing constructor. A wildcard also repairs coverage, but naming each constructor can make a future type extension easier to notice.

### Syntax and type errors to recognise

```haskell
-- Incorrect: missing of.
badOf :: Int -> Int
badOf n = case n
  0 -> 1
  _ -> 2
```

The key diagnostic is `parse error on input '->'`. Insert `of` after the scrutinee.

```haskell
-- Incorrect: the second alternative escaped the layout block.
badIndent :: Int -> Int
badIndent n = case n of
  0 -> 1
_ -> 2
```

The key diagnostic is `parse error on input '->'`. Align `_` with `0` inside the case.

```haskell
-- Incorrect: a Bool pattern cannot match an Int input.
badPattern :: Int -> Int
badPattern n = case n of
  True -> 1
  _ -> 0
```

GHC's key diagnostic includes `Couldn't match expected type 'Int' with actual type 'Bool'`. Use integer patterns, or change the scrutinee to a Boolean test.

```haskell
-- Incorrect: all alternatives must return the same type.
badResult :: Bool -> Int
badResult b = case b of
  True -> 1
  False -> False
```

GHC's diagnostic includes `Couldn't match expected type 'Int' with actual type 'Bool'`. Repair the second result to an integer, such as `0`. The earlier guard section covers a non-Boolean guard separately: the guard has type `Bool`, while its result has the case's result type.

## Summary

<Callout type="key" title="Remember">

Try alternatives from top to bottom. A pattern must match throughout; its names then become available in that alternative. Try guards in order and stop at the first `True`. If every guard fails, continue with the next alternative on the original scrutinee. Use `->` after a case pattern or guard, `=` after a function-equation guard. All results share one type. Check overlap, missing shapes, missing guarded outcomes and indentation before claiming a definition is complete.

</Callout>

<CheckQuestion question="Does a matching variable pattern guarantee a result?">

Only if it is unguarded, or one of its guards succeeds. If all guards are false, matching moves to the next alternative; if none succeeds, evaluation fails.

</CheckQuestion>

<CheckQuestion question="How do [x,y] and (x:y:rest) differ?">

The first requires exactly two elements. The second requires at least two and binds the remaining tail, which may be empty.

</CheckQuestion>

<CheckQuestion question="What does whole@(Just n) bind?">

It binds `whole` to the complete optional value and `n` to the payload. It does not match `Nothing`.

</CheckQuestion>

No. Put a calculation using `n` in that alternative's result with `let`, or use a helper that takes `n` as a parameter.

</CheckQuestion>

That comma-separated guard sequence fails. Try the next guard sequence, or the next alternative if no guards remain.
