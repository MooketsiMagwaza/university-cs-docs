Pattern matching selects between **equations**. But sometimes the decision belongs *inside* an expression — part-way through a definition, or on a value that is not one of the function's arguments. That is what `case` is for.

With guards, checking the value of one variable means rewriting `variable ==` on every line. A `case` expression states the variable once.

## 1. The form

```haskell
case expression of
  pattern1 -> result1
  pattern2 -> result2
  _        -> defaultResult
```

Read `->` as **“should return.”** The wildcard `_` catches everything remaining, exactly as in equation-level pattern matching.

| Placeholder | Stands for | Example |
|---|---|---|
| `expression` (after `case`) | The value being inspected — any expression, not necessarily a bare argument | `x`, `letter`, `length xs` |
| `of` | A keyword marking the start of the alternatives | (written exactly as `of`) |
| `pattern` | Same pattern forms as Section 3 of Pattern Matching: literal, variable, wildcard, tuple, list, cons | `0`, `'a'`, `_`, `(x, y)` |
| `->` | Separates a pattern from its result; read as "should return" | (written exactly as `->`) |
| `result` | What the whole `case` evaluates to when that alternative's pattern matches | `1`, `True`, `"Wednesday"` |

The whole block — `case ... of` plus every alternative — is one single **expression** with one single value once evaluated, exactly like `if...then...else`. That is what lets it appear anywhere a value is expected, including nested inside a larger expression, which Section 3 below relies on.

<QuizRef src="sem3/csi243/04-making-choices/notes/case-expressions" id="check-what-case-is-inspecting" />

```haskell
-- Map a small set of inputs to results, with a catch-all.
caseFunction :: Int -> Int
caseFunction x =
  case x of
    0 -> 1
    1 -> 5
    2 -> 2
    _ -> -1
```

```text
ghci> caseFunction 0
1
ghci> caseFunction 2
2
ghci> caseFunction 9
-1
```

As a program that runs every alternative, including the one the transcript above skips:

```haskell
main :: IO ()
main = do
  print (caseFunction 0)
  print (caseFunction 1)
  print (caseFunction 2)
  print (caseFunction 9)
```

```text
1
5
2
-1
```

Indentation is important here: the alternatives must be aligned with each other.

## 2. What can be scrutinised

The expression after `case` is not restricted to a bare argument. It can be:

- a single variable;
- a tuple;
- a calculation;
- a function applied to variables.

That is the essential difference from equation-level pattern matching, which can only inspect the arguments as they arrive.

```haskell
-- Match on a calculated value rather than on the argument itself.
parity :: Int -> String
parity n =
  case n `mod` 2 of
    0 -> "even"
    _ -> "odd"
```

```text
ghci> parity 4
"even"
ghci> parity 7
"odd"
```

```haskell
main :: IO ()
main = do
  putStrLn (parity 4)
  putStrLn (parity 7)
```

```text
even
odd
```

```haskell
-- Match on a tuple built from two arguments at once.
compareCounts :: Int -> Int -> String
compareCounts a b =
  case (a > b, a == b) of
    (True,  _)     -> "first is larger"
    (False, True)  -> "equal"
    (False, False) -> "second is larger"
```

```text
ghci> compareCounts 5 2
"first is larger"
ghci> compareCounts 3 3
"equal"
```

That transcript stops short of the third branch. As a program that reaches all three:

```haskell
main :: IO ()
main = do
  putStrLn (compareCounts 5 2)
  putStrLn (compareCounts 3 3)
  putStrLn (compareCounts 2 5)
```

```text
first is larger
equal
second is larger
```

### A second tuple example, a different domain

```haskell
-- Price a cinema ticket from age category and day of week.
ticketPrice :: (Bool, Bool) -> Double
ticketPrice (isChild, isWeekend) =
  case (isChild, isWeekend) of
    (True,  _)     -> 6.50
    (False, True)  -> 12.00
    (False, False) -> 9.50
```

```haskell
main :: IO ()
main = do
  print (ticketPrice (True, True))
  print (ticketPrice (False, True))
  print (ticketPrice (False, False))
```

```text
6.5
12.0
9.5
```

`ticketPrice (True, True)` matches `(True, _)` on the first alternative: a child's price is the same whether or not it's the weekend, so the wildcard in that position deliberately ignores the second component.

## 3. `case` is an expression

Like `if`, a `case` has a value and therefore a type. Every alternative must produce the same type, and the whole `case` can appear anywhere a value is expected — including inside a larger expression:

```haskell
-- The case sits inside a string concatenation.
report :: Int -> String
report n = "The number is " ++ case compare n 0 of
  LT -> "negative"
  EQ -> "zero"
  GT -> "positive"
```

```text
ghci> report (-4)
"The number is negative"
ghci> report 0
"The number is zero"
ghci> report 9
"The number is positive"
```

```haskell
main :: IO ()
main = do
  putStrLn (report (-4))
  putStrLn (report 0)
  putStrLn (report 9)
```

```text
The number is negative
The number is zero
The number is positive
```

This is something equation-level patterns cannot do: they select a whole equation, not a fragment of one.

## 4. Cases can carry guards

An alternative may be refined with guards, which keeps a nested decision readable:

```haskell
-- Classify the head of a list, or report that there is none.
classifyHead :: [Int] -> String
classifyHead xs =
  case xs of
    []    -> "empty list"
    (y:_)
      | y < 0     -> "starts negative"
      | y == 0    -> "starts at zero"
      | otherwise -> "starts positive"
```

```text
ghci> classifyHead []
"empty list"
ghci> classifyHead [-3, 1]
"starts negative"
ghci> classifyHead [0, 9]
"starts at zero"
ghci> classifyHead [7]
"starts positive"
```

```haskell
main :: IO ()
main = do
  putStrLn (classifyHead [])
  putStrLn (classifyHead [-3, 1])
  putStrLn (classifyHead [0, 9])
  putStrLn (classifyHead [7])
```

```text
empty list
starts negative
starts at zero
starts positive
```

If every guard under an alternative fails, matching continues with the next alternative.

## 5. Layout, and the explicit alternative

The alternatives are normally separated by line breaks and alignment. Haskell also accepts explicit braces and semicolons:

```haskell
caseFunction x = case x of { 0 -> 1 ; 1 -> 5 ; 2 -> 2 ; _ -> -1 }
```

This is valid but makes the code unreadable, and it is not used in this course. Prefer the layout form.

## 6. Choosing between the four forms

You now have four ways to express a choice. They overlap, but each has a shape it fits best.

### The same specification, four ways

Take the factorial specification:

```text
fac n = | 1               if n = 0
        | n * fac (n - 1) if n > 0
```

```haskell
-- 1. Conditional expression
facIf :: Integer -> Integer
facIf n = if n == 0 then 1 else n * facIf (n - 1)

-- 2. Pattern matching
facPat :: Integer -> Integer
facPat 0 = 1
facPat n = n * facPat (n - 1)

-- 3. Guards
facGuard :: Integer -> Integer
facGuard n
  | n == 0    = 1
  | otherwise = n * facGuard (n - 1)

-- 4. Case expression
facCase :: Integer -> Integer
facCase n =
  case n of
    0 -> 1
    _ -> n * facCase (n - 1)
```

```text
ghci> facIf 5
120
ghci> facPat 5
120
ghci> facGuard 5
120
ghci> facCase 5
120
```

Every call above uses `n = 5`, which only ever exercises the recursive case. As a program that also reaches the base case (`n = 0`) for each version:

```haskell
main :: IO ()
main = do
  print (facCase 0)
  print (facCase 5)
  print (facPat 0)
  print (facGuard 0)
  print (facIf 0)
```

```text
1
120
1
1
1
```

All four compute the same values. For this specification the pattern-matching version reads best, because the base case is a **literal**, which is exactly what a pattern expresses. Had the base case been `n <= 1`, guards would have read best, because that is a **range**.

<Callout type="info" title="The habit to build">
Write the specification first, then ask what the cases are made of. Literals and structures point to patterns. Ranges and compound tests point to guards. A computed value points to `case`. Two outcomes point to `if`.
</Callout>

## 7. Common errors

| Attempt | Problem | Repair |
|---|---|---|
| `case x of 0 = 1` | Alternatives use `->`, not `=` | `0 -> 1` |
| Misaligned alternatives | Layout decides what belongs to the `case` | Align every alternative in one column |
| Alternatives returning different types | A `case` is an expression with one type | Make every result the same type |
| No `_` alternative | `Non-exhaustive patterns in case` at run time | Add a wildcard alternative |
| `case` used where guards would do | Rewriting `x ==` on every line | Use guards for Boolean ranges |
