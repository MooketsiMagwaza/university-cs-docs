## 1. How to earn the tracing marks

Name the scrutinee; try alternatives in order; record the successful pattern's bindings; evaluate its guards in order; substitute into the chosen result. For guarded fall-through, explicitly say that matching continues with the **next alternative on the original value**.

For "write", give a type and a definition. For "trace", show failed attempts as well as the winning branch. For "find the error", name the defect, give a witness if relevant, and repair the code. The comments at the top of runnable solutions can serve as the question header when you copy a program to a file; keep only the comment when preparing a blank attempt.

### Exam question: first true wins

Trace `award 95` and state its printed result. (4 marks)

```haskell
award :: Int -> String
award x = case x of
  n
    | n >= 50 -> "pass"
    | n >= 80 -> "distinction"
    | otherwise -> "fail"
```

<Steps title="Answering the question">

<Step title="1. Read the question">

"Trace" requires the guard order, not the best-sounding grade. The input is 95.

</Step>

<Step title="2. Plan">

A variable pattern always matches. Test guards exactly as written.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: first true wins
award :: Int -> String
award x = case x of
  n
    | n >= 50 -> "pass"
    | n >= 80 -> "distinction"
    | otherwise -> "fail"

main :: IO ()
main = print (award 95)
```

```text
"pass"
```

</HaskellTryIt>

Bind `n = 95`. The first guard `95 >= 50` is true. Select `"pass"` immediately. The second guard would be true but is never selected.

</Step>

### Exam question: trace fall-through to the next alternative

Trace `pick [-3,8]` through every attempted pattern and guard. (6 marks)

```haskell
pick :: [Int] -> String
pick xs = case xs of
  (x:_)
    | x > 10 -> "large"
    | x > 0 -> "positive"
  [] -> "empty"
  (_:y:_) -> "has second"
  _ -> "other"
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command "trace" requires what happens after all guards fail. Do not stop when the first cons pattern fits.

</Step>

<Step title="2. Plan">

Preserve the original scrutinee while moving between alternatives.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: trace fall-through to the next alternative
pick :: [Int] -> String
pick xs = case xs of
  (x:_)
    | x > 10 -> "large"
    | x > 0 -> "positive"
  [] -> "empty"
  (_:y:_) -> "has second"
  _ -> "other"

main :: IO ()
main = print (pick [-3,8])
```

```text
"has second"
```

</HaskellTryIt>

The first pattern matches, binding `x = -3`. Test `-3 > 10`: false. Test `-3 > 0`: false. No guards remain, so try the next alternative on `[-3,8]`. The pattern `[]` fails. `(_:y:_)` matches, binding `y = 8` and an empty final tail. Return `"has second"`; the last wildcard is skipped.

</Step>

<Step title="4. Check">

For `[-3]`, the guarded pattern still fails its tests, `[]` fails and the two-cons pattern fails; the last wildcard returns `"other"`. This confirms that fall-through does not inspect only the tail.

</Step>

</Steps>

</details>

"Write" asks for a definition; the guards must use the fields bound by the tuple.

<Step title="2. Plan">

-- Question: tuple fields in guards

### Exam question: a guarded cons is not enough

Find an input that makes `unsafeHead` crash, explain why, and repair it to return `Nothing` whenever there is no positive head. (5 marks)

```haskell
-- Incorrect: guarded coverage is incomplete.
unsafeHead :: [Int] -> Maybe Int
unsafeHead xs = case xs of
  (x:_) | x > 0 -> Just x
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Find" needs a concrete witness. "Repair" needs a definition covering both structural and guarded failure.

</Step>

<Step title="2. Plan">

Use `[]` to show structural failure and `[0]` to show guarded failure. Add a later catch-all.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: a guarded cons is not enough
positiveHead :: [Int] -> Maybe Int
positiveHead xs = case xs of
  (x:_) | x > 0 -> Just x
  _ -> Nothing

main :: IO ()
main = do
  print (positiveHead [])
  print (positiveHead [0])
  print (positiveHead [3,9])
```

```text

Nothing
Just 3
```

</HaskellTryIt>

In the original, `[]` fails the cons pattern and has no next alternative. `[0]` matches the cons but fails `0 > 0`, again with no next alternative. The key run-time text is `Non-exhaustive patterns in case`. The repair covers both paths.

</Step>

<Step title="4. Check">

With `[-1]` the repair falls through to `Nothing`. With `[3,9]`, `x = 3` passes the guard and returns `Just 3`; the later element is irrelevant.

</Step>

</Steps>

</details>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Keeping" means returning `Just n`, not merely `n`. Zero must be retained.

<Step title="2. Plan">

Use `Just n` to expose the field, `n >= 0` to test it, and a catch-all for every failure.

Nothing
Nothing

</HaskellTryIt>

</Step>

Replacing `>=` by `>` would wrongly discard `Just 0`. The shown boundary check detects that mistake.

</Step>

</Steps>

### Exam question: guards on a custom constructor

Given `data Ticket = Cancelled | Active Int`, write `usable :: Ticket -> Bool`, true exactly for an active ticket with a positive remaining count. Use a case guard. (4 marks)

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The stored integer matters only for `Active`. Cancelled tickets are always unusable.

</Step>

<Step title="2. Plan">

Test the field under its constructor pattern; use one catch-all to cover cancellation and non-positive counts.

<Step title="3. Solution">

<HaskellTryIt>

```haskell

</HaskellTryIt>

</Step>

</Steps>

### Exam question: a pattern guard plus a Boolean guard

Trace `credit "b"` and `credit "missing"`. Explain exactly which qualifier fails. (5 marks)

```haskell
credit :: String -> Maybe Int
credit key = case key of
  k
    | Just v <- lookup k [("a",3),("b",-3)], v > 0 -> Just v
    | otherwise -> Nothing
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Trace" asks about two different failure paths: a found negative value and an absent key.

</Step>

<Step title="2. Plan">

A comma-separated sequence needs every qualifier to succeed; evaluate left to right.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: a pattern guard plus a Boolean guard
credit :: String -> Maybe Int
credit key = case key of
  k
    | Just v <- lookup k [("a",3),("b",-3)], v > 0 -> Just v
    | otherwise -> Nothing

main :: IO ()
main = do
  print (credit "b")
  print (credit "missing")
  print (credit "a")
```

```text
Nothing
Nothing
Just 3
```

</HaskellTryIt>

For `"b"`, `k` matches, lookup returns `Just (-3)` and binds `v = -3`. The Boolean qualifier fails, so `otherwise` returns `Nothing`. For `"missing"`, lookup returns `Nothing`; `Just v` fails, and `v > 0` is skipped. For `"a"`, both qualifiers succeed and return `Just 3`.

</Step>

<Step title="4. Check">

A successful pattern guard is not the same as the whole guarded result succeeding. The printed positive case checks the complete success path.

</Step>

</Steps>

</details>

### Exam question: convert function guards in both directions

Rewrite `level` using case guards, then state how to reverse your conversion. (4 marks)

```haskell
level :: Int -> Int
level n
  | n < 0 = -1
  | n == 0 = 0
  | otherwise = 1
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Rewrite" requires equivalent behaviour and the same order, not a different classification.

</Step>

<Step title="2. Plan">

Introduce a variable alternative; preserve the tests; change each guard separator from `=` to `->`.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: convert function guards in both directions
level :: Int -> Int
level input = case input of
  n
    | n < 0 -> -1
    | n == 0 -> 0
    | otherwise -> 1

main :: IO ()
main = print (level (-2), level 0, level 5)
```

```text
(-1,0,1)
```

</HaskellTryIt>

The variable pattern binds every input. Negative input succeeds first; zero fails the first test and succeeds second; positive input reaches `otherwise`. To reverse it, remove `case input of n`, make `n` the function parameter, and replace guard arrows with equals signs.

</Step>

<Step title="4. Check">

The triple checks every outcome. Do not change the initial definition `level input = ...`; that equals sign remains necessary.

</Step>

</Steps>

</details>

### Exam question: repair case guard punctuation and type

Fix both errors in the following definition and explain the relevant GHC diagnostics. (4 marks)

```haskell
-- Incorrect: equals after a case guard, and an Int used as a test.
bad :: Int -> Int
bad x = case x of
  n | n = 1
  _ -> 0
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Fix both" means a syntax repair alone is insufficient. The guard is required to be Boolean.

</Step>

<Step title="2. Plan">

First replace `=` after the guard with `->`. Then replace the bare integer guard with an explicit nonzero test.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: repair case guard punctuation and type
fixed :: Int -> Int
fixed x = case x of
  n | n /= 0 -> 1
  _ -> 0

main :: IO ()
main = print (fixed 0, fixed 4)
```

```text
(0,1)
```

</HaskellTryIt>

The original syntax gives `parse error on input '='`. After changing that separator alone, the bare `n` has type `Int`, so the diagnostic includes `Couldn't match expected type 'Bool' with actual type 'Int'`. The repaired test is Boolean.

</Step>

<Step title="4. Check">

At zero, the variable matches but the guard fails, so `_` gives `0`. At four, the guard succeeds and gives `1`.

</Step>

</Steps>

</details>

## 3. Patterns, conversions and complete definitions

### Exam question: multiple equations to case and back

Rewrite the following as one equation using `case`, and state the reverse conversion. (4 marks)

```haskell
points :: [Int] -> Int
points [] = 0
points [x] = x
points (x:y:rest) = x + y
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Rewrite" requires preserving both pattern order and bound names. The third pattern means at least two elements.

</Step>

<Step title="2. Plan">

Use a fresh list parameter and move each argument pattern to an alternative, replacing `=` with `->`.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: multiple equations to case and back
points :: [Int] -> Int
points xs = case xs of
  [] -> 0
  [x] -> x
  (x:y:rest) -> x + y

main :: IO ()
main = print (points [], points [7], points [3,4,9])
```

```text
(0,7,7)
```

</HaskellTryIt>

The empty list matches first. `[7]` fails empty and binds `x = 7` in the second alternative. `[3,4,9]` fails the exact lengths, then binds `x = 3`, `y = 4`, `rest = [9]`. To reverse, move the alternative patterns back into argument positions and replace arrows with equals signs.

</Step>

<Step title="4. Check">

Check `[3,4]`: the third alternative still matches with `rest = []`, returning `7`. It does not require a third element.

</Step>

</Steps>

</details>

Rewrite `if x > 0 then "positive" else if x == 0 then "zero" else "negative"` using `case compare x 0 of`. (4 marks)

<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command "rewrite" requests one equivalent expression with three outcomes.

<Step title="2. Plan">

`compare` turns less than, equality and greater than into `LT`, `EQ`, `GT`.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

-- Question: nested if to case
signWord :: Int -> String

  EQ -> "zero"
  GT -> "positive"

main :: IO ()
main = print (signWord (-2), signWord 0, signWord 6)

("negative","zero","positive")

```

</HaskellTryIt>

`[4]` fails `[]`, then matches `(_:_)`, so its result is `"non-empty"`. Every singleton also matches that earlier cons pattern. GHC can warn `Pattern match is redundant` for the last alternative. The warning is separate from printed program output.

</Step>

<Step title="4. Check">

Repair by placing `[_]` before `(_:_)`. Then `[4]` gives `"single"` and `[4,5]` still gives `"non-empty"`.

</Step>

</Steps>

</details>

### Exam question: fix nested layout

Repair the indentation so the optional value is checked first and the Boolean second. (4 marks)

```haskell
-- Incorrect: inner and outer alternatives have been mixed.
answer :: Maybe Bool -> String
answer value = case value of
  Just b -> case b of
  True -> "yes"
  False -> "no"
  Nothing -> "missing"
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

"Repair" asks which case owns each alternative. `Nothing` belongs to `Maybe Bool`; `True` and `False` belong to the inner `Bool`.

</Step>

<Step title="2. Plan">

Indent the Boolean alternatives further than `Just b`, and align `Nothing` with `Just b`.

</Step>

<Step title="3. Solution">

```haskell

answer :: Maybe Bool -> String

  Just b -> case b of

The broken layout can produce a parse error or an incorrectly attached alternative; restoring the intended nesting resolves both concerns.

</Step>

### Exam question: nested and as-patterns with local scope

Which alternative matches `Just [2,3]` below, what are the bindings, and why can `extra` not be moved unchanged into a whole-equation `where`? (5 marks)

```haskell
inspect :: Maybe [Int] -> ([Int], Int)
inspect value = case value of
  Just [] -> ([],0)
  Just whole@(x:_) -> let extra = x + 1 in (whole,extra)
  Nothing -> ([],0)
```


<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

The command "which" needs the matching alternative and bindings. The scope question asks where `x` is introduced.

</Step>

<Step title="2. Plan">

Match all nested structure before computing the local result. Locate the boundary between equation scope and alternative scope.

</Step>

<Step title="3. Solution">

<HaskellTryIt>

```haskell
-- Question: nested and as-patterns with local scope
inspect :: Maybe [Int] -> ([Int], Int)
inspect value = case value of
  Just [] -> ([],0)
  Just whole@(x:_) -> let extra = x + 1 in (whole,extra)
  Nothing -> ([],0)

main :: IO ()
main = print (inspect (Just [2,3]))
```

```text
([2,3],3)
```

</HaskellTryIt>

`Just []` fails on the inner non-empty list. The second alternative matches: `whole = [2,3]`, `x = 2`. The local `extra` is `3`, giving `([2,3],3)`. An equation-level `where` cannot see alternative-bound `x`; moving `extra = x + 1` there would give `Variable not in scope: x`.

</Step>

<Step title="4. Check">

`inspect (Just [])` takes the first alternative, and `inspect Nothing` takes the last. Keep `extra` local, or define a shared helper with its own parameter and call it with `x`.

</Step>

</Steps>

</details>

## 4. Common errors to check before handing in

| Mistake | What it changes or triggers | Repair |
|---|---|---|
| Stop after a guarded pattern matches | Misses possible guard failure and fall-through | Trace all attempted guards before selecting a result |
| Put a broad guard before a narrow one | The broad true guard wins | Order priority explicitly |
| Write `=` after a case guard | `parse error on input '='` | Use `->` |
| Use a bare `Int` as a guard | Expected `Bool`, actual `Int` | Write a Boolean comparison |
| Omit absence, an empty list or guarded failure | `Non-exhaustive patterns in case` at run time | Add the missing outcomes |
| Return `_` as if it named a value | `Found hole: _` | Bind a named pattern |
| Mix result types | `Couldn't match expected type` | Give every result one compatible type |

## Summary

<Callout type="key" title="Remember">

An exam trace follows the code's order, not the intended categories. A matching guarded pattern can still fall through. Case guards use arrows; function guards use equals signs. Nested patterns must match at every layer. Check all constructors, list lengths and boundary values, and keep pattern-bound names inside their scope.

</Callout>
