## Chapter 4: Making Choices

Almost every useful function treats some inputs differently from others. Haskell offers four ways to express that choice. They are not interchangeable stylistic preferences: each one reads best for a particular shape of decision, and this chapter teaches you to recognise which shape you have.

| Order | Lesson | Main question |
|---:|---|---|
| 1 | [Conditional Expressions](/docs/sem3/csi243/04-making-choices/notes/conditional-expressions) | How does `if … then … else` produce a value, and why must the `else` always be present? |
| 2 | [Pattern Matching](/docs/sem3/csi243/04-making-choices/notes/pattern-matching) | How does Haskell select an equation by the *shape* of an argument? |
| 3 | [Guarded Equations](/docs/sem3/csi243/04-making-choices/notes/guards) | How do I choose between results using Boolean conditions? |
| 4 | [Case Expressions](/docs/sem3/csi243/04-making-choices/notes/case-expressions) | How do I match patterns inside an expression, and which form should I reach for? |

## Placeholders used across this chapter's templates

Every construct in this chapter is written from the same small vocabulary. Once these names are fixed, every template below reads the same way:

| Placeholder | Meaning | Seen in |
|---|---|---|
| `funcName` / `functionName` | The identifier you give the function | All four forms |
| `param` / `parameters` | A name that receives an input value, with no pattern to match | Guards, if-then-else |
| `pattern` | A literal, variable, wildcard, tuple, list, or cons shape matched against a value | Pattern matching, `case` |
| `condition` | A Boolean expression — evaluates to `True` or `False`, nothing else | if-then-else, guards |
| `expression` / `result` | The value produced once a pattern matches or a condition succeeds | All four forms |

## Chapter outcomes

- Write a conditional expression and explain why Haskell requires the `else` branch.
- Select an equation by pattern matching and explain why order matters.
- Write guarded equations with a correctly placed `otherwise`.
- Use `case … of` inside a larger expression.
- Recognise and repair a non-exhaustive set of cases.
- Implement one specification in all four forms and justify which reads best.
