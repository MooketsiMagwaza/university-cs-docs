## 1. Placeholders used in every template on this page

| Placeholder | Meaning | Example |
|---|---|---|
| `funcName` | The name you give the function | `isZero`, `grade`, `square` |
| `param` / `parameters` | A name that receives an input value, with no pattern to match on | `x`, `n`, `mark` |
| `pattern` | A literal, variable, wildcard, tuple, list, or cons shape to match an argument against | `0`, `True`, `(x:xs)`, `_` |
| `expression` / `result` | What the equation, guard, or alternative evaluates to | `x * x`, `True`, `"Invalid"` |
| `condition` | A Boolean test | `mark >= 80`, `n == 0` |

## 2. Function equations and pattern matching

**What it's called:** a function defined this way is a set of **equations**; `_` is the **wildcard pattern**; choosing between equations by their shape is **pattern matching**.

**Template:**
```haskell
funcName :: InputType -> OutputType
funcName pattern1 = expression1
funcName pattern2 = expression2
funcName _        = fallbackExpression   -- catch-all
```

**Example:**
```haskell
describeNumber :: Int -> String
describeNumber 0 = "Zero"
describeNumber 1 = "One"
describeNumber _ = "Some other number"
```
```text
ghci> describeNumber 0
"Zero"
ghci> describeNumber 99
"Some other number"
```

### The wildcard `_`

Matches anything, binds no name. Use it as a catch-all, or to ignore part of a tuple/list.

```haskell
getFirst :: (a, b) -> a
getFirst (x, _) = x
```
`getFirst (10, 20)` → `10`.

### Order matters — most specific first

Equations are tried **top to bottom**; the first match wins. A wildcard or bare variable placed first swallows everything below it.

```haskell
-- WRONG: the wildcard/variable pattern comes first.
describeWrong :: Int -> String
describeWrong _ = "Some other number"   -- matches EVERYTHING
describeWrong 0 = "Zero"                -- unreachable
```
`describeWrong 0` → `"Some other number"`, and GHC says so at compile time:
```text
warning: [-Woverlapping-patterns]
    Pattern match is redundant
    In an equation for `describeWrong': describeWrong 0 = ...
```

**Rule:** most specific pattern first, most general (`_` or a bare variable) last.

### `if ... then ... else`

Both branches compulsory; both must have the **same type**.

```haskell
funcName param =
  if condition
    then expressionIfTrue
    else expressionIfFalse
```
```haskell
resultLabel :: Double -> String
resultLabel mark = if mark >= 50 then "Pass" else "Fail"
```
`resultLabel 64` → `"Pass"`. `resultLabel 49.5` → `"Fail"`.

### Guards (`|`)

```haskell
funcName param
  | condition1 = expression1
  | condition2 = expression2
  | otherwise  = defaultExpression
```
```haskell
grade :: Int -> String
grade mark
  | mark >= 80 = "A"
  | mark >= 70 = "B"
  | otherwise  = "F"
```
`grade 85` → `"A"`. `otherwise` is an ordinary Prelude binding equal to `True` — not special syntax.

### `case ... of`

```haskell
funcName param =
  case expressionToInspect of
    pattern1 -> result1
    pattern2 -> result2
    _        -> defaultResult
```
```haskell
isVowel :: Char -> Bool
isVowel letter =
  case letter of
    'a' -> True
    'e' -> True
    'i' -> True
    'o' -> True
    'u' -> True
    _   -> False
```
`isVowel 'e'` → `True`. `isVowel 'z'` → `False`.

<Callout type="info" title="case can inspect any expression, not just a bare argument">
`case length xs of 0 -> "empty"; _ -> "has elements"` is valid — `length xs` is computed first, and *that result* is what gets matched, not `xs` itself. That is the one thing `case` can do that equation-level pattern matching cannot.
</Callout>

### Local bindings: `where` and `let`

| Form | Attaches to | Visible to |
|---|---|---|
| `where` | The whole equation | Every guard and every result in that equation |
| `let ... in ...` | One expression | Only the expression after `in` |

```haskell
bmiTell :: Double -> Double -> String
bmiTell weight height
  | bmi < 18.5 = "Underweight"
  | otherwise  = "Normal"
  where bmi = weight / (height ^ 2)
```
`bmiTell 70 1.75` → `"Normal"`.

## 4. Common errors, at a glance

| Symptom | Cause | Fix |
|---|---|---|
| Compiles, but an early case "steals" a later one | Wildcard/variable pattern too early | Reorder: specific first |
| `Non-exhaustive patterns` at run time | A possible input has no matching equation/guard/alternative | Add a catch-all (`_` or `otherwise`) |
| Missing `else` | `if` is an expression in Haskell — both branches required | Add `else` |
| Two branches, two types | `if`/`case` needs one type for the whole expression | Make both branches the same type |
| `where` definitions misaligned | Indentation is significant | Align every `where` binding under itself |
