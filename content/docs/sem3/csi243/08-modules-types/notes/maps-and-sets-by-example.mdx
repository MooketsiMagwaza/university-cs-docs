`Data.Map` and `Data.Set` come from **containers**, a package that ships with GHC, rather than base. The examples assume a normal GHC installation with containers available; no separate installation is needed for these exercises. A package supplies modules; a qualified import gives their exported names a prefix. Every complete program below includes its imports inside its Haskell fence.

`Map.Map k v` holds keys of type k and values of type v. `Set.Set a` holds elements of type a. Ordered searches and insertions need Ord keys or elements; map values do not need ordering. Updates return new values. Keep their results to retain the changes.

**Ordering correction.** A Map does not preserve insertion order, but it is an ordered-key structure: Map.toList and Map.keys traverse ascending keys. Calling it simply "unsorted" hides this distinction. Set traversal is likewise ascending. Neither structure retains repeated occurrences and encounter order as a list does.

Diagnostics below are key phrases rather than complete compiler transcripts. A valid program with the wrong duplicate policy often produces no compiler warning.

## 1. Association list, Map or Set

An association list is an ordinary list of key/value pairs. It can repeat keys and retains pair order; Prelude.lookup takes the first matching pair. A Map stores one value per key; fromList keeps the last pair for a repeated key. A Set stores unique elements without associated values.

**Template and reading guide.** `lookup key pairs`, `Map.lookup key (Map.fromList pairs)` and `Set.member item (Set.fromList items)` ask different questions. `Prelude.lookup :: Eq k => k -> [(k,v)] -> Maybe v` searches pairs; Map.lookup needs Ord keys.

### Duplicate-key policies

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

pairs :: [(String,Int)]
pairs = [("a",1),("a",2)]

main :: IO ()
main = print ((lookup "a" pairs, lookup "z" pairs, Map.lookup "a" (Map.fromList pairs), Map.lookup "z" (Map.fromList pairs)))
```

```text
(Just 1,Nothing,Just 2,Nothing)
```

</HaskellTryIt>

The list finds first a, the Map retains last a, and both return Nothing for missing z.

### Order and information

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

pairs :: [(String,Int)]
pairs = [("b",2),("a",1),("b",3)]

main :: IO ()
main = print ((pairs, Map.toList (Map.fromList pairs), Set.toList (Set.fromList (map fst pairs))))
```

```text
([("b",2),("a",1),("b",3)],[("a",1),("b",3)],["a","b"])
```

</HaskellTryIt>

The list keeps all events; Map keeps latest b in key order; Set keeps only names.

### Empty structures

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print ((lookup "a" ([] :: [(String,Int)]), Map.lookup "a" (Map.empty :: Map.Map String Int), Set.member "a" (Set.empty :: Set.Set String)))
```

```text
(Nothing,Nothing,False)
```

</HaskellTryIt>

Neither optional lookup finds a value. Set membership returns a Boolean instead.

## 2. Map.empty

Map.empty holds no bindings. Its two type parameters describe permitted keys and values, not existing entries. Context or an annotation selects those types.

**Template and reading guide.** `Map.empty :: Map.Map keyType valueType`. The general type `Map.empty :: Map.Map k v` has no Ord constraint.

### Empty marks

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.empty :: Map.Map String Int))
```

```text
[]
```

</HaskellTryIt>

No key/value pairs are stored.

### A different value type

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.empty :: Map.Map Int String))
```

```text
[]
```

</HaskellTryIt>

Integer keys and String values still produce no pairs when empty.

### Values can be lists

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.size (Map.empty :: Map.Map Bool [Int]))
```

```text
0
```

</HaskellTryIt>

There are no bindings, even though each permitted value is itself a list.

## 3. Map.fromList and duplicate keys

Map.fromList constructs bindings from pairs, retaining the last value for each repeated key. Keys are compared with Ord; values need no Ord instance. Traversal order becomes key order.

**Template and reading guide.** `Map.fromList pairs`, with `Map.fromList :: Ord k => [(k,v)] -> Map.Map k v`. Every pair must have the same key and value types.

### Later mark replaces earlier

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.fromList [("b",2),("a",1),("b",9)]))
```

```text
[("a",1),("b",9)]
```

</HaskellTryIt>

Last b wins, then a is traversed before b.

### String values

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.fromList [(2,"old"),(1,"one"),(2,"new")]))
```

```text
[(1,"one"),(2,"new")]
```

</HaskellTryIt>

Key 2 ends with new; values are not sorted independently.

### No pairs

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.fromList ([] :: [(String,Int)])))
```

```text
[]
```

</HaskellTryIt>

The empty pair list constructs the empty map.

## 4. Map.toList

Map.toList walks ascending keys and returns each binding as a pair. It does not sort values or recover insertion order. Keeping pairs together preserves their association.

**Template and reading guide.** `Map.toList table`, with `Map.toList :: Map.Map k v -> [(k,v)]`. Walking an existing map needs no new Ord constraint.

### Values follow their keys

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.fromList [(3,"a"),(1,"z"),(2,"m")]))
```

```text
[(1,"z"),(2,"m"),(3,"a")]
```

</HaskellTryIt>

Keys 1,2,3 determine the order; z therefore comes before a.

### Singleton map

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.fromList [("only",True)]))
```

```text
[("only",True)]
```

</HaskellTryIt>

The single binding becomes one pair in a list.

### Empty map

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.toList (Map.empty :: Map.Map Int Bool))
```

```text
[]
```

</HaskellTryIt>

There are no pairs to traverse.

### Exam question 4: Map.toList (6 marks)

A map was built with keys 3, then 1, then 2. Explain what determines toList order.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

"Explain" asks for the ordering rule after construction with keys 3,1,2. No value ordering or insertion-order requirement is supplied.

</Step>

<Step title="2. Plan">

Distinguish the update sequence from the map's traversal rule.

</Step>

## 5. Map.lookup

Map.lookup returns Just value for a present key and Nothing for an absent one. A stored zero, False or empty String is still a present value. The Maybe wrapper records absence separately.

**Template and reading guide.** `Map.lookup key table`, with `Map.lookup :: Ord k => k -> Map.Map k v -> Maybe v`. Compare Prelude.lookup, whose second argument is a pair list.

### Stored zero, missing name and empty map

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [("a",0 :: Int)]

main :: IO ()
main = print ((Map.lookup "a" m, Map.lookup "z" m, Map.lookup "a" (Map.empty :: Map.Map String Int)))
```

```text
(Just 0,Nothing,Nothing)
```

</HaskellTryIt>

a is present with zero. Missing z and empty-map searches give Nothing.

### Integer keys and String values

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(1 :: Int,"one"),(2,"two")]

main :: IO ()
main = print ((Map.lookup 2 m, Map.lookup 9 m, Map.lookup 2 (Map.empty :: Map.Map Int String)))
```

```text
(Just "two",Nothing,Nothing)
```

</HaskellTryIt>

Just wraps the String, which retains its printed quotes.

### Pair keys and Boolean values

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [((1 :: Int,2 :: Int),False)]

main :: IO ()
main = print ((Map.lookup (1,2) m, Map.lookup (2,1) m, Map.lookup (1,2) (Map.empty :: Map.Map (Int,Int) Bool)))
```

```text
(Just False,Nothing,Nothing)
```

</HaskellTryIt>

The whole pair identifies a key; swapping fields requests a different key. False is a present value.

## 6. Map.member

Map.member tests keys, returning Bool. It does not search the values and does not return the stored value. Use lookup if the value is also needed.

**Template and reading guide.** `Map.member key table`, with `Map.member :: Ord k => k -> Map.Map k v -> Bool`.

### Present zero and absent name

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [("a",0 :: Int)]

main :: IO ()
main = print ((Map.member "a" m, Map.member "z" m, Map.member "a" (Map.empty :: Map.Map String Int)))
```

```text
(True,False,False)
```

</HaskellTryIt>

a is a stored key regardless of its value; z and empty-map a are absent.

### Negative key

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(-1 :: Int,"minus")]

main :: IO ()
main = print ((Map.member (-1) m, Map.member 0 m, Map.member (-1) (Map.empty :: Map.Map Int String)))
```

```text
(True,False,False)
```

</HaskellTryIt>

Negative one is present and zero absent; parentheses delimit the negative argument.

### Empty value

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(False,"")]

main :: IO ()
main = print ((Map.member False m, Map.member True m, Map.member False (Map.empty :: Map.Map Bool String)))
```

```text
(True,False,False)
```

</HaskellTryIt>

An empty String value does not make its False key absent.

## 7. Map.insert

Map.insert adds an absent key or replaces an existing key's value. Replacement does not increase size. Every insertion returns a new map; the old value remains available.

**Template and reading guide.** `Map.insert key value oldMap`, with `Map.insert :: Ord k => k -> v -> Map.Map k v -> Map.Map k v`.

### Replace, add and begin empty

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [("a",1 :: Int)]

main :: IO ()
main = print ((Map.toList (Map.insert "a" 9 m), Map.toList (Map.insert "z" 9 m), Map.toList (Map.insert "a" 9 Map.empty), Map.toList m))
```

```text
([("a",9)],[("a",1),("z",9)],[("a",9)],[("a",1)])
```

</HaskellTryIt>

Existing a is replaced; absent z is added; empty becomes a singleton. Original m keeps a=1.

### String replacements

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(1 :: Int,"old")]

main :: IO ()
main = print ((Map.toList (Map.insert 1 "new" m), Map.toList (Map.insert 2 "two" m), Map.toList m))
```

```text
([(1,"new")],[(1,"old"),(2,"two")],[(1,"old")])
```

</HaskellTryIt>

Key 1 is present and 2 absent. Both results start from the same original.

### Zero does not delete

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(False,5 :: Int)]

main :: IO ()
main = print ((Map.toList (Map.insert False 0 m), Map.toList (Map.insert True 0 m), Map.toList m))
```

```text
([(False,0)],[(False,5),(True,0)],[(False,5)])
```

</HaskellTryIt>

Existing False remains present with new zero; absent True becomes a new key.

## 8. Map.delete

Map.delete removes a present key and leaves an absent key's map unchanged in content. It retains all other bindings and does not alter the original map.

**Template and reading guide.** `Map.delete key oldMap`, with `Map.delete :: Ord k => k -> Map.Map k v -> Map.Map k v`.

### Present, absent and empty deletion

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [("a",1 :: Int),("b",2)]

main :: IO ()
main = print ((Map.toList (Map.delete "a" m), Map.toList (Map.delete "z" m), Map.toList (Map.delete "a" (Map.empty :: Map.Map String Int)), Map.toList m))
```

```text
([("b",2)],[("a",1),("b",2)],[],[("a",1),("b",2)])
```

</HaskellTryIt>

Deleting a removes its binding; z changes nothing; empty stays empty; original m survives.

### Singleton deletion

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(1 :: Int,"one")]

main :: IO ()
main = print ((Map.toList (Map.delete 1 m), Map.toList (Map.delete 2 m), Map.toList m))
```

```text
([],[(1,"one")],[(1,"one")])
```

</HaskellTryIt>

Removing the only key makes an empty result; an absent key leaves the singleton.

### Keys, not values

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

m = Map.fromList [(1 :: Int,9 :: Int),(2,1)]

main :: IO ()
main = print ((Map.toList (Map.delete 1 m), Map.toList (Map.delete 9 m), Map.toList m))
```

```text
([(2,1)],[(1,9),(2,1)],[(1,9),(2,1)])
```

</HaskellTryIt>

Delete key 1, not value 1. Missing key 9 does not remove the entry whose value is 9.

## 9. Map.size

Map.size counts bindings, hence distinct keys. It does not count input pairs before duplicate resolution or the lengths of stored values. Its result type is Int.

**Template and reading guide.** `Map.size table`, with `Map.size :: Map.Map k v -> Int`.

### No keys

<HaskellTryIt>

```haskell

import qualified Data.Set as Set

main :: IO ()
main = print (Map.size (Map.empty :: Map.Map String Int))
```

```text
0
```

</HaskellTryIt>

No bindings means zero.

### Repeated source key

<HaskellTryIt>

```haskell

import qualified Data.Set as Set

main :: IO ()
main = print (Map.size (Map.fromList [("a",1),("a",2),("b",3)]))
```


</HaskellTryIt>

Three input pairs resolve to two distinct keys.

<HaskellTryIt>

## 10. Map.keys

Map.keys extracts each key once in ascending order. It discards values and returns a list, not a Set. Duplicate source keys have already been resolved.

**Template and reading guide.** `Map.keys table`, with `Map.keys :: Map.Map k v -> [k]`.

### Names in key order

<HaskellTryIt>

```haskell
import qualified Data.Map as Map
import qualified Data.Set as Set

main :: IO ()
main = print (Map.keys (Map.fromList [("b",2),("a",1),("b",3)]))
```

```text
["a","b"]
```

</HaskellTryIt>

The final map has two keys, a then b.

### Numeric keys

## 12. Immutable update and retaining the result

An update calculates a new value. The old binding still refers to its original collection. Updates calculated independently from old do not automatically combine; chain the returned values.

**Template and reading guide.** `let new = operation arguments old`, then query new. Pass new into the next operation to keep both changes. This pattern applies to Map and Set.

### Independent map versions

<HaskellTryIt>

```haskell
import qualified Data.Set as Set

added = Map.insert "z" 8 old

main = print ((Map.toList old, Map.toList replaced, Map.toList added))
```

```text
([("a",1)],[("a",9)],[("a",1),("z",8)])
```

</HaskellTryIt>

Replacing existing a and adding absent z separately produce separate versions. Neither changes old.

<HaskellTryIt>

## 29. Shared names, different types

| Name | Map version | Set or list version |
|---|---|---|
| empty | `Map.empty :: Map.Map k v` | `Set.empty :: Set.Set a` |
| fromList | `Map.fromList :: Ord k => [(k,v)] -> Map.Map k v` | `Set.fromList :: Ord a => [a] -> Set.Set a` |
| toList | `Map.toList :: Map.Map k v -> [(k,v)]` | `Set.toList :: Set.Set a -> [a]` |
| lookup | `Map.lookup :: Ord k => k -> Map.Map k v -> Maybe v` | `Prelude.lookup :: Eq k => k -> [(k,v)] -> Maybe v` |
| member | `Map.member :: Ord k => k -> Map.Map k v -> Bool` | `Set.member :: Ord a => a -> Set.Set a -> Bool` |
| insert | `Map.insert :: Ord k => k -> v -> Map.Map k v -> Map.Map k v` | `Set.insert :: Ord a => a -> Set.Set a -> Set.Set a` |
| delete | `Map.delete :: Ord k => k -> Map.Map k v -> Map.Map k v` | `Set.delete :: Ord a => a -> Set.Set a -> Set.Set a` |
| size | `Map.size :: Map.Map k v -> Int` | `Set.size :: Set.Set a -> Int` |
| union | `Map.union :: Ord k => Map.Map k v -> Map.Map k v -> Map.Map k v` | `Set.union :: Ord a => Set.Set a -> Set.Set a -> Set.Set a` |

The prefixes help you read the operation. Data.List.insert inserts into an already ordered list, retaining repeated occurrences; Set.insert ensures membership; Map.insert provides a value for a key. The compiler checks argument types but cannot choose the intended duplicate policy for you.

The [Eq and Class Constraints](/docs/sem3/csi243/09-polymorphism/notes/eq-and-class-constraints) lesson covers list equality operations. The new choice here is representation and ordering: Map and Set operations use ordered keys or elements, while association-list lookup only requires equality. For tree-operation costs rather than a catalogue of library names, use [Complexity by Recurrence](/docs/sem3/csi243/10-reasoning-revision/notes/complexity-by-recurrence).

Lists retain occurrence order; Maps retain one value per key and traverse ordered keys; Sets retain unique ordered elements. Map.fromList keeps the last duplicate key. lookup preserves absence with Maybe; member returns Bool. Updates return new collections. Map.insert replaces while Set.insert ensures membership. Missing deletion is harmless. Union means either, intersection both, difference left excluding right, and subset every candidate is allowed. Select collision combiners deliberately and check their argument order.

No. Use the returned collection and pass it into later operations to retain changes.
