A type synonym renames an existing type. The `data` declaration creates a **genuinely new type**, distinct from every other, which the compiler will keep separate.

### The `data` template, formalised, and its four shapes

**Template:**
```haskell
data TypeName = Constructor1 Field1 Field2 | Constructor2
  deriving (ClassName1, ClassName2)
```
Read `TypeName` as the answer to "what type did I just create?", and each `Constructor` as one *way* to build a value of it — `|` between constructors reads as "or." A constructor with nothing listed after its name (`Constructor2` above) needs no arguments to build; a constructor followed by one or more types takes exactly that many arguments, in that order, every single time it is used.

**Example — no fields at all (an enumeration):**
```haskell
data Result = Pass | Fail deriving (Show, Eq)
```
Worked in full in Section 1 below. Neither constructor carries any data; the type's only content *is* which of the two constructors a given value uses.

**A variation: one constructor, with fields**
```haskell
data Point = Point Float Float deriving (Show)
```
Worked in full in Section 3 below. One constructor, `Point`, takes two `Float`s — it is a genuine curried function, `Float -> Float -> Point`, exactly like any two-argument function from Chapter 7, only this one builds a value instead of computing one.

**A variation: multiple constructors, each with its own fields**
```haskell
data Shape = Circle Float | Rectangle Float Float deriving (Show)
```
Also Section 3. Different constructors of the same type may carry completely different numbers and kinds of fields — `Circle` carries one `Float`, `Rectangle` carries two — and a function pattern-matching over `Shape` needs one equation per constructor to stay exhaustive.

**A variation: record syntax — the fields get names**
```haskell
data Student = Student { studentName :: String, studentMark :: Int } deriving (Show)
```
Worked in full in Sections 5.1–5.2 below, including the accessor functions GHC generates for free and `{ field = newValue }` update syntax. This is still exactly one constructor with two fields — record syntax changes *how the fields are written and read*, not how many constructors or fields the type has.

## 1. Enumerations

The simplest form lists the values the type can have:

```haskell
data Result = Pass | Fail
data TLights = Red | Green | Yellow
```

Read `|` as **“or”**: a `Result` is either `Pass` or `Fail`.

`Pass`, `Fail`, `Red`, `Green`, and `Yellow` are **data constructors**. They are the values of the type, and like all constructors they begin with a capital letter.

```haskell
-- Convert a mark into a result.
classify :: Int -> Result
classify mark
  | mark >= 50 = Pass
  | otherwise  = Fail
```

Because these are ordinary constructors, they can be pattern matched exactly as `True` and `False` were in Chapter 4:

```haskell
-- Describe a result in words.
describe :: Result -> String
describe Pass = "Congratulations"
describe Fail = "Please resubmit"
```

Two patterns, and the set is exhaustive — a `Result` has no other possible value.

A second enumeration makes the same point with three constructors instead of two:

```haskell
data TLights = Red | Green | Yellow
  deriving (Show, Eq)

-- Cycle to the next light in sequence.
nextLight :: TLights -> TLights
nextLight Red    = Green
nextLight Green  = Yellow
nextLight Yellow = Red
```

```text
ghci> nextLight Red
Green
ghci> nextLight (nextLight Red)
Yellow
ghci> nextLight Yellow
Red
```

Three constructors, three equations, and the match is still exhaustive — every possible `TLights` value is covered, so there is no case left for GHC to warn about.

## 2. Deriving standard behaviour

Try to print a `Result` and it fails:

```text
ghci> classify 64
<interactive>: error:
    * No instance for (Show Result) arising from a use of 'print'
```

GHC does not know how to display a type you just invented. A `deriving` clause asks it to work out the obvious definitions:

```haskell
data Result = Pass | Fail
  deriving (Show, Eq, Ord)
```

```text
ghci> classify 64
Pass
ghci> Pass == Fail
False
ghci> Pass < Fail
True
```

| Derived class | What it provides |
|---|---|
| `Show` | Converting the value to a `String`, so it can be printed |
| `Eq` | `==` and `/=` |
| `Ord` | `<`, `<=`, `>`, `>=`, and `compare` |
| `Enum` | `succ`, `pred`, and ranges such as `[Red ..]` |

`Ord` orders the constructors by the sequence in which they are declared, which is why `Pass < Fail`. Chapter 9 explains what a type class actually is; for now, `deriving` is the tool.

<Callout type="info" title="Add deriving (Show, Eq) by habit">
Almost every custom type in this course benefits from both. Without `Show` you cannot inspect a value at the prompt, which makes testing painful.
</Callout>

`Enum` and `Bounded` follow the same declared order:

```haskell
data Result = Pass | Fail
  deriving (Show, Eq, Ord, Enum, Bounded)
```

```text
ghci> [Pass ..]
[Pass,Fail]
ghci> minBound :: Result
Pass
ghci> maxBound :: Result
Fail
ghci> succ Pass
Fail
```

`[Pass ..]` needs `Enum`; `minBound`/`maxBound` need `Bounded`. Both read the constructors in declaration order — the same order `Ord` uses — so `Pass`, being declared first, is the "smallest", "first", and lower-bound value all at once.

## 3. Constructors that carry values

A constructor may take arguments, which lets the type carry data:

```haskell
data Shape = Circle Float | Rectangle Float Float
  deriving (Show)
```

A `Shape` is either a `Circle` holding one `Float`, or a `Rectangle` holding two.

```text
ghci> :type Circle
Circle :: Float -> Shape
ghci> :type Rectangle
Rectangle :: Float -> Float -> Shape
```

Notice that a constructor with arguments **is a function** that builds a value of the type.

Pattern matching takes the values back out:

```haskell
-- Calculate the area of a shape.
area :: Shape -> Float
area (Circle r)      = pi * r * r
area (Rectangle w l) = w * l
```

```text
ghci> area (Circle 2.0)
12.566371
ghci> area (Rectangle 3.0 4.0)
12.0
```

The pattern `(Circle r)` matches any circle and binds `r` to the radius it carries. Constructor patterns need parentheses, for the same reason cons patterns did — application binds tighter than anything else.

<Callout type="warn" title="Constructors are capitalised; the type is too">
`data Shape = Circle Float` declares the *type* `Shape` and the *constructor* `Circle`. They live in separate namespaces, so it is legal — and common — for a single-constructor type to use the same name for both.
</Callout>

A second example makes the same shape with different data — a point carrying two coordinates instead of one shape carrying its own dimensions:

```haskell
data Point = Point Float Float
  deriving (Show)

-- Distance from the origin.
distanceFromOrigin :: Point -> Float
distanceFromOrigin (Point x y) = sqrt (x * x + y * y)
```

```text
ghci> :type Point
Point :: Float -> Float -> Point
ghci> distanceFromOrigin (Point 3.0 4.0)
5.0
```

`Point` takes two `Float`s, so its constructor has type `Float -> Float -> Point` — a curried function, exactly like any other two-argument function from Chapter 7. `Point 3.0 4.0` applies it fully; `Point 3.0` alone would be a partially applied function still waiting for the second coordinate.

<CommonMistake title="Forgetting that a constructor is a function">
`Circle` and `Point` are ordinary (curried) functions that happen to build values instead of computing them. `:type Circle` shows `Float -> Shape` for the same reason `:type (+)` shows `Num a => a -> a -> a` — apply either to too few arguments and you get back another function, not a finished value.
</CommonMistake>

## 4. This is where the type safety comes from

Compare the synonym problem from the previous lesson:

```haskell
type Metres = Double
type Feet   = Double
-- distance + height is accepted
```

With `data`, the two become genuinely distinct:

```haskell
data Metres = Metres Double deriving (Show)
data Feet   = Feet Double   deriving (Show)
```

```text
ghci> Metres 100 + Feet 30
<interactive>: error:
    * Couldn't match expected type 'Metres' with actual type 'Feet'
```

The compiler now enforces what the synonym could only suggest. That is the reason to prefer `data` whenever mixing two things would be a real bug.

## 4.1 `newtype`: safety without the overhead

`data Metres = Metres Double` solves the mixing problem, but it brings more machinery than a single field needs: a `data` type could grow extra constructors, carry several fields, or be recursive. None of that applies to `Metres` — it only ever wraps one `Double`.

`newtype` is Haskell's middle ground between `type` and `data`. Syntactically it looks like `data` restricted to **exactly one constructor with exactly one field**. Semantically, GHC treats the wrapper as existing only while it checks your program — at run time, a `newtype` value has the identical representation as the thing it wraps, so there is no boxing, no extra pointer, no cost. You get `data`'s type safety at `type`'s run-time price.

```haskell
newtype Metres = Metres Double deriving (Show, Eq, Ord)
newtype Feet   = Feet Double   deriving (Show, Eq, Ord)
```

```text
ghci> Metres 100 + Feet 30
<interactive>: error:
    * Couldn't match expected type 'Metres' with actual type 'Feet'
ghci> :type Metres
Metres :: Double -> Metres
ghci> Metres 100
Metres 100.0
ghci> Metres 100 == Metres 100
True
ghci> Metres 100 == Feet 100
<interactive>: error:
    * Couldn't match expected type 'Metres' with actual type 'Feet'
```

Exactly the rejection `type Metres = Double` could not produce back in the previous lesson — but now compare the shape of the declaration, not just its effect: `newtype` still writes `Metres Double` with a real constructor, still needs `deriving` for `Show`/`Eq`/`Ord` the way `data` does, and is used identically at every call site. The only difference from `data Metres = Metres Double` is the keyword itself and what GHC guarantees about run-time cost.

<CommonMistake title="newtype allows only one constructor, one field">
`newtype Shape = Circle Float | Rectangle Float Float` is rejected — a `newtype` cannot have alternatives, because GHC relies on there being exactly one way to build (and unwrap) the value to erase it safely. The moment a type needs more than one constructor, or a constructor needs more than one field, reach for `data` instead.
</CommonMistake>

The decision in practice is a short chain of questions:

## 5. Grouping related fields

A single constructor with several arguments groups values together:

```haskell
data StudentP = StudentP String Int Bool
  deriving (Show, Eq)

kagoP :: StudentP
kagoP = StudentP "Kago" 72 True

-- Extract the mark: position 2 of 3 — nothing in the code says so.
studentMarkP :: StudentP -> Int
studentMarkP (StudentP _ mark _) = mark
```

```text
ghci> studentMarkP kagoP
72
ghci> kagoP
StudentP "Kago" 72 True
```

This is already clearer than the `(String, Int, Bool)` tuple of Chapter 6, because the constructor name says what the group represents and the type cannot be confused with any other triple. But look at what `studentMarkP` had to do to read one field back out: pattern match all three positions and throw two away. Nothing about `StudentP _ mark _` documents that position 2 is the mark rather than, say, an ID — you would need to check the `data` declaration every time. This positional style is sometimes loosely *called* a "record", but it is not Haskell's record syntax. Real records name their fields.

<CommonMistake title="Positional fields are not a Haskell record">
`data Student = Student String Int Bool` groups values, but Haskell's actual *record syntax* — `data Student = Student { field :: Type, ... }` — is a distinct piece of syntax that also generates accessor functions for you automatically. If a `data` declaration has no curly braces `{ }`, it is not a record, whatever it is informally called.
</CommonMistake>

## 5.1 Record syntax

Braces after the constructor name turn each argument into a **named field**:

```haskell
data Student = Student
  { studentName :: String
  , studentMark :: Int
  , isActive    :: Bool
  } deriving (Show, Eq)

kago :: Student
kago = Student { studentName = "Kago", studentMark = 72, isActive = True }
```

Two things happen that the positional version never gave you.

**First, GHC generates one accessor function per field, for free:**

```text
ghci> :type studentName
studentName :: Student -> String
ghci> :type studentMark
studentMark :: Student -> Int
ghci> studentName kago
"Kago"
ghci> studentMark kago
72
ghci> isActive kago
True
```

No pattern match was written for any of these. `studentName`, `studentMark`, and `isActive` are ordinary functions that GHC derived directly from the field names in the declaration.

**Second, values print with their field names attached**, which documents itself:

```text
ghci> kago
Student {studentName = "Kago", studentMark = 72, isActive = True}
```

Compare that to `StudentP "Kago" 72 True` above — the record's `Show` output states what each value means without anyone consulting the declaration.

## 5.2 Record update syntax

A record value can still be built positionally — `Student "Kago" 72 True` works exactly as before, the field names do not remove that option — but a record's distinctive feature is **update syntax**: producing a modified copy by naming only the fields that change.

```haskell
-- Kago's mark is corrected after a remark.
remarked :: Student
remarked = kago { studentMark = 75 }
```

```text
ghci> remarked
Student {studentName = "Kago", studentMark = 75, isActive = True}
ghci> kago
Student {studentName = "Kago", studentMark = 72, isActive = True}
```

`kago` is completely unchanged — Haskell values are immutable, so `kago { studentMark = 75 }` builds a **new** `Student` that copies every field from `kago` except the one named, and `remarked` is bound to that new value. Several fields may be updated in the same expression:

```text
ghci> naledi = Student { studentName = "Naledi", studentMark = 68, isActive = False }
ghci> naledi { isActive = True, studentMark = 70 }
Student {studentName = "Naledi", studentMark = 70, isActive = True}
```

<RecognitionStrategy title="Positional constructor vs record syntax, at a glance">
Look for curly braces immediately after the constructor name in the `data` declaration. `Student String Int Bool` is positional. `Student { studentName :: String, ... }` is a record — and only the second form gives you generated accessor functions and `{ field = value }` update syntax.
</RecognitionStrategy>

## 6. Recursive types

Unlike a type synonym, a **type declaration may be recursive**, because the constructors stop the expansion:

```haskell
data Tree a = Leaf a | Branch (Tree a) (Tree a)
  deriving (Show)
```

A `Tree a` is either a `Leaf` holding one value, or a `Branch` holding two subtrees. The `a` makes it work for any element type.

```haskell
exampleTree :: Tree Int
exampleTree = Branch (Leaf 1) (Branch (Leaf 2) (Leaf 3))
```

Functions over a recursive type follow the structure exactly, with one equation per constructor — the same discipline as `[]` and `(x:xs)`:

```haskell
-- Count the leaves in a tree.
countLeaves :: Tree a -> Int
countLeaves (Leaf _)     = 1
countLeaves (Branch l r) = countLeaves l + countLeaves r

-- Add up the values in a tree of numbers.
sumTree :: Tree Int -> Int
sumTree (Leaf n)     = n
sumTree (Branch l r) = sumTree l + sumTree r
```

```text
ghci> countLeaves exampleTree
3
ghci> sumTree exampleTree
6
```

The `Leaf` case is the base case and the `Branch` case is the recursive step. Every recursion technique from Chapter 5 transfers directly.

A second recursive type makes the same shape with a structure closer to the built-in list — worth building once so the parallel to `[]` and `(:)` is completely explicit:

```haskell
data IntList = Empty | Cons Int IntList
  deriving (Show)

-- The built-in [1,2,3] written with IntList instead.
exampleList :: IntList
exampleList = Cons 1 (Cons 2 (Cons 3 Empty))

sumIntList :: IntList -> Int
sumIntList Empty       = 0
sumIntList (Cons x xs) = x + sumIntList xs
```

```text
ghci> exampleList
Cons 1 (Cons 2 (Cons 3 Empty))
ghci> sumIntList exampleList
6
```

Line up the two equations against the built-in list functions from Chapter 5: `Empty` plays the role of `[]`, and `Cons x xs` plays the role of `(x:xs)`. `IntList` **is**, structurally, what `[Int]` already was — Haskell's list type is not special magic, just a recursive `data` declaration with friendlier syntax (`[]` and `:` instead of `Empty` and `Cons`) and built-in support for `[1,2,3]` notation.

## 8. Common errors

| Attempt | Problem | Repair |
|---|---|---|
| `data result = Pass \| Fail` | Type names must be capitalised | `data Result = ...` |
| `data Result = pass \| fail` | Constructors must be capitalised | `Pass`, `Fail` |
| `print (classify 64)` fails | No `Show` instance | Add `deriving (Show)` |
| `area Circle r = ...` | Constructor patterns need parentheses | `area (Circle r) = ...` |
| `Circle 2 == Circle 2` fails | No `Eq` instance | Add `Eq` to the deriving clause |
| Missing a constructor in a function | Non-exhaustive patterns at run time | One equation per constructor |
| `type Tree = Branch Tree Tree` | Synonyms cannot be recursive or carry constructors | Use `data` |
| `kago.studentMark` | Haskell records have no dot-access syntax | `studentMark kago` |
| `kago { mark = 75 }` | `mark` is not a field declared on `Student` | Use the exact field name: `kago { studentMark = 75 }` |
| `newtype Shape = Circle Float \| Rectangle Float Float` | `newtype` allows exactly one constructor with exactly one field | Use `data`, or split into separate `newtype`s |
