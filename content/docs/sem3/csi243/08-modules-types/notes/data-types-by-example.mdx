For a declaration, first list the alternatives; then list the information each alternative needs. For a function, copy that list into patterns and give every constructor an equation. An underscore discards a field, whereas a lowercase name binds it for use on the right.

**How to use the deliberately broken definitions.** They appear in plain fences, never in a runnable editor. Compile such a definition with `-Wincomplete-patterns`: the key warning is `Pattern match(es) are non-exhaustive`. If a missing case is demanded at run time, the key exception text is `Non-exhaustive patterns in function`. File locations and function names surround these phrases and are omitted here. Warnings do not make the function safe. The complete functions in the runnable examples are the repairs. For a single-constructor type there is no alternative constructor to forget; the corresponding failure must omit a field pattern or a guard case instead. The sections state that distinction explicitly.

## 1. Enumerations: finite choices in declaration order

An enumeration stores only which choice was made. Its constructors have no fields. Declaration order supplies the standard order and numbering, which need not match alphabetical order or a business rule.

**Template** (replace `Choice`, `First`, `Second` and `Last` with names):

```haskell
data Choice = First | Second | Last
  deriving (Show, Eq, Ord, Enum, Bounded)
code :: Choice -> Int
code First = 10
code Second = 20
code Last = 30
```

`Show` supplies text for `show` and `print`; `Eq` supplies equality and inequality; `Ord` supplies comparison, including `compare`, with earlier constructors smaller. `Enum` supplies numbering from zero, `succ`, `pred` and ranges. `Bounded` supplies the first and last values as `minBound` and `maxBound`. The annotation in `[minBound .. maxBound] :: [Choice]` tells Haskell which type's bounds to use. Neither bound is a wrap-around rule: `succ maxBound` is not a cycle.

### Worked variation: game phases

Three choices carry no data, but a score function gives each its own meaning.

<HaskellTryIt>

```haskell
-- Question: list all phases and score the final phase.
data Phase = Lobby | Playing | Finished
  deriving (Show, Eq, Ord, Enum, Bounded)
score :: Phase -> Int
score Lobby = 0
score Playing = 1
score Finished = 2
main :: IO ()
main = do
  print ([minBound .. maxBound] :: [Phase])
  print (succ Lobby, fromEnum Finished)
  print (Lobby < Finished, Playing == Playing, score Finished)
```

```text
[Lobby,Playing,Finished]
(Playing,2)
(True,True,2)
```

</HaskellTryIt>

The range starts at `Lobby` and ends at `Finished`. `succ` moves one place, `fromEnum Finished` counts two places from zero, and the last equation supplies score `2`.

### Worked variation: bank review stages

Same shape, but numbering and the function's result now deliberately differ.

<HaskellTryIt>

```haskell
-- Question: enumerate review stages and find their waiting allowance.
data Review = Submitted | Checked | Approved
  deriving (Show, Eq, Ord, Enum, Bounded)
allowance :: Review -> Int
allowance Submitted = 5
allowance Checked = 2
allowance Approved = 0

  print ([minBound .. maxBound] :: [Review])
  print (succ Checked, fromEnum Approved)
  print (Submitted < Approved, allowance Submitted)
```

```text
[Submitted,Checked,Approved]
(Approved,2)
(True,5)
```

</HaskellTryIt>

`Submitted` is smaller because it is written first, although its allowance is larger. Derived ordering does not inspect `allowance`.

### Worked variation: calendar slots

Same finite-choice template, with a boundary value and a duration rather than a score.

<HaskellTryIt>

```haskell
-- Question: list slots, advance one slot and total its minutes.
data Slot = Dawn | Noon | Dusk
  deriving (Show, Eq, Ord, Enum, Bounded)
minutes :: Slot -> Int
minutes Dawn = 30
minutes Noon = 60
minutes Dusk = 45
main :: IO ()
main = do
  print ([minBound .. maxBound] :: [Slot])
  print (succ Dawn, fromEnum Dusk)
  print (maxBound :: Slot)
  print (minutes Noon)
```

```text
[Dawn,Noon,Dusk]
(Noon,2)
Dusk
60
```

</HaskellTryIt>

`maxBound` is the last constructor, `Dusk`. The `Noon` equation returns `60`; enumeration numbering would instead return `1`.

### Missing case and common errors

```haskell
-- Wrong: Dusk has no equation; incomplete-pattern warning.
data Slot = Dawn | Noon | Dusk
onlyMorning :: Slot -> Int
onlyMorning Dawn = 30
onlyMorning Noon = 60
-- Demanding onlyMorning Dusk fails.
```

Add `onlyMorning Dusk = 45`. `succ (maxBound :: Slot)` exceeds the enumeration; repair it by writing an explicit cycle with one equation per constructor. Writing `Dawn == Noon` without deriving `Eq` leads to the key diagnostic `No instance for (Eq Slot)`; add `Eq`. Without `Show`, `print Dawn` similarly needs `Show Slot`.

**Practice with answer.** What is `fromEnum Noon`? `1`: count constructors from zero, independently of the duration.

## 2. One constructor carrying fields

A product groups fields that must all be present together. The constructor's type is a curried function: one arrow per field followed by the result type. Field order matters even when two fields share a type.

**Template:**

```haskell
data Item = Item String Int deriving (Show, Eq)
quantity :: Item -> Int
quantity (Item _ n) = n
```

`String` and `Int` stand for the required field types. `Item :: String -> Int -> Item`; a partially applied constructor is still a function. A one-constructor type needs just one constructor equation, but that equation must accept every valid field value.

### Worked variation: a game move

Two integer fields store changes in different directions.

<HaskellTryIt>

```haskell
-- Question: compute a move's Manhattan distance.
data Move = Move Int Int deriving (Show, Eq)
distance :: Move -> Int
distance (Move dx dy) = abs dx + abs dy
main :: IO ()
main = do
  print (Move (-2) 3)
  print (distance (Move (-2) 3))
  print (distance (Move 0 0))
```

```text
Move (-2) 3
5
0
```

</HaskellTryIt>

The pattern binds `dx = -2`, `dy = 3`; absolute values give `2 + 3`. Derived `Show` puts parentheses around a negative constructor argument.

### Worked variation: a library loan

Same product shape, but the first field is text and the second is a day count.

<HaskellTryIt>

```haskell
-- Question: extend a loan by seven days.
data Loan = Loan String Int deriving (Show, Eq)
extend :: Loan -> Loan
extend (Loan title days) = Loan title (days + 7)
main :: IO ()
main = do
  print (extend (Loan "Atlas" 0))
  print (extend (Loan "Poems" 3))
```

```text
Loan "Atlas" 7
Loan "Poems" 10
```

</HaskellTryIt>

The constructor is taken apart and rebuilt. The title is copied and only the day count changes: zero becomes seven, three becomes ten.

### Worked variation: a bank entry

Same grouping, now a signed amount is combined with its reference.

<HaskellTryIt>

```haskell
-- Question: turn an entry into a readable line.
data Entry = Entry String Int deriving (Show, Eq)
entryLine :: Entry -> String
entryLine (Entry ref amount) = ref ++ ": " ++ show amount
main :: IO ()
```


</HaskellTryIt>

### Restricted fields and common errors

```haskell
-- Wrong: there is only one constructor, but not every Move is covered.
data Move = Move Int Int
onAxis :: Move -> Int
onAxis (Move 0 y) = abs y
-- onAxis (Move 1 2) fails; -Wincomplete-patterns warns.
```

Repair with `onAxis (Move x y) = abs x + abs y` if distance was intended. This is missing a field case, not a constructor. `Move "left" 3` has the wrong field type (key diagnostic `Couldn't match`); supply an `Int`. `distance Move 2 3` fails because `Move` alone is a function; write `distance (Move 2 3)`. To display a partly applied constructor, first supply its remaining argument.

**Practice with answer.** What is the type of `Loan "Atlas"`? `Int -> Loan`: it still needs the days.

## 3. Several constructors with different fields

A sum offers alternatives. Each alternative can require different information; a value contains exactly one alternative, not all of them at once. Functions choose an equation using the outer constructor.

**Template:**

```haskell
data Request = Cancelled | Named String | Counted Int Bool
  deriving (Show, Eq)
weight :: Request -> Int
weight Cancelled = 0
weight (Named _) = 1
weight (Counted n _) = n
```

The pipe means an alternative. Parentheses gather each constructor pattern and its fields into one function argument.

### Worked variation: game rewards

A reward is absent, numerical, or named.

<HaskellTryIt>

```haskell
-- Question: score every kind of reward.
data Reward = NoReward | Coins Int | Badge String deriving (Show, Eq)
points :: Reward -> Int
points NoReward = 0
points (Coins n) = n
points (Badge _) = 10
main :: IO ()
main = print (map points [NoReward, Coins 4, Badge "Scout"])
```

```text
[0,4,10]
```

</HaskellTryIt>

The outer names select three different equations. The badge's string is irrelevant to scoring, so its pattern uses an underscore.

### Worked variation: bank instructions

Same alternatives idea, but a transfer has two fields and a freeze has none.

<HaskellTryIt>

```haskell
-- Question: compute the balance effect of each instruction.
data Instruction = Freeze | Deposit Int | Transfer String Int
  deriving (Show, Eq)
effect :: Instruction -> Int
effect Freeze = 0
effect (Deposit n) = n
effect (Transfer _ n) = negate n
main :: IO ()
main = print (map effect [Freeze, Deposit 8, Transfer "B" 3])
```

```text
[0,8,-3]
```

</HaskellTryIt>

A transfer removes its amount. Negative numbers inside a list print directly; the parentheses required for a constructor argument are unnecessary here.

### Worked variation: calendar appointments

Same sum, but one alternative requires both a day and a duration.

<HaskellTryIt>

```haskell
-- Question: count occupied minutes for each appointment kind.
data Appointment = Holiday String | Meeting Int Int | Free
  deriving (Show, Eq)
occupied :: Appointment -> Int
occupied (Holiday _) = 0
occupied (Meeting _ duration) = duration
occupied Free = 0
main :: IO ()
main = print (map occupied [Holiday "Founders", Meeting 12 40, Free])
```

```text
[0,40,0]
```

</HaskellTryIt>

Only `Meeting` stores minutes. Its first `Int` is the day, which the function discards; confusing field positions would give `12`, not `40`.

### Missing case and common errors

```haskell
-- Wrong: Badge is missing.
data Reward = NoReward | Coins Int | Badge String
cash :: Reward -> Int
cash NoReward = 0
cash (Coins n) = n
-- cash (Badge "Scout") fails; -Wincomplete-patterns warns.
```

Add `cash (Badge _) = 0` if badges have no cash value. `Coins 1 "bonus"` gives a constructor too many arguments; GHC's key phrase is `applied to too many arguments`. `Coins n` and `Badge s` must both return the function's declared result type: returning `s` from an `Int` function leads to `Couldn't match`.

## 4. Records: named fields, accessors and updates

A record names each field so callers can read and update it without remembering a position. The accessor is a function. An update returns a new value; the original remains available.

**Template:**

```haskell
data Stock = Stock { stockName :: String, stockCount :: Int }
  deriving (Show, Eq)
restock :: Stock -> Stock
restock (Stock name n) = Stock name (n + 1)
-- Equivalent update expression: s { stockCount = stockCount s + 1 }
```

`stockName :: Stock -> String` and `stockCount :: Stock -> Int` are generated. Construction can use field labels or positional arguments. Derived `Show` always uses the record labels, even if construction was positional.

### Worked variation: a game player

Names make a score update explicit, and the original is printed afterwards.

<HaskellTryIt>

```haskell
-- Question: award two points without changing the original player.
data Player = Player { playerName :: String, playerScore :: Int }
  deriving (Show, Eq)
award :: Player -> Player
award p = p { playerScore = playerScore p + 2 }
label :: Player -> String
label (Player name _) = name
main :: IO ()
main = do
  let p = Player "Ivy" 4
  print (award p)
  print p
  putStrLn (label p)
```

```text
Player {playerName = "Ivy", playerScore = 6}
Player {playerName = "Ivy", playerScore = 4}
Ivy
```

</HaskellTryIt>

`award` reads `4`, adds `2`, and returns a copy with `6`. The second print confirms the original's score is still `4`. `label` shows the single positional constructor equation.

### Worked variation: bank account

Same record mechanics, but a withdrawal can produce a negative field.

<HaskellTryIt>

```haskell
-- Question: withdraw five units and read the account owner.
data Account = Account { owner :: String, balance :: Int }
  deriving (Show, Eq)
withdraw :: Account -> Account
withdraw a = a { balance = balance a - 5 }
accountLabel :: Account -> String
accountLabel (Account name _) = name
main :: IO ()
main = do
  print (withdraw (Account "Ann" 2))
  putStrLn (owner (Account "Ann" 2))
```

```text
Account {owner = "Ann", balance = -3}
Ann
```

</HaskellTryIt>

The new balance is `2 - 5`. Record syntax prints the negative value after `=`, without argument parentheses. `owner` is the generated accessor; `accountLabel` is an explicit equivalent.

### Worked variation: library catalogue

Same update syntax, now the changed field is a Boolean rather than a number.

<HaskellTryIt>

```haskell
-- Question: mark a book unavailable and read its title.
data Book = Book { bookTitle :: String, available :: Bool }
  deriving (Show, Eq)
borrow :: Book -> Book
borrow b = b { available = False }
isAvailable :: Book -> Bool
isAvailable (Book _ flag) = flag
main :: IO ()
main = do
  let b = Book { bookTitle = "Maps", available = True }
  print (borrow b)
  print (isAvailable b)
  putStrLn (bookTitle b)
```

```text
Book {bookTitle = "Maps", available = False}
True
Maps
```

</HaskellTryIt>

The update copies the title and replaces the availability. Reading the original still gives `True`; accessor order is ordinary function application.

### Partial selectors and common errors

Records with several constructors can have partial accessors. Here `balance` exists only on `Open`:

```haskell
-- Wrong: Closed is missing from manualBalance.
data Bank = Closed | Open { bankBalance :: Int }
manualBalance :: Bank -> Int
manualBalance (Open n) = n
-- manualBalance Closed fails; -Wincomplete-patterns warns.
-- bankBalance Closed is also unsafe: Closed has no bankBalance field.
```

Repair with `manualBalance Closed = 0`, or return `Maybe Int` if closed and zero-balance are different meanings. Generated partial selectors have their own diagnostics; `-Wincomplete-patterns` here refers to the manual function. An update on an alternative lacking the named field is also unsafe. `p { score = 6 }` when the field is `playerScore` gives the key diagnostic `Not in scope`; use the exact declared field name. Expecting an update to mutate `p` is a reasoning error and produces no compiler warning.

**Practice with answer.** What is the positional form of `Book { available = False, bookTitle = "Maps" }`? `Book "Maps" False`: positional order comes from the declaration, not the labelled construction.

## 5. newtype: one distinct wrapper

Use `newtype` when exactly one stored value needs its own type. Construction and unwrapping remain explicit. Deriving `Show`, `Eq` or `Ord` does not automatically derive arithmetic. Unlike a synonym, the wrapper cannot be passed directly where its field type is expected.

**Template:**

```haskell
newtype Identifier = Identifier Int deriving (Show, Eq, Ord)
unIdentifier :: Identifier -> Int
unIdentifier (Identifier n) = n
```

Replace the type name, constructor and field type. There must be exactly one constructor and exactly one field. A tuple can itself be that single field. Recursive newtypes are legal in Haskell; the single-field rule does not prohibit recursion. They are unnecessary for these examples.

### Worked variation: game lives

Wrap a number, unwrap it to calculate, then rebuild the same wrapper.

<HaskellTryIt>

```haskell
-- Question: lose one life, stopping at zero.
newtype Lives = Lives Int deriving (Show, Eq, Ord)
lose :: Lives -> Lives
lose (Lives n) = Lives (max 0 (n - 1))
main :: IO ()
main = do
  print (lose (Lives 3))
  print (lose (Lives 0))
```

```text
Lives 2
Lives 0
```

</HaskellTryIt>

`3 - 1` gives `2`. For zero, `max 0 (-1)` gives `0`; the wrapper does not itself enforce non-negativity, so the function supplies that policy.

### Worked variation: banking cents

Same single-field wrapper, now an arithmetic operation must be defined explicitly.

<HaskellTryIt>

```haskell
-- Question: add two amounts of cents.
newtype Cents = Cents Int deriving (Show, Eq, Ord)
addCents :: Cents -> Cents -> Cents
addCents (Cents x) (Cents y) = Cents (x + y)
main :: IO ()
main = do
  print (addCents (Cents 12) (Cents 8))
  print (Cents 2 < Cents 5)
```

```text
Cents 20
True
```

</HaskellTryIt>

The equation unwraps both inputs and adds their `Int` fields. Derived ordering compares those fields, so `2` is smaller than `5`.

### Worked variation: a library identifier

Same wrapper, but its field is text and must not be mistaken for an arbitrary title.

<HaskellTryIt>

```haskell
-- Question: make a shelf label from a catalogue identifier.
newtype CatalogueId = CatalogueId String deriving (Show, Eq, Ord)
shelfLabel :: CatalogueId -> String
shelfLabel (CatalogueId s) = "ID:" ++ s
main :: IO ()
```


</HaskellTryIt>

The string is unwrapped, prefixed and returned as ordinary text. Equality compares wrapped identifiers using their string fields.

### Restricted fields and common errors

```haskell
-- Wrong: there is no missing constructor, but this guard misses zero.
newtype Lives = Lives Int
unsafeLose :: Lives -> Lives
unsafeLose (Lives n)
  | n > 0 = Lives (n - 1)
-- unsafeLose (Lives 0) fails; -Wincomplete-patterns warns.
```

Use the total `lose` above. Omitting the only constructor equation altogether is not a partial definition: it is a missing definition. `newtype Bad = Bad Int Int` violates the field rule; the key GHC phrase is `must have exactly one field`. Use `data`, or a single tuple field. `Cents 2 + Cents 3` without a `Num Cents` instance produces `No instance for (Num Cents)`; use `addCents`.

## 6. Parameterised types: Pair, optional values and alternatives

A lowercase parameter names a type to be supplied later. `Pair String Int` and `Pair Bool String` use the same declaration with different choices for its two parameters. A repeated parameter, as in `Pair a a`, requires matching types; different letters allow different types but do not require them to differ.

### Pair template: keep both values

```haskell
data Pair a b = Pair a b deriving (Show, Eq)
swapPair :: Pair a b -> Pair b a
swapPair (Pair x y) = Pair y x
```

The first `a` and `b` are parameters; the ones on the right are field types. There is one constructor equation and no constraint: swapping never compares or displays a field.

### Worked variation: pairing a player and a score

Start with text paired with an integer.

<HaskellTryIt>

```haskell
-- Question: swap this domain-specific pair.
data Pair a b = Pair a b deriving (Show, Eq)
swapPair :: Pair a b -> Pair b a
swapPair (Pair x y) = Pair y x
main :: IO ()
main = print (swapPair (Pair "Ayo" (9 :: Int)))
```

```text
Pair 9 "Ayo"
```

</HaskellTryIt>

The pattern binds the name to `x` and score to `y`, then constructs `Pair y x`. The result has type `Pair Int String`.

### Worked variation: pairing an account flag and reference

Same template, but neither field is numerical.

```haskell
-- Question: swap this domain-specific pair.
```

### Maybe template: a value may be absent

`Maybe'` is a fresh type name, with an apostrophe to distinguish it from Prelude `Maybe`. A `Maybe' a` stores no value or one value of type `a`. This makes failure visible in the result type.

```haskell
data Maybe' a = Nothing' | Just' a deriving (Show, Eq)
withDefault :: a -> Maybe' a -> a
withDefault fallback Nothing' = fallback
withDefault _ (Just' x) = x
```

The two equations cover both alternatives. The fallback must have the same type as the stored value.

### Worked variation: an optional game score

Use an integer when the score exists, zero otherwise.

<HaskellTryIt>

### Either-like template: retain the reason for failure

An optional value records absence; an either-like value can retain an explanation instead. `Outcome e a` supplies a failure field of type `e` or a success field of type `a`.

```haskell

resolve _ good (Accepted x) = good x
```

Both handlers return the same type `b`, even though their inputs can differ. `Rejected` and `Accepted` are alternatives, not two fields stored together.

## 10. Expression trees: evaluation and readable printing

An expression tree represents syntax as data. A number stops the recursion; arithmetic constructors hold subexpressions. Evaluation computes an integer, whereas pretty printing describes the syntax as text. These functions have different result types and meanings.

**Template:**

```haskell
data Expr = Num Int | Add Expr Expr | Mul Expr Expr deriving (Show, Eq)
eval :: Expr -> Int
eval (Num n) = n
eval (Add l r) = eval l + eval r
eval (Mul l r) = eval l * eval r
pretty :: Expr -> String
pretty (Num n) = show n
pretty (Add l r) = "(" ++ pretty l ++ "+" ++ pretty r ++ ")"
pretty (Mul l r) = "(" ++ pretty l ++ "*" ++ pretty r ++ ")"
```

`Num` here is a value constructor; Prelude `Num` is a type class in a separate namespace. Both functions need all three constructor equations. Parentheses in `pretty` deliberately preserve grouping; `show` derived for `Expr` instead exposes the constructors.

Replace the type and constructor names for your domain. `Outer` has two alternatives, `Inner` one; there are three equations across the two functions. In a finite `Wrap (Back Stop)`, the call path is `countOuter` to `countInner` to `countOuter Stop`.

## 12. Handwritten Show, Eq and Ord instances

A class describes operations; an instance defines those operations for one type. Write `show` to return `String`, `(==)` to return `Bool`, and `compare` to return `LT`, `EQ` or `GT`. The implementation can choose a domain meaning, but equality and ordering must agree: `compare x y == EQ` exactly when `x == y`. A lawful order is transitive, and equality is reflexive, symmetric and transitive for these finite defined examples.

**Template:**

```haskell
data Rank = Low | High
instance Show Rank where
  show Low = "low"
  show High = "high"
instance Eq Rank where
  Low == Low = True
  Low == High = False
  High == Low = False
  High == High = True
instance Ord Rank where
  compare Low Low = EQ
  compare Low High = LT
  compare High Low = GT
  compare High High = EQ
```

Every constructor is covered. For two-argument methods, every combination must be covered; a wildcard equation can cover several combinations when justified. Defining `(==)` is sufficient for `Eq` because its default `(/=)` negates equality. Defining `compare` is sufficient for `Ord`; its defaults supply the relational operators. `Ord` also requires an `Eq` instance. Define an instance once: do not both derive and handwrite the same one.

For a parameterised wrapper the template adds a constraint, for example `instance Eq a => Eq (Box a) where ...`. This says that comparing boxes needs equality for their fields. An instance head uses the complete applied type `Box a`, not the constructor `Box` by itself.

### How derived Ord treats constructors and fields

Derived ordering first compares constructor positions in the declaration. Only if the constructors match does it compare their fields, from left to right, stopping at the first unequal pair. Record labels do not change this rule; declaration order of the fields matters.

<HaskellTryIt>

```haskell
-- Question: distinguish constructor priority from field priority.
data Ticket = Standard Int Int | Premium Int deriving (Show, Eq, Ord)
main :: IO ()
main = do
  print (Standard 999 999 < Premium 0)
  print (Standard 2 100 < Standard 3 0)
  print (Standard 2 100 < Standard 2 101)
  print (Premium 9 < Premium 2)
```

```text
True
True
True
False
```

</HaskellTryIt>

The first test uses constructor order alone. The second stops at field one. The third reaches field two. The last compares two `Premium` amounts, and nine is not smaller than two. No function such as ticket price is consulted.

### Partial methods and common errors

```haskell
-- Wrong: show is missing High.
data Rank = Low | High
instance Show Rank where
  show Low = "low"
-- print High fails when show is demanded; incomplete-pattern warning.

-- Wrong: equality and comparison omit mixed-constructor pairs.
instance Eq Rank where
  Low == Low = True
  High == High = True
instance Ord Rank where
  compare Low Low = EQ
  compare High High = EQ
-- Low == High and compare Low High fail; incomplete-pattern warnings.
```

Repair using all four pairs from the template. `show Low = 1` has the wrong result type and leads to `No instance for (Num String)`; return `"low"`. Writing `compare Low High = True` leads to `Couldn't match` because the result must be `Ordering`, not `Bool`. Two `Show Rank` instances produce `Duplicate instance declarations`. An `Ord` instance without the required `Eq` instance produces `No instance for (Eq Rank)`. A custom equality that ignores comments and an order that compares them would compile but violate agreement: use the same key for both.

**Practice with answers.** If `data Tag = B Int | A Int deriving (Eq, Ord)`, is `B 900 < A 0` true? Yes: declaration order comes before the names and numbers. If custom `show Low = "low"`, `print Low` prints `low`, while `print (show Low)` prints `"low"` because its argument is a string.

## Summary

<Callout type="key" title="Remember">

List alternatives before fields. Use one equation per constructor and recurse once on each recursive piece that matters. Pair keeps both values; an optional type represents absence; an either-like type retains a reason. Empty-leaf and leaf-labelled trees have different base cases. Record updates return copies. A newtype has one constructor with one field. Derived ordering uses constructor order, then fields from left to right. Handwritten equality and ordering must agree. Enable `-Wincomplete-patterns` to find omitted cases, including restricted field patterns.

</Callout>
