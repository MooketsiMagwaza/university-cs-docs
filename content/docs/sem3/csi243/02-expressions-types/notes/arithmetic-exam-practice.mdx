## 1. A mixed arithmetic trace

An evaluate question needs a grouped expression and a reduction, not a guess from reading left to right. Keep the declared Integer type throughout.

**Template.**

```text
group by fixity -> reduce powers -> multiply/divide -> add/subtract
```

The trace must preserve operands at every step. Use a second parenthesisation only to explain an alternative question.

### Worked variation: power then multiplication

<HaskellTryIt>

```haskell
main :: IO ()
main = print (50 - 2 ^ (3 :: Int) * 4 :: Integer)
```



```text
18
```

</HaskellTryIt>

`50 - (8*4) = 50 - 32 = 18`.

### Worked variation: parentheses change the base

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((50 - 2) ^ (2 :: Int) :: Integer)
```



```text
2304
```

</HaskellTryIt>

First `50-2 = 48`, then `48*48 = 2304`.

### Worked variation: negative base

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-2) ^ (3 :: Int) * 4 + 5 :: Integer)
```



```text
-27
```

</HaskellTryIt>

`(-8)*4 + 5 = -32 + 5 = -27`.

### Exam question: A mixed arithmetic trace (4 marks)

Evaluate `50 - 2 ^ 3 * 4 :: Integer` with a fully parenthesised trace.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Evaluate `50 - 2 ^ 3 * 4 :: Integer` with a fully parenthesised trace. The command asks for a value, so give a reduction with the stated grouping and numeric type.

</Step>

<Step title="2. Plan">

Starting with 50-2 compiles as a different expression when parenthesised. There is no GHC diagnostic for answering the wrong grouping.

</details>

## 2. A numeric condition

A condition question has two levels: arithmetic values and Boolean combinations. A boundary comparison can change the result even when the arithmetic is correct.

**Template.**

```text
value -> comparisons -> not -> && -> ||
```

Use parentheses to indicate the argument of not; as a function, it binds to its immediate argument.

### Worked variation: inclusive threshold

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-8 :: Integer) `mod` 3 == 1 && 2^3 >= 8)
```



```text
True
```

</HaskellTryIt>

`-8 mod 3 = 1`; `2^3 = 8`; both comparisons are True.

### Worked variation: strict threshold

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-8 :: Integer) `mod` 3 == 1 && 2^3 > 8)
```



```text
False
```

</HaskellTryIt>

The first test is True, but `8>8` is False.

### Worked variation: alternative branch

<HaskellTryIt>

```haskell
main :: IO ()
main = print (not ((-8 :: Integer) `mod` 3 == 1) || 2^3 == 8)
```



```text
True
```

</HaskellTryIt>

The left becomes not True, hence False; the right is True, so the disjunction is True.

### Exam question: A numeric condition (4 marks)

Evaluate `(-8 mod 3 == 1) && (2^3 > 8) || True` with backticks around mod in source.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Evaluate `(-8 mod 3 == 1) && (2^3 > 8) || True` with backticks around mod in source. The command asks for a value, so give a reduction with the stated grouping and numeric type.

</Step>

<Step title="2. Plan">

Compute the signed remainder and power first. Then group && above ||.

</Step>

<Step title="3. Solution">

`(True && False) || True = False || True = True`.

</Step>

<Step title="4. Check">

Remove the final or True and the result becomes False; this checks that the grouping matters.

</Step>

</Steps>

</details>

### Common errors

Changing > to >= changes a strict boundary; the program compiles either way. A Bool cannot be added as a number: `True + 1` is rejected with `No instance for (Num Bool)`.

### Practice with answers

What if the final True is changed to False`

<details>
<summary>Answer</summary>

False, since `(True && False) || False = False`.

</details>

## 3. Design a measurement formula

A write question asks for a definition with units and a type. An arithmetic formula and its input-validation policy are separate parts of a specification.

**Template.**

```text
result :: Double -> Double -> Double
result x y = expression built from x and y
```

Keep fractional arithmetic when lengths are measured with fractional values.

### Worked variation: rectangle with decimal side

<HaskellTryIt>

```haskell
area :: Double -> Double -> Double
area width height = width * height

main :: IO ()
main = print (area 1.5 8)
```



```text
12.0
```

</HaskellTryIt>

`1.5*8 = 12`; the Double result prints a decimal point.

### Worked variation: zero-width boundary

<HaskellTryIt>

```haskell
area :: Double -> Double -> Double
area width height = width * height

main :: IO ()
main = print (area 0 8)
```



```text
0.0
```

</HaskellTryIt>

Zero width gives zero area and satisfies a non-negative-size policy.

### Worked variation: temperature slope and offset

<HaskellTryIt>

```haskell
fahrenheit :: Double -> Double
fahrenheit c = c*9/5+32

main :: IO ()
main = print (fahrenheit 100)
```



```text
212.0
```

</HaskellTryIt>

`100*9/5 + 32 = 180+32 = 212`.

## 4. Choose a signed quotient policy

When the question says `towards zero`, it selects quot/rem. When it says `floor quotient`, it selects div/mod. Write the policy before calculating.

**Template.**

```text
a = b*q+r
q floors: div/mod
q truncates: quot/rem
```

A remainder`s sign follows the chosen convention, not a universal positive-remainder rule.

### Worked variation: floor with negative dividend

<HaskellTryIt>

```haskell
main :: IO ()
main = print (divMod (-14 :: Integer) 5)
```



```text
(-3,1)
```

</HaskellTryIt>

`-14 = 5*(-3)+1`; floor -2.8 to -3.

### Worked variation: truncate with negative dividend

<HaskellTryIt>

```haskell
main :: IO ()
main = print (quotRem (-14 :: Integer) 5)
```



```text
(-2,-4)
```

</HaskellTryIt>

`-14 = 5*(-2)-4`; truncate -2.8 to -2.

### Worked variation: negative divisor

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((divMod (14 :: Integer) (-5), quotRem (14 :: Integer) (-5)))
```



```text
((-3,-1),(-2,4))
```

</HaskellTryIt>

Floor gives -3, remainder -1; truncation gives -2, remainder 4.

### Exam question: Choose a signed quotient policy (4 marks)

Calculate both quotient/remainder pairs for -14 and 5, showing the identities.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Calculate both quotient/remainder pairs for -14 and 5, showing the identities. The command asks for a value, so give a reduction with the stated grouping and numeric type.

</Step>

<Step title="2. Plan">

Use floor for div and truncation for quot; obtain remainders by subtraction.

</Step>

<Step title="3. Solution">

divMod gives `(-3,1)` and quotRem gives `(-2,-4)`. `5*(-3)+1 = -14`; `5*(-2)-4 = -14`.

</Step>

<Step title="4. Check">

Both remainder magnitudes are below 5; mod shares divisor sign and rem shares dividend sign.

</Step>

</Steps>

</details>

### Common errors

Mixing quot`s -2 with mod`s 1 reconstructs -9: a logical error. Divisor zero is a runtime `divide by zero` failure, so exclude it.

### Practice with answers

Find both pairs for -15 and 5.

<details>
<summary>Answer</summary>

Both are `(-3,0)` because the division is exact.

</details>

## 5. Check a decomposition

A verify question asks whether a proposed quotient/remainder pair obeys both the reconstruction identity and the convention. The identity alone does not uniquely choose a quotient.

**Template.**

```text
a == b*q+r
abs r < abs b
then check the required sign convention
```

The magnitude and sign tests distinguish an allowed pair from arbitrary decompositions.

### Worked variation: valid floor pair

<HaskellTryIt>

```haskell
main :: IO ()
main = print (((-14 :: Integer) == 5*(-3)+1, abs (1 :: Integer) < abs 5))
```



```text
(True,True)
```

</HaskellTryIt>

The floor pair reconstructs -14 and has a remainder smaller than 5.

### Worked variation: identity with wrong convention

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-14 :: Integer) == 5*(-2)+(-4))
```



```text
True
```

</HaskellTryIt>

This pair reconstructs correctly, but it is the truncation pair, not the floor pair.

### Worked variation: mixed pair fails

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-14 :: Integer) == 5*(-2)+1)
```



```text
False
```

</HaskellTryIt>

The proposed mixed pair gives -9 instead of -14.

### Exam question: Check a decomposition (4 marks)

A student gives q = -2, r = -4 for divMod (-14) 5. Is the identity enough to accept it`

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

A student gives q = -2, r = -4 for divMod (-14) 5. Is the identity enough to accept it` The question asks for an explanation or assessment. Identify the claim, then use the operation definition and the supplied domain to justify or refute it.

</Step>

<Step title="2. Plan">

Check reconstruction, magnitude, then the mod sign rule.

</Step>

<Step title="3. Solution">

The identity holds and abs r is below 5, but mod with positive divisor 5 must be non-negative. This is the quotRem pair. divMod is (-3,1).

An identity-only test misses this error and produces no GHC diagnostic. Add the named convention; do not claim every reconstructing pair is divMod.

## 6. Choose the power family

The exponent`s domain chooses the operator. Base/result type constraints then determine whether the expression is accepted.

**Template.**

```text
non-negative Integral exponent: ^
signed Integral exponent and Fractional base: ^^
floating exponent and Floating base: **
```

The symbol ^^ does not mean `more precise power`; it names a different exponent domain.

### Worked variation: exact Integer power

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-5 :: Integer) ^ (2 :: Int))
```



```text
25
```

</HaskellTryIt>

Two factors give 25 with an exact Integer result.

### Worked variation: inverse cube

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((4 :: Double) ^^ (-3 :: Integer))
```



```text
1.5625e-2
```

</HaskellTryIt>

`1/(4*4*4) = 1/64 = 0.015625`.

### Worked variation: fractional power

<HaskellTryIt>

```haskell
main :: IO ()
main = print (abs ((16 :: Double) ** 0.25 - 2) < 0.000000001)
```



```text
True
```

</HaskellTryIt>

The fourth root is mathematically 2; the floating calculation is checked approximately.

### Exam question: Choose the power family (4 marks)

Select operators and result types for exact 3 to power 8, 3 to power -2, and 3 to power 0.5.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Select operators and result types for exact 3 to power 8, 3 to power -2, and 3 to power 0.5. The command asks for an operation or policy. The exponent, numeric type or permitted error in the question determines that choice.

</Step>

<Step title="2. Plan">

Classify non-negative integral, signed integral, and fractional exponents.

</Step>

<Step title="3. Solution">

Use `3 ^ 8 :: Integer`, `(3 :: Double) ^^ (-2 :: Integer)`, and `(3 :: Double) ** 0.5`. Only the first is an exact integral answer; the latter two are Double approximations.

</Step>

<Step title="4. Check">

At exponent zero, ^ and ^^ return 1 at their respective result types. At base -3, the fractional-exponent case has no real square root.

</Step>

</Steps>

</details>

### Common errors

Using ^ with a negative integral exponent gives runtime `Negative exponent`, while a Double exponent causes `No instance for (Integral Double)`. These are different failures.

### Practice with answers

Which operator can use an Integer base without conversion`

<details>
<summary>Answer</summary>

^ for a non-negative integral exponent. ^^ and ** need Fractional and Floating bases respectively.

</details>

## 7. Refute the repeated-addition claim

A refute question needs one counterexample. Boundary tests are also useful when the proposed definition silently accepts inputs outside the intended domain.

**Template.**

```text
sum (replicate (fromIntegral n) n)
compare with n*n at positive, zero and negative n
```

Keep n :: Integer and use small inputs, so the Int conversion is not a second issue.

### Worked variation: normal case

<HaskellTryIt>

```haskell
main :: IO ()
main = print (sum (replicate 5 (5 :: Integer)))
```



```text
25
```

</HaskellTryIt>

Five copies of 5 total 25.

### Worked variation: zero boundary

<HaskellTryIt>

```haskell
main :: IO ()
main = print (sum (replicate 0 (0 :: Integer)))
```



```text
0
```

</HaskellTryIt>

The empty sum is zero.

### Worked variation: negative partition

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((sum (replicate (-5) (-5 :: Integer)), (-5 :: Integer)^2))
```



```text
(0,25)
```

</HaskellTryIt>

A negative count gives the empty list, whose sum is zero, while the square is 25.

### Exam question: Refute the repeated-addition claim (4 marks)

Refute the claim that repeated addition as written equals n*n for every Integer.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Refute the claim that repeated addition as written equals n*n for every Integer. The command is refute: one valid counterexample is enough. A collection of passing tests cannot establish the universal claim.

</Step>

<Step title="2. Plan">

Use the negative-input partition, not another positive test.

</Step>

<Step title="3. Solution">

At n = -5 the repeated-addition result is 0 but n*n is 25. The claim is false. Restrict counts to non-negative values that fit Int, or replace the implementation with multiplication.

</Step>

<Step title="4. Check">

At n = 0 both agree; that passing boundary is consistent with the narrower precondition.

</Step>

</Steps>

</details>

### Common errors

There is no GHC error on the negative count: replicate returns an empty list. An expected runtime rejection is therefore an incorrect output prediction.

### Practice with answers

Is n = -1 also a counterexample`

<details>
<summary>Answer</summary>

Yes: the repeated sum is 0; the square is 1.

</details>

## 8. Repetition and the empty product

The identity value differs between repeated addition and repeated multiplication: sum starts from 0, product from 1. That difference determines the zero-count result.

**Template.**

```text
sum (replicate n x)       -- n*x, for n >= 0
product (replicate n x)   -- x^n, for n >= 0
```

The count is Int; the repeated value can be Integer. Repetition does not require the value itself to be positive.

### Worked variation: negative factors

<HaskellTryIt>

```haskell
main :: IO ()
main = print (product (replicate 4 (-2 :: Integer)))
```



```text
16
```

</HaskellTryIt>

Four factors produce a positive result.

### Worked variation: zero copies

<HaskellTryIt>

```haskell
main :: IO ()
main = print (product (replicate 0 (-2 :: Integer)))
```



```text
1
```

</HaskellTryIt>

No factors gives the multiplicative identity 1.

### Worked variation: zero factor with positive count

<HaskellTryIt>

```haskell
main :: IO ()
main = print (product (replicate 3 (0 :: Integer)))
```



```text
0
```

</HaskellTryIt>

Three zero factors multiply to zero.

### Exam question: Repetition and the empty product (4 marks)

Explain why a power implementation using product must return 1, not 0, when the exponent is zero.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Explain why a power implementation using product must return 1, not 0, when the exponent is zero. The question asks for an explanation or assessment. Identify the claim, then use the operation definition and the supplied domain to justify or refute it.

</Step>

<Step title="2. Plan">

Use the multiplicative identity, so appending one factor preserves the power recurrence.

</Step>

<Step title="3. Solution">

`product [] = 1`; then a single-factor product is `x*1 = x`. Starting from 0 would make every product zero.

Using the sum seed 0 for multiplication is a logical error, without a GHC diagnostic. A negative replicate count also gives product 1, so it must be outside a non-negative power specification.

<summary>Answer</summary>

0 and 1 respectively.

</details>

## 9. Unary operations and argument order

A compare question can distinguish two functions whose names sound similar. Negation changes a sign; subtract removes a fixed amount; abs measures magnitude; signum retains only the sign.

**Template.**

```text
negate x = 0-x
subtract n x = x-n
abs x * signum x = x  -- Integer values
```

Trace argument positions explicitly instead of inferring the operation from a function name.

### Worked variation: subtract versus negate

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((subtract 4 (9 :: Integer), negate (9 :: Integer)))
```



```text
(5,-9)
```

</HaskellTryIt>

Subtract gives 9-4=5; negate gives 0-9=-9.

### Worked variation: negative amount and magnitude

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((subtract (-4) (9 :: Integer), abs (-9 :: Integer)))
```



```text
(13,9)
```

</HaskellTryIt>

Subtracting -4 adds 4; abs discards the sign of -9.

### Worked variation: zero sign and negative sign

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((signum (0 :: Integer), signum (-9 :: Integer)))
```



```text
(0,-1)
```

</HaskellTryIt>

signum distinguishes zero from a negative value.

### Exam question: Unary operations and argument order (4 marks)

Explain why `(-4)`, `(4 -)` and `subtract 4` are different.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Explain why `(-4)`, `(4 -)` and `subtract 4` are different. The question asks for an explanation or assessment. Identify the claim, then use the operation definition and the supplied domain to justify or refute it.

</Step>

<Step title="2. Plan">

Classify a negative literal and two functions; trace the two functions at input 9.

</Step>

<Step title="3. Solution">

`(-4)` is a number. `(4 -) 9 = 4-9 = -5`. `subtract 4 9 = 9-4 = 5`.

</Step>

<Step title="4. Check">

At input 4 both functions return zero; that single test would hide the argument-order difference.

</Step>

</Steps>

</details>

Printing a function instead of applying it is rejected: a key diagnostic is `No instance for (Show`. Apply the function to a concrete input. Using (-4) as a subtraction section is wrong.

### Practice with answers

What is `abs (-7) * signum (-7) :: Integer``

<details>
<summary>Answer</summary>

`7*(-1) = -7`.

</details>

## 10. Convert before dividing

A repair question often hides an integral operation inside a later conversion. Identify the first point at which information is discarded.

**Template.**

```text
fromIntegral numerator / fromIntegral denominator :: Double
```

Do not use div first if the specification requires a fractional mean.

### Worked variation: positive mean

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fromIntegral (23 :: Int) / fromIntegral (4 :: Int) :: Double)
```



```text
5.75
```

</HaskellTryIt>

Convert 23 and 4 before dividing; the remainder contributes 0.75.

### Worked variation: negative mean

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fromIntegral (-23 :: Int) / fromIntegral (4 :: Int) :: Double)
```



```text
-5.75
```

</HaskellTryIt>

Conversion keeps the sign; / returns the fractional result.

### Worked variation: too-late conversion

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fromIntegral ((23 :: Int) `div` 4) :: Double)
```



```text
5.0
```

</HaskellTryIt>

div has already discarded the remainder 3; widening cannot recover it.

### Exam question: Convert before dividing (4 marks)

Repair `average total count = fromIntegral (total div count)` for Int inputs and a Double result.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

Repair `average total count = fromIntegral (total div count)` for Int inputs and a Double result. The command asks for code. Preserve the required input and result types, then state any precondition before choosing the operation.

</Step>

<Step title="2. Plan">

Move conversion to both operands of /; require a positive count for a mean.

</Step>

<Step title="3. Solution">

`average :: Int -> Int -> Double`; `average total count = fromIntegral total / fromIntegral count`. Precondition: count is positive.

</Step>

<Step title="4. Check">

At total 23, count 4, the result is 5.75. At total 0, count 4, it is 0.0. A zero count is not a mean.

</Step>

</Steps>

</details>

Changing only div to / leaves Int operands and gives `No instance for (Fractional Int)`. Convert both before dividing.

### Practice with answers

Would converting only count be enough when total is already Double`

<details>
<summary>Answer</summary>

Yes. The other operand already has Double type, which determines the target of fromIntegral count.

</details>

## 11. Widen before multiplying

Conversion order matters for range as well as division. An Integer result annotation does not widen an Int multiplication that has already happened inside toInteger.

**Template.**

```text
toInteger x * toInteger y
not: toInteger (x*y) when x*y may overflow Int
```

Use safe small examples to compare routes, then justify the boundary argument from types rather than relying on the simulator to model machine overflow.

### Worked variation: small signed product

<HaskellTryIt>

```haskell
main :: IO ()
main = print (toInteger (-12 :: Int) * toInteger (12 :: Int))
```



```text
-144
```

</HaskellTryIt>

Convert both first; Integer multiplication gives the signed mathematical result.

### Worked variation: larger exact Integer power

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((toInteger (1000000 :: Int)) ^ (4 :: Int))
```



```text
1000000000000000000000000
```

</HaskellTryIt>

The base is widened before exponentiation; the result is ten to power 24.

### Worked variation: same conversion another spelling

<HaskellTryIt>

```haskell
main :: IO ()
main = print (fromIntegral (-12 :: Int) :: Integer)
```



```text
-12
```

</HaskellTryIt>

The explicit target makes fromIntegral equivalent here to toInteger.

## 23. Keep the direction quadrant

A direction question gives a vector, not just its slope. The signs of both coordinates select the quadrant. atan2 is the appropriate library operation.

**Template.**

```text
angle = atan2 y x
angleDegrees = angle*180/pi
```

Exclude the zero vector for a mathematical direction and preserve the y-first argument order.

### Worked variation: third quadrant

<HaskellTryIt>

```haskell
main :: IO ()
main = print (abs (atan2 (-1 :: Double) (-1) + 3*pi/4) < 0.000000001)
```



```text
True
```

</HaskellTryIt>

Both coordinates negative select the third quadrant, represented by -3*pi/4 in the principal range.

### Worked variation: fourth quadrant

<HaskellTryIt>

```haskell
main :: IO ()
main = print (abs (atan2 (-1 :: Double) 1 + pi/4) < 0.000000001)
```



```text
True
```

</HaskellTryIt>

Positive horizontal and negative vertical coordinates select -pi/4.

### Worked variation: downward vertical axis

<HaskellTryIt>

```haskell
main :: IO ()
main = print (abs (atan2 (-1 :: Double) 0 + pi/2) < 0.000000001)
```



```text
True
```

</HaskellTryIt>

The vector points down; atan2 handles the zero horizontal coordinate directly.

### Exam question: Keep the direction quadrant (4 marks)

Give the principal direction of vector (-1,-1) in radians and degrees.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

## 24. State a finite calculation contract

A design question may require only a precondition, not a new error-handling type. State it explicitly and test normal, boundary and invalid input partitions. Domain checks do not by themselves prove that finite floating arithmetic cannot overflow.

**Template.**

```text
for sqrt x / divisor:
finite inputs; x >= 0; divisor /= 0
then check a finite result if required
```

The runnable predicate below checks the real-domain part only, assuming finite inputs. The name and explanation keep that limited claim explicit.

### Worked variation: valid input

<HaskellTryIt>

```haskell
validRootRatio :: Double -> Double -> Bool
validRootRatio x divisor = x >= 0 && divisor /= 0

main :: IO ()
main = print (validRootRatio 9 2)
```



```text
True
```

</HaskellTryIt>

Non-negative radicand and nonzero divisor satisfy the real-domain checks.

### Worked variation: allowed zero radicand

<HaskellTryIt>

```haskell
validRootRatio :: Double -> Double -> Bool
validRootRatio x divisor = x >= 0 && divisor /= 0

main :: IO ()
main = print (validRootRatio 0 (-2))
```



```text
True
```

</HaskellTryIt>

Zero radicand is allowed; a negative nonzero divisor is also allowed.

### Worked variation: two invalid partitions

<HaskellTryIt>

```haskell
validRootRatio :: Double -> Double -> Bool
validRootRatio x divisor = x >= 0 && divisor /= 0

main :: IO ()
main = print ((validRootRatio (-1) 2, validRootRatio 9 0))
```



```text
(False,False)
```

</HaskellTryIt>

Negative radicand and zero divisor each violate a separate requirement.

### Exam question: State a finite calculation contract (4 marks)

State a precondition for a finite-real interpretation of sqrt x / d, and give tests for each invalid partition.

<details>
<summary>Worked answer, with the reasoning</summary>

<Steps title="Answering the question">

<Step title="1. Read the question">

State a precondition for a finite-real interpretation of sqrt x / d, and give tests for each invalid partition. The question asks for an explanation or assessment. Identify the claim, then use the operation definition and the supplied domain to justify or refute it.

</Step>

<Step title="2. Plan">

Check finiteness, the square-root domain and the nonzero divisor separately.

</Step>

<Step title="3. Solution">

Require finite x and d, x non-negative and d nonzero. If a finite Double result is required, check the computed result for Infinity and NaN too, because a tiny nonzero d can overflow the quotient.

</Step>

<Step title="4. Check">

Normal (9,2) gives 1.5; boundary (0,2) gives 0; invalid (-1,2) has no real root; invalid (9,0) has a zero divisor.

</Step>

</Steps>

</details>

### Common errors

A nonzero divisor test alone does not make sqrt safe. The program can still run and produce NaN, without a GHC type error. Nor does a finite-input check prove the final quotient stays in floating range.

### Practice with answers

Does d negative violate this real-domain contract`

<details>
<summary>Answer</summary>

No, provided it is finite and nonzero. The quotient can be negative; that is a valid real result.

</details>

Convert angles to radians and name principal inverse ranges.
