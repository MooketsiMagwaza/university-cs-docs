The previous lesson used `putStrLn "Hello, World!"` without stopping to ask why the message needed quotation marks, or what would happen without them. This lesson answers exactly that, from first principles, and does not move on until each rule has been tested in a real `main`.

## 1. What a literal actually is

A **literal** is a value written directly in your source code, spelled out completely, rather than computed from something else or looked up by name.

| Literal | Type | Meaning |
|---|---|---|
| `42` | numeric | A number, spelled out digit by digit |
| `True` | `Bool` | A truth value, one of exactly two |
| `'A'` | `Char` | One character, wrapped in single quotes |
| `"Hello"` | `String` | A sequence of characters, wrapped in double quotes |

An **identifier** is different in kind, not just in spelling: it is a *name* the program looks up, not a value spelled out in place. `cube`, `main`, and `putStrLn` are identifiers. Haskell has to look each one up in whatever is currently in scope to find out what it refers to; a literal needs no lookup at all, because it already **is** the value.

| Question | Answer |
|---|---|
| **What?** | A literal is a value spelled out directly in source code; an identifier is a name that must be looked up |
| **Why does the distinction matter?** | The parser has to decide, for every word it reads, whether that word *is* a value or *names* one — and it makes that decision before anything is evaluated |
| **When do you need to know this?** | Every time you write a message, a character, or any text — getting it wrong is the single most common first-week mistake in this course |
| **How does Haskell tell them apart?** | By punctuation alone: quotation marks mark a literal; their absence means "look this word up" |

### Why quotation marks exist at all — the actual reason

Without quotation marks, a program would have no way to write text that *isn't* mistaken for a request to look up a name. Consider what `Hello` alone would have to mean: either "the five-letter word Hello, as data" or "go and find whatever is named `Hello` in this program." Haskell cannot read your mind about which one you intend, so it commits to one rule, applied with no exceptions: **an unquoted word is always a name to look up; quotation marks are the only way to write a literal piece of text.** This is not a Haskell quirk — it is the same reason every programming language needs some marker for string literals — but Haskell enforces it with zero tolerance for "it looked like a sentence, so I assumed it meant text."

```haskell
-- File: Quoting.hs
main :: IO ()
main = do
  putStrLn "Hello"      -- a String literal: the value IS the text Hello
  print (length "Hello") -- length needs a real String to count
```

```text
Hello
5
```

Run the broken version to see exactly what goes wrong when the quotes are missing:

```haskell
-- File: QuotingBroken.hs — do not expect this to compile
main :: IO ()
main = do
  putStrLn Hello
```

```text
QuotingBroken.hs:4:12: error: [GHC-88464]
    Variable not in scope: Hello
```

Nothing about *evaluating* the program went wrong — the program never got that far. `Hello` was treated as a name, Haskell searched for a definition of that name, found none, and rejected the program before running a single line. This is exactly the mechanism the flowchart above describes, now seen as a real compiler error instead of an abstract rule.

## 2. Names are not text — three ways to write "H"

<ComparisonTable
  columns={[
    { header: 'Source', key: 'source' },

    { header: 'Why', key: 'why' }
  ]}
  rows={[
    { source: 'Hello', meaning: 'A program name (an identifier)', why: 'No quotation marks — this is the "look it up" branch of the flowchart above' },
    { source: '"Hello"', meaning: 'A String value', why: 'Double quotes mark a sequence of characters as literal text' },
    { source: "'H'", meaning: 'One Char value', why: 'Single quotes mark exactly one character as literal text' }
  ]}
/>

```text
ghci> :type 'A'
'A' :: Char
ghci> :type "A"
"A" :: String
ghci> :type A
```

The third line, typed with no quotes at all, does **not** ask "what type does the letter A have" — there is no such expression. It asks GHCi to look up an identifier named `A`, and since capitalised names are reserved for data constructors, GHCi reports something about an undefined constructor, not a type for a letter.

`'AB'` is invalid because a `Char` holds exactly one character — no more, no fewer. `"AB"` is a perfectly valid two-character `String`. This is not a stylistic preference; it is baked into what each type *is*: `Char` is defined to represent a single character, and `String` is defined as a list of characters, so a `String` of length one, `"A"`, and a `Char`, `'A'`, are still two different types even though they look almost identical on the page.

### Why Char and String are genuinely different types, not two spellings of the same thing

It helps to see the consequence directly, in a program that tries to treat them as interchangeable:

```haskell
-- File: CharVsString.hs
main :: IO ()
main = do
  print ('A' == 'A')       -- Char compared with Char: fine
  print ("A" == "A")       -- String compared with String: fine
  -- print ('A' == "A")    -- would NOT type-check: Char and String are different types
  print (length "Hello")   -- length works on the String; it counts 5 characters
  -- print (length 'H')    -- would NOT type-check: a single Char has no "length" to count
```

```text
True
True
5
```

The two commented-out lines are left in on purpose, exactly as `CharVsString.hs` would show them if you tried to compile with them uncommented: GHC would refuse before running anything, with a type error naming the mismatch between `Char` and `[Char]` (`String`'s real name). `length` is defined for lists — and a `String` is a list of `Char`, while a bare `Char` is not a list of anything.

## 3. Spaces apply functions

A single space between two things means **function application**: apply the thing on the left to the thing on the right.

```haskell
-- Apply the already-defined function square to the value 4.
square 4
```

This is not punctuation and not a separator between unrelated words — it is an operator every bit as real as `+`, just spelled as a blank space instead of a symbol. Multiple applications group to the **left**, exactly the way `first second third` would in ordinary left-to-right reading:

```text
f x y = (f x) y
```

Read this as: first apply `f` to `x`, producing some result; then apply *that result* to `y`. This is why `print Hello World` from the previous lesson does not mean "print the sentence Hello World" — with no quotation marks, Haskell sees three identifiers and applies them left to right: first `print` to `Hello`, then that whole result to `World`.

<StepByStep>
  <StepByStepTitle>Why print Hello World is not one message</StepByStepTitle>

  <Step number={1}>
  Haskell scans `print Hello World` and finds three space-separated words, none in quotes: `print`, `Hello`, `World`.
  </Step>

  <Step number={2}>
  With no quotation marks, all three are identifiers — names to look up — never literal text, regardless of how the words read to a human.
  </Step>

  <Step number={3}>
  Application groups left, so this is parsed as `(print Hello) World`: apply `print` to `Hello` first.
  </Step>

  <Step number={4}>
  `Hello` was never defined anywhere in the program, so Haskell reports `Variable not in scope: Hello` before `print` or `World` are even considered.
  </Step>
</StepByStep>

```haskell
-- File: Greeting.hs
main :: IO ()
main = do
  putStrLn "one word applied to text:"
  putStrLn "Hello World"        -- correct: one String literal
```

```text
one word applied to text:
Hello World
```

## 4. Putting it together: a program that exercises every rule above

```haskell
-- File: ValuesDemo.hs
-- PURPOSE: Show a literal, an identifier, a Char, and a String,
-- and prove that each behaves according to its own type.

greetingWord :: String
greetingWord = "Hello"      -- greetingWord is an identifier; "Hello" is the String literal it names

firstLetter :: Char
firstLetter = 'H'            -- a Char literal: exactly one character

main :: IO ()
main = do
  putStrLn greetingWord              -- looks up the identifier, then prints the String it refers to
  print firstLetter                   -- print shows a Char in its readable form, with quotes
  print (length greetingWord)         -- counts the characters in the String
  print (greetingWord == "Hello")     -- comparing two String values
```

```text
Hello
'H'
5
True
```

Two things worth noticing in that output, both direct consequences of the rules above:

- `print firstLetter` shows `'H'` **with** single quotes, because `print` always shows a value in Haskell-readable form, and the readable form of a `Char` includes the quotes that mark it as one.
- `greetingWord` is an identifier throughout the whole program — it is looked up every time it is used — but the *value* it refers to, `"Hello"`, never changes. Using the same name twice (`putStrLn greetingWord` and `greetingWord == "Hello"`) reads the same fixed value both times, for the same reason `taxRate` kept meaning `0.14` in the immutability lesson.

## 5. Common mistakes, with the actual reason each one fails

| Attempt | Cause | Why it actually fails | Correction |
|---|---|---|---|
| `hello` | Identifier, not text | No quotes means "look this name up"; if nothing is named `hello`, it is not in scope | `"hello"` |
| `'hello'` | More than one character inside single quotes | `Char` is defined to hold exactly one character; five characters cannot fit in that type | `"hello"` |
| `"A" == 'A'` | `String` and `Char` are different types | `==` requires both sides to share one type; comparing across types is rejected before evaluation | Compare like with like: `"A" == "A"` or `'A' == 'A'` |
| `true` | Haskell is case-sensitive | `true` is looked up as an ordinary lowercase identifier; the actual Boolean constructor is capitalised | `True` |
