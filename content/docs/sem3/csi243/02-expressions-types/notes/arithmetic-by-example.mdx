## 1. Arithmetic precedence and associativity

Precedence decides which operator binds more tightly. Associativity groups operators with equal precedence; it does not promise an evaluation order for unrelated arguments. Application binds tighter than infix arithmetic. Powers group right, multiplication and division group left, and addition and subtraction group left.

**Template.**

```text
parenthesise applications -> powers -> multiplication/division -> addition/subtraction
x - y - z = (x - y) - z
x ^ y ^ z = x ^ (y ^ z)
```

Rewrite grouping first, then reduce one operation per line. Prefix negation needs care: `-2 ^ 2` means `-(2 ^ 2)`; `(-2) ^ 2` squares a negative base.

### Worked variation: multiplication inside addition

<HaskellTryIt>

```haskell
main :: IO ()
main = print (8 + 3 * 4 - 2 :: Integer)
```



```text
18
```

</HaskellTryIt>

`8 + (3 * 4) - 2 = 8 + 12 - 2 = 20 - 2 = 18`. Multiplication binds tighter; additions/subtractions group left.

### Worked variation: division and subtraction group left

<HaskellTryIt>

```haskell
main :: IO ()
main = print (20 - 12 `div` 3 * 2 :: Integer)
```



```text
12
```

</HaskellTryIt>

`20 - ((12 div 3) * 2) = 20 - (4 * 2) = 12`. Moving multiplication inside the divisor changes the expression.

### Worked variation: powers group right

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((2 ^ (3 ^ 2), (2 ^ 3) ^ 2, -2 ^ 2, (-2) ^ 2) :: (Integer,Integer,Integer,Integer))
```



```text
(512,64,-4,4)
```

</HaskellTryIt>

`3^2 = 9`, then `2^9 = 512`; the alternative gives `8^2 = 64`. Negating `2^2` gives `-4`; two negative factors give `4`.

## 2. Boolean and comparison traces

Comparisons turn numeric results into Bool. `not` is a function, `&&` requires both conditions, and `||` requires at least one. Arithmetic binds above comparisons; comparisons bind above `&&`, which binds above `||`. Comparisons do not chain like mathematical inequalities.

**Template.**

```text
arithmetic -> comparison -> && -> ||
not (comparison)
lower <= x && x <= upper
```

Each comparison has numeric operands of the same type and produces Bool. Parentheses are needed when applying not to a whole comparison.

### Worked variation: arithmetic then comparisons

<HaskellTryIt>

```haskell
main :: IO ()
main = print (8 + 2 * 3 >= 14 && 5 /= (0 :: Integer))
```



```text
True
```

</HaskellTryIt>

`8 + 6 >= 14 && 5 /= 0 = 14 >= 14 && True = True && True = True`.

### Worked variation: and inside or

<HaskellTryIt>

```haskell
main :: IO ()
main = print (3 > (9 :: Integer) || 4 == 4 && not False)
```



```text
True
```

</HaskellTryIt>

`False || (True && not False) = False || (True && True) = False || True = True`.

### Worked variation: negative range boundary

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((-3 :: Integer) >= (-3) && (-3) < 0 || False)
```



```text
True
```

</HaskellTryIt>

`(True && True) || False = True || False = True`; the inclusive lower boundary passes.

## 3. Constructing expressions from prose

Translate the sentence`s operation order before calculating. `Add, then multiply` differs from `add the product`. Signatures say whether measurements are approximate and counts integral. A formula can be well typed while violating a physical requirement such as a non-negative width.

**Template.**

```text
name inputs = translated expression
combined = (first + second) * scale
changed = original * numerator / denominator + offset
```

Inputs represent quantities in the question. Parentheses preserve the stated order; units say what the result means.

### Worked variation: add twice before scaling

<HaskellTryIt>

```haskell
main :: IO ()
main = print (((19 + 1) + 5) * 10 :: Integer)
```



```text
250
```

</HaskellTryIt>

19 plus 1 is 20, plus 5 is 25; multiply the whole result by 10. Without grouping only 5 would be scaled.

### Worked variation: fractional rectangle

<HaskellTryIt>

```haskell
rectangleArea :: Double -> Double -> Double
rectangleArea width height = width * height

main :: IO ()
main = print (rectangleArea 2.5 4)
```



```text
10.0
```

</HaskellTryIt>

Substitute 2.5 and 4 into `width * height`; Double gives printed output `10.0`.

### Worked variation: negative temperature

<HaskellTryIt>

```haskell
celsiusToFahrenheit :: Double -> Double
celsiusToFahrenheit c = c * 9 / 5 + 32

main :: IO ()
main = print (celsiusToFahrenheit (-40))
```



```text
-40.0
```

</HaskellTryIt>

`(-40) * 9 / 5 + 32 = (-360) / 5 + 32 = -72 + 32 = -40`. Negative input is meaningful here.

## 4. Signed div, mod, quot and rem

`div` rounds towards negative infinity; `quot` truncates towards zero. `mod` belongs with div, and `rem` with quot. Nonzero mod has the divisor`s sign; nonzero rem has the dividend`s sign. All four need integral operands and a nonzero divisor.

**Template.**

```text
q = a `div` b; r = a `mod` b
q = a `quot` b; r = a `rem` b
a = b*q + r; abs r < abs b
```

Here a is the dividend and b the nonzero divisor. Compute r from the identity once q is chosen. Prefix `div a b`, `mod a b`, `quot a b` and `rem a b` are equivalent to the backtick forms.

### Worked variation: both positive

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((7 `div` 3, 7 `mod` 3, 7 `quot` 3, 7 `rem` 3) :: (Integer,Integer,Integer,Integer))
```



```text
(2,1,2,1)
```

</HaskellTryIt>

`7/3` lies between 2 and 3. Both quotients are 2; `7 - 3*2 = 1`.

### Worked variation: negative dividend

<HaskellTryIt>

```haskell
main :: IO ()
main = print (((-7) `div` 3, (-7) `mod` 3, (-7) `quot` 3, (-7) `rem` 3) :: (Integer,Integer,Integer,Integer))
```



```text
(-3,2,-2,-1)
```

</HaskellTryIt>

`-7/3` lies between -3 and -2. Floor gives -3, truncation gives -2. Remainders: `-7 - 3*(-3) = 2` and `-7 - 3*(-2) = -1`.

### Worked variation: negative divisor

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((7 `div` (-3), 7 `mod` (-3), 7 `quot` (-3), 7 `rem` (-3)) :: (Integer,Integer,Integer,Integer))
```



```text
(-3,-2,-2,1)
```

</HaskellTryIt>

`7/(-3)` lies between -3 and -2. Floor gives -3 with `7 - (-3)*(-3) = -2`; truncation gives -2 with `7 - (-3)*(-2) = 1`.

### Worked variation: both negative

<HaskellTryIt>

```haskell
main :: IO ()
main = print (((-7) `div` (-3), (-7) `mod` (-3), (-7) `quot` (-3), (-7) `rem` (-3)) :: (Integer,Integer,Integer,Integer))
```



```text
(2,-1,2,-1)
```

</HaskellTryIt>

The quotient lies between 2 and 3, so both give 2. `-7 - (-3)*2 = -1` in each convention.

### Worked variation: zero dividend

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((0 `div` (-3), 0 `mod` (-3), 0 `quot` (-3), 0 `rem` (-3)) :: (Integer,Integer,Integer,Integer))
```



```text
(0,0,0,0)
```

</HaskellTryIt>

Zero divided by a nonzero number is zero, remainder zero. Zero dividend is allowed; zero divisor is not.

## 5. divMod and quotRem pairs

`divMod` returns div and mod together; `quotRem` returns quot and rem together. They prevent mixing conventions. The quotient comes first.

**Template.**

```text
(q,r) = divMod a b
(q,r) = quotRem a b
check = a == b*q+r && abs r < abs b
```

Use either pair consistently. Infix forms require backticks. Pattern binding `(q,r)` names the components. Each operation has type `Integral a => a -> a -> (a,a)`.

### Worked variation: both positive

<HaskellTryIt>

```haskell
main :: IO ()
main = print ((divMod 7 3, quotRem 7 3) :: ((Integer,Integer),(Integer,Integer)))
```



```text
((2,1),(2,1))
```

</HaskellTryIt>

`7/3` lies between 2 and 3. Both quotients are 2; `7 - 3*2 = 1`. First tuple: floor; second tuple: truncation.

`-7/3` lies between -3 and -2. Floor gives -3, truncation gives -2. Remainders: `-7 - 3*(-3) = 2` and `-7 - 3*(-2) = -1`. First tuple: floor; second tuple: truncation.

## 6. Non-negative integral exponents with ^

`(^)` multiplies a base by itself a whole number of times. The base can be any Num type, including Integer or Double; the exponent must be Integral and non-negative. The empty product for exponent zero is 1, including `0 ^ 0` in this programming convention.

**Template.**

```text
(^) :: (Num a, Integral b) => a -> b -> a
base ^ nonNegativeExponent
```

The type variables are independent: base and exponent may have different types.

### Worked variation: integer base

<HaskellTryIt>


## 7. Signed integral exponents with ^^

`(^^)` extends integral exponents to negative values by taking a reciprocal. The base must therefore be Fractional. A negative exponent does not mean a negative answer: base sign and exponent parity decide that.

**Template.**

```text
(^^) :: (Fractional a, Integral b) => a -> b -> a
x ^^ (-n) = recip (x ^ n)
```

For negative exponents a nonzero base is required for a finite real answer. Double reciprocal of zero can produce Infinity.

## 8. Floating exponents with **

`(**)` accepts floating bases and exponents, including fractional exponents. Both have the same Floating type. A fractional power need not be exact even when its mathematical value is simple. A negative base with a non-integral exponent generally has no real result and gives NaN for Double.

**Template.**

```text
(**) :: Floating a => a -> a -> a
base ** exponent
```

Use ** for a fractional exponent. For exact Integer results and non-negative integral exponents, prefer ^. All three power operators associate right.

### Worked variation: fractional exponent with tolerance

<HaskellTryIt>

The mathematical root is 2. This checks the computed approximation within tolerance, without claiming exact equality.




```text

```

## 9. Repeated addition and its precondition

Repeating addition n times models multiplication only when the repetition count is non-negative. `replicate` uses an Int count; negative counts produce an empty list. Therefore the often-quoted squareByAdding definition does not square negative n. Its intended domain must also fit the Int count and available memory.

**Template.**

```text
squareByAdding n = sum (replicate (fromIntegral n) n)
precondition: 0 <= n and n fits in Int
```

The count determines the number of copies; the value determines what is added. These are separate roles, even when both happen to be n. For arbitrary signed Integer squares, `n*n` avoids the repetition-count conversion.

### Worked variation: positive repetition

<HaskellTryIt>

```haskell
squareByAdding :: Integer -> Integer
squareByAdding n = sum (replicate (fromIntegral n) n)

main :: IO ()
main = print (squareByAdding 4)
```



```text
16
```

</HaskellTryIt>

`replicate 4 4 = [4,4,4,4]`; `sum = 4+4+4+4 = 16`.

### Worked variation: zero copies

<HaskellTryIt>

```haskell
squareByAdding :: Integer -> Integer
squareByAdding n = sum (replicate (fromIntegral n) n)

main :: IO ()
main = print (squareByAdding 0)
```



```text
0
```

</HaskellTryIt>

`replicate 0 0 = []` and `sum [] = 0`, so the zero boundary agrees with the square.

### Worked variation: negative counterexample

<HaskellTryIt>

```haskell
squareByAdding :: Integer -> Integer
squareByAdding n = sum (replicate (fromIntegral n) n)

main :: IO ()
main = print ((squareByAdding (-3), (-3)*(-3)))
```



```text
(0,9)
```

</HaskellTryIt>

A count of -3 produces `[]`, whose sum is 0. Multiplication instead gives 9, disproving universal agreement.

### Worked variation: signed repair

<HaskellTryIt>

```haskell
main :: IO ()
main = print (sum (replicate 3 (abs (-3 :: Integer))))
```



```text
9
```

</HaskellTryIt>

Use magnitude 3 for both count and summand. This repairs small negative inputs, but still has the Int count limitation.

## 23. Annotations, inference and numeric defaulting

## 27. Infinity, NaN and failure categories

A type error prevents execution. A runtime exception stops a demanded calculation. A mathematical domain error has no intended real answer; Double often records it as NaN or an infinity rather than throwing an exception. ## Summary

<Callout type="key" title="Remember">

Check types, grouping and domain in that order. Keep div with mod and quot with rem; verify `a = b*q+r`. Choose powers by exponent domain. Convert before losing a remainder or overflowing. Rounding rules differ on negatives and ties. Repetition has a non-negative count precondition. Floating comparisons need an error policy, real-domain checks and a policy for non-finite results. Trigonometric functions use radians.

</Callout>

## Check your understanding

<CheckQuestions>

<CheckQuestion question="How do the integral division pairs differ at a negative non-exact quotient`">

div floors towards negative infinity; quot truncates towards zero. Matching remainders restore the dividend through `a = b*q+r`.

</CheckQuestion>

<CheckQuestion question="Why does an annotation not replace fromIntegral`">

An annotation checks a type. Conversion constructs a value of another numeric type. An existing Int does not become Double by asserting it has type Double.

</CheckQuestion>

<CheckQuestion question="What invalidates the universal squareByAdding claim`">

At -3 the negative replication count produces an empty list, sum 0, whereas the square is 9. Small positive tests do not cover that partition.

</CheckQuestion>

<CheckQuestion question="Does round always send halfway values away from zero`">

No. It chooses the even neighbour: round (-4.5) is -4; round (-5.5) is -6.

</CheckQuestion>

<CheckQuestion question="Is a well-typed Double result necessarily a valid finite real answer`">

No. Domain errors and overflow can produce NaN or Infinity. Check the domain and finiteness required by the problem.

</CheckQuestion>

<CheckQuestion question="Why compare a root or trigonometric result using tolerance`">

The real result or input pi may be inexact in binary floating point. The tolerance states the permitted error without claiming exact equality.
