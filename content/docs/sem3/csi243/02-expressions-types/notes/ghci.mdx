**Haskell** is the language. **GHC** — the Glasgow Haskell Compiler — checks and compiles it. **GHCi** is GHC's interactive environment; the final `i` means *interactive*.

This lesson takes you from an empty machine to a working Haskell session. By the end you will have installed the toolchain, evaluated expressions at the prompt, defined a function interactively, and learned the commands you will use in every laboratory.

```text
expression you enter  ->  GHCi evaluates it  ->  resulting value
       2 + 3          ->       add           ->        5
```

## 1. What you are installing

| Tool | What it is | When you use it |
|---|---|---|
| **GHC** | The Glasgow Haskell Compiler | Compiling a saved program into an executable; checking a complete module |
| **GHCi** | GHC's interactive read–evaluate–print environment | Trying expressions, inspecting types, loading files, testing functions quickly |
| **GHCup** | The installer that manages GHC, GHCi, and related tools | Once, at setup, and later to change versions |
| **A `.hs` file** | A text file holding saved Haskell definitions | Keeping work after GHCi closes; building larger programs |

GHC can be divided into three parts: the **compilation manager**, which handles multiple source files; the **Haskell compiler** itself (abbreviated `Hsc` inside GHC), which compiles a single source file; and the **pipeline**, which composes the external programs needed to turn a source file into object code.

GHCi is the interactive executable of the GHC interpreter. It can evaluate Haskell expressions interactively, interpret Haskell programs, and load GHC-compiled modules.

### Verify the installation

Run these two commands in a new terminal:

```text
ghc --version
ghci --version
```

Each should report a version number rather than an error such as `command not found`. The exact version differs between machines and releases; what matters is that both commands answer.

<Callout type="warn" title="If the command is not found">
The three usual causes, in order of likelihood: you did not open a **new** terminal after installing; the installer did not finish successfully (re-run it and read the final lines); or you ran the installer in a different user account from the one you are now using.
</Callout>

### Working without an installation

If your machine cannot run the installer yet, use the official [Haskell Playground](https://play.haskell.org/) for single-file programs. It is enough for the expressions in this chapter, but the local toolchain is still required for module work and for the laboratories, because the Playground cannot `:load` your own files.

## 3. Start GHCi and read the prompt

Type `ghci` at your terminal prompt. On Windows you can also launch it from the Start menu.

You will be greeted with something similar to:

```text
GHCi, version 9.10.3: https://www.haskell.org/ghc/  :? for help
ghci>
```

The trailing `>` means the Haskell system is **waiting for your input**.

### Why the lecture slides show `Prelude>`

Older GHC releases printed the prompt as `Prelude>`, and the course lecture material shows that form throughout. Both mean the same thing, but the older prompt carried extra information worth understanding:

- It **listed the modules loaded into the interactive session** — hence `Prelude`.
- **`Prelude`** is the standard library module containing a small set of standard definitions. It is included automatically into all Haskell modules, which is why arithmetic, comparison, and `putStrLn` work immediately.
- With several modules loaded the prompt grew to show them all: `Prelude Data.List Control.Monad>`.

Current releases shorten this to a plain `ghci>`. You can restore the older behaviour, or set any prompt you like:

```text
ghci> :set prompt "Prelude> "
Prelude>
```

<Callout type="warn" title="Do not type the prompt">
`Prelude>` and `ghci>` are printed *by* GHCi. In every example on this site, type only the text after the prompt.
</Callout>

## 4. Evaluate your first expressions

Functional programming evaluates **expressions** to give **values**. Haskell works like a functional calculator: it applies mathematical rules and stops when the expression cannot be reduced any further.

Consider `1 + 2 * 3`. The reduction is:

```text
1 + 2 * 3
=> 1 + 6
=> 7
```

Multiplication has higher precedence than addition, so `2 * 3` reduces first. Enter these one line at a time:

```text
ghci> 1 + 2 * 3 + 4
11
ghci> (1 + 2) * (3 + 4)
21
ghci> 400 > 200
True
ghci> 1 /= 1
False
ghci> True || False
True
```

### Three essential words

- An **expression** describes a computation: `2 + 3`.
- **Evaluation** is Haskell applying its rules until no rule applies.
- A **value** is the finished result: `5`.

GHCi interprets the whole line as one expression to evaluate. The expression may not span several lines — as soon as you press Enter, GHCi attempts to evaluate what you typed. (Section 8 shows how to enter something longer.)

### Comparison and Boolean operators

Boolean values are `True` and `False`. They combine with `&&` for *and* and `||` for *or*; `&&` has higher precedence than `||`.

| Operator | True when |
|---|---|
| `a == b` | `a` and `b` are equal |
| `a /= b` | `a` is not equal to `b` |
| `a < b` | `a` is less than `b` |
| `a > b` | `a` is greater than `b` |
| `a <= b` | `a` is less than or equal to `b` |
| `a >= b` | `a` is greater than or equal to `b` |
| `a && b` | both `a` and `b` are `True` |
| <code>a &#124;&#124; b</code> | at least one of `a` and `b` is `True` |
| `not a` | `a` is `False` |

Every value and every expression has a type, and **an expression always has the same type as the value it evaluates to**. Chapter lesson 4 develops this properly.

### Negative numbers need brackets

Haskell writes negative numbers with a `-` in front. When a negative number follows an operator, enclose it in brackets, or Haskell reads the `-` as subtraction and reports an error:

```text
ghci> 9 + -7
<interactive>:1:1: error: ...
ghci> 9 + (-7)
2
```

## 5. Ask for types with `:type`

```text
ghci> :type True
True :: Bool
ghci> :type 'A'
'A' :: Char
ghci> :type "A"
"A" :: String
```

Read `::` as **“has type.”** A type describes the kind of value and which operations make sense for it. Notice that `'A'` and `"A"` have different types: single quotes make one `Char`, double quotes make a `String`. The next lesson returns to this.

## 6. Name things with `let` and `it`

You may define a name at the prompt with the keyword `let`. The name can then be reused later in the session.

```text
ghci> let radius = 5
ghci> radius * 2
10
```

The keyword `it` refers to the value of the most recently evaluated expression. It is useful when you did not name a result but now want it:

```text
ghci> 12 * 12
144
ghci> it + 1
145
```

<Callout type="warn" title="Prompt definitions do not survive">
Expressions and definitions entered at the prompt are **lost when GHCi closes**. That is the whole reason for saving work in a `.hs` file, which the next lesson covers.
</Callout>

## 7. Define and test a function interactively

```text
ghci> cube x = x * x * x
ghci> cube 3
27
ghci> cube (-2)
-8
ghci> :type cube
cube :: Num a => a -> a
```

Line by line:

1. `cube` is the function name. Function names begin with a **lowercase** letter.
2. `x` names the input for this definition.
3. `=` separates the left side from the result expression.
4. `x * x * x` describes the value the function returns.
5. Brackets around `-2` stop the minus sign being read as subtraction.

There are no parentheses or commas between a function name and its arguments. A definition such as `a b c d = b * c * d` defines a function `a` taking three arguments `b`, `c`, and `d`.

### Every `if` needs an `else`

In Java an `if` statement can exist without an `else`. In Haskell it cannot:

```text
ghci> isNegative n = if n < 0 then True else False
ghci> isNegative (-4)
True
ghci> isNegative 4
False
```

This is because **everything in Haskell is an expression, and every expression has a type**. Without an `else`, the expression would have no value when the condition is `False`, so it could not have a type.

## 8. Entering something longer

Some definitions are too long for one line. Enclose them between `:{` and `:}`, pressing Enter after each line:

```text
ghci> :{
ghci| isVowel c =
ghci|   c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u'
ghci| :}
ghci> isVowel 'e'
True
```

The continuation prompt `ghci|` means GHCi is still collecting the block. Haskell expects the second and later lines to be **indented** relative to the name being defined. Indentation is part of the syntax, so use the space bar consistently — mixing tabs and spaces very often causes compiler errors.

## 9. The GHCi command set

GHCi commands begin with a colon; ordinary expressions do not. Most can be abbreviated to their initial letter, with ambiguities resolved in favour of the more commonly used command.

| Command | Short form | Purpose |
|---|---|---|
| `:help` | `:?` | Show the complete list of GHCi commands |
| `:type expression` | `:t` | Show the type of an expression |
| `:load File.hs` | `:l` | Check and load definitions from a file |
| `:reload` | `:r` | Reload the most recently loaded file |
| `:info name` | `:i` | Show information about a name, type, or operator |
| `:browse Module` | — | List the signatures a module exports |
| `:show modules` | — | List the modules currently loaded |
| `:set prompt "…"` | — | Change the prompt text |
| `:cd directory` | — | Change GHCi's current directory |
| `:!command` | — | Run an external operating-system command |
| `:quit` | `:q` | Leave GHCi (Ctrl+D also works) |

### `:info` in practice

`:type` answers "what type does this expression have?" `:info` answers the bigger question: "what *is* this name, and where did it come from?" For a type, it shows how the type is built and which typeclasses it belongs to:

```text
ghci> :info Bool
type Bool :: *
data Bool = False | True
        -- Defined in ‘GHC.Types’
instance Eq Bool -- Defined in ‘GHC.Classes’
instance Ord Bool -- Defined in ‘GHC.Classes’
instance Enum Bool -- Defined in ‘GHC.Enum’
instance Show Bool -- Defined in ‘GHC.Show’
instance Read Bool -- Defined in ‘GHC.Read’
instance Bounded Bool -- Defined in ‘GHC.Enum’
```

Read this line by line: `data Bool = False | True` is `Bool`'s complete definition — exactly two values, no more, no less. Each `instance` line lists a capability `Bool` has: it can be compared for equality (`Eq`), it can be ordered (`Ord`), and so on. The `-- Defined in …` comments tell you which library module to look up if you want the source. `:info` works on functions too:

```text
ghci> :info not
type Bool :: *
...
not :: Bool -> Bool     -- Defined in ‘GHC.Classes’
```

<Callout type="info" title=":type vs :info">
`:type expr` answers a question about an **expression** you supply. `:info name` answers a question about a **name already in scope** — a function, a type, or an operator — including facts `:type` does not show, such as which module defined it.
</Callout>

## 10. Common first-session failures

These are the mistakes almost every beginner makes in their first hour. Each is a language rule, not a bug.

| Attempt | Why Haskell rejects it | Correction |
|---|---|---|
| `9 + -7` | The `-` after an operator is read as subtraction | `9 + (-7)` |
| `X == x` | `X` is uppercase, so Haskell expects a constructor; `x` is undefined | Compare defined lowercase names or literal values |
| <code>False &#124;&#124; true</code> | `True` and `False` are constructors and must be capitalised | <code>False &#124;&#124; True</code> |
| `if 'A' > 'a' then True` | Every Haskell `if` expression requires an `else` | `if 'A' > 'a' then True else False` |
| `Print "Hello"` | Names are case-sensitive; `Print` is not `print` | `print "Hello"` |
| `print Hello World` | Unquoted words are program names, so this is three identifiers | `print "Hello World"` |

The last two matter enough that the next lesson takes them apart in full.

1. Evaluate `1+2*3+4`, `400>200`, `1/=1`, and `True || False`.
