The previous nine chapters taught you to write Haskell. This one is about **justifying** what you wrote: saying what a function should do, arguing that it does, classifying what goes wrong, and knowing what it costs.

These are the skills the written examination tests, and the ones that separate code that happens to work from code you can defend.

## Key ideas

### The three levels of evidence

Each is stronger than the last, and each has a place:

| Evidence | Shows | Limitation |
|---|---|---|
| It compiles | Types are used consistently | Says nothing about the values computed |
| Tests pass | It worked for those inputs | Says nothing about untested inputs |
| A completed induction | It holds for every finite input | Assumes termination, which is argued separately |

A compiler proves type consistency, not that your formula matches the problem. That is why every laboratory has asked for a specification, a dry run, **and** tests.

### Revision route

Working back through the course, the questions most likely to be asked:

| Chapter | Be able to |
|---|---|
| 1–2 | Explain purity, immutability, and effects; predict the type and value of an expression |
| 3 | Read a signature; separate a pure calculation from its IO boundary |
| 4 | Implement one specification with `if`, patterns, guards, and `case`, and justify the choice |
| 5 | Identify base case and recursive step; dry run; explain non-termination |
| 6 | Recurse over `[]` and `(x:xs)`; choose between a list and a tuple; read a comprehension |
| 7 | Explain currying; use `map`, `filter`, and folds; predict a fold by substitution |
| 8 | Structure a program in modules; declare and use custom types |
| 9 | Read constraints; diagnose a "No instance for" error; use `Maybe` |
| 10 | Write a specification; prove a property by induction; classify an error; compare costs |
