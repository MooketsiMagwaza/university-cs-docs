## 1. Model and individual report

The Test1 model holds one name and a list of Double marks. A name is a display label, not automatically a unique identifier. The raw model permits empty and invalid data. A report consumes the optional mean and returns text; it performs no IO.

**Template:** model → optional calculation → match result → report text. For `Student name values`, `name` labels the report and `values` supplies the calculation. A missing mean becomes “no marks”, not a failing mark.

These are the exact Test1 core definitions:

```haskell
data Student = Student
  { studentName :: String
  , marks :: [Double]
  } deriving (Eq, Show)

average :: [Double] -> Maybe Double
average [] = Nothing
average values = Just (sum values / fromIntegral (length values))

outcome :: Double -> String
outcome mark
  | mark >= 75 = "Distinction"
  | mark >= 50 = "Pass"
  | otherwise = "Fail"

summary :: Student -> String
summary (Student name values) =
  case average values of
    Nothing -> name ++ ": no marks"
    Just mark -> name ++ ": " ++ show mark ++ "% - " ++ outcome mark

classAverage :: [Student] -> Maybe Double
classAverage students =
  average [mark | Student _ values <- students, Just mark <- [average values]]
```

## 2. Missing data and a safe mean

A safe mean has no answer for an empty finite list. For a non-empty list, divide the sum by the count converted to Double. Safety here covers missing data; it does not promise validation, absence of overflow, or termination on infinite lists.

**Template:** `average [] = Nothing`; `average xs = Just (total / count)`, with total and count taken over exactly the same values. Keep absence visible until the caller chooses a policy.

## 4. Class denominator and complete datasets

Test1 gives each student with marks one vote: calculate student means, skip absent ones, then average the successful payloads. Pooling instead gives each mark one vote. Neither is automatically correct; the specification must choose. Unequal student mark counts can separate the results.

**Template:** equal-student policy is `average [mean | student <- students, Just mean <- [studentMean student]]`. Pooled policy is `average [mark | student <- students, mark <- studentMarks student]`.

In the exact constructor-pattern comprehension, `Student _ values` extracts each marks list. `[average values]` is a singleton list containing a Maybe. `Just mark` keeps a successful payload or skips that candidate when it is Nothing. This derives the missing-data path from the comprehension rules already taught; it does not validate marks.

An equivalent collector is `mapMaybe (average . marks) students` from Data.Maybe, followed by average. Explicit recursion can also skip Nothing and cons each Just payload. Neither rewrite should turn absence into zero.

## 5. Explicit weighting

This extension takes pairs of mark and weight. Marks lie in 0 through 100 and weights in 0 through 1; the bounded tests also reject non-finite inputs. Weights are relative shares and need not sum to one: divide by their positive total to normalise. Zero weights are allowed; an all-zero total has no mean. If marks and weights arrive as separate lists, check equal lengths before zip so nothing is silently discarded.

**Template:** validate pairs → total weight → weighted sum divided by positive total. This policy differs from the unweighted mean.

### Variation: equal weights

<HaskellTryIt>

```haskell
weightedAverage :: [(Double,Double)] -> Maybe Double
weightedAverage pairs
  | null pairs = Nothing
  | not (all (\(m,w) -> m >= 0 && m <= 100 && w >= 0 && w <= 1) pairs) = Nothing
  | total <= 0 = Nothing
  | otherwise = Just (sum [m*w | (m,w) <- pairs] / total)
  where
    total = sum [w | (_,w) <- pairs]

main :: IO ()
main = print (weightedAverage [(40,1),(80,1)])
```

```text
Just 60.0
```

</HaskellTryIt>

Weighted total 120 divided by weight total 2 gives 60.

## 6. Validation and error reports

The original core rejects neither invalid percentages nor duplicate labels. Add a boundary that rejects the whole class on its first invalid row. Within a row the priority is empty name, duplicate name, invalid mark. Empty marks are reportable absence, not invalid data. Names are compared exactly and case-sensitively; whitespace-only names are accepted by this minimal policy. A stronger identity policy would use separate student identifiers.

**Template:** raw class → Either reason checked class → Left error text or Right normal report. Preserve accepted rows and their order. Filtering invalid marks changes the mean without authorisation. A sibling “collect every reason” policy needs a separate list-of-errors collector; this first-error chain does not accumulate errors.

### Variation: inclusive endpoints

<HaskellTryIt>

```haskell
data Student = Student
  { studentName :: String
  , marks :: [Double]
  } deriving (Eq, Show)

average :: [Double] -> Maybe Double
average [] = Nothing
average values = Just (sum values / fromIntegral (length values))

outcome :: Double -> String
outcome mark
  | mark >= 75 = "Distinction"
  | mark >= 50 = "Pass"
  | otherwise = "Fail"

summary :: Student -> String
summary (Student name values) =
  case average values of
    Nothing -> name ++ ": no marks"
    Just mark -> name ++ ": " ++ show mark ++ "% - " ++ outcome mark

classAverage :: [Student] -> Maybe Double
classAverage students =
  average [mark | Student _ values <- students, Just mark <- [average values]]

validMark :: Double -> Bool
validMark m = m >= 0 && m <= 100

validateClass :: [Student] -> Either String [Student]
validateClass = go []
  where
    go _ [] = Right []
    go seen (s@(Student name values):rest)
      | null name = Left "empty name"
      | name `elem` seen = Left ("duplicate name: " ++ name)
      | not (all validMark values) = Left ("invalid marks: " ++ name)
      | otherwise = case go (name:seen) rest of
          Left reason -> Left reason
          Right checked -> Right (s:checked)

reportClass :: [Student] -> String
reportClass students = case validateClass students of
  Left reason -> "ERROR: " ++ reason
  Right checked -> "Class average: " ++ show (classAverage checked)

main :: IO ()
main = putStrLn (reportClass [Student "A" [0,100]])
```

```text
Class average: Just 50.0
```

</HaskellTryIt>

Both endpoints pass. The unchanged row has mean 50.

## 8. Test oracles

An oracle is an independent rule for deciding whether an actual result is right. Use exact equality for constructors, discrete outcomes and report text. Use a stated tolerance for computed Doubles, checking presence separately. Use Boolean properties for relationships across selected inputs. Finite property checks are evidence; [Proofs of Programs I](/docs/sem3/csi243/10-reasoning-revision/notes/proofs-of-programs-i) explains universal arguments.

**Template:** label + independently calculated expected + actual → IO Bool. An approximate oracle checks `abs (expected - actual) < epsilon`. Test1 fixes epsilon at 0.000001, strictly excluding the tolerance endpoint. This absolute tolerance fits small percentage calculations; it is not appropriate at every numerical scale. The helper rejects NaN and infinities and is intended for finite values.

## 9. The supplied harness and suite runner

**Suite template:** construct labelled `IO Bool` assertions, execute them with `sequence`, count the returned results, then choose `pure ()` or `exitFailure`. The action list, its execution and the final process status are three different stages.

Keep TestSupport.hs in the parent Test1 directory and the grade-book files in a child exercise folder. The following supplied-style implementation reports failures as values.

Assertions have type IO Bool: constructing a list of them does not run them. The runner uses sequence to execute every listed action in order, then inspects the Boolean results. An ordinary False does not suppress later assertions; an uncaught exception may abort the run.

**TestSupport.hs**

```haskell
module TestSupport (assertEqual, assertTrue, assertApprox, runTests) where
import System.Exit (exitFailure)

assertEqual :: (Eq a, Show a) => String -> a -> a -> IO Bool
assertEqual label expected actual = do
  let passed = expected == actual
  putStrLn (status passed ++ " " ++ label)
  if passed
    then pure True
    else do
      putStrLn ("    expected: " ++ show expected)
      putStrLn ("    actual:   " ++ show actual)
      pure False
  where
    status True = "PASS"
    status False = "FAIL"

assertTrue :: String -> Bool -> IO Bool
assertTrue label = assertEqual label True

assertApprox :: String -> Double -> Double -> IO Bool
assertApprox label expected actual =
  assertTrue label (abs (expected - actual) < 0.000001)

runTests :: [IO Bool] -> IO ()
runTests tests = do
  results <- sequence tests
  let passed = length (filter id results)
      total = length results
  putStrLn (show passed ++ "/" ++ show total ++ " tests passed")
  if and results then pure () else exitFailure
```

`pure ()` succeeds without a useful result; it is not an early exit command. `exitFailure` terminates with a failure exit status for an outer runner. An empty suite would print `0/0 tests passed` and succeed because `and []` is True; that offers no coverage evidence.

<CheckQuestion question="Can a non-empty class have no mean?">

Yes: every student may have no marks.

</CheckQuestion>

<CheckQuestion question="When can pooled and equal-student means differ?">

When students have unequal mark counts: [100] and [0,0,0] give 25.0 pooled and 50.0 equal-student.

</CheckQuestion>

<CheckQuestion question="Does the constructor validate percentages?">

No. A boundary validator must enforce the range and identity policies.

</CheckQuestion>

<CheckQuestion question="Why test presence before comparing approximately?">

A default can make absence look like a valid zero.

</CheckQuestion>

<CheckQuestion question="Does an ordinary failed assertion stop sequence?">

No. It returns False; the runner chooses an exit status after executing the listed assertions.

</CheckQuestion>
