---
title: "Files, Streams, and Tested Programs"
description: "Reading text files, handling exceptions, choosing tests by equivalence class, and the habits of a reliable lab submission."
---

File input and output lets a program work with data beyond a single console session, but file access is failure-prone: paths can be wrong, files can be missing and contents can be malformed. This topic covers reading a text file, handling exceptions sensibly, planning tests and the qualities of a good lab submission. Handling failure and showing that the program meets its specification are what turn working code into a reliable program.

<LearningObjectives items={[
  "Read a text file with try-with-resources, and make the path explicit about the program's working directory.",
  "Explain what an exception represents, and catch only those you can handle meaningfully, never with an empty catch block.",
  "Validate input at the boundary so that the rest of the program can rely on its assumptions.",
  "Design tests by equivalence class (normal, smallest and largest, empty or zero, malformed or missing, repeated values), recording input, expected output, actual output and diagnosis.",
  "Explain what a regression test is for.",
  "Structure a submission with meaningful names, small methods, named constants and tests that demonstrate the specification.",
]} />
