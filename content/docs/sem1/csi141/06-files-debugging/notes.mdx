## Files, Streams, and Tested Programs

File input/output lets a program work with data beyond one console session. Treat file access as a failure-prone boundary: paths can be wrong, files can be missing, and contents can be malformed.

## Reading a text file

```java
try (Scanner in = new Scanner(Path.of("scores.txt"))) {
    while (in.hasNextInt()) {
        int score = in.nextInt();
        // process score
    }
} catch (IOException ex) {
    System.err.println("Could not read scores.txt");
}
```

The try-with-resources statement closes the scanner automatically. The path should be explicit about the program's working directory, especially in an IDE.

Try it: the browser runner cannot open `scores.txt`, so the array stands in for what the file holds and the loop does the same processing. Add a score, then change the array to `{}` (an empty file) and predict what the program reports.

<JavaTryIt>

```java
public class Main {
    public static void main(String[] args) {
        // Stands in for the numbers in scores.txt.
        int[] fileContents = {72, 65, 90, 58};
        int total = 0;
        int count = 0;
        for (int score : fileContents) {
            total += score;
            count++;
        }
        System.out.println("Read " + count + " scores");
        System.out.println("Total: " + total);
    }
}
```

```text
Read 4 scores
Total: 285
```

</JavaTryIt>

## Exceptions

An exception represents an abnormal condition. Catch only exceptions that you can handle meaningfully; do not hide errors with an empty `catch` block. Validate input at the boundary so the rest of the program can rely on its assumptions.

Try it: the method rejects a mark outside 0 to 100 by throwing an exception, and `main` catches it and reports it. Add a negative mark to the array and predict the message, then call `checkedMark(-5);` on its own line before the loop and read what the runner says about an uncaught exception.

<JavaTryIt>

```java
public class Main {
    static int checkedMark(int mark) {
        if (mark < 0 || mark > 100) {
            throw new IllegalArgumentException("mark must be 0 to 100, not " + mark);
        }
        return mark;
    }

    public static void main(String[] args) {
        int[] marks = {72, 105, 40};
        for (int mark : marks) {
            try {
                System.out.println("Accepted: " + checkedMark(mark));
            } catch (IllegalArgumentException ex) {
                System.out.println("Rejected: " + ex.getMessage());
            }
        }
    }
}
```

```text
Accepted: 72
Rejected: mark must be 0 to 100, not 105
Accepted: 40
```

</JavaTryIt>

## Testing strategy

Test equivalence classes rather than a random handful of values:

- a normal valid input;
- the smallest and largest valid inputs;
- an empty input or zero;
- malformed or missing input;
- repeated values and duplicate records.

For each test, record the input, expected output, actual output, and diagnosis. A regression test prevents a fixed bug from returning later.

Try it: every test passes. Change `>= 50` to `> 50` in `grade` and run it again to see which test catches the bug, then add a test of your own.

<JavaTryIt>

```java
public class Main {
    static String grade(int mark) {
        if (mark >= 50) return "pass";
        if (mark >= 40) return "supplementary";
        return "fail";
    }

    static void check(int mark, String expected) {
        String actual = grade(mark);
        if (actual.equals(expected)) {
            System.out.println(mark + ": ok");
        } else {
            System.out.println(mark + ": expected " + expected + ", got " + actual);
        }
    }

    public static void main(String[] args) {
        check(75, "pass");
        check(50, "pass");
        check(40, "supplementary");
        check(39, "fail");
        check(0, "fail");
    }
}
```

```text
75: ok
50: ok
40: ok
39: ok
0: ok
```

</JavaTryIt>

## Lab-quality programs

A good submission has meaningful names, small methods, clear output, no unexplained magic numbers, and tests that demonstrate the specification. Follow the course collaboration and submission rules; learning to explain your own code is part of the assessment.

Try it: `final` means the value cannot change, and `PASS_MARK` gives the number a name. Change it to 65 in that one place and predict both lines.

<JavaTryIt>

```java
public class Main {
    static final int PASS_MARK = 50;

    static boolean hasPassed(int mark) {
        return mark >= PASS_MARK;
    }

    static void printReport(String name, int mark) {
        if (hasPassed(mark)) {
            System.out.println(name + " passed with " + mark);
        } else {
            System.out.println(name + " did not pass (" + mark + ")");
        }
    }

    public static void main(String[] args) {
        printReport("Thandi", 64);
        printReport("Sipho", 38);
    }
}
```

```text
Thandi passed with 64
Sipho did not pass (38)
```

</JavaTryIt>

## Common mistakes

- Assuming a relative path points to the source folder.
- Catching an exception and continuing with invalid state.
- Testing only a successful file and not the missing-file case.
- Mixing file parsing, business logic, and presentation in one large method.
