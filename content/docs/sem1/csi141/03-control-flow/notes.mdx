## Control Flow and Debugging

Control flow determines which statements execute and how often. A reliable program makes each decision and stopping condition visible.

## Conditions

Comparison operators produce booleans: `<`, `<=`, `>`, `>=`, `==`, and `!=`. Combine them with `&&` for “and,” `||` for “or,” and `!` for negation. Use parentheses when a condition has more than one operator.

```java
if (mark >= 50) {
    result = "pass";
} else if (mark >= 40) {
    result = "supplementary";
} else {
    result = "fail";
}
```

The branches are tested from top to bottom; the first true branch runs.

Try it: change `mark` to 50, then to 39, and predict the result each time. Then swap the first two conditions and find a mark that now gets the wrong answer.

<JavaTryIt>

```java
public class Main {
    public static void main(String[] args) {
        int mark = 45;
        int attendance = 75;
        String result;
        if (mark >= 50) {
            result = "pass";
        } else if (mark >= 40) {
            result = "supplementary";
        } else {
            result = "fail";
        }
        System.out.println(mark + " -> " + result);
        boolean mayWrite = mark >= 40 && attendance >= 80;
        System.out.println("May write the exam: " + mayWrite);
    }
}
```

```text
45 -> supplementary
May write the exam: false
```

</JavaTryIt>

## Loops

Use `while` when the number of repetitions is not known in advance, `for` for counter-controlled repetition, and `do-while` when the body must run at least once.

Every loop needs an initial state, a condition, and an update that moves toward termination. A useful invariant is a statement that remains true after every iteration.

<StepByStep>
  <StepByStepTitle>Designing a safe sum loop</StepByStepTitle>
  <Step number={1}>
    <StepTitle>Initialise</StepTitle>
    Set `sum = 0` before reading values. The invariant is that `sum` equals the total of values already processed.
  </Step>
  <Step number={2}>
    <StepTitle>Process</StepTitle>
    Add the current value, then advance the counter or read the next value.
  </Step>
  <Step number={3}>
    <StepTitle>Stop</StepTitle>
    Exit when the count reaches the limit or when a sentinel is read. The invariant then describes the required result.
  </Step>
</StepByStep>

Try it: after each line, check that `sum` equals the total of the values processed so far. Change the limit `5` to `0`, then to `10`, and predict the last line each time.

<JavaTryIt>

```java
public class Main {
    public static void main(String[] args) {
        int sum = 0;
        for (int i = 1; i <= 5; i++) {
            sum = sum + i;
            System.out.println("i = " + i + ", sum = " + sum);
        }
        System.out.println("Total: " + sum);
    }
}
```

```text
i = 1, sum = 1
i = 2, sum = 3
i = 3, sum = 6
i = 4, sum = 10
i = 5, sum = 15
Total: 15
```

</JavaTryIt>

## `switch` and input validation

`switch` is useful for discrete choices. Include `break` where fall-through is not intended and provide a `default` branch. A validation loop should reject bad input before the value is used.

Try it: change `day` to 9 and predict which branch runs. Then set `day` to 1, delete the first `break`, and predict what is printed before you run it.

<JavaTryIt>

```java
public class Main {
    public static void main(String[] args) {
        int day = 3;
        String name;
        switch (day) {
            case 1:
                name = "Monday";
                break;
            case 2:
                name = "Tuesday";
                break;
            case 3:
                name = "Wednesday";
                break;
            default:
                name = "unknown";
        }
        System.out.println("Day " + day + " is " + name);
    }
}
```

```text
Day 3 is Wednesday
```

</JavaTryIt>

## Debugging

Separate syntax, runtime, and logic errors. Use a trace table for loops, inspect the first wrong variable value, and reduce the failing input until the cause is obvious.

Try it: this program should add the numbers 1 to 5 and print 15. Use the lines it prints to find the first step that goes wrong, fix the loop, and run it again.

<JavaTryIt>

```java
public class Main {
    public static void main(String[] args) {
        // Goal: add the numbers 1 to 5. Expected total: 15.
        int sum = 0;
        for (int i = 1; i < 5; i++) {
            sum = sum + i;
            System.out.println("after i = " + i + ": sum = " + sum);
        }
        System.out.println("Total: " + sum);
    }
}
```

```text
after i = 1: sum = 1
after i = 2: sum = 3
after i = 3: sum = 6
after i = 4: sum = 10
Total: 10
```

</JavaTryIt>

## Common mistakes

- Writing `=` instead of `==` in a condition.
- Creating an infinite loop by forgetting the update.
- Using `||` where both conditions are required.
- Testing only the happy path.
- Placing a broad condition before a more specific condition.
