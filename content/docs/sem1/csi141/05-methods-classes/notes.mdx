## Methods, Libraries, and Classes

Methods isolate a responsibility behind a name. A method signature gives its access modifier, return type, name, and parameter types.

```java
public static double average(int total, int count) {
    return (double) total / count;
}
```

The method contract should state the preconditions, postconditions, and side effects. A `void` method performs an action but does not return a value.

Try it: call `average` with other arguments and predict each result before you run it. Then remove the `(double)` cast and see how the answers change.

<JavaTryIt>

```java
public class Main {
    public static double average(int total, int count) {
        return (double) total / count;
    }

    public static void main(String[] args) {
        System.out.println("average(10, 4) = " + average(10, 4));
        System.out.println("average(9, 3) = " + average(9, 3));
        System.out.println("average(7, 2) = " + average(7, 2));
    }
}
```

```text
average(10, 4) = 2.5
average(9, 3) = 3.0
average(7, 2) = 3.5
```

</JavaTryIt>

## Parameters and scope

Java passes arguments by value. For primitives, the method receives a copy of the value. For references, the method receives a copy of the reference, so it can mutate the referenced object but cannot replace the caller's reference itself.

Try it: predict the two lines before you run the program. Then add the line `values = new int[] {0, 0, 0};` at the end of `addOneToFirst` and predict again.

<JavaTryIt>

```java
public class Main {
    static void addOne(int number) {
        number = number + 1;
    }

    static void addOneToFirst(int[] values) {
        values[0] = values[0] + 1;
    }

    public static void main(String[] args) {
        int x = 5;
        int[] data = {5, 6, 7};
        addOne(x);
        addOneToFirst(data);
        System.out.println("x = " + x);
        System.out.println("data[0] = " + data[0]);
    }
}
```

```text
x = 5
data[0] = 6
```

</JavaTryIt>

Local variables exist only inside their block. Avoid shadowing a field or parameter with a local variable of the same name unless the distinction is intentional and clear.

## Libraries

The standard library provides tested abstractions. Read API documentation for the method's parameters, return value, exceptions, and mutation behaviour instead of guessing from its name.

Try it: predict each line before you run the program. `toUpperCase()` is called twice, so find out which call changes what is printed and why.

<JavaTryIt>

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(Math.max(7, 12));
        System.out.println(Math.sqrt(49));
        System.out.println(Math.pow(2, 10));
        System.out.println(Math.abs(-3.5));
        String text = "java";
        text.toUpperCase();
        System.out.println(text);
        String loud = text.toUpperCase();
        System.out.println(loud);
    }
}
```

```text
12
7.0
1024.0
3.5
java
JAVA
```

</JavaTryIt>

## Classes and objects

A class defines a type. Fields represent state, constructors establish valid initial state, and methods provide behaviour.

```java
public class BankAccount {
    private double balance;

    public BankAccount(double openingBalance) {
        if (openingBalance < 0) throw new IllegalArgumentException();
        balance = openingBalance;
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException();
        balance += amount;
    }

    public double getBalance() { return balance; }
}
```

`private` protects the representation. Public methods enforce the class invariant and expose only the operations clients need.

Try it: this is the class above with `public` dropped from `class BankAccount`, because a file can hold only one public class. Each object keeps its own balance, so change the amounts and predict both lines. Then add `account.balance = 5000;` to `main` and read the compiler message about `private`.

<JavaTryIt>

```java
class BankAccount {
    private double balance;

    public BankAccount(double openingBalance) {
        if (openingBalance < 0) throw new IllegalArgumentException();
        balance = openingBalance;
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException();
        balance += amount;
    }

    public double getBalance() { return balance; }
}

public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount(100);
        BankAccount spare = new BankAccount(20);
        account.deposit(50);
        System.out.println("account: " + account.getBalance());
        System.out.println("spare: " + spare.getBalance());
    }
}
```

```text
account: 150.0
spare: 20.0
```

</JavaTryIt>

## Common mistakes

- Forgetting to return a value on every branch of a non-void method.
- Confusing a parameter with an argument.
- Mutating a shared object accidentally.
- Making every field public and losing control over valid state.
- Giving a class many unrelated responsibilities.
