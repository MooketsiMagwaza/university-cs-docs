---
title: "Exceptions, Recursion, and Testing"
description: "Handling exceptions with try, catch and finally, recursive methods and the call stack, and unit tests with systematic debugging."
---

An exception represents an unusual condition that interrupts normal control flow, and a recursive method solves a problem by calling itself on a smaller one. This topic covers handling exceptions responsibly, writing recursive methods with a base case and a step toward it, and testing and debugging from the smallest failing case. Together these support programs that fail clearly instead of silently.

<LearningObjectives items={[
  "Use try, catch and finally, catching the narrowest useful exception type and never merely to hide a failure.",
  "Distinguish checked from unchecked exceptions, and use try-with-resources for files and other resources.",
  "Write a recursive method with a base case and a recursive case that moves toward it, and trace its call stack.",
  "Explain how missing progress or very deep recursion leads to non-termination or an exhausted stack.",
  "Write unit tests for normal, boundary, empty, invalid and error-path cases.",
  "Debug by reducing a failing input to the smallest case and fixing the first incorrect state instead of the symptom.",
]} />
