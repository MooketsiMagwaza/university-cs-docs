## Classes and Objects

A class defines a type: fields represent state and methods represent behaviour. An object is an instance created from that class. A reference variable stores a way to reach the object, not the object’s complete value.

Try it: `first` and `second` are two objects of one class, and each keeps its own `count`. Predict both lines, run the program, then add a third object and a call to `increment` on it.

<JavaTryIt>

```java
class Counter {
    private int count;

    public void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}

public class Main {
    public static void main(String[] args) {
        Counter first = new Counter();
        Counter second = new Counter();
        first.increment();
        first.increment();
        second.increment();
        System.out.println("first: " + first.getCount());
        System.out.println("second: " + second.getCount());
    }
}
```

```text
first: 2
second: 1
```

</JavaTryIt>

## Encapsulation

Keep fields private and expose controlled operations. A setter should preserve the class invariant rather than blindly accepting every value. For a bank account, a balance should not become negative if the contract disallows overdrafts; the class should reject or report an invalid withdrawal.

```java
public final class BankAccount {
    private double balance;

    public BankAccount(double openingBalance) {
        if (openingBalance < 0) throw new IllegalArgumentException();
        balance = openingBalance;
    }

    public boolean withdraw(double amount) {
        if (amount < 0 || amount > balance) return false;
        balance -= amount;
        return true;
    }
}
```

Try it: this is the class above with `getBalance` added and `public` dropped from `final class BankAccount`, because a file can hold only one public class. Predict both lines, then change `withdraw(500)` to `withdraw(70)` and predict again.

<JavaTryIt>

```java
final class BankAccount {
    private double balance;

    public BankAccount(double openingBalance) {
        if (openingBalance < 0) throw new IllegalArgumentException();
        balance = openingBalance;
    }

    public boolean withdraw(double amount) {
        if (amount < 0 || amount > balance) return false;
        balance -= amount;
        return true;
    }

    public double getBalance() { return balance; }
}

public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount(100);
        System.out.println(account.withdraw(30) + ", balance " + account.getBalance());
        System.out.println(account.withdraw(500) + ", balance " + account.getBalance());
    }
}
```

```text
true, balance 70.0
false, balance 70.0
```

## Constructors and `this`

A constructor has the class name and no return type. It establishes a valid initial state. `this` refers to the current object and distinguishes a field from a parameter with the same name. If no constructor is declared, Java may provide a default no-argument constructor; once a constructor is declared, that automatic constructor is no longer supplied.

Try it: predict the output, then change `this.name = name;` to `name = name;` and run it again to see why `this` is needed. Last, add `new Student();` to `main` and read the compiler message.

<JavaTryIt>

```java
class Student {
    private String name;
    private int mark;

    public Student(String name, int mark) {
        this.name = name;
        this.mark = mark;
    }

    public String describe() {
        return name + " scored " + mark;
    }
}

public class Main {
    public static void main(String[] args) {
        Student s = new Student("Naledi", 82);
        System.out.println(s.describe());
    }
}
```

```text
Naledi scored 82
```

</JavaTryIt>

## Identity and equality

Two references can point to the same object. `==` checks reference identity for objects; `.equals()` should express logical equality when a class implements it appropriately. When overriding `equals`, also consider the `hashCode` contract before using objects in hash-based collections.

Try it: predict the three lines. Then delete the whole `equals` method and run it again to see what `a.equals(b)` gives when a class does not define logical equality.

<JavaTryIt>

```java
class Ticket {
    private int number;

    public Ticket(int number) {
        this.number = number;
    }

    @Override
    public boolean equals(Object other) {
        // instanceof checks the type of other before it is cast.
        if (!(other instanceof Ticket)) return false;
        return number == ((Ticket) other).number;
    }
}

public class Main {
    public static void main(String[] args) {
        Ticket a = new Ticket(7);
        Ticket b = new Ticket(7);
        Ticket c = a;
        System.out.println("a == b: " + (a == b));
        System.out.println("a == c: " + (a == c));
        System.out.println("a.equals(b): " + a.equals(b));
    }
}
```

```text
a == b: false
a == c: true
a.equals(b): true
```

</JavaTryIt>

## Class checklist

- What invariant must always hold?
- Which state should be private?
- Which operations are part of the public interface?
- What should happen for invalid input?
- Can each public method be tested independently?
