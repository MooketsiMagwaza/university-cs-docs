## Collections and Generics

Collections model groups of objects with different performance and ordering properties. Program to an interface when possible: declare a `List` when the client needs ordered elements, a `Set` when duplicates are not allowed, and a `Map` when values are looked up by keys.

| Type | Main property | Typical implementation |
| --- | --- | --- |
| `List<E>` | Ordered, indexed, duplicates allowed | `ArrayList<E>` |
| `Set<E>` | Unique elements | `HashSet<E>` |
| `Map<K,V>` | Key-value association | `HashMap<K,V>` |
| `Queue<E>` | First-in-first-out processing | `ArrayDeque<E>` |

Generics provide compile-time type safety: `List<String>` communicates that the list contains strings. Primitive types use wrapper classes such as `Integer`; Java can autobox between `int` and `Integer`, but be aware that unboxing `null` causes an exception.

Try it: predict the two sizes and the last line before you run the program. Then add another repeated word to `words` and see which size changes.

<JavaTryIt>

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

public class Main {
    public static void main(String[] args) {
        List<String> list = new ArrayList<>();
        Set<String> set = new HashSet<>();
        String[] words = {"red", "blue", "red", "green", "blue"};
        for (String word : words) {
            list.add(word);
            set.add(word);
        }
        System.out.println(list);
        System.out.println("list size " + list.size() + ", set size " + set.size());
        System.out.println(set.contains("red") + " " + set.contains("pink"));
    }
}
```

```text
[red, blue, red, green, blue]
list size 5, set size 3
true false
```

</JavaTryIt>

## Iteration

Use an enhanced `for` loop for read-only traversal. Use an `Iterator` when elements must be removed safely during traversal, or collect changes and apply them afterward. Modifying most collections structurally during an enhanced loop can cause a concurrent modification error.

Try it: predict the list left after the `Iterator` removes the even numbers. Then change the condition to remove the numbers greater than 5, and try an enhanced `for` loop that calls `numbers.remove(...)` and read the error it gives.

<JavaTryIt>

```java
import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> numbers = new ArrayList<>();
        for (int i = 1; i <= 8; i++) {
            numbers.add(i);
        }
        Iterator<Integer> it = numbers.iterator();
        while (it.hasNext()) {
            if (it.next() % 2 == 0) {
                it.remove();
            }
        }
        System.out.println(numbers);
    }
}
```

```text
[1, 3, 5, 7]
```

</JavaTryIt>

## Maps and keys

`map.put(key, value)` associates a value and `map.get(key)` retrieves it. Check `containsKey` when a missing key must be distinguished from a key mapped to `null`. Keys should have stable equality and hash behaviour while stored in a hash map.

Try it: predict all four lines. Then add `marks.put("Alan", null);` before the last two prints and predict which lines change.

<JavaTryIt>

```java
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> marks = new HashMap<>();
        marks.put("Ada", 82);
        marks.put("Grace", 91);
        marks.put("Ada", 88);
        System.out.println("Ada: " + marks.get("Ada"));
        System.out.println("size: " + marks.size());
        System.out.println("has Alan: " + marks.containsKey("Alan"));
        System.out.println("Alan: " + marks.get("Alan"));
    }
}
```

```text
Ada: 88
size: 2
has Alan: false
Alan: null
```

</JavaTryIt>

## Choosing well

Choose based on required operations, not habit. An `ArrayList` gives fast indexed access; a linked structure may help with specific insertion patterns; a hash set offers fast average membership but no sorted order. State whether ordering and duplicates matter in the method contract.

Try it: a `Queue` serves items in first-in-first-out order and keeps duplicates. Predict who is served after Thandi, then add `"Sipho"` a second time and change the order of the `add` calls.

<JavaTryIt>

```java
import java.util.ArrayDeque;
import java.util.Queue;

public class Main {
    public static void main(String[] args) {
        Queue<String> line = new ArrayDeque<>();
        line.add("Thandi");
        line.add("Sipho");
        line.add("Lerato");
        System.out.println("Serving " + line.poll());
        System.out.println("Next is " + line.peek());
        System.out.println("Waiting: " + line.size());
    }
}
```

```text
Serving Thandi
Next is Sipho
Waiting: 2
```

</JavaTryIt>
