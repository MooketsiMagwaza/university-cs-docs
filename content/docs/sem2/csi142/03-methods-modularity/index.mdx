---
title: "Methods and Modularity"
description: "Method declarations and contracts, pass-by-value, scope and overloading, modular design, and testing methods."
---

A method packages a responsibility behind a name, and a well-designed method has a clear contract, a single purpose and tests that state the result they expect. This topic covers declarations, parameters and return values, how Java passes arguments by value, scope and overloading, and how to split a program into cohesive pieces. The aim is code that callers can reuse and test.

<LearningObjectives items={[
  "Write a method declaration and its contract, stating the inputs, the result, the side effects and the assumptions.",
  "Prefer returning a result to printing it, so that callers can test and reuse it.",
  "Explain pass-by-value for primitives and for references, and predict which changes a caller will see.",
  "Use scope, this.field and overloading correctly, and explain why changing only the return type does not overload a method.",
  "Apply modular design: cohesive methods, validation at a clear boundary and no duplicated logic.",
  "Test a method with normal, boundary, empty and invalid cases, each stating the expected result.",
]} />
