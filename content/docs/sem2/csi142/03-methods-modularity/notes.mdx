## Methods and Modularity

A method packages a responsibility behind a name. A method declaration has an access modifier, return type, name, parameter list, and body. The signature is the method name plus parameter types; changing only the return type does not overload a method.

## Contracts

Write a method contract before its implementation: state the inputs, the returned result, side effects, and assumptions. A method that calculates a result should usually return it rather than printing it, because callers can test and reuse the value.

```java
static int countPositive(int[] values) {
    int count = 0;
    for (int value : values) {
        if (value > 0) count++;
    }
    return count;
}
```

Java passes arguments by value. For a primitive, the method receives a copy of the value. For an array or object, the copied value is a reference to the same object, so the method can mutate that object but cannot replace the caller’s reference by reassigning its parameter.

Try it: `reset` changes all three of its parameters. Predict which changes the caller can see, run the program, then remove the line `list[0] = 0;` and predict again.

<JavaTryIt>

```java
public class Main {
    static void reset(int number, int[] list) {
        number = 0;
        list[0] = 0;
        list = new int[] {9, 9, 9};
    }

    public static void main(String[] args) {
        int number = 5;
        int[] list = {5, 6, 7};
        reset(number, list);
        System.out.println(number);
        System.out.println(list[0] + " " + list[1] + " " + list[2]);
    }
}
```

```text
5
0 6 7
```

</JavaTryIt>

## Scope and overloading

Local variables exist only within their method or block. Parameters shadow fields or outer names only when the language scope allows it; use `this.field` to make a field reference explicit. Overloaded methods share a name but have distinct parameter lists, and Java chooses a compatible method at compile time.

Try it: predict which version of `add` each call uses, then run the program. Add a fourth method `static double add(int a, int b)` and read the compiler message, because only the return type differs.

<JavaTryIt>

```java
public class Main {
    static int add(int a, int b) {
        return a + b;
    }

    static double add(double a, double b) {
        return a + b;
    }

    static String add(String a, String b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(add(2, 3));
        System.out.println(add(2.5, 3));
        System.out.println(add("2", "3"));
    }
}
```

```text
5
5.5
23
```

</JavaTryIt>

## Modular design

Keep each method cohesive, minimise hidden state, validate inputs at a clear boundary, and avoid duplicating logic. Small methods are useful when their names express a meaningful operation, not when a program is split into arbitrary fragments.

Try it: `average` calculates and returns, and `report` decides how the result is shown. Add a third `report` call with your own numbers and check that `average` needs no change.

<JavaTryIt>

```java
public class Main {
    static double average(int[] values) {
        int total = 0;
        for (int value : values) {
            total += value;
        }
        return (double) total / values.length;
    }

    static void report(String label, int[] values) {
        System.out.println(label + " average: " + average(values));
    }

    public static void main(String[] args) {
        report("Test 1", new int[] {60, 70, 80});
        report("Test 2", new int[] {50, 55});
    }
}
```

```text
Test 1 average: 70.0
Test 2 average: 52.5
```

</JavaTryIt>

## Testing methods

Test normal, boundary, empty, and invalid cases. For `countPositive`, include all-positive, all-negative, zero, and an empty array if the contract permits it. A test should state the expected result, not merely exercise the method.

Try it: all four tests pass. Change `value > 0` to `value >= 0` in `countPositive` and run it again to see which test catches the mistake.

<JavaTryIt>

```java
public class Main {
    static int countPositive(int[] values) {
        int count = 0;
        for (int value : values) {
            if (value > 0) count++;
        }
        return count;
    }

    static void test(String name, int[] input, int expected) {
        int actual = countPositive(input);
        if (actual == expected) {
            System.out.println(name + ": pass");
        } else {
            System.out.println(name + ": FAIL, expected " + expected + " but got " + actual);
        }
    }

    public static void main(String[] args) {
        test("all positive", new int[] {1, 2, 3}, 3);
        test("all negative", new int[] {-1, -2}, 0);
        test("zero", new int[] {0}, 0);
        test("empty", new int[] {}, 0);
    }
}
```

```text
all positive: pass
all negative: pass
zero: pass
empty: pass
```

</JavaTryIt>
