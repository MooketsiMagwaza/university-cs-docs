## Try it yourself

This is real CPython compiled to WebAssembly, so the behaviour matches the Python you would install. The first run downloads the runtime (about 10 MB) and shows a loading message. After that it starts almost instantly.

<CodePlayground language="python" />

## Things to try

1. Run **Error to diagnose**. Read the traceback from the bottom up: the last line names the error, the line above it shows where it happened.
2. Open **Reading input**, type `Neo` on the first input line and `20` on the second, then run it.
3. In **Functions and recursion**, call `fib(500)`. Why is the memoised version instant while a plain recursive one would never finish?
4. In **Lists, dicts, sets**, change the sentence and predict the word counts before running.

## Ready-made datasets

Pick a **Dataset** to have variables defined for you before your code runs, so you can practise loops, dictionaries and comprehensions without typing the data first.

| Dataset | Defines |
|---|---|
| Class marks | `students`, a list of dictionaries with `name`, `programme` and a list of `marks` |
| Sample text | `text`, a short paragraph, and `words`, its lower-case words without punctuation |

The dataset's code is shown under the editor. Because it runs first in the same scope, a traceback from your own code still reports your own line numbers.

## How input() works

A browser has no terminal, so the playground feeds `input()` from the **Input** box under the editor, one line per call. If your program asks for more lines than you supplied, Python raises `EOFError`, which is the same thing that happens when a real program runs out of piped input.

## Limits

- Programs stop after 15 seconds (the first run after page load gets extra time for the download).
- The standard library is available. Packages that need the network, threads, or the file system are not.
- Each run uses fresh globals, so a function you defined in one run does not exist in the next.
