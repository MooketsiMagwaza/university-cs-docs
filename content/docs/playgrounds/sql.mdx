## Try it yourself

The database is rebuilt from your script every time you run it, so each example starts with its own `CREATE TABLE` and `INSERT` statements. Every `SELECT` shows its rows as a table. This is SQLite, so the dialect is close to standard SQL with a few differences noted below.

## Things to try

1. In **GROUP BY and aggregates**, change `HAVING COUNT(*) > 1` to `> 2`. Which groups disappear, and why does `HAVING` run after grouping while `WHERE` runs before?
2. In **JOIN two tables**, change `LEFT JOIN` to `INNER JOIN`. Which row vanishes?
3. Write a query that returns each course's best student by name.
4. Cause an error on purpose: select from a table that does not exist, or insert a value into a column that is not there.

## SQLite notes

- Column types are flexible. `TEXT`, `INTEGER` and `REAL` are the ones to know.
- `LIMIT` and `OFFSET` are supported. `TOP` is not.
- Only the result sets of `SELECT` statements are shown. Statements such as `UPDATE` run silently, so follow them with a `SELECT` to check the effect.
