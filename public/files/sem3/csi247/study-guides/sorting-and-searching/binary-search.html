1. Meet the array and the goal

An array stores values at zero-based indexes. A search key is the value you want; the answer is its position or a failure marker.

The last valid index is 9. Returning 18 would confuse a value with an index.

2. Definition and plain-language idea

Binary search is a comparison search that repeatedly halves a sorted candidate range.

On a correctly sorted array, compare at the midpoint and discard the impossible half until the key is found or the range is empty.

Precondition: ordering must match the comparison direction and searched field. Running this code on unsorted input can incorrectly report that a present key is absent.

5. Why the movement is valid

In ascending order, if arr[mid] is smaller than the key, every value to its left is also too small. Exclude the midpoint itself with low = mid + 1. The symmetric case uses high = mid - 1.

A one-cell range still needs a comparison, so use low <= high, not low < high.

6. Fully commented Java implementation

Build it from scratch

  • State the sorted-input precondition.
  • Initialize the inclusive range.
  • Repeat while a candidate remains.
  • Calculate the midpoint; test equality.
  • Exclude mid and the impossible side.
  • Return -1 after the range becomes empty.

7. Recursive form and the call stack

Initial call: binarySearchRec(arr, key, 0, arr.length - 1). Depth is O(log n) because each child retains at most about half the range.

10. Variations: order, duplicates and reference values

For descending arrays, equality is unchanged. If key is larger than arr[mid], search LEFT by reducing high; otherwise search RIGHT by increasing low.

A standard binary search returns whichever equal midpoint it encounters first. To find the first duplicate, record the match and continue left instead of returning immediately.

Best timeO(1)First midpoint is a match.

Extra spaceO(1) iterative; O(log n) recursiveBounds versus suspended frames.
Input orderRequiredDiscard decisions depend on order.
DuplicatesAny matching midpointNo first/last guarantee.
Input mutated?NoOnly bounds change.

A successful or unsuccessful midpoint visit is counted as one probe in these tables. The exact Java code can evaluate equality and then a direction comparison on a failed probe; do not call probe count the exact number of all Boolean expressions.

12. When to choose this method

Choose binary search for repeated lookups on data already sorted by the relevant key. Sorting solely for one lookup may cost more than a linear scan. Binary search also relies on efficient random access; a linked list does not provide array-like midpoint access.

14. Exam-style practice with explanations

A. Trace key 31 on the main input. Show every index/bound and the failure result. [6]

Every retained candidate is eliminated; return -1. Four midpoint probes are required.

B. Explain the best and worst time using input examples. [4]

Best: key equals the first midpoint, one probe. Worst: key absent or only located after the range repeatedly halves, logarithmic probes.

C. Debug the bounds and return statement. [4]

low and high are inclusive. Use low <= high, calculate the overflow-safe midpoint, and exclude mid using ±1. The not-found return belongs after the range empties.

D. Return the first occurrence of a duplicate. What must change? [3]

Keep a result variable. On equality record mid, set high = mid - 1, and continue. Return the recorded index after the loop.

E. Empty array: can this code access index 0? [2]

No. high is -1, so low <= high is false. It returns -1 without reading a cell.
