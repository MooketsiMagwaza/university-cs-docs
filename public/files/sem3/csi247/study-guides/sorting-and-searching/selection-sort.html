Start with the idea

Selection sort puts values in order by finding the smallest value still waiting and placing it in the next position on the left.

Think of choosing the smallest numbered card from a mixed row. Look through all the remaining cards before moving anything. Then swap that card with the card in the position you are filling. Leave completed positions alone.

A small example

Start with [4, 2, 1]. Look at all three values: 1 is smallest. Swap 1 and 4 to get [1, 2, 4]. Next, check the remaining [2, 4]. The 2 is already in the next position, so no swap is needed.

Sorting / Selection sort · The textbook definition

The textbook definition

Selection sort is a comparison-based sorting algorithm that divides the array into a sorted prefix on the left and an unsorted suffix on the right. In each iteration it scans the whole unsorted suffix to find the smallest value, then swaps that value into the first position of the suffix. The sorted prefix therefore grows by one cell per iteration, and every cell in it is already in its final place.

Sorted prefixThe cells 0 .. i − 1. They hold the smallest values, in order, and never change again.
Unsorted suffixThe cells i .. n − 1. The next minimum is somewhere in here.
Boundary iThe first cell of the unsorted suffix, which is the cell about to be filled.
ScanLooking at every cell of the suffix once, comparing it with the best candidate so far.
minIndexThe position of the smallest value found so far. We remember where it is, not just what it is.
SwapExchanging array[i] with array[minIndex]. There is at most one per iteration.

The name says what it does: each iteration selects the right value for the next position, rather than shuffling values into place as bubble and insertion sort do.

Sorting / Selection sort · In plain language

In plain language

Keep choosing the smallest card from the pile that is left, and lay it down next in the row.

Imagine a pile of numbered cards on a table. Look through all of them and pull out the smallest; put it at the left end of your row. Now look through the cards that are left, pull out the smallest of those, and put it next in the row. Keep going until the pile is empty. Your row is sorted.

In an array there is no separate table: the “pile” is the part of the array to the right of the boundary, and “putting it in the row” means swapping the chosen value into the boundary cell. Whatever was sitting in that cell goes to the place the chosen value came from.

Sorting / Selection sort · The main idea

The main idea

Selection sort splits the array in two with a movable boundary. Everything left of the boundary is finished; everything right of it is untouched. The whole algorithm is: find the smallest value on the right, put it at the boundary, move the boundary one cell right.

One scan for the minimum

Here is the scan for i = 0. We start by assuming index 0 holds the minimum, then look at every other cell. Whenever we meet something smaller we move our “minimum so far” marker to it. Only when the scan ends do we know the true minimum and swap once.

The prefix is final, not just sorted

This is the biggest difference from insertion sort. In insertion sort the left part is sorted among itself but later values may still be inserted in the middle. In selection sort the left part holds the globally smallest values, so a finished cell is never touched again.

The cost of choosing

Finding the minimum means looking at every cell of the suffix, every time, even if the array was sorted to begin with. The algorithm has no way to know the minimum is already in place until it has checked. That is what you pay for the very small number of swaps.

The repeating recipe: set minIndex = i → scan i + 1 .. n − 1, updating minIndex whenever a smaller value appears → swap array[i] with array[minIndex] → move i right.
Sorting / Selection sort · Scan, select, swap

Scan, select, swap

Selection sort separates finding from moving. Seeing them as two phases makes the code and the trace easy to follow.

ComparisonA question inside the scan: array[j] < array[minIndex]. Every iteration makes n − 1 − i of them, regardless of the data.
SelectionDeciding which cell holds the minimum. Nothing in the array moves during this phase.
SwapThe only movement: one exchange per iteration at most, and none if the minimum is already at i.
IterationOne value of i: a full scan plus (maybe) one swap.

Why remember the index, not the value?

Knowing that the smallest value is 1 is not enough: to swap we must know where the 1 is. That is why the code keeps minIndex. A common slip is to store min = array[j] and then be unable to find its position.

One swap can move a value a long way

Bubble sort moves values one neighbour at a time. Selection sort's swap jumps: in iteration 0 the 4 and the 1 trade places across three cells. That long jump is what keeps the swap count tiny, but it also has a price, which you will meet in the section on stability: jumping over equal values can reorder them.

Implementation

Selection sort
public static void selectionSort(int[] arr) {
    // i is the next position to fill in the sorted prefix.
    for (int i = 0; i < arr.length - 1; i++) {
        int minIndex = i;
        // Search the unsorted suffix for its smallest value.
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIndex]) minIndex = j;
        }
        // Place the selected minimum at i; avoid a self-swap.
        if (minIndex != i) {
            int temp = arr[i];
            arr[i] = arr[minIndex];
            arr[minIndex] = temp;
        }
    }
}

Why selection sort is not stable

The swap moves a value across everything between the two positions, which can jump it over an equal value. Label two equal 2s as 2ᵃ and 2ᵇ and sort [2ᵃ, 2ᵇ, 1]: the minimum 1 is swapped with 2ᵃ.

Before

After the swap at i = 0

2ᵇ now sits before 2ᵃ, so the equal values changed relative order. Insertion sort avoids this because it never moves a value past an equal one. Merge sort avoids it because, on a tie, the merge takes the left value first (<=).

Questions

Why might selection sort be chosen over bubble sort?
Selection sort makes at most one swap per outer iteration, so it can be useful when writes or swaps are expensive.
Why is it not adaptive?
It scans the entire remaining unsorted section to find the minimum even when the array is already sorted.

Not stable

The long-distance swap can jump a value over an equal one. In [2ᵃ, 2ᵇ, 1] the first swap moves 2ᵃ behind 2ᵇ, and nothing later repairs it. A stable version exists (shift instead of swap), but that is a different algorithm.

In-place

Not adaptive

The scan always examines the whole suffix, so sorted input costs exactly the same n(n − 1) / 2 comparisons as random input.

Fewest swaps

At most one swap per iteration, so at most n − 1 swaps in total, the smallest of the simple sorts. Bubble sort can need up to n(n − 1) / 2.

Comparison-based

Every decision comes from comparing two values.

Sorting / Selection sort · When to use it

When to use it

A good choiceSmall arrays; situations where writing is much more expensive than reading (flash memory, very large records, writing to a file); when you need a predictable, data-independent running time; and when simplicity matters more than speed.
A poor choiceLarge arrays (O(n²) comparisons); data that is already or nearly sorted (it cannot take advantage); anywhere stability is needed, for example sorting records by one field while keeping an earlier order for ties.

Compared with its relatives: insertion sort beats it on nearly sorted data and is stable; bubble sort makes many more swaps; merge sort is far faster on large arrays. Selection sort is a good answer to “which simple sort minimises swaps?”, and almost nothing else.

Sorting · Why sort data at all?

Why sort data at all?

Before the algorithms: what does sorted data give you that unsorted data does not, and what does it cost?

Everything in this chapter is about putting values in order. Before learning how, it is worth being clear about why, because it is a favourite exam question and because it explains why searching and sorting are taught together.

Short answer for a test: sorting data makes it easier and faster to find information in it. A sorted array can be searched with binary search, in O(log n) instead of O(n).

Duplicates end up side by side

Finding repeated values in [3, 1, 3, 2, 3] means comparing every pair. After sorting, [1, 2, 3, 3, 3], equal values are neighbours, so one pass comparing each cell with the next finds them all.

Sorting is not free: is it worth it?

Sorting costs about n log₂ n steps, and it only pays off if you search more than a few times. Suppose you have 1,000,000 values and will search for 1,000 different keys:

StrategyWorkTotal
Never sort: linear search every time1,000 searches × up to 1,000,000 comparisons1,000,000,000
Sort once, then binary search every timesort ≈ 20,000,000 steps, then 1,000 searches × 20 probes20,020,000

That is about 49× less work after sorting. With a single search the answer flips: scanning once costs 1,000,000 and sorting first costs 20,000,000. The rule: search once, scan; search often, sort first.

Quick check: Exam-style question 3(a), “What is the purpose of sorting data?”
To arrange data in a defined order (ascending or descending) so that information is easier and faster to find, for example by using binary search instead of scanning every element. Other valid points: duplicates become adjacent, minimum and maximum are at the ends, and sorted data is easier to read and merge.

Count the disorder: inversions

An inversion is a pair of positions whose values are in the wrong order: a larger value sits to the left of a smaller one. [4, 2, 5, 1, 3] has six: (4,2), (4,1), (4,3), (2,1), (5,1), (5,3).

AlgorithmWhat is countedOn [4, 2, 5, 1, 3]Link to inversions
Bubbleadjacent swaps6Each swap of neighbours removes exactly one inversion.
Insertionshifts6Each shift removes exactly one inversion.
Selectionswaps2At most n − 1 swaps; one swap can remove several inversions at once.

A fully reversed array of n values has n(n − 1) / 2 inversions. For [5, 4, 3, 2, 1] that is 10, which equals the 10 shifts in the reverse-order insertion example. This is the reason bubble and insertion sort are O(n²) in the worst case.

Sorting / Selection sort · Descending order

Descending order

To sort largest to smallest, select the largest value of the suffix instead of the smallest. Only the comparison changes, and the variable is best renamed so the code still reads honestly.

Ascending: pick the minimum
if (arr[j] < arr[minIndex]) {
    minIndex = j;
}
Descending: pick the maximum
if (arr[j] > arr[maxIndex]) {
    maxIndex = j;

Sorting / Selection sort · Common mistakes

Common mistakes

1
Storing the minimum value instead of its index.
To swap you need the position. Keep minIndex.
2
Starting the scan at i instead of i + 1.
It still works, because a value compared with itself is never smaller, but it wastes one comparison per iteration and changes your counts.
3
Swapping inside the scan.
Swap after the scan finishes, once you know the true minimum. Swapping every time you find a smaller value turns it into a different (and slower) algorithm.
4
Forgetting that the minimum may already be at i.
Then minIndex == i and no swap is needed. Counting a swap here gives a wrong total.
5
Running the outer loop to n instead of n − 1.
When only one cell is left it is automatically correct, so the last iteration is wasted.
6
Expecting it to stop early on sorted data.
It cannot. All n(n − 1) / 2 comparisons are made whatever the input looks like.
7
Calling it stable.
It is not: the long-distance swap can reorder equal values.
8
Using the wrong comparison for descending order.
Select the maximum (>); do not run the ascending sort and reverse the answer unless the question asks for it.
Sorting / Selection sort · A test-ready summary

A test-ready summary

Selection sort is an in-place, comparison-based sorting algorithm that is not stable and not adaptive. It splits the array into a sorted prefix and an unsorted suffix. In each iteration it scans the whole suffix to find the smallest value, remembers its index, and swaps it into the first position of the suffix, so the prefix grows by one final cell. It makes exactly n(n − 1) / 2 comparisons whatever the input, but at most n − 1 swaps. Its best, average and worst cases are all O(n²) with O(1) extra space. It is useful for small arrays and when swaps are expensive, but not for large data.

B. Explain stability with tagged equal keys. [4]

Swap 1 with 2a in [2a, 2b, 1]: result [1, 2b, 2a]. The equal records crossed, so the taught version is not stable.

C. Give the time and space, then justify both. [5]

Best / average / worst: O(n²). Every suffix is fully scanned, even on sorted input. Key comparisons: n(n - 1)/2. Lengths n - 1, n - 2, ... , 1. Swaps: At most n - 1. At most one actual exchange per pass; self-swaps are skipped. Auxiliary space: O(1) iterative; O(n) recursive. Only index variables and a temporary value in the iterative form. Stable / in place / adaptive: No / yes / no. A long swap can cross equal records; scanning does not shrink with presortedness.
