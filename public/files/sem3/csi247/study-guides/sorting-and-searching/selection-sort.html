1. The array we will sort

Arrays use zero-based positions. Sorting changes which values occupy those positions. The target is ascending order; record tags would move with their values.

We will distinguish comparisons, swaps, shifts, temporary writes and copy-back writes. They are different units.

2. Definition and plain language

Selection sort partitions an array into a sorted prefix and unsorted suffix. Each pass selects the smallest suffix value and exchanges it with the first suffix position.

Find the smallest remaining card before you move anything. Put it in the next empty final position. Repeat with the cards still waiting.

The scan proves which value belongs at index i; one swap puts it there. A new smaller candidate updates an index during the scan rather than causing an immediate swap.

3. Vocabulary and the central invariant

TermMeaning in this chapter
iThe final position being filled.
minIndex of the best candidate seen so far, not the candidate value.
jIndex currently being scanned.
Sorted prefixPositions 0..i-1 already contain the smallest i values.
SelectionFinding a minimum before one final swap.

Invariant: Before pass i, positions 0..i-1 contain the i smallest values in final order. During the scan, min names the smallest value seen from i through j.

10. Descending order: change the decision

Select the maximum instead: change arr[j] < arr[min] to arr[j] > arr[min]. The prefix then grows in descending order.

Keep the bounds and movement rules consistent. Reversing a final array is a different procedure and does not reproduce the descending trace of this implementation.

12. Properties and why the complexity occurs

PropertyResultReason
Best / average / worstO(n²)Every suffix is fully scanned, even on sorted input.
Key comparisonsn(n - 1)/2Lengths n - 1, n - 2, ... , 1.
SwapsAt most n - 1At most one actual exchange per pass; self-swaps are skipped.
Auxiliary spaceO(1) iterative; O(n) recursiveOnly index variables and a temporary value in the iterative form.
Stable / in place / adaptiveNo / yes / noA long swap can cross equal records; scanning does not shrink with presortedness.

For n=5, the full suffix scans make 4+3+2+1=10 key comparisons even on sorted input. Fewer swaps do not imply fewer comparisons.

13. When to choose it

Useful when swaps are more costly than comparisons and the input is small. It offers few swaps but still requires quadratic comparisons.

14. Common mistakes, symptoms and repairs

AttemptWhat goes wrongRepair
Set min = arr[i]Treats a value as an index.Set min = i, then compare arr[j] and arr[min].
Swap every new minimum immediatelyChanges the taught selection procedure and swap counts.Finish the full scan, then swap once.
Always swap min and iAdds redundant writes when they are the same.Skip the swap when min == i.
Call it stableLong-distance exchanges can cross equal values.Use a tagged duplicate counterexample.

B. Explain stability with tagged equal keys. [4]

Swap 1 with 2a in [2a, 2b, 1]: result [1, 2b, 2a]. The equal records crossed, so the taught version is not stable.

C. Give the time and space, then justify both. [5]

Best / average / worst: O(n²). Every suffix is fully scanned, even on sorted input. Key comparisons: n(n - 1)/2. Lengths n - 1, n - 2, ... , 1. Swaps: At most n - 1. Stable / in place / adaptive: No / yes / no. A long swap can cross equal records; scanning does not shrink with presortedness.
