1. Meet the array and the goal

An array stores values at zero-based indexes. A search key is the value you want; the answer is its position or a failure marker.

The last valid index is 9. Returning 18 would confuse a value with an index.

2. Definition and plain-language idea

Linear search, also called sequential search, compares each position with the key in order.

Check one position at a time and return the first matching index; report -1 only after every position has failed.

No sorted-order precondition. Equality provides no reason to skip distant positions.

5. Why the movement is valid

Before index i is checked, every position 0..i-1 has failed. After a failure, advance by exactly one position. On a match, the invariant proves this is the first match.

10. Variations: order, duplicates and reference values

To find the last occurrence, continue scanning and retain the latest matching index. To count matches, increment a counter instead of returning. Descending, ascending and unsorted arrays all use the same equality scan.

Objects need a field comparison or an appropriate equals method. Guard nullable references before invoking a method.

DuplicatesFirst matchImmediate return.
Input mutated?NoThe method only reads cells.

The tables count one primitive-key equality test per visited cell. Boundary/loop conditions are not included.

12. When to choose this method

Choose linear search for small, unsorted, or one-off searches. It avoids sorting cost and works with sequential access structures.

13. Common mistakes and repairs

MistakeConsequenceRepair
Use i <= arr.lengthReads one cell beyond the array.Use i < arr.length.
Return -1 inside the loop after first failureStops before later matches.Return failure after the loop.
Return arr[i]Returns a value rather than position.Return i.
Use == for String textCompares references.Use a null-safe equals test.

Every retained candidate is eliminated; return -1. Ten equality checks are required.

B. Explain the best and worst time using input examples. [4]

Best: key at index 0, one equality test. Worst: key last or absent, n equality tests.

C. Debug the bounds and return statement. [4]

i must stay below length; a failed equality test means continue, not return -1. Failure belongs after the loop.

D. Return the first occurrence of a duplicate. What must change? [3]

Nothing: the left-to-right immediate return already selects the first occurrence.

E. Empty array: can this code access index 0? [2]

No. i = 0 is not less than length = 0. It returns -1 without reading a cell.

15. Test-ready summary and mastery check

Check one position at a time and return the first matching index; report -1 only after every position has failed.

  • Return an index, or -1 after the full scan.
  • Keep every index in 0..length-1.
  • Know why unsorted input is acceptable.
  • Explain first-match behavior.
  • Use equals for reference text.
