Start with the idea

Insertion sort grows an ordered section on the left. Save the next value separately, move larger values one position right, then place the saved value in the space they leave.

The left section is already sorted, so moving backward past its larger values finds the right place for the key. Stop after a value that is no larger than the key, or at the start of the row. A shift copies one value right; a swap would exchange two values.

The textbook definition

Optional · expand to explore
Sorting / Insertion sort · Definition

The textbook definition

Insertion sort is a comparison-based sorting algorithm that builds a sorted section of an array one element at a time. During each iteration, it takes the next element from the unsorted section, shifts all larger elements in the sorted section one position to the right, and inserts the element into its correct position.

Comparison-basedThe order is decided by comparing one value with another.
Sorted sectionThe part already placed in the correct order.
Unsorted sectionThe part that has not yet been processed.
ShiftCopying a value one position to the right.
InsertPlacing the saved value in the gap made by the shifts.
IterationOne complete turn of the outer loop.

The main idea

The first element is treated as sorted. That is valid because one item on its own cannot be out of order.

The algorithm processes 2, then 5, then 1, then 3. After each iteration, the sorted section grows by one value.

Comparison, shift, insertion

Optional · expand to explore
Sorting / Insertion sort · Comparison, shift, insertion

Comparison, shift, insertion

These words describe different actions. Keeping them separate makes traces much easier to understand—and keeps test answers accurate.

ComparisonAsk a question such as 1 < 5.
ShiftCopy a larger value one position right.
InsertionPut the saved key into the gap.
SwapExchange two values. Standard insertion sort does not normally do this.

If 1 is the key in [2, 4, 5, 1, 3], then 5, 4, and 2 each shift right. Those are three shifts, not three swaps. The key is then inserted once.

The Java implementation

Optional · expand to explore
Sorting / Insertion sort · Java implementation

The Java implementation

InsertionSort.java
public static void insertionSort(int[] array) {
    // Index 0 is already a sorted prefix of length one.
    for (int i = 1; i < array.length; i++) {
        // Save the next unsorted value before shifts overwrite its cell.
        int key = array[i];
        int j = i - 1;

        // Shift every larger prefix value one position right.
        while (j >= 0 && key < array[j]) {
            array[j + 1] = array[j];
            j--;
        }

        // j stopped before the key's correct insertion position.
        array[j + 1] = key;
    }
}

What each variable means

arrayThe array being sorted.
iThe index of the next unsorted value.
keyA safe copy of the value being inserted.
jMoves backwards through the sorted section.

Why does i start at 1?

Index 0 already forms a one-value sorted section. The first value that needs inserting is therefore at index 1.

Why save the key?

Shifts can overwrite array[i]. Saving it in key prevents the original value from being lost.

Understanding the while condition

j >= 0 && key < array[j]

The algorithm may shift only when a valid position remains on the left and that value is larger than the key. The boundary check comes first so Java never attempts to access array[-1].

How the shift and insertion happen

array[j + 1] = array[j] copies a larger value one place right. When the loop ends, array[j + 1] = key fills the gap with the saved key.

Write it from scratch
  1. Start i at 1.
  2. Save key and set j = i - 1.
  3. Shift larger prefix values right.
  4. Insert at j + 1.
Ascending ↔ descending

Ascending shifts while key < array[j]. Descending shifts while key > array[j].

Debug checklist
  • Save the key before shifting.
  • Check j >= 0 first.
  • Insert at j + 1, not j.

The same algorithm, expressed recursively

The recursive idea is: first sort the first n - 1 values, then insert the final value into that sorted portion.

Base casen <= 1. Zero or one item is already sorted.
Smaller problemSort only the first n - 1 values.
Work after returnInsert array[n - 1] into the sorted prefix.
First callinsertionSortRec(array, array.length).

Approach 1 · recursive outer process

The recursion chooses how much of the array to sort. A loop still performs the insertion step.

Recursive sort + iterative insertion
public static void insertionSortRec(int[] array, int n) {
    // Base case: a prefix of length zero or one is sorted.
    if (n <= 1) return;

    // First sort the smaller prefix.
    insertionSortRec(array, n - 1);

    // Then insert the final value into that sorted prefix.
    int key = array[n - 1];
    int j = n - 2;
    while (j >= 0 && key < array[j]) {
        array[j + 1] = array[j];
        j--;
    }
    array[j + 1] = key;
}

Approach 2 · fully recursive shifting

This version also replaces the insertion loop with a recursive helper. It is useful for understanding recursion, although the first version is usually simpler to read.

Recursive sort + recursive insertion
public static void insertionSortFullyRec(int[] a, int n) {
    // Stop shrinking at a one-value prefix.
    if (n <= 1) return;
    insertionSortFullyRec(a, n - 1);
    // Recursively place the last value into the sorted prefix.
    insertRec(a, a[n - 1], n - 2);
}

private static void insertRec(int[] a, int key, int j) {
    // Stop at the left edge or after a value no larger than key.
    if (j < 0 || a[j] <= key) {
        a[j + 1] = key;
        return;
    }
    a[j + 1] = a[j];
    insertRec(a, key, j - 1);
}

The final return inserts 3 into the sorted prefix [1, 2, 4, 5]. The helper is called with j = n - 2 = 3.

Stable

Equal values keep their original relative order. The condition uses <, so equal values are not moved past each other. Changing it to <= would remove that guarantee.

In-place

The values are rearranged inside the original array. Only a few variables are added, so extra space remains constant: O(1).

Adaptive

Already sorted or nearly sorted data needs very few shifts. The algorithm notices this naturally; it does not keep scanning left once a comparison fails.

Comparison-based

Every placement decision comes from questions such as 3 < 5 and 3 < 2.

Why those complexities occur

Optional · expand to explore
Sorting / Insertion sort · Why those complexities occur

Why those complexities occur

Best case · O(n)An already sorted array needs one failed comparison for each new key and no shifts.
Worst case · O(n²)A reverse-sorted array makes every new key cross the entire sorted section.

Best case

For [1, 2, 3, 4, 5], the comparisons 2 < 1, 3 < 2, 4 < 3, and 5 < 4 all fail immediately. That is n − 1 comparisons and no shifts, so the work grows directly with n.

Worst case

For [5, 4, 3, 2, 1], the new keys move past 1, then 2, then 3, then 4 earlier values.

1 + 2 + 3 + … + (n − 1) = n(n − 1) / 2 → O(n²)

Average case

In random data, a key moves across roughly half of the sorted section on average. The constant is smaller than in the worst case, but the dominant growth is still proportional to n².

When should you use it?

Optional · expand to explore
Sorting / Insertion sort · When to use it

When should you use it?

A good choiceSmall arrays; nearly sorted values; data arriving one item at a time; very limited memory; cases that need stability.
A poor choiceVery large arrays; reverse-ordered data; situations requiring predictable O(n log n) performance.

Insertion sort is excellent for a small hand of cards or adding a new score to an already sorted leaderboard. For a large, disorderly array, merge sort is usually more efficient.

Why sort data at all?

Before the algorithms: what does sorted data give you that unsorted data does not, and what does it cost?

Everything in this chapter is about putting values in order. Before learning how, it is worth being clear about why, because it is a favourite exam question and because it explains why searching and sorting are taught together.

Short answer for a test: sorting data makes it easier and faster to find information in it. A sorted array can be searched with binary search, in O(log n) instead of O(n).

Sorting costs about n log₂ n steps, and it only pays off if you search more than a few times. Suppose you have 1,000,000 values and will search for 1,000 different keys:

StrategyWorkTotal
Never sort: linear search every time1,000 searches × up to 1,000,000 comparisons1,000,000,000
Sort once, then binary search every timesort ≈ 20,000,000 steps, then 1,000 searches × 20 probes20,020,000

That is about 49× less work after sorting. With a single search the answer flips: scanning once costs 1,000,000 and sorting first costs 20,000,000. The rule: search once, scan; search often, sort first.

Quick check: Exam-style question 3(a), “What is the purpose of sorting data?”
To arrange data in a defined order (ascending or descending) so that information is easier and faster to find, for example by using binary search instead of scanning every element. Other valid points: duplicates become adjacent, minimum and maximum are at the ends, and sorted data is easier to read and merge.

Count the disorder: inversions

An inversion is a pair of positions whose values are in the wrong order: a larger value sits to the left of a smaller one. [4, 2, 5, 1, 3] has six: (4,2), (4,1), (4,3), (2,1), (5,1), (5,3).

AlgorithmWhat is countedOn [4, 2, 5, 1, 3]Link to inversions
Bubbleadjacent swaps6Each swap of neighbours removes exactly one inversion.
Insertionshifts6Each shift removes exactly one inversion.
Selectionswaps2At most n − 1 swaps; one swap can remove several inversions at once.

A fully reversed array of n values has n(n − 1) / 2 inversions. For [5, 4, 3, 2, 1] that is 10, which equals the 10 shifts in the reverse-order insertion example. This is the reason bubble and insertion sort are O(n²) in the worst case.

Reverse the order by reversing one comparison

Only the shift condition changes. Everything else, including saving the key, starting at index 1, and inserting at j + 1, stays identical.

Two versions of the while line
// Ascending: shift while the key is SMALLER than the value on its left.
while (j >= 0 && key < array[j]) {
    array[j + 1] = array[j];
    j--;
}

// Descending: shift while the key is LARGER than the value on its left.
while (j >= 0 && key > array[j]) {
    array[j + 1] = array[j];
    j--;
}

The costs differ because “out of order” depends on the direction. This array has 10 pairs of positions. Six have a larger value on the left, and those cost a shift when sorting ascending. The other four have a smaller value on the left, and those cost a shift when sorting descending: 6 + 4 = 10.

Stability is unchanged. Descending still uses a strict >, so equal values do not shift past each other.
Quick check: for an already descending array, which direction is the best case?
Sorting descending. Every key is already not larger than the value on its left, so each iteration makes one failed comparison and no shifts: O(n).

Before you start: what changes for descending?

In ascending insertion sort the key moves left while it is smaller than the value before it. In descending order the key moves left while it is larger. In code, the only change is the comparison in the while loop:

Ascending
while (j >= 0 && key < arr[j]) {
    arr[j + 1] = arr[j];
    j--;
}
Descending (this question)
while (j >= 0 && key > arr[j]) {
    arr[j + 1] = arr[j];
    j--;
}

Questions

Why is shifting preferred to swapping the key repeatedly?
Saving one key and shifting a block makes the algorithm’s purpose clearer and avoids unnecessary repeated exchanges.
What happens if the while comparison uses <=?
Equal values may move past one another, so the implementation can lose stability.
Does descending order cost the same as ascending order?
Not necessarily. On [4, 2, 5, 1, 3] ascending makes 8 comparisons and 6 shifts, while descending makes 7 comparisons and 4 shifts. Each shift removes one out-of-order pair, and the number of such pairs depends on the direction. See Descending order.
Insertion sort in one sentence

Take the next key, shift larger values in the sorted prefix right, and place the key into the gap.

Common mistakes

Optional · expand to explore
Sorting / Insertion sort · Common mistakes

Common mistakes

1
Calling shifts swaps.
Insertion sort saves the key, shifts larger values, and inserts the key. It does not normally exchange pairs.
2
Starting at index 0.
The first element already forms the initial sorted section, so the outer loop begins at index 1.
3
Forgetting to save the key.
A shift may overwrite its array position. Save array[i] before moving anything.
4
Checking the value before the boundary.
Use j >= 0 && key < array[j]. The reverse order may attempt to read index −1.
5
Using <= unnecessarily.
Moving equal values can destroy the algorithm’s stability. Use <.
6
Forgetting the final insertion.
After shifting, place the key with array[j + 1] = key.

A test-ready summary

Optional · expand to explore
Sorting / Insertion sort · Test summary

A test-ready summary

Insertion sort is a stable, in-place and adaptive comparison-based sorting algorithm. It builds a sorted section from left to right. During each iteration, the next value is saved as the key, larger values in the sorted section are shifted to the right, and the key is inserted into the resulting gap. Its best-case time complexity is O(n) for an already sorted array, while its average and worst-case complexities are O(n²). It is suitable for small or nearly sorted arrays but inefficient for large, randomly ordered arrays.

Best: O(n). Already sorted input makes one failed key comparison per insertion. Average / worst: O(n²). Reverse input shifts across every earlier prefix cell.
