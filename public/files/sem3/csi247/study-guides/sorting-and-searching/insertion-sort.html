1. The array we will sort

Arrays use zero-based positions. Sorting changes which values occupy those positions. The target is ascending order; record tags would move with their values.

We will distinguish comparisons, swaps, shifts, temporary writes and copy-back writes. They are different units.

2. Definition and plain language

Insertion sort builds a sorted prefix one value at a time. It inserts each next value into the correct location among the earlier sorted values.

Keep the left-hand cards ordered. Pick up the next card and hold it safely. Move larger cards right until there is a gap after a card no larger than the one you hold.

The prefix is already sorted, so comparisons move backwards. Once a prefix value is no larger than the key, every earlier prefix value is also no larger.

3. Vocabulary and the central invariant

TermMeaning in this chapter
KeyThe saved value being inserted, not a permanent array index.
ShiftCopy one prefix value to the next cell; it temporarily leaves duplicate cells.
GapThe cell at j + 1 where the held key will be placed.
iOriginal index of the next key.
jBackwards-moving index within the sorted prefix.

Invariant: Before outer iteration i, prefix 0..i-1 is sorted. The key remains saved while larger prefix values shift; after insertion prefix 0..i is sorted.

10. Descending order: change the decision

Change arr[j] > key to arr[j] < key. Shift smaller prefix values right, stopping after a value at least as large as the key.

Keep the bounds and movement rules consistent. Reversing a final array is a different procedure and does not reproduce the descending trace of this implementation.

12. Properties and why the complexity occurs

PropertyResultReason
BestO(n)Already sorted input makes one failed key comparison per insertion.
Average / worstO(n²)Reverse input shifts across every earlier prefix cell.
Auxiliary spaceO(1) iterative; O(n) recursiveOne saved key versus suspended recursive frames.
Stable / in place / adaptiveYes / yes / yesStrict > never shifts an equal value past the key; few inversions mean few shifts.

On the main input there are 8 key comparisons, 6 shifts and 4 insertion writes. The guard j >= 0 is not a key comparison. Reverse input gives the triangular worst-case number of shifts; sorted input makes n-1 failed key comparisons.

13. When to choose it

A strong choice for small or nearly sorted arrays. It is simple, stable, and adaptive; it can also serve as the small-input stage of a larger sorting algorithm.

14. Common mistakes, symptoms and repairs

AttemptWhat goes wrongRepair
Overwrite arr[i] without saving itThe key is lost during shifting.Save int key = arr[i] first.
Evaluate arr[j] before j >= 0May read arr[-1] at the left edge.Place the bounds condition first with &&.
Insert at arr[j]Writes before the identified gap.Write arr[j + 1] = key.
Describe every shift as a swapCounts and intermediate states become wrong.A shift performs one array write; a swap exchanges two values.

B. Explain stability with tagged equal keys. [4]

Strict inversion comparisons do not move a value past an equal one. Using >= (or <= descending) would remove that guarantee.
