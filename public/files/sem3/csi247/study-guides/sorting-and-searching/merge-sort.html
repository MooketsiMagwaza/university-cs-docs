1. The array we will sort

Arrays use zero-based positions. Sorting changes which values occupy those positions. The target is ascending order; record tags would move with their values.

We will distinguish comparisons, swaps, shifts, temporary writes and copy-back writes. They are different units.

2. Definition and plain language

Merge sort is a divide-and-conquer comparison sort. It recursively sorts two disjoint halves and combines them by repeatedly selecting the smaller front value.

One card needs no sorting. Sort small piles first, then combine two sorted piles by taking their smallest remaining front card. Repeat until the original range is complete.

Splitting changes the problem boundaries, not the array values. Actual copying occurs during merging after both recursive child calls return.

TermMeaning in this chapter

left / rightFirst unread indexes in each sorted run.
outNext free temp index, beginning at 0.
Stable mergeChoose left on equality using <=.

Invariant: Before a merge, both input runs are sorted. During merging, temp contains the smallest consumed values in order, and each pointer identifies the next unread value in its run.

7. Fully commented Java implementation

Write it from scratch

  • State the inclusive base case.
  • Calculate a midpoint that shrinks both ranges.
  • Sort left, sort right, then merge.
  • Track both input pointers and temp output.
  • Choose one front value; advance only its source.
  • Copy both possible leftover suffixes.
  • Copy temp back with start + k.

8. Recursion, calls and returns

The primary implementation is already recursive. Its 15 calls form a tree, but Java executes them depth-first and retains only a path on the stack.

The live stack at the first base case

The base-case frame returns and disappears. Its parent then calls the right leaf, merges the pair, and returns to its own parent. A parent resumes exactly where its child call suspended it.

10. Descending order: change the decision

Use arr[left] >= arr[right] to choose the left run. Both children must also be sorted descending; left-first equality still preserves stability.

Keep the bounds and movement rules consistent. Reversing a final array is a different procedure and does not reproduce the descending trace of this implementation.

12. Properties and why the complexity occurs

PropertyResultReason
Best / average / worstO(n log n)The standard implementation still splits and merges sorted input.
Auxiliary arraysO(n) peakThe largest merge needs n temporary cells.
Call stackO(log n)Only one root-to-leaf path is active at once.
Stable / in place / adaptiveYes / no / noLeft-first ties preserve equals; the taught form allocates temp; no ordered-range shortcut.

For n=8, three merge levels each copy eight values, so this execution has 24 copy-back writes and 24 writes into temporary output. This is work across levels, not 24 simultaneous temporary cells: peak auxiliary storage remains O(n). The active call path has O(log n) frames.

13. When to choose it

Suitable for large unpredictable arrays when consistent O(n log n) time and stability matter and temporary memory is available.
