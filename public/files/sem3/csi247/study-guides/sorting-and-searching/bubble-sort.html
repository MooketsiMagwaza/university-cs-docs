Sorting / Bubble sort · The textbook definition

The textbook definition

Bubble sort is a comparison-based sorting algorithm that makes repeated passes over an array. In each pass it compares every pair of neighbouring values and swaps the pair if it is in the wrong order. After each pass the largest value in the part still being sorted has moved to its final place at the right end. The algorithm stops when a pass makes no swaps, or when only one value is left.

PassOne complete walk from the left of the active range to its right end. A pass is not one comparison: it is many.
Adjacent pairTwo neighbouring cells, array[j] and array[j + 1]. Bubble sort only ever compares neighbours.
SwapExchange the two values of a pair so the smaller is on the left (for ascending order).
Active rangeThe cells a pass still has to look at. It shrinks by one cell after every pass.
Locked tailThe right-hand cells that already hold their final values, so later passes skip them.
swapped flagA boolean that becomes true when a pass swaps anything. If it stays false, the array is sorted and we can stop early.
InversionA pair of values that is in the wrong order. Every swap of neighbours fixes exactly one inversion.

The name comes from the picture: big values slowly “bubble up” to the end of the array the way air bubbles rise through water, while small values sink towards the front, only one place at a time.

Sorting / Bubble sort · In plain language

In plain language

Think of walking along a line of people and swapping any neighbours who are standing in the wrong order.

Picture a row of students you want ordered from shortest to tallest. You stand at the left end and look at the first two students. If the left one is taller, they swap places. Then you take one step right and look at the next pair, and so on to the end of the row.

When you reach the end, something useful has happened without any planning: the tallest student has been swapped all the way to the right end, because whenever you met a taller student you carried them one step further. Walk along again (stopping one place earlier, since the end is finished) and the second tallest lands next to them.

Sorting / Bubble sort · The main idea

The main idea

Bubble sort never looks at the whole array at once. It follows one tiny rule, “if the left neighbour is bigger, swap”, and repeats it along the array. Everything else follows from that rule.

One pass carries the biggest value to the end

Watch pass 1 on [4, 2, 5, 1, 3]. The 4 is carried one step (it beats 2), then meets 5 and is left behind. From then on it is the 5 that gets carried, past 1 and past 3, all the way to the end. A larger value is only stopped by an even larger one, so the maximum can never be stopped.

Small values move slowly

Notice the 1: it starts at index 3 and moves left one place per pass (index 2, then 1, then 0). A big value can travel the whole array in one pass; a small value can only creep. That asymmetry is the reason bubble sort is slow on some inputs, and we will measure it in the examples.

The repeating recipe: compare a pair → swap if the left one is larger → step right → at the end of the range lock the last cell → start the next pass, one cell shorter → stop when a pass makes no swaps.
Sorting / Bubble sort · Comparison, swap, pass

Comparison, swap, pass

These words describe different things. Counting them separately is what makes a trace table correct, and exam questions often ask for exactly one of them.

ComparisonOne question, such as 4 > 2. Bubble sort asks one for every pair in every pass, whether or not anything moves.
SwapExchanging two neighbours. It happens only when the answer to the comparison was yes, they are out of order.
PassA whole run of comparisons along the active range. “Show the array after each pass” means one snapshot per pass, not per swap.
Early exitStopping because a pass made no swaps. Without the flag, bubble sort keeps making every pass even on sorted data.

How one swap actually works

Java cannot exchange two cells in a single step. If you wrote a[j] = a[j + 1]; a[j + 1] = a[j]; both cells would end up equal, because the first line destroys the original a[j]. A third variable, temp, keeps it safe. Follow the swap of a[j] = 4 and a[j + 1] = 2:

StepCodetempa[j]a[j + 1]What happened
0(before)—42Out of order, so we swap
1int temp = a[j];442The 4 is saved
2a[j] = a[j + 1];422Both cells hold 2; the 4 survives only in temp
3a[j + 1] = temp;424The 4 is restored on the right: swapped

Swap versus shift

Insertion sort shifts: it copies a larger value one place right while the key waits in a variable, then drops the key in once. Bubble sort swaps: it exchanges two neighbours using three assignments. They fix the same kind of problem (an out-of-order pair) but a swap does more writing, which is one reason insertion sort is usually the faster of the two in practice.

Every swap fixes exactly one inversion

An inversion is a pair of values in the wrong order. In [4, 2, 5, 1, 3] the inversions are (4,2), (4,1), (4,3), (2,1), (5,1), (5,3): 6 of them. A swap of neighbours repairs exactly one pair and breaks none, so bubble sort needs exactly 6 swaps for this array, and that is what the trace shows. Counting inversions is a quick way to predict the number of swaps before you trace anything.

Implementation

Optimised bubble sort
public static void bubbleSort(int[] arr) {
    // Each pass locks one more large value at the right.
    for (int pass = 0; pass < arr.length - 1; pass++) {
        boolean swapped = false;
        // Ignore the positions already locked by earlier passes.
        for (int j = 0; j < arr.length - 1 - pass; j++) {
            // Ascending order: swap an inverted neighbouring pair.
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = true;
            }
        }
        // No swaps means the whole array is already sorted.
        if (!swapped) break;
    }
}

Ascending ↔ descending

Ascending swaps when arr[j] > arr[j+1]. Descending swaps when arr[j] < arr[j+1].

Same pair, opposite decision: for neighbours 63, 29, ascending swaps (63 > 29) while descending keeps them (63 < 29 is false). In every descending pass the smallest active value is carried to the right edge.

* only with the swapped early-exit flag. Without it, bubble sort always makes n(n − 1) / 2 comparisons.

Stable

Equal values keep their original left-to-right order, because a pair is swapped only when the left value is strictly greater. Equal neighbours are left alone, so they can never cross each other.

In-place

Everything happens inside the original array. The only extra storage is a few variables (j, pass, temp, swapped), so the extra space is constant, O(1).

Adaptive (with the flag)

On sorted or nearly sorted data the flag lets the algorithm stop after very few passes. But note nearly sorted must mean “no small value is far to the right”: one turtle forces many passes (see [2, 3, 4, 5, 1]).

Comparison-based

All decisions come from asking whether one value is greater than another; it never uses the value's digits or range. This is why no comparison-based sort can beat O(n log n) in general.

Swaps equal inversions

The number of swaps is exactly the number of inversions in the input, from 0 (sorted) to n(n − 1) / 2 (reversed).

Sorting / Bubble sort · Why those complexities occur

Why those complexities occur

Best case · O(n)An already sorted array: pass 1 makes n − 1 comparisons, finds no swap and stops.
Worst case · O(n²)A reversed array: every pair is out of order in every pass, so all n(n − 1) / 2 comparisons also swap.

Counting the comparisons

Pass 1 compares n − 1 pairs. Pass 2 compares one fewer, because the last cell is locked. Pass 3 one fewer again, down to a final pass of one comparison. For five values:

Each row is one pass and each square one comparison. The shape is a staircase, and the area of a staircase of height n − 1 is half of a square:

(n − 1) + (n − 2) + … + 2 + 1 = n(n − 1) / 2 → O(n²)

For n = 8 the staircase has 28 squares (7 + 6 + 5 + 4 + 3 + 2 + 1). Here is how fast that grows:

Double the array from 1,000 to 2,000 values and the work does not double, it roughly quadruples (499,500 → 1,999,000). That is what “quadratic” means in practice, and it is why bubble sort is only comfortable for small arrays.

Best case with the flag

For [1, 2, 3, 4, 5] the first pass makes 4 comparisons, sets nothing, and the loop ends: n − 1 steps, so O(n). Without the swapped flag the staircase would still be walked in full.

Average case

For random data about half of all pairs are inverted, so about n(n − 1) / 4 swaps happen. The constant halves, but the growth is still proportional to n².

Space

Nothing is copied. A few variables are enough, so the space is O(1).

Sorting / Bubble sort · When to use it

When to use it

A good choiceTeaching the idea of sorting; tiny arrays (a handful of values); checking whether data is already sorted (one pass with no swaps proves it); data where the only disorder is a few large values near the front.
A poor choiceAnything large or random: O(n²) comparisons grow too fast; data with a small value far to the right (turtles); any situation where you need guaranteed O(n log n) time; and almost every real program, where insertion sort or merge sort does better.

In practice bubble sort is a learning tool, not a working tool. It earns its place because it is the clearest example of repeated local fixing: a rule about two neighbours, applied repeatedly, produces a globally sorted array. When you are asked in an exam to choose between algorithms for a large array, bubble sort is almost never the answer.

Compared with its two quadratic cousins: insertion sort does less writing and is better on nearly sorted data; selection sort makes the fewest swaps. Bubble sort is the one that can notice “already sorted” in a single pass, but only if you remember the flag.

Sorting · Why sort data at all?

Why sort data at all?

Before the algorithms: what does sorted data give you that unsorted data does not, and what does it cost?

Everything in this chapter is about putting values in order. Before learning how, it is worth being clear about why, because it is a favourite exam question and because it explains why searching and sorting are taught together.

Short answer for a test: sorting data makes it easier and faster to find information in it. A sorted array can be searched with binary search, in O(log n) instead of O(n).

Sorting is not free: is it worth it?

Sorting costs about n log₂ n steps, and it only pays off if you search more than a few times. Suppose you have 1,000,000 values and will search for 1,000 different keys:

StrategyWorkTotal
Never sort: linear search every time1,000 searches × up to 1,000,000 comparisons1,000,000,000
Sort once, then binary search every timesort ≈ 20,000,000 steps, then 1,000 searches × 20 probes20,020,000

That is about 49× less work after sorting. With a single search the answer flips: scanning once costs 1,000,000 and sorting first costs 20,000,000. The rule: search once, scan; search often, sort first.

Quick check: Exam-style question 3(a), “What is the purpose of sorting data?”
To arrange data in a defined order (ascending or descending) so that information is easier and faster to find, for example by using binary search instead of scanning every element. Other valid points: duplicates become adjacent, minimum and maximum are at the ends, and sorted data is easier to read and merge.

Count the disorder: inversions

An inversion is a pair of positions whose values are in the wrong order: a larger value sits to the left of a smaller one. [4, 2, 5, 1, 3] has six: (4,2), (4,1), (4,3), (2,1), (5,1), (5,3).

AlgorithmWhat is countedOn [4, 2, 5, 1, 3]Link to inversions
Bubbleadjacent swaps6Each swap of neighbours removes exactly one inversion.
Insertionshifts6Each shift removes exactly one inversion.

A fully reversed array of n values has n(n − 1) / 2 inversions. For [5, 4, 3, 2, 1] that is 10, which equals the 10 shifts in the reverse-order insertion example. This is the reason bubble and insertion sort are O(n²) in the worst case.

Sorting / Bubble sort · Descending order

Descending order

To sort from largest to smallest, change one symbol: swap when the left value is smaller than its right neighbour.

Ascending
if (arr[j] > arr[j + 1]) {
    swap(arr, j, j + 1);
}
Descending
if (arr[j] < arr[j + 1]) {
    swap(arr, j, j + 1);
}

Nothing else moves: the loops, the shrinking range and the swapped flag stay identical. The only difference is which value gets carried. In descending order the smallest value of the active range is carried to the right end each pass, and the largest values drift left.

Both runs start from the same array. Ascending needs 6 swaps (the 6 inversions). Descending needs 4 swaps: out of the 10 possible pairs, 6 are out of order for ascending, so the other 10 − 6 = 4 pairs are out of order for descending. Comparisons: 10 for ascending and 9 for descending, because the early-exit pass happens at a different moment.

Test habit: when a question says descending, write the direction at the top of your working and check the first comparison before you start. Most lost marks on this question type come from silently sorting in the wrong direction.

Sorting / Bubble sort · Common mistakes

Common mistakes

1
Letting the inner loop run to the end every time.
With j < arr.length - 1 the program still works but re-checks the locked tail. Use j < arr.length - 1 - pass so each pass is shorter.
2
Reading past the end.
The comparison uses arr[j + 1], so j must stop at length - 2. A loop condition of j < arr.length throws ArrayIndexOutOfBoundsException.
3
Swapping without a temporary variable.
a[j] = a[j + 1]; a[j + 1] = a[j]; leaves two equal values and loses one. Always save one value in temp first.
4
Using >= instead of >.
Equal values then swap with each other. That wastes swaps and destroys stability.
5
Forgetting to reset swapped at the start of each pass.
If it stays true from an earlier pass, the early exit never triggers and the sort loses its best-case speed.
6
Writing the array after every swap when asked for “after each pass”.
A pass is the whole walk. Record one array per pass, and count swaps and comparisons separately.
7
Reversing the loops for descending order.
Only the comparison changes (< instead of >). The loops, the range and the flag stay the same.
8
Stopping early for the wrong reason.
Stop when a whole pass makes no swaps, not when one pair happens to be in order.
Sorting / Bubble sort · A test-ready summary

A test-ready summary

Bubble sort is a stable, in-place, comparison-based sorting algorithm. It repeatedly walks through the array, compares each pair of neighbouring values and swaps them when they are in the wrong order, so after each pass the largest remaining value has moved to its final place at the right. Each pass is one cell shorter than the one before, and with a swapped flag it stops as soon as a pass makes no swaps. The number of swaps equals the number of inversions. Its best-case time is O(n) for sorted input, and its average and worst cases are O(n²) with O(1) extra space. It is suitable for teaching and tiny arrays, but not for large or random data.

B. Explain stability with tagged equal keys. [4]

Strict inversion comparisons do not move a value past an equal one. Using >= (or <= descending) would remove that guarantee.

C. Give the time and space, then justify both. [5]

Best: O(n). Already sorted input: one pass makes n - 1 comparisons and no swaps. Average / worst: O(n²). A reverse-order array needs many shrinking sweeps. Auxiliary space: O(1) iterative; O(n) recursive worst case. A temporary swap value versus a chain of calls. Stable / in place: Yes / yes. Strict > avoids crossing equals; values are exchanged inside the input. Adaptive: Yes in this optimized version. The swapped flag enables early stop.
