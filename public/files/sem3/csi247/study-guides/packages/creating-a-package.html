1. The problem and the plain-language idea

Declare a package, match its path below the source root, and coordinate the class name, public visibility and entry point.

Think of a package as a class address. Two classes may share a simple name when their package addresses differ. Source paths and compiled paths are measured from different roots.

2. Definition and essential vocabulary

A user-defined package groups named types under a declared namespace. The package declaration, source location below the root, and dotted class identity must agree.

TermMeaning in this chapter
Source rootDirectory above the first package segment.
package pkg;Defines membership; first non-comment statement.
public class AExternally visible class saved as A.java.
Package-privateNo access modifier; visible within the same package.
Entry pointpublic static void main(String[] args).

4. Rules before code

  • Put a package declaration before import declarations and the class declaration.
  • Match the package path below the source root.
  • Match a public class name to its source filename, including case.
  • Classes in the same package do not need imports for one another.
  • Named packages cannot import a class from the unnamed default package.
  • An import does not change an access modifier.
  • Use a fully qualified class name when launching a packaged program.

Protected access from a different package is through inheritance and is subject to receiver restrictions; it is not blanket permission to access any superclass object. A top-level class may be public or package-private, not protected/private.

9. Build or explain it from scratch

  • Choose the package and public class names.
  • Create matching source directories.
  • Write the package declaration first.
  • Add a main entry point to the class you intend to run.
  • Compile with an output root and source dependency root.
  • Run with a classpath root and fully qualified name.
  • Check output and exercise cross-package public access.

10. Properties and when to use packages

Packages organize names and collaboration; imports are compile-time name resolution conveniences. A wildcard is not a performance optimization. There is no useful sorting-style O(n) claim to assign to an import declaration.

PropertyPractical consequence
NamespaceSame simple type names may exist in different packages.
EncapsulationPackage-private members form an internal package API.
MaintainabilityRelated classes have predictable source locations.
Dependency lookupSourcepath/classpath roots must locate the required types.
Case sensitivitypkg.A and pkg.a name different types.

12. Exam-style practice and answers

A. Place Helper in ub.cs.tools. Give declaration, source path, output path and binary name. [4]

package ub.cs.tools; / src/ub/cs/tools/Helper.java / classes/ub/cs/tools/Helper.class / ub.cs.tools.Helper. The src and classes roots are not package segments.

B. Explain import java.util.* and whether it includes subpackages. [3]

It allows accessible types directly in java.util to be named simply. It does not import types from subpackages, copy code or install dependencies.

C. Why can pkg.Tester call B.secret while app.Main cannot? [3]

secret has no access modifier, so it is package-private. Tester shares pkg. Main belongs to app; importing B does not grant member visibility.

D. Repair java -classpath classes/pkg Tester.class. [3]

Use java -classpath classes pkg.Tester. The classpath names the root above package folders; the launch argument is a dotted binary name without an extension.

E. Compile and run the four classes in this chapter. State expected output. [6]

pkg.Tester prints Hello from pkg.A, 42, pkg only. app.Main prints Hello from pkg.A, 10.

F. Scanner is unresolved even though the JDK is installed. What are two fixes? [2]

Add import java.util.Scanner; or use java.util.Scanner at every relevant type/constructor use. Both name the same class.

13. Test-ready summary and mastery check

Declare a package, match its path below the source root, and coordinate the class name, public visibility and entry point.

  • I can separate package declaration, import and access modifier.
  • I can translate dots to directories below a specified root.
  • I can explain specific/wildcard/fully qualified alternatives.
  • I can identify the main class and run it without an extension.
  • I can diagnose naming, lookup and visibility errors separately.
