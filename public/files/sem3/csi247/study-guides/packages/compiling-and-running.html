Java packages

Group related classes together

A package is a named group of related classes organised in a matching folder structure. Packages improve maintainability and prevent class-name conflicts.

Built-in packagesProvided by Java, such as java.lang, java.util, and java.io.
User-defined packagesCreated by programmers to organise their own related classes.

Common built-in examples

PackagePurposeExample
java.langFundamental Java classes; imported automaticallyString, Math
java.utilUtilities and collectionsScanner, Random, Arrays
java.ioFile input and outputPrintWriter, File

A source file with no package statement belongs to the unnamed default package. Classes in a named package cannot import classes from the default package, so every file in this chapter declares a package. (The earlier array and file examples are single files in the default package, which is fine for a one-file program.)

The required folder hierarchy

The pkg folders under src and classes mirror each other. The package name is the folder path with dots instead of slashes.

Inside every packaged source file

A offers a method, B a second helper, and Tester is the class you run because it alone contains main.

src/pkg/A.java
package pkg; // first non-comment statement

public class A {
    // public: other packages may call this method after importing pkg.A
    public static void greet() {
        System.out.println("Hello from pkg.A");
    }
}
src/pkg/B.java
package pkg;

public class B {
    // public: visible everywhere
    public static int twice(int x) {
        return 2 * x;
    }

    // no modifier = package-private: visible only inside pkg
    static String secret() {
        return "pkg only";
    }
}
src/pkg/Tester.java
package pkg;

public class Tester {
    // The class you run must contain a main method like this one.
    public static void main(String[] args) {
        A.greet();                        // same package: no import needed
        System.out.println(B.twice(21));  // prints 42
        System.out.println(B.secret());   // legal here: same package
    }
}

Imports and visibility

Choose specific, wildcard, or fully qualified
import java.util.Scanner;  // one class
import java.io.*;           // every public class directly in java.io
import pkg.A;               // a user-defined class

// Without an import you may write the fully qualified name instead:
pkg.A.greet();
  • java.lang is imported automatically. Classes in the same package never need an import.
  • A wildcard such as java.io.* imports the classes directly in that package, not classes in its sub-packages.
  • An import only shortens names. It does not grant access to members that are not visible.

Build a package from scratch
  1. Create src/pkg and classes.
  2. Place package pkg; first in each source file.
  3. Save source files inside src/pkg.
  4. Give one class a main method.
  5. Compile with -d classes.
  6. Run the fully qualified class name.
Debug checklist
  • Package name and folder path must match.
  • Java is case-sensitive.
  • Run from the folder above classes.
  • Do not include .class in the run command.
  • The class you run needs main.

Fully annotated Java and commands

Imports and access: different responsibilities

Member modifierSame classSame packageSubclass outside packageUnrelated outside class
publicYesYesYesYes
protectedYesYesYes, with subclass access restrictionsNo
none (package-private)YesYesNoNo
privateYesNoNoNo

Protected access from a different package is through inheritance and is subject to receiver restrictions; it is not blanket permission to access any superclass object. A top-level class may be public or package-private, not protected/private.

Properties and practical cost

Packages organize names and collaboration; imports are compile-time name resolution conveniences. A wildcard is not a performance optimization. There is no useful sorting-style O(n) claim to assign to an import declaration.

PropertyPractical consequence
NamespaceSame simple type names may exist in different packages.
EncapsulationPackage-private members form an internal package API.
MaintainabilityRelated classes have predictable source locations.
Dependency lookupSourcepath/classpath roots must locate the required types.
Case sensitivitypkg.A and pkg.a name different types.

Exam-style practice with worked answers

A. Place Helper in ub.cs.tools. Give declaration, source path, output path and binary name. [4]

package ub.cs.tools; / src/ub/cs/tools/Helper.java / classes/ub/cs/tools/Helper.class / ub.cs.tools.Helper. The src and classes roots are not package segments.

B. Explain import java.util.* and whether it includes subpackages. [3]

It allows accessible types directly in java.util to be named simply. It does not import types from subpackages, copy code or install dependencies.

C. Why can pkg.Tester call B.secret while app.Main cannot? [3]

secret has no access modifier, so it is package-private. Tester shares pkg. Main belongs to app; importing B does not grant member visibility.

D. Repair java -classpath classes/pkg Tester.class. [3]

Use java -classpath classes pkg.Tester. The classpath names the root above package folders; the launch argument is a dotted binary name without an extension.

E. Compile and run the four classes in this chapter. State expected output. [6]

pkg.Tester prints Hello from pkg.A, 42, pkg only. app.Main prints Hello from pkg.A, 10.

F. Scanner is unresolved even though the JDK is installed. What are two fixes? [2]

Add import java.util.Scanner; or use java.util.Scanner at every relevant type/constructor use. Both name the same class.

Lab05 / Steps 2–4

The marks application: merge sort, random data, and a repeat loop

Both files live in src/lab05/ and start with package lab05;. MergeSort holds the two methods; MarksApp is the class you run.

src/lab05/MergeSort.java
package lab05;

import java.util.Arrays;

public class MergeSort {
    public static void mergeSort(int[] arr, int start, int end) {
        // A zero- or one-value range is already sorted.
        if (start < end) {
            int mid = start + (end - start) / 2;
            mergeSort(arr, start, mid);      // sort the left half
            mergeSort(arr, mid + 1, end);    // sort the right half
            merge(arr, start, mid, end);     // combine the two sorted halves
        }
    }

    public static void merge(int[] arr, int s, int m, int e) {
        // Copy both halves; the right half starts at m + 1.
        int[] left = Arrays.copyOfRange(arr, s, m + 1);
        int[] right = Arrays.copyOfRange(arr, m + 1, e + 1);
        int i = 0, j = 0, cur = s;

        // Take the smaller front value each time (<= keeps the merge stable).
        while (i < left.length && j < right.length)
            arr[cur++] = left[i] <= right[j] ? left[i++] : right[j++];

        // Exactly one of these loops copies the leftovers.
        while (i < left.length) arr[cur++] = left[i++];
        while (j < right.length) arr[cur++] = right[j++];
    }
}
src/lab05/MarksApp.java
package lab05;

import java.util.Arrays;
import java.util.Random;
import java.util.Scanner;

public class MarksApp {
    public static void main(String[] args) {
        Random random = new Random();
        Scanner keyboard = new Scanner(System.in); // create ONCE, outside the loop
        String again = "y";                        // lets the first pass run

        while (again.equalsIgnoreCase("y")) {
            int[] marks = new int[30];

            // Fill every cell with a random mark from 0 to 100 inclusive.
            int i = 0;
            while (i < marks.length) {
                marks[i] = random.nextInt(101); // upper bound is exclusive
                i++;
            }

            System.out.println("Before: " + Arrays.toString(marks));
            MergeSort.mergeSort(marks, 0, marks.length - 1);
            System.out.println("After:  " + Arrays.toString(marks));

            System.out.print("Run again? (y/n) ");
            again = keyboard.nextLine().trim();
        }
        keyboard.close();
    }
}
Compile and run
javac -d classes -sourcepath src src/lab05/*.java
java -classpath classes lab05.MarksApp

Each run prints a Before: line of 30 random marks, an After: line with the same 30 values in ascending order, and the prompt Run again? (y/n). Answering y repeats with fresh random marks; anything else ends the loop.

DetailWhy it is written that way
random.nextInt(101)The bound is exclusive, so nextInt(101) gives 0 to 100 inclusive. nextInt(100) could never produce 100.
int i = 0; while (i < marks.length) { … i++; }The lab asks for a while loop. The three parts of a for loop are still there: start, condition, update.
String again = "y"Starting at y lets the loop body run once before the user is asked anything.
Scanner keyboard created onceClosing a Scanner on System.in closes the keyboard stream. Create it before the loop and close it after.
MergeSort.mergeSort(marks, 0, marks.length - 1)Both bounds are inclusive indexes, so the last index is length - 1.
Quick check: what would go wrong if int[] marks = new int[30]; were placed before the while (again…) loop?
Nothing would visibly break. The fill loop sits inside the while, so every run still overwrites all 30 cells with new random marks, prints a fresh Before: line, and sorts it. Declaring the array inside the loop is still better: each run starts from a brand-new array, no values can leak from the previous run, and marks exists only where it is used.

src/lab05/Doctor.java
package lab05;

public class Doctor {
    protected String name;      // protected: visible to subclasses
    protected double basePay;

    public Doctor(String name, double basePay) {
        this.name = name;
        this.basePay = basePay;
    }

    public String tagName() { return "Dr " + name; }
    public double calculatePay() { return basePay; }
}
src/lab05/GP.java
package lab05;

public class GP extends Doctor {          // a GP IS-A Doctor
    private int patients;

    public GP(String name, double basePay, int patients) {
        super(name, basePay);             // must be the first statement
        this.patients = patients;
    }

    @Override public String tagName() { return "GP " + name; }
    @Override public double calculatePay() {
        return super.calculatePay() + patients * 2.0; // placeholder formula
    }
}

Read the records, then route them

src/lab05/StaffReport.java
package lab05;

import java.io.File;
import java.io.FileNotFoundException;
import java.io.PrintWriter;
import java.util.Scanner;

public class StaffReport {
    public static void main(String[] args) throws FileNotFoundException {
        Doctor[] staff = new Doctor[20];   // capacity; holds Doctor, GP and Surgeon
        int count = 0;                     // logical size

        try (Scanner in = new Scanner(new File("data.txt"))) {
            while (in.hasNextLine() && count < staff.length) {
                Doctor d = parse(in.nextLine());
                if (d != null) staff[count++] = d;   // skip records with an unrecognised field count
            }
        }

        // All three writers are closed automatically, which flushes their output.
        try (PrintWriter doctors = new PrintWriter("doctors.txt");
             PrintWriter gps = new PrintWriter("gps.txt");
             PrintWriter surgeons = new PrintWriter("surgeons.txt")) {
            for (int i = 0; i < count; i++) {
                Doctor d = staff[i];
                // Test subclasses first: every GP and Surgeon is also a Doctor.
                PrintWriter target = (d instanceof Surgeon) ? surgeons
                                   : (d instanceof GP) ? gps
                                   : doctors;
                target.println(d.tagName() + " " + d.calculatePay());
            }
        }
    }

    // The number of fields on the line decides which class to build.
    static Doctor parse(String line) {
        String[] f = line.trim().split("\\s+");
        switch (f.length) {
            case 2:  return new Doctor(f[0], Double.parseDouble(f[1]));
            case 3:  return new GP(f[0], Double.parseDouble(f[1]), Integer.parseInt(f[2]));
            case 4:  return new Surgeon(f[0], Double.parseDouble(f[1]),
                                        Integer.parseInt(f[2]), f[3]);
            default: return null;          // wrong field count
        }
    }
}

Build it in this order
  1. Draw the UML and decide what is shared.
  2. Write and test Doctor.
  3. Write GP and Surgeon; test each constructor and method.
  4. Parse one line into one object.
  5. Loop over the file, storing into the array with a count.
  6. Open three writers and route each object.
  7. Open every output file and check it.
Debug checklist
  • Test Surgeon and GP before Doctor in the routing chain. A Doctor test first would match all three kinds.
  • super(…) must be the first statement of a subclass constructor.
  • Close the writers (try-with-resources does it) or buffered output may never reach the file.
  • Skip a record whose field count is not recognised rather than crashing.

Package and lab questions

Why is classes the classpath rather than classes/lab05?
The classpath names the root above the package hierarchy. Java then uses lab05.ClassName to find lab05/ClassName.class below that root.
Where must package lab05; appear?
It must be the first non-comment statement in the source file.
Why does java -classpath classes pkg.A fail even though A.class exists?
Class A only defines greet(). To start a program Java needs public static void main(String[] args) in the named class. Run pkg.Tester, which contains it.
What is the difference between an import and a fully qualified name?
Both reach the same class. An import lets you write the short name A for the rest of the file; the fully qualified name pkg.A spells out the package each time. Neither bypasses visibility rules.
Can a Doctor[] array hold a GP?
Yes. A GP is a Doctor, so a Doctor reference may refer to it. The array stores references, so the cell holds a reference to the GP object and calculatePay() runs the GP version.
Packages in one sentence

The declared package, source folders, compiled folders, imports, classpath root, and fully qualified class name must all describe the same hierarchy, and the class you run must contain main.
