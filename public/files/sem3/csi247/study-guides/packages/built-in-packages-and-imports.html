The concept, plain language and vocabulary

A Java package supplies a namespace for types. An import declaration lets a compilation unit refer to an accessible type using its simple name instead of its fully qualified name.

TermMeaning in this chapter
PackageA namespace grouping related top-level types.
ImportA source-level name-shortening declaration.
Fully qualified namePackage plus type, such as java.util.Scanner.
WildcardImports accessible types directly in that package; not its subpackages.
java.langAutomatically imported; contains String, System and Math.

An import does not install a library, execute code or copy a class. A dependency still has to be available to compilation and runtime.

PackagePurposeExamples
java.langCore language types, automatic importString, System, Math
java.utilUtilities and collectionsScanner, Arrays, ArrayList

Java packages

Group related classes together

A package is a named group of related classes organised in a matching folder structure. Packages improve maintainability and prevent class-name conflicts.

Built-in packagesProvided by Java, such as java.lang, java.util, and java.io.
User-defined packagesCreated by programmers to organise their own related classes.

Common built-in examples

PackagePurposeExample
java.langFundamental Java classes; imported automaticallyString, Math
java.utilUtilities and collectionsScanner, Random, Arrays
java.ioFile input and outputPrintWriter, File

A source file with no package statement belongs to the unnamed default package. Classes in a named package cannot import classes from the default package, so every file in this chapter declares a package. (The earlier array and file examples are single files in the default package, which is fine for a one-file program.)

The required folder hierarchy

The pkg folders under src and classes mirror each other. The package name is the folder path with dots instead of slashes.

Inside every packaged source file

A offers a method, B a second helper, and Tester is the class you run because it alone contains main.

src/pkg/A.java
package pkg; // first non-comment statement

public class A {
    // public: other packages may call this method after importing pkg.A
    public static void greet() {
        System.out.println("Hello from pkg.A");
    }
}
src/pkg/B.java
package pkg;

public class B {
    // public: visible everywhere
    public static int twice(int x) {
        return 2 * x;
    }

    // no modifier = package-private: visible only inside pkg
    static String secret() {
        return "pkg only";
    }
}
src/pkg/Tester.java
package pkg;

public class Tester {
    // The class you run must contain a main method like this one.
    public static void main(String[] args) {
        A.greet();                        // same package: no import needed
        System.out.println(B.twice(21));  // prints 42
        System.out.println(B.secret());   // legal here: same package
    }
}

Imports and visibility

Choose specific, wildcard, or fully qualified
import java.util.Scanner;  // one class
import java.io.*;           // every public class directly in java.io
import pkg.A;               // a user-defined class

// Without an import you may write the fully qualified name instead:
pkg.A.greet();
  • java.lang is imported automatically. Classes in the same package never need an import.
  • A wildcard such as java.io.* imports the classes directly in that package, not classes in its sub-packages.
  • An import only shortens names. It does not grant access to members that are not visible.

Build a package from scratch
  1. Create src/pkg and classes.
  2. Place package pkg; first in each source file.
  3. Save source files inside src/pkg.
  4. Give one class a main method.
  5. Compile with -d classes.
  6. Run the fully qualified class name.
Debug checklist
  • Package name and folder path must match.
  • Java is case-sensitive.
  • Run from the folder above classes.
  • Do not include .class in the run command.
  • The class you run needs main.

Protected access from a different package is through inheritance and is subject to receiver restrictions; it is not blanket permission to access any superclass object. A top-level class may be public or package-private, not protected/private.

Properties and practical cost

Packages organize names and collaboration; imports are compile-time name resolution conveniences. A wildcard is not a performance optimization. There is no useful sorting-style O(n) claim to assign to an import declaration.

PropertyPractical consequence
NamespaceSame simple type names may exist in different packages.
EncapsulationPackage-private members form an internal package API.
MaintainabilityRelated classes have predictable source locations.
Dependency lookupSourcepath/classpath roots must locate the required types.
Case sensitivitypkg.A and pkg.a name different types.

Foundations / Arrays

An array is one fixed-size row of same-type values

An array stores a numbered sequence. Its length is fixed when it is created, its first index is 0, and its final valid index is always length - 1.

Declare, create, initialise, use

Array basics (code fragment)
// 1. Declare a variable that can refer to an int array.
int[] marks;

// 2. Create five int cells. Every cell starts at 0.
marks = new int[5];

// 3. Store values by index.
marks[0] = 63;
marks[marks.length - 1] = 18; // last valid cell

// A literal declares, creates, and fills in one statement.
int[] ready = {63, 29, 72, 85, 18};

// Reading index 5 would throw ArrayIndexOutOfBoundsException.
System.out.println(ready[2]); // prints 72
Fixed size does not mean fixed values. You may replace values in existing cells, but you cannot make the same array gain a sixth cell. Create a new array or use an ArrayList when size must grow.
Quick check: why is marks[marks.length] invalid?
For length 5, valid indexes are 0 through 4. marks.length is 5, one position beyond the array.

Array helpers you will meet

These come from java.util.Arrays (add import java.util.Arrays;). The file and merge-sort examples later in this guide use them.

CallWhat it doesResult for the example
Arrays.toString(a)Readable text for the contents. Printing an array directly shows an unreadable reference such as [I@6d06d69c.[63, 29, 72, 85, 18]

Quick check: what does Arrays.copyOfRange(a, 1, 3) return for a = {63, 29, 72, 85}?
[29, 72]. It copies indexes 1 and 2. The end index 3 is excluded, which is why merge sort writes m + 1 for the left half.

Capacity versus logical size

buffer.length is the capacity: 100 cells always exist. count is the logical size: only cells 0 .. count − 1 hold file values. The first eight of the 100 cells are drawn here; the rest also hold 0.

6329728518000
FileArraySort.java
import java.io.File;
import java.io.FileNotFoundException;
import java.util.Arrays;
import java.util.Scanner;

public class FileArraySort {
    public static void main(String[] args) throws FileNotFoundException {
        int[] marks = readIntegers("marks.txt");
        System.out.println("Read:   " + Arrays.toString(marks));
        insertionSort(marks); // apply the course algorithm
        System.out.println("Sorted: " + Arrays.toString(marks));
    }

    public static int[] readIntegers(String filename)
            throws FileNotFoundException {
        int[] buffer = new int[100]; // maximum capacity
        int count = 0;               // values actually stored

        // try-with-resources closes the Scanner automatically.
        try (Scanner input = new Scanner(new File(filename))) {
            while (input.hasNext() && count < buffer.length) {
                if (input.hasNextInt()) {
                    buffer[count] = input.nextInt();
                    count++; // advance only after storing a valid int
                } else {
                    System.out.println("Skipped token: " + input.next());
                }
            }
        }
        // Remove unused zero-filled cells before sorting.
        return Arrays.copyOf(buffer, count);
    }

    public static void insertionSort(int[] a) {
        for (int i = 1; i < a.length; i++) {
            int key = a[i];
            int j = i - 1;
            while (j >= 0 && key < a[j]) {
                a[j + 1] = a[j];
                j--;
            }
            a[j + 1] = key;
        }
    }
}

Application questions

Why keep count separately from buffer.length?
buffer.length is capacity: 100 cells exist. count is logical size: only the first count cells contain values read from the file. Sorting all 100 would drag unused zeros into the result.
Why must the invalid token be consumed with input.next()?
hasNextInt() only looks at the next token; it does not consume it. Without input.next() the Scanner stays on the same invalid token and the loop never progresses.
What should happen if the file contains more than 100 integers?
This version stops when the buffer is full and ignores the rest, because the loop condition includes count < buffer.length. To keep every value, remove that part of the condition and grow the array inside the if (input.hasNextInt()) branch (below), or use an ArrayList<Integer>.
Doubling the capacity
// Change the loop condition: drop "&& count < buffer.length" so the loop keeps reading.
while (input.hasNext()) {
    if (input.hasNextInt()) {
        // Grow instead of stopping: double the capacity when the buffer is full.
        if (count == buffer.length) {
            buffer = Arrays.copyOf(buffer, buffer.length * 2);
        }
        buffer[count] = input.nextInt();
        count++;
    } else {
        System.out.println("Skipped token: " + input.next());
    }
}
Why does return Arrays.copyOf(buffer, count) help the sort?
It returns an array whose length equals the number of real values. insertionSort loops to a.length, so it never touches the unused zero cells.

Indexes connect loops to array cells; primitive cells store values, reference cells store nullable object references, and file input needs both capacity control and a logical count before sorting.

Applications / Objects by key field

Sort and search an array of objects by one field

Binary search needs the array sorted “by the same key” it searches. For objects the key is a field you choose. The algorithms are unchanged: the comparison reads the field through a getter instead of comparing the cell directly.

Staff.java
public class Staff {
    private String name;
    private int staffId;
    private String department;

    public Staff(String name, int staffId, String department) {
        this.name = name;
        this.staffId = staffId;
        this.department = department;
    }

    public String getName() { return name; }
    public int getId() { return staffId; }
    public void setId(int staffId) { this.staffId = staffId; }
    public void setDepartment(String department) { this.department = department; }
}
StaffTools.java · sort and search by id
public class StaffTools {
    // Insertion sort by id over the USED part only: staff[0 .. count - 1].
    public static void sortById(Staff[] staff, int count) {
        for (int i = 1; i < count; i++) {
            Staff key = staff[i];               // save the object reference
            int j = i - 1;
            while (j >= 0 && key.getId() < staff[j].getId()) {
                staff[j + 1] = staff[j];        // shift the reference right
                j--;
            }
            staff[j + 1] = key;
        }
    }

    // Binary search by id. The array must already be sorted by id.
    public static int findById(Staff[] staff, int count, int id) {
        int low = 0, high = count - 1;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            int midId = staff[mid].getId();
            if (midId == id) return mid;
            if (midId < id) low = mid + 1;
            else high = mid - 1;
        }
        return -1;
    }

    public static void main(String[] args) {
        Staff[] staff = new Staff[6];           // capacity 6
        staff[0] = new Staff("Mike", 17, "Bio");
        staff[1] = new Staff("Ana", 3, "Mat");
        staff[2] = new Staff("Raj", 11, "Phy");
        staff[3] = new Staff("Lee", 9, "Bio");
        int count = 4;                          // only four cells are used

        sortById(staff, count);
        for (int i = 0; i < count; i++) {
            System.out.println(staff[i].getId() + " " + staff[i].getName());
        }
        System.out.println("id 11 is at index " + findById(staff, count, 11));
        System.out.println("id 99 is at index " + findById(staff, count, 99));
    }
}

The used part versus the whole array

The staff array has capacity 6 but only 4 cells are filled. Cells 4 and 5 are null.

That is why both methods take count. If sortById were called with staff.length, the loop would reach staff[4], and key.getId() would throw NullPointerException because the cell holds no Staff object.

Sorting by text instead of a number

Use compareTo, never <, for Strings. It returns a negative number if the left String sorts first, zero if equal, and a positive number otherwise. Only the while line changes:

Sort by name
// Text key: compareTo returns a negative number when the left String sorts first.
while (j >= 0 && key.getName().compareTo(staff[j].getName()) < 0) {

The same main then prints 3 Ana, 9 Lee, 17 Mike, 11 Raj: alphabetical by name, so the ids are now out of order. Its two lookups therefore print id 11 is at index -1 and id 99 is at index -1. Binary search by id fails on this array, even though id 11 is present. Binary search by name would need the matching compareTo test as well, on an array sorted by name.

Quick check: why would binary search by id fail on an array sorted by name?
The array is ordered by name, so ids appear in any order. Comparing the id at the midpoint says nothing about which half holds the target, and the search can discard the half that contains it.
Quick check: after staff[0] = staff[1];, how many Staff objects exist?
The number of objects is unchanged. The statement copies a reference, so staff[0] and staff[1] now reach the same object, and the object previously at index 0 may become unreachable.

Book.java
public class Book {
    private String title;
    private double price;

    public Book(String ttl, double pr) {
        title = ttl;
        price = pr;
    }
    public String getTitle() { return title; }
    public double getPrice() { return price; }
    public void setTitle(String ttl) { title = ttl; }
    public void setPrice(double pr) { price = pr; }
    public String toString() { return title + " (" + price + ")"; }
    public boolean equals(Book bk) { return title.equals(bk.title) && price == bk.price; }
}
BooksApp.java · BufferedReader answer
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class BooksApp {
    public static void main(String[] args) {
        Book[] books = new Book[50];              // 50 empty (null) cells
        int count = 0;                             // how many cells really hold a Book

        try (BufferedReader br = new BufferedReader(new FileReader("books.txt"))) {
            String line;
            while ((line = br.readLine()) != null && count < books.length) {
                String[] details = line.split(",");              // "Hobbit,20.99" -> ["Hobbit", "20.99"]
                String title = details[0].trim();
                double price = Double.parseDouble(details[1].trim());
                books[count] = new Book(title, price);
                count++;
            }
        } catch (IOException e) {
            System.out.println("Error reading file: " + e.getMessage());
        }

        for (int i = 0; i < count; i++) {          // only the filled cells
            System.out.println(books[i].getTitle());
        }
    }
}

The checked exception is handled by catch (IOException e); try-with-resources closes the reader even if parsing fails. trim() removes spaces around comma-separated fields, and Double.parseDouble converts the price text.

Question 2(e): print only cells that contain objects

The 50-cell trap. If only three records were read, an enhanced-for loop over all 50 cells eventually calls getTitle() on null and throws NullPointerException. Loop from 0 to count - 1. Use println because the question requires one title per line.
Scanner route · also compiled and run
import java.io.File;
import java.io.FileNotFoundException;
import java.util.Scanner;

public class BooksScanner {
    public static void main(String[] args) {
        Book[] books = new Book[50];
        int count = 0;

        try (Scanner in = new Scanner(new File("books.txt"))) {
            while (in.hasNextLine() && count < books.length) {
                String[] details = in.nextLine().split(",");
                books[count] = new Book(details[0].trim(), Double.parseDouble(details[1].trim()));
                count++;
            }
        } catch (FileNotFoundException e) {
            System.out.println("File not found!");
        }

        for (int i = 0; i < count; i++) {
            System.out.println(books[i].getTitle());
        }
    }
}
Why keep count separate from books.length?
books.length is capacity: always 50. count is logical size: how many Book objects were actually stored. Algorithms that read the data must stop at count.
