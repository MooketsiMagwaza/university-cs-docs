## 5. The Java runner (TRY-08)

The runner is a TeaVM compiler and class library in WebAssembly workers (`public/java-playground`, driven by `lib/java-playground/runner.ts`), so it supports a subset of the JDK. A headless-Chromium harness measures it (`node scripts/test-java-runner.mjs`, options `--only probes|playground|notes|api`, `--match <text>`, `--fresh`, `--write docs/plans/java-runner-support.md`). It loads the site's **real** `runner.ts` (transpiled on the fly) and compares programs with the local JDK 21 (`scripts/java-api-probes.mjs`, about 130 one-feature programs).

Findings before the fixes (fresh page per program): probes 43/58, playground 13/14, notes 47/50, API differential 82/131. Root causes:

- **The compiler keeps state.** One program with a `package` line or a non-`Main` class made every later compile in the page fail with "Multiple main methods found" until reload. This is the main "crashes a lot" cause.
- `printf`/`String.format` with `%f`/`%e` crashes (null pointer in TeaVM's Formatter); `DecimalFormat` crashes.
- Missing from the class library: `Scanner`, `System.in`/`BufferedReader` on it, `Throwable.getMessage()`/`getCause()`, `Map.Entry` (use `var`), `StringJoiner`, `System.exit`, `getClass()`, threads, files, `Integer::sum`.
- Runtime: recursion deeper than about 5,000 frames raises a JavaScript `RangeError` (not a catchable `StackOverflowError`); a null dereference is a wasm trap and cannot be caught; some built-in exceptions arrive as a bare `Error`; output was capped at 500 lines.
- Differences from the JDK that print wrong answers silently: `HashMap`/`HashSet` iteration order, `Random(seed)` and `Collections.shuffle(seed)` sequences, `Math.round(-2.5)`, `Math.rint`, `Math.log10(1000)`, `Double.toString` of tiny values, `Collections`... (see the support table).

Done so far (uncommitted until this handoff's commit; the full harness run was in progress): `lib/java-playground/compat.ts` and `shim.ts` rewrite a program before compiling (formatter written in Java, `Scanner` and `BufferedReader` over an Input box, `getMessage`, `System.exit`, `Thread.sleep`, `Integer::sum`, package line removed, a lone public class renamed to `Main`); `runner.ts` resets the compiler when a type disappears and retries once on "Multiple main methods found", maps stack and null-pointer failures to readable messages, and takes `{ stdin }`; `executor-worker.js` allows 2,000 lines / 256 KiB and treats the exit marker as normal completion. `node scripts/test-java-shim.mjs` shows the formatter, Scanner and message helper match the JDK on 106 cases. The printf probes pass through the real runner.

## 6. Tooling notes and gotchas

- Shell: Git Bash on Windows. Backslashes in heredocs and `node -e` strings are mangled (`\n`, `\b`, `\u`): write files with the editor/Write tool, or build the character with `String.fromCharCode(92)`. The Edit tool fails on multi-line `old_string` in CRLF files. A `/tmp` path passed to node needs `cygpath -m`.
- `gh` lost its login once and recovered itself; if it does not, the owner must run `gh auth login`. Use `git ls-remote` to test plain git access.
- Free memory is about 2 GB: do not start the Next dev server, `tsc` or Playwright while many bots run; check for Valorant first (`tasklist | grep -i valorant`). The Java harness uses headless Chromium and is fine alone.
- The permission classifier refused: remote branch deletion, batches of `git branch -D`, `sleep` inside a compound command. Single, simple commands pass.
- MDX: never put program text in a JSX attribute; no `import` in MDX; no raw `<` or `{` in prose; escape `|` in table cells; blank lines around fences and tags. `HaskellTryIt` takes a `haskell` fence and a `text` fence with exactly what GHC prints.
