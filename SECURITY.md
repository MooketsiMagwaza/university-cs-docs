# Security Policy

## Supported version

Security fixes are applied to the current `main` branch and the production deployment. Historical commits and forks are not supported releases.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability.

Use [GitHub's private vulnerability reporting form](https://github.com/MooketsiMagwaza/university-cs-docs/security/advisories/new). Include:

- the affected route, component, dependency, or commit;
- a clear description of the impact;
- reliable reproduction steps or a proof of concept;
- any prerequisites or affected browsers/environments;
- a suggested mitigation, if known;
- whether the issue has been disclosed elsewhere.

Please avoid accessing data that is not yours, degrading the service, or publishing the vulnerability before a fix can be assessed.

## What to expect

The maintainer will acknowledge valid reports as capacity permits, investigate impact, coordinate a fix, and credit reporters who want recognition. Timelines depend on severity and maintainer availability; no guaranteed response or bounty program is currently offered.

## Scope

Reports about authentication bypasses, cross-site scripting, unsafe resource handling, leaked secrets, dependency vulnerabilities with a demonstrated project impact, or deployment misconfiguration are in scope.

General bugs, content inaccuracies, availability complaints, and vulnerabilities that only affect unsupported third-party software should use the normal issue process or be reported upstream.
